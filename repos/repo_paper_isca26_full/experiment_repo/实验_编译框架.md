## Accelerator Polymorphism: Transcending Domain-Specific Architectures with Robotics（近似层次匹配：多态 ISA + 队列语义编译映射，论文无独立编译器评估）

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为面向多态执行的 32-bit ISA 与配套编译流程（论文是硬件架构论文，本层次取其 ISA 设计与编译映射部分，属近似匹配；论文明确声明"Compilation for accelerators remains an open problem"，无编译器性能实验）。(1) ISA 以三组机制实现指令级多态：① morpha 选择/重配指令——MORPHA_STATIC_CONFIG（指定 morpha 类型、目标核 XY 坐标、按 N/S/W/E/Local 顺序编码 crossbar 方向位）与 MORPHA_DYN_CONFIG（配置输出端口及路由地址范围上下界，供 graph/tree 地址比较器用）；② queue 指令组——INIT_Q/FREE_Q（分配/释放，256 个架构队列）、POP_Q/PEEK_Q/PUSH_Q/IS_EMPTY_Q/SIZE_Q、Q_CONDITIONAL_PUSH、Q_LOOP_UNTIL_EMPTY（带 INSTRUCTION_COUNT 字段告知硬件循环体大小），以及共享队列 + REMOTE_STORE/READ 跨核通信；③ Namespace-ID 统一操作数模型——计算指令以 (Namespace, ID) 对寻址操作数，由 Queue Manager/迭代表解析，同一 ADD 等指令可跨 queue/vector/graph/tree morpha 使用而不暴露底层存储布局；另有 SET_ITER/SET_STRIDE/SET_BASE_ADDR 迭代表配置、DMA 配置（LD_CONFIG_BASE/STRIDE/ITER）、collective 配置（BROADCAST/COLUMN_REDUCE）、SYNC 屏障（code_block_end 隔离 morpha 间同步）。
  - 编译流程：regular 访存负载复用 in-house tensor compiler [60,72]（标准张量优化：prefetching、memory tiling、operator fusion）；queue-centric 负载先在软件层按 Morpha Core 的 queue 语义重写并做功能正确性验证（RoWild），再开发编译器把软件 queue 函数直接映射为 Morphatron queue 指令；编译器负责静态编程 DMA（vector/systolic 的 prefetch/double-buffering）与插入 barrier。实验比较：无独立编译实验，编译产物的效果体现在端到端与消融实验（见硬件架构/kernel调度层条目）。

## AutoFHE: An Automatic Hardware Generation Framework for Domain-Specific FHE Accelerators

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为 AutoFHE：基于 Chisel + FIRRTL 编译栈的 FHE 加速器自动硬件生成框架，把普通领域专用 RTL 加速器设计自动转换为对 TFHE 密文运算的加速器。四步流程：(1) Chisel 加密信号注解——设计者用 `Secure(io.vec1)` API 声明式标记密文信号，AutoFHE 自定义 SecureAnnotation 类（继承 ChiselAnnotation）在 Chisel elaboration 阶段记录注解，序列化阶段由 FIRRTL 后端产出 `.fir`（FIRRTL IR）与 `.anno.json`（Target 字符串定位被注解信号，如 `VecUnit|VecUnit>io.vec1`）；(2) 自动加密组件识别——以设计者注解为种子在 FIRRTL 图（Chisel diagrammer 生成）上 BFS 追踪，标记所有直接/间接依赖密文信号的下游逻辑：算子级（c=Mul(a,b) 中 a 加密则乘器与输出 c 标密）、模块级（复杂模块整体作一个节点）；(3) 基于 CPE 模板的架构翻译——按算子到 CPE 映射规则替换：逻辑/关系运算与算术/密文-明文运算→ciphertext arithmetic 模板（密文×密文用模板内 external product），两输入 MUX→HMUX 模板；bootstrapping 模板按 TFHE 协议自动置于 arithmetic CPE 下游（仅实例化硬件单元，算法级 bootstrapping 时机由算法设计者定）；用 CPE-virtualization 策略让 K 个物理 CPE 时序共享全部逻辑 PE，硬件调度器固化离线搜出的调度策略在线执行；(4) 自动 DSE——双层嵌套优化：外层枚举硬件参数（CPE 微架构参数 PoV/PoD/BFU/IBFU/PoE/PoC/PoK + 物理 CPE 数 K），内层对每个候选用遗传算法搜时空调度（chromosome=|V| 个基因编码节点调度优先级，critical-path-first 初始化种群、order crossover、swap mutation、tournament selection、依赖校验），解析模型评估：latency=max(计算周期,访存周期)、面积=DC 预表征原语线性组合、能量=off-chip/on-chip 访存+计算+片上通信四源聚合，目标可切 Latency 或 EDP（Latency×Energy）。
  - 实验比较：与专家手工 FHE 加速器在同约束下对比——Strix（eNPU，142 mm²、300 GB/s）、MATCHA（加密逻辑/关系，37 mm² 14nm、640 GB/s）、PPGNN（加密查找引擎，57 mm² 14nm、512 GB/s），另比 CPU（Intel Xeon 6148 @2.5 GHz + TFHE 库）与 GPU（NVIDIA A100 + cuFHE/nuFHE）。附加实验：可扩展性（Strix 8→48 CPE、面积预算至 400 mm²）、灵活性（riscv-mini 3 级 / KyogenRV 5 级 RISC-V ALU 生成加密 ALU，200 mm²、640 GB/s）、GA 调度 vs round-robin、unrolling 因子 r∈{1,2,3,4} 扫描、EDP 目标、设计空间可视化、生成耗时开销（每设计编译 20 次取平均）。
- 硬件平台是什么，配置是什么。
  - 生成目标硬件用 Synopsys Design Compiler + TSMC 28nm 综合评估面积、时钟 1 GHz（跨工艺对比做等效面积缩放：MATCHA 的 PTM 16nm 36.9 mm² 等效 TSMC 28nm 156 mm²）。TFHE 参数三组（表 I）：Set1 n=500/N=1024/L=2/k=1（80-bit）、Set2 n=630/N=1024/L=3/k=1（110-bit）、Set3 n=592/N=2048/L=3/k=1（128-bit）。
- 开源编译框架是什么。修改了什么。
  - 基座为开源 Chisel（chisel-lang.org，注解机制类比 dontTouch 特性）与 FIRRTL 编译器：扩展 `firrtl.annotations.Annotation` 实现 SecureAnnotation，自定义 transformation 经 `--custom-transforms` 注入 FIRRTL 编译流程；用 Chisel diagrammer 把 HCL 转 FIRRTL 图。AutoFHE 自身组件（加密组件识别、DSE、调度搜索、硬件模拟器）用 Python 编写。

  - AutoFHE 源码论文未给开源链接，联网搜索未找到公开仓库（IEEE Xplore 11617778 仅有论文，ISCA 2026）。基座与案例输入设计开源：Chisel（https://www.chisel-lang.org）、Vector MulAdd Accelerator（https://github.com/meton-robean/Vector-MulAdd-Accelerator，eNPU 案例的明文 Chisel 起点）、riscv-mini（https://github.com/ucb-bar/riscv-mini）、KyogenRV（https://github.com/panda5mt/KyogenRV）。
  - 编译框架输入到输出全过程：输入 = 设计者按明文语义写的 Chisel RTL（如 Vector MulAdd Accelerator），仅对密文输入端口加 Secure 注解 → Chisel elaboration 记录 SecureAnnotation → FIRRTL 后端产出 `.fir` + `.anno.json` → 自定义 FIRRTL pass 按 Target 字符串定位注解信号 → FIRRTL 图上 BFS 传播加密标记（算子级/模块级）→ 按算子-CPE 映射规则把加密算子绑定到 CPE 模板（arithmetic/bootstrapping/key-switching/HMUX），bootstrapping 置于 arithmetic 下游 → CPE-virtualization：FIRRTL 图抽象为 DAG，GA 搜 PE→物理 CPE 时空调度（依赖约束 j>i、资源约束 |St|≤K、最大化利用率 |V|/(K·(Tmax+1))）→ DSE 外层枚举 (CPEmicro, K) 查面积模型超预算跳过、内层逐候选跑 GA 调度 + 解析性能模型评 latency/EDP → 输出 = 全局最优 (硬件参数, 调度策略)，调度固化为硬件调度器 RTL 与 CPE 池一起生成最终 FHE 加速器。生成耗时（表 IV）：eNPU 203.5 s（Chisel 编译 5 s + FIRRTL 图生成 1 s + 组件识别 0.1 s + DSE 197.4 s）、ALU1 335.1 s、ALU2 672.1 s。

## Bringing Near Data Processing into the Low-Bit Floating-Point Era

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为 FlexQ-NDP：面向分组低比特浮点（group-wise low-bit FP）GEMM 的 DRAM-Near Data Processing（NDP）编译器，基于开源 UniNDP [63]（HPCA'25，NDP 统一编译+仿真工具）扩展，复用其 INT 导向的编译流程（operator partition → loop tiling → DRAM mapping → instruction generation）并加入三项面向低比特 FP 的机制：
    (1) Scale-Value 交织 FP 布局（Sec. VI）：把多个 QGroup 的 scale 区域与 value 区域打包成交织块 itBlock 连续放置。交织比 Ratio = Size(ValueRegion)/Size(ScaleRegion) = Prec.(Value)·G_M·G_K / Prec.(Scale)（Eq.1）；scale 区列数 Col_S 受 scale 缓冲约束，itBlock 内 QGroup 数 #QGroup = Col_S×len/Prec.(Scale)（Eq.2）；按 K 维 loop tiling 对齐，每 itBlock 沿 K 的 QGroup 数 #QGroup_K = ⌈K_Tile/G_K⌉（Eq.3），跨 tile 边界时按 #QGroup' = #QGroup_K×⌊#QGroup/#QGroup_K⌋ 收缩（Eq.4），再按 Eq.5/6 算 value/scale 实际列数；DRAM 映射经 itBlock id 与块内 id（Eq.7）、逻辑列号（Eq.8）、物理行列号（Eq.9）完成，scale 区置于 value 区之前便于先缓冲，仅对权重矩阵离线排布。
    (2) 去量化隐藏指令重排（Sec. VII + Alg.1）：把细粒度高精度 dequant 指令"前移"进 PU 空闲窗口（free slot，如 DRAM 行切换 precharge+activate 的 t_RP+t_RCD=48 cycle；一次 dequant 仅 8 cycle=2·t_CCDL）。三条规则：① 数据依赖——只能向前移、不能越过后续 dequant、不能越过 scale 缓冲 refill 触发的 DRAM 读；② partial-sum 缓冲容量——按 extra_buf 逐指令扣减（越过 Compute 扣其产生的 partial sum 数，越过 ReadData 不扣，越过 ReadScale/Dequant/WriteBack 直接阻断）；③ 空闲窗口容量——slot 被填满即失效。按逆序处理 dequant 指令（后到先占，保前面指令的移动弹性），仅用于 weight-activation 量化。
    (3) 编译空间裁剪 + 代价模型 DSE（Sec. VIII）：编码维度 = 算子划分 {Part^M,N,K 于 Ch/Ra/De/Bk 层级}、缓冲四元组 (Val_Buf, Scale_A_Buf, Scale_W_Buf, Dequant_Buf)（结果缓冲固定 32B、分配粒度 32B）、循环置换 {Order1=M→KOuter→N→KInner（权重驻缓冲）/ Order2=N→KOuter→M→KInner（输入驻缓冲）}，K_Tile=Tile_Col×#Value/Col 且 K_Tile≤Data_Buf、DRAM 映射 Col_S。两条 QConfig 兼容 guideline：G1 算子划分须对齐 QGroup 尺寸（否则跨 PU 的 QGroup 造成 padding 与指令流发散）；G2 缓冲分配随组粒度偏斜（大组多分 value、小组多分 scale）。裁剪：padding>50% 的划分剪掉；按 loop tiling 与 itBlock 实际列数算 DRAM 列利用率、低于阈值剪掉（空间缩 4~5×）。两阶段代价模型：先粗粒度统计缓冲 miss、dequant 次数、行切换次数（区分自然行切换与 buffer-miss 引发行切换并做重合抵扣），再用解析式 Lat = t_CCDL·Num_col + Lat_RowChange·Num_row + Lat_Dequant·(1−Ratio_Overlap)（Eq.18）估延迟。
  - 实验比较：baseline 为面向低比特 FP 的朴素 NDP 编译策略（AiM [33] 风格按输出通道跨 PU 划分；scale 与 value 分离连续存储，沿用 [30] 与 Triton [57] 惯例；缓冲按 scale:value 比例匹配分配；Order1 循环序）。图 8 算子级最高 3.29×；消融（Tab. IX）累计贡献：Layout ×1.36、Dequant-Hiding ×1.18、DSE ×1.17；代价模型最优性 W-A 平均 95.97%（P90 90.52%）、W-Only 平均 99.66%（P90 99.22%）（Tab. X）；DSE 使单个 batched MVM 搜索从 3 小时降到 1 分钟、LLaMA2-7B 全模型 10 分钟内完成；端到端 LLaMA2-7B/34B decode 最高 2.73×（相对量化 baseline）、相对 FP16 最高 15×（7.17× 来自量化消除 34B 权重重写 + 2.09× 来自编译优化）；CNN CONV（im2col 转 MVM）平均 1.49×；仅 8×32B 缓冲即可接近最优（baseline 需 >20×32B）；FP32 吞吐降至 1/2、1/4 时仍有 1.45×/1.28× 平均加速。
- 硬件平台是什么，配置是什么。
  - 目标 NDP 架构取自 Hynix GDDR6-AiM [33] 扩展：32 颗 GDDR6 芯片 × 2 通道 × 16 bank，共 1024 个 PU，32 GB 容量，12 Gbps/pin、1.5 TB/s 聚合带宽，主机经 PCIe 通信；每 bank 一个多精度 PU（0.4 GHz，FP4 51.2 / FP8 25.6 / FP16 12.8 / FP32 6.4 GFLOPs）+ 5Kb SRAM（20×32B，可配置为 value/scale/partial-sum 缓冲），PU 操作数位宽 256b 对齐 GDDR6 读写位宽。DRAM 时序取 DRAMSim3 [38]：tCK=0.66ns、tRCD=24、tRP=24、tCCDL=4、BL=16、tCL=24。复现平台为多核 Linux 服务器（AMD CPU 128 核）、Python3。
- 开源编译框架是什么。修改了什么。
  - 基座为开源 UniNDP [63]（https://github.com/thu-nics/UniNDP，HPCA'25 unified NDP compilation + simulation tool）。FlexQ-NDP 在其上修改：① 在原有指令格式外包一层携带量化元数据的高层 IR（支撑去量化隐藏等优化）；② 编译器侧建模 scale 缓冲与 partial-sum 缓冲行为，向算子 kernel 插入 scale 读取/去量化/写回指令；③ 新增交织布局 DRAM 映射、dequant 指令重排 pass 与代价模型 DSE。非基于 GPU 编译栈（Triton [57]/CUTLASS [52] 仅作对照引用）。

  - 完全开源：GitHub https://github.com/ISCA26-FlexQ-NDP-ae/flexq_ndp（thu-nics 旗下，Python+Shell，MIT License），Zenodo DOI https://doi.org/10.5281/zenodo.19452117（含全部结果文件）。安装：git clone + pip install -r requirements.txt，export FLEXQ_NDP_DIR，脚本从 flexq_ndp 根目录运行。
  - 输入到输出全过程：输入 = 量化 GEMM 描述（QConfig：QGroup (G_N,G_K)∈{(1,16)…(128,128)}、value/scale 精度如 W4A4S8/W8A8S16/W4A16S8、weight-only 或 weight-activation）+ NDP 硬件描述（bank/PU/缓冲容量、DRAM 时序）。FlexQ-NDP 按 guideline 编码编译空间（划分×缓冲×循环序×Col_S），先剪掉 padding 超标与列利用率过低的策略 → 对剪后空间逐策略构造交织布局（Eq.1–9 算 itBlock 参数并映射逻辑→物理行列地址）→ 指令生成阶段插入 scale 读取/GEMM/dequant 指令，并对 dequant 做 Alg.1 重排隐藏 → 两阶段代价模型预测延迟、选出最优策略 → 输出带量化元数据的指令流，交给 UniNDP 扩展仿真器展开为 DRAM bank/PU/缓冲命令逐 cycle 仿真得延迟，按 DRAMSim3 功率模型从 trace 算能量。实验脚本：scripts/final/3_single_op_with_predictor/part_1.sh（DSE 搜策略，~1 天，最优策略存 tmp_strategy/tmp_strategy.yaml）→ part2_m1~m4096.sh（baseline 与 FlexQ-NDP 逐 config 仿真）→ mm_speedup_optimal.sh（理论下界，PU 无空闲假设）。

## CODO: An Automated Compiler for Comprehensive Dataflow Optimization

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为 CODO：基于 MLIR 的端到端 FPGA 数据流加速器自动生成编译器，输入 C/C++ kernel 或 PyTorch 模型，输出 host code + HLS C++ kernel。前端双通道：(1) Polygeist [28] 把 C/C++ 翻译为 affine dialect；(2) Torch-MLIR [3] 把 PyTorch 模型先降到 linalg（做元素级算子融合与 tensor bufferization）再降到 affine dialect，affine dialect 为后续所有优化的主表示（面向常量循环界的 affine 程序，覆盖卷积、注意力、ReLU/GeLU、矩阵乘、点积等）。核心优化（均为模块化 MLIR pass，每步变换后跑内建 verification + canonicalize/cse）：① 粗粒度 violation 消除——pattern-aware 代码变换（Algorithm 1）：遍历所有 buffer 收集访问节点、analyze_access_pattern 识别违例、按三类访问模式分派变换：single-producer-multi-consumer（残差 bypass 模式，如 ResNet-18/GPT-2）插入中间节点 Node1' 读 a 并写复制缓冲 b/b'；multi-producer-single-consumer（初始化+padding 配对）用 node fusion 融合共享外层迭代域且无 loop-carried 依赖的写循环，内层结构不同则插控制逻辑，先前写的结果暂存并并入最后一次写；multi-producer-multi-consumer 复制 buffer 使每个 buffer 单写单读。② 细粒度 violation 消除——reduction operation rewriting（针对全连接/最大池化/归一化等归约：识别归约维度移入最内层、把写移出归约区、临时数组聚合中间结果，使生产者写数与消费者读数一致，并保证尽早 FIFO 写、just-in-time 传输）+ permutation map generation（选计算强度/迭代数最大的 bottleneck 循环为 reference loop，Step1 建立连接数组维度↔循环深度映射，Step2 对 reference loop 做 tiling size=1 的循环切分对齐深度，Step3 构造深度-深度映射，Step4 按映射置换 target loop 嵌套顺序，统一 producer/consumer 访问顺序）。③ 通信缓冲确定——FIFO-first：无违例处优先 FIFO（延迟低、只存 in-flight 数据省资源），无法消除的细粒度违例处回退 ping-pong。④ violation-free reuse buffer 生成——检测乘加等计算模式识别卷积/矩阵乘等计算密集 kernel，把出现在数组索引中的循环维度分类为 FIFO 维度、其余为归约维度，按归约循环迭代域自动构造 line buffer（lb[n][ci][kh][w]，深度=kh、保留 kh-1 行历史）与 window buffer（wb[n][ci][kh][kw]，新列进入时横向移位更新），同时重写循环保证 FIFO 访问循环维度与数组索引精确对齐；并给出并行化合法性指引：最外层循环不可并行（会展开全部三个内部区域、引入复杂依赖）、中间 FIFO 索引相关循环并行需配套措施、最内层与 FIFO 无关循环可安全并行——用于剪枝后续 DSE 设计空间。⑤ 片外传输管理——codo-transmit 命令自动生成 host code 与 burst 访问操作，把模型权重等参数分布到多个 HBM channel 并行访问独立内存区域，提升 HBM 带宽利用率。⑥ 自动调度——resource-aware bottleneck-centric DSE 三阶段：PA 用 profiling-based 性能模型（基本操作延迟/资源离线 profiling 为模型参数）按循环 trip count 与并行策略估计各循环 latency，按延迟比例分配并行度（最小 1）、保持比例整体放大到用户上限或资源极限，优先 tile 与 FIFO 无关的循环维度，自动插入 pipelining/unrolling/array partitioning pragma；UP 遍历 bottleneck 循环，延迟仍 ≥ 最低延迟 n 倍者把并行度提到 max(⌈n⌉×初始度, 最大度) 并迭代；DP 把比最长循环快 n 倍的过度优化循环并行度除以 n 回收资源（可配置开关），平衡阈值 n=2.0 经验值；inter-task optimization 把 bottleneck 循环的 tiling/unrolling/partitioning 策略传播给 FIFO 对端 producer/consumer 循环，冲突不可解时把该缓冲降级为 ping-pong、保住其余 FIFO 段。优化后的 ## DCC: Data-Centric Compilation of Machine Learning Kernels for Processing-In-Memory Architectures

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为 DCC：首个面向 PIM 系统的 data-centric ML 编译器，在统一 tuning 流程中联合协同优化"数据重排策略（tensor 数据如何在 PIM core 间分区）"与"loop 级计算调度（嵌套循环如何拆分并分配到 PIM core）"。五个组件：(1) Multi-Layer Abstraction 多层抽象——把 PIM 内存层次映射为计算层次：System 级（Host xPU + Host 内存空间 + PIM 设备）、PIM Group 级（同 channel/rank 的多 PIM core，支持 group 级广播指令与组级专用计算单元）、PIM Core 级（单个处理单元 + 其本地 bank），把编译器与后端语义解耦；(2) Data-Centric Schedule Generator 数据优先调度生成器——先枚举数据张量在 PIM 组/core 上的所有候选数据分区（data tiles），再映射到循环划分（compute tiles）生成 tiling drafts，四阶段 = ①Dimension Set Construction（张量维度经 loop 变量映射为映射函数 F(b)=b+1、F(i)=i*2 等，收集 reference set，共享同一 loop 变量的维度合并为 complex dimension set）→ ②Data-Tile Construction（对每个 dimension set 做 [1,k] 组 × [1,m] 核的全分配穷举 DFS + memoization，递归 avail_resources_{i+1}=avail/allocated，每个 draft 每 part 记 [组数, 核数, representative mapping]）→ ③Draft Pruning（3 条规则：等价 representative mapping 的冗余 draft 去重；SIMD 对齐——d-way SIMD 下每核分配的维度集大小非 d 倍数即剪枝，如 16-way MUL 下 4 核分 16 元素每核 4 非 16 倍数被剪；执行性能等价——各组 worst per-core 性能相同则去重）→ ④Data-Tile to Compute-Tile Mapping（core 级 data-tile 大小=dimension_size/(groups×cores)，compute-tile=映射函数结果落在 data-tile 内的 loop 变量范围，再导出全部张量数据索引；索引非连续时两条策略：扩展为连续区间 vs 保持原索引集，二者都生成由 predictor 选择）；(3) PIM-Specific Code Optimizer——数据重排优化：利用可控片上内存（GPU shared memory）做 staging，块大小 B=on-chip_memory/N（N=PIM channel 数），串行 N 次 Host 读入片上后并行 N 路写 PIM channel，使 Host 读与 PIM 写都获得 channel 级并行（无片上内存则用 PIM 后端默认 copy/DMA 接口）；计算代码优化：分级命令生成——优先 group 级广播指令（对组内各 core 数据 padding 到相同大小保证相同地址偏移，一条命令驱动全组，减少内存控制器命令瓶颈），无 group 支持或偏移不同则退化 bank 级并行命令；(4) Coupled Performance Predictor——XGBoost（learning_rate=0.1、max_depth=8、num_boost_round=5000）联合预估数据重排+计算端到端时间选最优 draft：静态尺寸离线训练查 lookup table，动态尺寸（LLM token 变化）运行时在线生成 draft 并预测（可选在线增量训练）；(5) Data-Centric IR——complex_dimset/data_tile/compute_tile/tensor_tile/rearrange[to_PIM_core|to_host]/parallel_PIM/loop 等构造，随后 lowering 到后端 PIM 指令。
  - 实验比较（5 个对比点）：(1) GPU（A100 全部 kernel 跑 GPU）；(2) AttAcc 默认开源实现（batch/head 分布到 16 pCH、第一维分到每 pCH 16 bank group、第二维分到每 bank group 4 bank 的固定分布）；(3) AttAcc+DCC；(4) HBM-PIM（沿用 AttAcc 数据分布）；(5) HBM-PIM+DCC。另在 §2.2 动机实验比较 TVM 式 compute-centric 编译方案（T，公平复刻 ATiM）vs 手工最优（B）vs DCC（D）：TVM 方案数据重排占 kernel 时间 64.68%、比手工最优差 1.28×；DCC 达 1.27× 反超 T 并逼近 B。附加实验：剪枝/预测器消融（Table 3/4）、在线动态预测（MT-NLG 2000 批未见 shape 查询）、能耗分析、编译时间评估。

## DICE: Enabling Efficient General-Purpose SIMT Execution with Statically Scheduled Coarse-Grained Reconfigurable Arrays

- 属于编译框架的实现是什么？实验比较什么？
  - 实现：自研 DICE p-graph 编译器（不改既有开源编译框架，NVCC 仅作 PTX 前端）。流程：CUDA 源码 → NVCC → PTX IR → DICE 编译器构造 CDFG → 按四条约束划分 p-graph → 生成带 metadata 的 p-graph IR → CGRA mapper（placement & routing）→ CGRA 配置位流。核心编译决策：(1) p-graph 划分四约束——p-graph 内无控制发散（branch/jump，与 basic block 相同；可用 predication 放宽以合并发散路径）、无 load-to-use 依赖（访存生产-消费边跨 p-graph 分离到 CGRA 边界，由 RF/LDST Unit 外部处理）、同步 barrier 终止 p-graph、资源用量须容于 CGRA 容量；(2) predication 合并 pass：把因控制发散拆开的路径并入单 p-graph，用 1-bit 谓词选择性使能操作与写回，省重配置开销；(3) 编译期 thread unrolling 选择：编译器感知硬件 swizzled bank 映射（bank = (r+T) mod N_r），按 p-graph 输入寄存器集合静态求最大安全 unroll factor，bank 冲突限制时可调整寄存器分配换取更高 unroll；(4) metadata 生成（Table I：BITSTREAM_ADDR/BITSTREAM_LENGTH、UNROLLING_FACTOR、LAT、IN_REGS/OUT_REGS 位图、LD_DEST_REGS、NUM_STORES、BRANCH_*、BARRIER、PARAMETER_LOAD）。
  - 实验比较：编译产物驱动的 Accel-sim 仿真评测（baseline = RTX2060S 与 DICE-naïve 变体，详见硬件架构层条目）。编译侧效果指标：空间执行消除 MOV/S2R 等数据搬移指令，静态指令数在低指令数 kernel（NN、BFS-2、GE-1）最多 −17.8%；平均 p-graph 大小即 Fig.11 的 stall-excluded 利用率曲线依据；共享内存访问 kernel（BPNN/HS/PF）因 bank conflict 延迟不可静态预知、barrier 频繁而 p-graph 偏小，共享内存的流水优化留作未来工作。

  - 编译与仿真均在主机侧：64-bit Linux、多核 CPU（推荐并行构建），无需物理 GPU；CUDA Toolkit 11.7（nvcc + ptxas）。目标配置 = DICE CC/CP（4×5 CGRA：16 ALU PEs+4 SFUs、N_r=32 bank、N_Tmax=4、K=8/16，详见硬件架构层 Table II）与 Turing/Ampere 基线；编译目标资源上限由 CGRA 阵列容量决定（资源约束划分）。

## Distilling Magic States in the Bicycle Architecture（近似层次匹配：非对开源编译框架的修改，本层取其把 triorthogonal 蒸馏电路编译到 BB 码 native 测量/automorphism 门集的编译优化流水线）

## Dynamic Scheduling for AI Accelerators via TISA

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为语义保持编译器（semantics-preserving compiler）：端到端保留算子边界、类型化依赖（RAW/WAR/WAW）与资源亲和性，把高层模型逐层 lower 为硬件可消费的 TISA tile 指令。五级流水：① Framework bridge——用 torchxla 前端接入 PyTorch/JAX/TensorFlow，导出框架图到 XLA/StableHLO dialect，TISA 的 OpType 分类与 StableHLO 算子抽象对齐；② Graph compiler（GC）——MLIR 基础上消费 StableHLO IR，做 fusion、tiling（64×64 tile，贴合 Epoch 256 KB staging buffer；不可整除边界生成 edge tile，用精确 Shape/TileMem 免 padding）、locality 重排，输出带算子边界与类型化依赖边的软件调度 tile 图（自定义 MLIR dialect）；③ Fusion compiler（FC）——把融合子图特化为 TISA 兼容算子，定义自定义 TISA dialect（tisa.gemm、tisa.softmax），OpType 编码算子语义、UnitMap 编码资源意图（执行单元类）、TileMem 编码符号化内存范围/scope；④ TISA generator + 后端——虚拟 tile 级 ISA 统一多后端，OpType 静态绑定张量/向量/DMA 单元类；⑤ Runtime interface——编译产物每 tile 输出描述符（OpType/UnitMap/TileMem）组成就绪集填充运行时 WQ/IQ。关键设计：编译器在 tile 粒度截断 lowering（不再 lower 到细粒度 ISA 指令），ping-pong 缓冲只需分配两 buffer + 交替发射 TISA tile，无需循环展开/指令重排（运行时调度器负责重叠）。
  - 实验比较：① Epoch 上三配置消融隔离编译器与调度器贡献——Naive TISA（仅接口+fence 手工依赖）vs TISA+Static（编译期静态软件流水+fence+重排）vs TISA+Dynamic（同编译器优化+硬件动态调度），比执行周期（表 VI）与 Accumulated Overlap Score（表 VII/VIII）；② 与 GPU 编译栈对比——Epoch(TISA 编译产物) vs A100/H100 上 TensorRT 10.3.0（ResNet50/BERT）与 TensorRT-LLM 0.12.0（GPT-J/LLaMA2/DeepSeek-R1）端到端延迟（表 IX）；③ 可移植性——CPU 上 Triton-TISA（语义指导编译优化：kernel 融合、循环序、内存局部性）vs Torch-Manual（标准 PyTorch 算子组合），比层级/全模型执行时间（图 7）；④ FA3 案例——编译器自动生成的 TISA FA3 kernel vs 手调 CUDA FA3（代码量 -30%、同步频率 -50%、性能在手调基线的 5% 内）。

## FlashTFHE: A Scalable Architecture for Efficient Multi-bit Fully Homomorphic Encryption（近似层次匹配：编译部分为加速器配套编译器，与开源 Concrete 工具链集成，非独立编译框架评估）

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为 FlashTFHE 加速器的配套编译流程（Section V），直接集成于开源 Zama Concrete 工具链，继承其参数选择、量化流程与软件生态。它消费 MLIR 中间表示（Concrete 的 FHELinAlg dialect，带精确类型与参数集），把 batched 操作（matmul、multi-LUT 等）展开为 per-ciphertext primitives，做依赖分析以暴露程序级优化，并输出匹配 FlashTFHE temporal-reuse 执行模型的指令流。核心优化：(1) KS-dedup——把 key-switching 提到 blind rotation 之前（key-switching-first PBS 顺序），当多个 LUT 作用在同一 ciphertext（fanout 结构）时复用 key-switching 结果广播到多个 BRU，最多减少 47.12% key-switching 操作；(2) ACC-dedup——多-bit 程序常对多个 tensor element 应用同一 accumulator，共享 GLWE accumulator 使 GLWE 存储需求减少 91.54%、显著缩小程序体积与 DRAM 容量需求；(3) adaptive batching——编译器按程序实际 ciphertext-level parallelism 动态调整 batch size，并行丰富时 batch 增至 48，并行稀缺时收缩 batch（配合 LPU 的 compile-time lane masking）消除空闲轮次，把回收的 key-switching 带宽重分配给 external product 流水线。
  - 实验比较什么：编译优化本身无独立编译 benchmark，其效果通过消融实验（Fig.20，在同等吞吐与带宽的空间 baseline 上逐步叠加 temporal 设计/异构 FFT/adaptive batching/两级去重，量化 delay、EDP、EDAP 改善）、KS-dedup/ACC-dedup 的统计（key-switching 减少 47.12%、GLWE 存储减少 91.54%）、以及端到端 workload 加速（CNN-20 相对 Morphling 0.34s→0.0139s、CNN-50 1.72s→0.0925s；KNN adaptive batching 延迟 -41.7%）体现。

- 属于编译框架的实现是什么？实验比较什么？

  - MANATEE 编译器是基于 LLVM 的编译期静态分析 + 代码插桩，是"编译器/运行时协同软件内存管理"方案的前端：①解析 linker 生成的 .map 文件，获取 .text/.data/.bss 在 ROM/NVM 的物理地址布局，把 data section 按 64B 划分逻辑页为线性页数组；②在 CFG 上做页级 liveness 分析（Andersen 别名分析 [7]，>99% 精度：97% 指针指向全局数组、地址从 .map 可见；mayalias 指针保守分配新颜色或最远可用颜色；已知迭代次数循环先展开再做指针分析；未知迭代次数的循环/I/O 页保留专用颜色不参与着色）；③先做干扰图着色（每个 SPM page frame 视为一个颜色），颜色不足时触发 intermittence-aware speculative coloring：以功率开启周期 T_on 为滑动窗口尺寸，从冲突点双向（反向+正向）DFS 遍历 CFG 路径累计指令周期设置 distance boundary（含 20% 安全裕量），窗口外页面视为不会共存、窃取其颜色复用，优先取正反向窗口交集颜色、否则优先反向窗口；④为每条 load/store 指令插桩两个 hint（NVM 页号 + 页颜色），生成 metadata（每条指令关联的页号与颜色）链接进二进制，运行时不需查表。
  - 实验比较：编译器侧比较 MANATEE（intermittence-aware speculative coloring）vs Memory Coloring [63]（传统图着色、无滑动窗口、冲突页永久 spill）vs Mapi-Pro [9]（profiling + ILP 的 hot/cold 静态映射 + 整 SPM checkpoint）vs NVSRAM [56]（整 SPM JIT checkpoint）vs Unsecure（无安全机制）；指标：归一化执行时间开销、页 miss rate、编译时间开销、功率周期误估敏感性、SPM 大小/电容大小/数据集大小敏感性。
- 硬件平台是什么，配置是什么。
  - MSP430FR5994 MCU（LaunchPad，MSP-EXP430FR5994 [51]），默认 1mF 电容（100µF/10mF 灵敏度实验），配 power generator board 产生真实电源失效；三条真实功率 trace：thermal、RFHome、solar [17,19,42,69]；默认 SPM 512B。工作负载变化实验在 STM32 平台（ARM Cortex-M33 + 4MB 片外 MRAM）。工具链：LLVM 插桩（-O3）+ TI MSP430 GCC linker 生成 .map 与二进制。

  - 开源：论文未给出代码/artifact 链接，联网搜索未找到 MANATEE 公开仓库，无法确认是否开源。编译框架输入到输出全过程（以一条 store 指令的编译为例）：输入 = C 源码 + TI MSP430 GCC 链接生成的 .map 文件（data section 在 NVM 的物理地址）+ 设备手册参数（V_dd、I_leak、C_msp、f、电容容量 E_buf，用于算 T_on = E_buf/(P_device − P_input)，P_device = V_dd·I_leak + C_msp·V_dd²·f，P_input 为环境输入功率、系统设计时给定 [47]）→ ①解析 .map 得 data 段 NVM 地址，按 64B 划分逻辑页；②构建 CFG，页级 liveness/别名分析（unroll 已知迭代循环；未知迭代循环/I/O 页分配专用颜色）；③干扰图着色，冲突时以 T_on 换算的 MCU 周期为滑动窗口，从冲突点反向+正向 DFS 累计指令周期（静态能量/时序成本模型 [18,19,22,71,72,84,99]），C_available = C_total − C_accessed 为窗口外可回收颜色（加 20% 裕量），优先取正反向窗口交集、否则反向窗口，窃取后继续着色；④为每条 load/store 生成 (NVM 页号, 颜色) hint 与 metadata（含页内偏移支持），链接进二进制。输出 = 插桩后可执行二进制，运行时按 hint 直接索引 BT 对应条目即可判定页驻留，无需查表。作用：把"页→SPM frame"映射决策从运行期搬到编译期，滑动窗口把冲突解决限制在短功率周期内，从根源降低页冲突与 SPM frame 压力；编译时间随 SPM 增大而增长（更多 frame 扩大着色搜索空间，Figure 19 为归一化编译时间开销）。

## Kernpiler: Compiler Optimization for Quantum Hamiltonian Simulation with Partial Trotterization

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为面向量子哈密顿量模拟（Hamiltonian simulation）的专用编译框架 Kernpiler：输入一个哈密顿量 H（加权 Pauli 串集合），输出经过优化的量子线路（u3+CNOT 门集合），目标是生成 e^{iHt} 的近似量子线路，在达到 ≥99.5% 精度（L2 范数）的前提下最小化门数与深度。编译流水线四阶段：(1) Partial Trotterization 哈密顿量项划分——按最高 qubit 索引再按 term 权重排序（Algorithm 1），贪心把非对易项分到至多 n=3 个 qubit 的 partition，把每个 partition 的指数 e^{itΣH_i} 作为一个整体 unitary（而非逐项指数），从根源降低 Trotter 误差的 commutator 项；(2) Trotter step 重排与合并——为每个 Trotter step 构建 conflict graph（边=不交换的对），贪心最大独立集分组成可交换 group（Algorithm 2），把最大的两个 group 放在 Trotter step 两侧且相邻 step 交换两侧使相同 group 相邻，从而跨 step 合并 e^{iH_it}e^{iH_it}→e^{i2H_it}；(3) 随机化——每个 step 内 group 内 term 顺序随机 shuffle 把 coherent 误差转成 stochastic；(4) MCTS unitary 分解——用 Monte Carlo Tree Search（UCT 策略）只搜索 CNOT 骨架（每个树节点=纯 CNOT 线路），模拟阶段在 CNOT 间随机穿插单比特门并用 Gauss-Newton 最小化 L2 范数（cost 函数 Eq.5），奖励函数（Eq.6）= −#CNOT（误差<1e-8）或 −误差，backpropagation 更新 Q 值，输出最优线路后由 Qiskit transpiler level 3 优化为 (u3,cx) 门集。
  - 实验比较什么：两类实验。(1) 不考虑误差缩减的绝对门数/深度对比（图 5，28-220 qubit，固定 3 Trotter steps）——比较 5 个方案：Kernpiler（MCTS 重写）vs Kernpiler 把 MCTS 替换为 Qiskit unitary synthesis vs BQSkit synthesis vs Qiskit PauliEvolutionGate（Paulihedral 重排）vs Rustiq PauliEvolutionGate，指标为 depth、CX、U3 与编译时间（秒）；MCTS 相比各 benchmark 次优方案 peak(avg) 减 U3 60%(33%)、CNOT 67%(34%)、depth 60%(32%)，且即使不含 Trotter step 节省仍比次优 CNOT 减 14%(0%)、depth 减 60%(14%)。(2) 含误差缩减的对比（图 6，8-10 qubit，编译到 <1% 近似误差）——一阶（Lie-Trotter，t=0.1）与二阶（Trotter-Suzuki，t=1）Trotterization 下，相对 Qiskit Rustiq 与 PauliEvolutionGate 中较优者，depth 与 CNOT 减最多 86%（平均 40%）、单比特门最多减 85%（平均 11%），二阶最好情况门数约 3×、深度最高 10× 缩减。(3) 误差随 group 大小缩放（图 8）、非对易对占比随 lattice 增大（图 9，n=3 与 n=5 partition）、各 pass 运行时间分解（图 7：partition 近零、reorder 最高 ~159s、rewrite/MCTS 主导 58-5397s、总最高 ~5886s）。

## Leveraging Phase Polynomials for Quantum Circuit Optimization

- 属于编译框架的实现是什么？实验比较什么？
  - PhasePoly 是一个量子电路编译优化 pass（编译器优化阶段），把 phase polynomial 优化从"局部子电路重写框架的辅助工具"提升为通用编译流水线中的一等公民阶段。输入 OpenQASM 2.0 线路（门集 {CNOT, Rz, T/T†, S/S†, Z, X, H, SWAP}），输出功能等价但门数更少的线路。核心组件：(1) 耦合 parity 矩阵 [phase-parity | output-parity] 联合优化——CNOT 对应 GF(2) 行操作同时更新两 block，用 space-bounded A* 搜索（代价 f(n)=g(n)+h1(n)+h2(n)，priority queue + 多解池 k）最小化总 CNOT；(2) SSA 风格 qubit-state 重命名实现整线路（跨 block）rotation merging；(3) cross-block IR：把被 H gate 分割的多个 phase polynomial block 合并为一个大 block，post-H 行以 inactive 状态存在，经 rank-based 线性相关性检验（rank(M∪{v})=rank(M)，等价于目标单位向量 v ∈ span(候选行)）保证可消除后激活；(4) Incremental Block Merging 渐进合并策略，避免过合并回归。
  - 实验比较：(Q1) 与三个 phase polynomial baseline——Rotation Merging（仅合并同 parity 的 rotation，不动 CNOT 网络）、Single-block Greedy Optimization（单 block 内 phase/output parity 分别用贪心合成 + 高斯消元，平均总门减 26.93%、两比特门减 8.14%）、Gray-Synth [10]（单 block、仅 phase 部分，报告平均 CNOT 减 17.62%）；PhasePoly 平均总门减 34.70%（最高 50.00%）、CNOT 减 26.83%（最高 48.57%），CNOT 减幅优于 Gray-Synth 9.21 个百分点。(Q2) 与通用 subcircuit rewriting 优化器 Quartz（总门减 22.17%/CNOT 16.88%）和 QUESO（27.83%/20.70%）比；并测组合管线：PhasePoly 后接 rewriting 再增 ≈0.75–1.25%，rewriting 后接 PhasePoly 再增 ≈6–13%。(Q3) 大电路可扩展性（MCX/Adder/HWB 三族，Quartz/QUESO 饱和或失败，PhasePoly 线性增长）。(Q4) 映射到受限连接 2D grid 后加权两比特门数与物理深度（Qiskit SABRE 路由，SWAP 权重 3 CNOT；PhasePoly 物理深度平均减 28.35%、大电路族 40.84% vs Quartz 2.7%/QUESO 15.25%）。(Q5) FT 编译——Azure Resource Estimator 下 wall-clock 运行时减 44.62%（Quartz 11.99%、QUESO 31.80%）；与 GridSynth（Clifford+T 合成）的两种编译顺序对比（PhasePoly 在 GridSynth 前应用深度最低）。(Q6) 正确性与鲁棒性：Qiskit unitary 对比（<8 qubit）+ MQT QCEC 形式化验证全部通过（mod_adder_1024 因硬件限制除外）；merge size 消融（Group k vs Incremental，Table I）。(Q7) 编译时间与参数敏感性（Q/P/G 三参数，Q=P=1000 饱和）。
- 硬件平台是什么，配置是什么。
  - 编译与 A* 搜索运行于 2.8 GHz AMD EPYC 7313 CPU（Python 实现，经典侧编译/仿真，无量子硬件）。路由用 Qiskit transpiler 的 SABRE pass 把逻辑线路映射到 2D 平面耦合图（square grid）。FT 资源估计用 Microsoft Azure Quantum Resource Estimator（surface code、nearest-neighbour 架构）。等价性验证用 Qiskit（unitary 对比）与 MQT QCEC（形式化工具）。编译预算：PhasePoly ≤3,600 s/电路（最大实例 hwb8_113 用时 <5,500 s），Quartz/QUESO 固定 7,200 s/电路。
- 开源编译框架是什么。修改了什么。
  - PhasePoly 本体为全新自研（https://github.com/ruadapt/PhasePoly），非对既有编译框架的修改；它消费/对比的开源生态：Quartz（https://github.com/quantum-compiler/quartz，PLDI'22 自动生成等价电路类 ECC + 成本搜索重写）、QUESO（https://github.com/qqq-wisc/queso，已并入 qqq-wisc/guoq，PLDI'23，用 phase polynomial identity filter 增强 ECC 生成）、Qiskit（SABRE 路由、unitary 对比）、MQT QCEC（https://github.com/cda-tum/qcec，形式化等价验证）、GridSynth（Ross-Selinger z-rotation→Clifford+T 合成，Qiskit gridsynth_rz / Quantinuum grid_synthesis 实现）。修改了什么：PhasePoly 自身新增耦合 parity 矩阵联合优化、cross-block IR、SSA rotation merging、rank check、incremental merging；对 Quartz/QUESO 仅作为外部 baseline/组合对象按推荐设置运行（3-qubit/6-gate 子电路、2 小时/电路），未修改其本体。

  - 开源：PhasePoly 开源（https://github.com/ruadapt/PhasePoly，v1.0.0 2025-06-28，Python ≥3.10，依赖 qiskit==1.1.1、mqt-core==3.2.1、mqt.qcec==3.2.0、networkx、sympy、depq、numpy），输入/输出 OpenQASM 2.0，内置 Qiskit+MQT-QCEC 等价性检查器；提供 6 种合成方法：row_heap（默认，A* Phase Polynomial Co-Optimization）、row_heap_classical_GE、single_block_greedy / single_block_greedy_classical_GE（单 block 贪心 baseline）、pure_rotation_merging / rotation_merging（仅 SSA rotation merging，无 CNOT 合成）。Quartz/QUESO 均开源。
  - 编译框架输入到输出全过程（以论文 Fig.2 的 3-qubit 示例：5 CNOT + 3 T 门线路）：输入 = OpenQASM 2.0 线路 → ① 预处理器：把 X gate 经 Clifford 共轭前推、消相邻 H 对、处理被 H 夹住的 CNOT（两线都夹则消 4 个 H 并交换 control/target，仅一线夹则共轭该线并在另一线插 2 个 H），使 H 成为唯一 block barrier（预处理与 rotation merging 交错两轮）；② block 划分：按 H barrier 把线路切成最大 {CNOT,Rz} 子电路（phase polynomial block）；③ 对每 block 建耦合 parity 矩阵 [phase-parity | output-parity]——phase 每列为一个 parity 向量（如 (110)ᵀ 表 q0⊕q1），output 矩阵转置后每列为一个 output parity；④ SSA rotation merging：每个输入 qubit 态与每个 H 后状态分配 fresh SSA ID，每个 Rz 打上所在 qubit 态的 SSA ID 标签，同 SSA ID 的 Rz 全局合并（可跨 block）；⑤ cross-block IR：沿 block DAG 前向遍历评估相邻 block 合并（仅当共享多比特交互），post-H 行 inactive，用 CNOT 行操作逐步把 phase 列降到 Hamming weight 1 后发射 Rz 并删列，同时用 rank(M∪{v})=rank(M) 检验 pre-H 行可消除性（需该行 phase 全零 + 行/列隔离），求解 Mα=v 得 witness set、用 CNOT 完成行/列隔离后删行、插 H、激活 post-H 行；⑥ A* 搜索：active row pair（能降低 active column set 中某列 Hamming weight 的行对）扩展，f(n)=g(n)+h1(n)+h2(n)（已用 CNOT 数 + phase 矩阵总 Hamming weight + output 矩阵高斯消元估计），space-bounded priority queue + 多解池 k，tie-break 按 [f,h1,h2,−g] 字典序；⑦ 剩余 output-parity 矩阵用高斯消元合成；⑧ 输出优化后 OpenQASM 2.0（示例结果 4 CNOT + 1 T）。作用：把"单 block、phase-only"的局部优化扩展为跨 block 全局 CNOT/Rz 联合优化，直接压缩通用线路中占比 75%+ 的 {CNOT,Rz} 区域，平均总门减 34.70%、CNOT 减 26.83%，且大电路下不退化。

## Lotus A Multi-FPGA Task Dataflow Architecture to Accelerate Cycle-Level Simulation

- 属于编译框架的实现是什么？实验比较什么？
  Lotus 编译器：一个 C++ 嵌入式领域专用语言（DSL）用于编写同步数据流图 + 一系列编译器 passes，把高层数据流图编译为高效 Lotus 程序（task unit 配置数据 + 每 tile 可执行代码），并包含一个 multicore CPU 后端（RepCut 风格划分）。此外论文修改了 Verilator（开源 RTL 仿真器）使其从 Verilog 直接生成 Lotus 程序。实验比较：Lotus DSL benchmark（NTT/MatMult/Cores/Multicore，手写 DSL）vs Verilog benchmark（Vl-NTT/Vl-Chronos，改版 Verilator 生成）在 Lotus 上的性能差异；以及 CPU 后端（DSL 程序）vs 并行 Verilator（Verilog 程序）在 CPU 上的性能。结果：DSL 版本比 Verilog 版本快得多——NTT vs Vl-NTT 在 Lotus 上差 21×、在 CPU 上差 114×，尽管 Vl-NTT 指令只多 2.4×；原因是 Verilator 对每个复制单元生成独立代码导致指令复用差（icache 压力大）、并行度瓶颈与负载不均衡（Lotus 核仅约 10% 周期提交指令）。这证明 DSL 编译路径（支持任务间代码复用、精细任务粒度）对扩展到数千核至关重要。
- 硬件平台是什么，配置是什么。
  Lotus 目标平台：8 块 AMD Alveo U55C FPGA（每块 68 tile、272 个 4 核 tile、400 MHz、HBM2 16GB、25×25 蝶形 token 交换机），两台服务器（各 4 FPGA + 2×64核 AMD Zen 3 EPYC 7763 @2.45GHz + 1TB 内存），QSFP28 光链路 1:4 breakout 全互联（dancehall），350GB/s 对分带宽，200ns FPGA 间延迟。CPU 后端在 128 线程 Zen 3 服务器上评估（并行 Verilator 与 CPU 后端均扫线程数取最优）。
- 开源编译框架是什么。修改了什么。
  Lotus 编译器是论文原创实现（非基于开源编译框架，使用 PaToH [10] 超图划分库 https://www.cc.gatech.edu/~umit/software.html）。修改了 Verilator（https://www.veripool.org/verilator/，开源 RTL 仿真器）以产生 Lotus 程序：从 Verilog 提取数据流图后应用与 Lotus 编译器相同的 passes。编译器关键设计：①Mapping——PaToH 分层超图划分（先分 FPGA 再分 tile，平衡负载并最小化跨芯片通信），限制：same-cycle 边通信的任务必须同 FPGA（避免高跨芯片延迟上关键路径）、经内存通信的任务必须同 tile（无跨 tile 一致性）；②Communication——数据流 token vs 内存通信的选择，大而部分访问的值放内存，超限输入走 overflow memory，不折叠常量/指针而作为参数传递以复用代码（减小 icache 压力）；③Order Edges——为数据/结构依赖添加无数据 token 边（如单缓冲内存的 B@N 先于 A@N+1）；④Coarsening and Temporal Unrolling——合并短任务成更大任务、时间展开复制图（2×/4×）以支持更高延迟跨周期边，提升计算/通信比最多 3×（NTT 3.0×、MatMult 3.4× 加速）。

  论文声明开源：http://lotus.csail.mit.edu（web search 未能确认公开仓库，可关注 MIT CSAIL Sanchez 组页面；当前未能确认链接可用性）。使用例子（论文 Fig.9/Fig.1b，两级流水线 y[n]=a·x[n-1]+b·y[n-1]）：①编写任务函数，参数用 In/Out/InOut/PartialIn/PartialOut/PartialInOut<T> 标注（Partial 提示编译器把大而部分访问的值放内存），如 mult(int v0,int v1) 与 add(int v0,int v1)；②在 genDfg() 中定义数据流图：Reg<int>（跨周期边，带初值）、Wire<int>（同周期边）、task(fn, edge0, ...) 创建任务节点，可加 Feeder/Checker 测试任务；③编译器执行图定义代码，经 C++ 库发出图的文本表示（复用 C++ 编译器做类型检查）；④passes 依次处理：分层映射到 8 FPGA/544 tiles → 决定 token/内存通信 → 插入 order edges → coarsening（把 mult+add 合并）与 temporal unrolling（展开使跨周期边可更高延迟，若增加指令数则停止）→ 输出 task unit 配置（每任务 taskId、函数指针、输出 token 目的地、输入存储分配）+ 每 tile 可执行文件；⑤加载到 FPGA，每个模拟周期按数据流图驱动执行。作用：把高层数据流图自动化映射到 2176 个核上高效执行，最小化跨芯片通信（Hier 映射比随机快 3.3×–10.3×）、平衡负载、避免通信延迟落上关键路径，使软件仿真达到 emulator 级性能。

## M100: An Orchestrated Dataflow Architecture Powering General AI Computing

- 属于编译框架的实现是什么？实验比较什么？
  - M100 AI compiler toolchain（与硬件 co-design 的自研编译器栈）：① space-time scheduler —— 把 NN 子图映射到 M100 NPU 硬件；必要时把大 tensor 沿多轴维度分解成 mini-tensor，按时间调度的阶段流经空间分配的 TPB 流水线（Fig.14：子图 4 个算子 OP1~OP4 分给 4 个 TPB，输入 tensor 维度分解后按时相流动）；② graph compiler —— 图优化（tensor fusion、死代码消除、代数化简、layout 变换）+ 动态 tensor 的动态内存分配；③ backend compiler —— C 扩展编译器，生成利用 M100 硬件能力的 intrinsic 指令（tensor 计算、数据搬运、同步）。运行时侧：NPU 固件（RISC-V 上）基于工具链生成的二进制用 JIT 编译动态生成优化 TPB 指令，实时计算 tensor shape 与存储地址，并把 TPB 指令下发给任务分配的 TPB 组；AI inference runtime 与 NPU driver 运行在 ARM Cortex-A78 上。
  - 实验比较：论文不独立比较编译器版本，而是通过端到端在 M100 实机上跑 UniAD / LLaMA2-7B / MindVLA 与 NVIDIA Thor-U 对比（结果见实验_硬件架构 条目），验证"编译器编排 dataflow"（松散有序指令流 + 数据就绪驱动执行）带来的高并行度、低同步开销与高硬件利用率；TCO 与可扩展性亦为主要动机。
  - 硬件平台：M100 SoC/NPU（TSMC N5A，14 TPB cluster；UniAD 用 8 cluster、LLM 用 12 cluster）vs NVIDIA Thor-U（TSMC N4），同功率预算。
  - 框架与修改：全部为自研新增（非修改开源框架）——M100 编译器工具链 + AI inference runtime（输入准备/模型加载/任务踢发/结果后处理/FuSa 错误监控）+ NPU driver（硬件抽象层）+ NPU firmware（RISC-V JIT）。编译产物为 TPB 指令流（数千 bit/条，含 tensor shape 与通信需求元数据），经 ICB 广播。
  - 开源情况：未开源，论文未给出仓库/链接；无法确认任何公开实现。
  - 使用例子（基于论文描述，编译器输入→输出全过程）：输入 = 训练好的 NN 图（如 UniAD 某子图）→ space-time scheduler 把子图空间映射到 4 个 TPB，输入 tensor 按多维分解成 mini-tensor 并沿时间阶段流动 → graph compiler 做算子融合/死代码消除/代数化简/layout 变换并为动态 tensor 分配内存 → backend compiler（C 扩展）为每个 tensor 算子生成 intrinsic 指令（含 tensor 计算、数据搬运、同步操作，附 shape/通信需求等元数据）→ NPU 固件 JIT 依据二进制动态生成最终 TPB 指令、解析 tensor shape 与地址 → 固件经 ICB（64 bits/cycle，destination mask 广播）下发给任务分配的 TPB 组 → TPB 指令队列在数据就绪与同步条件满足时派发（同功能单元保序、跨单元可乱序）。作用：让编译器承担传统 dataflow 架构的编排复杂度，使硬件保持简单（无 cache 一致性、无 register file、无全局执行顺序），同时保留数据流并行的高效率与对新模型的可适配性。

## MTIA 300: Meta's First Training Chip Featuring Built-in NICs and Collective Offloading Engines

- 属于编译框架的实现是什么？实验比较什么？
  - 属于编译框架的实现：MTIA 编译器（自研、作为自定义 PyTorch backend）+ HCCL 集体通信编译/运行时（ISCA 2026）。关键点：(1) **单图编译 compute+collective**——collectives 经 torch.export/torch.compile 与 compute 算子编译进同一个 monolithic 图，降低子图启动开销、提升效率与确定性，compute/communication 依赖用 semaphore 管理；静态 shape collective 完全支持，动态 shape 与 device-resident AllToAll（动态 send/recv counts）进行中；(2) **图捕获与反向**——TorchDynamo 抓前向图、AOTAutograd 生成反向图，应用 MTIA 优化算子分解；(3) **融合**——手写 pattern-based fusion + TorchInductor 编译器驱动 fusion；(4) **训练内存优化**——图调度器用启发式（如整数线性规划）降低每迭代峰值内存压力，activation rematerialization 支撑更大有效 batch、提升 HBM 利用；(5) **kernel 生成**——TorchInductor Triton 代码生成 + C++/Triton kernel 编写 + 编码 agent 自动化 kernel 生成（[13][21]）；(6) **HCCL 编译**——用户调 HCCL 通信 API（PyTorch Distributed/torchcomms 接口 → contiguous buffer + communicator）后，库先验（a priori）按 outstanding work、系统拓扑、通信类型等选算法与通道，翻译为 work packets → subgraphs → WQEs（SEND/RECV/WRITE/WAIT/SET/REDUCE）供 ME 设备端执行，多级并行：stream 内保序、subgraph 逻辑并行（硬件可用性排队）、WQE 顺序发出但仅按流控字段阻塞。
  - 实验比较什么：编译器本身不独立对比版本，而是通过端到端验证：(a) 同一 DLRM 模型（TorchRec + TorchInductor 全图编译，均达最优配置）在 MTIA 300 与 H100 上的对比——通信 3.9×、Perf/TCO 1.42×（Table IV）；(b) LLM 推理（DeepSeek-R1、InferenceMax benchmark、vLLM runtime、8 卡、TP8-TP8/DP8-EP8）对比 H200——高并发下优于 H200；(c) 重叠微基准（1000 次 TF32 4K×4K×4K GEMM + collectives、16 加速器）验证"单图 + semaphore + ME 卸载"下计算/通信并发双 ~100% 效率（vs H100 因 SM 争用退化）。
  - 硬件平台：MTIA 300（CPU-C RISC-V quad SMP 控制核 + 72 PE + 16 ME + NMC）与 H100/H200；软件栈 PyTorch 最新 + TorchDynamo/TorchInductor/Triton、FSDP2/DTensor/TorchRec/XFormers、CUDA 兼容 runtime API、eager + graph 双模式。
  - 开源编译框架：非修改开源框架——MTIA 编译器是 Meta 自研 PyTorch backend；它消费开源生态：TorchDynamo（图捕获）、AOTAutograd（反向生成）、TorchInductor（Triton 代码生成与编译器驱动融合）、Triton、PyTorch Distributed/torchcomms、TorchRec。修改了什么：MTIA-2i 的 CPU-C 扩展为同时向 PE 网格与 ME 派发工作（工作包含 compute 和/或 communication 任务、按依赖派发、ME 完成后回报解阻塞）；HCCL 用 RDMA verbs 管理控制路径（ibv_create_qp/ibv_modify_qp 到 ready-to-send/receive、express doorbell 映射、ibv_get_async_event 捕获非 WC 错误），数据路径用 MTIA streaming interface 提交所有通信操作；因无硬件 QP caching，HCCL 需时连 QP、设计算法最小化闲置 QP、communicator 内复用 QP（12 NIC × 1088 = 13056 QP 可切分/共享于 scale-up/scale-out 域）。
  - 开源情况：MTIA 编译器/HCCL 未开源（Meta 专有，论文未给链接；HCCL 配套论文 arXiv:2608.00358 亦无代码）；依赖的开源生态（PyTorch、TorchInductor、TorchRec、Triton、vLLM、torchcomms、InferenceMax）均公开。

## O3LS: Optimizing Lattice Surgery via Automatic Layout Searching and Loose Scheduling

- 属于编译框架的实现是什么？实验比较什么？
  O3LS 是一个面向容错量子计算（FTQC）的 lattice surgery 编译器框架（ISCA 2026，HKUST-GZ / NUDT），包含四个模块：Module 1 自动逻辑量子比特数据布局设计——基于评分函数 S(B)=C(B)×(N_x(B)+N_z(B)−α_e·N_e(B)) 的迭代贪心布局搜索（每次把最高分候选位置作为新数据 patch，之后做单步移动后处理），复杂度 O(n|B|)；Module 2 Y 算子合成算法——把 Pauli-Y 分解为 X/Z 旋转组合并挖掘 Pauli 算子抵消机会（Algorithm 1，Y-decompose + Pauli operator synthesis），配合 O3LS-IR/PDAG（Pauli 有向无环图，记录旋转角、Pauli word、前驱/后继节点）表达依赖与并行性，复杂度 O(nl)；Module 3 松散调度（Loose Scheduling）——动态重指派 patch 功能、用 Dijkstra 确定最小 bus patch 路由、奖励函数驱动选择 patch 操作，复杂度 O(n²)；Module 4 边感知初始映射（Edge-aware EA mapping）——用 PDAG 估计每个 qubit 的旋转需求，旋转需求高的 qubit 优先映射到同时邻接 ancilla X/Z 边缘的 patch，复杂度 O(n log n)。实验比较：与 SPC（Litinski "A Game of Surface Codes" [34] 的实现 [32][52]）、LAPBC（locality-aware Pauli-based computation [25]）、SPARO（自动数据布局设计 [28]）对比时间步数、空间开销（tile 数/ancilla patch 长度）与逻辑错误率（LER）。结果：相对 SPC 在 compact/standard 布局上时间步平均减少 36.07%/24.76%；相对 LAPBC 时间步平均减少 35.10%（最大 80.6%）、LER 平均减少 38.8%（最大 82.3%）；空间开销相对 standard/sparse 布局减少 28.0%/46.7% 而不增加时间步；与 SPARO 布局设计对比：O3LS 生成的布局配 SPARO 调度 LER 平均改善 3.05%（ancilla 路由空间降 17.35%），完整 O3LS 栈再降时间步 78.24%、路由空间 27.17%、LER 77.1%；最优性分析显示 O3LS 与暴力枚举最优解平均 gap 仅 4.20%。
- 硬件平台是什么，配置是什么。
  目标"硬件"为二维表面码晶格（surface code lattice）的 patch/board 抽象：每个 patch 是 distance-d 表面码（用 d² 个物理数据量子比特编码一个逻辑量子比特），放置在 tile 网格（board）上，测量/旋转/移动等 patch 操作有固定时间成本（初始化 0、deformation 0~1、rotation 3、measurement 1 时间步）。对比的固定布局：compact [34]、sparse [25]、standard [25]；O3LS 自动生成 squeezed 布局；board 尺寸 N×M 从 5 到 12 扫描。仿真设备：Intel Core i9-14900K 32 核处理器 + 188 GB RAM，Python 3.10。原子 lattice surgery 操作在 d=9 表面码、电路级去极化噪声模型（物理错误率 p=10⁻³）下表征；magic state factory 采用 15-to-1 蒸馏协议 [8]，置于布局外并通过至少一条路由路径连接数据区；π/4 与 π/8 Pauli-product measurement 用标准 gate teleportation 协议 [34]。
- 开源编译框架是什么。修改了什么。
  O3LS 是论文原创实现（非修改开源编译框架），本身是新的编译框架。它消费开源生态：GridSynth（qiskit-gridsynth-plugin [13]，Clifford+T 门合成，误差容限 10⁻⁵）、STIM [18]（稳定器电路仿真，原子操作表征）、PyMatching 2 [24]（解码）、MQT Bench [41] 与 FTCircuitBench [21]（benchmark QASM 来源）。修改了什么：论文未明确说明对开源库的具体修改；O3LS 自身为全新实现——自动布局搜索、Y-synthesis、松散调度、EA 初始映射四模块 + O3LS-IR/PDAG 中间表示，替换 SPC/LAPBC 的固定布局映射与静态调度 pass。

  开源情况：论文未声明开源、未给出仓库链接，联网搜索（2026-08）未能确认公开实现，无法确认。使用例子（基于论文 Fig.5 pipeline，输入到输出全过程）：输入 = 高层量子算法（Hamiltonian simulation、QFT、Shor 的 adder/multiplier 组件、SWAP test 等，QASM 来自 MQT Bench [41] / FTCircuitBench [21]；除名称注明外默认一维 Hamiltonian）→ ①Clifford+T 分解（GridSynth，Solovay-Kitaev/优化合成，误差容限 10⁻⁵）→ ②转译为 Pauli product rotations（P_θ=exp(−iPθ)，H=Z_{π/4}X_{π/4}Z_{π/4}、CNOT=(Z⊗X)_{π/4}(I⊗X)_{−π/4}(Z⊗I)_{−π/4}，按 Pauli 交换/反交换规则化简，Clifford 门吸收进最终测量）→ ③O3LS 编译：Module 1 自动布局搜索（board 角上放 ancilla patch A，迭代按评分函数 S(B) 选最高分位置放置数据 patch，之后单步移动后处理，直到全部 qubit 放置完成，生成 squeezed 布局）→ Module 2 Y-synthesis（对含偶数个 Y 的 Pauli 算子按奇数 Y 分组做左/右 Z 旋转分解，选可被前驱/后继算子吸收的分组，构建 O3LS-IR/PDAG 表达依赖与并行执行机会）→ Module 4 边感知初始映射（按 PDAG 中旋转需求把 qubit 排序，高旋转需求 qubit 映射到 X/Z 双边缘 patch）→ Module 3 松散调度（按 PDAG frontier 执行：可执行算子用 Dijkstra 求最短 bus patch 路径后执行 PPM；不可执行算子遍历候选 patch 操作 O_B，选奖励函数 r(o_b,P_i) 最高者——操作后使 P_i 可执行的 patch 数最大、不破坏连通、同奖励取低时间开销）→ 输出 = 可执行 lattice surgery 指令序列（时间步序列 + 每时间片 patch 布局 + ancilla 路由路径）。作用：同时优化空间（squeezed 布局减少 28.0%~46.7% tile 数）与时间（时间步减少 24.76%~36.07%）开销，缩短 ancilla patch 距离，从而把 LER 压到最低（相对 SPC 降 ~44%，相对 LAPBC 最高 93.95%）。

## Photonic Quantum Computing on Spin Memory Architecture with Tree-Encoded Fusion

- 属于编译框架的实现是什么？实验比较什么？
  - MemTree 编译框架：把量子程序的目标图态（graph state）从一组原始 caterpillar 态分层生成，核心三个算法：(1) 目标图态划分——用混合整数规划（MIP，Gurobi 求解器）把程序图态 g_prog 划分为最小融合次数的线性子图集合 G^l={g^l}：每条 CZ 边定义二元变量 x_e∈{0,1}（1=保留在子图、0=切断用于融合），约束每个顶点度 deg(v)≤2 保证子图线性，目标函数 K=|E|-Σx_e 最小化总切割边数（=总融合数），后处理切断环边并按硬件最大 caterpillar 长度（30 qubit）细分；(2) 平衡二叉树（BBT）构建——从根 G^l 递归二分 G^l_i 为 G^l_j、G^l_k，第二个 MIP 模型（变量 y_g^l∈{0,1} 表示子图分到左/右子树，约束 |G^l_j|,|G^l_k|≥2^⌊log2|G^l_i|⌋ 保持平衡，目标 L=Σ|y_{g1}-y_{g2}| 最小化跨分组切割边数）最小化临界路径（leaf→root 最大融合数）开销；(3) 生成流水线——类似 OneAdapt 时间模型，光子源迭代生成 caterpillar 态，每时间步 BBT 一层各子图并行融合合并为父图，融合失败/擦除时兄弟子图延迟到下一时间步，最大化限定时间周期内成功执行的 shots。编译输出：BBT 各层切割边数 = 每时间步需执行的融合操作数。
  - 实验比较：与 SOTA MBQC 编译器 OneAdapt（all-photonic 架构，MICRO'25）及论文自改进的 OneAdapt-ET（在 OneAdapt 的 RSL 规范化路径外选相邻自由 qubit 做 X 测量 + 对其余相邻 qubit 做 Z 测量 = 间接 Z 测量，处理融合擦除，Fig.7）对比。Fair setting：OneAdapt/OneAdapt-ET 时间类边长度限制 D_f=30 虚拟层（遵循 [74] 评估设置）、RSL 尺寸 14n×14n（按 OneAdapt 源码）、PsiQuantum 125 MHz 源泵浦、每虚拟层 PL=4 物理资源层、time-like 边最大 960 ns；对应 MemTree 最大延迟 32 发射层（caterpillar 每层 30 ns）。结果（p_eras 0%~5%，36/64/100 qubit）：执行时间指数级改善，reduction rates 1.5×10^-2、1.1×10^-2、3.8×10^-2、5.6×10^-3、1.1×10^-2、8.8×10^-3（VQE/QAOA/Grover/RCA/QSIM/QFT）；光子源平均 0.18×；编译时间平均 0.14×；与 RLGS（emitter-based，ISCA'25）比 fidelity：F_de 与 F_CZ/F_fus 均提升（QFT/QAOA 指数级）。两个 MIP 模型复杂度 O(|E|) 与 O(|G^l_i|) 二元变量数。
- 硬件平台是什么，配置是什么。
  - 编译在经典 CPU 上运行（论文未明确给出编译机规格；OneAdapt 对比 artifact 环境为 Intel CPU 服务器、128 GB RAM、Python 3.10）；目标硬件为 spin memory PQC 架构（InGaAs QD 发射器 + 线性光学融合硬件，配置见实验_硬件架构条目）；真实硬件验证在 Quandela 云端平台。

## PipeComm Maximizing Link Utilization through Pipeline-Aware Collective Communication Synthesis

- 属于编译框架的实现是什么？实验比较什么？
  - PipeComm 是一个 pipeline-aware 的 collective communication 综合/合成框架（ISCA 2026，北京大学 PKU-Liang 组）：把高层通信逻辑规格（可编程 primitive：broadcast from / reduce at / tile / pipeline / interleave / reverse / constraint / extend）作为输入，自动合成针对具体物理网络拓扑的集体通信算法（spanning tree 通信 pattern + Modulo-II 流水线调度）。核心是一个两阶段合成流程：阶段一 Communication Pattern Construction（用 MILP 或增量策略构造避免跨迭代拥塞的广播/归约 spanning tree pattern 集合，受 II 约束）；阶段二 Pipeline Schedule Generation（用基于 Modulo-II Reservation Table 的堆式启发式调度器，Algorithm 1，为每条数据传输分配无冲突的执行时隙，最小化 pipeline depth）。支持 AllReduce（含 reduce/broadcast 相位重叠）、AllGather、AlltoAll。相比 baseline，PipeComm 显式建模 pipeline 行为（软件流水线思想应用于通信，II=相邻两次迭代启动间隔），通过重叠多个数据 chunk 最大化链路利用率。实验比较：①AllReduce 带宽/链路利用率 vs 启发式 baseline（TACOS [MICRO'24]、Themis [ISCA'22]、BlueConnect、MultiTree）与 solver-based baseline（TACCL [NSDI'23]、TE-CCL [SIGCOMM'24]），以及端到端训练 vs TACOS 与手调 TTO [HPCA'24]；②AllGather vs TACOS、AlltoAll vs TACCL/TE-CCL；③可扩展性分析；④真实 GPU 平台 vs NCCL v2.20.3 与 TACOS。主要结果：Pipe-Sol（MILP）比 SOTA 方法快 1.39×+；vs BlueConnect 1.98×、vs MultiTree 2.23×（Pipe-Sol）/2.08×（Pipe-Ict）；vs TACCL 小消息 1.49×/1.12×、大消息 2.43×/2.36×；vs TE-CCL 大消息 1.50×；端到端训练 vs TACOS 1.43×、vs TTO 1.12×；AllGather vs TACOS 1.26×（Pipe-Ict）/1.22×（Pipe-Sol）；真实 16-GPU 上 Pipe-Sol 平均 1.24× over NCCL、1.18× over partitioned TACOS。
- 硬件平台是什么，配置是什么。
  - 仿真层：ASTRA-sim 2.0（congestion-aware analytical backend，链路粒度建模 send/receive、FCFS）上评估，拓扑与参数如下（默认 α=200ns、1/β=50GB/s）：①同构：3D Hypercube 5×5×5（α=0.2µs、50GB/s）、2D Mesh 8×8（α=0.2µs、50GB/s）；②vs MultiTree 对比采用其论文参数 α=150ns、1/β=16GB/s，拓扑 2D Mesh 8×8 与 2D Torus 8×8；③异构：2D Mesh 8×8（Dim-1 0.2µs/50GB/s，Dim-2 0.15µs/100GB/s）与 2D Switch 8×8（Dim-1 0.2µs/50GB/s，Dim-2 0.05µs/200GB/s），switch 拓扑用 TACOS 的 unfolding 方法展开为固定点对点连接；AllReduce 数据量 4MB~16GB 扫描。端到端训练：8×8 2D mesh（64-NPU）上跑 ResNet-50/RegNet（数据并行）与 LLaMa2-7B/Qwen2.5-7B（张量并行）。真实硬件：两节点、每节点 8 块 NVIDIA L20 GPU 经 PCIe switch 互联，节点间 InfiniBand+RDMA，形成分层异构带宽（节点内高带宽 PCIe、节点间低带宽 IB）；消息 2MB~2GB，对比 NCCL v2.20.3。MILP 求解器：Gurobi（Pipe-Sol，1 小时超时返回当前最优）；Pipe-Ict 增量策略每步 20 次尝试。

## QiMeng-Tensify Scaling up Tensor Computation Optimization via Architecture-Aware LLM-Guided MCTS

- 属于编译框架的实现是什么？实验比较什么？
  - QiMeng-Tensify（中科院计算所/中国科大，ISCA 2026）是一个图级（graph-level）张量计算自动优化编译框架：把张量计算图的调度问题形式化为 MDP P=(S,A,T,M,R)——状态 S(G,n) = 计算图 + 调度节点（按逆拓扑序规范化处理），动作 A(r,p) = 调度规则 + 参数配置（7 条规则：A1 MultiLevelTiling(tiling factors)、A2 AutoInline、A3 ParallelizeVectorizeUnroll(loop,unroll length)、A4 CrossThreadReduction(split factors)、A5 ComputeAtLocation(compute locations)、A6 AutoBind、A7 InlineConstantScalar），通过无约束图变换扩大变换空间；用 architecture-aware LLM-guided MCTS 求解（LLM 生成 7 规则上的先验概率分布引导 Selection/Expansion，Gumbel 噪声保持探索，Simulation 阶段用 XGBoost 成本模型 + guided local search 做细粒度参数规格，真机执行奖励 R=flops(p*)/t_best 回传），并引入离线 Architecture-aware Prior Adaptation（用 7 个代表子图收集 12,500 次性能测量，蒸馏自然语言启发式自进化 prompt + 离线训练 XGBoost cost model）。实现：~16,000 行 Python + ~1,500 行 C++ 低层调度原语；LLM 用 gpt-5-preview (2025-07-01) via OpenAI API（temperature 0.8、8192 token、失败回退随机游走）；数值验证：候选 kernel 与高精度 Golden Reference 对比，超阈值 ϵ 或 NaN 给零奖励。
  - 实验比较（两层）：①Subgraph 级 9 个子图（LoRA-LLaMA3-lora、GatedMLP-Falcon-7B、GQA-LLaMA3-70B、QKNorm-Chameleon-7B、nTrans-nGPT-1B、RMSNorm-LLaMA2-7B、LayerNorm、SelfAtten、NSA）vs PyTorch v2.7.0、TensorRT v10.8.0.43、TVM(MetaSchedule) commit 567eeed3、Triton v3.2.0、FlashAttention v2.7.3、Welder commit af53ab1、Mirage v0.2.4、Reasoning Compiler commit 1390945；FP32(CUDA core) 与 FP16(TensorCore) 两种精度。结果：FP16 上平均加速 PyTorch 6.49×、TensorRT 2.86×、TVM 1.68×、Triton 2.64×、FlashAttention 1.27×、Welder 13.49×、Mirage 1.29×、Reasoning Compiler 1.31×；FP32 上 vs PyTorch 3.23×、vs MetaSchedule 2.05×。②Network 级 4 个 LLM（Chameleon-7B、LLaMA3-8B、GPT-3-7B-LoRA、nGPT-1B），batch 1/8、seq len 4096，vs PyTorch、TensorRT-LLM v1.1.0、Mirage；A100 平均 1.56×/1.22×/1.30×，H100 平均 1.78×/1.29×/1.30×。另做：prompt 进化/离线 cost model 消融（4 组合）、LLM prior 消融（MCTS vs MLP/RandomForest priors vs DeepSeek-V3.2/Qwen3-max/GPT 5.0，LLM prior 高 20%-30%）、可移植性分析（L0 软件版本 CUDA 11.8→12.4 差距 0.7%、L1 A100→A30 同代 SKU 差距 1.3%、L2 A100→H100 跨代差距 7.7%）。

## SATIC: An Optimizing Ising Compiler for SAT(isfiability)

- 属于编译框架的实现是什么？实验比较什么？
  - SATIC/SATIC++：面向 Ising 机器的 SAT 优化编译器，把 CNF 格式 SAT 问题映射到 Ising 硬件。核心流程（Algorithm 1 / Fig.3）：输入 CNF → 构建加权 Variable Interaction Graph (VIG) → 随机选根节点 BFS 生成按距离排序的变量表 L → 在 CNF 层（QUBO 数学公式化之前）做子问题分解：从 L 底部逐个 freeze 未选变量（取全局解向量 S_global 的固定值）+ 单元传播（unit propagation）化简 CNF → 检查子问题公式化为 QUBO 后是否超过 Ising 机器 spin 容量 → 匹配容量则发到 Ising 硬件求解 → 回收局部解更新全局解向量 → CheckSolution 检查是否满足原 SAT，未满足则换根节点继续迭代直到解出或达 max.iter。关键创新是"先分解后公式化"（subproblem formation 在 CNF 层进行，此时尚无 ancillary 变量），按构造满足两个正确性条件：ancillary-awareness（每个 clause 的 ancillary 与问题变量同组）与 clause-completeness（被选变量的全部含该变量 clause 都必须进子问题）。SATIC++ 增加启发式技巧包：Limited Neighbors（加权 VIG 剪枝：MST + 逐节点按权重降序恢复至每节点邻居上限 N）、Neighbor Shuffling（BFS 邻接表随机置换）、Negative Literal Inversion（NLI，负文字为主的变量极性反转再公式化、求解后还原）、Clause Based Formulation Mix（按 clause 宽度 k 混用 Chancellor's 与 ILP/Flat ILP 公式化）、Ancillary Estimation（按 k 查表估算 ancillary 数，避免重复公式化做 size check）、Bulk Freeze（按学习到的批量 B 一次性冻结变量）、Local Search（全局解向量按 T_LS 间隔随机重启）、Adaptive Spin Merging / Dynamic Upscaling（硬件 embedding：动态合并未用物理 spin 扩大系数范围、自适应系数缩放）。实验比较：SATIC（无启发式）vs SATIC++（全启发式），对照 Cilasun et al. [46] 的 SAT 分解器（其报告数据基于 49-spin 芯片）与 D-Wave EID（Energy Impact Decomposer，最新版 qbsolv）及变体 D-Wave EID++（论文修改版：每次迭代子问题形成前随机化 clause 级 ancillary 值）。指标：solved instances、successful repeats、iteration count（hardware 调用次数）、TTS（Time to Solution，95/100 repeats 置信）、端到端 runtime 分解（Software/Hardware Preparation/Hardware/PCIe/Preprocessing）。结果：Batch-4-100-1000（100 变量/1000 clause 4SAT）上基础 SATIC 解 67/100，逐 trick 叠加到 SATIC++ 全 100/100；受控实验（UF75，50K 迭代）违反 clause-completeness 0/100、违反 ancillary-awareness 44/100、SATIC 87/100、SATIC++ 100/100；Scalability 分析中 Batch-4-150-1570 全解（73.1× 硬件容量），Batch-4-175-1800 部分可解（保守上界）；unseen SATLIB UF 系列 UF20→UF175 全解（UF175 为 23× 容量），UF200/225/250 解 98/97/92；vs D-Wave EID（UF20 以上即失败），SATIC++ 平均 9.4 迭代解出 10 个基准实例（最接近 baseline 约 250 迭代）；端到端 runtime SATIC++ 69.3ms vs SATIC 1540.9ms vs D-Wave EID 18877.0ms（22.2×、272.4× 加速）。
- 硬件平台是什么，配置是什么。
  - 目标 Ising 机器测试床：45 个全互连（all-to-all）spin 的 CMOS Ising 芯片，每个 spin 对应一个室温 CMOS 环形振荡器（COBI 系列，见文献[20]），系数范围 [−14,+14]；45-spin all-to-all 等价于 1000+ spin 的受限邻居连接芯片。芯片装在带 FPGA 的板卡上，经 PCIe 与主机通信；服务器挂 8 张 Ising 卡（PCIe 多路复用），支持并发并行 repeats。主机：Intel Xeon Gold 6240R @2.40GHz，24 物理核/48 线程。SATIC/SATIC++ 用 Python 3.8 实现。另用 D-Wave Tabu 软件求解器（dwave-tabu）替换 Ising 芯片做硬件无关性验证：Tabu 无限系数范围但 20ms 最大退火时间、约 3.3J/iteration；Ising 芯片 200μs 最大退火时间、4.8μJ/iteration（约快 2 个数量级、能耗低约 5 个数量级）。

  - SATIC 是论文自研编译框架（非基于现成开源编译器修改），未声明开源，联网搜索未找到公开仓库。对照/基线的现成框架：D-Wave EID 取自开源 D-Wave Hybrid 包（dwave-hybrid，https://pypi.org/project/dwave-hybrid/0.6.12/，按官方文档 Energy Impact Decomposer 方法使用）；qbsolv（D-Wave 开源 decomposer，把大 QUBO 切为子 QUBO 用能量启发式迭代求解）。D-Wave EID++ 是论文对 D-Wave EID 的修改：每次迭代子问题形成前随机化 clause 特定 ancillary 值（诊断性启发式，不保证按构造 ancillary-aware）。SATIC 自身的新增内容：加权 VIG + Limited Neighbors 剪枝、CNF 层子问题形成（freeze + 单元传播）、按 k 混合 Chancellor's/ILP/Flat ILP 公式化 + NLI、Ancillary Estimation、Bulk Freeze、Local Search、Adaptive Spin Merging/Dynamic Upscaling。

## Transpiler-Architecture Co-Design to Curb Clifford Costs in Fault-Tolerant Quantum Computing

- 属于编译框架的实现是什么？实验比较什么？
  - 实现是 TACO（Transpiler–Architecture Co-design Optimization），一个集成到 NWQEC 的 FTQC 专用编译/转译框架，工作流四步：(1) FTQC 导向的动态电路变换（Section IV-C）——枚举最多 3 比特门的全部分解规则并逐门选择 FTQC 代价最低者（相比 NISQ 转译器把两个 4 比特 QPE 电路的中间 Rz 门数压到最优）；用 Clifford+T 等价替换简化平凡情形（如 Rz(π)→Pauli-Z）；合并连续单比特门；(2) Clifford+T 合成——对剩余单比特 Rz 旋转用 GridSynth（Ross-Selinger 数论算法）做最优 T-count 合成（默认误差 ε=10^-10），替代 Qiskit 默认的 Solovay-Kitaev；(3) 保持并行的 Clifford 门消除——把单比特门序列转成 Matsumoto-Amano (MA) Normal Form，再依次消除 Phase 门（利用恒等式 TS=T†Z，把 S 门全转成免费虚拟 Z 门）、Pauli 门（用 ZH=HX、ZT=TZ、XT=T†X 等交换律把 Pauli 门换到序列末尾合并）、Hadamard 门（引入硬件原生 Rx(π/4) 门，用恒等式 HT=Rx(π/4)H 把 H 换到末尾或与相邻 H 相消）；(4) Toffoli(CCX) 分解中的 Clifford 门局部相消——交换 C3/C4 后 8 个 Clifford 门按自逆对 (C2,C4)(C3,C5)(C7,C8)(C1,C6) 两两配对相消，只留 7 个非 Clifford 旋转。三步单比特优化均为 O(n)。
  - 实验比较：①与 Qiskit 2.2.3 转译器（Optimization Level 3，Solovay-Kitaev 合成）对比 Clifford+T 转译，指标为需合成的 unitary 数、T 门数、转译时间（Table VI：TACO 平均少 1.26× 需合成 unitary、490× 更少 T 门、352× 更快，QFT 从 34.73s 降到 0.041s、T 门从 2,623,881 降到 9,529）；②与 PBC（Pauli-Based Compilation）对比 Clifford 门减少率与电路深度/门并行（平均降 91.2%、最高 98.6%；18 比特 QFT 深度 6,598 vs PBC 39,055，浅 5.9×，保留 40,777 T 门中仅 1,080 个 Clifford）；③与 NISQ 转译器对比中间电路 Rz 门数（Qiskit 优化级别 0-3 × 三种基门集，TACO 在 QPE 上最优）；④对 Synthetiq 的 16 个合成电路（10-68 Clifford+T 门）与 TRASYN 的 41 个合成电路（28-26,215 门）做后处理，平均再消除 49.1%/78.7%（中位 41.0%/80.2%，最高 92.9%/95.5%）的 Clifford 门；⑤可扩展性：100-300 比特 QFT 的 Clifford 减少率稳定在约 95%。

## Unifying Qubit Routing Across Diverse Quantum ISAs via Canonical Representation

- 属于编译框架的实现是什么？实验比较什么？
  - CANOPUS（Canonical-Optimized Placement Utility Suite，HKUST/Tsinghua/Edinburgh 等，ISCA'26）是统一的、ISA-aware 的量子比特映射/路由（qubit mapping/routing）编译框架，适用于多样的量子 ISA。核心创新：①利用 2Q 门规范表示（canonical form，由 KAK 分解得到 Can(a,b,c) := e^{-iπ/2(aXX+bYY+cZZ)}，系数限制在 Weyl chamber）与 monodromy polytope 理论，对任意 ISA 精确建模 2Q 门合成成本（给定 basis 门集，可被 N 个 2Q 门实现的 2Q 门集合对应 Weyl chamber 内的一个多胞形）；②路由阶段做 routing-synthesis 深度协同优化——SWAP mirroring：把候选 SWAP 与同一物理 qubit 对上的前驱 2Q 门 U∈L（last mapped layer）合并为复合酉 U'=SWAP·U，SWAP 插入成本定义为边际合成成本增量 c_g = COST(SWAP·U) − COST(U)，通常低于独立 SWAP 成本甚至为负（CX 基下 SWAP·iSWAP ~ Can(1/2,0,0) 仅需 1 个 CX，c_g = −c_cx）；③通过规范形式形式化任意共享一个 qubit 的两个 2Q 门的交换关系（Theorem 1：Can(a,b,c) 与 Can(a',b',c') 可交换当且仅当 b=b'=c=c'=0，即两者均为纯 XX 旋转），做广义交换性优化（超越仅针对 CX 的交换优化）；④统一启发式 H = w_g·c_g + w_d·Δdepth + (ΔAvg{dist}_E + k_E·ΔAvg{dist}_E)·c_swap，同时最小化门数（Ccount）与深度（Cdepth），其中 Δdepth 通过 wire duration record D 跟踪每个物理 qubit 的累计时长（按 basis 门物理时长加权的关键路径）计算，ΔAvg{dist} 为候选 SWAP 引起的差分平均最短路径距离，乘 ISA 特定 SWAP 成本 c_swap。
  - 实验比较：与三个 baseline 对比——SABRE（工业标准、Python 版 QISKIT 实现）、TOQM（SOTA 深度驱动的 A* 路由）、BQSKIT（数值优化/暴力近似合成的 cross-ISA 编译范式）。6 种 ISA（CX、ZZPhase={ZZ(π/6),ZZ(π/4),ZZ(π/2)}、SQiSW={√iSWAP,iSWAP}、ZZPhase_=ZZPhase+镜像 pSWAP 族、SQiSW_=SQiSW+镜像{ECP,CX}、Het=ZZPhase+SQiSW 异构组合）× 3 种拓扑（1D chain、heavy-hex、2D square）× 12 个 benchmark = 216 个 case。指标：routing overhead = 路由后电路成本 / 路由前电路成本（Ccount=全部 2Q 门按一致成本表(式3)的成本和；Cdepth=成本加权关键路径长度；路由前逻辑级成本统一按 CX ISA 计算）。一致 basis 门成本设定：CX:1、ZZ(π/t):2/t、√iSWAP:0.75、iSWAP:1.5、ECP:1.25、pSWAP(π/t):2−1/t。结果：CANOPUS 在所有 ISA-topology 组合下 routing overhead 最低；相对 SABRE 平均降 16.06%（Ccount）/26.44%（Cdepth），相对 TOQM 降 34.70%/21.25%，相对 BQSKIT 降 19.89%/20.72%。换更强 ISA 收益放大（chain 上 CX 1.88× → ZZPhase_ 1.39×，−26%；square 上 1.38× → 0.99×，−28%），baseline 方法无此放大。两个 case study：QFT kernel 在 IBM ibm_marrakesh 真机执行（vs QISKIT 默认编译：CZ 门数降 52.9%、2Q 深度降 66.4%、CZ/CX 门集错误降 26.89%、ZZ(θ) 门集错误降 34.98%；1D chain 上 QFT 达到理论最优路由，超越 TOQM 与 Maslov 手工最优方案）；qLDPC stabilizer 电路端到端仿真（CX 与 CX-iSWAP 两种 ISA，stim+BP-OSD，CX 下逻辑错误率 square 降 49.4%/heavy-hex 降 11.4%，CX-iSWAP 下降 52.6%/29.3% vs SABRE）。消融实验：关闭交换性优化后平均 Ccount 恶化 2-11%、Cdepth 恶化 2-10%（个别 benchmark 达 37-48%，chain+CX 下最明显；knn、swap_test、算术电路收益最大，ising、wstate 收益可忽略）。敏感性分析：w_g/w_d 在 [0.35,0.65] 中心区域 overhead 变化 <3.5%，默认 0.5 距全局最优 2.5% 内。
- 硬件平台是什么，配置是什么。
  - 编译框架本身在标准 CPU 上运行（Python + Rust 混合实现，maturin 构建 Rust 加速扩展 canopus.utils._accel），无 GPU 要求。编译耗时：216 个 medium case 中 CANOPUS 为 SABRE 的 1-2×；可扩展性基准（QFT、QAOA MaxCut on random 3-regular graphs、CDKM ripple-carry adder，10-50 qubit，1D chain 与 2D square）上平均 T_CANOPUS/T_SABRE = 2-5×（square 2.3-3.4×、chain 2.6-4.8×），两者均为多项式扩展（log-log 线性）。对比：BQSKIT 216 个 case 平均每电路 18 分钟（Apple M3 Max CPU，Rust backend），Python SABRE 仅 17 秒。
  - 真机验证平台：IBM Quantum Platform 的 ibm_marrakesh QPU（Heron-R2，原生门集 {CZ, √X, Z(θ), ZZ(θ)}，heavy-hex 拓扑但含足够长的 1D chain 供 QFT n∈{6,8,10,12} 使用）。指标：Hellinger fidelity（实验 vs 理想输出分布），shots = MAX{4096, 2^n × 10}，每个电路追加一层 Hadamard 使理想终态为 |0>^⊗n。
  - qLDPC case study：模拟器 stim（https://github.com/quantumlib/Stim），BP-OSD decoder（https://github.com/quantumlib/ldpc 系 BP-OSD），电路级噪声模型同文献[6]（qLDPC 标准记忆实验）；qLDPC 码取自 [53][67] 的 generalized bicycle（GB）与 bivariate bicycle（BB）码。
- 开源编译框架是什么。修改了什么。
  - CANOPUS 是论文自研的新框架，构建在 SABRE 的骨架之上（继承 SABRE 的 DAG 分层、front layer F、extended set E、双向迭代 layout 等数据结构与流程），而非对现成开源编译器的简单修改。实现基于 qiskit、monodromy、pytket 三个开源库 + 自研工具；核心路由算法实现为原生 QISKIT TransformationPass（CanopusMapping 类），可无缝集成进 QISKIT transpilation pipeline。新增数据结构：last mapped layer L（最后映射层，用于 SWAP mirroring 判断）、wire duration record D（每个物理 qubit 的累计时长，用于深度开销）、commutative pairs C（L 内可交换规范门对），由 Algorithm 1（加 2Q 门时更新 L/D/C）与 Algorithm 2（加 SWAP 时按交换对更新 D）维护；所有计算基于条件控制与哈希结构，O(1) 时间；合成成本通过定位 canonical 坐标所在凸多胞形计算（线性时间），并缓存已算成本。
  - 相对 SABRE 的增强点：①把 SABRE 的绝对平均最短路径距离启发式替换为差分距离 ΔAvg{dist} × ISA 特定 c_swap；②取消 SABRE 需要的经验衰减因子（c_g 与 Δdepth 提供精确硬件感知反馈）；③超参数 k_E=0.5（同 SABRE）、w_g=w_d=0.5，w_d 额外乘以拓扑自适应因子 d̄/(2+d̄)（d̄ 为设备耦合图平均度，反映深度优化在更密拓扑上更重要）。扩展到新 ISA 只需配置步骤——指定目标 basis 门的单位成本，无需算法改动。
  - baseline 实现方式：SABRE 与 CANOPUS 均在 Python QISKIT 框架实现（刻意不用 Rust 加速版 SABRE 以保证公平运行时对比）；TOQM 为确定性方法（1 次运行取结果）；BQSKIT 编译结果含随机性，每个输入 3 次 trial 取最好。SABRE/CANOPUS 超参数一致：10 次 layout procedure，每次 8 轮双向 pass，每 pass 10 trial，取全部尝试中最优。

## æSIP μArch-aware ASIP-ISA Co-Design via Program Synthesis, Equality Saturation, and External Don't Cares

- 属于编译框架的实现是什么？实验比较什么？
  - 实现是 æSIP（ISCA 2026，University of Michigan）的硬件感知程序重写框架（编译优化层，工作流 Fig.4/Fig.6）：输入为自包含 RV32IM 汇编（库函数已手工 inline、伪指令已展开为 canonical 真实指令序列、无外部符号），输出多种语义等价但指令多样性更低、可直接汇编成可运行二进制（.s）的重写变体。四部分：(1) 重写规则发现——扩展 Greenthumb 超优化器框架（Fig.5）：RISC-V 验证引擎（程序状态 State=R×M，指令序列复合状态转移，Z3 SMT 证明 S_spec≡S_synth）＋四个搜索算法（继承 Greenthumb 的 symbolic/stochastic/enumerative 三算法 + 新增 LLM-guided 神经符号搜索，用 Claude Opus 4.5，以 RV32I 软件仿真库中 mul/div/rem 例程作 warm-start，反例喂回 LLM 形成 CEGIS 循环）；候选指令集排除原指令以强制合成替代序列、优先利用不同硬件单元的指令子集以便后续裁剪硬件。共得 51 条重写规则覆盖 26 条指令（Table II：I-type 8 条、Arithmetic 17 条、Branch 14 条、Mult/Div 8 条、Ld/St 4 条；如 or→xor(xor,and)、add→sub rs2 (sub x0 rs1)、mulh→Karatsuba/convolution 风格 mul 序列、lh→lw+slli+srai、blt→bge+jal）。传统三算法对 mulh/div 等 12 小时超时，LLM 搜索几轮内收敛。(2) 分治 equality saturation——用 egglog（egg）e-graph：按 CFG 把程序切成 basic block，每 block 局部饱和（pseudo-root e-class 锚定），orphan e-class（不参与本 block 主表达式树但被其他 block 消费的值）显式链回 block pseudo-root 防误判死代码；局部饱和子图并入单一全局 e-graph（global root），捕获全程序等价空间且避免整体饱和的组合爆炸。(3) ILP 全局提取——把提取建模为 Gurobi ILP（目标 λ·Σw_o·y_o + (1-λ)·Σc_e,n·x_e,n：第一项最小化 distinct 指令类型集合（硬件感知权重 w_o，乘/除法远大于 ALU），第二项最小化指令总数；约束：每激活 e-class 恰选一个 e-node、pseudo-root/orphan 强制激活、父子一致性、opcode 使能变量 y_o 绑定、Big-M 线性化的 level 无环约束）；各 block 共享全局 y_o 变量实现隐式块级并行，全局提取从小时级降到秒级。(4) 后处理——重建表达式图、后序遍历发射汇编，自动跟踪/继承 rd 寄存器，轻量线性扫描寄存器分配器处理重写引入的临时寄存器（live range 不重叠即复用、耗尽 spill 到栈）。λ 扫 27 值（细粒度靠近 λ=0 面积主导区）生成变体族，探索 area-latency 权衡（latency 用 spike 预估、RTL 仿真后精确化）。
  - 实验比较：baseline 是未重写的原程序（PDAG 类方法只 profiling、不改程序）与全局 monolithic equality saturation（受控 e-node/e-class 规模下 1 小时超时）。重写后 distinct instruction 数平均降 31.8%（最高 md5 46.4%，Fig.8）；重写使 ASIP 面积平均多降 17.0%（SKY130 无约束，Table III）；运行时 saturation 1.2-32.4s、extraction 0.3-78.4s（中位 21.9s，Fig.11）；消融（Fig.9）ISA-level only vs +µArch-aware 约束在保留复杂指令的 workload 上差距最大；可扩展性：Rocket 5-stage core 上重写+裁剪面积降 24.6% 无约束 / 13.0% 1.2× 约束（Fig.13）；code size（Fig.12）：32-bit 定长编码平均 2.27× 膨胀（mont64/basicmath 最大），但熵编码（Huffman，距下界 0.5% 内）下平均 0.60×、均匀编码 ⌈log2 N⌉ 开销很小；Turing completeness 保持（每条规则保留同功能类至少一条指令，不会清空某个功能类）。
