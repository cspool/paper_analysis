# 实验_硬件架构

## Accelerating MoE with Dynamic In-Switch

- 属于硬件架构的实现是什么？实验比较什么？
  - **实现**：DySHARP 在 GPU 和 Switch 两侧均引入硬件微架构修改以支持动态 in-switch computing：
    - **GPU 侧**：(1) **SM LSU 扩展**——新增 MultimemQ（32 entry），支持 dymultimem 指令的 target list 预取和请求包组装；(2) **Hub Hardware Memory Manager**——AL TLB（512 entry，CAM + SRAM，16-bank dual-port 1R1W）+ DRAM 中 AL Table（每 entry 4B: 1b Valid + 31b LIdx）；(3) **Token Tracker 硬件表**——TS Table（1024 entry，on-chip）、TID Table（DRAM）、OR Table（1024 entry，on-chip）。
    - **Switch 侧**：(1) **Route 模块增强**——target-aware 转发逻辑，按每个 target 计算输出端口，复制并裁剪请求包；(2) **Reduction Logic 增强**——追踪每个请求关联的 target 数量及归约完成（计数器递减至零后返回结果）。
    - **Packet 格式**：扩展 NVLink 数据链路层包格式，flit0 含 48-bit multimem 地址 + 1-bit stage + 15-bit target count，后续 target extension flit 编码 destination expert ID（16-bit each, 8 per flit）。
  - **实验比较**：硬件开销评估：所有组件 RTL 实现，Synopsys Design Compiler® 综合，TSMC 12nm 工艺。GPU 侧新增硬件仅 0.198mm²（约 H100 die 的 0.024%），Switch 侧控制逻辑 <0.01mm²（<0.1% NVSwitch die）。AL-TLB（512 entry）与 reduction buffer（64KB）命中率设计空间探索，确认 sweet spot。

- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - **模拟器**：**BookSim2**（开源，https://github.com/booksim/booksim2）——cycle-accurate 片上网络模拟器；**Accel-Sim**（开源，https://github.com/accel-sim/accel-sim）——GPU 模拟器。
  - **论文修改**：整合 BookSim2 + Accel-Sim 实现 cycle-accurate 多 GPU 模拟，Accel-Sim 扩展支持 Hopper 架构 FP8 kernel，BookSim2 模拟 switch-based NVLink/NVSwitch 网络。

- 模拟器模拟什么的性能，修改了什么。
  - **模拟性能**：模拟 MoE 训练/推理在 GH200 NVL32（及扩展 DGX-H100、64 GPU、多节点 IB）上的端到端性能。BookSim2 模拟 NVLink 4.0 双向带宽 900 GB/s、延迟 250ns、flit 16B、NVSwitch 端口 VC 和 buffer 行为。Accel-Sim 模拟 GPU SM 执行 GEMM/dymultimem 指令、token tracker 表操作和 megakernel scheduler。
  - **修改**：Accel-Sim 扩展 Hopper 基本特性 + FP8 kernel 支持；BookSim2 集成以支持 switch 多播/归约、动态包转发、完成检测；实现多 GPU 并发执行框架。

- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - **开源情况**：DySHARP 论文未明确说明其硬件 RTL 或修改版模拟器是否开源。BookSim2（GitHub）和 Accel-Sim（GitHub）开源。
  - **模拟原理**：
    1. **输入**：硬件配置参数（GPU 数量、NVLink 带宽/延迟/flit size、NVSwitch 端口数/VC depth/buffer size、AL TLB entry 数、TS/OR Table entry 数、MultimemQ entry 数）；模型配置（hidden size、MoE hidden size、attention heads、sequence length、expert 数量、topk）；token 分布参数；benchmark 选择（DeepSeek-V3 等）。
    2. **模拟过程**：Accel-Sim 以 cycle-accurate 方式模拟 GPU 内 SM 执行——GEMM kernel 按 FP8 精度以 tile 粒度在 SM 上调度，dymultimem 指令通过 LSU MultimemQ 发射请求包，Token Tracker 表更新 token 级状态，Scheduler 按 readiness-gated 方式调度 TB。同时 BookSim2 以 cycle-accurate 方式模拟 NVLink/NVSwitch 网络——flit 级传输、VC 分配/仲裁、switch 内多播复制和归约合并。两者通过统一时钟同步，GPU 间通信请求经 NVLink→NVSwitch→destination GPU 全路径建模。
    3. **输出**：cycle-accurate 执行时间分解（Dispatch/GEMM-1/GEMM-2/Combine 各阶段 cycles）、通信流量统计（每方向、每 GPU）、带宽利用率、硬件表命中率（AL TLB、reduction buffer）、端到端加速比。
    4. **硬件开销评估独立流程**：RTL 实现 GPU/Switch 新增组件 → Synopsys Design Compiler® 综合（TSMC 12nm library）→ SRAM macros 用 Memory Compiler 生成（16-bank dual-port 1R1W）→ 输出面积（mm²）、功耗、关键路径延迟（Switch 数据路径仅增加 1 cycle）。
