## 用户学习方向

> 单个GPU、NPU、加速器作后端，单请求模型推理（MoE、DiT、多模态、Video等较新模型）的负载场景下，如何进行多算子/微算子的并发，垂直梳理方法、实验框架/环境。侧重硬件体系结构、编译框架的方法、对应实现和实验环境。

## 该层覆盖范围

L4 Kernel 调度层覆盖：
- **算子实现**：MoE expert FFN kernel、DiT attention/convolution kernel、多模态 cross-attention/fusion kernel、Video spatial-temporal attention/3D conv kernel 的底层实现方法
- **Tile 切分**：tile size/shape 选择、block/tile mapping 到 SM/CU/NPU 核心、wavefront tiling、persistent kernel 中的 tile 调度
- **微算子并发**：单 kernel 内多个微算子（如 GEMM + activation + element-wise）的并发编排、多 kernel 间的 CUDA Stream/Graph 并发、异步拷贝与计算重叠
- **Memory Hierarchy**：register file 分配、shared memory/L1 cache 划分与 bank conflict 避免、L2 cache 驻留策略、global memory (HBM/GDDR) 合并访问、NPU 片上 buffer/TPU 的 VPU memory
- **指令流水线**：指令级并行（ILP）、warp/wavefront 调度、scoreboarding、software pipelining、dual-issue、Tensor Core/MMA 指令流水
- **并发 kernel**：CUDA Graph 并发 kernel 启动、persistent kernel 中 work-item 级并发、MPS（Multi-Process Service）/MIG（Multi-Instance GPU）对并发的影响
- **所有问题均从硬件体系结构侧重出发**：kernel 设计如何匹配 GPU SM 微架构（warp scheduler、dispatch unit、register file bank、Tensor Core）、NPU 脉动阵列/达芬奇架构（Cube Unit、Vector Unit、Scalar Unit）、TPU systolic array/MXU 的计算模式

## Q4.2

**层**: L4
**问题**: 在单 GPU/NPU/加速器上，多算子/微算子并发的指令编排（instruction scheduling）和软件流水线（software pipelining）设计如何进行？具体包括：(1) 指令级并行（ILP）——如何在单 warp/wavefront 内编排多条独立指令（如 global memory load 与 compute 重叠、Tensor Core MMA 与 shared memory store 并行）；(2) warp/wavefront 级调度——GPU warp scheduler 如何在 stalls（memory latency、execution dependency）时切换到其他 warp 以隐藏延迟，以及 warp 调度的 fairness 与并发粒度的关系；(3) software pipelining——如何通过异步拷贝（async copy / TMA / memcpy_async）将 global→shared memory 数据搬运与计算流水线化，实现 producer-consumer 流水线；(4) 指令混合——如何将 GEMM/attention 的 MMA 指令与 element-wise activation/normalization 的 ALU 指令混合调度以提升计算单元利用率？结合硬件体系结构侧重：不同平台（GPU SIMT 的 dual-issue、NPU 的 VLIW/超长指令字、TPU 的 VLIW/XLA 指令编排）在指令并行度、寄存器压力、流水线深度方面的差异。

## Q4.3

**层**: L4
**问题**: 在 MoE、DiT、多模态、Video 四类模型的多算子/微算子并发场景下，Memory Hierarchy（register file → shared memory/L1 → L2 cache → HBM/GDDR/global memory → host memory）如何影响 kernel 设计与调度？具体包括：(1) register file——registers per thread 对 occupancy 的限制，MoE expert weight 的 register tiling 策略，DiT attention 中 QKV 矩阵的 register 缓存；(2) shared memory——shared memory 如何在多微算子间划分（如 attention kernel 中 QKV tile + softmax workspace），bank conflict 如何影响并发访存吞吐，shared memory 大小（H100 228KB/SM、A100 164KB/SM）如何限制 tile size；(3) L2 cache——L2 cache residency 策略与多 kernel 并发时的 cache thrashing 问题；(4) global memory (HBM/GDDR)——合并访问（coalesced access）对 memory bandwidth 利用率的影响，MoE expert weight 的分散访存模式对并发 kernel 的带宽竞争；(5) NPU 片上 buffer / TPU VPU memory——不同于 GPU 的 memory hierarchy 架构如何影响 tile 切分和 kernel 并发策略？结合硬件体系结构侧重：shared memory banking 结构、L1/SMEM 统一架构（如 H100 的 SMEM/L1 可配置）、HBM3/HBM3e 带宽峰值下的并发访存瓶颈。
