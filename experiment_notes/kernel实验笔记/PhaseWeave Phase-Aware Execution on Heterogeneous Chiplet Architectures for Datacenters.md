## PhaseWeave Phase-Aware Execution on Heterogeneous Chiplet Architectures for Datacenters

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - （近似匹配：论文无新 kernel 算子，其核心"运行时调度"是硬件-OS 协同的 phase 级线程迁移，把计算调度到异构 chiplet 后端上。）实现：(1) benefit-aware 迁移算法（Algorithm 1）——每 100µs epoch 末，对每个线程 t、候选 chiplet c' 计算迁移效用 U(t,c')=S(p,c')-S(p,c)-λ·Q(c')-C_switch（S=phase p 在 chiplet c 的离线预期性能如 IPC，Q=Load State 报告的 runqueue 长度，λ 把排队折算延迟惩罚，C_switch=一次 context switch 代价；c'=c 时 U=0），选 c*=argmax U，仅当 U(c*)>θ 且线程在现 chiplet 驻留 ≥T_min 才迁移（T_min 防预测噪声振荡）；(2) OS 集成——chiplet 暴露为 CPU 簇（类似 NUMA 节点、不连续 CPU ID 区间），PhaseWeave 不改 OS 调度器数据结构，经 MSR/MMIO 硬件接口给 placement recommendation，OS 周期性读取并用自己的 affinity 机制迁移线程；(3) Load State 模块 + 软件可写 task-count 寄存器（OS 在 runqueue 变化时更新）。实验比较：PhaseWeave vs PhaseWeave-NoMigrationAlg（无条件迁到预测最优 chiplet）——吞吐 1.26×（仅专精+多核）→ 1.56×（+迁移算法，即迁移算法再贡献 1.24×）；迁移统计：53.2% 的 epoch 迁移≥1 线程，其中 18.5% 因最优核满载而迁往次优核；真实系统迁移开销（平均 23.8µs、中位 9.5µs，phase 时长数百 µs 可忽略）与功耗（同核数下比 baseline 少 7.2% 功耗）。
- 后端平台是什么，配置是什么。
  - 全系统模拟：QEMU+SST Ariel+DRAMSim3 中四类异构 chiplet 后端（Table III，38 核：10 compute@3GHz 6-wide / 9 fast-mem@2.5GHz 4-wide / 9 near-net@2.5GHz 4-wide / 10 low-power@2.0GHz 2-wide）。真实系统：Intel Emerald Rapids（28 核 2-way SMT 3GHz，128GB DDR5 5600MT/s），把核分组为 pool 各模拟一类 chiplet，按 PhaseWeave 参数设置每 pool 频率（cpu-freq-utils）、内存带宽（pqos/CAT）、网络带宽，用改变 OS scheduling affinity 迁移线程；迁移时间=从中断线程到目标核起跑的时间。
- 评估性能的软件/脚本是什么。修改了什么。
  - 全系统模拟中的迁移调度器（Algorithm 1 实现于 SST 环境内）+ 真实系统上用 OS 亲和性（sched_setaffinity 机制）+ perf 采集 PMU 指标评估。修改：SST 内新增 task-count 寄存器、Load State 模块与迁移调度逻辑；OS 侧不改调度器数据结构，仅周期读硬件 recommendation 并设置 affinity。评估指标：SLO（100ms @P99）下吞吐 QPS、端到端延迟、迁移开销、功耗。
- 开源情况。基于开源文档和论文，使用例子解释评估软件/脚本如何使用？至少具体到评估软件的评估原理和kernel输入到性能输出的全过程。
  - 开源：PhaseWeave 未开源（论文未给链接，联网检索无公开仓库，截至 2026-08）；DCPerf（https://github.com/facebookresearch/DCPerf）与底层模拟器开源。使用例子（一次 phase 迁移的输入到性能输出全过程）：输入 = 预测器输出的 phase p + 各 chiplet runqueue 长度（Load State）+ 离线 phase-特征表 S(p,c) + 阈值 θ/T_min/λ/C_switch → 调度器枚举候选 chiplet 计算 U(t,c')，若 U(c*)>θ 且驻留 ≥T_min，把线程从当前核出队、标准 context switch（页表根更新与 TLB 一致性走既有硬件/OS 机制）入队目标 chiplet runqueue → 线程在目标核跑下一 epoch（预测器并行采样新特征）→ 请求全程按 100µs epoch 反复预测-决策-迁移 → 汇总各负载等级下的 QPS、P99/P50 延迟、功耗与迁移次数统计，从而量化迁移算法带来的 1.26×→1.56× 吞吐提升与 7.2% 真实系统功耗节省。
