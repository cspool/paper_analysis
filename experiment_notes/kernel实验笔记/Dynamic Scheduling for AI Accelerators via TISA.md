## Dynamic Scheduling for AI Accelerators via TISA

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现为 tile 粒度 kernel 算子库 + 语义感知动态 tile 调度运行时：(1) 在 Epoch 的 ME/VE/DE 三引擎上实现高性能算子库，kernel 以 tile 粒度表达、按 OpType 直接映射到对应单元（ME 自定义 block 张量指令、VE 扩展 tile 友好向量指令、DE 暴露 DMA 风格异步非阻塞描述符），经双缓冲（ping-pong）流水跨 ME/VE/DE 执行，shape-parametric；(2) 运行时调度器消费 TISA 指令的语义字段（OpType/UnitMap/TileMem）做动态 tile 分发：语义路由到每单元等待队列 WQ → 就绪窗口内与 in-flight 语义表 Fu 做区间重叠/scope 隔离/语义兼容/资源可行性检查 → 无冲突者提升 IQ → 依赖清除即乱序发射 → 完成退休 Fu 并反馈调整优先级（Algorithm 1/2）。kernel 以 run-to-complete 非抢占方式执行，调度决策仅在 tile 边界（>10³ 运算），硬件调度器 RTL 综合每 tile dispatch 仅 7~9 cycles @1GHz。
  - 实验比较：① Epoch 上三种调度配置对同一算子库的 kernel 执行周期消融——Naive（fence 手工依赖、无重排）/ Static（编译期软件流水 + fence + 重排）/ Dynamic（硬件动态调度），Dynamic vs Naive 1.52–1.92×、vs Static 再高 1.14–1.63×（表 VI）；② Accumulated Overlap Score（DM/DV/MV/DMV 四类跨单元重叠周期累加）动态调度达 Naive 的 2.60–32.64×、Static 的 1.10–5.17×（表 VII/VIII）；③ GPU kernel 对比——Epoch(TISA FA3 kernel, BF16) vs H100 手调 FlashAttention-3（1:8 计算比下硬件利用率全序列长高 >10%，head dim 128 高 26.4%；1:16 仍高 15.7%）；④ CPU kernel——Triton-TISA vs Torch-Manual 算子执行时间（ResNet50/BERT/LLaMA2，图 7）。
- 后端平台是什么，配置是什么。
  - 主后端 Epoch：32 核、1 GHz 已流片硅片（W=8），每核 3 引擎——ME（张量算术）/VE（元素级与规约）/DE（DMA 异步搬移），每核 1.5 MB 本地内存、片上共享 SRAM（核间 tile 复用）、NoC 互连、48 GB GDDR6（与主机共享）、峰值 256T FP16、1 TB/s 带宽。多核：编译期空间划分（attention head/batch 独立 tile 组静态分配核），每核本地 TISA 调度器独立运行，核间同步用共享 SRAM bank 更新触发的轻量 NoC 信号。GPU 对照：H100（132 SMs、3.35 TB/s HBM3，跑手调 FA3）、A100（108 SMs、1.55 TB/s HBM2，跑 TensorRT 10.3.0/TensorRT-LLM 0.12.0，CUDA 12.1）。CPU：Intel Xeon 6348（56 核、204.8 GB/s DDR4）。
- 评估性能的软件/脚本是什么。修改了什么。
  - Epoch 侧：真硅片周期计数（表 VI 执行周期、表 VII/VIII 重叠分），软件 = 自研 TISA 语义算子库 + 编译产物 TISA 二进制（Naive/Static/Dynamic 三配置共用同一算子库与编译器优化，仅调度策略不同，严格隔离调度贡献）。GPU 侧：TensorRT 10.3.0（ResNet50/BERT）与 TensorRT-LLM 0.12.0（GPT-J/LLaMA2/DeepSeek-R1）作为静态调度基线原样运行；FA3 的 H100 结果引用 FlashAttention-3 论文（https://github.com/Dao-AILab/flash-attention）。CPU 侧：PyTorch 算子（Torch-Manual）与 Triton（Triton-TISA）对比。修改了什么：Epoch 侧为自研（算子库 + 调度器 RTL）；未修改 TensorRT/FA3/Triton/PyTorch。

  - 评估原理与 kernel 输入到性能输出全过程（FA3 kernel）：CUDA 版——tma_load_q/tma_load_k_transpose 载入共享内存 → warpgroup_fence_producer + wgmma::mma_sync 做 QK^T（M0）→ wgmma::wait + softmax_warpgroup 算 softmax（S）→ 循环内 tma_load_k_next + wgmma::mma_async 预取下一 K tile、tma_load_v + wgmma::mma_sync 做 AV（M1）→ rescale + warpgroup_commit_batch + update_carousel_index，8 处显式同步（bar.sync/wait/commit）锁定静态双阶段流水（图 2b/d），DMA 停顿会无条件阻塞依赖消费者。TISA 版——同一循环以 tisa::gemm<me>/tisa::softmax<ve>/tisa::load<de>/tisa::store<de> 声明式表达、零屏障（图 2c/e），每 tile 描述符进 Reception Buffer → 按 OpType/UnitMap 路由到 ME/VE/DE 各自 WQ → 就绪窗口 W 内与 Fu 做 Hazard(I,Fu)=∃r∈Fu:SemanticConflict(I,r)（区间重叠 + scope 隔离 + 语义兼容 + 资源可行性）→ 通过者进 IQ 依赖清除即乱序发射（S_i 可与 M0_{i+1}、M1_i 可与 S_{i+1} 并发）→ 完成退休 Fu 唤醒依赖 tile。指标：执行周期（Epoch 硅片计时）与硬件利用率=Achieved GFLOPs/Peak GFLOPs。结果：Epoch 上 Dynamic 把 ME/VE/DE 三单元同时激活（DMV 类重叠）从 0 提到最高 1129011 周期（BERT）；FA3 对比 H100（1:8 BF16 匹配比）全序列长利用率高 >10%、head dim 128 高 26.4%，即便 Epoch 带宽只有 H100 的 1/3.35。
