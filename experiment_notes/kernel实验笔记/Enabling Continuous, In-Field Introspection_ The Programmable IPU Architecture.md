## Enabling Continuous, In-Field Introspection: The Programmable IPU Architecture

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现为运行在 IPU（新异构后端：RISC-V 核 + 直方图/hash/循环加速器 + eFPGA 软逻辑）上的 introspection 程序（分析型运行时 kernel 算子）：输入是 HIT 的微架构内部信号（每次执行 32 个命名输入寄存器），程序按数据驱动方式运行（新数据到达即调用 _main，处理期间新数据被丢弃——Little's Law 下无 stall 时丢数据不可避免），把高带宽原始信号流（如 PICS 的 215 bits/cycle、256-cycle 窗口的 3 路活动信号）在片上聚合/过滤/统计后只导出低带宽高层洞察（直方图、PICS、失败模式计数）。kernel 经编译器 intrinsics/函数库使用直方图累加、hash、循环指令，IPU_pro 还打包 Verilog 软逻辑（eFPGA 位流）。四类 introspection kernel：①entangled 预取器状态机（eFPGA 软逻辑，每地址 1 cycle，300 行 Verilog）；②PICS 生成（每 cycle 更新 PSV + 每 400k cycle 归并输出，75 行）；③TensorCore 利用率直方图（单条直方图指令 + 循环指令，256-cycle 窗口，2 行）；④Gaze 逐 miss 根因分类（4 类失败模式直方图，20-cycle 处理窗口，50 行）。
  - 实验比较：①预取器 emulation 对比 entangled 原始实现（ChampSim，135 CVP traces，覆盖/准确/缺失率误差 <5%）；②PICS 对比 TEA 专用硬件（gem5，13 SPEC，平均相对误差 <3%，3 个应用 10-14%，丢 PC 覆盖 ≤0.37% cycles）；③GPU 利用率直方图对比聚合 PMU（AccelSim，21 GEMM，输出带宽 1.7 GB/s @108 SM、10/108 采样 0.16 GB/s）；④逐 miss 根因诊断对比 PMU/PEBS（ChampSim，189 SPEC traces，平均误差 <3.5%、中位 2.46%）。
- 后端平台是什么，配置是什么。
  - IPU 后端：32-bit RV32I 顺序 RISC-V 核，IPU_lite 最高 2 GHz、IPU_pro（soft-logic）1.3 GHz（7nm），32KB scratchpad SRAM，8KB 指令内存（2048 条指令），32 输入 IORegs + TS/TE/ADDR 触发寄存器，4-bit STATUS（PAUSED/ACTIVE-PAUSED/ACTIVE-RUNNING/FINALIZE/ERROR/UNDEFINED）；IPU_pro 另含 590 CLB eFPGA + 470 AIO tiles + 8×64×64-bit BRAM。被监控的 HIT 后端：CPU 前端（entangled，2 信号 64 bits）、CPU 核流水线（PICS，17 信号 215 bits）、GPU SM scoreboard（3 信号 4 bits）、L1D cache/prefetcher（Gaze，6 信号 132 bits）。对照硬件：CPU Zen2 4-core complex（31 mm²、4W）、GPU SM（3.475 mm²、1W）、BOOM（2.2 mm²）。IPU 与 HIT 时钟不同步（HIT 可 3-4 GHz），支持三模式：亚采样（1-in-2 cycles）、快 buffer 异步窗口处理、只限低频相或优化 IPU 速度。
- 评估性能的软件/脚本是什么。修改了什么。
  - 评估软件：ChampSim、gem5 SE、AccelSim 三个模拟器 + 自研 IPU emulator（RISC-V 功能模拟 + Verilog co-sim，耦合 HIT traffic injector）；RTL 评估用 DC Compiler/Primetime + Innovus + VCD 功耗估计（netlist 仿真）。修改了什么：把自研 IPU 模拟器（建模 IPU 处理延迟与丢数据行为）加进三个模拟器做性能 co-simulation；Capability 4 用"离线分析脚本"按 IPU 20-cycle 处理窗口忠实建模丢数据并分类每个 demand miss。未修改 ChampSim/gem5/AccelSim 本体。
- 开源情况。基于开源文档和论文，使用例子解释评估软件/脚本如何使用？至少具体到评估软件的评估原理和kernel输入到性能输出的全过程。
  - 开源情况：IPU introspection 程序/IPU 模拟器未提供公开仓库（论文未给出，联网未找到，无法确认）；评估软件均开源：ChampSim（https://github.com/ChampSim/ChampSim，用法 `bin/champsim --warmup_instructions N --simulation_instructions M <trace>.champsimtrace.xz`）、gem5（https://www.gem5.org，SE 模式跑 SPEC SimPoints）、AccelSim（https://github.com/accel-sim/accel-sim-framework，SASS trace 驱动，`./util/job_launching/run_simulations.py -B <bench> -C QV100-SASS -T <traces> -N <name>`）；参考实现：TEA（https://github.com/uv-xiao/chipyard-ntnu）、Gaze（Zenodo https://zenodo.org/records/14252372）、CVP-1 traces（https://microarch.org/cvp1/）、DARCHR microbench（https://github.com/darchr/microbench）。
  - 评估原理与 kernel 输入→性能输出全过程（Capability 2 PICS，gem5）：输入 = SPEC trace（SimPoints 100M instr/region）+ IPU 配置（订阅 17 个核流水线信号：长延迟事件控制信号 + 4 处流水线的 6 个虚拟地址 PC，TS/TE 用 fetch-PC 的 ADDR 限定 ROI）→ 每 cycle gem5 推进核流水线并把 215-bit 事件输入喂给 co-simulated IPU → IPU 顺序核执行 introspection kernel：if-else-if 事件链把事件置位到对应 PC 的 PSV（load-modify-store 序列）、flush 时保存 PC、每 400k cycle 扫描活动 PSV 列表归并成 PICS 条目（PC+签名）经 FIFO 发主机 → 主机后处理按 PC 汇总 cycle 栈。输出 = 每指令 cycle 栈（如 PC 0x7912d0：DTLB miss+DCache Miss = 50000000 cycles），与 TEA 硬件 PICS 对比平均相对误差（红柱 <3% 平均，蓝柱丢 cycle 比例）。作用：证明软件定义性能归因——把专用固定功能硬件（TEA/PICS）的职责移交给可编程 IPU，且可用 IPU_PAUSE/RESUME 做细粒度控制，无需 RTL 改动（对比 TEA 需 BOOM RTL 修改）。
