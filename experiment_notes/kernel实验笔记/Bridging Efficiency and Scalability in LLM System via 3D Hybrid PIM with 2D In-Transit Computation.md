## Bridging Efficiency and Scalability in LLM System via 3D Hybrid PIM with 2D In-Transit Computation

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 近似匹配（无 GPU kernel，为 PIM 后端的 NoC in-transit 运行时计算）：实现 = CompAir-NoC 边传输边计算的运行时算子调度：(1) 归约/广播树——16 宽归约展开为 4 层二叉归约树（2^N 节点恰好用 2^N−1 个中间节点、每非叶节点 ArgReg 存累加和），bank 为归约粒度，支撑 input-split 映射的低开销 inter-bank reduction（此前受 global buffer 带宽限制需串行访问 DRAM bank）；(2) RoPE 数据重排——NoC_Exchange（T/R±，swap 目标 (x+Offset)%Group）经 4 router 五阶段交换完成邻居交换与奇数位取反，DRAM-PIM 以 EWMUL 完成 RoPE，替代数据回 CXL 控制器 CPU 的行粒度搬运；(3) 流式非线性函数——exp 用 Curry ALU 迭代（ArgReg=6 轮，逐轮 *=X、/=IterRound、+=1，每通道 16 bank × 2 路 = 32 路并发 exp）、sqrt 用 Newton 迭代；(4) path generation 运行时调度——编译期按 DST→SRC 生产者-消费者链把依赖的 NoC_Scalar 融合为单 packet（一次打包携带全部计算与路由），消除每步保守的 DRAM 写回（vs 纯 SIMD 数据流 IO buffer→Curry ALU→IO buffer 延迟 -33%~50%）。实验比较：Curry ALU vs 集中式 NLU（非线性总延迟 -30%、长上下文延迟 -25%）、4×Curry ALU vs 定制 16 输入 Softmax 单元（Vivado 综合资源显著更少）、path generation 开关、CENT_Curry_ALU 消融、input-split vs output-split 映射（(512,8) vs (256,16) 宏配置，input-split 2560×20 一致优于纯 output-split）。
- 后端平台是什么，配置是什么。
  - PIM 后端：32 设备经 CXL switch、每设备 32 通道 × 16 bank；NoC 4×16 2D-mesh（每 bank 4 router）、每 router 2 个 BF16 Curry ALU（各 1 adder/multiplier/divider）、flit 72b、SWIFT 式 1–2 cycle/跳；DRAM-PIM bank 32MB、16 输入 BF16 MAC；SRAM-PIM 宏 128 输入 8 输出 BF16、每 bank 4 宏。对比件：CENT GDDR6-PIM（32/96 设备）、AttAcc 4×80GB A100 + 4×16GB HBM3-PIM。
- 评估性能的软件/脚本是什么。修改了什么。
  - 评估软件：ramulator2.0（DRAM 时序）、Booksim（NoC flit 级逐周期）、CENT 模拟器（CXL 通信 + DRAM-PIM 指令执行）、自研 translate/（ISA 翻译与 path generation）。修改：booksim2 加入 Curry ALU 的 flit compute 流水级与 ArgReg/IterArg/IterOp 寄存器、归约/广播树与交换路由行为；编译端新增 row→packet 静态降级与依赖融合。一键脚本 compair_perf_pipeline.py（--use-noc 开关控制 in-transit 计算启用），输出 compair_summary.json。全部开源：https://github.com/Man0xbfc00380/comp-air.git。
- 开源情况。基于开源文档和论文，使用例子解释评估软件/脚本如何使用？至少具体到评估软件的评估原理和kernel输入到性能输出的全过程。
  - 开源（https://github.com/Man0xbfc00380/comp-air.git）。评估原理：cycle-accurate 联合仿真，NoC 按 flit 逐跳推演、flit compute 阶段与 switch traversal 并行（零额外流水级）。全过程（16 bank 上的 Softmax）：row-level 程序（NoC_Scalar/NoC_Reduce）→ translate/ 降级为 packet ISA：NoC_Scalar(exp) 经 path generation 融合为单 packet（Path[0..3] 携带 X/Y 坐标、WrReg、IterTag、Opcode）→ 每 bank 对本地分片发 exp 迭代 packet：flit 携带 InputVal 入 router，Curry ALU 以 ArgReg=6 做 6 轮 *=X、/=IterRound、+=1 就地替换 flit Data，IterTag 逐轮更新 ArgReg → NoC_Reduce 按固定树模板依 bank id 实例化 4 层二叉归约 packet、ArgReg 累加 → 广播回各 bank。输出 = 每算子周期与能量 → 非线性通信+计算占 block 时间比由 >20%（4K 上下文）大幅压缩，128K 长上下文 decode 加速 2.13–2.73×（GPT3-175B/Qwen-72B vs CENT）、非线性总延迟 -30%、长上下文 -25%。
