## CHIME: A Case for Efficient Long-Context Attention-FC Disaggregated Inference with DIMM-PIM

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现 = DIMM-PIM 后端上的 attention kernel 运行时计算与调度：(1) bubble-free pipelining——借鉴 FlashAttention 的 chunked tile 融合思想把 score/softmax/context 分 chunk 流水：bank PU 每算出一个 token 的 score 输出 O^s 暂存本地 result buffer，rank PU 立即经空闲的外部总线取回，adder 累加后 softmax 单元做 per-chunk softmax；全部 token 处理完后以 streaming chunk-wise 做跨 chunk 归一化得全局正确 S，S 元素写回 DRAM 与后续 context 计算继续流水。内部总线（bank PU↔bank）与外部总线（rank PU↔bank PU/shared buffer）解耦，bank PU 计算与 rank PU 传输并行。bubble-free 条件 = 跨芯片传输时间 T_comm ≤ bank PU 计算时间 T_comp，其中 T_comm = L_t×N_gqa×N_chips/B_rk、T_comp = L_t×E_h×⌈N_gqa/N_cmr⌉/(B_bk×N_bk×N_hc)，推出 head 映射约束 N_hc ≤ E_h×B_rk×⌈N_gqa/N_cmr⌉/(B_bk×N_bk×N_gqa×N_chips)：MHA(N_gqa=1) 取 N_hc=8、GQA-8 取 N_hc=1（表 I/II 配置）。(2) hybrid-grained re-layout——rank PU 上的 re-layout 单元在传输过程中做 in-flight 数据变换：fine-grained 把单元素各位连续排进单 chip 的 burst beat（元素不跨芯片，FP16 的 16 bit 放两个连续 burst beat 存入 Chip 0），coarse-grained 把每个 head 映射到 N_hc 个芯片（N_hc=8 时每个 burst beat 只含单 head 元素、每 head 分布到 8 chips；每 head 1 chip 时 8 个 head 的元素混排一个 burst beat）；offload 时 QKV 先入 rank PU 片上 SRAM 重排再写 DRAM，onload 反向。
  - 实验比较：硬件消融 baseline = bank-level CHIME-PIM 但 head 计算跨芯片映射 + CPU 辅助 re-layout（按 [68] 保守估计为读旧布局+写新布局的访存时间）；指标 = attention 延迟。结果：bubble-free pipelining 使 MHA 延迟 -27.9%、GQA -74.4%；hybrid re-layout 最多 -17%（收益随 token 长度增大占比下降，因计算主导，但 re-layout 开销每层每 token 累积仍需消除）；全部硬件优化后 CHIME 1.42–4.18× 加速；所有 bank-level 实现较 rank-level DIMM-PIM (R-DP) 快 >1.5×。
- 后端平台是什么，配置是什么。
  - CHIME-PIM（DIMM-PIM）：DDR4-3200，每 DIMM 2 Rank（8 chips）× 4 Bank Group × 4 Banks；2TB 容量、等效带宽 13.0TB/s（CHIME bank PU）vs 1.6TB/s（rank-level R-PIM）；DRAM 时序 BL=4:CCD=4:RRD=4/8:RCD=22:RAS=52:RP=22:RC=74:CL=22:WL=16:CDLR=4/12:WR=24:CCDL=8:RTP=12；bank PU 计算访存比 N_cmr=n（对应 GQA-n）。GPU 侧 8× A100（AttAcc roofline 模拟执行 FC）。
- 评估性能的软件/脚本是什么。修改了什么。
  - CHIME-PIM-sim：基于修改版 DRAMSim3（https://github.com/umd-memsys/DRAMSim3）的 trace-driven 逐周期模拟器，新增 PIM 命令（PIM_WR_R/PIM_LD_SB/PIM_WR_SB/PIM_MAC/PIM_RD_RB）、相应时序约束与 FIFO 调度方式。GPU 侧集成 AttAcc（https://github.com/scale-snu/attacc_simulator）的 roofline 模拟。

  - 评估原理与全过程（decode 一个 attention head）：CPU 以正常写把 PIM 请求发给 rank PU 译码为 PIM 命令 → 专用 PIM 控制器经标准 DDR 接口发命令给 DRAM chips → PIM_WR_R 配置寄存器（加法树/累加器计算范式、buffer 自增索引）→ PIM_WR_SB/PIM_LD_SB 把 Q 向量写入/读出 shared buffer → PIM_MAC 全 bank 的 bank PU 从 DRAM cell 读 K cache 与 shared buffer 做 MAC，score 按 chunk 写各 bank result buffer → PIM_RD_RB 经外部总线取回 O^s 到 rank PU，adder 累加、per-chunk softmax、跨 chunk 归一化出 S → S 写回 DRAM 后 bank PU 做 S×V context 计算 → 模拟器按 DRAM 时序逐 cycle 推演 bank PU 流水与总线占用，输出 attention 延迟/吞吐。kernel 输入 = Q/K/V 张量与 head 映射配置（N_hc）；性能输出 = Fig.14 消融延迟（bubble-free pipelining -27.9%/-74.4%、re-layout -17%）。
