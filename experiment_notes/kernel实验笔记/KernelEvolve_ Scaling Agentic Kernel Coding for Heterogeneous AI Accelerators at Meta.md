## KernelEvolve: Scaling Agentic Kernel Coding for Heterogeneous AI Accelerators at Meta

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现为 agentic kernel 生成/调度框架 KernelEvolve：以 kernel 规格说明为输入，LLM 自动生成面向异构后端的 Triton kernel（并支持 Triton-TLX 低层扩展与 MTIA 低级 DSL），把 kernel 优化形式化为图搜索 (F, π_sel, O, τ)——fitness F(v)=t_pytorch/t_triton（正确性失败/编译运行错误置 0）、selection 支持 greedy/MCTS(UCT)/进化算法、单一 universal operator 经检索增强动态 prompt 合成（替代传统 Draft/Debug/Improve 静态多 operator）、termination 按预算/停滞/阈值。落地为跨后端运行时调度：对每个平台离线生成+验证平台专属 kernel，部署时 shape-aware dispatch 选最高性能变体、生成 kernel 性能不足时回退 vendor library（conv1d/conv2d）或 PyTorch 基线，防止回归。
  - 实验比较：(1) OSS 正确性——160 个 PyTorch ATen 算子（torch.add/div、cos/exp、amax/allclose、aten.elu 等）× 3 平台（NVIDIA H100、AMD MI350、MTIA v3）= 480 配置 100% 正确（vs torch.compile 的 PyTorch 参考，torch.allclose 容差）；KernelBench（250 题，Level 1 单算子/Level 2 融合/Level 3 完整模型块）100% pass。(2) 生产 case studies vs PyTorch baseline：conv1d 生产形状 (B,Cin,Cout,L)=(2048,96,96,200) FP16 下 2.30× vs torch.conv1d、1.62× vs conv2d workaround（FP32 1.73×/1.30×）；跨平台 conv1d 同形状：1.75× (AMD MI300)、2.30× (NVIDIA H100)、2.54× (AMD MI350)、1.77× (NVIDIA A100)、6.54× (MTIA v3) vs conv1d，相对 conv2d 为 1.25×/1.62×/1.06×/1.35×/4.71×；WuKong Optimized FM（N≤64 生产形状）2-4×（峰值 3.6-3.9×）；InterFormer PFFN 1.5-2×（峰值 2.0-2.6×，无回归）；MapId MTIA v2i 最高 4.07×（大 batch 3.28-3.48×）、MTIA v3 最高 1.36×；MBDT MTIA v2i 2.94-9.25×、v3 2.31-3.09×；Batch Event Truncate 最高 14.5×（生产端到端 2×）；RMSNorm 2D backward 17× (MTIA)、Sparse Inverted Index 1.25×。
- 后端平台是什么，配置是什么。
  - NVIDIA A100 / H100（Hopper：TMA、WGMMA 128-thread warp-group、mbarrier 异步流水、TLX warp specialization、Tensor Core）、AMD MI300 / MI350（Infinity Cache 感知 tiling）、Meta MTIA v2i / v3（8×8 PE 阵列 + NoC，每 PE 双 RISC-V core + 固定功能单元 MLU/DPE/RE/SE/CP；MTIA v3 为最新代）。解释器环境（Meta Bento Jupyter 平台）：meta_kernel_gpu_interpreter / meta_kernel_amd_interpreter / meta_kernel_mtia_interpreter，捆绑完整软件栈（TritonGPU/AMDGPU/MTIA-MLIR 后端、mtia_triton_launcher、cuDNN 等），Conveyor CD 每日重建部署。评估工具：TritonBench（正确性+speedup）、Torch Profiler（系统级时间线/launch 开销）、NCU（kernel 级 occupancy/内存吞吐/指令混合）、Triton Proton（intra-kernel 指令延迟/流水）、MTIA Insight（PE 利用率、DPE/SFU/MLU 利用率与 stall、CPU I/D-cache、LLC/DRAM 带宽、load-store 吞吐）、Triton MPP 统一多遍 profiler；FaaS 平台承载远程 kernel 评估（扩展 Tasklet 资源模型加入 GPU 资源，8 GPU 或 24 MTIA 设备/宿主）。
- 评估性能的软件/脚本是什么。修改了什么。
  - 评估软件：TritonBench（https://github.com/meta-pytorch/tritonbench，Meta 开源）的 BenchmarkOperator 框架 + kernel_evolve CLI 自动生成 TritonBench Operator 文件（附录 A 给出 conv1d 完整生成代码：PytorchModel/TritonModel/get_inputs 双实现接口 + 20+ 组 autotune configs + TritonBench Operator 包装）；KernelBench（arXiv:2502.10517，公开 benchmark）。修改了什么：KernelEvolve 全部自研（图搜索状态机、context memory/deep search 子代理、检索增强 prompt 合成、持久知识库、evaluation code generator 确定性生成各工具 harness、Triton MPP 集成、FaaS 远程评估）；不修改 Triton 编译器/NCU/Torch Profiler 本身；MTIA-Triton 支持 emit_cxx=True 暴露中间 C++ 表示 + replay_cpp 免全量重编译快速重放调试（生产 Triton 为 Meta 内部 trunk，与开源版略有差异）。

  - 开源情况：KernelEvolve 本体未开源（论文未给代码/artifact 链接，联网未找到公开仓库，无法确认）；TritonBench 开源 https://github.com/meta-pytorch/tritonbench，KernelBench 公开（arXiv:2502.10517）；Triton/TLX fork（https://github.com/facebookexperimental/triton）开源；附录 A 提供完整可复现的 TritonBench conv1d Operator 脚本（合成数据保留生产数据统计特性）。
  - 评估原理与 kernel 输入→性能输出全过程（附录 A conv1d 为例）：输入 = get_inputs() 生成的合成生产数据（shape (2048,96,96,200) FP32，mean/std 取自生产数据统计，torch.manual_seed(42)，按 batch 64-2048 切片）→ kernel_evolve CLI 生成的标准文件含 PytorchModel（torch.nn.functional.conv1d 或 unsqueeze+channels_last 后 conv2d 走 cuDNN）与 TritonModel（kernel_function：_maybe_pack_weight 调 pack_conv1d_weight_kernel 把权重 [Cout,Cin_g,Ksz] 打包为 [Cin_g*Ksz,Cout]（.cg cache modifier 促 L2 复用，可禁 cache 测冷启动）→ conv1d_gemm_kernel 以 GEMM 风格 3D grid (gm, groups, gn) 启动（M=B×Lout、N=Cout/group、K=Cin_g×kernel_size），BLOCK_M/N/K、GROUP_M、WARP_SPECIALIZE 由 @triton.autotune 20+ configs 按 key=["M","N","K","stride","dilation","kernel_size","Cin_g"] 选择，kernel 内 static_range 遍历 kernel taps、double-buffer 预取 x/w tile（.ca 流式激活/.cg 复用权重）、fp32 累加、融合 bias epilogue，3D grid 的 group 维并行分组卷积）→ Operator(BenchmarkOperator) 包装两模型，run() 以 --device cuda --mode fwd --metrics latency,speedup,accuracy --precision fp16 --atol 1e-4 --rtol 5e-4 执行 → TritonBench 对每输入尺寸测 latency 并输出 userbenchmark_dict（tritonbench_conv1d[x_...-triton_kernel]_latency/speedup/accuracy）→ run() 校验所有尺寸 accuracy==PASS 后按 avg_speedup 截断到 [0.1,10] 打印 FITNESS_SCORE 与 KERNEL_TEST_PASSED/FAILED → 该 fitness 即图搜索节点 fitness（t_pytorch/t_triton）供 selection 决策。生产环境另有 Torch Profiler 时间线、NCU occupancy/内存吞吐、Proton instruction-level、MTIA Insight PE 指标经 MPP 汇总为结构化数据反馈搜索。作用：把 kernel 评估从人工验证转为自动化系统评估，使图搜索可迭代数千个变体并保持正确性保证（conv1d 300 步搜索 fitness 从 ~2000 收敛到 6889）。
