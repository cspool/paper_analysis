## Lembas: Cost-Efficient Genome Alignment with External Memory and FPGA Acceleration

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - （近似分层：本论文核心是 FPGA 硬件架构，此处从"FPGA kernel 实例化数量与运行时调度/数据移动"角度记录）实现为三个 FPGA kernel 集合 + 软件 orchestrator 的运行时调度：seed 阶段 16 个 columnsort merge-sort kernel（各独占一对 HBM pseudo-channel，单发射 16-to-1 merger，250 MHz/4 GB/s，合计饱和 ~8 GB/s 双工 PCIe），minimizer parse 与 anchor matching 与 columnsort 共享同一 bitfile；chain 阶段 4 个 chaining kernel（各单 PE，分数前向传播流水，II=1）；extend 阶段 16 个 kernel × 16 PE 脉动阵列 + 8×8 tile traceback（每次预取 4 tile 缓解 HBM 延迟）。软件 orchestrator 负责：按阶段把对应 bitfile 编程进全部 FPGA（时分复用）、调度 PCIe 上 NVMe↔FPGA 的数据搬运（minimizer 流/anchors/chains 作为中间数据驻留 NVMe）、列排序转置后 host 侧多 KB 大块 memcpy 重组、以及少量计算。
  - 实验比较的核心是 kernel 配置/数量选择对性能的影响：(1) 排序 kernel 设计空间——16-to-1 单发射 vs 更宽 fan-in（32-to-1 减少 sweep 数但占芯片更多、可放数量更少；更小 fan-in 省空间但 pass 更多）；16 个 kernel 已饱和 U50 PCIe 带宽（即该器件最大性能），32 个无法布局布线；256 MB 列需 6 次 sweep（16B 元素、单发射）。 (2) chaining kernel 数量由 PCIe 带宽而非芯片资源决定（表 IV 资源占用低，仍只放 4 个）。 (3) extend kernel 16×16 PE、8×8 tile 满足历史寄存器时序（更大 tile 不满足时序），480 bit/tile 对齐 512-bit HBM 接口。 (4) 多 FPGA 扩展性：2 FPGA 默认配置性能最优且成本最低；3 FPGA 时 4 个 NVMe 几乎饱和成为瓶颈（12 核 host CPU 未满载）。
- 后端平台是什么，配置是什么。
  - 后端平台 = 2× Xilinx Alveo U50 FPGA（8 GB HBM2、32 HBM pseudo-channel、PCIe Gen3x16 ~8 GB/s 双工、~250 MHz）+ 4×1 TB M.2 NVMe SSD（阶段间持久中间存储，非缓存）。host = 桌面级 i7-8700（16 线程 3.2 GHz，2017 年）/12 核、16–32 GB DDR4。
- 评估性能的软件/脚本是什么。修改了什么。
  - 无公开评估脚本。评估 = 真实原型运行（端到端/分步运行时间、内存峰值、实测功耗）+ Vivado 布局布线报告（LUT/BRAM）。软件组件：软件 orchestrator（自研：bitfile 编程、数据移动调度、大块 memcpy）、Minimap2（软件 baseline）、NVIDIA Parabricks minimap2 beta（GPU baseline）、NextDenovo（生成 all-to-all 工作流参数）、PBSIM3（合成 reads）。修改了什么：三个阶段 bitfile（RTL 经 Vivado 综合）；seed 阶段 32 排序 kernel 布局布线失败改 16；chaining/extend kernel 数量以饱和 PCIe 为准。

  - 评估原理与 kernel 输入→性能输出全过程（以 seed 阶段一次列排序为例）：输入 = 256 MB 列（16B 〈minimizer,index〉 元组，存 NVMe）→ orchestrator 经 PCIe 读入 FPGA HBM 一对 pseudo-channel → 16-to-1 单发射 merge-sort kernel 递归归并排序（每 cycle 发 1 元素，250 MHz→4 GB/s，整列 6 次 sweep）→ 排序后转置成子网格经 PCIe 写回 NVMe（host 多 KB 大块 memcpy 重组为连续列）→ 循环后续轮次 → 输出完全排序的 minimizer 流（columsort 共 4 轮列排序，有效端到端吞吐 ~2 GB/s）。chaining kernel：输入 anchor 流（NVMe→HBM）→ 每 anchor 前向传播分数给后续 N 个 anchor（增量 max reduction，N cycle 流水，II=1）→ 输出 chains。extend kernel：输入 chain 序列对 + band → 16 kernel 并行、每 kernel 16 PE 交错算行（S 经 2 元素 FIFO、E/b 经寄存器链传递）→ 分数矩阵存 HBM → 8×8 tile traceback（边缘单元 2-bit 编码跨 tile 路径、popcount 定位下一 tile、每 cycle 1 tile、预取 4 tile）→ 输出比对结果。性能输出 = 各阶段运行时间（vs mm64/mm32/Parabricks）、extend GCUPS（48/FPGA）、资源利用率、功耗。评估原理：真实 FPGA 执行（非模拟器），性能受 PCIe 带宽与 HBM 访问约束——这也是各阶段 kernel 数量以饱和 PCIe 为准而非芯片资源的原因。
