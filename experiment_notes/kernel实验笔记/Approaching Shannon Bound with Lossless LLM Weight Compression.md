## Approaching Shannon Bound with Lossless LLM Weight Compression

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现为 fused tile-aligned rANS 解压 + GEMM 微内核（GPU kernel，CUTLASS plugin）：(1) 双组件融合内核（Algorithm V.1）——warp 0 作生产者：从全局内存按 offset 表取压缩 weight tile、rANS 解码直接写 shared memory tile A(b)；warp 1..W 作消费者：把 A(b) 与激活 tile B(k) 送入 tensor core 做 GemmTile；double-buffered shared memory（A(0)/A(1)）+ cuda::atomic_ref<int, cuda::thread_scope_block> 的 ready 标志同步，每 tile 解压与上一 tile 计算重叠；(2) warp-cooperative rANS 解码（Algorithm V.2）——每 tile 压缩流分 R 个独立 substream、每 warp lane 一条：x ← s mod R → 查 shared memory 解码表 T̃[x]=(σ,f,c) → w ← DecodeSymbol(σ) 写 A[r,c]（r,c 与交错解码序锁步，直接写 GEMM 所需 swizzle 布局）→ s ← f·⌊s/R⌋+(x−c) → s 低于归一化阈值时 coalesced 32-bit load 补流（流跨 lane 交错使补位 load 天然 coalesced）；(3) tile swizzle + 确定性驱逐——大维度 GEMM 按固定 tile-swizzle 遍历序最大化复用并均衡 shared memory 压力，工作集超容量时按该静态序驱逐（recency 由 swizzle 序静态决定，无运行时记账），被逐 tile 的解压形式暂存小 decompression buffer 避免近期重复解压，压缩形式常驻全局内存；(4) 生产者/消费者管线重叠——解码 warp 只用整数/LSU 管线（概率表 load、状态更新、shared memory store），GEMM warp 只用 shared memory load + tensor core MMA，两物理分立管线由 warp scheduler 同周期 co-issue，四阶段 shared memory ring buffer 让解码领先若干 sub-tile。
  - 实验比较：naive 基线（DietGPU ANS decode + CUTLASS GEMM 分离两段）；CUTLASS 原生 GEMM；SOTA 无损压缩 NeuZip、DFloat11（H200 微基准）；KTransformer（OOM 场景 CPU offload 对比）。指标：TFLOP/s vs batch size（1–64、4096 input tokens）、逐步优化分解（tile 对齐 → 双缓冲）、A100/H200 跨架构对比。
- 后端平台是什么，配置是什么。
  - NVIDIA A100（80 GB HBM2e 2 TB/s；tile 32×128）与 NVIDIA H200（shared memory 更大、支持 tile 64×256）。PyTorch 2.5.1、CUDA 12.1。
- 评估性能的软件/脚本是什么。修改了什么。
  - 基于 DietGPU（https://github.com/facebookresearch/dietgpu）的 ANS 内核扩展出 tile 粒度解码，基于 CUTLASS（https://github.com/NVIDIA/cutlass）实现 plugin 式投影算子与 tensor-core GEMM 微内核，并提供 PyTorch 直接调用 wrapper。论文自身 kernel 代码未找到公开仓库（arXiv 2606.15789）。
- 开源情况。基于开源文档和论文，使用例子解释评估软件/脚本如何使用？至少具体到评估软件的评估原理和kernel输入到性能输出的全过程。
  - 评估原理：单层投影 GEMM 微基准（batch 1–64、seq 4096）实测 TFLOP/s。输入 = 压缩 tile bitstreams + offset 表 + per-layer codebook + 激活 tile。全流程：每层开始解码 warp 把 codebook 拷入 shared memory T̃ → 循环 K_tiles 个 K-tile：warp 0 按 offset 从全局内存取压缩 substream，各 lane 独立 rANS 状态机（x←s mod R → 查 T̃ → 写 shared memory swizzle 布局 → s←f·⌊s/R⌋+(x−c) → 阈值重归一化 coalesced 补位）解出权重 tile A(b)，置 ready[b]←1；warp 1..W 等 ready 后从 shared memory 读权重 tile 与激活 B(k)、tensor core MMA 累加 C，消费完置 ready[b]←0 → 块级同步，双缓冲交替 → 输出 C tile → 上报 TFLOP/s。结果：tile 对齐解压（vs 分离两段）3.3–8.2×（Qwen-1.5B 3.66×、Llama-405B 8.20×）；再加双缓冲后总计 4.0–10.1×（Qwen-1.5B 4.41×、DeepSeek-67B 6.71×、Llama-405B 10.06×）；A100 大 batch 达 CUTLASS 的 1.0–1.1× 内、H200 最高 1.2× 超越 CUTLASS；vs NeuZip 最高 ~10×、vs DFloat11 ~6–7×、vs KTransformer prefill 7.7× / decode 18.1×。小 batch 时 tensor 管线先耗尽、内核 decoder-bound（退化为 decode-then-GEMM 行为）；大 batch 时 GEMM 主导、解码被完全隐藏、接近完全重叠。
