## DisDP: Disaggregating Compute, Network, and Storage for Model-Sharded Data-Parallel Training

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现为 DisDP 的 SmartNIC-managed contention-free collectives：把 MSDP 训练中的集合通信（AllGather/ReduceScatter）从 GPU/NCCL 整体卸载到 FPGA SmartNIC 上的 collective processing module，充当 GPU 显存与网络之间的运行时传输调度器。具体包括：(1) 两方软件 API `handle_t push(void* buf, size_t len)` / `handle_t pull(void* buf, size_t len)` / `void wait(handle_t)`：worker 与 PS 双向调用，push 把一整层 partial gradients 从 GPU 显存发出，pull 接收参数到 GPU/CPU 内存；调用返回 handle、异步完成，wait(handle) 阻塞到完成，使 PS 可预取参数。(2) SmartNIC 内独立的 push/pull processing unit，各配独立请求队列与独立流（类比 GPU stream），host CPU 经 MMIO 写入请求（含 handle 指针），处理单元出队后经 GPU 虚拟地址直接对 GPU 显存发 DMA（register_buf 预注册应用缓冲区），DMA 与网络收发按流水线重叠。(3) format conversion unit：按 SwitchML 的格式转换策略把 fp16/bf16 梯度转换为 SmartSwitch 可聚合的整数格式，固化在 SmartNIC 硬件流水线中（论文未展开位宽/缩放细节）。
  - 实验比较：(a) 与 NCCL AllReduce 的 algorithm bandwidth 对比（2/4/8 GPU，并发/不并发 GEMM）：并发 GEMM 下 DisDP 高 2%/35%/44%，无并发 GEMM 下高 8%/20%（4/8 GPU），因 push/pull 相对 AllReduce 流量最多减半且收发在 SmartNIC 执行、与 GEMM 零争用；(b) 消融 DisDP-GpuColl（由 GPU kernel 发起 push/pull 请求并轮询完成，与 GEMM 争 GPU 计算单元，模拟），DisDP 最高 1.58× 吞吐；(c) 端到端迭代分解：DisDP 几乎完全重叠计算与集合（Custom-175B），且集合时间再降 20%。
- 后端平台是什么，配置是什么。
  - 8 台 worker 机器：双 Intel Xeon Silver 4214 CPU、256GB DDR4、1× NVIDIA A100 40GB GPU、每机 1× Xilinx Alveo U50 FPGA SmartNIC；100Gbps 网络，SmartNIC 接 Edgecore Wedge100BF-32X SmartSwitch（Tofino），单台 PS（双 Intel Xeon Gold 5320、12 SSD、SmartNIC）。对照：ZeRO-Infinity/ZeRO-3 用 Mellanox CX-5 NIC + SN2700 常规交换机（每机 2 SSD）；SHARP 对比组用 4 机 × 100Gbps CX-6 + InfiniBand QM8790 交换机、每机 4 SSD；NVLink 组用 8×A100-40GB 全 600GB/s NVLink 互连机。
- 评估性能的软件/脚本是什么。修改了什么。
  - 自研 DisDP 集合通信库（push/pull/wait 两方 API + FPGA SmartNIC 固件 + SmartSwitch P4/逻辑）；对照 NCCL 2.20.5（DeepSpeed 0.9.3 内）AllReduce 微基准，干扰实验用 CUDA MPS 静态隔离 SM 后并发跑 GEMM 与 NCCL AllReduce（OPT-175B 典型配置）；大规模扩展（TP8、PP16 1F1B、DP 1–256）用 ASTRA-sim 2.0 + Chakra execution traces 仿真。未修改任何开源框架；NCCL/DeepSpeed 作为 baseline 原样运行。

  - 论文与 arXiv（2409.00918）均未给出 DisDP 代码/固件开源链接，联网搜索未发现官方仓库（无法确认）；ASTRA-sim 开源（https://github.com/astra-sim/astra-sim）。评估原理（真机测量）：host 调 push(buf,len) → 库分配 handle 并经 MMIO 提交请求（含 handle 指针）到 push 请求队列 → push processing unit 出队、按 GPU 虚拟地址对 buf 所在 GPU 显存发 DMA 读 → DMA 与网络发包流水重叠，format conversion unit 把 bf16 梯度转整数 → 线速发往 SmartSwitch（交换机内聚合）→ 对端 PS 的 SmartNIC 经 pull 处理单元 DMA 写入 CPU 内存 → 完成状态写回 handle，wait(handle) 返回；algorithm bandwidth = 集合数据量 S / 执行时间 t。对照原理：NCCL AllReduce kernel 与 GEMM kernel 在 GPU 上争 SMs 与内存带宽/L2，GPU 非抢占调度使占满 SMs 的 GEMM 阻塞后续集合 kernel 启动（65% 集合时间不可重叠、并发 GEMM 使 NCCL 带宽降 30%）；DisDP 的 DMA 与发包在 FPGA SmartNIC 执行，实测与 GPU GEMM 几乎零干扰（PCIe DMA 与 GEMM 双向无感，图 4）。
