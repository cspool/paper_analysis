## MNEMOS A GPU-based TFHE Acceleration Framework with Memory Access Optimization

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 属于kernel调度/运行时计算的实现：在 ZAMA 的 TFHE-rs/Concrete 之上重写 PBS 的 GPU CUDA kernel 集合，全部为新的 GPU kernel 算子：(1) **PBS MAC（External Product）kernel 的 BSK 分块复用**——利用 BSK 与傅里叶系数之间的 Hadamard 积性质，把单个线程块的数据足迹从"整个 BSK"降为"一个 BSK 分块（TBSK）对一个 GLWE 分块（TGLWE）"，使一批中多个 PBS 实例可并发处理同一份 BSK 分块（跨密文密钥复用），并按 GPU 事务粒度设计分块几何：一个分块 = 8 个连续复数 FP64 元素（16B/个）即 128 字节，对齐 128 字节内存事务粒度保证全局内存合并访问（coalesced）；分块大小在"合并带宽 vs 复用度"间权衡（32/64/128B 候选，最终取 8×16B=128B）。(2) **Tensor Core FFT kernel**——FP64 WMMA（A100 原生 8×8×4）加速 FFT：复数乘分解为 4 个实数 MMA（A_rB_r−A_iB_i、A_rB_i+A_iB_r，每个实数乘 2 次 WMMA）；8 点 FFT 为基例，N>8 用四步 FFT radix-8 递归分解，64 点特化算法利用 warp 内 fragment 布局省去一次显式转置与共享内存往返；分层策略：N>64 优先 radix-64、8<N≤64 用 radix-8、<8 用 CUDA Core+warp shuffle；Fourier 矩阵**运行时片上生成**（8 点 DFT 元素来自稀疏集 {0,±1,±sin(π/4)}，在寄存器内算术生成，消除共享内存载入、bank 冲突与布局管理）；宽数据类型（复数 FP64=16B 跨 4 个 bank）专用 **swizzle 模式**（任意 8 个连续线程映射到 32 个互异 bank）消除转置 bank 冲突。(3) **跨迭代 kernel 融合**——FFT 与 IFFT 使用同一系数集（twiddle factors 与 precomputation factors）的共轭版本，构造跨越盲旋转循环迭代边界的融合 kernel，把两套系数从片上内存跨迭代复用，消除主循环内对这些系数的冗余全局内存载入（收益随分解层数 ℓ 线性增长）。
  - 实验比较：PBS 吞吐（BS/s，batch 4096）vs ZAMA baseline（Table III：Para-A~F 在 A100 上平均 1.8×、Para-A~D 平均 2.23×、最高 3.01×（Para-D）；H100 上平均 1.83×、最高 2.86×）；跨平台吞吐对比（Table IV：Para-I/II 下 A100 22007/13744 BS/s、H100 38748/24348 BS/s，vs Concrete CPU 615.0×/676.3×、NuFHE 15.5×/44.3×、cuFHE 4.4×、VeloFHE 3.2×/9.7×、XEHC 8.7×、MATCHA 3.9×，并达 Strix 的 51.9% 与 Morphling 的 26.2%）；应用端到端（Table V：DeepCNN-20/50/100 2.03×/1.97×/2.04×、VGG-9 2.21×、AES 1.53× vs ZAMA GPU，vs 单线程 CPU 平均 142.4×）；消融（图 11：+MAC 单独 1.10×~1.77×，k 大时显著；+FFT 到最终版本）；stall 分解（图 3 vs 图 12：stall_long_scoreboard 从 >50% 降到约 20%，stall_MIO_throttle 主导变为 Stall Math Pipe；图 13：FFT 共享内存 stall_MIO_throttle 延迟降 3.2×/2.9×/1.8× 对应 N̄=256/512/1024）；内存流量（图 14：GMEM→L2 平均降 15.7%、L2→SM 平均降 69.4%）；batch size 敏感性（图 15，Para-B：baseline 在 batch>1024 因工作集超 40MB L2 而性能骤降，MNEMOS 全程稳定）；参数敏感性（图 16：k 增大→MAC 优化贡献增大，ℓ 增大→两者同时受益，N 增大→FFT 优化贡献增大）。
- 后端平台是什么，配置是什么。
  - NVIDIA A100 80GB PCIe（108 SM，每 SM 192KB 合并 L1/SPM，40MB 统一 L2，128 字节缓存行，FP64 Tensor Core WMMA 8×8×4）与 NVIDIA H100 80GB PCIe；宿主机双路 Intel Xeon Platinum 8558P（96 核）；软件栈 Python v3.8.20、Rustc v1.85.0，基于 ZAMA 开源库 TFHE-rs v0.11.2、Concrete-Python v2.10.0、Concrete-ML v1.9.0。参数集（Table II）：Para-A（N=512,k=4,ℓ=1,β=23,n=532）、Para-B（512,4,2,16,679）、Para-C（1024,2,2,15,728）、Para-D（512,4,11,4,654）、Para-E（2048,1,1,23,742）、Para-F（2048,1,3,12,592）均 128-bit 安全；Para-I（1024,1,2,16,500,80-bit）与 Para-II（1024,1,3,12,630,110-bit）用于跨平台对比。
- 评估性能的软件/脚本是什么。修改了什么。
  - 评估软件：ZAMA 开源栈作为 baseline 与执行框架——TFHE-rs（Rust，GPU PBS kernel）、Concrete-Python（TFHE 编译器，生成 Para-A~D 参数与 PBS 任务划分）、Concrete-ML（加密 CNN 推理，CUDA backend 运行 DeepCNN/VGG-9）。修改了什么：(1) 修改 Concrete 后端的任务划分策略，默认按内部启发式在 CPU/GPU 间分配 PBS 任务，改为全部 PBS 操作独占卸载到 GPU；(2) 修改 Concrete-ML 的 CUDA backend 使所有操作（含 PBS）全部在 GPU 执行，得到全 GPU baseline；(3) 重写/新增 PBS 的 MAC kernel（BSK 分块）、Tensor Core FFT kernel（WMMA、片上 Fourier 矩阵生成、swizzle、64 点特化）、跨迭代融合 FFT/IFFT kernel。AES-128 工作负载采用开源实现 [33]。

  - 评估原理与 kernel 输入→性能输出全过程（以一次批量 PBS 为例，Para-B：N=512,k=4,ℓ=2,n=679，batch 4096）：输入 = 4096 个 LWE 密文 c=(a_1,…,a_n,b)（同一卷积层共享参数）、预计算 BSK（(k+1)ℓ×(k+1)×N×n 个元素）、KSK、测试多项式 TP。kernel 流水线：Modulus Switching 把每个分量按模 2N 舍入缩放 → 盲旋转循环（n=679 次迭代，每次：Rotation 计算 ACC_rotate=X^{ã_i}·ACC−ACC → Decompose 把每系数按基 β 位切片成 ℓ 组 → Tangent FFT（N/2=256 点复数 FFT，negacyclic 卷积专用，b_j=(a_j−i·a_{j+N/2})·ω^j）在 Tensor Core 上执行（WMMA 8×8×4，四步 FFT 分解，Fourier 矩阵片上生成，跨迭代融合 kernel 复用共轭系数）→ MAC：TGLWE ⊙ TBSK 分块 Hadamard 乘（一个线程块读同一 BSK 分块服务一批 GLWE，128B 合并访问）→ IFFT + 累加）→ Sample Extraction（GLWE (k+1)×N → LWE kN+1）→ Key Switching（分解 + KSK 线性组合降回 n+1 维）。输出：PBS 吞吐（BS/s，batch 4096 固定）、相对 ZAMA 的 speedup、stall 分解（Nsight 类剖析：stall_long_scoreboard/stall_MIO_throttle/Stall Math Pipe）、GMEM/L2/SM 流量。作用：量化"BSK 分块复用 + Tensor Core FFT + 跨迭代融合"三项 kernel 优化相对 ZAMA CUDA 实现的吞吐收益（Para-B A100 2.26×、H100 2.02×）。
