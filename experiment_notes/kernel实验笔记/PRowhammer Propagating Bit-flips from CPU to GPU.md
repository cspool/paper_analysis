## PRowhammer Propagating Bit-flips from CPU to GPU

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现是面向 GPU kernel 运行时执行的攻击（非性能优化，为安全攻击，按最接近的"kernel 算子运行时"归类）：以无特权 CPU 进程在 hDRAM 中对 GPU 共享库（cuBLASLt、GGML）的 .nv_fatbin 压缩 SASS 代码页施加 Rowhammer 位翻转，借助 OS 页去重（.nv_fatbin 以 mmap(MAP_PRIVATE)+PROT_READ|PROT_EXEC 映射、只读页跨进程去重）使受害者 GPU-bound ML 进程被迫映射同一份被破坏的 kernel 代码；kernel 从 hDRAM 传至 GPU（cudaMemcpy/动态链接）后按被篡改 SASS 执行，位翻转传播到 GPU 计算并破坏输出。核心运行时机制：单 bit-flip 把 SASS 指令变为"不同但合法"的指令（表 I 归纳四类：寄存器变化、opcode 变化、offset 变化、指令变化，如 FFMA→FSET.F.FTZ.AND、LDS [R17+0x140]→[R17+0x148]、SHL→LOP3.LUT）；单 bit-flip 在压缩码中可产生平均 2–5 个（最多 25 个）合法改义指令，部分 kernel 崩溃、相当数量（cuBLASLt 3–83、GGML 41–99）不崩溃但输出改变。kernel 定位环节：用单线性层 profiling 模型确定目标模型实际调用的 cuBLASLt kernel（sm_86 共 3508 个 kernel，给定输出维度只调 1–2 个；CIFAR-10/MNIST/FMNIST 输出 10 类共用一个 kernel，ImageNet 输出 1000 类用另一个）。
  - 实验比较：图像分类 16 配置在 RTX 4090 与 RTX A6000 上攻击前后准确率（单 bit-flip 后接近随机猜测，ImageNet 0%，RPL>80%）；LLM 在 RTX A6000/4090/5060 上对 Llama-2-7B/Mistral-7B/Falcon-7B（4-bit 量化、llama.cpp/GGML）的 ggml_mul_mat kernel 单 bit-flip 后 BERTScore 0.58–0.62→0.25–0.30（输出 # 串或跨语言乱码，部分位置产生语法连贯但语义错误的文本）。攻击有效性：DDR3 无噪声成功率 50%/有噪声 30%，DDR4 无噪声 80%/有噪声 73%（噪声=多份 GAP PageRank 在全部核上持续占用内存与 CPU 调度）；首次 flip 需几分钟、首次可利用 flip 一小时内（DDR4 快于 DDR3），memory massaging 微秒级（vmtouch 刷 page cache）。
- 后端平台是什么，配置是什么。
  - NVIDIA 离散 GPU：RTX 4090、RTX A6000、RTX 5060，经 CUDA 软件栈（runtime/driver API、NVIDIA 驱动、GPU-bound 共享库）由 CPU 管理；hDRAM 为平台 A（Intel i7-4790 Haswell、8GB Kingston DDR3 1600MT/s、kernel 5.15.0-131）与平台 B（Intel i7-8700 Coffee Lake、8GB Corsair DDR4 2400MT/s、kernel 6.2.0-060200）；OS Ubuntu 20.04.6、CUDA Toolkit 12.8。SASS 指令集按 GPU 架构不同（表 I 以 RTX 4090 为例，Fig. 6 为 Ampere 架构示例）。
- 评估性能的软件/脚本是什么。修改了什么。
  - 评估软件：PyTorch（图像分类，经 cuBLASLt 加速 GEMM）；llama.cpp + GGML（LLM，ggml_mul_mat kernel）；cuobjdump（反汇编 .nv_fatbin、验证翻转后 SASS 合法性）+ diff；vmtouch（刷 page cache 便于 memory massaging）；GAP benchmark 的 PageRank（构造系统噪声）。修改了什么：无开源 Serving/推理框架被修改——攻击不改变框架代码，而是用 profiling 管线（kernel_locater_<lib>.sh、choose_target_region.sh、run_flipper_watchdog_<lib>.sh、segregate.sh、extract_useful_flips.sh）在目标库上离线定位可利用 bit，攻击阶段用 Rowhammer 篡改库文件在 hDRAM 中的映射副本。
- 开源情况。基于开源文档和论文，使用例子解释评估软件/脚本如何使用？至少具体到评估软件的评估原理和kernel输入到性能输出的全过程。
  - 开源：Zenodo artifact https://doi.org/10.5281/zenodo.19326669（prowhammer-artifact.tar.gz；Ubuntu 24.04 LTS、CUDA 12.8、Python 3.12/Anaconda；GPU RTX A6000/4090/5060 之一、≥8 核 CPU、≥16GB DRAM、~70GB 磁盘；准备 2–3 小时、实验 6–9 小时）。流程：`cd prowhammer-artifact/image_classification_and_llm_attack && bash setup_env.sh && conda activate prowhammer`；`cd profiling_bit_flip_location && bash get_golden_lib.sh prowhammer`（拷贝 libcublasLt.so.12 到 lib/）后 `bash run_profile_custom.sh / run_profile_cublas.sh / run_profile_ggml.sh` 跑五阶段管线 → 得 bitflip_data_<lib>.csv（第一列索引对应 outs_<lib>/stdout/out_err_<index>.log 的 corrupted 输出）；攻击复现：`bash scripts/flip_analysis.sh most_critical_bit_flip.csv && bash get_output.sh`（imagenet 用 flip_analysis_imagenet.sh；LLM 在 profiling_bit_flip_location 下跑对应 ggml profiling）。
  - 评估原理与 kernel 输入→性能输出全过程（以图像分类单 bit-flip 为例）：输入为 PyTorch 加载的模型（如 ResNet-50）与测试图 batch。(1) kernel 定位——攻击者用 profiling 模型（单线性层、输出维度=类别数）确定前向末层调用的 cuBLASLt GEMM kernel（CIFAR-10 等一个、ImageNet 另一个）；(2) 剪枝定位——对 cuBLASLt 的 nv_fatbin 二分分段、对段内 bit 逐一翻转后执行该 kernel 并与 golden 输出比对，保留下崩溃/改输出的 1KB 有用段，随机抽 10000 bit 逐个模拟（500–700ms/次）得可利用 bit 集合（mnist/fmnist/cifar10 用偏移 0x95c787a 的 bit 4，imagenet 用偏移 0xc56745c 的 bit 8）；(3) Rowhammer 攻击——memory profiling 找 hDRAM 中可在该页内偏移翻转的 page-frame，加载 cuBLASLt 到自身地址空间做 memory massaging 使可利用 bit 落在可翻转位置（vmtouch 刷 page cache、必要时 Frame Feng Shui 控制 page-frame 分配），对 aggressor 行 hammering 完成单 bit-flip；(4) 受害者启动——OS 页去重使 victim 的 cuBLASLt 映射到同一被篡改物理页，kernel 经动态链接从 hDRAM 传至 GPU；(5) GPU 执行——被改 SASS 指令（如 FFMA→FSET、LDS offset+8、SHL→LOP3.LUT）在 SM/Tensor Core 上执行，破坏最终线性层 GEMM 输出 → 分类概率分布被打乱 → 准确率跌到随机猜测（ImageNet 0%，RPL 100%）。
