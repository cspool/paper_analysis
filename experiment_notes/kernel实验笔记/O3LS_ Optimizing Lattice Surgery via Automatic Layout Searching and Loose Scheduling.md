## O3LS: Optimizing Lattice Surgery via Automatic Layout Searching and Loose Scheduling

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  O3LS 的 Module 3 松散调度（Loose Scheduling）与 Module 4 边感知初始映射（Edge-aware mapping）属于运行时计算/调度实现——在表面码晶格 patch board 这一后端上，对 lattice surgery 操作（Pauli product measurement PPM、patch rotation、patch deformation/movement、ancilla 路由）进行动态调度与映射。松散调度算法（Algorithm 2）：输入 Pauli 算子序列 S={P_1..P_l}、qubit 数 n、board B → 构建 Pauli DAG → while DAG 非空：对 frontier 中可执行算子 P_i 用 Dijkstra 依次求所需 patch 间最短路径（之前路径视为零成本节点），得到最小 bus patch 列表 Lp_i 后执行 P_i（每算子复杂度 O(|B|²)）；对不可执行算子 P_i，遍历当前 board 全部候选 patch 操作 O_B，选奖励函数 r(o_b, P_i) 最高者执行并加入 S'，循环直到 P_i 可执行。奖励函数三部分：①B_o（施加操作后的 board）中使 P_i 可执行（存在有效路径支持）的数据 patch 数；②破坏数据 patch 连通性的操作奖励为 0（连通性为后续 lattice surgery 必需）；③同奖励优先低时间开销。奖励函数保证每步至少增加一个满足执行要求的 patch，总调度复杂度 O(n²)。Module 4 边感知初始映射：分析 PDAG 估计每个 qubit 的旋转需求，旋转需求高的 qubit 优先映射到同时邻接 ancilla 的 X/Z 边缘的 patch，避免 3 时间步的 patch 旋转，复杂度 O(n log n)。实验比较：EA 映射相对 [28] 的 greedy mapping 时间步减少 15.0%、LER 减少 8.4%；松散调度 + Y-synthesis 相对 prior passes 时间步降 37.74%、LER 降 34.34%（ablation）；与高并行执行策略（LAPBC 风格 [4][5][20][25]）集成再降 9.31% 时间步；在紧凑布局中 patch 旋转可占 >50% 时间步（Fig.7 量化），松散调度正是针对这一瓶颈。
- 后端平台是什么，配置是什么。
  后端平台 = 表面码 patch board（二维 tile 网格），patch 抽象自 distance-d 表面码（每 patch 用 d² 个物理数据量子比特编码一个逻辑量子比特；X/Z 边界抽象为 X/Z 边缘，虚线=Z 算子、实线=X 算子）。配置：compact [34]（顺序放置、按需加列）、sparse [25]（每数据 patch 与邻居间隔至少一个空 tile、X/Z 边缘均邻接路由空间）、standard [25]（类 sparse 但放置不同）三种固定布局 + O3LS 自动生成的 squeezed 布局；board 尺寸 N×M∈[5,12] 扫描（Fig.10 heatmap）；d=9 表面码、p=10⁻³ 电路级去极化噪声模型用于 LER 仿真；15-to-1 magic state factory [8] 置于布局外。
- 评估性能的软件/脚本是什么。修改了什么。
  评估软件：STIM [18]（稳定器电路仿真器——每个原子 lattice surgery 操作独立编译成 STIM circuit，Monte Carlo 采样 ≥10⁶ 次，在 d=9、p=10⁻³ 电路级去极化噪声下表征 PPM/rotation/measurement 的错误率）+ PyMatching 2 [24]（最小权匹配解码）+ SPARO [28] 的分层 LER 模型（p_total ≈ Σ_t p_layer^(t)，p_layer = 1−(1−P_PPM)(1−P_PR)(1−P_idle)，PPM 错误率由路由空间与码距决定、rotation 分解为变形/角移动/移动三片分别仿真、idle 记忆错误累加；假设独立稀有失败事件）。时间成本按 [25][51] 的记录方式以时间步（⊕，round of code cycles）计。修改了什么：论文未明确说明对开源软件的具体修改；O3LS 新增了松散调度器、Y-synthesis、自动布局搜索与 EA 映射四模块，替换 SPC [32][52] / LAPBC [25] 的静态调度与映射 pass（对比时与 SPARO 的 greedy mapping [28] 对照）。
