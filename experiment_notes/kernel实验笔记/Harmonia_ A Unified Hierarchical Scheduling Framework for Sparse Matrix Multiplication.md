## Harmonia: A Unified Hierarchical Scheduling Framework for Sparse Matrix Multiplication

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现为稀疏矩阵乘法（SpMSpM）的分层运行时调度框架，含静态分析层、动态 Profiling 层、动态 Tuning 层三层：(1) 静态层离线按矩阵形状/全局密度/datatype 枚举候选 tile 形状 (T_M,T_K,T_N)，以操作强度 OI=OPs/Bytes 为目标、SRAM 可行性约束过滤，输出基线块形状、遍历顺序（k-outer 保持 C 驻留 / M,N 复用优先）与 SRAM 分区；(2) 动态 Profiling 层对 SRAM 中每个 tile 用精确 nnz 做轻量采样（tile 密度、行/列方差、聚类），细化 tile 形状（低密度扩张、高密度收缩、聚类对齐）并选择 InP/Row/OutP 数据流（InP 适合均匀中稀疏、Row 适合行方差大/聚类 A、OutP 适合均匀 A + 低密度 B）；(3) 动态 Tuning 层消费硬件反馈计数器（SRAM pressure、psum spill、MRN merge-depth、PE stall）在 tile 边界做数据流切换（InP↔Row↔OutP，规则见论文）与微重切块（K 缩小降 merge depth、M/N 限制 buffer/DN 负载），成本模型 Gain>α·Cost 控制是否重构，滞回 T=2~4 周期防振荡，最坏情况回退 1 次重构延迟（50 cycles）。
  - 实验比较 4 种调度 + oracle：Vesper 静态调度（baseline 归一化为 1.0×）、Misam-like 逐 tile 数据流选择（仅局部优化，忽略共享 SRAM 压力）、HYTE-like tile 编排（全局 tile 边界调整但 tile 内数据流固定）、Harmonia、静态最优 oracle（2.03× 上界）。全部在相同 32-row 硬件配置上模拟。指标：16 个 SpMSpM workload 平均 1.75× 加速（orani678 3.46× 接近 oracle）、端到端 4 个 DNN 管道 1.87×、SRAM 流量降 32%（Misam/HYTE 仅 10%，bcsstk10 上 Misam 反而 +39%、orani678 上 HYTE +50%）、off-chip DRAM 流量与片上 stall（HYTE 因固定数据流遇稠密簇 psum 溢出导致 stall 激增）、能耗 -40%、PE 阵列 16×16~64×64 与 SRAM 容量扩展鲁棒性。
- 后端平台是什么，配置是什么。
  - 后端为 Harmonia 稀疏加速器（基于 Trapezoid 行并行模板）：32 PE 行 × 32 FP32 MAC/加法器，0.5 GHz，峰值 1 TFLOPS；1 MB 片上 SRAM + 32 KB 分布式本地 buffer（每行 1KB、64B 宽）；off-chip HBM 2 TB/s；NoC 32-to-32 crossbar；总面积 7.51 mm²（TSMC 28nm 综合）。三种数据流（InP/Row/OutP）共享同一 PE 数据通路，仅 DN（16-to-16 Benes）路由、MRN（radix-16 加法树，merge-before-store 或 column-accumulate 模式）归约与 on-row buffer 策略不同，由 Reconfiguration Engine 在 tile 边界重编程。所有 baseline 调度在同一 32-row 配置上模拟以保证公平。
- 评估性能的软件/脚本是什么。修改了什么。
  - 自研 cycle-accurate 稀疏数据流模拟器（建模 MAC、MRN、DN、本地 buffer、SRAM、HBM，忠实建模 PE stall、psum spill、路由拥塞；动态调谐时注入 pipeline flush + DN/MRN 重编程 + buffer reset 的 20–50 cycle 重构开销）；数据通路 RTL 用 Synopsys Design Compiler（TSMC 28nm）综合评估面积，CACTI 7 建模 SRAM，HBM 能耗用厂商 datasheet。修改了什么：论文自研模拟器；Trapezoid/Vesper/Misam/HYTE baseline 按论文描述在同一硬件配置上重实现（未修改公开代码，均无公开 RTL）。

  - 评估原理与 kernel 输入→性能输出全过程（以 email.mtx 上 OutP→Row 数据流切换为例）：输入 = 矩阵（CSR/CSC+坐标列表或 bitmask）+ 全局描述符（M,K,N、密度、datatype）+ 硬件配置（Table III）→ 静态层 Algorithm 1 枚举候选块、约束 (2) 过滤、选最大 OI 的块形状与遍历顺序 → 每个块进 SRAM 后动态层按 tile 实际 nnz 采样（行密度方差、聚类）选初始数据流 → 模拟器逐周期执行：DN 按所选模式路由操作数（OutP 广播 (A_*k,B_k*) 对、Row 按 A 行 nnz 选择性路由 B 行片段并缓冲共享、InP 的 B 列流水转发最大化跨行复用），MRN 按 merge-before-store 或 column-accumulate 归约，反馈计数器记录 merge 事件/spill/stall → 若 merge depth 超预期或 spill 触发，Dynamic Tuning 用成本模型 (3) 评估 Gain vs Cost（重构 20–50 cycles）后切换数据流或缩放 tile → 输出每 tile 延迟、PE 利用率、A/B/C SRAM 流量、off-chip DRAM 访问、片上 stall cycles、操作强度 OPs/Byte、能耗。作用：验证"分层静态-动态协同调度"相比单层调度（Misam/HYTE/Vesper）在高度不规则稀疏模式（bcsstk10、orani678、rajat19 等）下的性能优势（平均 1.75×）与动态稀疏变化下的稳定性（stall <1%）。
