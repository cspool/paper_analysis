## ConBin: A Performance-Convergence Framework for Wafer-Scale Chip Binning

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - （近似归类，反馈：非 GPU kernel 实现，而是 WSC 空间加速器上计算任务与通信的运行时调度：bin 感知 workload 映射 + 通信序列调度，性能评估软件见 实验_硬件架构.md 同名条目。）实现 = (1) bin 感知 workload 映射：把有向负载图 WG=(W,D)（节点为计算任务如 GEMM/attention 层，边 d_{i→j} 为数据依赖/通信任务）单射映射到修复拓扑 TG=(V,E)，最小化期望最大链路 contention MLCC_exp=max_e LCC_exp(e)，LCC_exp(e)=Σ p_{i→j}（路由过 e 的传输频率权重，式 6），用 SEGA（Geatpy，种群 100、最多 100 代、10 代停滞早停）优化，命中当前 bin 目标 MLCC_exp^target 后自适应升级到高一档 bin（最多 2 次、30 代内未达标回退上一有效目标）；(2) 通信序列调度：把通信时间线切成 CAP（contention 近似稳定区间，三粒度批处理 b1≤b2≤b3 + 历史感知 contention 传播因子 μ∈(0,1)），用多染色体 NSGA-III（种群 120、最多 100 代）最小化各 CAP 期望最大链路/目的端 contention Φ，同样按 bin 目标 Φ^target 自适应升级；(3) pre-binning：按硬件指标 F 把芯片分 B+1 个分位组，每组轻量采样（top 5–15%）跑缩减版映射/调度得到该 bin 的优化目标。实验比较：CB*+NFT（CUPOKer，ISPD 2020 CS-1 WSE 负载分配冠军、非容错）、CB*+SK（Si-Kintsugi，hop 数最小化容错调度）vs CB*+Ours-SW* / Ours-WM / Ours-ALL*；结果：Ours-ALL* 方差降幅最高 79.21%（CB*+Ours-SW* 仅 9.16%）、speedup Ours-WM 至 1.85× / Ours-ALL* 至 2.39×；分 bin 后 Ours-ALL 对 CB*+SK* 获 2.80× premium-bin yield 与 2.64× SECC（8 bins）。
- 后端平台是什么，配置是什么。
  - WSC 空间加速器（系统级仿真）：stitched-die 2D mesh、[40×48, 64×72, 96×104, 128×136] 核（默认 128×136）、每核 8MB SRAM、跨 die 直连同延迟；修复后拓扑含多跳冗余 R-R 链（延迟按 hop 成比例）、turn-prohibition 路由。开销：128×136 下映射 ~18.36 min、通信序列调度 ~28.19 min（复杂度 O(|D|·h)）。
- 评估性能的软件/脚本是什么。修改了什么。
  - 自研系统级仿真（ScaleSim 核级 + BookSim 2.0 NoC），论文未给出脚本名/接口；优化器为 Geatpy 的 SEGA/NSGA-III，本文扩展自适应 bin 感知机制（达标后升级 bin 目标、最多 2 次，30 代或全局上限内未达标则采纳上一有效目标的最优解）。
- 开源情况。基于开源文档和论文，使用例子解释评估软件/脚本如何使用？至少具体到评估软件的评估原理和kernel输入到性能输出的全过程。
  - 开源情况：ConBIN 调度代码未开源（论文未给链接，无法确认）；Geatpy（https://github.com/geatpy-dev/geatpy）、ScaleSim（https://github.com/ARM-software/SCALE-Sim）、BookSim（https://github.com/booksim/booksim2）开源。评估原理与全过程（一个 chip 一次映射+调度）：输入 WG（LLaMA/GPT 各层或 GEMV/GEMM 32k×32k 的依赖图，边带 p_{i→j} 权重）与修复拓扑 TG → pre-binning 给出该 chip 所属 bin 的目标 MLCC_exp^target → SEGA 种群随机生成映射个体，按式(6) 沿每个通信任务 d_{i→j} 的 turn-prohibition 路由路径累加链路 contention 权重、取最大链路得 MLCC_exp，选择/交叉/变异进化并保留精英，达标后升级目标到高一 bin → 固定映射后把传输序列按 CAP 切分，NSGA-III 优化每 CAP 内并发传输的链路/目的端争用（μ 把未解决的高 contention 任务跨 CAP 传播、三粒度批处理控制复杂度）→ 每个映射/序列候选由 ScaleSim+BookSim 评出执行 latency → 输出该 chip 的映射方案、通信序列与平均 latency；512 实例汇总成性能分布供 DP 分 bin。kernel 输入 = 计算任务依赖图（节点=计算任务、边=通信任务及权重）与拓扑图；性能输出 = 端到端 latency / speedup / 方差降幅 / bin yield / SECC。
