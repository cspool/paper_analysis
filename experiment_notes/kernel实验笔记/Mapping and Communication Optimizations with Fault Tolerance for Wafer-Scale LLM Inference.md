## Mapping and Communication Optimizations with Fault Tolerance for Wafer-Scale LLM Inference

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 属于kernel调度/运行时计算：论文（ISCA 2026，HKUST-GZ）提出 BALD（Balanced Allocation with Load and Distance awareness）通信调度算法，为 wafer-scale 层次化 2D mesh 上的 point-to-point、多组 multicast（区域受限 collective 与广播）及 All-Gather / All-to-All 等 collectives 做链路分配（link allocation）与路径调度，属运行时通信调度在不同后端平台（wafer-scale NPU 阵列）上的调度。BALD 三步：(1) Path Profiling——对拓扑 T=(N,E) 用 Dijkstra 全源最短路径（Algorithm 1），记录最短距离映射 S 与唯一路径映射 U（记录等长多路径并把 pair 标记为非唯一），天然处理非对称节点度与异构边权重；(2) Path Scheduling——对每个通信任务 C=P(s,D)（源 s、目标集 D）按优先级 score = α×branch_cost + β×link_load + γ×neighbor_distance 迭代选择分支与邻居分配链路（Algorithm 2），branch_cost 为当前分支最早可调度时间、link_load 为链路当前占用（mesh 上 collective 的主要瓶颈）、neighbor_distance 为到最近目的地的距离（预计算）；(3) Heuristic Backtracking——维护 tabu forbidden/candidate 列表，迭代找出最大负载链路 l*、对其上任务按概率 ρ 重分配（成功回退的任务进 tabu candidates、失败进 tabu forbiddens），最多 I 次迭代（Algorithm 3）。算法基于 BFS/DFS，拓扑无关，只要存活图连通即可容忍任意节点/链路故障；实现为硬件路由器 Look-Up Table（LUT），主机在每次推理任务前加载路由配置、执行中更新，与 TPUv4 的 LUT 机制一致。
  - 实验比较什么：(a) 合成通信研究——5×5 mesh（无故障与 1 条故障链路 (12,13)，链路带宽 256 GB/s，消息 1 KB–16 GB 4× 递增），比较 All-Gather 与 All-to-All 的有效带宽（有效带宽=总数据量/总完成时间）：All-Gather 对比 Hierarchical Ring [34,61]、MultiTree [26]、TACOS [70]（MultiTree/TACOS 抽取调度步骤后用 alpha-beta 模型 [67] 建模总时间以公平比较），BALD 峰值有效带宽 533.3 GB/s 与 TACOS 持平，超过 MultiTree 1.25×、XY baseline 1.5×、Hierarchical Ring 近 2×；All-to-All 峰值 213.3 GB/s，是 XY baseline 收敛有效带宽的 2.4×，链路故障下保持 1.84–2.25× 优势。(b) 故障敏感性——6×6 mesh 上 7 类故障场景（1 节点/1 链路/2 节点/2 链路，覆盖不等价故障类，Fig.9），BALD 相对 XY routing 在 All-Gather 上 1–1.94×、All-to-All 上 1.56–2.55× 加速。(c) 超参数——α=100,β=1,γ=100（首轮偏好最短路径），随后 α=1,β=100,γ=1（均衡各链路负载）。
- 后端平台是什么，配置是什么。
  - 后端平台：wafer-scale chiplet 集成系统——层次化两级 2D mesh（上层 die、下层 die 内 core），die 间经 D2D 链路（多 SerDes lanes）通信，die 内 2D mesh NoC；每个 core 为通用 NPU（tensor core + vector unit + private buffer + NoC router 经高速 crossbar 互连），部分 router 直连 HBM 接口、其余连 D2D 链路（AXI→UCIe 协议转换）。Table I 参数：on-chip link 1 ns、256 GB/s；D2D link 20 ns、256 GB/s；off-chip HBM 100 ns、256 GB/s 每 die、8 GB 容量；计算与链路均 1 GHz；每 core 16 MB SRAM、1 tensor core + 1 vector unit。评估在自研事件驱动模拟器上进行（无真实 wafer-scale 硬件）。
- 评估性能的软件/脚本是什么。修改了什么。
  - 评估软件：论文自研事件驱动后端模拟器（10K+ 行 Python，ASAP as-soon-as-possible 调度，alpha-beta 成本模型 [67] 建模链路），同时调度计算事件、通信事件与 off-die DRAM 访问；artifact 以 `bash run_all.sh 16`（并行任务数默认 16）运行全部实验并产出 12 张图与 summary.txt（`bash run_quick_test.sh 16` 快速验证 <3 小时）。修改了什么：在模拟器中实现 BALD 三步算法（Dijkstra profiling、优先级路径调度、tabu 回退）作为通信调度器，替换 XY/XY-YX-FT 路由；XY-YX-FT baseline 为论文采用的 XY-YX 增强版（加入回溯规则覆盖更多故障情形）；fairness 上用 alpha-beta 模型统一建模 MultiTree/TACOS 的调度步。

  - 开源情况：开源（ISCA 2026 artifact）——GitHub: https://github.com/redbird-arch/isca2026-busybarn-artifact.git，Zenodo: https://doi.org/10.5281/zenodo.19686855；Python 3.9 + conda，依赖 numpy、networkx、simanneal、matplotlib、tqdm、PyYAML（requirements.txt）；Makefile + Bash 脚本，可选 SLURM；`make generate exp` / `make run scripts` / `make draw pic` 可独立跑各阶段；SA 带种子 --seed 123；硬件要求多核 CPU + 32 GB RAM（ablation ~32 GB/任务，其余 ≤4 GB/任务）。
  - 评估原理与 kernel 输入→性能输出全过程（以 All-to-All、5×5 mesh 含故障链路 (12,13)、消息 16 MB 为例）：输入 = 拓扑文件（5×5 mesh 节点/边，故障边 (12,13)）+ 通信任务集合（All-to-All 每源到多目标的 multicast 对 P(s,D)）+ 链路带宽 256 GB/s + BALD 超参数 (α,β,γ)。执行：Path Profiling 用 Dijkstra 得全对最短距离 S 与唯一路径映射 U（等长多路径标记非唯一）→ Path Scheduling 逐任务按 priority=α·branch_cost+β·link_load+γ·neighbor_distance 选分支邻居分配链路、更新 branch_cost 与 link_load，任务目标全达则从 P 移除 → Heuristic Backtracking 找出最大负载链路 l*、对其上任务按概率 ρ 重分配（成功→tabu candidates、失败→tabu forbiddens）直至收敛 → 生成路由 LUT。事件驱动后端把 LUT 路径上的数据包按 alpha-beta 模型（固定开销 + 数据量/带宽项）逐事件推进链路，ASAP 调度自动重叠通信与计算。输出：有效带宽（GB/s，总数据量/总完成时间）、相对 XY/XY-YX-FT、Hierarchical Ring、MultiTree、TACOS 的加速比、故障场景下的带宽保持率（Fig.8/Fig.9）。作用：量化"负载均衡+距离感知+故障感知的链路分配"对 wafer-scale mesh 上 point-to-point/multicast/collective 通信的带宽收益与容错能力。
