## Taking Analytic Databases to the Bank

- 属于kernel调度/运行时计算的实现是什么？实验比较什么？
  - 实现是面向 BLIMP PIM 平台的数据库算子内核（select/semijoin/join/aggregate kernel）与异构调度编排：(1) 内核本身——Algorithm 1 FILTERTOBITVECTOR（select，位图输出）、Algorithm 2 SEMIJOINPROBE（semijoin，位图输出）、join（probe 输出 hash 表 payload）、aggregation kernel；内核以 200MHz RISC-V 指令执行 fetch-read-apply-store 流程，以 1KB row buffer 粒度访存；(2) 调度——host 将列数据按 PIMDT chunk 均匀分发到全部 512 个 BLIMP core（模拟时假设数据同质、计算对称、总时延=最慢 bank），host 负责建 hash 表并 relayout 复制到各 bank；join 的 hash 表大于 32MB bank 容量时按分区多轮 build-probe 循环（每轮 offload 一个分区 hash 表、探测 PIMDT 列、结果 OR 到下一轮）；查询执行器在算子前预处理（切分 PIMDT、建数据结构），kernel+分区+辅助数据经 relayout 载入 bank，执行完后决定部分物化/原位保留或 host 取回；(3) 运行时策略——物化策略（Early/Hybrid/Late Mat.）、算子链（PIM 内 AND 合并双选择位图）、join 顺序（左深树、低选择性优先）。实验比较：各算子内核在 BLIMP-S/BLIMP-V vs host 手调 C++ kernel 的算子级加速比；端到端 SSB 中三种规划（Isolated / CPU-optimal / PIM-optimal）的 relayout、host 编排、hash build、数据加载、post-processing 时间占比。
  - 关键数字：隔离算子外推导致平均 22% 查询时间在 relayout（输出数据送回 host）；Isolated 计划平均比手调基线慢 2.1×、比 PIM-optimal 慢 3.2×；join 在隔离计划中平均差 3.1×；CPU-optimal（DuckDB 生成的 join 顺序）与 PIM-optimal 差异平均 28%、最大 40%（Q3.3）；CPU 推荐顺序 SDC 是 6 种候选序中第 4 差（比最优 CSD 慢 23%）。Q4.3 的 bushy join 树需多次重建 hash 表（重复 relayout+build+broadcast），与最小化 relayout 目标相悖。
- 后端平台是什么，配置是什么。
  - BLIMP-S / BLIMP-V：DDR4 DRAM bank 内 200MHz RISC-V 核，每核本地 32MB bank、1KB row buffer；BLIMP-S 为 RV64GC 标量核（1KB 指令缓冲、1KB scratchpad、5×1KB R/W buffer），BLIMP-V 为 RV64GCV 向量核（32×64b vALU、5×1KB vector register）；512 core bank 级并行、约 12.5TBps bank 内带宽（模拟配置）。Host：2× Intel Xeon Silver 4114（20 物理核/40 线程、AVX512）、27.5MB LLC、384GB DDR4（90GBps 峰值带宽）。BLIMP 与 host 间无 bank 到 bank 直连，跨 bank 数据传输走 host 读-写中转；compute mode 下 host 不能访问该 bank 数据，下游/并行相邻操作需等待。
- 评估性能的软件/脚本是什么。修改了什么。
  - 评估软件是论文定制的 BLIMP 周期级仿真框架（基于 prior work [25] ISCA'22 与 [2] riscvovpsim 的 validated cycle-level simulator + DRAMSim2 的 DDR4 timing），把离核 kernel 放到单个 BLIMP bank 的上下文中模拟，host 侧 kernel 在真实硬件上执行；框架硬件与软件参数化，可模拟任意能在 BLIMP 上跑的 kernel。修改/扩展：实现 BLIMP-S 与 BLIMP-V 两种核配置（向量引擎）、配置 1KB row buffer + 32MB subarray、16 banks/chip 的 DDR4 时序；新增数据库算子内核（select/semijoin/join/aggregate）与 PIMDT 数据布局/哈希表数据结构的运行时。host 侧基线为手调多线程 AVX512 C++ kernel（select/join/aggregate 各一个）与 DuckDB（state-of-the-art 分析型 DBMS）作为端到端基线；hash 表 build 时间与 CPU 侧 Swiss Table 等实现相当（论文引用 abseil Swiss Table）。
- 开源情况。基于开源文档和论文，使用例子解释评估软件/脚本如何使用？至少具体到评估软件的评估原理和kernel输入到性能输出的全过程。
  - 论文未明确说明数据库内核与仿真脚本开源（论文未明确说明）；可依托同组开源 BLIMP 框架 dovedevic/blimp（https://github.com/dovedevic/blimp）的 /simulation、/compilation、/relayout、/chronometry 目录复现 BLIMP 风格仿真流程（instrumentation → compilation → execution → simulation → evaluation），以及 riscvovpsim（https://github.com/riscv-ovpsim/imperas-riscv-tests）与 DRAMSim2（https://github.com/umd-memsys/DRAMSim2）。
  - 评估原理与 kernel 输入→性能输出全过程：以 select 为例——输入：PIMDT 列分区 d、谓词 p、元素宽度 w（如 10 亿 32-bit 值均匀分布在 512 个 bank，每 bank 一个 chunk）+ 输出位图区 b；host 把 kernel 可执行体与分区经 relayout 载入各 bank，BLIMP 核进入 compute mode（host 无法同时访问该 bank 数据）；核按 1KB row buffer 逐行 FetchMem，用 vALU 逐元素 apply 谓词，位图结果写回 b[HitmapRow]；模拟器以 cycle 级推进指令执行与 DRAM 时序（tRP=tRCD=21ns、tRFC=640ns、tREFI=7.8us、row buffer 开关/命中惩罚），输出该 bank 的周期数；系统假设对称计算，取最慢 bank 周期为内核总时延；host 侧 C++ kernel 在真实 Xeon 上多线程 AVX512 执行并计时；最后在端到端评估中叠加 relayout（host 29GBps）、hash build、数据加载、编排与 post-processing 时间，输出 SSB 各 query 的总延迟与相对加速比。BLIMP-V 相对 BLIMP-S 的加速（select 2.5×、join-heavy 1.4×、整体 1.7×）直接源于向量化内核（hash 可向量化、hash 探测是随机访存不能向量化）。
