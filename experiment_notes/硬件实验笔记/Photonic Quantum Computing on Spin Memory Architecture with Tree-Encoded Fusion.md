## Photonic Quantum Computing on Spin Memory Architecture with Tree-Encoded Fusion

- 属于硬件架构的实现是什么？实验比较什么？
  - 论文自研 realistic error-aware 模拟器，模拟 spin memory PQC 架构的图态生成与执行，属于硬件架构仿真层：核心模拟 caterpillar 态生成流水线（InGaAs QD 发射器 + LA 激发脉冲 + OSRP 光学自旋旋转脉冲 → 主路径链 + 叶量子比特的 branched-chain 结构，实验已小规模演示 [29]）与 Type-II 融合操作（HWP+PBS 线性光学）在流水线中的执行。实现包含：(1) 噪声模型——融合失败（1-p_fail=0.75，来自 OneAdapt 错误模型 + 额外干涉装置 [18][22][49]）、融合擦除（光子丢失，真实硬件观测 p_eras≈10%，仿真 0%~10%）、光子源退相干 F_de=e^(-N_e·T_gen/T2)（T2=2.34 μs，由 4-qubit GHZ 95% fidelity 反推）、融合保真度 σ_fus=(1+V_HOM)/2=99.75%（V_HOM=99.5%）、OSRP 99%；(2) 流水线时序模型——caterpillar 生成 12 ns 初始化 + 0.6 ns/qubit 发射、t_cycle=30 ns/层、最大 caterpillar 30 qubit、融合按 BBT 分层并行执行、失败子图延迟调度；(3) feed-forward 控制——SNSPD 单光子探测器（延迟 <50 ps）+ 小型组合逻辑块（b 输入 AND/OR 网络判断逻辑融合成功/需 stall）+ 时间延迟模块，总经典 feed-forward 延迟 <5 ns，用 Perceval FFCircuitProvider 实现。评估指标：平均执行时间、所需光子源数、编译时间、fidelity（F_de、F_CZ/F_fus）。
  - 实验比较：同架构融合方案（redundantly-encoded、RUS）的执行时间/光子源对比（2~20 qubit，p_eras 0~10%，执行时间上限 6×10^5 ns）；跨架构编译器对比（OneAdapt/OneAdapt-ET，36/64/100 qubit，p_eras 0~5%，执行时间上限 2×10^5 ns，误差棒 = 1000 次实验 × 2×10^4 shots 的 95% CI）；系统特征 trade-off 分析（Table III，30-qubit QAOA：MemTree 发射频率 ~7×10^2/ns、CZ 频率 ~2×10^2/ns、光子利用率 ~10%，vs OneAdapt 2×10^3/1×10^3/0.03%（融合为主导误差）、vs RLGS ~10/~1/100%（退相干为主导误差））。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟器模拟 spin memory PQC 架构执行量子程序的性能：输入量子程序图态 + 融合方案 + 噪声参数 → 模拟 caterpillar 发射（2×10^4 周期）、树编码逻辑量子比特制备（b_prep=6 并行尝试 + 失败/擦除重试）、按 BBT 分层的 Type-II 融合（成功/失败/擦除三结果 + 间接 Z 测量恢复）、失败子图延迟调度 → 输出平均执行时间（总周期时间/成功 shots）、所需光子源数、编译时间与 fidelity。模拟器实现树编码方案自身的制备误差（分支制备失败自动测量掉、擦除用 {q_i^b,q_i^e} 间接测量恢复），确保对容错方案 realistic 评估。与 OneAdapt/RLGS 共享统一 fidelity 对比噪声模型（Table II：平台 PsiQuantum/[57] 仿真/Quandela、T2=2.04/4.4/2.34 μs、CZ 保真度 99.75%/99%/99%、t_cycle=8/10/30 ns）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：自研模拟器未开源；Perceval 开源可复现真实硬件电路（pip install perceval-quandela；pc.Processor 定义光学电路、pc.Circuit 组合组件、FFCircuitProvider 添加 feed-forward 组合逻辑、execute()/pc.remote 提交 Quandela 云 QPU）。以下以 Perceval 为例说明模拟器/工具使用原理。
  - 模拟器输入→性能输出全过程（36-qubit VQE，p_eras=0.5%）：输入 = VQE 程序图态 + 树编码参数（b=4, b_prep=6）+ 噪声配置（p_fail=0.25、p_eras、T2=2.34 μs、σ_fus=99.75%、t_cycle=30 ns、caterpillar≤30 qubit）→ ① 生成流水线：模拟 InGaAs QD 发射器按 caterpillar 结构逐层发射（12 ns 初始化 + 0.6 ns/qubit），进入树编码逻辑量子比特制备（b_prep=6 分支并行制备，失败自动测量掉、擦除间接测量恢复，不足 b 个则下 timestep 重试）；② 融合执行：按 BBT 时间步对子图做 Type-II 融合，每分支按测量模式处理成功（X,X 连 q_root）/失败（Z+备份）/擦除（X+Z 间接 Z 测量恢复），融合失败 → 兄弟子图延迟下一时间步（SNSPD 探测 + 组合逻辑 + 延迟模块，feed-forward <5 ns）；③ 统计 2×10^4 发射周期内成功执行 shots 数 → 输出平均执行时间 = 总周期时间/成功 shots、所需光子源数（光子资源分解）、fidelity（F_fus=σ_fus^N_fus × F_de=e^(-N_e·T_gen/T2)）。作用：在真实硬件不可及的大规模（36~100 qubit）下量化融合错误对程序执行的影响，证明树编码 + 分层生成相对 OneAdapt 的执行时间指数级改善、光子源 0.18×、fidelity 3.64×，并揭示 MemTree 在"操作频率 vs 光子利用率"上的平衡点。
