## From Memorization to Generalization: A Practical Neural Network Prefetching Framework

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现 = Moirai 的 CaPNet 神经引擎硬件（Verilog RTL）+ 在 ChampSim 中的完整微架构集成。CaPNet 由三个硬件组件组成：①Input Processing Unit（Window-based Extended Delta 预处理，仅需位运算与算术，无 PC 表）；②CaPNet Predictive Engine：FCC（Forward Convolutional Cell，XNOR+popcount 位逻辑替代 MAC）+ BCC（Backward Convolutional Cell，反向梯度更新），前向层用 1-bit 二值化权重、反向层用 7/4-bit 混合精度潜在权重；③Adaptive Control Unit（双指标策略：平均 loss L_avg + 访问计数器，控制训练/推理相位切换与置信度三档预取激进性）。微架构集成：预取器接收 LSU 的 speculative VA（与 L1D/dTLB 并行，不占关键路径），训练用 ROB 的 retired PA 流，生成的预取 VA 进 PRQ；前向 pass 强制 3-cycle 流水线延迟（基于综合结果）；相位控制逻辑异步更新。实验比较：IPC speedup vs IPCP/Berti/Pythia+Hermes/SPP-PPF；预取质量（accuracy/coverage/timeliness）；L1D 预取引发的 eviction 分类与无用预取流量分解（L2 Hit/LLC Hit/DRAM Access）；硬件面积/功耗/频率（相对 Apple A13 Bionic 核心 2.61mm²/3W）。
  - 结果：面积 1178 μm²、功耗 8.5mW（ASAP7 7nm @4GHz），相对 A13 核心仅 0.05% 面积 / 0.28% 功耗；3-cycle 流水线设计最高 4.0GHz，单周期设计最高 2.5GHz；总存储 780 Bytes（CaPNet 核心 818 bits：Wraw 648 + 二值权重/激活 170 + HT 1024 + 杂项 110 + 计数器 32 + 阈值 64×2 + L_avg 32 + loss 阈值 64×2；辅助 stride 预取器 4096 bits）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 性能评估模拟器 = ChampSim（修改版），开源：https://github.com/ChampSim/ChampSim（wiki: https://champsim.github.io/ChampSim/develop/）；论文引用的 ChampSim 论文 https://arxiv.org/abs/2210.14324。硬件成本评估 = CaPNet RTL 用 ASAP7 7nm 预测性 FinFET PDK 综合：https://github.com/The-OpenROAD-Project/asap7（BSD-3，Clark et al. 2016，Microelectronics Journal DOI 10.1016/j.mejo.2016.04.006）；综合工具名论文未明确说明（论文仅写"使用 ASAP7 7-nm predictive FinFET process library 综合"）。
- 模拟器模拟什么的性能，修改了什么。
  - ChampSim 模拟乱序核心 + 完整 cache 层次 + 内存控制器的 IPC 与预取统计（accuracy/coverage/timeliness/eviction/traffic），trace-driven（DPC3/SPEC/GAP traces）。修改：实现 Moirai 预取器（moirai.cc/moirai.h，含 CaPNet 推理/训练引擎、Adaptive Control Unit、Window-based Extended Delta 预处理、辅助 stride 预取器、PRQ），配置在 inc/uarch/isca_config.h（Table I 处理器配置：4GHz 乱序、TAGE-SCL、48KB L1D 等），编译脚本支持 0-latency 与 3-latency 两种配置（严格建模 CaPNet 3-cycle 前向延迟）。存储/控制参数（Table II）：input length 10、HT 16 entries、window size 5、Ntrain 131072、Ninf 2048、[8,4,2] 结构、Wraw 首层 7-bit 其余 4-bit、Ltrain 0.5、Linf 0.01。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：Moirai artifact 在 Zenodo：Source Code https://doi.org/10.5281/zenodo.19450687、Workload Traces https://doi.org/10.5281/zenodo.19447159（MIT License）。基座 ChampSim 开源 https://github.com/ChampSim/ChampSim；ASAP7 PDK 开源 https://github.com/The-OpenROAD-Project/asap7。CaPNet 的 Verilog RTL 是否包含在 artifact 中论文未明确说明（artifact 描述列出的组件聚焦 ChampSim 修改；RTL/综合脚本未见列出，联网搜索无法确认）。
  - 模拟器输入→输出全过程（以一次单核评估为例）：输入 = (a) trace 文件（DPC3 SPEC 2006/2017 的 champsimtrace 等，如 429.mcf-192B）+ (b) 配置（build_champsim.sh 生成 0/3-latency 二进制，isca_config.h 定 cache/TLB/核心参数，ISCA26_AE.tlist 定 trace 列表）。模拟推进：ChampSim 逐条取指/执行 trace 指令，LSU 每周期生成 speculative VA → Moirai 预取器与 L1D 并行接收：Input Processing Unit 算 window-based extended delta（(aw[0]>>13)⊙(aw[i]>>13)==1 判定同页，返回 Δ=aw[i]-aw[0]，否则 abnormal 丢弃）→ CaPNet FCC 3 周期 XNOR/popcount 前向（0-latency 配置为 0 周期）→ 控制器按 L_avg 三档置信度决定预取个数（1/5/9）→ 预取 VA 进 PRQ 经 cache 层次下发（L1D 命中/L2 命中/LLC 命中/DRAM 访问分别记账）；训练流从 ROB retired 地址异步进入 BCC 更新 Wraw；cache 层次按 LRU 替换、维护 L1D eviction 与 prefetch fill 统计、LLC 与 DRAM 模型按 Table I 时序推进。输出 = 每 workload 的 simulation log：IPC（相对 no-prefetch baseline 算 speedup，Simpoint 加权）、accuracy/coverage/timeliness、prefetch-induced eviction 分类（harmless/harmful）、traffic（demand/prefetch 分开，L1-L2/L2-LLC/LLC-DRAM 三个边界）、4-core 混合评估出多核 IPC。作用：验证 Moirai 在 780 Bytes 预算下达到与 SOTA 记忆式预取器相当的 IPC，同时量化 CaPNet 的硬件成本（面积/功耗/频率由 ASAP7 综合给出）。
