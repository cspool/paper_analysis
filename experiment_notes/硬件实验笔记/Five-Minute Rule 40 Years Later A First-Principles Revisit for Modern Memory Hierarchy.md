## Five-Minute Rule 40 Years Later A First-Principles Revisit for Modern Memory Hierarchy

- 属于硬件架构的实现是什么？实验比较什么？
  - 属于硬件架构的实现是 MQSim-Next，一个校准的、基于物理的 SSD 模拟器（在 MQSim 基础上扩展），在 Storage-Next 高随机 IOPS 场景下以真实保真度刻画 NAND flash 设备级行为（IOPS/延迟），用于验证论文的第一性原理解析 IOPS 模型（Section III-B）并支持敏感性分析与未来架构/系统研究。实验比较：①解析模型 vs MQSim-Next 模拟的 SSD IOPS（90:10 读写比，两者紧密吻合，模拟略高因模型保守地取 Φ_WA=3）；②不同读写比下 IOPS（只读→82M、90:10→68M、70:30→52M、50:50→34M，GC 流量与主机 I/O 竞争）；③不同 NAND 通道带宽（3.6GB/s→68M、5.6GB/s→85M，凸显更宽通道或 Xtacking 堆叠 I/O 收益）；④不同 BCH 解码失败率 p_BCH（<1% 失败率下吞吐接近无错误平台；512B BCH 失败触发 4KB LDPC 解码只带来适度下降）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - MQSim-Next：论文在开源 MQSim 基础上扩展（CMU-SAFARI，https://github.com/CMU-SAFARI/MQSim，FAST 2018 "MQSim: A Framework for Enabling Realistic Studies of Modern Multi-Queue SSD Devices"）。MQSim-Next 自身未见公开仓库（联网搜索无法确认开源）。论文 arXiv:2511.03944（ISCA 2026，备选标题 "From Minutes to Seconds: Redefining the Five-Minute Rule for AI-Era Memory Hierarchies"）。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟现代多队列 SSD 的端到端设备级性能：NAND 时序（sensing/program 延迟）、die 内多平面并发、ECC 行为（两级级联码）、通道调度、PCIe/TLP 与 FTL/cache 时序、请求获取控制与稳态预处理，输出设备级 IOPS 与延迟趋势。修改（相对 MQSim）：①增加 JEDEC SCA（Separate Command/Address）NAND 通道协议，命令/地址开销降到 100-200ns，请求尺寸缩小时维持有效通道带宽；②支持独立多平面读（independent multi-plane reads），更好利用现代 NAND 的 die 内并行；③支持显式 transfer-sense 重叠，一个请求的阵列 sensing/programming 与另一个请求的命令/地址或数据搬运并发；④后端调度器增强为 read-prioritized、plane-aware 仲裁，让短读与长 program 重叠、在数据传输前交错 SCA burst 以最大化小 I/O 利用率；⑤显式可配置 ECC 模型——每 512B 扇区 BCH 内码 + 跨 8 扇区 LDPC 外码的两级级联码，小读只解码所需 BCH 字并跳过 LDPC（消除 SSD 内读放大），BCH 失败升级为 4KB LDPC 解码（增加传输与迭代解码延迟），可调 BCH 错误概率参数；⑥支持更多 I/O 队列，在深主机并行下提取满随机 IOPS。配置采用论文 Table I 参数（SLC τ_sense=5μs、τ_prog=50μs、N_Plane=6、N_CH=20、N_NAND=4、B_CH=3.6GB/s、τ_CMD=150ns、l_PG=4KB、C_NAND=32GB）与 Gen7 ×8 PCIe 链路（防 PCIe 带宽瓶颈化随 NAND 通道带宽升至 4.8-5.6GB/s 时的 4KB IOPS）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：MQSim-Next 无公开仓库；基座 MQSim 开源（CMU-SAFARI/MQSim，C++，MIT 许可）。论文未给 MQSim-Next 复现命令，以下基于 MQSim 机制+论文描述重建用法：配置 SSD 架构参数（Table I 时序/通道/plane/ECC 模型）→ 加载主机 I/O 请求流（块大小 512B-4KB、读写比、深队列并发）→ 运行模拟 → 得到 IOPS、延迟、GC 干扰等设备级统计，再喂给解析可行性框架（Sections III-V）确定可用 IOPS、break-even 阈值与系统可行性。
  - 模拟原理与输入→输出全过程（一次 512B 随机读的数据路径）：输入 = SSD 架构配置（通道/plane 数、NAND 时序、SCA、两级 ECC）+ 主机 I/O 请求流（块大小、读写比、队列深度）→ MQSim-Next 事件驱动推进：主机请求经 PCIe/TLP 进入 SSD → FTL 地址翻译（8B/条、控制器内部 DRAM 40GB/s、xlat 上限 ~5G IOPS，配置为非瓶颈）→ 后端 read-prioritized、plane-aware 仲裁将请求分配到某通道 → NAND 阵列 sensing（τ_sense=5μs，按 SCA 协议与 transfer-sense overlap 与其他请求的命令/数据搬运并发）→ 512B 数据从 4KB 物理页按扇区读出 → BCH 内码解码（512B 扇区级，命中即完成、跳过 LDPC，无读放大）→ 数据经通道、控制器、PCIe 返回主机 → 逐请求累计 IOPS/延迟 → 输出设备级 IOPS 及对读写比/通道带宽/ECC 失败率的敏感性曲线（Fig. 7）。作用：校准验证 Section III 解析模型（两者紧密吻合），并为 KV/ANN 两个案例研究提供设备级峰值 IOPS 与延迟行为输入（案例研究=解析框架 + MQSim-Next 设备特征 + 校准合成 trace 的组合）。
