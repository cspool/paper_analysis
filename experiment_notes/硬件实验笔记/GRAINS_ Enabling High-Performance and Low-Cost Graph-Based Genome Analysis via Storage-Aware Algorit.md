## GRAINS: Enabling High-Performance and Low-Cost Graph-Based Genome Analysis via Storage-Aware Algorithm-Architecture Co-Design

- 属于硬件架构的实现是什么？实验比较什么？
  - GRAINS 是面向大规模基因组图分析的存储中心计算（SCC）架构，在 SSD 内部实现并评估以下硬件单元：(1) 闪存 die 内的轻量 IFP 处理单元（PE）——实现两种功能：selection（按偏移从页缓冲抽取目标窗口，直接复用/重定向已有列解码与列选择电路，把目标窗口路由到 die 的 I/O 接口或内部 IFP 比较单元）与 comparison（小移位寄存器+位比较器，把 k-mer 与目标窗口逐位匹配）；避免把低复用或未使用部分页传出 flash die。(2) SSD 控制器上的轻量 ISP 单元与 FSM 控制单元——ISP 单元流式扫描 Colors Bitmap（每 channel 仅 2 个 32-bit 寄存器，不缓存进内部 DRAM）、调度/协调 IFP 操作并与主机和内部 DRAM 交互；FSM 在 GRNS_Steps 命令触发下驱动 SCC 内部执行流。(3) GRAINS Scheduler Table（GST）轻量调度——内部 DRAM 中每 Strings 页一行（页内位地址、k-mer minimizer 及其前后缀、full 标志+扩展表指针、one-hot plane 位图），round-robin 逐行读取并在所有 die/plane 上轮流发请求，天然合并同页访问、支持 multi-plane 操作，用极少元数据换取高 die 级并行。(4) FTL 集成与可靠性——块粒度 L2P 映射（1 TB 图仅 0.7 MB 元数据，对比页粒度约 4 GB），图数据/查询按 round-robin 均匀布放到 channel/die/plane 且 active block 跨 plane 页偏移对齐；采用 ECC_LITE + Bias Error Encoding 的轻量片上 ECC。
  - 实验比较：GRN（完整 SCC）vs Fulgor、MetaGraph、IdealAccMem、GRN-Ext（GRAINS 优化在 SSD 外）、消融 GRN-B/GRN-B-S，以及集成 SeGraM 的对齐流程；指标为吞吐/速度up、能耗（4.4–31.6× 能耗降 vs 软件基线）、面积与功耗（333 MHz 综合）、成本效率（低配 $ vs 高配 $$$ 系统）。关键结果：k-mer lookup 在 SSD-G4（G5）上 GRN 平均 8.4×（5.5×）超 FG、11.9×（8.5×）超 MG；GRN 平均 2× 超 GRN-Ext；GRN($) 平均 4.7×/5.2× 超 FG($$$)/MG($$$)。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - (i) MQSim（SSD 内部操作模拟器，https://github.com/CMU-SAFARI/MQSim，论文 References [432] 给出源码链接）；(ii) Ramulator 2.0（内部 DRAM 模拟器，https://github.com/CMU-SAFARI/ramulator，References [436]）；(iii) 论文自研组件级模拟器：建模 host 操作、内部 DRAM、flash die 访问、in-storage 硬件单元（on-die 与 on-controller）与 SSD-host 接口，把各组件的延迟/吞吐作为输入喂入；(iv) GRAINS 的 ISP/IFP 逻辑单元以 Verilog 实现，22nm 库 + Synopsys Design Compiler 综合（References [430][431]）。
- 模拟器模拟什么的性能，修改了什么。
  - MQSim 模拟 SSD 内部操作（channel/die/plane 访问、FTL、内部 I/O 调度、带宽利用），Ramulator 模拟 SSD 内部低功耗 DRAM 的延迟与带宽；自研模拟器负责把 host 侧与 SSD 侧时序正确组合（论文称时序组合细节在 extended version）。论文在 MQSim 中按 Table 1 的 SSD-G4/SSD-G5 配置忠实建模：16 channel、8 die/channel、4 plane/die、4-KiB 页、7/14.8 GB/s 顺序读带宽、1.2/2.4 GB/s channel I/O、4 TB 容量、4 GB 内部 DRAM。GRAINS 的 IFP PE、ISP 单元、GST 调度逻辑以 Verilog 综合结果（延迟/面积/功耗）作为输入；软件侧组件（查询准备、k-mer 提取、Sizes 查找、排序）在真实系统（EPYC 7742 + 1.5 TB DRAM）上实测。这是对 MQSim 之上新增 SCC/IFP/ISP 建模的定制模拟流程。

  - 模拟器使用流程示例（SSD-G4 配置上的一次 k-mer set lookup）：① host 侧在真实机器上运行 GRAINS 查询准备阶段（k-mer 提取、Sizes 查找、排序分批），实测该阶段耗时；② 把批次请求的访问序列输入 MQSim——请求按 GRAINS 块粒度 L2P 映射解析为物理地址（数据均匀分布在 16 channel × 8 die × 4 plane），模拟器按 FTL 调度与通道仲裁模拟每个读请求：die 读页→页缓冲→ECC_LITE→IFP selection/comparison→仅返回结果/命中窗口，输出 SSD 内部各阶段延迟与内部带宽利用；③ Ramulator 模拟内部 DRAM 上 GST 表与 Offsets/结果缓存的读写延迟（4 GB LPDDR4/DRAM 模型）；④ 自研模拟器把 host 段与 SSD 段延迟按流水线（一批排序 ∥ 上一批传输+查询）组合，输出端到端吞吐（queries/sec）与能耗；Verilog+22nm 综合给出 IFP/ISP 单元面积与功耗（on-controller 0.0025 mm²/0.21 mW，仅占 SSD 控制器 4 个 ARM 核面积的 0.7%；on-die ECC_LITE 0.036 mm²/18.04 mW，占 flash 芯片面积 0.2%；on-die 其他逻辑 0.000093 mm²/0.01 mW）。模拟原理：各组件按真实 SSD 时序参数（通道 1.2 GB/s、页大小 4-KiB、die 并行度）串起请求生命周期，把"低复用数据整页搬出"替换为"die 内处理、只回传结果"，从而量化消除外部/通道带宽浪费带来的加速。
