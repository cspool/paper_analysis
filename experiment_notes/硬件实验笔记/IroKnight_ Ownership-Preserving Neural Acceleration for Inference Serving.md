## IroKnight: Ownership-Preserving Neural Acceleration for Inference Serving

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 IroKnight NPU：一种 ownership-preserving（所有权保持）的 LLM 推理加速器，核心思想是让明文只短暂出现在 ALU 内部线网/组合逻辑门中（纳秒级闪烁），而所有片上存储（pipe-register、buffer、SRAM）与片外存储始终保持 AES-GCM 加密并带完整性保护，从而在接近 FHE 的加密所有权保证下避免其巨大开销。实现分两个 SystemVerilog 变体：(1) 仅加密（IroKnight w/ Encrypt）；(2) 加密 + 执行中认证（IroKnight w/ Auth）。两个变体都在一个 TPU-like NPU 基线上修改（Table I）：128×128 脉动阵列、128 个向量 lane、1 GHz、18MB scratchpad、16GB HBM（1TB/s 带宽、41ns 访问延迟）、128GB/s PCIe（双向）、INT8 精度。两个域特定洞察驱动设计：(a) LLM 细粒度 tiled/vectored 算子具有规则仿射访问模式 → 地址可知即可提前流水化预计算 pad（pad 生成与数据无关，只与 key/地址/版本号有关），把同周期 in-ALU 加解密降为纯 XOR、不增加关键路径；(b) AES-GCM 认证的 ⟨Galois-Field 乘, XOR 累加⟩ 结构与 GEMM 的乘累加(MACC)流同构 → 在脉动阵列/向量引擎里旁挂一条镜像认证路径，使 hash 与 MACC 并行计算、实现 mid-execution 完整性校验且几乎零运行时开销。
  - 实验比较什么：(1) 端到端运行时与能量 vs 明文 conventional TPU-like NPU（baseline，归一化基准）——输入 token 256→4096（图 6）、输出 token 256→4096（图 7）扫描；加密变体运行时开销 0.2%、能量 ≤14%，加密+认证变体运行时 3.3%（认证开销来自 hash 的片外读写流量）、能量 ≤18%；compute-only 能量加密提升 4.3×，但 LLM 能量以 HBM 访存为主（pad 生成 128-bit 仅 5.4 pJ vs HBM 读 508.2 pJ，差 94.1×），故总能量开销低；(2) 非 LLM 小网络 BERT/MobileNet-v2/ResNet-50/ViT（图 8）——计算密集型，能量开销升到 3.28×–4.68×；(3) 与 FHE NPU 对比（表 III/IV，基于 [9] SHARP 乐观建模）：FHE 运行时 713×–1793×、能量 871×–7396×，IroKnight 仅 1.001×–1.037× / 1.09×–1.18×；(4) 与 NPU TEE（基于 [49] MGX，off-chip 接口加解密引擎 + 片上 tile 版本号）对比（图 9）：tile 级 scratchpad 清除 19.6% 运行时/5.4% 能量、layer 级 5.1%/4.9%、无清除 2.8%/4.8%，而 IroKnight 3.3%/15% 且始终不暴露明文（TEE 无论是否清除都不保有所有权）；(5) 敏感性：内存带宽 1–4TB/s（图 10）、batch 1–16（图 11）、PE 数 32×32–256×256（图 12）；(6) 动态推理优化兼容性：投机解码（图 13，drafter 3/5 token、接受率 α 0–100%）与 token pruning（图 14，0–80%），加密/认证开销分别保持 0.2%–0.7% / 3.1%–3.7%。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟 conventional TPU-like NPU 的端到端推理延迟与能量：脉动阵列 GEMM + 向量引擎非 GEMM 算子全流水线执行、含编译器（tiling/fusion 等优化生成硬件可执行 kernel）与 KV cache 增长；端到端延迟 = 生成完整输出序列的总时间；能量 = 综合得到的 activity-level 能量（SRAM 用 CACTI 6.0，HBM2/PCIe Gen4 用 prior work 能量模型）。修改了什么：扩展模拟器显式建模 IroKnight 两种变体的全部微架构与内存级开销——in-ALU 加解密、pad 生成（PadGen 流水线填充延迟）、mid-execution 认证（hash 与 MACC 并行）、hash 的片外读写、片上 buffer 访问等；加密+认证时每数据块附带 hash 的尺寸比按 prior secure NPU 工作 [49]；神经编译器原始功能与优化保持不变，但用访问模式知识提供版本号与 pad 生成信息（版本号跟踪、pad 预计算）。综合侧修改：给 TPU-like NPU 加 PadGen 单元（AES-like 10 轮 key addition/S-box/row shifting/column mixing 生成 128-bit pad）、ALU 输入输出 XOR 行、Run-Ahead Index/Address Generator + Run-Ahead FIFO、认证的 ⟨GF-multiply, XOR⟩ 镜像路径；脉动引擎中 1 个 PadGen（128-bit/cycle）共享给 16 个 8-bit 操作数 PE，向量引擎中 3 个 PadGen 服务 4 组 memory-ALU 对（2×32-bit 源 + 32-bit 输出 = 96 bit，4 组共 384 bit = 3×128 bit）。

  - 模拟器使用示例与原理、输入→输出全过程（以 Llama3-70B、8 个 NPU、1024 输入/1024 输出 token、batch 1 的一次推理为例）：输入 = (a) 模型图（Transformer 层 → self-attention / expert router / expert FFN 子块，算子级 DAG）；(b) NPU 配置（Table I：128×128 阵列、128 lane、18MB scratchpad、1TB/s HBM）；(c) IroKnight 开关（仅加密 vs 加密+认证）与编译器提供的 tile 基址/stride/offset/版本号信息。处理流程：神经编译器对每个算子做 tiling/fusion 生成 kernel——GEMM 按 tile 分配到 128×128 脉动阵列（权重流经 Weight Buffer 下灌到各 PE），非 GEMM（缩放、softmax 分母的指数/求和/除法、Top-K）走 128-lane 向量引擎的仿射 walk；模拟器每个周期推进：Run-Ahead Index Generator 提前输出 WBUF 索引 → 索引同时喂给流水化 PadGen（10 轮 AES 结构、10+ 级流水，产生 128-bit pad）与 Run-Ahead FIFO（深度 = PadGen 流水级数，同步 pad 与 ALU 操作）→ 加密操作数从 WBUF/IBUF 读出后在 PE 内 XOR 解出明文、MACC 乘累加、结果 XOR 回加密写回 OBUF/pipe-register；认证路径与 MACC 并行：权重写 WBUF 时经 ⟨GF-multiply, XOR⟩ 立即算 hash，输入激活在首列 PE 逐 PE 下传部分 hash，输出激活在末行 PE 从左到右算 hash，加载 tile 时 hash 与存储的期望值比对、不符则报警；加密+认证时 hash 随 tile 进出片外存储产生额外 HBM 流量。KV cache 以加密形式缓存 K^T/V 供后续 token 复用，softmax 输出 tile 加密中间态在向量引擎 SIMD 处理。输出 = 端到端延迟（常规 NPU 21.88s / IroKnight w/ Encrypt 21.91s / IroKnight w/ Auth 22.58s，表 III）与端到端能量（681.6 / 750.1 / 784.1 mWh，表 IV），以及随 token 长度、带宽、batch、PE 数变化的归一化曲线。作用：无需流片即可验证"明文仅短暂存在于 ALU 组合逻辑、所有存储加密 + 完整性保护"这一新安全范式在 8 个真实 LLM（含 MoE：GPT-OSS-120B、Llama4-Scout）上保持 near-line-rate（加密 0.2%、加认证 3.3% 运行时开销），对比 TEE（3.3%/15% vs 清除式 19.6%/5.4%）与 FHE（1110× 运行时 / 2872× 能量量级）确立新的设计点；综合（Design Compiler + FreePDK45/OpenRAM + DeepScaleTool→7nm）给出面积/TDP：加密 1.79×/1.76×、认证 1.95×/2.18×（30W/9.4mm² → 52.9W/16.9mm² → 65.5W/18.4mm²），且关键路径保持在 SRAM 读路径、不降频。
