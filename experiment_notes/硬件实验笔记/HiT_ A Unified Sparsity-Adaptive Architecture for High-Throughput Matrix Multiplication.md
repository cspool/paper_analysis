## HiT: A Unified Sparsity-Adaptive Architecture for High-Throughput Matrix Multiplication

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 HiT，一个覆盖全稀疏度谱（HS/MS/D）的统一稀疏自适应矩阵乘法加速器（22nm @ 1GHz，峰值 32 TFLOPS FP32）。核心是三种数据流：(1) HSparse（针对 HS×HS/HS×MS/HS×D）——基于外积（outer-product）数据流，按列处理 Matrix A、顺序流式读取 Matrix B，消除 Gustavson 数据流的并发随机访存与 bank 冲突，用 Parallel Intersection & Distribution Unit (PIDU) 每周期匹配 4 个 A 非零与最多 64 个 B 非零（两层空间并行：列内多非零并行 + 列间多列并行），PSum Router + ring network 把 psum 路由到目标 Compute Row 归约，Dual-mode Accumulator (DMAccum) 以压缩格式（binning-compare-update）在片上累积稀疏 psum，利用 HS×HS 的高输出稀疏性；(2) MSparse（针对 MS×MS/MS×D）——同为外积数据流，但把 Matrix A 的行映射进单个 Compute Row，使 psum 立即在同一 Row 内累积（绕过 PSum Router 环网），Matrix B 元素经 cluster-local broadcast 通道每周期广播 64 个到 Cluster 内所有 Compute Row（部分同步，开销 ≤12%），复用 PIDU/DMAccum/Local Buffer；(3) 内积（inner-product）数据流——D×D 时关闭/时钟门控稀疏部件、power-gate Local Buffer，把架构重构为 128×128 2D systolic array（TPU-like）。
  - 实验比较什么：与 Trapezoid（首个大规模统一稀疏加速器，Gustavson 数据流）、TPU-like（现代 TPU MXU，合成估算）、Sigma-E/Flexagon-E（MS 专用，从 Trapezoid 缩放）、Spada（自适应数据流，开源模拟器缩放）、SpArch/OuterSPACE（HS 外积，GFLOPS 从 SpArch 缩放）比较 performance/area、能量、MAC 利用率、off-chip 流量、面积/功耗分解。结果：HS×HS 上 performance/area 比 Trapezoid 高 3.24×（geomean）、全部 workload 高 1.93×、能耗低 1.64×；HS×HS 的 MAC 利用率比 Trapezoid 高 3.46×、HS 下比 TPU-like 高 3933×；总体 performance/area 相对 TPU-like/Sigma-E/Flexagon-E/Trapezoid 分别高 66.5×/8.22×/5.84×/1.93×（D×D 因面积大比 TPU-like 低 1.23×）。
- 硬件平台是什么，配置是什么。
  - HiT 为 22nm @ 1GHz 片上加速器，峰值 32 TFLOPS（FP32）。层次结构：4 个 Compute Cluster（每 Cluster 32 个 Compute Row，共 128 Row）；每个 Compute Row 含 4 个 Compute Group（每 Group 32 个 FP32 乘法器 + 32 个 FP32 加法器，即 128 乘法器/加法器每 Row）、PIDU（4×(64 comparator & shifter)）、PSum Router、DMAccum（4×(32 FP32 adder & 512 comparator)）、11.4KB 8-bank register-file Local Buffer（每 bank 4 读 4 写，multi-ported）；Global Memory 16MB（512 SRAM bank、64B datawidth），整体 17.5MB 片上存储；off-chip HBM @ 2TB/s（3.9 pJ/b）。Compute Group 沿 y 轴经 ring network（点对点双向链接，每链接每周期传 psum+列索引对向量，4 个 ring buffer：up/down 各 6、multiplier 4、DMAccum 6）互连；HS 模式每 Row 经专属通道静态连接 4 个 Global Memory bank，MS 模式另接 cluster-local broadcast 通道，D×D 模式启用 systolic 连接。面积 166.3 mm²（22nm，Trapezoid 的 1.07×、TPU-like 的 1.82×），功耗 54.6–113.5W。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟每周期所有硬件部件活动（PIDU 索引比较、乘法器、PSum Router/ring 路由、DMAccum 累积、Local Buffer 读写、Global Memory bank、HBM 访存），忠实建模 contention 与 pipeline stall，输出各 workload 执行周期/延迟、MAC 利用率、off-chip 流量、能量（compute + HBM 3.9pJ/b）；面积/功耗来自 Verilog 综合（Design Compiler + PrimePower）与 CACTI。配置 flags 选择数据通路并建模静态数据流切换（reconfiguration 固定周期数、与矩阵大小无关，占执行时间 0.009% geomean）。修改了什么：论文自研模拟器，非修改开源工具；数据流按 sparsity 启发式（<10% HS、10-90% MS、>90% D）由用户在每个 dataset 选择一次。

  - 模拟原理与输入→输出全过程（以 HS×HS 的 p2p-Gnutella24 × M^T 为例）：输入 = (a) 稀疏矩阵数据（SuiteSparse .mtx；片上 COO-like 格式——非零元素显式存 tile 内相对行列索引，按列索引再行索引连续排列以匹配外积数据流顺序流式；off-chip 保持 CSR/CSC，流式时用轻量 converter [44] 在线转换；稠密矩阵用稠密格式）+ (b) 硬件配置（Table II：128 Row × 128 FP32 MAC、PIDU 4×(64 comparator & shifter)、DMAccum 4×(32 adder & 512 comparator)、Local Buffer 11.4KB、16MB Global Memory、HBM 2TB/s、1GHz）+ (c) 数据流选择（按密度启发式选 HSparse/MSparse/内积）+ (d) tiling 参数（HS×HS 默认用 bitmap intersection 采样选 tile 大小保证 psum 全进 Local Buffer；B 列交错平衡非零分布，缓冲需求降 14×；MS/D 按输出全进 Local Buffer 切 tile）。模拟推进：HSparse 下 A 沿列分 tile 映射到各 Compute Row、B 沿行分 tile，每周期每 Row 从专属 4 个 Global Memory bank 流式读最多 4 个 A 非零与 64 个 B 非零（无 bank conflict）；PIDU 4 级流水并行做列-行索引比较（每 Compute Group 64 比较器，HS×HS 交叠率 geomean 仅 0.12%），leading-zero count + 轻量 shifter（非 barrel shifter）把匹配 B 元素对齐到可用乘法器（匹配 >32 时 stall 新 A 读取）；乘法器输出送 PSum Router 检查行索引——本地则送 DMAccum、否则经 ring network 路由到目标 Row（buffer 满则 stall）；DMAccum 对 HS×HS 用 binning-compare-update（modulo 映射 bin、每 bin 2 项只比较候选：匹配→更新、空槽→插入、满→spill overflow buffer，行满→row-granularity spill 到 Global Memory 第二遍合并，平均 3.30% 输出行 spill、4.05% 开销），其他模式直接行列索引稠密累积。输出 = 每 workload 执行周期/延迟、MAC 利用率、面积（166.3 mm²）、功耗（54.6–113.5W）、能量、off-chip 流量。作用：在未流片情况下验证统一稀疏自适应架构在 27 个 SuiteSparse workload + Llama2-7B/ResNet50/VGG16（含 magnitude pruning 稀疏化）上的性能/面积与能效优势（3.24×/1.93× vs Trapezoid）。
