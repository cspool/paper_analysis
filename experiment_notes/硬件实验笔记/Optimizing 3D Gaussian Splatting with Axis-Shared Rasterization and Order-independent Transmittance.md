## Optimizing 3D Gaussian Splatting with Axis-Shared Rasterization and Order-independent Transmittance

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现：3DGS 专用加速器，核心是 16×16=256 个可重构 PE 的统一阵列（同时支持光栅化与 MLP 推理），配 X-PE 线/Y-PE 线（轴共享项预计算）、坐标生成器 CG（tile 调度）、GS-feature cache（每 GS 9 参数）、depth buffer（存深度 d_i 与衰减因子 F(d_i)，带宽需求不同故分置）、输出 buffer + 除法阵列（4 个 Div）。可重构 PE 含 6 MUL + 6 ADD + 1 EXP（FP16），MAC 分两组：M-{1~3}/A-{1~3} 独立工作、M-4-{1~3}/A-4-{1~3} 协作工作，MUX 控制切换光栅化/MLP 两种模式；广播寄存器 10 单元（光栅化模式用 5 个）。光栅化模式每周期处理一个 GS 对 16×16 tile 像素；MLP 模式每周期处理 256 个深度值、结果写回 depth buffer。Leaky ReLU 用符号检测 + 5-bit 整数加法器实现（对 FP16 指数减 3）。另设计 fine-grained interleaved pipeline（tile 细分为 subtile，光栅化当前 subtile 与下一 subtile 的深度装载/MLP 推理重叠，隐藏内存延迟）与 π 轨迹 tile 调度（Hilbert/格雷码启发的 8×8 tile block 内 π 轨迹、块间 S 轨迹，利用水平/垂直/层级局部性）。
  - 实验比较：四个硬件消融变体（同面积预算）：BS（常规 16×16 光栅化阵列 + 32 并行 bitonic 排序网络，参照 GSCore）、BS+AR、BS+AR+OIT、BS+AR+OIT+IP，吞吐提升 1×/1.37×/2.16×/2.27×（几何均值）；与 SOTA 加速器 GSCore/MetaSapiens/GBU 比较（均 28nm、1GHz、归一化同面积、同 Gaussian 削减技术）得 1.67~1.88×/1.49~1.52×/1.33~1.55× 加速；与 edge GPU（Jetson Orin Nano）比光栅化 4.6~7.9×（150+ FPS）、MLP-OIT 替换排序 21~119×（naive）~300×+（interleaved）、端到端 4.0~5.5× 加速与 16.2~31.9× 能耗节省；与 RTX 3090 端到端 1.1~1.4× 加速与 45.6~79.6× 能耗节省；相对 32 并行 bitonic 排序网络，MLP 推理 21.1~32.4× 加速；可重构（加 MUX）相对专用阵列仅 +5% 面积/+6% 功耗/2 cycle 延迟，相对 naive 双阵列方案 1.91× 面积效率（吞吐/面积）与 1.89× 能量效率（吞吐/功耗）；π 轨迹相对无 cache/baseline 轨迹/Z 轨迹分别 2.56×/1.51×/1.23× off-chip 访问能耗节省（命中率 43%→55%→62%）。

- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 无独立全系统模拟器；论文用自研 cycle-accurate simulator 评估延迟与访存流量（与 RTL 仿真结果交叉验证）。DDR5-4800 DRAM（38.4 GB/s）用 Ramulator [24]（https://github.com/CMU-SAFARI/ramulator）建模，on-chip SRAM 面积/能耗用 CACTI [35]（https://github.com/HewlettPackard/cacti）估算，总能耗（on-chip + off-chip）用 DRAMPower [3]（http://www.drampower.info）估算。RTL 用 SystemVerilog 实现、Design Compiler + TSMC 28nm 库综合、FP16 算术基于 DesignWare IP [43]（https://www.synopsys.com/designware-ip），设计全流水、1 GHz。
- 模拟器模拟什么的性能，修改了什么。
  - Ramulator 模拟 DDR5-4800 的时序/带宽（38.4 GB/s），输出 off-chip 访存延迟与带宽受限情况；CACTI 估算 on-chip SRAM（GS Feature 88KB + Output 4KB + Depth 4KB = 96KB）的面积与每访问能耗；DRAMPower 结合 Ramulator 的访存命令流估算 DRAM 功耗。论文自研/修改的是 cycle-accurate simulator（论文未开源、未说明基于什么框架修改，论文未明确说明）；加速器 RTL 由论文团队自行编写（SystemVerilog），未开源。

  - 开源情况：加速器 RTL 与 cycle-accurate simulator 未开源；代码仓库 https://github.com/WangZhican/ISCA26_3DGS_Acc 目前仅含 MLP-based_OIT 的 CUDA 算法实现。评估工具链（Ramulator/CACTI/DRAMPower）均开源。使用例子（以 Ramulator 为例）：输入为 DDR5-4800 配置（通道/rank/bank/时序参数）与访存 trace（cycle-accurate 模拟器产生的 DRAM 读写请求流）→ Ramulator 按 DRAM 协议逐命令模拟 bank 状态机与预充电/激活/读写时序，输出每请求延迟与带宽利用率 → 与 RTL 仿真交叉验证的 cycle-accurate 模拟器累计总 latency/memory traffic；CACTI 输入 SRAM 容量/工艺(28nm)/端口数输出面积与每访问能耗；DRAMPower 输入 Ramulator 的访存命令流输出 DRAM 功耗。三者合计得到表 II 面积/功耗分解（可重构 PE 阵列 2.958mm²/1.48W、支持模块 0.064mm²/0.02W、片上缓冲 0.826mm²/0.14W，总计 3.85mm²/1.64W）以及 Fig. 13-18 的吞吐/速度/能耗对比。加速器输入到性能输出全过程：输入场景 Gaussian 特征与相机位姿 → projection 在 edge GPU 执行（论文把其延迟/能耗计入端到端）→ 加速器按 π 轨迹调度 tile → X/Y-PE 线算轴共享项广播给 16×16 阵列 → 每周期一个 GS 的光栅化/MLP 推理 → α-blending 累加 → 除法阵列归一化输出像素，最终给出 FPS/吞吐/能耗指标。
