## Cassandra: Enabling Reasoning LLMs at Edge via Self-Speculative Decoding

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 Cassandra encoder/decoder 硬件 IP（SystemVerilog 实现，Synopsys Design Compiler 28nm 综合）及其与 GPU/NPU 内存系统的集成：GPU 中 decoder 置于 L2 cache 与 interconnect 之间、encoder 置于主存与 L2 之间（每内存分区独立一组，由 memory controller 管理，类似 L2）；NPU 中 encoder/decoder 置于 DMA 内由 DMA controller 管理（NPU 无虚拟内存，物理地址区间预存于 DMA controller）。decoder 微架构：mantissa concatenator（拼接截断 mantissa 高低位）→ dynamic shifter（等待指数解码）→ parallel zero counter（8-bit 分块并行数 0 + 跨 chunk 进位修正，Algorithm 1）→ LUT unary 解码（Cassandra-1）；MX 路径（Cassandra-2）：指数经 crossbar 广播到各元素 accumulator，parallel zero counter 数 mantissa 前导 0 决定移位量与指数减量，再经 dynamic shifter 移位。最后均做 bitmap-based de-sparsification 按 bitmap 补 0 输出标准 FP。encoder 微架构：输入数据 top-k 分组为 speculation/verification 两组，verification 组连同 bitmap 直接入 buffer，speculation 组做指数压缩 + mantissa 截断后入 buffer 写主存（权重离线格式化，encoder 主要用于 KV cache 在线格式化）。配套 superblock-based data management：以多个 cache block 组成的 superblock 为加载/驱逐单位，bitmap、变长指数、mantissa 混装打包；decoder 内部 buffer 缓存跨 block 余量并拼接，buffer >128B 时 memory controller 跳过该类型 block 并记账下一次应送的地址，保证连续访存与稠密映射（scratchpad 型 NPU 用任意 block 尺寸同样适用）。
  - 实验比较：Cassandra-1/Cassandra-2 集成后归一化性能 vs BF16 baseline（图 12：RTX 4090 / Jetson AGX Orin / 64TFLOPS NPU × 4 benchmark，1.78×–2.41×）；面积功耗 vs 64TFLOPS NPU 各模块（Table V：encoder 0.08mm²/0.1%/0.017W，decoder 1.76mm²/1.9%/0.264W，合计约 2% 面积开销；NPU 配 40 个 decoder 保证 1024B/cycle scratchpad 带宽不被解码拖慢）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - GPU：Accel-Sim（https://github.com/accel-sim/accel-sim-framework ，论文引用 [18]），在其中实现 Cassandra encoder/decoder；NPU：扩展 Scale-Sim（https://github.com/ARM-software/SCALE-Sim ）与 LPU simulator（论文引用 [21],[36],[53]）的自研 cycle-level 模拟器。综合工具：Synopsys Design Compiler（28nm）+ Samsung 28nm SRAM Compiler（SRAM 面积）。
- 模拟器模拟什么的性能，修改了什么。
  - Accel-Sim 模拟 Ampere 架构 GPU cycle-level 执行（论文用 Ampere trace + 近似 RTX 4090 配置，因 Accel-Sim 不支持 Ada-Lovelace；另模拟 Jetson AGX Orin）；修改：在 L2↔interconnect 间插入 Cassandra decoder、主存↔L2 间插入 encoder，模拟压缩权重/KV 从主存经 decoder 解压供给 SM 的周期开销与带宽收益。Scale-Sim/LPU 扩展模拟 systolic array NPU（64 TFLOPS MAC、273 GB/s、128GB LPDDR5X、9MB scratchpad），修改为 DMA 内 encoder/decoder 的格式转换数据通路。模拟器输出每 token cycle 数，与实测接受率结合换算吞吐增益。

  - Cassandra 的 RTL 与修改版模拟器：论文未提供开源链接，无法确认；Accel-Sim、Scale-Sim 本身开源（链接如上）。使用流程示例：(1) 用 PyTorch+CUDA 软件模拟器对模型做格式变换（Wanda 校准约 128 样本、grid search 剪枝 30–60%/截断 0–5 bit），产出 speculation/verification 超参数（默认 40% 剪枝 + 4-bit 截断）与接受率；(2) 在 Accel-Sim 上回放 Ampere trace，权重/KV 读取路径经 Cassandra decoder（superblock 加载 → parallel zero counter 解析 unary 指数 → LUT → bitmap de-sparsification → 标准 FP 数据进 SM），得到每 token 周期数；(3) 结合 4 个 benchmark 场景（LiveCodeBench、GPQA-Diamond、Longbench、Math-500）的平均输入/输出长度与接受率，换算总吞吐增益 1.78×–2.41×。面积功耗流程：SystemVerilog 实现 encoder/decoder + 自研 64TFLOPS NPU（systolic array、VPU、DMA、scratchpad）→ Design Compiler 28nm 综合 + Samsung SRAM Compiler → Table V 分模块面积/功耗对比。
