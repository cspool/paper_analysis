## MLX: Multi-Layer Execution for Structured LLM Workload Acceleration on Spatial Architectures

- 属于硬件架构的实现是什么？实验比较什么？
  - 属于硬件架构的实现：**MLX 空间数据流加速器（Multi-Layer Execution）**——面向混合化（FFT-CMP + hierarchical BSMM）LLM 结构化算子执行的空间阵列。核心概念 **Closed Dependency Components (CDCs)**：把算子数据流图 G=(V,E) 拆成"对入边封闭"的子图 C（∀v∈C: 前置依赖⊆C∪In(C)），每个 CDC 有固定输入/输出接口（只由模板参数如蝴蝶宽度或 MM/CONV 块形状决定，不随问题规模增长），重复的 CDC 实例可复用同一 tagged-block 模板。结构化算子（FFT、BSMM、block MM、sliding-window attention）都被形式化为**前向分层 CDC 层 {C_0,...,C_K}**（层内边或到下一层边），据此把深层逻辑算子**折叠（fold）**到紧凑物理阵列上、解耦逻辑深度与物理阵列大小。硬件支撑：(1) **Skip-hop NoC**：4×4 网格，每 PE 带固定距离直连链路（覆盖蝴蝶 stride ±2,±4,±8...），hop-encoded 数据搬运原语（xfer 指令带残差 hop 数、方向、目标寄存器），无状态路由器按最大可用步长转发，单/两跳完成跨层传输，无路由表/虚拟通道。(2) **Tagged block 指令**：每逻辑层编码为短静态指令序列+loop trip count 的 tagged block（LD 在头、COMP 在中间、XFER 在尾），PE 重放 block 覆盖所有 CDC 实例，指令存储与层数解耦（4×4 网格每 PE 32 条指令即满足覆盖条件）。(3) **解耦流水 PE**：每个 PE 分 4 条独立流水（memory 移动、dataflow 传输、异构算术），以层粒度调度，active-window 内不同折叠层同时处于不同流水阶段（一层加载、一层计算、一层转发），tag 仲裁（优先小 tag + round-robin），实现粗粒度混合调度（层内静态确定、跨层 tag 级弹性）。实验比较什么：(a) 与 Jetson Xavier（同 12nm、峰值算力相近 1.7 TFLOP/s vs 1 TOp/s）比较 Llama2-7B 八类 kernel：蝴蝶稀疏 kernel 3.1× 加速、3.2× 能量节省（对比 Xavier dense TensorCore kernel），稀疏 CUDA 执行上平均 3.2× 加速、3.1× 能量节省；端到端稀疏模型 vs 稠密模型 3.2× 加速，Xavier 因 16 GB 内存无法支持 >512 token 而 MLX 可到 2048。(b) reduced 256 GOp/s 版本（模拟器）与先验稀疏加速器 FABNet（FPGA 16nm）、SpAtten（40nm）、DOTA（22nm）、Sanger（55nm）、ViTALiTy（28nm）、BitVert（28nm int8）比较（单 Transformer block，N=1024,D=512）：s=0.75/0.5 下相对前三个动态稀疏加速器 2.93-4.10×/4.14-5.8× 加速；vs ViTALiTy 1.28×/1.81×；vs BitVert 2.3×；FABNet 重实现（同模型参数）1.19-1.30× 端到端加速、1.14× LUT 开销（2D-FFT attention 1.11-1.23×，BSMM-FFN 1.21-1.31×）。(c) 与 AGX Orin / RTX-3090 的 structured-workload sweep（batch 32）与 roofline 利用率：蝴蝶结构化算子 MLX 52-84% vs Orin 12-29% vs RTX 8.2-31%；SWA 43-75% vs 10.8-31%/8.9-28%。(d) 可扩展性：SIMD 8/32-way × mesh 4×4/8×8 四组合，均近线性，SIMD 3.9×、mesh 3.6×、联合 14×（N=512-8K,D=512,batch 8）。
  - 硬件配置：MLX 全设计 = 4×4 网格、32-way SIMD、FP16、12nm @1GHz（Synopsys DC 综合、Verilog RTL，从真实流片通用 dataflow 设计裁剪），峰值 1 TOp/s FP16，PE 阵列 7.712 mm²/5846.4 mW（FU SIMD32 0.298 mm²/252.4 mW 占 70%，skip-hop PE 开销 6.2%，PE 阵列功率 5846.4 mW）；reduced 设计 = 8-way SIMD、256 GOp/s、0.772 mm²/433.8 mW（约占原始芯片 10% 面积/8% 功率，去掉 vector shuffle/除法/高精度浮点单元）。设计参数原理：SIMD≥8（n≥8 蝴蝶稀疏才有效，GEMM 需 n≥4 保复用）；4×4 mesh + 每 PE 32 条指令（覆盖条件 B_T·C ≥ T_load+T_xfer）；FP16 为最小稳定精度（sub-FP16 蝴蝶累加不稳定）；支持 8192 点 FFT（4096 个 twiddle 因子）；超越函数单元每 PE 一个、仅为 SIMD 宽度 1/4。transformer 全算子（RMSNorm、位置编码等）经指令驱动可编程性 + 全设计的 vector shuffle/超越函数单元支持。

- 模拟器模拟什么的性能，修改了什么。
  - SimICT 模拟 MLX reduced 设计（4×4 网格、8-way SIMD、256 GOp/s、12nm）在混合 LLM 结构化算子（FFT-CMP、hierarchical BSMM、sliding-window attention、dense MM 折叠）上的周期与功耗，用于与先验稀疏加速器（FABNet/SpAtten/DOTA/Sanger/ViTALiTy/BitVert）对比。SimICT 组件化设计（component-based）+ 自动并行/松弛同步加速仿真，集成性能与功耗模型；论文在其上建模 MLX 的 skip-hop 网格、tagged-block 调度、解耦流水与 scratchpad（SIMD-striped 行布局、列向序列轴 N / 行向隐藏轴 D 两种访问模式，V=8 行宽）。

  - 使用例子（基于论文描述 + SimICT 论文定位）：SimICT 以组件方式组装目标系统（各 PE 的 memory/compute/transfer 流水、skip-hop 路由、scratchpad 与 DRAM 模型），用图形配置接口搭建 4×4 网格；配置/输入包括：算子 kernel（BSMM 的 stride±2/±4/±8 蝴蝶层、chunked FFT 的 L 点变换、SWA tile、折叠 MM）、tagged block 指令序列与 loop trip count、CDC 到 PE 的静态放置、(Δx,Δy) 路由类、批大小与序列长度（N=512-8K,D=512,batch 8）；模拟器按 cycle 推进：LD 流水从 SIMD-striped scratchpad 取数（列向 SIMD lane 对齐序列轴 N 做 BSMM、行向流式隐藏轴 D 做 FFT）→ COMP 流水在 FU 上执行 FMA 等 → XFER 流水经 skip-hop 网格按残差 hop 数向目的 PE 转发 → tag 仲裁调度 active-window 内多层的相位重叠；输出各 kernel 的周期数、PE/FU 利用率（BSMM/FFT 计算利用率约 90%、kernel launch 开销 17%→<12%）、DRAM 流量与功耗（结合综合报告），汇总为相对各基线的加速比、roofline 利用率（P_achieve/min(P_peak, OI·BW)）与能量节省。
