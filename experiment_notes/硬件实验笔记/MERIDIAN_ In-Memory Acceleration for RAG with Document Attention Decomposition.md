## MERIDIAN: In-Memory Acceleration for RAG with Document Attention Decomposition

- 属于硬件架构的实现是什么？实验比较什么？
  - 属于硬件架构的实现：MERIDIAN 去中心化 PIM 加速器（与 document attention decomposition 协同设计）。系统级基于 CXL 3.0 协议：多个 PIM 设备经 CXL switch 挂到 host（Type-3 模块，经 CXL.mem 用标准 load/store 访问），CXL switch 同时提供 host-device 连接与 device-to-device 直连（绕开 host 降低延迟）。PIM 设备统一设计但逻辑分为两个 cluster：Document Attention Cluster（DAC，执行文档注意力）与 Context Execution Cluster（CEC，执行 query-response 注意力、融合与全部其余模型算子：QKV 投影、FFN、LN）。设备内部含 CXL 控制器 + 多个 LPDDR-PIM package（每设备最多 8 个，每个由 8-channel PIM 控制器管理，128-bit 总宽，每 channel 4 个 16-bit DRAM die），LPDDR5X die 每 die 16 Gb、16 banks/4 bank groups、每设备最高 512 GB，32 设备共 16 TB。
  - 核心微架构：(i) **PIM Unit (PU)**——每个 LPDDR bank 旁放置，All-Bank-Mode 设计（DRAM 命令广播到所有 bank 同地址，利用 bank 级并行最大化内部带宽，连续 column 命令间隔受 t_CCD_L 限制）；每 PU 消费 256-bit（16 FP16）输入，含 16 个 FP16 比较器（非线性区间选择）+ 16 个 FP16 乘法器 + 16 个 FP16 加法器（可重构 reduction/elementwise-add）+ 4 个双缓冲 4KB buffer；breakpoint 与非线性参数存于 DRAM array。(ii) **Controller-Side Unit (CU)**——每 PIM 控制器每 channel 一个 Near-Memory Unit (NMU)：加法单元（channel 内 reduction 与逐元素累加）+ 专用 softmax 单元（完整 softmax 流水、高吞吐、数值稳定）；CXL 控制器内 8 个 BOOMv2 RISC-V 核做跨 channel/跨设备聚合与轻量控制。
  - 资源高效子设计：(a) **Skinny GEMM 实现**——LPDDR 功率/带宽受限下不复制完整 GEMV 数据通路（对比 PAPI 的 full-unit 复制），只复制 buffer 结构（约占 GEMV 单元面积 14% [49]）而共享算术单元，实现 weight reuse 且面积/功耗小；DRAM 访问占能耗 >96% [16]，更大 buffer 提升 row locality、降低 row-switch 开销。(b) **非线性函数**——不用外部引擎，在内存侧流水用分段线性逼近 y=ax+b（每函数几十段，输入区间细分、高曲率区域更细），breakpoint 比较 + 单次乘加，复用 GEMV 算术单元；GeLU/Swish 等用 LUT 逼近，数值敏感的 softmax 用专用精度硬件。
  - 调度器（硬件协同软件）：host 侧统一调度器，初始化时按 tensor/pipeline/hybrid 并行策略静态分配模型层到设备，运行时按设备负载动态下发推理任务。tensor 并行下 CEC 的 FC 层跨设备分片（轻量算子集中到主设备并保 KV cache），DAC 按 attention head 分配文档 KV（每 head 分配到最少设备避免广播）；pipeline 并行把 decoder 分多 stage、micro-batch 流水；混合并行对跨设备 stage 内部做 intra-stage tensor 并行。**Interleaved Cluster Execution (ICE)**：动态在空闲 cluster 上启动后续 batch，消除 DAC/CEC 时序失衡；残余失衡用动态负载迁移——初始化时把部分 CEC 参数静态复制到 DAC，DAC 空闲时协助上下文计算（两 cluster 微架构同构，迁移开销可摊销）。
  - 实验比较什么：与两类共五个 baseline 对比：CPU-GPU 系统 TurboRAG [44] 与 BlockAttention [46]（文档 KV 存 CPU 内存、计算全在 GPU）；PIM 系统 CENT [14]（GDDR6，仅支持 GEMV+轻量激活，GEMM 拆成多次 GEMV）、PAPI [16]（HBM 异构，Attn-PIM/FC-PIM/GPU，2:1 设备比）、HeterRAG [40]（HBM-DIMM 端到端 RAG）。指标：吞吐、延迟、阶段分解（通信/prefill/decode）、能量效率、准确率、面积开销、扩展性（OPT-66B、4→32 设备、pipeline vs tensor 并行：32 设备时 4.19× vs 3.68×）、长 query 通用性。面积：10nm DRAM 工艺每 PU 0.15mm²（算术 50.5%/buffer 34.9%/控制 14.6%），每 die 16 个 PU 共 2.41mm²，仅占 47.53mm² LPDDR5X die 的 5.07%；7nm 逻辑下 16-lane FP16 加法单元 0.02mm²、softmax 单元 1.38mm²、每个 BOOMv2 核 2.94mm²。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 论文扩展 **Ramulator 2.0** [45] 构建周期精确模拟器。链接：https://github.com/CMU-SAFARI/ramulator2（MIT 许可，现代、模块化、可扩展、快速的 cycle-accurate DRAM 模拟器，论文 IEEE CAL 2023，arXiv:2308.11030）。所有算术单元用 Verilog 实现并经 Synopsys Design Compiler 28nm 综合；DRAM die 内的 PIM 逻辑按 10nm-class（1z-nm）DRAM 工艺缩放面积/功耗并乘 10× 保守膨胀因子（逻辑 vs DRAM 工艺效率差 [12]）；controller-side 单元按 7nm 建模；SRAM buffer 面积/功耗按 AttAcc [49] 估计；DRAM 能量用 Micron LPDDR5/LPDDR5X datasheet 参数 + DRAMPower [8]（集成进 Ramulator）计算。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 MERIDIAN 端到端 RAG 推理的吞吐、每请求延迟、通信/prefill/decode 阶段分解与能耗。修改内容：基于 Ramulator 2.0 的 DRAM 模拟框架扩展出 32 设备 PIM 系统模型——加入 LPDDR5X 时序参数（t_RC=60/t_RAS=40/t_CL=23/t_RP=20/t_RCDRD=17/t_RCDWR=8，8.5 Gb/s/pin，128 channels）、CXL 3.0 over PCIe Gen5 ×16 链路（128 GB/s/链路、端到端 165ns 延迟、switch 处按活跃设备共享带宽并串行化超限传输）、每 bank 16-lane PU（1 GHz，32 TFLOPS/设备）、NMU/softmax 单元/BOOMv2 核、DAC/CEC 集群划分、tensor/pipeline/hybrid 映射与 ICE 调度/动态负载迁移，并把 DRAMPower 集成进 Ramulator 计算 DRAM 能量。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：MERIDIAN 本身未开源（截至 2026-08 未找到公开仓库）；其基础模拟器 Ramulator 2.0 完全开源（MIT）。Ramulator 2.0 构建于"interface + implementation"模块化架构：组件经 class registry 注册、用 YAML 配置文件实例化（无需样板代码），支持 DDR3/DDR4/DDR5/LPDDR5/HBM2/HBM3/GDDR6，内存控制器插件（RowHammer 缓解等），可与 gem5 集成，提供 C++ 与 Python 绑定。
  - Ramulator 2.0 使用例子（通用流程）：`mkdir -p build && cd build && cmake .. && make -j` 构建；`python3 examples/example_config.py` 生成配置并运行；配置 YAML 指定 DRAM 标准/时序、控制器策略、前端（trace/gem5/Python 生成请求流），模拟器对每个内存请求按 DRAM 命令协议（ACT/RD/WR/PRECHARGE）在 cycle 级推进状态机（bank/row/bank-group 状态、t_CCD_L 等时序约束、控制器调度），统计带宽利用率/延迟/能量。
  - 论文中模拟器输入→性能输出全过程：以配置（32 PIM 设备、LPDDR5X 时序、CXL 链路带宽/延迟、模型层到设备/head 到设备的映射、请求/批量到达流、KV 分片布局、ICE 调度策略）为输入；Ramulator 2.0 扩展在 cycle 级模拟各设备的 PIM 命令流——host 经 CXL.mem 发 load/store 与 PIM 命令（PIM_MAC/PIM_CMP/PIM_EW_MULT/PIM_EW_ADD 及 PIM_ACT/PIM_WR_PB/PIM_RD_PB）到 channel/PU，PU 以 All-Bank-Mode 在 bank 内完成 GEMV/skinny-GEMM/非线性，NMU 做 channel 内 reduction 与 softmax，BOOMv2 核做跨设备聚合，CXL switch 处按活跃设备共享链路带宽并串行化超限传输（contention 建模）；输出各阶段（communication/prefill/decode）周期与能耗，汇总为吞吐（tokens/s）、每请求延迟、通信占比（MERIDIAN 通信占比 ≤6.34%，baseline 最高 93.40%）与能量效率（相对 CPU-GPU 7.48×/9.24×，相对 CENT/PAPI 4.48×/4.54×）。
