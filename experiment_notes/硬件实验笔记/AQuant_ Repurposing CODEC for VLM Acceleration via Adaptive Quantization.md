## AQuant: Repurposing CODEC for VLM Acceleration via Adaptive Quantization

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为增强版视频 CODEC + 混合精度 NPU 的 SoC 级 RTL：增强 CODEC 复用 H.265 ME 模块的 subtract-and-abs 归约树做指数相似检测——提取 FP token 指数、移位求 2^exponent、拼 sign 后做 INT10 减法；ME PE 阵列改为可重构（4×4 PE 为最小块，⌈M/16⌉ 块合并成逻辑大块，适配 16/32/64 候选 base token；配套 4 级比较树 + 可级联 2 级比较树），(T^i,T^j) 对写入 similar token table。量化数据路径扩展为自适应模式：delta 与 scale 的 mantissa 从 23 bit 截断到 16 bit 后复用 CODEC 现有乘法器/加法器，sign 走 XOR 门，结果不归一化直接进 fp-to-int 单元（2 个 2-to-1 MUX + 1 个 7-to-1 MUX + 1 个 32-to-1 MUX + AND 门 + 16 个寄存器），bitmask 由 top-k QuickSelect 单元（3 个 FIFO + 4 组比较器 + OR/XOR + 2-to-1 MUX）按 p 阈值生成。NPU 含 4×32×32 INT2×INT16 低精度 MAC 阵列 + 1×32×32 INT4×INT16 高精度 MAC 阵列（1:4 配比对齐 p=25%），row-wise product 数据流，两阵列 lockstep 并行；结果重构引擎 3 个 on-chip buffer（base 128×128/16KB/256B、delta 64×128/8KB/128B、recovery 128×128/16KB/256B）按 similar token table 并行取特征相加，减少 off-chip 流量。
  - 实验比较：GPU-Full（Xavier 按面积预算缩放）、GPU-Full-unscale、GPU-Mixed-precision（假设原生混合精度 GPU）、GPU-AQuant、GPU-VisPruner、LLM.265、CMC、OliVe，及组合 AQuant+VisPruner、AQuant+CMC；消融 AQuant-plain → AQuant-FP → AQuant-Exp → AQuant-CODEC。指标：加速比、能耗效率、面积/功耗分解（Design Compiler）、执行 cycle 分解、prefilling/decoding 分阶段延迟。
- 硬件平台是什么，配置是什么。
  - RTL 用 Verilog 实现，Synopsys Design Compiler 综合，28nm 工艺、500MHz；外部内存 LPDDR4x 32GB、带宽 136.5 GB/s（与 NVIDIA Jetson AGX Xavier 相同配置）。面积/功耗（Table III）：低精度 MAC 阵列 0.476mm²/164.8mW，高精度 MAC 阵列 0.238mm²/82.4mW，重构引擎 0.183mm²/9.3mW，NPU on-chip buffer 0.675mm²/197.4mW，增强 CODEC 的 ME 模块 0.138mm²/23.4mW、量化模块 0.122mm²/21.3mW、CODEC buffer 0.026mm²/11.9mW。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 自研 cycle-level 模拟器（论文未给出名称与链接），集成 Ramulator（DRAM 时序，https://github.com/CMU-SAFARI/ramulator），建模方法参考 Scale-Sim（https://github.com/ARM-software/SCALE-Sim）；CODEC 部分基于修改 OpenASIC（H.265/HEVC encoder IP core v2.0，http://openasic.org/topic/71/h265-video-encoder-rtl-ip-core-version-2-0）；片上 buffer 用 CACTI 7 估算能量/面积；RTL 综合用 Synopsys Design Compiler。
- 模拟器模拟什么的性能，修改了什么。
  - cycle-level 模拟器采集各 workload 矩阵乘法的 latency 统计与 buffer 访问次数，Ramulator 提供 DRAM 时序；未开源故修改点无法逐条确认，论文声明参照 Scale-Sim 方法论校准。OpenASIC 被修改用于仿真增强 CODEC（论文未披露具体改法细节）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - AQuant 自研模拟器与 Verilog 源码论文未明确说明是否开源；依赖工具均开源（Ramulator、Scale-Sim、CACTI 7、OpenASIC 参考 IP）。基线 CMC/LLM.265/OliVe 由作者复现算法并自建 cycle-accurate 模拟器；GPU 实测跑 PyTorch 于 Jetson AGX Xavier。
  - 模拟原理与全过程：输入 = 3 个 VLM（LLaVA/VideoLLaVA/Qwen2.5-VL 72B）× 14 个数据集 benchmark 的层定义与 tensor 形状/数据流映射 + 面积/功耗配置（DC 综合 netlist 参数、CACTI buffer 参数、LPDDR4x 时序）。模拟器逐周期推进流水：off-chip 读视觉 token → 增强 CODEC ME 模块指数相似检测（INT10 减法 + 比较树）→ 量化模块 fp-to-int + top-k bitmask 生成 INT2/INT4 delta → 按 bitmask 路由到 NPU 高低精度 MAC 阵列（row-wise product 并行执行）→ 累加引擎 → 重构引擎查 base buffer + 加 delta buffer 恢复 FP 激活；解码阶段 KV-cache 重新量化后写 off-chip、使用时在线重构。输出 = 各阶段 latency 统计与 DRAM 访问次数 → 折算相对 GPU-Full 的加速比、能耗效率（pJ/bit 级）、执行 cycle 分解（ME/量化/重构分别占 MAC 阵列的 47.8%/24.3%/7.8%，被流水线隐藏）。
  - 效果：平均加速比 vs GPU-Full 6.9×、vs GPU-Full-unscale 2.1×、vs GPU-Mixed-precision 2.2×、vs GPU-VisPruner 2.8×、vs OliVe 2.5×、vs LLM.265 4.6×、vs CMC 2.8×；AQuant+VisPruner 8.3×；AQuant+CMC 相对 CMC 再 3.4×；CODEC 同时解码视频时（AQuant-Decoding）仍 6.8×（视频解码仅占 8.3% 端到端时间）。能耗效率 vs GPU-Full 7.2×、vs LLM.265 14.0×。消融：AQuant-FP 3.3× → AQuant-Exp 1.6× → AQuant-CODEC 1.4×（CODEC 面积 0.26mm² vs 等价 MAC 0.714mm²，省 36% 面积转投 NPU 算力）。
