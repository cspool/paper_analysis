## LIPPEN: A Lightweight In-Place Pointer Encryption Architecture for Pointer Integrity

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 LIPPEN 全指针加密（full-pointer encryption）硬件加速器：把 64 位指针整体当作密文块，用低延迟轻量级分组密码 PRINCEv2 以 ECB 模式加/解密（seal: cipher = Enc_{k⊕m2}(plain ⊕ m1)；unseal: plain = Dec_{k⊕m2}(cipher) ⊕ m1，m = m1||m2 为上下文 modifier），解引用时透明解密并校验（解密后未用高位须为全 0，否则抛异常标志），实现完整性+机密性且零元数据开销。RTL 为 PRINCEv2 加密引擎，通过 Rocket Custom Coprocessor (RoCC) 接口挂接到 Rocket（顺序）与 BOOM（乱序）64 位 RISC-V 核；新增 ISA：SET_KEY(K1,K2)（128-bit 密钥）、SET_M_SIZE(conf)、PTR_SEAL(ptr,mod)、PTR_UNSEAL(ptr,mod)，语义对齐 Arm PAC 的 PAC*/AUT*。
  - 实验比较：LIPPEN vs in-house RISC-V PAC baseline（QARMA 认证加速器，同样挂 RoCC）+ Apple M1 商用 PAC（arm64e）。指标：运行时开销与动态指令数（相对未插桩 baseline 归一化）、FPGA 资源（LUT/FF）、最高频率、后综合功耗。benchmark：返回地址保护与数据指针保护的定向微基准（pointer-chasing 负载链）、nbench、SPEC CPU2017 rate；另测 PacTight 移植兼容性。
- 硬件平台是什么，配置是什么。
  - AMD/Xilinx VCU118（Virtex UltraScale+）FPGA，Xilinx Vivado 2021.2 综合，Rocket 与 BOOM 均以 100 MHz 运行；系统由 Chipyard v1.8 构建，Linux 镜像由 FireMarshal 管理。Rocket 与 Large BOOM 默认配置；LIPPEN 配置 M1=16 bits、M2=0（16 bit 足以区分全部指针上下文）。FPGA 资源/功耗（100 MHz）：Rocket-LIPPEN 58,137 LUT/42,100 FF（核心 30,837/14,793，RoCC 加速器 1,034 LUT/131 FF），Fmax 99 MHz，4.035 W；BOOM-LIPPEN 248,416 LUT/98,674 FF（RoCC 862/193），Fmax 90.6 MHz，5.625 W。对比 Rocket-PAC（QARMA）RoCC 2,071 LUT，Fmax 89 MHz；Rocket-base 150 MHz/3.935 W。RoCC 接口本身是频率下降主要来源，QARMA 比 PRINCEv2 多约 1 倍 RoCC 逻辑。
  - 密码引擎后实现对比（Table III）：QARMA-unrolled-verilog 1,794 LUT/1 cyc/40 MHz；PRINCE-unrolled 1,378 LUT/41 MHz；PRINCEv2-unrolled+mod（LIPPEN 选用）1,522 LUT/1 cyc/42 MHz。Apple M1 侧：PAC 16-bit（PACMAN 实验证实），arm64e 编译，禁用 SIP 后跑用户态微基准。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 非独立模拟器：基于 Chipyard v1.8（https://github.com/ucb-bar/chipyard）SoC 生成框架，RTL 仿真用 Verilator，性能评估在 Xilinx VCU118 FPGA 原型上跑真实 Linux；Linux 镜像由 FireMarshal 生成。LIPPEN 对 Chipyard 打补丁（chipyard.patch、rocket-chip.patch）扩展 Rocket/BOOM 与 RoCC 接口并加入 PRINCEv2/QARMA 加速器。
- 模拟器模拟什么的性能，修改了什么。
  - Verilator 仿真用于功能验证与跑小测试程序；性能数据来自 FPGA 原型（100 MHz）实际运行：运行时开销、退休指令数增量。硬件成本用 Vivado 后综合资源/时序报告；功耗用 VCU118 后综合功耗分析（100 MHz 归一）。修改：Rocket/BOOM 核加 RoCC 接口 + PRINCEv2 加密加速器（QARMA 认证加速器作 PAC baseline）；LLVM v18.1 RISC-V 后端新增 seal/unseal 插桩指令（返回地址保护用 SP 作 modifier）；PacTight LLVM IR pass 由 Arm PAC 移植到 RISC-V LIPPEN（<50 行改动）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：https://github.com/bearhw/LIPPEN（GPL-3.0），artifact https://doi.org/10.5281/zenodo.19901476。仓库结构：chipyard 子模块（v1.8.0）+ patches/（chipyard.patch、rocket-chip.patch、llvm.patch、pactight.patch）、llvm-project（llvmorg-18.1.6）、micro-benchmarks/（lippen-riscv RISC-V LLVM 测试二进制、m1 Apple M1 ARM64 微基准）、pactight 子模块；HARDWARE.md、COMPILER.md 分述。构建流程：Chipyard 初始化+打补丁（Ubuntu 20.04/22.04、Conda、Java 11，~20 min）→ riscv-tools 工具链（2–4 h）→ Verilator RTL 仿真（30–60 min）→ VCU118 bitstream（Vivado 2021.2，4–6 h）→ FireMarshal 生成 Linux 镜像 + SD 卡 → 运行微基准；Apple M1 流程需禁用 SIP。
  - 全过程（一次被保护的函数调用，SPEC/nbench 返回地址保护）：LLVM RISC-V backend pass 在 call 站点前插 PTR_SEAL、ret 站点前插 PTR_UNSEAL（modifier=SP）→ 编译产物运行在 FPGA 原型（Rocket/BOOM + RoCC 上的 PRINCEv2 引擎）→ 调用时 PTR_SEAL 把 64-bit 返回地址经 RoCC 紧耦合队列送入 PRINCEv2 单周期引擎得 Enc_{k⊕SP}(ra)，密文写回栈；返回时 PTR_UNSEAL 送 RoCC 解密并检查高 16 位（m1）为全 0，通过则恢复真实返回地址供分支预测/RAS 与取指使用，失败则置异常标志 → 计时器（perf）记录运行时间与动态指令数，对未插桩 baseline 归一化得开销。数据指针保护（pointer-chasing）：每次 load 前插 PTR_UNSEAL，认证位于 load-use 关键路径（Loop 单依赖 load 与 Unrolled 32 依赖 load 两种变体，分别测 zero modifier / 共享非零 modifier / 每访问加载 modifier 三种配置）。模拟原理：Verilator 把 Rocket/BOOM+RoCC+PRINCEv2 RTL 编译为 C++ 周期精确模型验证正确性；FPGA 以真实时序提供性能；输入=插桩 benchmark 二进制 + FireMarshal Linux 镜像，输出=运行时间、动态指令增量、归一化 overhead；面积/频率/功耗由 Vivado 后综合报告输出。
