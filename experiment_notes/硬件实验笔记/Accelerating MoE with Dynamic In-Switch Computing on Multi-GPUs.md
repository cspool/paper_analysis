## Accelerating MoE with Dynamic In-Switch Computing on Multi-GPUs

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 DySHARP 的 dynamic multimem addressing 全栈硬件扩展 + token-centric kernel fusion 硬件支撑，RTL 实现并以 Synopsys Design Compiler 在 TSMC 12nm 综合：(1) 数据链路层包格式扩展：flit0 将 64-bit 地址替换为 48-bit multimem address（代数索引，支持 128TB）+ 1-bit stage（Dispatch/Combine）+ 15-bit target count，后接 target extension flits（每 flit 8 个 16-bit expert ID），payload/byte-enable 不变；(2) 源 GPU SM 内 LSU 扩展 + 独立 MultimemQ（32 项）：dymultimem.* 指令先从 shared/global memory 取连续 target list 再组装完整请求包；(3) 交换机 Route 模块扩展：按 target 计算每目标输出端口（OutPort^i = Target^i / 每 GPU expert 数）、逐端口复制并裁剪 replica；Reduction Logic 记录请求 target 数并随部分响应递减、归零即返回归约结果，逻辑仅 +1 cycle；(4) 目的 GPU Hub 内硬件 memory manager：AL Table（DRAM，每项 4B = 1b Valid + 31b LIdx，共 4×nToken 字节）+ AL TLB（512 项，CAM tag（ExpertID+AIdx）+ SRAM buffer），MV translation：VAddr = VBase + LIdx×bsize + MAddr%bsize，Dispatch 时累加式分配 layout block、Combine 复用同一映射；(5) token tracker 的 TS Table 与 OR Table（各 1024 项，16-bank 双端口 1R1W SRAM）。
  - 实验比较：面积开销——交换机扩展 <0.01mm²（<0.1% NVSwitch die）、GPU 侧合计 0.198mm²（约 0.024% H100 die）；设计空间——AL TLB 大小-命中率扫描（512 项为 sweet spot）、交换机 reduction buffer 大小-逐出率扫描（64KB 为 sweet spot）；同时作为性能评估（speedup/流量，见 kernel 调度层条目）的硬件载体。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - Accel-Sim（https://github.com/accel-sim/accel-sim）+ BookSim2（https://github.com/booksim/booksim2）集成，论文修改两者模拟多 GPU 系统；RTL 综合用 Synopsys Design Compiler（https://www.synopsys.com/implementation-and-signoff/rtl-synthesis-test/design-compiler-nxt.html）+ TSMC 12nm 库，SRAM macro 由库 Memory Compiler 生成。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 GH200 NVL32（32 GPU、9 NVSwitch 全连接 fat-tree、H200 规格 GPU、NVLink 4.0 参数：900 GB/s 双向、250ns 单跳、1µs 往返、16B flit、每端口 16×256 VC、64KB reduction buffer）上 MoE 训练/推理的逐周期性能：通信指令执行、交换机多播/归约、AL 地址翻译、token tracker 状态更新与 megakernel 调度。修改：Accel-Sim 扩展 FP8 GEMM kernel、多 GPU 并发与 switch 网络；BookSim2 集成 NVSwitch 建模；新增 dymultimem 指令流水线、MultimemQ、AL Table/AL TLB、token tracker 三表与 readiness 门控。校准：vs DGX-H100 实测，GEMM 与 DeepEP 通信算子平均误差 <6%。

  - Accel-Sim 与 BookSim2 均开源（链接见上，论文参考文献 [16][18]）；DySHARP 的模拟器修改代码与 RTL 未见公开仓库（论文未给出链接，联网搜索未找到）。面积综合流程论文明确说明：RTL + Synopsys DC + TSMC 12nm。
  - 模拟原理与全过程：输入 = 指令流（含 dymultimem.st / dymultimem.ld_reduce 与 target list）+ MoE workload 配置。源 GPU SM 执行 dymultimem 指令 → LSU 读 target list 入 MultimemQ → 组装 flit0 + target extension flits 请求包经片上网络出 GPU → BookSim2 逐周期模拟 NVLink→NVSwitch：Route 按 target 计算输出端口并复制裁剪转发（Dispatch 多播），或 Reduction Logic 累加部分响应、计数归零后返回归约结果（Combine）→ 目的 GPU Hub 的 AL TLB 命中直接得 LIdx（miss 访 AL Table；Dispatch 首触达分配 layout block）→ MV translation 得虚拟地址 → 写/读数据，写可见后更新 tracker 表 → megakernel 轮询 readiness 发射 GEMM/Combine。输出 = 逐周期时间/流量统计 → MoE 层与端到端 speedup、流量体积、payload 效率（vs explicit addressing 8 目标：80% vs 69%）与硬件面积开销。
