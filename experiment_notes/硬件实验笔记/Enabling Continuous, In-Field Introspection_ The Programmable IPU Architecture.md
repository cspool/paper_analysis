## Enabling Continuous, In-Field Introspection: The Programmable IPU Architecture

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 Introspection Processing Unit（IPU）——一个新的轻量级硬件架构原语（introspection 专用处理单元）：32-bit 顺序 RISC-V 核（RV32I）+ 32 个命名输入寄存器（IORegs）+ 3 个触发寄存器（TS/TE/ADDR）+ 32KB scratchpad SRAM + 可选微架构加速扩展（直方图加速器、hash、循环指令）+ 微控制器式执行模型（init/main/end 三段程序区，8KB 指令内存 = 2048 条指令，数据驱动调用，ACTIVE 时新数据被丢弃）。两种变体：IPU_lite（紧凑无 cache 核 + 直方图/hash/循环原语，面积 0.019 mm²）；IPU_pro（额外集成 eFPGA 软逻辑：590 CLB + 470 AIO tiles（去掉 staging flip-flop）+ 8 个小 BRAM（64 深 × 64 位），用于状态机遍历类 introspection，面积 0.22 mm²）。每个 IPU 在 P&R 时 flatten 进其 HIT（Hardware-module Introspection Target，如 CPU 前端、L1 cache/prefetcher、GPU SM scoreboard），经片上网络 OCN + PCIe 与主机通信；代码签名（类似 Android/iOS app-store 的公/私钥基础设施）控制部署策略（closed/restrictive/permissive 三模式），IPU 只能读信号不能向 HIT 注入。
  - 实验比较：用单一 IPU 架构演示四大能力类别（此前 field 中不可行的分析类别）：①Stateful Emulation——IPU_pro eFPGA 实现 entangled 指令预取器（ChampSim，135 条 CVP traces，对比 entangled 原作者实现，误差 <5%）；②Software-Defined Performance Attribution——IPU_lite 软件实现 PICS（per-instruction cycle stacks，对比 TEA 专用硬件块，gem5 SE，13 个 SPEC benchmark + 3 个 DARCHR microbenchmark 验证）；③Scalable On-Chip Data Aggregation——IPU_lite 单条直方图指令监控 GPU TensorCore 利用率（AccelSim，21 个 GEMM，QV100 模型）；④Real-Time Component-Level Diagnosis——IPU_lite 对 L1D data prefetcher（Gaze）的 demand miss 做逐事件根因分类（4 类失败模式，ChampSim，189 条 SPEC traces）。硬件开销：7nm 综合面积 <1%、功耗 <25mW（IPU_lite 15.0mW、IPU_pro 20.8mW）；BOOM 单核全 P&R 集成（含 4 级缓冲线）面积 3% 上界（BOOMv2 仅 2.2 mm²，Zen2 级核上约 0.2%）；5×IPU_pro + 10×IPU_lite 仅占 200 mm² die 的 0.65%；GPU SM 全覆盖也 <1%。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 修改/集成了三类开源模拟器构建 co-simulation 环境（把自研 IPU 模拟器加进其中）：ChampSim（https://github.com/ChampSim/ChampSim，trace-based 微架构模拟器，用于预取器仿真与逐 miss 根因诊断）、gem5（https://www.gem5.org / https://github.com/gem5/gem5，SE 模式 cycle-level 全核模拟，用于 PICS）、AccelSim（https://github.com/accel-sim/accel-sim-framework，基于 GPGPU-Sim 4.0 的 GPU cycle-level 模拟器，用于 TensorCore 利用率）。另有自研 IPU emulator（RISC-V 功能模拟器 + IPUpro 的 Verilog co-simulator，耦合 HIT traffic injector 测试台验证 introspection 程序与丢数据行为）。RTL：Verilog 实现 IPU_pro/IPU_lite，用 AsAP7 7nm 教育 PDK（The-OpenROAD-Project 的 OpenROAD-flow-scripts 内含）综合；SRAM 用 CACTI 从 32nm 缩放到 7nm（按 [71] CMOS scaling equations）；eFPGA 软逻辑用 FABulous（https://github.com/FPGA-Research-Manchester/FABulous）生成并评估面积/功耗/利用率；ASIC 流程：DC Compiler/Primetime（综合/时序）、Innovus（APR）、VCD 功耗估计（netlist 仿真）。全综合 P&R 集成到 BOOM（https://github.com/riscv-boom/riscv-boom，4-wide OOO RISC-V 核），单核（256KB L2）与 4 核（1MB L2，仿 Zen2 4-core complex）两配置，TEA case study 信号，Innovus 在 ASAP 7nm 上 P&R 均 meet timing。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟内容：①ChampSim 模拟预取器（entangled）覆盖率/准确率/缺失率统计对比参考实现；及 Gaze prefetcher 下每个 demand miss 的根因分类（用离线分析脚本忠实建模 IPU 20-cycle 处理延迟与丢数据）；②gem5 SE 模拟 PICS：每 cycle 更新 Performance Signature Vector（PSV，bit-mask 表示某 PC 动态实例发生的事件组合），每 400,000 cycles（TEA 设计值）归并输出 PICS 条目（PC + 事件签名 + cycle 数）；③AccelSim 模拟 GPU SM 的 SIMT/TensorCore/L1 三个 1-bit 活动信号，256-cycle 窗口直方图聚合，输出每窗口 3 字节（108 SM 全采样 1.7 GB/s、10/108 采样 0.16 GB/s）；④IPU emulator + HIT traffic injector 验证 introspection 正确性（数据到达率/丢包行为/近似误差）。修改了什么：论文把自研 IPU 模拟器加进 ChampSim/gem5/AccelSim 做性能 co-simulation（建模 IPU 处理延迟、每周期输入、丢数据）；RTL 本体（IPU_lite/IPU_pro）为自研新设计，非修改第三方模拟器；对比工作（entangled、TEA、Gaze）用原作者实现跑在各自模拟器里。总模拟超过 200 个应用。

  - 开源情况：IPU 架构/RTL/IPU 模拟器未提供公开仓库，联网搜索（本 skill）未找到官方开源链接（论文未提供，无法确认）。用到的工具均开源/公开：ChampSim、gem5、AccelSim、FABulous、BOOM、AsAP7 PDK、CACTI（https://github.com/HewlettPackard/cacti）；参考实现：entangled prefetcher（ISCA 2021 Ros & Jimborean）、TEA（ISCA 2023，实现位于 https://github.com/uv-xiao/chipyard-ntnu，Chipyard/FireSim/BOOM）、Gaze（HPCA 2025 SJTU，Zenodo 数据 artifact https://zenodo.org/records/14252372 提供 ChampSim traces）；traces：CVP-1（https://microarch.org/cvp1/）、SPEC（SimPoints 100M instr/region）、DARCHR microbench（https://github.com/darchr/microbench）。
  - 模拟原理与输入→输出全过程（Capability 1 Stateful Emulation，ChampSim + IPU co-sim）：输入 = CVP trace（指令/PC 流）+ IPU 配置（entangled 预取器 eFPGA 位流，订阅 CPU 前端 fetch-PC 信号，仅 2 个 HIT 信号、64 bits 输入，全程序分析故不配 ADDR/TS/TE）→ ChampSim 逐指令推进流水线，每 cycle 把 fetch-PC 喂给 co-simulated IPU → IPU 在 eFPGA 软逻辑上每地址一个 cycle 跑 entangled 状态机（分支密集的历史表/状态转移图，用 RISC-V 软件跑会丢维持 cache 状态所需数据，故放软逻辑；entangling 假设 L1 miss 全为 L2 hit 以确定 entangling 对，不改变 L1 内容故执行仍正确）→ 预取决策返回模拟器，IPU 内硬件计数器累计覆盖/准确/缺失（每 2³¹ cycle 上报避免溢出）→ 输出统计与 entangled 原作者参考实现对比误差（always-hit-in-L2 假设使每项指标平均优于实际 <5%）。作用：证明通用 IPU 能以 line-rate 在真实部署上做有状态仿真（in-field A/B 测试预取器二进制），这是 PMU（无状态）/JTAG trace（数据洪流）做不到的。
