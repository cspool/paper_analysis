## NasZip Software and Hardware Co-design to Accelerate Approximate Nearest Neighbor Search with DIMM-based Near-Data Processing

- 属于硬件架构的实现是什么？实验比较什么？
  - 属于硬件架构的实现是 DIMM-based NDP 上的 GANNS 加速硬件：(1) 向量处理引擎 VPE——每 sub-channel 一个，内含 4 条并行路径（各对应一个 DRAM device），每条含 Dfloat 解码模块（16-to-1 MUX 逐 cycle 装 128-bit burst 进寄存器 + barrel shifter 按偏移寄存器抽 n-bit Dfloat 元素并零填充到 FP32）、query buffer（wrap-counter MUX 每 cycle 输出一个 query 元素）、距离计算模块（L2/IP 共享数据通路，MUX 切换模式，参考 ANSMET/CXL-ANNS）、accumulator 汇总 4 路部分距离、FEE 模块（α_k/β_k 缩放估计距离并与 threshold 比较触发早退）；(2) 数据感知邻居表映射 DaM——邻居表按与向量同 sub-channel 共置方式切分存储，配 NLT（Neighbor List Table，记录长度+地址）支持变长表索引，把邻居检索从 CPU 卸载到 NDP 并消除跨 sub-channel 通信；(3) 局部邻居缓存 LNC——LNC-T（8KB 全相联，TLB 式，缓存 NLT 条目，每条 4 字节、每 cache line 16 条）与 LNC-D（256KB 8-way 组相联，数据缓存式，tag 记录段起止节点 ID），利用查询间时间/空间局部性；(4) 邻居表预取与 batch 调度——hop 间隙预取下一 BFS hop 的邻居表到 LNC，隐藏 CPU 合并等待，batch=16 时最优。实验比较：QPS 吞吐（对 CPU/GPU/ASIC/UPMEM/FPGA/NDP 平台）、延迟分解（邻居检索/距离计算/部分结果处理）、能量效率、LNC-D 命中率 vs efSearch、预取命中率 vs hop 与 M、batch size 影响、sub-channel 负载均衡、面积（0.7091 mm² vs RCD/DB 10.22 mm²）与功耗、3D-ICE 热（峰值 65.47°C，t_REFI 内无需主动散热）、每项优化相对 ANSMET 的延迟削减。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 论文修改并使用的模拟器为 UniNDP（HPCA 2025 论文 "UniNDP: A Unified Compilation and Simulation Tool for Near DRAM Processing Architectures"，清华 NICSEFC；官方 artifact 仓库 https://github.com/UniNDP-hpca25-ae/UniNDP，原仓库 https://github.com/godfather991/UniNDP）。功能正确性在 FPGA 上验证；面积/功耗用 Synopsys Design Compiler（28nm）综合 + Cadence Innovus P&R；热用 3D-ICE（https://github.com/CSML-IUT-UdeS/3D-ICE 或论文引用的 [77]）评估。
- 模拟器模拟什么的性能，修改了什么。
  - UniNDP 是周期精确（cycle-accurate）、指令驱动的 NDP 模拟器：统一树形 NDP 硬件抽象 + 对应指令集，跟踪 PU/内存单元/buffer/内部总线的状态（支持乱序执行），覆盖 UPMEM PIM、Hynix AiM、Samsung FIM-DRAM、HBM-PIM、Dimmining 等架构；配套 NDP 编译器做数据划分/映射/调度优化，带基于 DRAM 时序的快速性能预测器。论文修改 UniNDP 以支持 rank-level parallelism（README："UniNDP is modified to support rank level parallelism"），在其上配置 NASZIP 的 DDR5 多通道/多 rank/双 sub-channel 结构（Table II：DDR5-4800、2/6 通道、2 DIMM/通道、2 rank/DIMM、2 VPE+LNC/rank、256KB LNC-D、8KB LNC-T、1.2GHz），模拟 ANNS 搜索的 QPS、延迟、recall 与各硬件模块行为（FEE 早退、DaM 映射、LNC 命中、预取）。

  - 开源情况：NasZip 全部代码公开（GitHub https://github.com/Intelligent-Computing-Research-Group/NasZip，Apache-2.0/MulanPSL-2.0；Zenodo DOI 10.5281/zenodo.19453078），仓库内含修改版 UniNDP/ 目录、simulate/、sim_tools/（NDP 模拟脚本与工具）、result/Data + sync_csv_results.py、Plot/plot_fig_*.py、fee_dim_freq.sh / overall_basic.sh / overall_hp.sh / qps_vs_recall_*.sh / prefetch_hit_rate.sh / cache_hit_rate.sh 等实验脚本。UniNDP 本身开源（HPCA 2025 artifact：`git clone git@github.com:UniNDP-hpca25-ae/UniNDP.git && pip install -r requirements.txt`，MIT 许可，Python+Shell+C++/Scons）。
  - 模拟器输入→性能输出全过程（UniNDP 模拟 NASZIP ANNS 搜索）：输入 = 预构建 HNSW 索引（cuVS 构建，仓库提供预建索引下载，含向量数据 + 图结构 + 经 FEE-sPCA 的 PCA 变换参数 α/β + Dfloat 配置 C_opt）+ query 集与 ground truth + NASZIP 系统配置（Table II 的通道/DIMM/rank/sub-channel/带宽/缓存大小）。执行：UniNDP 以 cycle 粒度驱动 NDP 流水——host CPU 将距离计算命令与向量位置下发给 NMA → 每 sub-channel 的 VPE 按 DaM 映射从本 sub-channel 取 Dfloat 编码向量（4 device 并行，每 burst 128bit，SIFT 128 维三段 18/14/16 bit 共 16 burst），Dfloat 模块解码零填充到 FP32 → 距离计算模块算 L2/IP 部分距离 → accumulator 累加 → FEE 模块按 d_est^k=α_k·d_part^k/β_k 与 threshold 比较触发早退；LNC-T/LNC-D 缓存 NLT 条目与邻居表命中时免 DRAM 访问；两 VPE 结果进共享优先队列合并排序后只返回 top 候选给 CPU；hop 间预取下一邻居表。模拟器按 DRAM 时序（DDR5-4800，19.2 GB/s per sub-channel）累计各阶段 cycle，输出 QPS、每查询延迟（分解为邻居检索/距离计算/部分结果处理）、recall@k，经 sync_csv_results.py 写入 result/Data CSV 后由 Plot 脚本还原论文 Fig.8/15/16/18/19/22。
