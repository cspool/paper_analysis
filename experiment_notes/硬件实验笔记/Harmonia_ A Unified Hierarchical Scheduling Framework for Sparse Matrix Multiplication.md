## Harmonia: A Unified Hierarchical Scheduling Framework for Sparse Matrix Multiplication

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为三层静态-动态协同调度框架 + 可重构数据流硬件基板：(a) Static Analytical Layer——离线用粗粒度描述符（矩阵形状 M,K,N、全局密度 ρA/ρB、数据类型）和硬件参数（PE 阵列大小、SRAM 容量 S_SRAM）枚举候选 tile 形状 (T_M,T_K,T_N)，以操作强度 OI=OPs/Bytes_loaded 为目标、受 SRAM 可行性约束 s_val(E[nnz_A]+E[nnz_B])+s_psum·T_M·T_N ≤ β·S_SRAM（β=0.8 安全系数）过滤，选出基线块形状、块间遍历顺序与 SRAM 分区 S_A/S_B/S_C；(b) Dynamic Profiling Layer——块进入 SRAM 后用 tile 元数据（精确 nnz、tile 密度 ρtile=nnz/(T_M·T_K)、行/列密度方差、非零聚类）做轻量逐 tile 分析，细化 tile 形状（低密度扩张、高密度收缩、聚类对齐边界）并选择 InP/Row/OutP 数据流与 DN/MRN 资源分配；(c) Dynamic Tuning Layer——由 Adaptive Hardware Substrate 的硬件反馈（SRAM pressure/psum spill 计数器、MRN merge-depth 监视器、PE stall 指示）触发数据流切换（InP↔Row↔OutP）与微重切块（micro-retiling，块内缩放 K/M/N），用成本模型 Gain=T_before−T_after > α·Cost(=T_reconfig+T_flush+T_buf_reset) 决定是否重构；滞回机制（异常计数器需连续 T=2~4 周期超阈值）防振荡，最坏情况回退 1 次重构延迟（50 cycles）。
  - 硬件改动仅三项轻量控制结构：Feedback Counters（每 PE 行一组计数器，128 行仅 128 个计数器，占 <0.5% PE 阵列面积，经轻量 metadata crossbar 汇聚到 Tiling Controller）、Reconfiguration Engine、Tiling Controller；PE 数据通路、MRN 加减逻辑、DN 分发流水线完全不变，反馈路径与主数据通路解耦。
  - 实验比较：在完全相同 32-row 硬件配置上（非 baseline 论文原始规模）模拟 4 种调度 + oracle：Vesper 风格静态调度（baseline）、Misam-like 逐 tile 数据流选择、HYTE-like 全局 tile 编排、Harmonia、逐 tile 静态最优 oracle。指标：16 个 SpMSpM workload 平均 1.75× 加速（orani678 达 3.46×）、端到端 4 个 DNN 管道 1.87× geomean、off-chip DRAM 访问与片上 stall cycles（大规模矩阵超 1MB SRAM）、A/B/C SRAM 流量与操作强度（平均降 32% vs Misam/HYTE 仅 10%）、能耗（平均 -40%，rajat19 超 -60%）、扩展性与鲁棒性（16×16~64×64 PE 阵列、不同 SRAM 容量）。
- 硬件平台是什么，配置是什么。
  - Harmonia 加速器（基于 Trapezoid 行并行模板）：32 PE 行 × 32 FP32 乘法器/加法器，0.5 GHz，峰值 1 TFLOPS；1 MB 片上 SRAM（32×64B line）+ 32 KB 分布式本地 buffer（每 PE 行 1 KB、64B 宽 BUF）；off-chip HBM 2 TB/s 带宽；NoC 为 32-to-32 crossbar；总面积 7.51 mm²（计算 2 PEs×32 Rows 5.16 mm²/68.7%、SRAM 1.89 mm²/25.2%、Schedule 反馈与重构 0.25 mm²/3.3%、NoC 0.21 mm²/2.8%）。单 PE 行：16× FP32 乘法器（37,382 μm²/46.4%）+ radix-16 FP32 加法树 MRN（23,234 μm²/28.8%）+ 16-to-16 Benes DN 与控制（7,001 μm²/8.7%）+ 1KB 64B 宽 SRAM BUF（13,003 μm²/16.1%）。
  - 建模方法：数据通路 RTL（向量乘法器、归约树、分发网络、稀疏控制逻辑）在 TSMC 28nm 用 Synopsys Design Compiler 综合，翻转率（switching activity）估计计算能耗；片上 SRAM 用 CACTI 7 建模；HBM 能耗来自厂商 datasheet。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 自研 cycle-accurate 稀疏数据流模拟器，明确建模 MAC 单元、merge-reduction tree（MRN）、distribution network（DN）、本地 buffer、SRAM、HBM；忠实建模 PE stall、psum spill、路由拥塞；动态调谐触发时显式向执行时间线注入 pipeline flush + DN/MRN 重编程 + buffer reset 的重构开销（20–50 cycles）。论文未说明基于或修改某个开源模拟器，也未给出模拟器链接（联网未找到）。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟稀疏矩阵乘法（SpMSpM）与 DNN 稀疏层（生成式 LLM 与视觉模型）在 32-row 可重构数据流加速器上的执行：merge-tree 碰撞与 psum 传播延迟、DN/MRN 路由拥塞、瞬时 SRAM 压力/峰值 buffer 占用、生产者-消费者失配 stall；支持 InP/Row/OutP 三种数据流在 tile 边界的切换与块内微重切块。修改了什么：论文自研模拟器，非修改开源工具（未说明）。重构开销（20–50 cycles）导致总 stall <1% 也由该模拟器验证。

  - 模拟原理与输入→输出全过程（以 bcsstk10.mtx 一个 64×64 tile 为例）：输入 = (a) 矩阵数据（CSR/CSC + 显式坐标列表用于高稀疏，bitmask 用于轻度稀疏）+ 全局粗粒度描述符（M,K,N、ρA/ρB、datatype）；(b) 硬件配置（Table III：32×32 MAC、1MB SRAM、32KB 本地 buffer、HBM 2TB/s、0.5GHz）；(c) 调度参数（静态层输出的块形状 (T_M,T_K,T_N)、遍历顺序、SRAM 分区）。模拟推进：静态层按 Algorithm 1 枚举候选 tile、按可行性约束 (2) 过滤、选最大 OI 的基线块；块载入 SRAM 后动态层按 tile 实际 nnz 采样细化形状与初始数据流；执行时每 PE 行按所选数据流（InP 的 A 行驻留+B 列流水转发、Row 的 A 行驻留+B 片段按 nnz 选择性路由、OutP 的 rank-1 更新广播）推进 MAC，MRN 按 merge-before-store 或 column-accumulate 归约；反馈计数器把 merge 事件、spill 标志、stall 周期经 metadata crossbar 汇聚到 Tiling Controller，Dynamic Tuning 按成本模型 (3) 决定是否在 tile 边界切换数据流/缩放 tile（注入 20–50 cycles 重构开销）。输出 = 每 tile 延迟、PE 利用率、A/B/C SRAM 访问量、off-chip DRAM 访问、片上 stall cycles、操作强度 OPs/Byte、能耗（面积 + CACTI/Synopsys 能量模型叠加）。作用：未流片情况下验证分层调度在真实稀疏矩阵与 DNN 剪枝模型上的加速比（1.75×）、能效（2.47×）与动态稀疏变化下的鲁棒性。
