## LIBRA: A High-Accuracy, Cost-Aware, and Coordinated Multi-GPU Page Prefetcher

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 LIBRA：面向 UVM（Unified Virtual Memory）多 GPU 系统的访问模式感知（access-pattern-aware）、成本感知（cost-aware）、跨 GPU 协调（coordinated）的 stride-based 页面预取器，由三部分组成：(1) 每 GPU 一个硬件 Multi-way Multi-stride Prefetcher（MMP），含 Triggered Table（按 VPN 索引、缓存近期触发预测的 far-fault 以去重、周期性清空）与 Multi-way Multi-stride Access Table（MMAT），是论文唯一新增的片上硬件组件（~6500 bytes/GPU，含 100 SM×4 way）；(2) 成本-收益分析：复用 NVIDIA GPU 既有 per-page 本地访问计数机制（GMMU 在 TLB lookup 时自动更新寄存器计数，达阈值触发中断并写 ring buffer），修改 CPU 侧 UVM runtime 的 fetch_access_counter_buffer_entries(.)（论文 Figure 11 只改 step 4），把报告的页面虚拟地址与 MMAT 的 monitored VPN 比对并累加计数，从而估计被预取/迁移页面的未来访问次数；(3) Page Prefetching Coordinator（PPC）：纯软件模块，位于 CPU 侧 UVM runtime（PPC runtime + 按 hashed VPN 索引的 PPC hash table，每条目含 36-bit 实际 VPN、recent-migration 位(1b)、recent-use 位(1b)、3-bit 当前 GPU ID、8 个 8-bit 跨 GPU 估计访问计数），按式(2) lat_remote*(acc_highest - acc_source) > page_migration_overhead 决定是否迁移、迁移到估计访问数最高的 GPU；仅 PTE 预取调用 uvm_va_block_map(.)，真实迁移调用 uvm_api_migrate(.)。
  - 实验比较什么：与 7 个 SOTA 页面迁移/预取方法对比：TBNP-O（NVIDIA TBNP + on-touch 迁移）、TBNP-F（TBNP + first-touch 迁移）、TBNP-AT（自适应阈值，基于硬件计数器在 remote zero-copy 与迁移间调整）、TBNP-EA（Early Adaptor，按 page fault 波动动态调 prefetch 阈值）、Forest（按访问序列修改 block 与 tree 的预取大小）、HOPP（disaggregated memory 按分类访问模式预取）、GRIT（反应式 SOTA，per-page 动态选 on-touch/counter-based/duplication 策略）。主要指标：归一化端到端性能（对 TBNP-O 归一化）、prefetch accuracy（被预取页中目的 GPU 实际访问比例）、prefetch coverage（访问页中已预取且访问时位于本地内存的比例）、page migration overhead（critical-path 迁移延迟：TLB 失效、SM 流水线 flush、cache flush、数据传输，仅首次 far-fault 触发的迁移计入）、remote access overhead、translation overhead、remote access changes（每页每次迁移相对不迁移直到下次迁移事件所改变的跨 GPU 远程访问总数；模拟器认为一次页面迁移开销≈200 次远程访问，与 NVIDIA UVM 迁移阈值 256 吻合，故 >200 才视为有益）。结果：端到端平均优于 GRIT 30%、Forest 35%、HOPP 32%、TBNP-EA 40%（regular 44%/37%/31%/29%，irregular 30%/29%/38%/36%）；prefetch accuracy 81.8%、coverage 83.9%（表 V，TBNP 系仅 33.8%–47.4% accuracy、42.2%–48.9% coverage，且预取页数 21333–28548 远超 LIBRA 19967）；LIBRA >95% 迁移减少远程访问、>69% 有益（Forest 仅 12%）；迁移+远程访问时间合计比 GRIT 减 59%、翻译开销比 GRIT 减 54%；CPU 开销 3.2%（TBNP 系 0.4%、HOPP 0.1%）；消融（去 cost estimation & coordination 时 55% 迁移低效，加 cost estimation 减 16% 总迁移/31% 不必要/36% 低效 + 12% 性能，再加 coordination 减 13%/35%/45% + 6% 性能）；敏感性（prefetch 阈值 15%/25%/35%/40%/50%，25% 最优；NVLink 200/300/400 GB/s 下相对 TBNP-O 提升 64.7%/46%/36.8%；1/8/16/32 GPU 扩展；125%/150% 内存超订；multi-rack 2 rack×8 GPU 下相对 TBNP-EA/Forest/HOPP/GRIT 提升 74%/65%/60%/56%）。面积评估：MMAT 用 CACTI 建模（read 0.0051 nJ/access、write 0.0062 nJ/access、data array 0.00964041 mm² + tag array 0.0031502 mm² = 共 0.01279061 mm²；按 6T SRAM 折算约 7.8×10^4 NAND2 等效门）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - MGPUSim：https://github.com/sarchlab/mgpusim（ISCA 2019 "MGPUSim: Enabling Multi-GPU Performance Modeling and Optimization"，Yifan Sun 等，MIT 许可）。用 Go 编写、基于 Akita 离散事件模拟框架（github.com/sarchlab/akita），默认面向 AMD GCN3（R9 Nano 建模），v3+ 增加 CDNA3/GFX942(MI300A) 支持；支持 fast functional emulation 与 cycle-accurate timing 两种模式；模型含 L1/L2 cache、TLB、DRAM controller、多 GPU 通信的 RDMA 组件，支持 discrete/unified memory。论文引用 [11] Griffin、[60] GRIT 等 prior multi-GPU 迁移工作均基于 MGPUSim 扩展，本论文沿用同一模拟器。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 UVM 管理的 4-GPU 离散多 GPU 系统端到端执行性能。基线配置（表 III）：SM 1.0 GHz、108 个/GPU；L1 D-Cache 64KB 4-way；L1 I-Cache 32KB 4-way；L2 2MB 8-way；DRAM 配置为应用内存足迹的 70%（[11],[60] 惯例）；L1 TLB 16 条目 16-way 1-cycle、TPC 共享、LRU；L2 TLB 128 条目 8-way、16 sub-entries/entry、10-cycle、GPC 共享；L3 TLB 1024 条目 8-way、16 sub-entries/entry、40-cycle、GPU 共享；GMMU 8 个共享 page table walker、100-cycle/级；Inter-GPU 300 GB/s NVLink 3.0；CPU-GPU 32 GB/s PCIe-v4。每 GPU 独立 local page table 与 GMMU；CPU 侧 UVM driver 维护统一页表并协调跨 GPU page fault。修改了什么：(a) GPU 侧新增 MMP 硬件——Triggered Table + MMAT（每 SM 4 way，每 way 36-bit last VPN + 8-bit access counter + 4×(6-bit stride + 6-bit occurrence counter) + 8-bit sum + 36-bit monitored VPN）；扩展 TLB-miss 元数据携带 source SM 信息（NVIDIA 默认未指定，论文扩展）；L3 TLB miss 转发 MMAT 学习（按 VPN 差阈值 512 归类 way，出现第五 way 淘汰最低 counter way）；far-fault 路由 MMAT 做动态深度预测（对 4 个最高频 stride 按式(1) stride_likelihood = 该 stride counter/总 counter 决定每 stride 预取页数，每 +25% 概率多预取 1 页，预取请求含 VPN 列表 + 估计未来访问数）；(b) 修改 CPU 侧 UVM runtime 的 fetch_access_counter_buffer_entries(.) 以回填 MMAT monitored VPN 的访问计数；(c) 新增 PPC 软件模块（hash 表 + 协调逻辑 + 周期全局维护：右移访问计数衰减历史、清 recent-migration/recent-use 位、回收长期未用条目）。

  - 模拟器使用示例与输入→输出全过程（以 4 GPU 运行 Matrix Transpose (MT, 16MB/GPU) 为例）：输入 = (a) MGPUSim 配置（Go 配置文件/命令参数，如 -num-gpu=4、GCN3 GPU 微架构 108 SM、缓存/TLB/DRAM/NVLink3.0 300GB/s 参数、UVM 与 GMMU 使能）；(b) 用 MGPUSim 的 Go 测试框架编写的 benchmark 内核（MT 按 GPU 划分数据，GPU 访问本地 partition 并远程访问其他 GPU 数据）；(c) LIBRA 开关（MMP 与 PPC 使能/关闭做消融）。模拟原理与推进：Akita 离散事件模型推进 SM 访存请求 → L1 cache 与 L1 TLB 并行访问（virtually indexed, physically tagged）→ L1 TLB miss 进 MSHR → L2 TLB → L3 TLB → GMMU 多级页表遍历（8 walkers、100-cycle/级、page-walk cache）→ 仍缺失则 far-fault 记录进 GMMU MSHR、中断 CPU 侧 UVM driver → driver 用统一页表解析并更新跨 CPU/GPU 映射。LIBRA 插入点：L3 TLB miss 同时转发 MMAT 学习 stride（每 SM 4 way）；far-fault 时 Triggered Table 判重（已存在则跳过，避免多 SM 冗余预测）→ MMAT 动态深度预测出页 VPN 列表 + 估计未来访问数 → 经中断发 CPU 侧 PPC → PPC 查 hash 表更新请求 GPU 访问计数、查 recent-migration 位、按式(2) 判断：估计收益超过迁移开销则 uvm_api_migrate(.) 迁到估计访问数最高 GPU 并给请求 GPU 预取 PTE，否则仅 uvm_va_block_map(.) 建 PTE 不迁移 → GMMU 按协调结果解析原 far-fault 并迁移全部/部分/零个请求页；GPU 侧 UVM support 周期性经 access-counter 中断把实际本地访问数回填 MMAT monitored VPN，形成学习闭环。输出 = 端到端执行时间（归一化 TBNP-O）、accuracy/coverage、迁移开销分解（SM 流水线 flush、cache/TLB 失效、数据传输）、remote access 变化分布（<0/0–200/>200 三档）、CPU 开销、消融与敏感性（不同 NVLink 带宽、GPU 数、预取阈值下的归一化性能）。作用：无需流片即可在 cycle-accurate 级别验证"stride 预取 + 成本收益 + 跨 GPU 协调"相对 7 个 SOTA 的端到端优势（accuracy 81.8% vs Forest 42.9%、coverage 83.9% vs 48.9%、-30%~-40% 执行时间）、面积开销（MMAT 0.01279061 mm²，CACTI）与 CPU 开销（3.2%），并验证 1–32 GPU、multi-rack、内存超订等扩展场景。
