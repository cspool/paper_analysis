## Revisiting Global Value Prediction: A Resurgent Complement to Local Predictors

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 EgDiff——重设计的增强全局值预测器（global load value predictor），在 OoO 乱序处理器后端实现。核心架构：PC 索引预测表（4K 项）+ Global Value Queue（GVQ，共 64 项，逻辑上分为 speculative 段 32 项（与 LQ 同步）与非 speculative 段 32 项（匹配预测器 order））。四大核心机制：① aggressive confidence 机制——tag-based 索引（tag 用与索引不同哈希的 PC 哈希，减少 aliasing）、usefulness bits（u 位，正确预测递增、10-bit TICK 计数器周期性衰减、替换时只允许 u=0 的项被换出）、last misprediction 控制（误预测后 1024 条指令窗口内全局抑制预测输出，与 FPC 互补）、FPC（3-bit Forward Probabilistic Counter，概率向量 {1,1/4,1/4,1/8,1/8,1/8,1/8}，高位概率递减以减缓置信累积，误预测后从零重建）；② 非投机更新机制——预测器只用 commit 阶段的架构正确值更新（非投机段保存已提交值，预测用投机段），pipeline squash 只回滚投机段状态，杜绝误预测值污染预测器（对比 gDiff 的 no-squash 策略）；③ deferred prediction——base value 不可用时暂缓预测，把 distance/diff 写入投机 GVQ 条目并绑定到 base 指令条目的 Wake 字段，base 值就绪后反向触发（reverse-triggered）生成预测，无需前端 stall；④ distance polling 压缩——每表项只保留 1 个 diff + 1 个 5-bit distance 字段（替代 gDiff 每项 32 个 diff），用 Algorithm 1 轮询算法（δa≠δp 时 distance-1 递减探测更近位置、重置计数器，δa=δp 时递增 FPC 与 u）持续精化相关性，把 4K 项预测表从 1.03MB 压到 44KB（降 95.8%）。预测值同时写入 PRF 与投机 GVQ，验证在 GVQ 内完成（无需 PRF 读），仅误预测时回写 PRF，降低 PRF 端口压力；唤醒复用现有 load 完成端口与 wakeup 广播协议，无需专用端口。
  - 实验比较什么：① staged 消融：gDiff+sc（saturating counter）→ +tag → +lastmisp → +fpc，量化各置信机制贡献（gDiff+fpc 平均 3.24% IPC 提升，去 EVES 辅助仅微降至 3.11%）；② update/prediction 策略：nonSpec update（3.11%→3.25%）、squash vq（→3.61%）、gDiff+deferred（理想化反向扫描，→4.07%）vs gDiff+wakeuplinst（单 wakeup 实用实现，4.05%）；③ distance polling 有效性：distance 分布对比（图 13）+ 性能/覆盖（3.62%→4.37%，覆盖 22.27%→25.87%）；④ 与 baseline 对比：gDiff（4K 项 1.03MB）、EVES 8/32KB/unlimited（EVTAGE+ES）、hybrid EgDiff+EVES（Eves8Hybrid 6.17%、Eves32Hybrid 6.48%、EvesULHybrid 7.02%）、ES-HC-VS-VT unlimited（5.79%）；⑤ 成本-性能：EgDiff 5.5/11/22/44/88KB vs EVES 8/32KB vs 19KB hybrid（11KB EgDiff+8KB EVES=6.16% > 32KB EVES 4.81%）与 coverage 分解（EgDiff-only 9.4%、Ev-only 38.3%、Es-only 0.8%）；⑥ 敏感性：order 8-64（order-16 后饱和）、stride width 8-64 bit（32 bit 后稳定、56-64 bit 有小回升）、微架构规模（BASE/MID/LARGE：ROB 192/256/384、LQ 32/48/64、INT/FP/VEC PRF 168/224/336、L1D/L2 MSHRs 4/8/16 与 8/32/48；speedup 4.37%→3.75%→3.5%，EgDiff-deferred 每档贡献 0.6%/0.58%/0.33%）；⑦ 面积/功耗：McPAT + CACTI 7.0 @22nm。指标：IPC speedup（平均 4.37%）、预测覆盖率（25.87%）、误预测率（>99% 精度）、面积（预测表+GVQ 0.078mm² = 0.22% 处理器面积）、能耗（0.07% 处理器总能耗）。
  - 模拟基线配置（Table II）：gem5 中 4GHz OoO superscalar 核；Fetch/Issue/Commit 宽度 8 insts/cycle；L1I 32KB 4-way 2 cycle、64 项 ITLB、4 MSHR、64B fetch buffer；Branch Predictor: L-TAGE、4K 项 BTB、16 项 RAS、最小误预测代价 21 cycles（值误预测惩罚同为 21 cycles）；ROB/IQ/LQ/SQ = 192/64/32/32（STLF 延迟 1 cycle）；168/168 INT/FP PRF、1K-SSIT/LFST store sets（squash 时回滚、每 250K 次访问清除）、6 ALU(1c)、2 Mul/Div(3c/20c*)、4 FP(2c)、2 FPMulDiv(4c/12c*)、4 Ld/Str 端口+1 Str 端口（*非流水化）；L1D 32KB 4-way 3 cycle load-to-use、4 MSHR、64 项 DTLB；L2 私有 8-way 256KB 12 cycle 20 MSHR；L3 私有 16-way 2MB 32 cycle 32 MSHR；全部 cache 64B 行、LRU 替换、stride prefetcher（degree=4）；内存双通道 DDR4-2400、2 通道 2 rank/channel 16 banks/rank 512 row-buffer tREFI 7.8us。值预测器：gDiff 4K 项 1.03MB；EgDiff 4K 项 44KB；EVES 8KB/32KB/unlimited。

- 模拟器模拟什么的性能，修改了什么。
  - gem5 模拟什么：OoO 乱序超标量核的端到端执行性能——取指（L-TAGE 分支预测、BTB/RAS）、发射、执行（ALU/Mul/FP/load-store）、访存层级（L1I/L1D/L2/L3、MSHR、stride prefetcher、DTLB/ITLB）、DRAM（DDR4-2400 双通道时序）、ROB/IQ/LQ/SQ 与 PRF；加入值预测后模拟投机值注入 PRF、唤醒依赖指令、值误预测触发 21 周期最小惩罚的 pipeline squash 与恢复。输出每 workload 的 cycle/IPC、预测覆盖率、误预测率（→ 归一化 IPC speedup）。
  - 修改了什么：① 在 gem5 的 OoO 核中实现 gDiff baseline（PC 索引预测表每项 n=32 个 diff + distance index + 1.03MB 表；speculative update）；② 实现 EgDiff：预测表（4K 项 × 88 bit = 14-bit tag + 2-bit u + 3-bit FPC + 64-bit diff + 5-bit distance，44KB）、GVQ（64 项 × 141 bit = 64-bit value + VP/misp/available/distance/diff/wake 元数据，共 1.1KB；speculative 段与 LQ 同步、非 speculative 段 FIFO 接收提交值）、tag/u-bits/lastmisp/FPC 置信逻辑、10-bit TICK 衰减、非投机更新（commit 时值从 speculative 段传播到非投机段、squash 只清投机段）、deferred prediction（Wake 字段绑定、base 就绪反向触发、wakeup 广播复用 load 完成端口）、distance polling（Algorithm 1：δa = v_actual − NVQ[d].value 与预测 δp 比较，不等则 distance-1 并重置计数器/更新 diff，d 失效则重置默认 n；每 commit 至多算 distance 与 distance-1 两个 diff）；③ 实现 EVES（EVTAGE+ES，8KB/32KB/unlimited）与 hybrid 模式（EVES 预测写入 PRF 和 GVQ 作 base value，两者都有效时 EVES 优先）；④ 建模预测器延迟：EVES/gDiff/EgDiff normal 3 cycle、EgDiff deferred 额外 2 cycle（首周期读 Wake 字段定位绑定条目、次周期访问依赖条目取 diff 计算预测值）；⑤ 理想化 deferred 模型（CAM-like 反向扫描整个 value queue）与实用单 wakeup 模型对照。
  - 面积/能耗建模：McPAT 估处理器面积/功率；CACTI 7.0 @22nm 估预测表+GVQ 物理成本（0.078mm²、0.22% 处理器面积；能耗 0.07%）。GVQ 1.1KB；预测表为标准直接索引 SRAM（类似单个 TAGE 组件表），GVQ 为随机访问循环缓冲（类似 load queue），预测单次读取、更新至多两位置访问，无相联查找。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：gem5 开源（GPL，github.com/gem5/gem5，提供 value prediction 框架）；McPAT 开源（github.com/HewlettPackard/mcpat）；CACTI 开源（github.com/HewlettPackard/cacti）；Simpoints 3.2 开源（https://github.com/darchr/SimPoint）；SPEC CPU 2017 为商业 benchmark（需授权）。EgDiff 本身未找到公开实现（无法确认）。
  - 使用例子（gem5，基于官方文档与论文流程）：① `git clone https://github.com/gem5/gem5 && cd gem5 && scons build/ARM/gem5.opt -j$(nproc)`（AArch64 需 build/ARM 目标，SE 模式）；② 对 SPEC CPU 2017 ref 输入集用 ARMv8-A 交叉编译器以 -O3 编译（aarch64-linux-gnu-gcc -O3 -static），并用 Simpoints 3.2 选定 region of interest；③ 编写 gem5 配置脚本设置 Table II 的 OoO 核参数（--cpu-type=O3CPU、ROB/IQ/LQ/SQ 192/64/32/32、cache 层级、L-TAGE、DDR4-2400 内存），在 src/cpu/valuepred/ 下挂载实现的 EgDiff/EVES predictor，用 --simpoint-profile 跑 50M warmup + 100M 统计（共 150M 指令）；④ `./build/ARM/gem5.opt configs/... --cmd=./benchmark --options=...` 运行，从 stats.txt 读取 IPC、值预测覆盖率/误预测率、squash 次数；⑤ 对 baseline（无 VP / gDiff / EVES）与 EgDiff 各配置分别跑全部 SPEC CPU 2017 workload，IPC 归一化得 Figure 8-19。
  - 模拟器输入到性能输出全过程（gem5 原理）：输入 = ARMv8-A 二进制（SPEC CPU 2017 ref 输入、-O3、SE mode、Simpoint 选定区间）+ OoO 核/缓存/DRAM 配置（Table II）→ gem5 的 O3CPU 逐周期推进：取指单元经 L-TAGE/BTB 预测分支、每周期最多 8 条进入 decode/rename 分配 ROB/IQ/PRF/LQ/SQ 条目 → 发射后执行（load 经 L1D→L2→L3→DDR4-2400，load-to-use 3 cycle、L2 12 cycle、L3 32 cycle，miss 经 MSHR 处理）→ 值预测器在 dispatch/rename 阶段访问：PC 哈希索引预测表 → tag 匹配且 FPC 饱和(7) 时取 diff+5-bit distance → 从投机 GVQ 取 distance 处的 base value → 预测值=base+diff 写入 PRF（唤醒依赖指令）与投机 GVQ；base 不可用则进入 deferred 模式（写 distance/diff、VP=0、绑定 Wake）；执行完成后 LQ 结果与 GVQ 预测值比对验证，匹配则不回写 PRF，不匹配则置 misp、触发 21 cycle 最小惩罚的 pipeline squash 并回滚投机 GVQ；commit 时实际值 FIFO 传播到非投机段并更新预测器（Algorithm 1 距离轮询）→ 输出 stats.txt（总 cycles/IPC、每 workload 预测覆盖率、误预测率、squash 统计），归一化得到 IPC speedup。作用：在周期级精度评估"置信机制+非投机更新+延迟预测+距离轮询"四重改动对 OoO 处理器 ILP 的净收益、预测器面积/能耗成本，以及全局与局部值预测的互补性（hybrid 19KB 6.16% > 32KB EVES 单独 4.81%）。
