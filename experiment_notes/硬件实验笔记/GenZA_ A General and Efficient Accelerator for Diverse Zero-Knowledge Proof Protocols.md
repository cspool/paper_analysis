## GenZA: A General and Efficient Accelerator for Diverse Zero-Knowledge Proof Protocols

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现 = GenZA 统一可重构 ZKP 证明生成加速器：(1) 16×8 = 128 个同构 PE 组成 2D 阵列，每个 PE 含 32 条 lane（每条 lane 一个 64-bit 乘法器 + 两个 64-bit 模加/减器，乘法器物理实现为 66-bit）、128 kB SRAM scratchpad、lane 间 forward chain 与 crossbar；(2) 多 bitwidth 算术：用 Karatsuba-Ofman（KO）分解把 128/256（KO-2）、384（KO-3→KO-2）、768-bit（KO-3→KO-2→KO-2）分解到 64-bit lane，PE 内置四组 Pre/Post 阶段；提出 hybrid spatial-temporal 映射（KO-2 用 2 lanes、KO-3 用 4 lanes，2 cycle 完成、两个独立计算交错可达 100% 利用率），对比 fully spatial（ReZK 资源碎片化）与 fully temporal（768-bit 乘法 54 cycle 延迟）；(3) 模运算：通用大素数域（256–768 bit EC 域）用 Montgomery 算法（可配置 adder chain 多周期调度 + shifter 选中间积高低半部分），特殊模如 64-bit Goldilocks（p = 2^64−2^32+1）用 lane 内简化加减实现；(4) 全局辅助模块：SRAM 高 banked 全局 transpose buffer、MSM decoder & dispatcher、SHA3 core（Fiat-Shamir，<1% 时间）；(5) 2D mesh NoC（32×64-bit links @ 2 GHz）+ 2 个 HBM2e 接口共 1 TB/s；(6) 核心是 kernel mapping 软件策略（NTT 折叠流水线 + scratchpad 借贷、MSM 动态 window sizing + window-major 映射、Poseidon 1D 向量单元、sumcheck 延迟绑定 + eq-poly 空间压缩、多项式 kernel fusion/segmented-parallel、inter-kernel 空间分区流水线），由静态调度器用分析成本模型选择映射参数（NTT pipeline 长度、MSM window size）、分配 PE、生成静态执行调度。
  - 实验比较：(1) CPU：80 线程（2×20-core Intel Xeon Gold 5218R @ 2.1 GHz，8-channel DDR4 ~200 GB/s），Groth16 用 Jsnark+libsnark、HyperPlonk 用官方实现、Plonky2 用官方实现，平均 644×/374×/156× 加速（mock circuit 2^14–2^23）；(2) GPU：Groth16 对比 GZKP（V100）36.6×、Plonky2 对比 Plonky2 CUDA（A100）63.7×；(3) ASIC（统一缩放到 7nm）：Groth16 对比 PipeZK（181.79× 速度、24.64× ATP）、SZKP（17.94×、7.75× ATP）、LegoZK（4.79×、1.98× ATP）；HyperPlonk 对比 zkSpeed（2.51× 更好 ATP）；Plonky2 对比 UniZK（1.66×、1.64× ATP）；(4) 消融：折叠 NTT pipeline（2^23 NTT 时间 27.1→11.4 ms、off-chip 流量 7.4→3.0 GB、PE 利用率 16%→38%）、动态 MSM window sizing（最高 2.90×）、sumcheck 优化（流量 2.9→0.7 GB，4.1×）、fusion+pipelining（Plonky2 流量 1220→128.3 GB，9.5×）；(5) 可扩展性：PE 数与带宽 0.5×–4× 缩放；(6) NoC 分析：NTT worst-case 152 GB/s（仅 per-hop 容量 30%），MSM packet-level 模拟 dispatch stall 3.97%、peak link 44.51%。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 自研 cycle-accurate GenZA 模拟器（论文未给出独立名称/仓库），kernel 级正确性与性能经 RTL 验证；片上计算延迟按 kernel 分析建模，访存用 Ramulator2（https://github.com/CMU-SAFARI/ramulator2，References [49]）精确建模，显式考虑计算-访存依赖。面积/功耗：关键组件（PE 及其可重构算术单元）Verilog RTL 用 ASAP 7nm PDK（https://github.com/The-OpenROAD-Project/asap7，References [78]）综合，SRAM 用 FN-CACTI（References [61]）建模。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟器模拟 GenZA 加速器端到端证明生成：kernel 计算延迟（NTT 蝴蝶、MSM PADD、Poseidon、sumcheck、多项式运算）、HBM 访存（Ramulator2）、PE 间 NoC 数据流与 kernel 间依赖。论文没有修改现有模拟器，而是自建模拟器并内嵌 Ramulator2 做 DRAM 建模；同时为 NoC 分析另建一个 cycle-accurate packet-level 2D mesh NoC 模拟器（喂 MSM dispatch 流量评估 link 利用率与 stall）。RTL 侧：Verilog 实现 PE 与可重构算术单元，ASAP 7nm 综合出面积/功耗（Table III、Table VII）。

  - 模拟器输入→输出全过程（以 2^23 电路 Groth16 一次证明为例）：输入 = (a) 电路/mock circuit 参数（门数 2^23，控制 selector 多项式为二元、witness/constant 多项式 90% 稀疏 10% 稠密，曲线 MNT4-753/BLS12-381/BN128）；(b) 调度器输出：静态执行调度（各 kernel 的 PE 分配、NTT pipeline 长度 L=13 折叠到 2×8 PEs、MSM window size c 由成本模型按 bitwidth/N/SRAM/带宽选定、融合与流水线 cut 点）；(c) 架构配置（128 PEs、每 PE 128 kB、1 GHz、2 HBM2e、NoC 32×64-bit @ 2 GHz）。模拟推进：按调度逐 kernel 执行——MSM 阶段 decoder&dispatcher 把点分发给 window-major 映射的 PEs，PE 内 32/768-bit PADD 单元（14 次模乘时间复用）做 bucket 积累/归约；NTT 阶段沿行实例化 MDC 折叠流水线（FIFO 用 PE scratchpad 分区并跨 PE 借贷）；Poseidon 阶段每 PE 划成 8 个 1D 四乘法器单元做 x^7 S-box 与 MDS 矩阵向量乘；计算延迟按 kernel 分析模型算，访存延迟由 Ramulator2 对 HBM2e 建模，两者依赖关系显式串起。输出 = 端到端证明时间（如 Groth16 AES 2^14 电路 2.1 ms）、各 kernel 时间占比、off-chip 内存流量、PE 利用率、面积（58.5 mm²）与功耗（64.1 W）。作用：在无芯片情况下量化多协议统一架构的端到端性能与面积效率（ATP），并逐一验证折叠 NTT/动态 MSM window/sumcheck 压缩/融合流水线等映射优化各自的贡献。
