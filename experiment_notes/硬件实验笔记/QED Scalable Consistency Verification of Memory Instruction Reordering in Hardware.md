## QED Scalable Consistency Verification of Memory Instruction Reordering in Hardware

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 QED——对乱序发射（out-of-order-issue）处理器的访存指令重排做无界（unbounded）形式化验证的方法学框架（非新硬件设计，而是面向 RTL 微架构 LSQ 的验证流程，属于硬件架构验证层）。两部分：(1) MCM 侧——输入 MCM 规格（指令类型、顺序松弛、外部事件列表如 invalidation/外部读/miss/prefetch/eviction），用 Algorithm 1 自动生成探索树（exploration tree），对每条执行 trace 做环检测（cycle detection，成环 = MCM 违反），把违反 trace 转为决策树（decision tree）中简单、窄定义的谓词（如"被重排的 load 在 invalidation 时是否被 squash"）；two+two 结果保证谓词数与程序长度、in-flight 指令数、核心数无关；(2) RTL 侧——把谓词翻译成 SystemVerilog Assertions（cover/assert/assume），用 Cadence JasperGold 对 BOOMv3 的 LSQ RTL 做无界验证，并用"有限状态机 fast-forwarding"经验性状态空间缩减（其自身也被断言验证）对抗 RTL 状态爆炸（7^N 状态）。
  - 实验比较：对 SC、TSO、RVWMO 三种 MCM 自动生成探索树/决策树（SC 26 树/38 谓词、TSO 36/51、RVWMO 167/227，含 trivial 树与重复谓词），用 JasperGold 验证 BOOMv3 的 LSQ（128 loads/64 stores）是否符合 RVWMO。对比 baseline 是 prior work：litmus 测试（"*check" 系列，仅覆盖给定测试的交错）、bounded 穷举测试（[39]，实践上限 7 条指令）、PipeProof（SMT 无界但需人工不变量、仅 in-order）、Kami（模块化、仅 in-order）。指标：full proof time（墙钟时间，不按引擎数归一）、full proof depth（JasperGold 工作量）、memory consumed（找到证明的引擎内存），对 4 个代表谓词（ldA-ldA、fence-ldA、ldA-stB、stA-stB）在不同 LSQ 尺寸（WxNLxNS，如 6x32x16）下报告；另报告发现的 bug 数与修复后全验证时间。
  - 结果：发现 2 个正确性 bug（ld-amo：amo 在 store queue pre-commit 头部提前写、未等 ROB commit，破坏同地址 ld-amo 序；st-st：nacked 的 store 重试后把已完成的 younger store 也重复重发，重复写覆盖外部合法写）和 1 个性能 bug（ld-ld：observed 字段在 younger load 未 succeeded 或 store-forwarded 时也被置位，导致多余 squash）。修复后对 128ld/64st BOOMv3 LSQ 的 RVWMO 全验证在 10 天内完成。扩展性：LSQ 尺寸翻倍 → 验证时间约 ×10（2^n vs 10^n≈2^3.4n，各谓词斜率一致），proof depth 近似线性（翻倍约翻倍），内存近似二次（翻倍约 ×4）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 论文不修改也不使用周期级模拟器，而是商用形式化验证工具 JasperGold（Cadence，JasperGold Platform and Formal Property Verification App，闭源商业工具，论文引用 [1]）。被验证 RTL 为 BOOMv3（SonicBOOM，Berkeley Out-of-Order Machine，https://github.com/riscv-boom/riscv-boom，Chisel 编写、RV64GC、BSD-3-Clause、经 Chipyard https://github.com/ucb-bar/chipyard 实例化）。QED 框架本身未开源（论文无链接，联网检索截至 2026-08 未发现公开仓库；arXiv 2404.03113 为早期版本，本 ISCA 版含完整 BOOMv3 验证与 bug 修复闭环）。
- 模拟器模拟什么的性能，修改了什么。
  - JasperGold 对 SVA 属性做无界形式验证：cover 语句证明谓词前置条件可达（如乱序 load 可达），assert 语句证明 A|->B 对全部可达状态成立（反例 = 实现 bug），输入经 assume 约束（如 uop.valid |-> is_load XOR is_store）。对 BOOMv3 LSQ RTL 的附加/修改（仅验证辅助、不改功能）：(1) shadow logic——load_matrix[i][j]、ooo_load_matrix[i][j]、ld_st_mtx[i][j] 等组合逻辑辅助信号，判断 ldq[i] 与 ldq[j]/stq[j] 的程序序与乱序执行关系，综合时 elided、不影响功能；(2) 为 fast-forwarding 修改 load/store 条目 FSM——验证某直接序对时，把其余 load 在分配时立即快进到终态 observed（红色 fast-forward 迁移，图 12），仍按程序序提交，并加断言验证只有合法迁移存在、一个条目 FSM 不直接影响另一条目 FSM（间接交互经外部模块被 JasperGold 全输入空间捕获）；(3) backward-slicing 剪枝无关输入——83% 输入（91% bit）自动 assume 为 0（如 uop.is_br=0），因 BOOMv3 文档过时需逆向工程推断块级接口定义 assume；(4) 前缀-后缀不变式断言——valid 条目天然构成 load/store queue 连续前缀、invalid 构成连续后缀（连续分配、squash 作废后续指令），保证 fast-forward 后状态可数。
  - 模拟器输入到性能输出全过程：输入 = MCM 规格（指令类型与顺序规则、外部事件类型，Table I）+ BOOMv3 LSQ RTL + 谓词翻译的 SVA（图 11：cover(load_matrix[i][j] & ldq[j].succeeded & !ldq[i].succeeded) 等）+ assume 约束 → Algorithm 1 对每指令对/每事件类型枚举 trace 建树（O(m²e²) 棵树，m≤5 种指令、e<10 种事件）→ 叶 trace 环检测筛选违反 → 决策树谓词（Q1 重排？Q2 invalidation 下 squash？Q3 命中/缺失…）→ JasperGold 逐谓词无界证明/找反例 → 输出 full proof time/depth/memory 与通过/反例（反例定位到具体 RTL 信号，如 stq[j].in_flight、ldq[j].observed），修复后重验直至全部 proof。

  - QED 未开源（论文无代码链接，联网检索无公开仓库，无法确认）；JasperGold 为 Cadence 商业闭源工具（论文未用开源替代，如 Yosys-SMT/SymbiYosys）；BOOMv3 开源（BSD-3-Clause，git clone https://github.com/riscv-boom/riscv-boom 经 Chipyard 生成 SoC）。使用例子（复现一个 ldA-ldA 谓词的验证）：①按 RVWMO 规则（同地址 load 保序、异地址可重排）生成 ld-ld 探索树与决策树；②把谓词写成 SVA（如 Figure 11(c)：assert(load_matrix[i][j] & commit_load_idx==i & ooo_load_matrix[i][j] |-> (ldq[i].addr!=ldq[j].addr) || !ldq[j].observed)，附 cover 前置条件）；③把 BOOMv3 LSQ 模块 + shadow logic 读入 JasperGold，配置 assume（含 backward-slicing 的 0 假设）→ 跑 property verification engine（无界）→ 得反例则定位 bug（如 observed 字段在 load 未 succeeded 时被 invalidation 置位），修复 RTL 后重验，直到该谓词 proof 完成；④加 fast-forwarding shadow 逻辑并验证 FSM 正确性后，对 128ld/64st 配置跑全部 227 个 RVWMO 谓词，记录各谓词 time/depth/memory。作用：在无流片硬件的情况下，对真实乱序核（BOOMv3）的 LSQ 做无界 MCM 合规验证——覆盖所有程序的访存重排场景而非特定 litmus 样例，量化验证成本（时间/深度/内存）随 LSQ 尺寸的可扩展性，并给出 QED 相对 litmus/有界验证（≤7 指令）/in-order-only 方法的能力边界证据。
