## DICE: Detailed Inter-Chiplet End-to-End PHY Modeling for Accurate Chiplet Simulation

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现：DICE 是集成进 gem5 的运行时 PHY 建模模块，两条实现线：(1) 仿真器修改——扩展 gem5 Garnet 路由器微架构，在 chiplet 边界 PHY 路由器中新增 FEC 编码器、发送缓冲+allocator、调制仲裁器、PAM4 调制器（发送侧）与接收缓冲、LLR 计算、layered min-sum FEC 解码器（接收侧），实现 cut-through 流控、flit 级 ACK/NACK 与重传；(2) RTL 校准——用 Verilog 实现 flit 级 QC-LDPC 编码器与 layered min-sum 解码器，Yosys 综合 + OpenSTA 静态时序分析（TSMC 40nm 标准单元库）标定编码器 175 cells 满足 2.0 GHz、解码器 1 cycle/iteration 的延迟预算。
  - 实验比较：DICE（PHY 建模 chiplet）vs HeteroGarnet HG（固定延迟+限流 SerDes 抽象）vs Mono（32 核单片 4×8 mesh）；验证实验对照真实 AMD EPYC 9454P（8 CCDs×6 核）实测最大 C2C 延迟（HG RMSE 141.2 cycles / 46.4%，DICE 89.5 cycles / 29.4%，保真度提升 17.0%），及 ThreadRipper 3960X、EPYC 7R13 平均 C2C 延迟；敏感性实验：SNR_base（15–45 dB）对 pre/post-FEC FER、符号率（2–32 symbols/cycle）对平均包延迟与执行时间、IOD 路由器延迟、全局 vs 本地 LLC；系统级指标为 IPC（DICE 相对 HG 平均偏移 6.8%、最高 27.6%）与 gem5 运行时开销（0.3–26.1%，平均 9.2%）。
- 硬件平台是什么，配置是什么。
  - 模拟配置（Table II）：x86_64 OoO 核 3.0 GHz、ROB 512、IQ 160、LQ/SQ 各 160、TAGE_SC_L 64 Kbits 分支预测、L1 64KB-I/64KB-D 8 路、LLC 1MB/bank 16 路 MESI-Two-Level；CCD 8 核 2×4 mesh（4 CCDs 共 32 核），CCD NoC 2.0 GHz 128-bit、1-cycle router/2-cycle link；IOD 4 个 PHY 路由器 2×2 mesh、8 个内存控制器，IOD NoC 1.0 GHz 128-bit；32GB DDR5 4400、8 controllers；PHY 参数：QC-LDPC R=0.88（128-bit flit + 16 parity bits，Z=8）、1-cycle 编码、1-cycle 调制、layered Min-Sum 解码 1-cycle syndrome + 4-iteration 预算 + 1 cycle/iteration（总延迟 2N+1 cycles）、符号率 32 GT/s、SNR_base 35 dB、jitter 26 dB、crosstalk 20 dB（SNR_eff ≈ 19 dB、σ ≈ 12.7 mV）。真实硬件对照：AMD EPYC 9454P / ThreadRipper 3960X / EPYC 7R13。
- 开源编译框架是什么。修改了什么。（此问句模板为编译框架，本论文不适用；对应修改对象为 gem5）修改了 gem5 的 Python 配置脚本（构建 AMD EPYC 风格 CCD/IOD 布局）与 Garnet 路由器：chiplet 边界路由器新增 PHY 输出单元（FEC 编码、发送缓冲、调制仲裁）与 PHY 接收单元（接收缓冲、LLR 计算、FEC 解码、ACK/NACK 生成）；错误注入器在 flit 离开调制器时以 AWGN 噪声（σ 由 SNR_eff 谐和求和 SNR_base/jitter/crosstalk 导出）污染 2-bit PAM4 符号。
- 开源情况。代码已开源：GitHub https://github.com/RashidAGP/DICE-Simulator ；Zenodo artifact https://zenodo.org/records/19428665 ；arXiv:2607.24221。ISCA 2026 三枚 artifact 徽章（Artifact Available / Artifact Functional / Results Reproduced）。
- 基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 使用方式：gem5 SE 模式直接加载 14 个 benchmark（GAPBS bc/bfs/cc、SPEC2017 leela/mcf/omnetpp、Splash 4 lu-cb/ocean-cp/radix/radiosity/volrend、Rodinia kmeans、Kouilla sc、XSBench），每 CCD 跑一个进程模拟多程序服务器环境，初始化后打 checkpoint 进入 ROI；FS 模式引导 Linux 跑 C2C benchmark（内核时间戳测核心间延迟）用于验证。
  - 模拟原理与输入→输出全过程：benchmark 输入 → gem5 OoO 核执行产生访存 → Ruby 缓存层次 LLC miss 生成 NoC 请求包 → Garnet 在 CCD 内 2×4 mesh 转发 → 到达 chiplet 边界 PHY 路由器：每个 128-bit flit 独立 QC-LDPC 编码（+16 parity bits，1 cycle）→ PAM4 Gray 映射为 ±50/±150 mV 符号并串行化 → AWGN 错误注入（σ 由 SNR_eff 决定）→ 接收侧反序列化、逐符号计算位 LLR → layered min-sum 解码逐层更新 VN LLR、每轮 syndrome 检查，≤4 迭代（2N+1 cycles）→ syndrome 为零则 ACK 并释放发送缓冲，预算内不收敛则 NACK 触发仅该 flit 重传（cut-through 流控避免 HOL blocking）→ 通过后包继续经 IOD 2×2 mesh 到达内存控制器或目标 CCD → 输出统计量：逐包端到端延迟分解（NI queuing / network / FEC 编码 / SerDes / FEC 解码与 EC）、尾延迟直方图、IPC 与执行时间。
