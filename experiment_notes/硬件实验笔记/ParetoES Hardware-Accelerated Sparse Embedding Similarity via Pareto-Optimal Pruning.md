## ParetoES Hardware-Accelerated Sparse Embedding Similarity via Pareto-Optimal Pruning

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 ParetoES 的 FPGA 多核检索加速架构，部署于 HBM+FPGA（Xilinx Alveo U280）平台：32 个 Adaptive Cluster Probing Engine（ACPE）核心，各绑定一个 HBM2 pseudo-channel（512-bit 接口、225MHz、峰值 460GB/s），构成完全隔离的 compute-memory 对，无核间通信/同步，持续占满 32 通道带宽流式拉取稀疏矩阵。ACPE 内部数据流：(1) Distributed Micro-Sorting Unit（DMSU）——用 32 个核内 Bitonic-16 排序器替代单体 Bitonic-512（比较器从 11,520 降至 2,560、流水 45 级降到确定性 10-cycle 延迟），支持簇筛选与核内局部排序，集群索引与分数联合排序；(2) x-decoder——对 Ultra-CSR packet 做位宽 popcount 单周期解析行索引，生成 (x,y,val) 元组流入乘法器；(3) 15 路复制的 URAM bank 存 query 向量（每 packet 30 非零 vs 单 URAM 双读口，复制消除并行随机读瓶颈，30 读/cycle 全片上完成）；(4) Aggregator 行式部分和累加 → Top-16 Updater（LUT 比较器堆，拆成 4 个并行 Top-4 单元 + round-robin 轮询缩短关键路径，达 225MHz）→ Bitonic-16 两段 merge-sort；(5) 质心-向量共置（cluster-centroid co-placement）：质心预编码为 Ultra-CSR 放 HBM 通道头部，Mem Map scheduler + 预载 LUT 按软件配置的 sub_nprobe 定位下一目标簇地址，随机访问取簇块后走同一条 decode→multiply→aggregate→update 流水；(6) sub_nprobe 软件接口把 nprobe 与 bitstream 解耦（host 计算 sub_nprobe=⌈nprobe/32⌉ 静态配置），运行时调 Recall 无需重综合；(7) H2Balance 系统级负载均衡：热点 profiling（100 query 热点矩阵 H∈R^{100×C}，Q[c]=Σ_t H[t,c]）→ 热点锚定（top-32 簇静态分配给专用核）→ 贪心调和（其余簇按 argsort_desc(Q) 顺序贪心给最轻负载核）。实验比较：对比 CPU（Faiss-CPU、sparse_dot_topn）、GPU（Faiss-A100/V100）、FPGA（AccelES、FPGA32）的 QPS-Recall 曲线（Sp.Baidu 上 Recall@100≈0.8/0.9/1.0 时 QPS 4761.9/2857.1/1851.9，对应 (nprobe/nlist)=(128/398)/(224/398)/(384/398)，vs AccelES 固定 1818.2、FPGA32 固定 425.5）、延迟分布（Fig.12，P99 平均 179.6× vs Faiss-CPU、5.5× vs Faiss-GPU）、资源利用与功耗（Table V）、TCO 每查询成本（Table VI，中等 Recall 下比 AccelES 低 50–60%）；多优化消融（Fig.13）；H2Balance 消融（Fig.8，CV 34.25%→0.01%/5.16%、κ 4.64→1.24，吞吐 +37.52%）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 无模拟器：ParetoES 是实际 FPGA 综合实现，用 Vitis HLS 2023.2 工具链（AMD/Xilinx，https://www.xilinx.com/products/design-tools/vitis.html）编写 HLS 内核并综合到 Xilinx Alveo U280（https://www.xilinx.com/products/boards-and-kits/alveo/u280.html）。论文未修改任何公开模拟器；所有性能数据为实测。Baseline FPGA 设计：AccelES [60]（HPCA 2025，同组，Ultra-CSR + INT6 + ReSparse）、FPGA32 [47]（DAC 2021，BS-CSR 块流式 Top-K SpMV）。
- 模拟器模拟什么的性能，修改了什么。
  - 不适用（无模拟器，FPGA 实测）。实测性能（Sp.Baidu，Recall@100≈1.0）：LUT 54%、FF 37%、DSP 13%、BRAM 34%、URAM 63%、频率 225MHz、81.5 GOPS、59W、1.38 GOPS/W、0.18 GOPS/(GB/s)、成本 $8,575、9.51 MOPS/$；对比 FPGA32（46%/39%/18%/28%/46%、203MHz、34.1 GOPS、54W、0.63 GOPS/W、0.07 GOPS/(GB/s)）与 AccelES（44%/38%/13%/17%/63%、210MHz、83.3 GOPS、55W、1.51 GOPS/W、0.18 GOPS/(GB/s)）。INT6 计算/传输使数据并行度较 FPGA32 提升 2.7×（11→30 元素），DSP 单周期 3 个 6-bit 乘法。

  - 开源：论文未提供代码/工程链接，联网检索未发现公开仓库（截至 2026-08）；Vitis HLS 2023.2 为可获取的商业工具链。使用例子（输入到性能输出全过程）：输入为 C/C++/OpenCL HLS 内核（ACPE 各 stage：Ultra-CSR 解码、内积乘加、Top-4×4 updater、Bitonic-16 排序、Mem Map 调度）+ 约束（目标器件 U280、时钟、AXI/HBM 接口）→ Vitis HLS 综合（调度、绑定、流水线化、DSP/BRAM/URAM 分配）生成 RTL → Vitis 流程 place & route → bitstream 加载到 U280，host 端 XRT runtime 通过 PCIe 控制。检索运行过程（输入到性能输出）：(1) host CPU 量化 query、计算 sub_nprobe 并配置；(2) 各 ACPE 从本地 HBM 通道头部读质心（Ultra-CSR packet，30 非零/512-bit）→ x-decoder popcount 单周期解析 → 乘法器从 15 复制 URAM bank 取 query 元素做 6-bit 内积（DSP 1 周期 3 次 6-bit 乘法）→ Aggregator 累加行部分和 → 4 并行 Top-4 updater 维护局部候选 → Bitonic-16 两段 merge-sort 10 级输出有序 Top-16；(3) Mem Map scheduler 依据 sub_nprobe 与 LUT 表发随机访问请求取下一簇块，重复至 sub_nprobe 个簇完成；(4) 32 核各回传 Top-16，host 聚合为全局 Top-512（2KB/query、微秒级 PCIe 传输）→ 输出 QPS/Recall@K/延迟；H2Balance 的 cluster-to-core 映射 M 在 host 侧离线由热点矩阵 H 计算后静态配置，运行时仅改 sub_nprobe 参数即可调 Recall 目标，无需重新综合 bitstream。
