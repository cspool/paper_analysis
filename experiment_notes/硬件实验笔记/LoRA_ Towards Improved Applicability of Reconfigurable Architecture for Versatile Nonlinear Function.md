## LoRA: Towards Improved Applicability of Reconfigurable Architecture for Versatile Nonlinear Functions

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为基于 Chipyard 的 CGRA SoC：在通用 CGRA 中集成可重构非线性功能单元 XCore-PE（LoRA），配合编译器端到端框架，让 CGRA 无需把非线性函数卸载到 host CPU 即可高效执行各种非线性函数（激活函数、三角函数、幂/对数等）。XCore 是 5 级流水线（Pre-Process→LOG→LNS→ALOG→Output，级间寄存器分隔）的轻量可重构单元，采用普通算术+LNS 混合数制：加/减用普通算术，乘法/除法/幂/对数/多项式用 LNS（把 c_i·x^(k_i) 化为 2^(log2(c_i)+k_i·log2(x))，把乘法变成加法）。32-bit 数据，支持可编程定点（Qm.n，fraction 宽度可调）、FP32、LNS 三种格式。四种可配置模式：①乘/除法（4 cycle）、②幂 x^y（4 cycle）、③对数 log_b(x)（4 cycle）、④多项式（最多 6 项=5 个含变量项+1 个常数 bias 项，7 cycle）。关键硬件点：LOG 级对数转换器（LOD 检测 MSB + APP 单元 PWL 近似 log2(1+f)，APP 由 SOTA 探索框架 [82] 生成，定点输入由 LOD 隔离 f、FP 输入直接取 f）；LNS 级用可编程 30b×30b 乘法器（5 个 Booth 编码器生成 30b×6b 部分积后求和），6 项多项式时把 30b 操作数分解为 5 个 6b 子操作数（k_i 指数只需 6 bit）复用大部分硬件；ALOG 级反log转换器（2^f 的 PWL 近似 + 自定义 fine-tuning）+ CPA 加/减 + 饱和单元（SAT 检测饱和/溢出并对齐格式）；Output 级加法树（每 CPA 可配定点/浮点加，输出加寄存器改善时序）。6 项时 30-bit 操作数分解为 5 个 6-bit 存 k_i；4/5 项时 LNS 宽度相应降到 18/24-bit。
  - CGRA 集成：异构 CGRA（类 [16][27][66][71] 空间架构），每个 FU 加载一个配置执行所有迭代再切换配置，每单元自带配置内存。组件：PE（普通计算，partial-prediction [29] 处理分支，需额外细粒度输入输出做 select）、XCore-PE（复杂运算：多项式、x^y）、IOB（与 SPM 数据交换，loop 元信息隐式编码在访存中由 IOB 控制器管理；仿射访问由配置自动生成 SPM 地址，非仿射访问如 A[B[i]]/A[i*i] 由其他单元算地址经第二输入喂入，故 IOB 双输入接两个 GIB）、GIB（port-to-port/track-to-port/track-to-track 三类互连，track-to-track 按 Wilton 模式支持长距离通信，后端生成所用 GIB 配置）。参数化设计可配 CGRA 尺寸、每位置 PE 类型、每 PE 支持运算。SoC（Fig.5）：5 级 in-order 64-bit RISC-V Rocket CPU + 异构 CGRA + 其他子系统，RoCC（Rocket custom coprocessor）自定义指令经 reservation station 按依赖分发到各控制器，load/store 控制器经 TileLink+DMA 管理 L2↔SPM 数据传输，CGRA 控制器配置并监控执行。
  - 实验比较（系统级三套 SoC）：①Generic CGRA（baseline，支持定点/浮点但不能处理非线性，仅评估加非线性支持的硬件开销）②PICACHU（ASPLOS'25，重实现 FP2FX 浮点转定点模块 + Taylor 展开 + 算子融合模块集成进 Generic CGRA 的 PE）③LoRA（Generic CGRA + 2 个 XCore-PE + PE 中加 MAD 运算提升计算密度）。为公平，各 CGRA 尺寸 6×6=36 PE + 12 IOB + 12 个 4KB SPM bank，L2 128KB；PICACHU 与 LoRA 为异构（部分 PE 加 MAD）。系统级 8 benchmark/11 loop kernel（Mish、Logsigmoid、Softmax×3、Softplus、Swiglu、Svm、DCT、KNN×2，激活函数 benchmark 来自 CGRA-Nonlinear-Benchmark [55]/PICACHU [56]）；另与 STM32H750 MCU（ARM Cortex-M7，480MHz，CMSIS-DSP [5]，40nm）比扩展性。指标：总周期数（分解为 CPU EXE/LOAD/CFG/CGRA EXE/STORE）、能耗效率、SoC/CGRA fabric 面积、频率。结果：LoRA vs PICACHU 平均性能 2.18×（DFG 节点从 PICACHU 36-37 降到 11-15，释放 PE 支持 loop unrolling；sqrt 由 XCore 在片上算而 PICACHU 卸载 CPU）、能耗效率 2.13×；LoRA-6×6 vs STM32H750 平均 23.33×；面积 vs PICACHU 增 3.7%（SoC）/10.1%（CGRA fabric）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 无独立第三方模拟器名：SoC（除 XCore 外）用 Chisel [8] 建模，XCore 用 Verilog 建模，生成 Verilog 可用于 ASIC 或 FPGA 原型；论文用 Synopsys VCS 仿真验证正确性与性能；面积/功耗用 Synopsys Design Compiler + TSMC 40nm 工艺库 + compiled memory 综合估算（~475MHz，关键路径在普通 PE 的浮点加法器）。开源（artifact 因 EDA 许可改用 Verilator 仿真器）：https://github.com/Dai-dirk/COFFA/tree/LoRA-ISCA-AE（LoRA 是 Fusion 框架的一部分，主仓库 https://github.com/Dai-dirk/COFFA，branch LoRA-ISCA-AE 含 App-Compiler/FGRA-Compiler/LoRA_SoC_Src/PiecewiseChebFitter/System_level_benchmarks/Verilogs/SoC_Area_Report/Resources(COFFA-Manual-1.0.pdf)），Docker 镜像 docker.cnb.cool/fudaneda/docker/chipyard，Zenodo DOI https://doi.org/10.5281/zenodo.19447155，BSD 3-Clause。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 SoC 端到端执行：总周期数及其分解（CPU EXE/LOAD/CFG/CGRA EXE/STORE），用于比较 PICACHU vs LoRA 各 benchmark 的周期、有/无 loop unrolling 的性能，以及扩展性（LoRA-5×5 2 XCore / 6×6 2 XCore / 9×8 3 XCore / 16×6 4 XCore，频率近 475/470MHz）。修改内容：在 Chipyard 生成的 Rocket+CGRA SoC 基础上集成 XCore（Verilog）为 XCore-PE、给 PE 加 MAD 运算；实现 20 个 XCore 变体（不同转换器精度/段数/项数）做设计空间探索（图 8 按归一化 ADPP-精度选点），选 XCore-A/B/C（7 段）与 XCore-C（6 段）用于单元级与系统级集成。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：LoRA 全部源码开源（COFFA 仓库 LoRA-ISCA-AE 分支，BSD 3-Clause，Zenodo 归档），依赖 Chipyard（https://github.com/ucb-bar/chipyard）、Chisel、Rocket Chip Generator；建议用提供 Docker（docker.cnb.cool/fudaneda/docker/chipyard，Ubuntu 20.04，约 23GB，准备约 2 天、跑完三级评估约 14 天）。论文/artifact 明确说明因 EDA 许可无法提供 Synopsys VCS，改用 Verilator 仿真器复现系统级结果。
  - 模拟器使用例子（system-level 复现）：`cd /root/chipyard && conda activate ./.conda-env && cd generators/fgra`；`python3 build_verilator.py LoRA` 构建 LoRA 的 Verilator 仿真器 → `python3 run_verilator_lora.py`（或无 unroll 的 `run_verilator_lora_unroll.py`）跑 11 个 kernel → 输出各 benchmark 周期数（对应 Fig.10）；PICACHU 同理 `build_verilator.py PICACHU` + `run_verilator_picachu.py`/`run_verilator_picachu_unroll.py`。面积报告在 https://github.com/Dai-dirk/COFFA/tree/LoRA-ISCA-AE/SoC Area Report。
  - 模拟原理与输入→输出全过程：输入 = bare-metal 可执行文件（C 编译；loop kernel 经 LLVM 前端 → DFG 生成（非线性函数作为 __CGRA__HARDWARE_OP 自定义节点）→ 后端模拟退火映射到 CGRA + 内存分区算法分配多 bank SPM 并调度 bank 冲突 → 生成 CGRA calling function：load 配置/数据到 SPM、配置 CGRA、激活执行、写回主存的 RoCC 指令序列）→ Rocket CPU 经 RoCC 接口把指令送 reservation station → 各控制器执行：load/store 控制器经 TileLink/DMA 把数据从 L2(128KB) 搬入 SPM(12×4KB)（LOAD）→ CGRA 控制器配置各 FU（CFG）→ CGRA 按配置执行（CGRA EXE，XCore 内 4/7 cycle 流水完成非线性多项式运算，配置切换间数据同步靠 FU 内寄存器同步器）→ 结果写回主存（STORE）→ 周期精确仿真器累计并输出各阶段周期 → 除以频率得 runtime。作用：在没有真实芯片（TSMC 40nm 综合未流片）情况下周期精确验证 CGRA 架构与 XCore 的正确性和性能，量化非线性函数不卸载 CPU 的收益（KNN 的 sqrt 在 PICACHU 卸载 CPU 造成 CPU EXE 周期占比极高，LoRA 用 XCore 直接在片上算）。
