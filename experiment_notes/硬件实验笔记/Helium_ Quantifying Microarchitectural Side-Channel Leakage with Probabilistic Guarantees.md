## Helium: Quantifying Microarchitectural Side-Channel Leakage with Probabilistic Guarantees

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 Helium，一个量化特定微架构上程序秘密经硬件侧信道泄漏的三部分框架：(1) Pointwise Maximal Leakage（PML）指标——逐观测量化泄漏 ℓ(y)=log max_{x} P_{X|Y=y}(x)/P_X(x)，支持 tail-bound 隐私保证 P_Y[ℓ(Y)≤ε]≥1−δ；(2) µobs functions——把硬件数据相关优化（zero-skip、digit-serial、bit-serial 等 computation simplification 优化）建模为"指令不安全操作数→可观测微架构执行（µobs）"的约束公式集，对 intrinsic transmitter（自身产生执行可变性的指令，如 MUL）把不安全操作数映射到其自身可观测执行路径；(3) Tracer——TracerSym（扩展 Angr 的符号执行 + Bitwuzla/CSB SMT 求解 + Ganak 模型计数，精确）与 TracerSim（Intel Pin 动态二进制插桩的 Monte Carlo 模拟 + Clopper-Pearson/Rule of Three 保守统计界，近似），计算程序级 µtrace（逐指令 µobs 序列）概率分布并输出 tail-bound 保证。
  - 实验比较什么：四个 case study 比较不同 µobs functions（硬件优化）下同一程序/微架构组合的泄漏，以及"接受小概率泄漏"vs 零泄漏软件缓解 cio（ASPLOS'24 二进制码变换，表 V 的 mul64/cs64/cs32 类别）的性能开销权衡：(1) Poly1305（Libsodium MAC，128-bit key）在 zero-skip 与 digit-serial 乘法 µobs function 下——zero-skip 得 P[ℓ≤1.35×10⁻⁹]≥1−9.39×10⁻¹⁰，digit-serial 得 P[ℓ≤0.97]≥1−0.49；(2) Firefox feConvolveMatrix SVG 卷积滤波（3 像素秘密，全 1 卷积矩阵）在同样两种优化下——zero-skip 产生 8 个 µtrace、每个 PML=3（全泄漏），digit-serial 仅 1 个 µtrace、PML=0（无泄漏），两种优化的相对安全性在两个程序间反转；(3) TracerSym 可扩展性——图像变换 kernel（box blur 及自设计 posterization/channel swapping/packing/bit reversal/thresholding/nibble interleaving）上增加被插桩动态指令数（不同 opcode 加 zero-skip µobs）或每 µobs 函数 µobs 数（digit-serial 改 8/4/2/1-bit 宽度→1/2/4/8 个 µobs），观察运行时与 SMT 查询数（最坏指数增长，可达 µtrace 集饱和后近线性）；(4) Chacha20-Poly1305/AES-GCM/Ed25519/Argon2id 在 cio 优化类别下——如 Chacha20-Poly1305 容忍 P[ℓ≤0.0004]≥0.9997 即可消除 mul64 的 2.31×、cs32 的 3.37× cio 开销；Ed25519 按函数分解（表 VII）支持选择性缓解避免 8.79× 全量开销。
- 硬件平台是什么，配置是什么。
  - 论文评估机：两个 compute node，各 2× 32-core 2.9GHz Intel Xeon CPU、512GB RAM。artifact 复现规格：2× Intel Xeon Gold 6226R @2.90GHz（每 socket 16 物理核，32 物理核、64 逻辑 CPU 超线程）、512GB RAM（实验最多用 32GB）、8GB 磁盘；需 x86_64 机器 + Docker + Git + Bash + Python 3（其余依赖在 Docker 镜像内）。被建模的微架构为抽象的 µobs functions（非真实硬件），对应计算简化优化：zero-skip（操作数含 0 时快速路径）、zero/all-ones-skip（AND）、zero/one-skip（MUL）、digit-serial（MUL 按乘数最高字节为 0 分 4/8 个 µobs）、bit-serial（DIV，CVA6 RISC-V CPU 风格位串行除法单元，65 个 µobs）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - Tracer 是自研的程序分析/仿真框架（artifact：https://github.com/samanthaarcher0/Helium-Artifact，MIT License；归档 DOI：https://doi.org/10.5281/zenodo.19446913）。TracerSym 扩展符号执行引擎 Angr（https://angr.io，ref [85]），使用 Bitwuzla（https://github.com/bitwuzla/bitwuzla，ref [69]）与 CSB（ref [84]，bit-vector 计数采样工具）做 SMT 求解、Ganak（https://github.com/meelgroup/ganak，ref [83]，probabilistic exact model counter，正确性保证概率可配置、论文用 0.95）做模型计数；TracerSim 用 Intel Pin（https://www.intel.com/content/www/us/en/developer/articles/tool/pin-a-dynamic-binary-instrumentation-tool.html，ref [65]）做动态二进制插桩。未修改现成处理器模拟器（如 gem5 等）。
- 模拟器模拟什么的性能，修改了什么。
  - Tracer 模拟/分析的是 victim 程序在（µobs functions 建模的）微架构上的可观测执行，不是 cycle-accurate 性能：给定二进制程序 P、秘密输入列表、µobs functions 集合 F={f^{µobs}_{op0},...}，输出每个程序级 µtrace 的概率分布，进而计算每条 µtrace 的 PML（确定性信道下 ℓ(y)=−log P_Y(y)）与 tail-bound 保证 (ε,δ)。TracerSym 修改 Angr 符号执行引擎：符号执行中拦截秘密相关 transponder，把 µobs function 的每条约束与已有 µtrace 约束合取、SAT 检查后逐层构造符号 µtrace 树（图 6，SAT 黑节点保留/UNSAT 白节点丢弃），路径终点 bit-blast 后交 Ganak 模型计数（概率 = 模型数/2^{|ŝ|}）；TracerSim 修改 Intel Pin 写插桩工具：逐 trial 记录动态 transponder 操作数值生成具体 µtrace，频率/N 估计概率，两轮采样（N₁ 定 ε、N₂ 定 δ）+ Clopper-Pearson 95% 置信区间，仅见单 µtrace 时用 Rule of Three（未观测事件概率 <3/N）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：Helium-Artifact（https://github.com/samanthaarcher0/Helium-Artifact）公开，MIT License，Zenodo 归档 DOI 10.5281/zenodo.19446913；Docker 化：Dockerfile 构建含 Python 3、必要 Python 包、Intel Pin 与 solver 二进制的镜像；所有 workload 预编译并包含在仓库中（自包含，无需运行时安装 Libsodium/Firefox 等第三方库）。使用：git clone https://github.com/samanthaarcher0/Helium-Artifact.git → cd Helium-Artifact → docker build -f Dockerfile -t helium_artifact . → docker run -it helium_artifact → 逐 case study 跑 ./run_case_study_I.sh（<6min）、./run_case_study_II.sh（<1min）、./run_case_study_III.sh（~1.5h）、./run_case_study_IV.sh（<6h，Monte Carlo 结果略有波动属正常）；输出在 results_case_study_{I,II,III,IV}/ 目录（日志、Table、PDF 图，如 Poly1305_tail_bound_guarantees.log、Figure_7_poly1305_ep_delt_under_two_lfs.pdf、Table_IV_convolve_tail_bound_guarantees.log、Figure_8_scalability_eval.pdf、Table_VI_case_study_4_results.log、Table_VII_ed25519_leakage_by_function.log）。
  - 模拟原理与输入→输出全过程（以 Case Study I 的 Poly1305 zero-skip 为例）：输入 = (a) 预编译 Libsodium Poly1305 二进制；(b) 秘密输入：128-bit key（假设均匀分布，符号化位向量 ŝ）；(c) 一个 µobs function f^{µobs}_{MUL}（zero-skip 变体：仅看第二操作数是否为 0，两个 µobs）。TracerSym 推进：Angr 符号执行初始化 ŝ 与 µtrace 约束集 C₀={True}，到达第 j 个秘密相关 MUL 时取符号操作数 O_j，对 C_{j-1}×f^{µobs}_{MUL} 的每个合取 φ∧c(O_j) 做 SAT 求解，SAT 保留进 C_j（UNSAT 丢弃），逐路径构造 µtrace 树；路径终点得到完整符号 µtrace 集 C_n，每个 φ 与路径约束合取后 bit-blast 成布尔公式，交 Ganak 模型计数得到对应具体 µtrace 的秘密输入个数，除以 2¹²⁸ 得概率（图 5 上分支）。输出 = µtrace 概率分布 → 每条 µtrace 的 PML（ℓ=−log P_Y(y)）→ 按 §VI-B 选"可容忍划分"中概率最低的 µtrace 作 ε-µtrace（ε=其 PML=1.35×10⁻⁹），1−δ=可容忍集概率和（δ=9.39×10⁻¹⁰），得 tail-bound 保证 P[ℓ(Y)≤1.35×10⁻⁹]≥1−9.39×10⁻¹⁰；TracerSim 路径（图 5 下分支）以 Pin 插桩逐 trial 记录动态 MUL 操作数、频率/N 估计概率、两轮采样 + Clopper-Pearson 出保守 (ε,δ)（Case Study IV：N=10,000/轮，Chacha20-Poly1305 mul64 仅见单 µtrace ⇒ Rule of Three 得 P[ℓ≤0.0004]≥0.9997）。作用：在设计早期评估硬件数据相关优化（zero-skip/digit-serial/bit-serial）对不同程序的泄漏风险，量化为可解释的 (ε,δ) tail-bound，支撑"接受多少小概率泄漏以换取多少性能/避免多少 cio 缓解开销（2.31×~15.71×）"的缓解决策。
