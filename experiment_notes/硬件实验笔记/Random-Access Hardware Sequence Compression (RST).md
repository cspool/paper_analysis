## Random-Access Hardware Sequence Compression (RST)

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 RST 压缩器与解压器专用硬件（可综合 SystemVerilog IP）。(1) 压缩器三模块并行（Fig.11）：substitution module——CAM 匹配选中序列的所有出现→替换为字典索引→scatter-gather compaction（Fig.12）；含 overlap-filter 电路解决 run 内重叠匹配的数据冒险（Fig.13：当选中序列在重复周期<序列长度的 run 中出现时并行匹配会误报重叠匹配，仅 10 种重叠 pattern，用沿 run 重复的 mask 过滤，保持单周期吞吐）；update generator——对每个替换位点生成 {sequence, ±1} count updates（-1 给与替换符号重叠的序列，+1 给含新字典索引的序列），用 splice-and-cancel 构造（每个位点左侧 post-substitution、右侧 pre-substitution 拼接成 decrement/increment 窗口，Fig.15）消除相邻位点窗口重叠导致的双计数（重叠序列以相反符号出现并相消，类似 telescoping series）；table update module——4 个子表（2/3/4/5 符号长度），共 32 个 SRAM bank（16 sets/bank、4-way 组相联），路径为 hash→sorting network 聚合相同序列的 ±1 为净更新→按 bank 分区→per-bank FIFO→每 bank 每周期一次更新，满时淘汰最低 count way（Fig.16）。吞吐瓶颈在表更新：每替换位点最多 44 个更新（n 长度 2n+4，n∈{2,3,4,5} 共 8+10+12+14=44），故 update generator 每周期处理 2 个位点、substitution 以 256-symbol 硬件 chunk 处理（匹配/compaction 宽度 4096→256，压缩率仅损失 2.32%），模块流水重叠。最后静态符号字典 pass 用 LUT+shifter 每周期编 8 个 code。(2) 解压器（Fig.17）：8B 位置元数据 64-bit 向量前缀和(~1ns)定位含目标块的 DRAM 块→静态符号字典解码（数据 ~8 cycle、序列字典 ~16 cycle）→展开表（≤2880 bits 只读结构，寄存器实现，索引→2~5 符号序列）→多个独立 LIFO expander 并行展开（DRAM 块分段，每 LIFO 每周期 2 次栈操作：字面量 pop 到输出缓冲、字典索引 push 序列倒序入栈），输出拼接。最坏深度嵌套 <4n 次栈操作、<128 cycle。
  - 实验比较：综合指标对比 TMCC ASIC Deflate（同一 ASAP7 7nm、2.5GHz、同一 Synopsys 流程，Fig.20）：解压计算延迟平均 17ns + 定位 1ns = 18ns vs Deflate 半页解压 140ns；解压器面积 0.03mm²、功耗 91mW（比 Deflate 解压更省电）、吞吐 13.3GB/s（较小配置并行度略低）；压缩器 0.0923mm²、349mW、4.13GB/s vs Deflate 0.094mm²、320mW、17.2GB/s（吞吐低但可用多引擎并行、压缩延迟远不如解压关键）。功能正确性：post-synthesis gate-level 仿真 100 万页 byte-exact roundtrip。系统级：在 DyLeCT 硬件压缩内存系统（baseline 用 ASIC Deflate + expand-on-access）替换为 RST，平均性能 +15%（几何平均 14%，Fig.22），压缩数据访问延迟 ~110ns vs baseline 260ns~1µs（Fig.23），readStride-1K 微基准 5.1×。

- 模拟器模拟什么的性能，修改了什么。
  - gem5+Ramulator 模拟：硬件压缩内存系统（DyLeCT 基线）在 4 核 2.8GHz 乱序核（Table 4）、1 通道 25.6GB/s 8-rank FR-FCFS 内存下的端到端性能（提交 store 指令数归一化、LLC miss 中压缩数据访问延迟从 MSHR 分配到响应的时延）。修改（Fig.21）：把 DyLeCT 的 ASIC Deflate 换成 RST——读压缩页时先只取+解压请求的块、回复 cache 后再取整页扩展（Deflate 必须先取整页）；排队延迟高时跳过页级 fetch/expansion（Deflate 无法跳过）；写压缩页时用页内现有字典+目标 DRAM 块局部重压缩被写块（不更新字典，比全 RST 压缩快，因大部分延迟在字典构建），若该 DRAM 块仍装得下则跳过页 fetch/expansion（Deflate 需取被写块之前全部数据并重压其后所有数据）。8B 位置元数据与压缩翻译条目（CTE）共存，16B/页翻译项。Verilator 侧：SystemVerilog 压缩器+解压器端到端验证，从 cycle count 提取压缩率、吞吐（B/cycle→GB/s@2.5GHz）、每块解压延迟（对应 Fig.20）。综合侧：Design Compiler + ASAP7 2.5GHz 出面积/时序 slack/功耗（synthesis/results/ + evidence/signoff_summary.md）。

  - 模拟器输入到性能输出全过程（Verilator 原理）：输入 = SystemVerilog RTL + 内存 dump 页 → Verilator 5.046 将 RTL 编译为 C++ cycle-accurate 模型 → 压缩：对每页驱动压缩器时钟，substitution（CAM 匹配+overlap filter+替换+compaction，256-symbol chunk/cycle）/ update generator（2 位点/cycle，splice-and-cancel 生成 ±1 更新）/ table update（sorting 聚合→32 bank FIFO→SRAM 更新）三模块流水重叠 → 输出压缩页+128B 字典 → 解压：位置元数据前缀和→静态符号解码→展开表→LIFO 并行展开 → 与原始页 byte 比对 + 计数 cycle → 输出每页压缩率/吞吐/解压延迟 → 聚合为 Fig.20 指标。gem5+Ramulator 全系统原理：输入 = workload 二进制（12 DyLeCT workloads + readStride-1K）→ gem5 乱序核模型产生访存 → Ramulator 建模 DDR 时序（1 通道 8 ranks、FR-FCFS、tCL/tRCD/tRP=13.75ns、25.6GB/s）→ 硬件压缩层翻译压缩页访问：RST="取 128B 字典+64B 块→解压→先回块后扩展" vs Deflate="取整页→串行解压→扩展" → 输出每条 LLC miss 的压缩数据访问延迟（MSHR 分配→响应，Fig.23）与整机性能（提交 store 数，Fig.22）。仿真时长：5s atomic warmup（>200 亿指令）+ 1ms detailed warmup（流水线/分支预测/预取器）+ 4ms 详细仿真。
