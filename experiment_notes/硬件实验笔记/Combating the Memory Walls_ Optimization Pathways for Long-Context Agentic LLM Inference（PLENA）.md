## Combating the Memory Walls: Optimization Pathways for Long-Context Agentic LLM Inference（PLENA）

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 PLENA 加速器（SystemVerilog RTL + 多保真模拟器）：(1) flattened systolic array——由若干小方阵 sub-arr 串成一排构成，输出驻留（output-stationary）数据流，全流水消除 tile 间气泡；每个 sub-arr 产出 (BLEN,BLEN) 输出 tile 的 (BLEN,MLEN)×(MLEN,BLEN) GEMM，跨 sub-arr 部分和用结果加法树汇总（专用 M_SUM 指令，沿大 K 维一次 GEMM 仅需一次 cross-array 求和）；FFN 场景 BLEN 设小（≈batch 的 M 维），FlashAttention 场景阵列切分为多个小 flattened core 做 per-head GEMM（(BLEN,HLEN)×(HLEN,BLEN)，MLEN//HLEN 头并行）；PE 原生吃 MX 格式输入、INT 精度累加、写回前转目标激活精度；(2) 非对称算术数据通路——激活以高精度 FP 存 Vector SRAM（scratchpad），权重/KV 以低精度 MX（MXINT/MXFP）存 Matrix SRAM，可选片上旋转抑制 outlier；新 K/V append 前做 Hadamard 旋转再量化入 HBM，读入 Matrix SRAM 后做逆变换，权重加载绕过逆变换；(3) 存储系统——Matrix SRAM 支持转置/非转置读（逻辑行分布到多 sub-bank 的不同地址，行列访问映射不同 bank 无冲突、零额外周期），HBM 中 MX 块与每块 scale 分离存储以对齐内存边界；Matrix/Vector SRAM 各带硬件预取引擎（H_LOAD_M/H_LOAD_V 指令控制、M_Load/V_Load 可配）后台流式取数隐藏 HBM 延迟；(4) FlashAttention 原生支持四要素：tile 级预取与计算重叠、transpose-on-read、vector/scalar 单元提供 online softmax 的行归约与非线性（max/sum/exp/div；VLEN 可配、softmax 常用高精度如 FP12）、ISA 细粒度 tile-by-tile 持久调度；(5) PLENA ISA：32-bit 指令，Matrix(6)/Vector(13)/Scalar(17)/HBM(3)/Control(8) 共 47 条，PCIe 动态分发。
  - 实验比较：加速器基线 MicroscopiQ、OliVe、FIGNA（其核心组件由作者复现并集成到 PLENA 平台公平比较，均 64×64 方阵；Table XI：comp area 0.237 vs 0.138/0.319/0.471 mm²，TOPs/mm² 34.49 vs 59.45/25.66/17.39，标准负载 S.A FLOPs/mm² 29.31 vs 3.36/1.60/7.51，agentic 负载 A.A FLOPs/mm² 12.81 vs 1.08/0.40/6.71，PLENA 用 4×1024 阵列）；系统级 vs 4×A100 SXM（80 GB、1.99 TB/s/卡）、4×H100 SXM（80 GB、3.35 TB/s）、16×TPU v6e（32 GB、1.56 TB/s/设备），按乘法器数对齐设备数；PLENA/MicroScopiQ 建模为 16 加速器系统（HBM 容量带宽对齐 TPU 系统）。LLAMA-3.3-70B OSWorld-L：TTFT 43.43 s、TPS 2.21× A100、Tok/J 4.04×；整体最高 2.23× A100（114k/5k 负载）、4.70× TPU v6e（2.21/0.47）吞吐、4.04× 能效。消融：Figure 12（BLEN 对齐 batch 时 FFN 阵列利用率最优）、Figure 13（prefill/decode 分阶段 comp/mem active 时间、SA 利用率、带宽利用率分解）、Figure 14（不同阵列形状矩阵单元面积/功耗对比，flattened 阵列面积功耗略增但有效能耗显著降低）。
- 硬件平台是什么，配置是什么。
  - PLENA：SystemVerilog RTL，Synopsys Design Compiler + 7 nm OpenROAD 预测 PDK 综合，1 GHz；co-design 选出配置 BLEN=32、MLEN=2048、VLEN=2048、W/A/KV=4/4/4；HBM 建模见上（16 加速器系统对齐 TPU 系统容量带宽量级）。容量墙示例：LLAMA-3-70B 128k 上下文 FP16 KV cache 单 batch ≈39 GB。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 自研 Rust transaction-level（cycle-approximate）emulator，事件驱动执行生成的 PLENA 机器码，建模计算执行、指令调度与内存事务（cycle 粒度）；集成开源 Ramulator [43]（https://github.com/CMU-SAFARI/ramulator）与 DRAMSys [63]（https://github.com/tukl-msd/DRAMSys）做 off-chip 内存时序/带宽/bank 级建模。多保真框架另有解析型（analytic）模拟器与 RTL 仿真共三层。整体 planned 开源（https://plena-cam.github.io/，"Code Coming Soon!"，arXiv:2509.09505），暂无仓库链接。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 PLENA 架构全集（含非对称混合精度算术、flattened systolic 映射、片上 FlashAttention）在 LLM 推理下的 cycle 级执行与内存交互；未报告修改 Ramulator/DRAMSys 本体（作为库集成）。验证（Table II，LLAMA-3-70B 单 Transformer block）：transactional emulator 与 RTL 综合相比延迟误差 4.17%、执行时间 4.3 min（RTL 14 h），约 200× 加速；analytic 模拟器延迟误差 11.32%、面积 4.79%、功耗 23.81%（8 ms）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：PLENA emulator 论文计划开源（"We plan to open-source this emulator"），主页显示 Code Coming Soon，无法确认链接；Ramulator/DRAMSys 开源（链接见上）。
  - 模拟原理与全过程：输入 = (a) 编译器产出的 32-bit PLENA 指令流与模型张量布局，(b) 架构配置（BLEN/MLEN/VLEN、MX 精度、SRAM 容量、HBM 配置），(c) workload token 序列（prefill/output 长度，如 OSWorld-L 90k/8k、GSM8K 1.4k/0.2k、BFCL-W 114k/5k）→ emulator 事件驱动逐 cycle 执行：decode → 矩阵单元 GEMM（systolic 数据流 + M_SUM 加法树归约）、向量单元 elementwise/reduction/online softmax、标量单元、HBM 事务（H_LOAD_M/H_LOAD_V 预取与写回，数据 MX 布局、块与 scale 分离存储）→ 内存事务转发 Ramulator/DRAMSys 做 DRAM 时序建模 → 输出 cycle 级统计：TTFT（s）、每 token 周期 → TPS（tokens/s）、compute/memory active 时间、SA 利用率、带宽利用率、面积/功耗（综合模型）→ 支撑与 A100/H100/TPU 的 TPS、Tok/J 归一化对比（乘法器数、HBM 容量带宽对齐后）。batch size 取每硬件–负载组合下 HBM 容量可容最大（Table XII）。
  - 效果：LLAMA-3.3-70B OSWorld-L (90k/8k)：PLENA TPS 2.21× A100、Tok/J 4.04×（batch 从 4 提到 16，容量允许）；LLAMA-3.1-8B：TPS 1.45×、Tok/J 2.65×；GPT-OSS 20B MoE：TPS 1.93×、Tok/J 3.52×；Qwen3-32B：TPS 1.23×、Tok/J 2.25×；equal-batch 场景（均 BS 同）LLAMA-3.3-70B 仍 1.34× TPS、2.45× Tok/J。
