## DESSCam: An Event-Driven Architecture with In-Sensor Epitopological Sparse Sampling to Break the Latency-Power Tradeoff in Eye Tracking

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 3D 堆叠事件驱动传感器的定制电路与 RTL IP：(1) SSPL（Sparse Sampling Logic，底层像素逻辑）——每像素新增 1-bit 6T SCtrl SRAM（稀疏控制位，SCtrl=0 时门控切断比较器电源以省电）与 2-bit 8T SDP SRAM（事件就地锁存 + EventFlag 输出），SCtrl 将 Vdiff 与两个比较器解耦实现选择性稀疏采样，事件就地采样 + 全局 Spulse（200 ns）复位替代标准 DVS 的 per-pixel 握手，事件输出延迟从典型 120 ns 降到数 ns；(2) PAC 电路阵列——每 16×16 SSPL 配一个 PAC，列级加法器 + 加法树统计 EventFlag 数，超过阈值即置 ReqX/ReqY 与外围握手，仅激活 patch 读出（in-sensor token pruning）；(3) 外围电路——ping-pong 行采样 buffer（读/传两路流水）、输出 FIFO、SRAM 读出电路、AER 打包器（addrX 5 bit + addrY 5 bit + 512 bit 事件（16×16×2 bit）+ 32 bit timestamp）经 MIPI CSI-2（假设 2.5 Gbps）输出给 host NPU。
  - 实验比较：系统配置消融 3D-EPV（ESS+PAC+Robust ViT，全系统）、3D-PV（去 ESS，PAC+ViT）、2D-V（标准 DVS + ViT）、BlissCam [47]（帧式 in-sensor 随机稀疏采样 + ROI 预测 NPU，平均每帧输出 34,257.8 像素即 13.38% 阵列）、TinyTracker [23]（Sony IMX500 近传感器计算）。指标：功耗（像素静态/动态/逻辑/MIPI/NPU 分解）、端到端跟踪延迟（6 段分解）、芯片面积（像素/PAC/SRAM 外围分项）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 论文不使用系统级模拟器，采用标准 EDA 流 + 电路级仿真：模拟前端 PSC 与 SSPL 用 Cadence Virtuoso（SPICE，40 nm CMOS，对数放大器与源跟随器 2.5 V、其余像素电路 1.1 V）；PAC 阵列、外围电路与输出接口写 RTL，Synopsys Design Compiler 综合（22 nm、0.8 V）、Synopsys PrimeTimePX（含完全标注翻转活动）做功耗、ARM Memory Compiler 编译 SRAM 外围；数字电路结果用 DeepScaleTool [101,115] 折算到 40 nm 与模拟/SRAM 对齐；SSPL 版图由 Cadence Virtuoso 在 40 nm 完成。论文未修改既有开源模拟器，RTL/网表无公开链接。
- 模拟器模拟什么的性能，修改了什么。
  - Virtuoso SPICE 仿真像素模拟前端触发延迟、eventification/采样延迟与像素功耗，按标准 DVS 评估方法 [48,62,111] 拆静态（低事件率闲置条件，由像素与外围数字电路决定）与动态（活跃成像，由事件触发能量 E_ts 与事件率决定）：P_in_sensor = P_pixel_static + (1/M)Σ_s N_ev(s)·E_ts / T_acc(s) + P_logic；RTL 综合/时序报告给出加法树传播、握手与 AER 打包延迟及数字逻辑面积/功耗（动态功耗由遍历 EVBEYE 得到的平均事件量 N_ev 换算开关活动）；MIPI 与 NPU 部分为解析估计（MIPI 100 pJ/byte [73]、2.5 Gbps [92,112]；NPU 按 MAC/能效折算 STM32N6x7）。修改：无（自建 RTL 与电路网表，不改既有模拟器）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：DESSCam 的 RTL/网表/评估脚本论文未说明开源，联网搜索未找到公开仓库。
  - 评估原理与全过程：输入 = 分辨率假设 346×260（对齐 DAVIS346 [2]）、ESS 掩码（2% 使能）、EVBEYE 遍历得到的每 event frame 平均事件数 N_ev、事件触发能量 E_ts、累加时间 T_acc、22 nm 综合网表与 40 nm 工艺库参数 → ① Virtuoso 对 PSC/SSPL 做 SPICE 仿真得像素静态功耗、E_ts、模拟前端触发延迟与 eventification/采样延迟；② Design Compiler 综合 PAC/外围 RTL，PrimeTimePX 以数据集平均开关活动标注功耗，DeepScaleTool 把 22 nm 数字结果折算到 40 nm；③ 系统动态功耗 = 平均事件量 × E_ts 的帧能量 × 等效帧率（PAC 激活频率实测 162.76–64,170.78 Hz，12 patch 触发一次推断 → 等效帧率 13.56–5,347.56 Hz，取快速眼跳峰值样本报告）；④ 延迟 = 顶层模拟前端检测 + Virtuoso 仿真的 eventification/采样 + 时序报告的加法树传播 + 握手/AER 打包 + 解析的 MIPI 传输（AER 包大小 × 激活 patch 数 / 2.5 Gbps）+ NPU 推断（patch 数决定 MAC）六段求和 → 输出：功耗（3D-EPV 比 BlissCam 低 2.7×、比 2D-V 低 5.1×；SSPL 像素比标准 DVS 像素低至 5.26×（比较器 12.6×、采样电路 9.6× 削减），平均 per-pixel 功耗比 3D-PV 低 4.93×；新增 SRAM 仅占像素静态功耗 2.1%）；延迟（比 BlissCam 低 15.2×、比 2D DVS 低 2.6×，亚 1 ms，0.19–73.75 ms 随眼动速度自适应）。
  - 面积结果：SSPL 底层像素 36.97 μm² vs 标准 DVS 像素 [117] 36.76 μm²，仅 0.6% 开销（采样逻辑 6%→15% 的增大被共享 PAC 握手（握手逻辑 21%→18%）与小 buffer（总线驱动 buffer 15%→10%）抵消）；SRAM 外围 0.067 mm²；顶层 PSC 5×5 μm²、底层像素 6.1 μm，346×260 阵列整芯片面积 3.414 mm²。
