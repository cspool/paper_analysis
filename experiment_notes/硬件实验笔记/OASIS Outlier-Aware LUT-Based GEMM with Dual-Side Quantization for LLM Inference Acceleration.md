## OASIS Outlier-Aware LUT-Based GEMM with Dual-Side Quantization for LLM Inference Acceleration

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 OASIS ASIC 加速器，直接支持 NU-WAQ 的 WAQ LUT-GEMM 双分支计算：主分支（look-ahead LUT-GEMM）+ outlier 分支（Orizuru 检测 + 误差补偿）。片上配置（TSMC 28nm @ 500MHz，总面积 15.31 mm²，总功耗 9.66W，Table II）：16 条 PE Line（每条含 4096 个 Concat Unit、2KB Weight Index Buffer、32 个 16-input Index Counter、1 个 Dequant Unit、1 个 32-input FP16 MAC Tree、8 个 FP16 MAC）、2KB Cartesian Product LUT、16KB Activation Index Buffer、64KB Output Buffer、273 个 16-input Orizuru 单元、4 个 Clustering Unit、1 个 Error Calculation Unit、1 个 Functional Unit、1 个 Memory Controller。实验比较：单 batch decoding、低 batch（1/2/4）decoding、不同 prefill/decode 长度组合下的归一化吞吐与能耗，对比 FP16 A100 GPU、INT-WAQ QuaRot W4A4 kernel（A100 上运行；Atom kernel 仅 LLaMA-2-7B 可用故不用）、WOQ LUT ASIC FIGLUT（W4A16）。结果：OASIS-A4 平均相对 A100/QuaRot/FIGLUT 提速 5.41×/3.12×/3.00×（A3 为 5.67×/3.27×/3.15×），能效提升 198.1×/108.8×/1.44×（A3 为 206.53×/113.56×/1.51×）；低 batch 下相对 baseline 提速 3.41×/3.73×；prefill/decode 组合下相对 FIGLUT 提速 2.80×/2.93×；相对 conventional 动态检测设计（OASIS-C）吞吐高 16%/18%，验证 look-ahead 移出关键路径。
  - 模拟器名：cycle-accurate 模拟器，由 DnnWeaver 修改而来（DnnWeaver [48] 为 2016 MICRO 的 DNN-to-FPGA 高层综合/仿真框架，论文未给链接，GitHub 上有同名开源项目 esharma/dnnweaver：https://github.com/esharma/dnnweaver，是否即论文所用版本无法确认）；面积/功耗来自核心逻辑单元（Concat Unit、MAC Tree、Index Counter、Orizuru）用 TSMC 28nm 标准单元库的综合结果（论文未说明综合工具名）；片上 SRAM 用 Cacti（https://github.com/HewlettPackard/cacti）建模，片外 HBM 用 DRAMSim3（https://github.com/umd-memsys/DRAMsim3）建模。
  - 模拟器模拟什么的性能，修改了什么：DnnWeaver 把高层 DNN 模型综合到 FPGA 并做性能建模；论文将其修改为 cycle-accurate 模拟器，建模 OASIS 加速器在 LLM 推理（prefill/decode、单/低 batch）下的吞吐与能耗。修改内容：加入 OASIS 的 PE Line、Concat Unit、Index Counter、MAC Tree、Clustering Unit、Orizuru、Error Calc Unit 的微架构与数据流模型，以及 Memory Controller 对主/outlier 双分支的流水调度（Fig. 14 给出 1-4096-4096 GEMM W4A4、1% outlier 下各步骤 cycle 数，如聚类、索引拼接、计数、MAC Tree 归约、outlier 检测/反量化/误差补偿的并行调度）。
  - 开源情况：OASIS 无公开代码/模拟器（见算法pipeline条目）。模拟器使用例子（输入到性能输出全过程）：以 1-4096-4096 W4A4 GEMM、1% outlier 为例——输入 FP16 激活与量化索引：主分支（①）4 个 Clustering Unit 读 Output Buffer 中激活，用 binary search tree 每元素 log2(16)=4 级比较映射到最近质心索引；(②) 激活索引存 16KB Act. Idx Buffer 并广播到 16 条 PE Line；(③) 每条 PE Line 的 4096 个 Concat Unit 并行把 4-bit 激活索引与 Weight Index Buffer 的 4-bit 权重索引拼接成 8-bit 拼接索引；(④) 32 个 16-input Index Counter 把拼接索引解码为 one-hot 并行做行求和得到各拼接索引计数；(⑤) 32-input FP16 MAC Tree 以计数为权重对 2KB Cartesian Product LUT 条目做加权和，产出 look-ahead 结果。outlier 分支并行：(①) 273 个 Orizuru 以 1.5N+2k·log2(N) 次比较选出每 token top/bottom k outlier 值及其通道索引（min 树复用 max 树最底层比较结果省 50% 初始化比较）；(②) 按 outlier 通道索引取 Weight Index Buffer 对应 K 通道的权重索引；(③) Dequant Unit 按权重码本反量化为 FP16；(④) Error Calc Unit 并行算残差 (x_outlier − C_A[idx])；(⑤) 8 个 FP16 MAC 把残差×反量化权重累加为误差补偿项；(⑥) 合并主/outlier 分支结果写回 64KB Output Buffer。Memory Controller 双分支流水执行，各步骤 cycle 延迟见 Fig. 14；模拟器输出归一化吞吐与能耗（含 Cacti SRAM/DRAMSim3 HBM 开销），相对 A100/QuaRot/FIGLUT 对比（Fig. 11-13、15、18；Fig. 18 显示 Weight Index Buffer 占内存流量 76.0%、LUT 读写占 19.2%，能耗主要来自归约 33.1% 与分支合并 22.1%）。
