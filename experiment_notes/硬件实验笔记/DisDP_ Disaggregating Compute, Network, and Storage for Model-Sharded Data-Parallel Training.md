## DisDP: Disaggregating Compute, Network, and Storage for Model-Sharded Data-Parallel Training

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 DisDP 的硬软件协同三件套：(1) 每 GPU 配一块 FPGA SmartNIC（Xilinx Alveo U50 原型）实现 collective processing module——on-path 硬件流水线（区别于 SoC lookaside），含独立 push/pull processing unit、请求队列、DMA engine（经 GPU 虚拟地址直访 GPU 显存）、format conversion unit（SwitchML 式浮点→整数转换固化在硬件）。资源（U50）：LUT 135K(15.5%)、FF 225K(12.9%)、BRAM 354(26.3%)、URAM 128(20.0%)。(2) SmartSwitch（Edgecore Wedge100BF-32X，Tofino ASIC）：梯度 many-to-one 聚合 + 参数 one-to-many 广播（沿用 SwitchML 语义）+ 心跳聚合（heartbeat table 记录各 worker 最新 Ack/Credit 并周期性 min 聚合为单包）。资源：11 级流水(91.7%)、MAT 99(51.6%)、TCAM 111B(28.9%)、VLIW 1.64Kb(12.0%)、Register 37(77.1%)、SRAM 48MiB(39.5%)。(3) 单台 PS：step-centric optimizer pipelining（软件），SSD↔CPU Adam↔SmartNIC 深度流水（前向 2 步、反向 6 步）。
  - 实验比较：vs ZeRO-Infinity（CPU/GPU 聚合型 MSDP）、ZeRO-3、ATP（SmartSwitch 增强 MRDP）、ZeRO-Infinity+SHARP、ZeRO-Inf+MPS / ZeRO-Inf+Preemp（仿真假设的 GPU 调度优化）、消融 DisDP-GpuColl / DisDP-Colocated / DisDP-LC；另与 SoC SmartNIC 方案对比（BlueField-2 实测仅 20% 链路利用率，BlueField-3 按规格分析亦不足）。指标：吞吐 tokens/s、MFU、algorithm bandwidth、最大可训模型、成本效率、FPGA/交换机资源占用。
- 硬件平台是什么，配置是什么。
  - 8 台 worker 机器：双 Intel Xeon Silver 4214、256GB DDR4、1× NVIDIA A100 40GB，每机 1× Xilinx Alveo U50 FPGA SmartNIC；100Gbps 网络接 Edgecore Wedge100BF-32X SmartSwitch；单台 PS：双 Intel Xeon Gold 5320（PCIe Gen4）、12× SSD（合计 26GB/s 双向聚合 I/O）、SmartNIC。对照组：ZeRO-Infinity 用 CX-5 NIC + Mellanox SN2700、每机 2 SSD（共 16 块）；SHARP 组 4× CX-6 100Gbps + QM8790 InfiniBand 交换机；SoC SmartNIC 对照为 BlueField-2 真机实测。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 硬件本身非模拟器：SmartNIC 为 Xilinx Alveo U50 FPGA 真实原型（Vivado 综合资源表），SmartSwitch 为 Tofino ASIC（Edgecore Wedge100BF-32X）真实可编程交换机，性能真机测量。集群扩展与成本评估部分用开源模拟器 ASTRA-sim 2.0（https://github.com/astra-sim/astra-sim，配 Chakra execution traces）。
- 模拟器模拟什么的性能，修改了什么。
  - ASTRA-sim 模拟工业规模 3D 并行（TP8 over 600GB/s scale-up + PP16 1F1B + DP 1–256 over 100Gbps scale-out，沿用 Llama-3/MegaScale 实践）下 175B 模型训练全局 TFLOPS 随 DP 度的扩展（micro-batch 16）；对照 ZeRO-Infinity 的 ring 与 PAT 两种集合算法。论文未说明对 ASTRA-sim 的具体修改（DisDP 侧按 SmartNIC-managed 集合带宽建模，细节论文未明确说明）。SmartNIC/SmartSwitch 性能为真机测量，无模拟器修改。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - DisDP 的 RTL/固件未开源（论文与 arXiv 2409.00918 无链接，联网搜索未发现官方仓库，无法确认）；ASTRA-sim 开源（链接如上）。FPGA SmartNIC 输入→输出全过程：host 调 push → MMIO 写入请求队列 → push 处理单元 DMA 读 GPU 显存（GPU VA）→ 流水线中 format conversion 把 bf16 梯度转整数 → 线速发往 SmartSwitch → 交换机转发路径上把 N 个 worker 的部分梯度聚合为一份（many-to-one）→ 送 PS；反向 pull 时 PS push 参数、交换机广播（one-to-many）→ 各 worker SmartNIC DMA 写 GPU 显存。可靠协议：worker/PS 周期发心跳（Ack=下一期望序号、Credit=可接收最大序号），交换机把 PS 心跳广播给所有 worker、并把各 worker 心跳在 heartbeat table 中 min 聚合为一份给 PS——PS 每心跳周期只收发 1 个确认包、与 worker 数无关（one-to-one 方案 32 worker 降至 30Gbps、64 worker 仅 18Gbps，本方案不随规模衰减）；流控靠 TX Credit 停发/恢复，可靠性靠 Ack 超时（用户定义，如 1s）未增长则从 Ack 序号重传，交换机把重传的聚合梯度包转发给 PS。选择 FPGA 的原因：Tofino ≤20 级流水无法承担 ≥50 级的可靠连接端点；BlueField-2 类 off-path SoC SmartNIC 需 400Gbps/方向 Arm-switch 带宽（实际 250Gbps）与 800Gbps 内存带宽（实际理论 204.8Gbps，实测仅 20% 链路利用率），BlueField-3 亦不足（需 1600Gbps vs 716.8Gbps），而 on-path FPGA 流水线以片上 SRAM 暂存流水级间数据、免 off-chip DRAM 中转，可线速服务双向 push/pull。作用：证明完全解耦后单 PS + 单 SmartSwitch + 每 GPU 一块 FPGA SmartNIC 即可让 8×A100 训 175B 达 3.98× ZeRO-Infinity 吞吐（134 tokens/s）、276B 达 59% MFU、最大可训 1T（ZeRO-Infinity 8 机仅 175B、ATP 仅 1.3B）、DP=256 时 2.0×（PAT）/15.1×（ring）、吞吐/美元 1.96×（成本仅 DGX 的 60%）。
