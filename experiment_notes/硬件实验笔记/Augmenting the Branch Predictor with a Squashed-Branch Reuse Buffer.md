## Augmenting the Branch Predictor with a Squashed-Branch Reuse Buffer

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 Squashed-Branch Reuse Buffer（SBRB）+ 不变签名（invariant signatures）机制，改动全部集中在 CPU 前端（fetch unit），无 RTL、无面积/功耗评估（以存储开销 KB 计成本，总 11KB）。(1) 层级循环迭代标识符：动态分支实例由 {header block, iteration count} 栈唯一标识，用 Signature Stack（SS）紧凑实现——hpc 寄存器（fold8(header PC)，8 bit）+ sig 寄存器（32-bit Galois LFSR，带数据输入 XOR）+ 8 项 {hpc,sig} 保存/恢复栈；进入循环 push 并 sig=LFSR_step(sig^fold32(PC))，继续循环 sig=LFSR_step(sig^0)（LFSR 旋转 1 bit 等价迭代计数 +1），退出循环按 pop amount 弹栈恢复；call/return 同样 push/pop（call 用 call site PC 增量更新 sig，保证递归/同循环多次调用的签名唯一且不变）。(2) Loop Information Table（LIT）：LIT-H 150 项×62 bit 存 header PC、LIT-E 300 项×66 bit 存 {exit 分支 PC:62, dir:1, popcnt:3}，按 PC 查找；O/S 调度进程时从二进制 LIS 段装入（SMT 均分分区）；自研 LLVM 编译器 pass（基于 LLVM release/16.x commit 464bda7）生成 loop descriptor（{header PC, exits{branch PC, dir, pop amount}}）并按 header PC profile 频率排序写入 LIS 段。(3) SBRB：256 项 4-way 组相联、每项 30 bit（valid:1, lru:2, tag:26, outcome:1），key = fold32(PC) XOR sig；分支执行（execute 阶段）按 key miss 则分配写 outcome、hit 则更新 outcome；分支预测（fetch 阶段）按 key 查找，命中且 BTB 置信计数高则用 outcome 覆盖默认预测器。(4) BTB 每项扩展 3-bit 饱和置信计数器（阈值 >3，即上半态才允许覆盖），分支退休时按 {squashed outcome 可用且 != 默认预测} 条件训练：squashed outcome == 实际结果则 +1 否则 -1。(5) 延迟 squash（deferred squash）：基于 MIPS R10K branch mask 构造——误预测时 fetch~dispatch 立即 squash，但 rename 之后已分配资源的 squashed-path 指令继续派发/发射/执行，直到第一条 resolved-path bundle 到达 rename 才最终 squash 并自无效化 IQ/执行通道中的更年轻指令，让更多 squashed-path 分支执行完并把 outcome 存入 SBRB（squash 阴影中完成分支占比从 25% 提升到 45%）。(6) 恢复路径：64 个分支 checkpoint 每项追加 SS 副本用于精确恢复；BQ 每项 +8 bit 冗余维护退休 SS（load violation/异常恢复到 ROB 头时使用）。开销明细：LIT-H 1162.5B + LIT-E 2475B + SS 45.375B + SS checkpoints 2949.375B + SBRB 960B + BTB 置信 3072B + BQ 额外位 592B。
  - 实验比较（同一模拟器、同 benchmark 集）：(a) 64KB TAGE-SC-L baseline；(b) 192KB TAGE-SC-L（预测器直接放大 3×）；(c) SYRANT 的 fetch 阶段 squashed-branch reuse（state-of-art，ABL 592 项/SBL 512 项，并复用本文 per-branch 置信计数器）；(d) SBRB；(e) SBRB-literal-stack（256 项字面栈 → SHA-256 → CRC 缩减到 32-bit 签名，验证 LFSR 签名是完整标识符的有效代理）。设计空间：SBRB 容量/组相联（4-way 与 fully-assoc 在 256 项收敛到无界 SBRB 峰值）、sig/hpc 位宽与栈深（32/8 bit、8 项为最终选择）、LIT 容量敏感性（150/300 vs 无界）、置信机制（3/4-bit 饱和 vs 复位计数器 vs 无条件复用 vs 全局 4-bit 计数器）、无 calls 签名消融、PC-only key 消融、baseline 参数敏感性（192KB 预测器 / 1.5× 窗口 / 更深流水 / immediate squash）。指标：MPKI 与 IPC speedup。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟 RISC-V 超标量 CPU 上 SPEC 2006/2017 integer 与 GAPBS benchmark 的逐周期性能。默认核参数：12 级 fetch-to-execute、fetch/dispatch/issue/retire 宽度 8/8/8/8、执行通道 2 ld/st + 4 simple ALU + 2 complex/fp ALU、ROB/PRF/LQ/SQ/IQ=512/576/256/256/128、64 分支 checkpoint、64KB TAGE-SC-L 预测器 + 8K 4-way BTB + 64 项 RAS、L1I 64KB/L1D 64KB（4-cycle load-to-use）/L2 1MB 10cyc/L3 8MB 30cyc、主存 100 cycle。修改：fetch 单元加 LIT-H/LIT-E/SS/SS 恢复逻辑、SBRB 访问（预测与执行两处）、BTB 置信计数器、BQ 增位、分支 checkpoint 增 SS、squash 模型由 immediate 改为 delayed。工具链与负载配合：LLVM -O3 编译 + 自研 pass 生成 LIS 段；SPEC 2006/2017 int 用 ref input 中加权平均 MPKI 最高的输入（exchange2 因 Fortran 无法编译而缺），每 benchmark 至多 10 个 1 亿指令 SimPoint；GAPBS 用 Road/Twitter/Web 三个真实图；profiling 用全部 train SimPoint（SPEC）与 Kronecker/random 合成图（2^19 顶点）+ road-PA 真实图（GAPBS，全跑非 SimPoint）。

  - 模拟器为 NC State 自研、未开源（论文未给链接，联网搜索无公开仓库）；SBRB 硬件实现无公开代码。开源可获取：LLVM（编译器与 pass 基座，链接见上）、GAPBS benchmark 套件（https://arxiv.org/abs/1508.03619 ，GitHub sbp34/GAPBS）、SimPoint 方法论 [41]；SPEC 2006/2017 为商用 benchmark（需授权）。
  - 模拟原理与全过程：输入 = LLVM -O3 编译的 RISC-V 二进制（LIS 段含 loop descriptor）+ 硬件配置（Table II/III）+ SimPoint/图输入。取指阶段：fetch 监测 LIT-H hit 的 header PC 与 LIT-E hit 的 exit 分支 → SS 执行 push/LFSR 增量更新/pop（call/return 同样驱动）维护当前 sig；分支预测：默认 64KB TAGE-SC-L 出预测，同时 key=fold32(PC)^sig 查 SBRB，命中且 BTB 置信计数 >3 则用 SBRB outcome 覆盖为最终预测；执行阶段：分支执行后按 key 写/更新 SBRB outcome；误预测 → deferred squash（fetch~dispatch 立即清、rename 后指令继续执行到 resolved-path bundle 到 rename 才最终清）→ 从分支 checkpoint 恢复 SS 并从正确目标重新取指。输出 = 逐周期统计 → MPKI 曲线与 IPC speedup：geomean SPEC +2.08%（最高 14.1% 473.astar_rivers）、GAPBS +7.25%（最高 21.2% bfs-twitter）、全部 +4.43%、无 benchmark 负收益；SYRANT 同口径 1.27/2.36/1.77%；192KB TAGE-SC-L 仅个别 benchmark 有效（445.gobmk 6.43%、602.gcc 5.18%）且预测延迟不可接受；SBRB 与 SBRB-literal-stack 几乎无差；无 calls 签名降到 4.34%、PC-only key 明显退化；敏感性：192KB 预测器 4.36%、1.5× 窗口 4.91%、更深流水 5.57%、immediate squash 仅 2.22%（squash 阴影平均 17.68 分支、检测时完成 24%、延迟后 45%）。
