## æSIP μArch-aware ASIP-ISA Co-Design via Program Synthesis, Equality Saturation, and External Don't Cares

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 æSIP（ISCA 2026，University of Michigan）的 don't care 驱动的微架构感知 ASIP 生成器：以 baseline 处理器 RTL（Ibex Small 配置，2-stage pipeline、无分支预测、RV32IM）、重写后的程序、内存配置为输入，经三个阶段产出裁剪后的 ASIP RTL：(1) 微架构约束提取——三类 External Don't Cares (EDC)：ISA 级约束（decoder 只允许重写程序出现的 opcode）、数据级约束（操作数宽度受限、立即数取值受限，如 srai 的 shamt∈{1,2}、mul 只处理 16-bit 操作数时去掉高位乘法逻辑）、时序级约束（如 dcache miss 5 cycle 内响应，简化访存状态机）；(2) 约束翻译——静态分析重写汇编提取 opcode/立即数使用 + 用户提供的内存配置，SVA generator 自动转成 SystemVerilog Assertions（assume 声明）注入 baseline netlist（ISA/立即数约束纯静态导出；操作数宽度约束需动态 profiling，本工作为保证通用性未采用）；(3) 半形式验证门级裁剪——用 abc 的 scorr（sequential resubstitution：k-induction 找 EDC 下功能等价的节点对并替换）与 dsec（sequential redundancy removal：注入 stuck-at-0/1 故障，验证 faulted 电路在 EDC 下与原电路顺序等价后删除冗余节点）两个引擎（k 取 2-5 实践足够）证明可安全移除的电路。产出 ASIP 不新增指令（保持 RV32IM）、不改 pipeline 深度/发射宽度/分支预测，与未修改的 RISC-V 工具链完全兼容；端到端正确性用 spike+pk 对 22 个 benchmark 验证。
  - 实验比较：baseline 是 PDAG [11]（SOTA RISP 方法学：软件 profiling 得 ISA 约束、LTL model checking 裁剪 baseline 硬件），所有结果归一化到 PDAG。①重写后最小指令集（Fig.8）：distinct instruction 平均再降 31.8%（最高 md5 46.4%），Mul/Div 全部消除、简单算术/分支平均降 33.3%/31.9%、访存降 8.1%；②多目标优化（Table III 面积、Table IV 能量）：1.2× 时延约束下面积几何平均降 5.9%（SKY130）/5.8%（PPDK）、功耗降 4.9%/4.4%；无约束下面积降 17.0%（SKY130）/12.4%（PPDK）、功耗降 12.3%/9.0%（单 benchmark 最高 basicmath -29.5%、wikisort -28.3%）；能量最优变体（按最高可达频率缩放执行时间）能量几何平均降 4.1%（SKY130）/6.3%（PPDK）；③area-latency Pareto 前沿（Fig.9）：扫 27 个 λ，含 ISA-level only 与 +µArch-aware 两档约束的消融，bitcnts/qsort-small/patricia/sha 面积与时延同时改善（最高 29% 面积降 + 0.79× 时延），dijkstra -14.4% 面积 + 1.02× 时延、rijndael -14.6% 面积 + 0.94× 时延（ADP 也优于 PDAG）；µArch-aware 约束在保留复杂指令的 workload（dijkstra、rijndael）上额外收益最大；④扩展性（Fig.13）：Rocket 5-stage in-order RV32IM 上无约束面积降 24.6%（vs PDAG 10.1%），1.2× 约束下 13.0%（1.07× 时延）；⑤ecosystem 共享（Fig.10）：num-chip=5 时 17.3% 面积降 + 11.9% 时延开销（vs 全 per-application num-chip=22 的 22.4% 面积降 + 15.1% 时延），70/30 train/test 划分下 test_train 接近 test_best 且优于 test_global；⑥运行时（Fig.11）：saturation 1.2-32.4s、extraction 0.3-78.4s（中位 21.9s）、scorr 22.5-213.8s（中位 25.0s），对比全局 monolithic saturation+extraction 1 小时超时、PDAG RV32I baseline 5 小时超时；多进程并行下 22 benchmark×27 variant 全 Pareto 探索 44 分钟内完成。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 被修改的硬件：Ibex RISC-V core（https://github.com/lowRISC/ibex，Small 配置 2-stage、无分支预测、RV32IM），以 git submodule 随 artifact 附带；Rocket core（https://github.com/chipsalliance/rocket-chip，5-stage in-order RV32IM）用于扩展性验证。
  - 综合/验证工具链：Yosys 0.33（https://github.com/YosysHQ/yosys，配 Synlig 与 sv2v v0.0.13 做 SystemVerilog 综合）+ OpenSTA v2.7.0（https://github.com/OpenSTA/OpenSTA，静态时序分析）做快速面积/频率探索；Cadence Innovus（商用，https://www.cadence.com，需许可）配 SkyWater SKY130 PDK（https://github.com/google/skywater-pdk）与 PPDK（EGFET printed electronics 标准单元库，论文 ref [17]，1.0V/25°C typical corner）做最终 place-and-route；abc（https://github.com/berkeley-abc/abc）的 scorr/dsec 引擎做 k-induction 半形式裁剪；Verilator（https://www.veripool.org/verilator/）做 cycle-accurate RTL 仿真；spike + pk（https://github.com/riscv-software-src/riscv-isa-sim，RISC-V ISA simulator）做 ISA 级功能验证；Gurobi（https://www.gurobi.com，商用 ILP solver）用于 ILP 全局提取。
- 模拟器模拟什么的性能，修改了什么。
  - Verilator RTL 仿真：模拟 Ibex/裁剪后 ASIP 的 cycle-accurate 时延（指令与数据 cache 均开启），输出每 variant 的 cycle 数，latency = cycles/(freq×10^6)（配合综合后时钟频率）；修改内容即论文主体——abc scorr/dsec 在 EDC（SVA assume）下 k-induction 证明并裁剪节点，删除的电路在目标程序的输入域内不可观测。
  - Yosys/OpenSTA：综合 ISA 子集对应的 ASIP netlist，输出面积（SKY130 µm²、PPDK cm²，logic only 含寄存器堆、排除 cache/SRAM）与 post-synthesis 频率（iso-frequency 25 MHz 对比）。
  - Cadence Innovus PnR：130nm iso-frequency 25 MHz 输出物理面积/功耗；PPDK（1.0V/25°C typical corner）验证 printed electronics 适用性（静态功耗占 99%、die 面积 67.53 cm² 量级）。
  - spike+pk：端到端功能验证——MiBench 对比重写与原始程序输出，EmBench 用内置 verify 函数与 exit code；同时用于 ILP 成本模型中的 latency 预估。
  - 功耗/能量：综合 netlist + 活动因子经 Innovus 输出功耗；能量 = 功耗×执行时间，variant 按最高可达频率缩放后动态能量不变、静态能量随执行时间缩短而降低。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：是。GitHub https://github.com/CrucibleComputingGroup/aesip（GPL-3.0，README 给出五阶段 pipeline：program synthesis → equality saturation（egglog）→ ILP extraction（Gurobi）→ don't care pruning → ecosystem NRE optimization，配套 ISCA 2026 论文）；artifact 存档 Zenodo https://zenodo.org/records/19560118（artifact.zip 74.4MB，匿名稳定版）；预构建 Docker 镜像 polasip/esip:rv32im（artifact 附录另给 rv32im-sta270 变体），内含 egglog、Yosys、ABC、OpenSTA、riscv-gnu-toolchain（rv32im_zicsr_zifencei）、spike、Verilator，或 Conda 环境 esip（Python 3.12）；Gurobi 12.0.x 与 Cadence Innovus 需许可。仓库结构：frontend/（RV32IM 汇编→e-graph 前端）、Saturation/（equality saturation 规则）、Extractor/（ILP 提取）、backend/（ASIP RTL 生成）、program_synthesis/、PdatScorrWrapper/（don't care 裁剪）、scripts_pipeline/run_pipeline.sh、artifact_evaluation.ipynb（复现 Fig.8-10 与 Table III/IV）。
  - 使用例子（模拟器输入到性能输出的全过程）：`docker pull polasip/esip:rv32im` → 启动 Jupyter（artifact_evaluation.ipynb，自包含四实验）或 `scripts_pipeline/run_pipeline.sh <program>` → ① 预处理：gcc -O3 编译 MiBench（EmBench 预编译）→ 展开伪指令（li/mv→canonical 序列）→ 附加软件 mul/div 例程 → basic block/CFG/SSA 提取；② e-graph 重写：egglog 按 basic block 局部饱和 + Gurobi ILP 按 27 个 λ 全局提取，spike 验证重写程序与原程序等价（详见编译框架条目）；③ 硬件裁剪：对每个 variant 静态提取 ISA 子集/立即数使用 + 用户内存配置 → DSL 约束文件 → SVA generator 生成 SystemVerilog assume → 注入 Ibex netlist → abc scorr/dsec 在 assume 下 k-induction（BMC 证明 k 步成立推 k+1 步，2≤k≤5）证明节点等价/冗余并裁剪 → 并行 Yosys/Synlig 综合得面积/频率 → Pareto 前沿；④ 后处理（Section 5）：clone+patch Ibex → Verilator cycle-accurate RTL 仿真（~3 小时，全部 variant 的 cycle 数）→ Innovus PnR（~6 小时）输出物理面积/功耗 → 聚合生成 Fig.8/9/10 与 Table III/IV。作用原理：EDC 把优化问题从"完全指定布尔函数"放松为"布尔关系"——SVA assume 声明某些输入模式（未用 opcode、受限 shamt、cache miss 时序）永不出现，被证明在这些输入域内等价或冗余的节点可安全裁剪；k-induction 用有限 k 步 BMC 窗口换来工业级规模的可扩展性（完整 LTL model checking 随状态元素指数膨胀不可行）。
