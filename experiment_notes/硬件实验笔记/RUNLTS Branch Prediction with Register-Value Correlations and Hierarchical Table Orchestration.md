## RUNLTS Branch Prediction with Register-Value Correlations and Hierarchical Table Orchestration

- 属于硬件架构的实现是什么？实验比较什么？
  - RUNLTS 是一个新的条件分支预测器（微架构级 IP/前端模块设计），基于 TAGE-SC 构建，属于处理器前端分支预测单元（Branch Prediction Unit）的硬件实现。核心创新是 RBias：一个基于 hashed-perceptron 的 SC 扩展组件，直接学习"逻辑寄存器值摘要（digest）↔ 分支结果"之间的相关性，不显式跟踪数据依赖链。两个变体：Log-RBias（按逻辑寄存器组织，AArch64 65 个寄存器，需要 digest table checkpoint 恢复）和 Seq-RBias（按动态指令距离的 ring buffer 组织，无恢复、可利用 wrong-path 值）。此外对 TAGE-SC 部分做了三组精修：① 新的历史长度集合（短历史用二阶等差、中历史用几何、长历史用比率等差，使每张表服务的分支数尽量均匀）；② 基于 thrashing 检测的分配节流（复用 ctr∈{0,-1}+u=1 的稀有状态组合作为 newly-allocated 标记，按 newly_decayed/newly_useful 比例决定每次 misprediction 分配 2/3/4 个 entry）；③ SC 内部精修（IMLI 组件 gain 2→3、WT 更新步长×3、UT 条目 8→256；新增基于调用栈历史的 GEHL 组件 sC 6.053 KiB）。
  - 实验比较什么：① 预测精度：RUNLTS-Log / RUNLTS-Seq / RUNLTS(No-RBias) vs baseline TAGE-SC-L（192 KiB 配置，Sheikh 等为 CBP2025 适配版），以及 CBP2025 前六名中的另外五个预测器 MPP-2025、TAGE-SC-2025、LVCP、TASQ-SC-L、Bullseye，全部遵守 192 KiB 存储预算。指标为 MPKI 及相对 TAGE-SC-L 的 MPKI reduction。RUNLTS-Log 在 673 条 trace 中 597 条优于 TAGE-SC-L，平均 MPKI 降低 0.137、中位数 0.048，整体约 5.0% MPKI 降低；② 机制贡献分解（Figure 11/12）：RBias -2.46%、IMLI tweaks -0.74%、call-stack GEHL -0.43%、历史长度+分配节流平均为正；③ 错误路径影响（gem5 vs CBP simulator，Figure 14/Table III）：Log-RBias/noRecov 无恢复时收益很小，Log-RBias 两个模拟器结果一致，Seq-RBias 在 gem5（模拟 wrong-path）下明显更有效；④ 能量与面积（McPAT，Figure 15/16）：Seq-RBias 在 4/8/16-wide 上降低整核 EPI 0.19%/0.74%/1.08%，Log-RBias 在 16-wide 降低 0.20%、在小核上增加；面积开销 Log-RBias +0.66%/0.58%/0.49%、Seq-RBias +0.35%/0.14%/0.04%（4/8/16-wide）；⑤ 前端宽度/深度敏感性（Figure 17，front-end width 4/8/16 × depth 5/10/15）。
  - 处理器参数（Table I，16-wide 模型）：前端 16-wide 10 cycles、issue 24、BTB perfect（gem5: 65536 entries）、Int/FP×16 + Load/Store×8 执行单元、ROB 1024、scheduler 1024（age-based）、物理寄存器 Int×1024/FP×1024、LSQ 1024、L1I/L1D 128 KiB 8-way 3 cycles、L2 4 MiB private 8-way 12 cycles、L3 32 MiB shared 16-way 50 cycles、主存 150 cycles。还评估了半尺寸 8-wide 与四分之一 4-wide 模型。
  - 存储预算分配（Table II，192 KiB）：Bimodal 20 KiB、short-history tagged 29.25 KiB、long-history tagged 106.25 KiB、global history 4316 bits、sB 2.631 KiB、sG 3.011 KiB、sP 0.758/0.383 KiB、sL 5.069 KiB、sS 4.547 KiB、sT 4.543 KiB、sI(IMLI-SIC) 2.464 KiB、sC(call-stack) 6.053 KiB、sR(Log/Seq-RBias) 6.576/7.112 KiB、总量 191.760/191.921 KiB（baseline TAGE-SC-L 189.199 KiB，含 loop predictor 9984 bits）。

- 模拟器模拟什么的性能，修改了什么。
  - CBP simulator 模拟什么：条件分支预测器在乱序处理器前端+后端流水线模型下的行为（trace-driven，不模拟 wrong-path 执行）。预测器接口读取分支 trace（PC、全局/局部历史、方向等），模拟 TAGE tagged tables 的 tag 匹配/最长历史 entry 选择/ctr 与 u 更新、SC 各 hashed-perceptron 组件的加权求和与训练、以及新的 RBias 组件（digest 读取、WT/UT 访问、按 bank 选择）。输出每 1K 指令的条件分支误预测数（BrMisPKI/MPKI）及周期统计。处理器模型参数见上（16-wide、ROB 1024、三级缓存、150 cycle 主存），8-wide/4-wide 为相应减半/四分之一。
  - 修改了什么（CBP simulator）：在官方 cbp2025 仓库（固定 commit，workflow 脚本中指定）基础上集成 RUNLTS 系列预测器：RUNLTS-Log（Log-RBias）、RUNLTS-Seq（Seq-RBias）、RUNLTS 无 RBias（No-RBias）三种配置；按 Table II 重新分配 192 KiB 存储预算（Bimodal、两段 tagged tables、各 SC 组件容量、digest table 65/256 entries）；实现新历史长度集合、thrashing 检测与分配节流计数器（32 bits）、IMLI 增强、call-stack GEHL 组件、RBias 的 digest 生成（整数：trailing/leading zeros/ones 计数 XOR + 低 6 位；FP：符号+指数高位；flag：位模式重复拼接）。
  - gem5 模拟什么：full-system execution-driven 模拟，除了预测精度（MPKI、IPC）还精确建模 wrong-path 执行对 RBias 可观察 digest 的影响（flush 时 Log-RBias 的 digest table 恢复；Seq-RBias 的 ring buffer 指针回滚、buffer 内容保留以利用 wrong-path 值）。SPEC CPU 2017 用 gcc 13.1.0 -O3 -march=armv8-a 编译，SimPoints 100M 指令区间（总 11.8B 指令），full-system 模式。修改了什么：集成 RUNLTS 作为 reference 实现（gem5 SCons 构建流），Log-RBias 需要 checkpoint（每 checkpoint ~1 Kbit，需持续监听所有 completion 通知以更新各 checkpoint 的 ROB index→digest 替换），Seq-RBias 使用 ring buffer（初步实验显示约 ROB 尺寸的 1/4 即可无精度损失）。
  - McPAT：以 gem5 的活动计数为输入，输出整核每提交指令能量 EPI（含 speculative/wrong-path 活动）与面积（Log-RBias digest table 多次关联查找导致能量开销大；Seq-RBias 简单 ring buffer 能量开销小）。

  - 使用例子（复现 Figure 10 的官方 workflow）：① 解压 artifact 后 `cd ISCA_2026_Artifact_RUNLTS`；② `./docker/launch.sh`（自动构建容器）或按 Dockerfile 在 bare Linux 装依赖（bash/build-essential/git/python3/python3-matplotlib/python3-numpy/python3-pandas/tar/unzip/wget/xz-utils/zlib1g-dev 等）；③ `./run.sh`：自动用 wget 从 Zenodo 下载 CBP2025 评估 traces、下载五个对比预测器、克隆固定 commit 的 cbp2025 simulator 仓库；④ 对 8 个预测器配置（RUNLTS-Log、RUNLTS-Seq、RUNLTS 无 RBias、五个对比预测器 + baseline）× 673 条 trace 逐条跑 trace-driven 模拟；⑤ 聚合日志到 result 目录的 CSV；⑥ 自动运行 `python3 plot_s_curve_mpki.py` 生成 `cbp2025/s-curve-mpki.pdf`（对应论文 Figure 10，baseline 只用于算 reduction 不画图）。gem5 复现参考 `gem5 runlts/README.md`。
  - 模拟器输入到性能输出全过程（CBP simulator 原理）：输入 = 分支 trace 文件（`.gz`，每分支含 PC、方向、全局/局部历史及后端的寄存器值/ROB 信息供 RBias digest 使用；CBP 官方模拟器用法如 `./cbp trace.gz` 或 `./cbp -E 1000000 trace.gz` 定期输出误预测统计）+ 预测器参数（192 KiB 预算下的表结构与容量、历史长度集合、gains、throttling 阈值）→ 对每条条件分支按流水线时序：先查 bimodal 与各 tagged table（按不同历史长度 hash 索引、tag 比较），选最长匹配 entry 得 TAGE 预测与置信度；同时 SC 各 hashed-perceptron 组件（sB Bias 偏向 TAGE、sG 全局、sP 路径、sL/sS/sT local、sI IMLI、sC call-stack）分别检索权重求和；RBias 读取 digest table 检查每寄存器/每 ring buffer 位置的 digest 可用性，按 bank 选出 usefulness(UT, gskew 3-hash) 最高的寄存器访问 WT（3 表 3-hash 求和 ×2.5 gain）；SC 总加权和符号给出最终预测 → 与实际方向比较后按 perceptron 规则训练（仅预测错误或正确但 |sum| 低于阈值时更新；RBias 对未被访问的 bank 随机选有 digest 的寄存器训练以探索相关性；UT 用假设 RBias 输出 0 vs 2.5×sum 时符号是否翻转来增/减）→ 输出每 trace 的 MPKI 与相对 TAGE-SC-L 的 MPKI reduction，聚合后画 S-curve。作用：在 trace 级快速、确定性地比较大量预测器配置的精度（673 traces × 8 配置约 4 小时/64 核）。
  - 模拟器输入到性能输出全过程（gem5 + McPAT）：输入 = SPEC CPU 2017 可执行文件（armv8-a）+ SimPoint 100M 区间 + 16/8/4-wide 核心配置 + RUNLTS 预测器 → full-system 执行驱动模拟，精确建模错误路径：flush 时 Log-RBias 恢复 digest table（checkpoint 比较广播的 ROB index）、Seq-RBias 回滚 ring buffer 指针而保留 wrong-path 写入的内容 → 输出 MPKI、IPC（Table III：16-wide 下 RUNLTS-Log ΔMPKI -0.324、ΔIPC +1.55%）→ McPAT 以活动计数为输入建模各部件动态/静态能量与面积 → 输出整核 EPI（含 speculative/wrong-path）与面积开销（Figure 15/16、面积数字见上文）。作用：验证 RBias 在完整 wrong-path 语义下的收益与能效，评估实际处理器集成可行性（Seq-RBias 因恢复机制简单而能量/面积开销小、且在 full wrong-path 模拟下与 Log-RBias 收益相当）。
