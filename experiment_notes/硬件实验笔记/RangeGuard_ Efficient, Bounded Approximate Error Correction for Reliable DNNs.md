## RangeGuard: Efficient, Bounded Approximate Error Correction for Reliable DNNs

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 RangeGuard 的 ECC 编码器/解码器 RTL（SystemVerilog）+ GPU 内存控制器侧的 RID 保护架构。编码器：flip-flop 实现的多条目 RangeMap（每 32B 访问把 16 个 16-bit 值的 exponent 与全部 16 个 8-bit RangeMap entry 并行比较，256 个 8-bit comparator，1 cycle 完成 RID 提取），第二 cycle 生成 redundancy bits；解码器：第一 cycle 用同构 RangeMap 重新生成 RID，第二 cycle 计算 syndrome 并检错，检错后用门电路硬化的改进 Berlekamp–Massey 算法纠错（每次纠错 +1 cycle）。两种 ECC 配置：8b SSC = RS(10,8)、8-bit 符号、单符号纠错（2 个 parity 符号，最多纠 32 个损坏数据 bit）；4b DSC = RS(12,8)、4-bit 符号、双符号纠错（4 个 parity 符号，最多纠 64 个损坏数据 bit；12-symbol 字长满足 4-bit 符号 RS 上限 15）。多格式支持：每个 32-bit 区域按 32/16/8-bit 值拆分（4/2/1-bit RID），同一 32-bit 区域内全部值的 RID 打包进一个 ECC 符号（使 32-bit 对齐 burst 故障表现为单个符号错误）；内存控制器用物理地址未用高位 bit[57:54] 作 Map Tag 选择子映射，也可选传统 SEC-DED 精确纠错。
  - 实验比较：① 硬件开销（Table V）——RG 8b SSC vs 4b DSC 编码器/解码器面积（NAND2 等价）与功耗，及相对 GPU die 面积占比；② 系统性能（图 9）——RangeGuard vs SEC-DED baseline 在 GPU 上的 IPC（11 个 Rodinia [52] + Parboil [53] workload）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - Accel-Sim（cycle-level GPU 模拟器，ISCA 2020 [51]，https://github.com/accel-sim/accel-sim-framework），配置为 NVIDIA V100 模型；RTL 综合用 Synopsys Design Compiler + UMC 28nm standard-cell 库，1GHz。
- 模拟器模拟什么的性能，修改了什么。
  - Accel-Sim 模拟 V100 GPU 上 11 个 Rodinia/Parboil workload 的 IPC（错误稀少、按天/月级发生，故只在无错场景评估性能开销）。修改：调整读延迟以反映解码开销——假设 RangeGuard 需 2 cycle 返回无错数据（检错阶段后立即返回），baseline 已有 1 cycle 检错，净增 1 cycle 读延迟；写延迟不加（baseline 已有 1 cycle 编码，额外 cycle 可被 memory-controller 队列等待或 DRAM 写命令到写数据到达的间隔隐藏）。结果：geomean IPC 仅降 0.008%，最访存密集 workload <0.05%，计算密集 workload 几乎无影响。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：RangeGuard 本身论文未明确说明是否开源（无官方仓库，无法确认）；Accel-Sim 开源（https://github.com/accel-sim/accel-sim-framework）；RTL 综合用 Synopsys Design Compiler + UMC 28nm 库（商业工具，论文未提供脚本）。硬件开销（Table V，BF16）：RG 8b SSC encoder 合计 3,300 μm²（6,500 NAND2，其中 RangeMaps 3,100 + ECC encoder 200）、decoder 合计 7,800 μm²（15,400 NAND2，其中 RangeMaps 6,700 + ECC decoder 1,100），encoder 0.54mW、decoder 0.61mW；RG 4b DSC encoder 合计 800 μm²（1,600 NAND2，其中 RangeMaps 650 + ECC 150）、decoder 合计 4,200 μm²（8,200 NAND2，其中 RangeMaps 1,600 + ECC 2,600），encoder 0.18mW、decoder 0.63mW。8b SSC encoder+decoder 合计 11,100 μm² = 21,900 NAND2（87,600 晶体管），相对 208B 晶体管 Blackwell 约 5e-7 die 面积。
  - 使用例子（Accel-Sim，来自官方文档/论文）：输入 = CUDA 应用（用 util/tracer_nvbit/ 的 NVBit tracer 在真实 GPU 上记录 SASS trace）+ GPU 配置（描述 V100 风格 SM/内存层级）→ Accel-Sim SASS frontend 消费 SASS trace 并喂给 GPGPU-Sim 4.0 周期级性能模型（建模 warp 调度、访存流水线、DRAM 时序）→ 输出每 workload 的指令/cycle 统计 → 计算 IPC。RangeGuard 场景：把内存控制器读返回延迟参数 +1 cycle，重跑 11 个 workload，对比 SEC-DED baseline 的 IPC 差。作用：在周期级精度评估"每读 +1 cycle"这种微小内存控制器改动对吞吐型 GPU 整体性能的净影响（结论：可忽略，0.008%）。
  - 模拟器输入到性能输出全过程（Accel-Sim 原理）：输入 = SASS trace（每条指令含 opcode/寄存器/内存地址）+ V100 GPU 配置 → GPGPU-Sim 4.0 按 SM 内部流水线逐周期推进：warp 取指/调度 → 访存指令进 LSU/MIO → L1/L2 miss 后向 DRAM 发请求 → 内存控制器排队（FR-FCFS 等）→ DRAM 时序模型返回数据（读延迟含 ECC 检错/纠错的 +1 cycle）→ 写回 L1/L2 → 记录 cycle。输出 = 每 workload 已提交指令数与总 cycle 数 → IPC = retired/cycle，对 11 个 workload 取 geomean，与 baseline 对比得 0.008% 下降。RTL 侧（面积/功耗）：SystemVerilog encoder/decoder → Design Compiler 用 UMC 28nm 库、1GHz 综合 → 输出面积（NAND2 等价）、时序、功耗（Table V）。
