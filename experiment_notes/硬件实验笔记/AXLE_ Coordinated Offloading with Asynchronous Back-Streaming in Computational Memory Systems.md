## AXLE: Coordinated Offloading with Asynchronous Back-Streaming in Computational Memory Systems

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 AXLE：在 CXL Type 3 CCM 设备（近内存处理 PNM 单元 + 内存扩展）之上新增"设备主动反流"的数据平面与控制平面（仿真器级硬件架构，无 RTL、无面积/功耗评估）。CCM 侧：DMA executor 作为 CXL Type 3 设备上的 bus master DMA 引擎，把 µthread 产出的部分结果打包（DMA slot 32B/64B）后经 CXL.io posted write 从设备内存写到主机物理地址（device-initiated 反向数据流，替代主机发起的 CXL.mem 同步结果 load）。主机侧：本地 DMA 区域划分为 metadata 与 payload 两个固定大小 ring buffer（默认 32B/slot、容量 50000 slot），主机处理单元只轮询本地 metadata 尾指针（轮询点从远端 mailbox 移到本地）；CXL.mem store 作轻量 flow control 回传 head 索引；CCM 本地维护保守 head/tail 索引使陈旧流控消息仍安全。支持 OoO 流式（metadata 携带 payload slot ID、payload ring gap-aware 非连续消费）；内存栅栏保证 {payload 写→payload tail 更新 / metadata 写→metadata tail 更新} 排序；DMA 区域 cache-bypass 固定防止缓存陈旧。硬件形态参照真实 CCM 原型：SK hynix 定制 add-in card（CXL 内存控制器 + PNM 引擎集成于 Xilinx Versal VP1502 FPGA，4 DIMM 槽 DRAM；PNM 引擎含 MAC/ACC/CMP 硬核 PFL IP + Cortex-A72 ARM 通用核）。
  - 实验比较：RP（设备中心 CXL.io 邮箱远程轮询）、BS（M2NDP 内存中心 CXL.mem 同步流）、AXLE_Interrupt（中断通知变体）与 AXLE；扫参轮询间隔（50ns/500ns/5µs）、Streaming Factor（SF1=32B 至 SF64 与 SF_25%/50%/100%）、OoO 开关、RR/FIFO 调度、DMA slot 容量（12.5%–100%）。指标：端到端 runtime、CCM idle time、host idle time、host core stall time。另定性讨论 CXL Type 2（DCOH 硬件一致性引擎，大 SRAM 目录 + bias-flip 延迟）vs Type 3（软硬件协同管理数据/控制面）的架构取舍，结论是 Type 3 更适合低成本高带宽 CCM。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - M2NDP 开源 cycle-level CCM 模拟器（POSTECH PSAL，https://github.com/PSAL-POSTECH/M2NDP-public，论文参考文献 [13]），组合 Ramulator（CXL 内存设备）+ BookSim2（CXL 互连协议）；论文在 M2NDP 上实现 AXLE。真实硬件 KNN 原型实验跑在 SK hynix 的 Xilinx Versal VP1502 FPGA CCM 板上（仅用于 §III 动机观测，不作 AXLE 主评估）。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 CCM 部分卸载系统的端到端逐周期执行：CCM µthread 计算、CXL 内存访问、结果数据搬运、主机任务执行及其重叠；CXL.mem/CXL.io 协议延迟按 CXL 3.0 规范与文献配置（70ns/350ns 往返）。修改：原生 M2NDP 只支持 BS 同步流，作者新增 RP 模型（邮箱入队/远程轮询/出队）、AXLE 的 DMA executor、双 ring buffer、本地轮询 + ready pool、CXL.mem 流控消息、OoO 流式与栅栏排序、中断通知变体 AXLE_Interrupt；主机/CCM 硬件配置做了适配（主机 2 µthreads/处理单元模拟超线程，CCM 16 µthreads）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - M2NDP 模拟器开源（链接同上，MIT 风格公开仓库，Ramulator/BookSim2 亦开源）；AXLE 修改代码与新增 workload kernel 是否开源论文未明确说明。真实 FPGA CCM 板为 SK hynix 硬件原型，不开源。
  - 模拟原理与全过程：输入 = RISC-V 指令形式的 workload kernel（KNN/SSSP/PageRank/SSB/OPT 2.7B attention/DLRM）+ 输入分块 + 硬件配置（频率、µthread 数、DDR5 通道、CXL 协议延迟）。主机对特定远端地址发 CXL.mem store，M2NDP 的自定义 packet filter 区分普通访存与 kernel launch → CCM 调度器把任务划分为固定大小输入向量分派给 16 µthreads/处理单元执行（Ramulator 逐周期模拟 DDR5 时序与带宽）→ AXLE 的 DMA executor 打包结果并经 BookSim2 模拟的 CXL.io 链路 DMA 反流到主机本地 ring buffer（主机侧物理地址由预 pin 的 DMA 区域 + scatter-gather 描述符影子化给出）→ 主机本地轮询 metadata 尾指针、调度下游任务读本地 payload、经 CXL.mem 回传 head 索引 → 逐周期累加 CCM 执行/数据搬运/主机执行时间与空闲/back-pressure 周期。输出 = 端到端 runtime 及 CCM idle、host idle、host core stall 归一化对比（vs RP 最高 -50.14%、vs BS 最高 -48.88%；CCM idle 平均 -14.53×、host idle 平均 -3.93×、host core stall 最高 -6×）。
