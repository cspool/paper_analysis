## MXFFP Microscaling Flexible Floating Point Format for Large-Scale AI Model Acceleration

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 MXFFP Tensor Core：扩展传统 NVIDIA Tensor Core 低位宽数据通路，用每 block 单 configuration bit 解释执行多配置（E1Mx/E2Mx）MXFFP 格式。关键组件：(1) bit mapper——轻量多路选择器阵列，按配置 bit 把 4-bit 操作数重排对齐到统一格式（E1M2 只送最高指数位、其余用高 mantissa 位填充；E2M1 直送 2 指数位+1 mantissa 位）；(2) 扩展 dot-product 单元——FP4（E2M1）算术核加宽为内部 E2M2（significand 路径 +1 mantissa bit、normalization 加宽，指数偏置与范围不变），每周期算 4 元素点积；(3) MXFFP converter——Max 单元→Subtractor→Counter→Config Selector→Normalization & Round 动态重生成 MXFFP block（大 block 时先同步全局 E_b^MAX，E1Mx sub-block 共享指数减 1）；(4) threadgroup 每 TG 配 configuration 寄存器（2B，block set 一次加载、跨 4 步保留）与 shared exponent 寄存器（2B，每步更新）。实验比较：GEMM 延迟（矩阵 256/512/1024）MXFP vs MXFFP 相对 BF16 加速比；端到端 LLM prefill 推理延迟（1024 token、batch 1/2/4/8）；面积/功耗（RTL 综合，threadgroup 面积 +22.26%、功耗 +21.4%、配置级 power gating 后有效功耗 ~12%）；能量（AccelWattch，4-bit 1024³ GEMM 0.35× BF16）。
  - 模拟器名：Accel-Sim（https://github.com/accel-sim/accel-sim，Khairy et al., ISCA 2020，基于 GPGPU-Sim 的 NVIDIA GPU 模拟框架）；配置派生自 NVIDIA RTX 5090 GPU（Blackwell 架构）；CUTLASS（https://github.com/NVIDIA/cutlass）生成 GEMM kernel 并提取指令 trace 作为模拟输入；能量建模用 AccelWattch（https://github.com/accel-sim/accelwattch，Kandiah et al., MICRO 2021）；RTL 综合用 Synopsys Design Compiler + FreePDK 45nm。
  - 模拟器模拟什么的性能，修改了什么：Accel-Sim 模拟 RTX 5090 派生 GPU 架构在 MXFP/MXFFP GEMM 与端到端 LLM prefill 下的延迟/吞吐；修改：(1) 在模拟器中建模额外元数据内存访问——MXFP 的 shared exponent 与 MXFFP 的 configuration bit 的取数流量；(2) 在 Tensor Core 数据通路中加入 MXFFP 硬件模型（bit mapper、扩展 dot-product、converter、TG 寄存器）。硬件成本评估：baseline MXFP Tensor Core 与 MXFFP 增强设计均用 RTL 实现并经 Design Compiler 综合得面积/功耗（因 NVIDIA Tensor Core 微架构不公开，用代表性 4-bit 低位宽数据通路建模，论文说明此方法高估了全 Tensor Core 开销）。
  - 开源情况：MXFFP 硬件（RTL、模拟器修改）未开源（论文无链接，联网搜索未发现公开实现，无法确认）。Accel-Sim、AccelWattch、CUTLASS、FreePDK 45nm 均开源；MXFP 规范 OCP v1.0 公开（https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf）。
  - 使用例子（模拟器输入→性能输出全过程，1024³ 4-bit GEMM）：输入 = CUTLASS 生成的 GEMM kernel 指令 trace（MXFP/MXFFP 4/6/8-bit 量化、矩阵 1024）+ Accel-Sim 的 RTX 5090 GPU 配置 + 修改后的 Tensor Core 数据通路模型。执行：Accel-Sim 逐周期驱动 GPU 前端把 kernel trace 分发到 SM/Tensor Core；MXFFP block 取入 matrix buffer（每 block set 9B 元数据：1B 配置位 + 8B 共享指数，按块集字节寻址）；Tensor Core 把 16×16 输出 tile 分成 8 个 4×8 子矩阵，每子矩阵由 threadgroup（TG，4 个 dot-product 单元）经 4 步迭代累加；TG 从 config 寄存器取本 step block 的配置 bit、从 shared exponent 寄存器取缩放值；dot-product 内 bit mapper 按配置 bit 重排操作数进入扩展 E2M2 算术核乘累加，结果按 block 共享指数缩放后累加进高精度 accumulator；converter（Max→Subtractor→Counter→Config Selector→Normalization&Round）把 32 元素输出重转回 MXFFP block（大 block 先同步全局 E_b^MAX）。输出：GEMM 延迟与相对 BF16 加速比（4-bit 1024³ 达 2.7×、8/6-bit 1.8×；MXFFP 与 MXFP 几乎相同，说明配置位无延迟开销）；prefill 端到端加速比（8/6-bit 1.55×、4-bit 2.08×，batch 1-8 时 4-bit 1.86-2.18×）；RTL 综合面积/功耗（GPU 192 Tensor Core 规模下 MXFFP 开销仅占 750mm² die 的 0.038%）；AccelWattch 能量（4-bit 1024³ 降至 BF16 的 0.35×，RF 与 core 执行为能量主导）。
