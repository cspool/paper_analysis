## Coset Ensemble Decoder for Quantum Error Correction with Algorithm-Hardware Co-Design

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现：面向 coset ensemble decoding 的 FPGA 专用架构（SystemVerilog HDL，Xilinx Virtex UltraScale+ VU19P，Vivado 2024.2，163 MHz）。两段式：① 全流水 7 级 clustering engine（S1–S7，每周期处理 1 个 VID：S1–S3 出队 VID 并取 RID/边权解析 CID；S4 grow/merge 判定，经 forwarding/bypass 网络前馈回前级解决 RAW 依赖；S5–S7 用 priority FIFO 管理 active CID 并更新边界顶点状态）；② K=24 个并行 Ensemble Forest Exploration（EFE）实例 + Voting 模块（遍历态无法时分复用，故复制 K 份，不占关键路径）。核心硬件优化：conflict-aware multi-bank hashed memory（线性同余哈希 b_v(x,y,z)=(x+3y+5z) mod 22，22 banks，中心顶点+轴对齐邻居+入射边并发访问 pairwise 落不同 bank，d≤15 单周期访问；同 bank 顶点按 (i,j,k) 字典序密排，bank 内地址=同哈希三元组中该点的秩）、hierarchical ID mapping（VID→RID→CID 两层间接，merge 仅更新 RID→CID 小表，写扇出从"触及 VID 数"塌缩为"触及 RID 数"，单周期 remap）。以时间复用（temporal reuse）替代随码距增长的 spatial 架构。
  - 实验比较：vs Micro-Blossom（MWPM）、Helios、QUEKUF（UF）比较 LUT/FF/BRAM/频率（Table I，含归一化到 d=15 的估算）、平均/尾延迟（p95/p99）、吞吐、系统 infidelity Ĉ(R)、动态功耗（Vivado power report）、资源随 d 扩展（d=3~25，d=3/9/15 完整综合 + 解析估算 O(2^{⌈log2 d⌉})）；消融：无优化 baseline vs 逐项开启 Hierarchical ID Mapping（1.03×）、Multi-bank Hashing（2.30×）、Graph Compression（1.18×），全开 3.24×（d=11，p=0.0015）。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟 clustering pipeline 逐 cycle 行为（stall/busy 周期分解）、EFE 森林遍历与 ROE、Voting 聚合，输出解码延迟/周期数与访存冲突统计；"修改"即本论文四项硬件优化（hierarchical ID mapping、multi-bank hashing、graph compression、forwarding bypass）在模拟器中可开关以做消融。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：整体开源（如上链接；公开仓库含 software/、hardware/、plotting/、stimcircuits/、tools/ 目录与 run_full.sh/run_minimal.sh/run_lightweight.sh/run_plot_only.sh 四档复现脚本，README 说明 Verilog RTL 稍后在 hardware_code/ 发布，当前硬件评估经软件模拟器）。Stim、PyMatching 开源（链接见算法pipeline层）。
  - 模拟原理与全过程：输入 = 码距 d、噪声模型参数（p、bias η）、syndrome parity s、候选数 K、随机种子、3D decoding graph G(V,E)（Stim 生成噪声电路→detector 构建）→ clustering 流水每周期一个 VID 流式处理：S1–S3 出队 VID 并发取 RID 与边权解析 CID，S4 依据元数据判定 grow/merge（bypass 把 S4 判定回喂前级消 RAW），S5–S7 经 priority FIFO 更新 active CID 与边界顶点状态；访存经哈希 b_v=(x+3y+5z) mod 22 散列到 22 个 bank 保证 7-顶点邻域并发访问无冲突；merge 只改写紧凑的 RID→CID 表实现逻辑重标号 → clustering 完成后 K 个 EFE 实例并行做优先级森林遍历 + ROE → Voting 聚合 K 个候选的逻辑结果 → 输出最终 correction Ê 与 cycle 计数（→延迟/吞吐/冲突统计）。
  - 作用与效果：定位并消除 clustering pipeline 瓶颈——stall 占比从 48–58% 降至 1–7%（残余来自聚类尾部 parity-update RAW hazard，论文论证 speculative parity 或乱序发射代价不值），整体延迟 2.2–3.6×（d=9 为 3.0–3.4×，d=11 为 3.2–3.6×）；d=9 时 p95 2.12→0.65 μs（−69%）、p99 3.09→0.90 μs（−71%），p99 较 Micro-Blossom 低 3.5–4×、略低于 Helios。资源：108k LUT / 43k FF / 252 BRAM @163 MHz（d=15），较 Micro-Blossom 少 ~8.0× LUT、频率 3.7×，较 QUEKUF 归一化值少 4.3× LUT / 14.7× FF，BRAM 约为 QUEKUF 一半却支持近两倍码距；K=24 分支合计 ~1.2 W 动态功耗（每 EFE 分支 ~50 mW）。系统 infidelity Ĉ(R) 在 d=11 较 Micro-Blossom 低 74.3%、较 Helios 低 51.7%。
