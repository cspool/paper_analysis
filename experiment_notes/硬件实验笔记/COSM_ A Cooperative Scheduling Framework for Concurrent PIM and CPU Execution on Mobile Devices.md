## COSM: A Cooperative Scheduling Framework for Concurrent PIM and CPU Execution on Mobile Devices

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现 = 内存控制器 + DRAM 命令接口的软硬件协同扩展（不改 OS 与用户程序）：(1) 低干扰 PIM 控制接口——可抢占 PIM 执行命令 PIM_Exec（bank 级，PIM 单元按 tCCD 自主递增 Column State Counter (CSC)/PIM Counter (PC) 连续执行 nPTL=128 周期，免逐列触发命令，命令总线占用降 nPTL/tCCD 倍）+ PIM_Pause 暂停命令（列边界原子暂停：完成当前列、冻结 CSC/PC、释放总线，CPU 访问后重发原命令从冻结列恢复；仲裁器用 PC_inf=(clk-clk1)/tCCD 推断 PIM 进度，无需额外同步信号）。(2) 带宽解耦传输命令——PIM_RdBuf/PIM_WrBuf（控制器↔bank 旁 buffer，走外部总线）+ PIM_LdBuf/PIM_StBuf（buffer↔DRAM bank，走内部带宽），把一次 CPU-mediated 传输拆成两段独立调度。(3) PIM 单元内 PIM Execution Engine (PEE)（CSC/CR/PC 寄存器状态机）+ 每 bank 旁新增 SRAM buffer 段（1kB，容量匹配单条 nPTL 长度 PIM_LdBuf/StBuf 传输量）。(4) 内存控制器内新增 PEQ（PIM 执行队列）/PRWQ（PIM 读/写队列，各 per-bank 深度 2）、IWE（空闲窗口估计器）、PIM scheduler、Command Arbiter（严格优先级：CPU 访问/refresh > PIM_Pause > PIM 命令；四阶段流水：按类型排队→IWE 预测→FR-FCFS 与 PIM 调度器各选命令→仲裁）。实验比较 4 个 baseline：All-Bank Command（ISSCC'21 HBM2 FiM 全 bank 命令 + 95%CPU/5%PIM 时间片轮转 + 理想化零切换开销）、Chopim（ISCA'20 CPU-first，单 bank 命令长=tBL）、AsyncDIMM-Bank（HPCA'25 的 bank 级版，PRE 触发 CPU/PIM 队列切换 + rank 内 relay 控制器）、Chopim(128)（命令长提至 128）。指标：CPU/PIM 归一化性能（相对独立执行）、PIM 吞吐（tokens/sec）、能量/token、面积（Synopsys DC 综合）。
- 硬件平台是什么，配置是什么。
  - 主机：Qualcomm Snapdragon 888 级手机平台（真机 = 小米 Mi 11 Pro：1×2.84GHz Cortex-X1 + 3×2.42GHz Cortex-A78 + 4×1.8GHz Cortex-A55，12GB LPDDR5，256GB 存储，Android 15）；模拟主机 CPU 8 核 @2.1GHz、OoO 160-entry RoB、4 IPC、L3 4MB（8 路、64B cache line）。
  - DRAM：LPDDR5-6400（JEDEC JESD209-5C），2 Channels × 2 Ranks、8GB/Rank；组织 Bank/Bank Group/Row/Column = 4/4/16384/2048B（即 4 BG × 4 Banks = 16 banks/rank，2 ranks 共 32 banks）；时序(ns) tBL=2.5(16 拍)、tRCD=tRP=4.7、tCL=6.3、tRAS=10.7、tRRD=1.3、tRFC=87.5、tWR=8.8、tWTR=3.1、tRTP=1.3、tCS=0.6、tREFI=967.5。
  - PIM 单元：每 rank 16 个（bank 级），1GHz、6.4 GB/s、6.4 TFLOPS（按三星 LPDDR5-PIM 流片芯片 [36] 建模）、16-bit PIM-bank 线宽、1kB 传输缓冲。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - Ramulator2（https://github.com/CMU-SAFARI/ramulator2，基于 Ramulator 的模块化 DRAM 模拟器）——扩展内存控制器模型与 LPDDR5 模块；DRAM 功耗用 DRAMPower；SPEC CPU2017/PolyBench-ACC 的 CPU trace 用 zsim 生成，手机应用 trace 用 Frida 插桩小米 Mi 11 Pro 真机采集；面积用 Synopsys Design Compiler + TSMC 90nm 库 @2.4GHz 综合，再按公开工艺缩放数据分别折算逻辑/存储到 5nm。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 CPU 与 PIM 并发执行时内存控制器的逐周期调度：Ramulator2 的 O3CPU 前端以内存 trace（含访问与访问间隔延迟）回放 CPU 请求生成背景流量，PIM 命令经 PIM scheduler/Command Arbiter 按新时序约束注入 LPDDR5 模型，推演 PIM 执行/暂停/两阶段传输与 CPU 访问的干扰，输出 CPU/PIM 归一化性能与 PIM 吞吐。修改：LPDDR5 模块新增 PIM 命令与时序约束（表 1：ACT→PIM_Exec/PIM_LdBuf/StBuf 需 tRCD；PIM_Exec→PIM_Pause 需 tCCD；PIM_Pause(Ld)→PRE 需 tRTP；PIM_Pause(St)→PRE 需 tCCD+tWR；同通道 PIM_RdBuf/WrBuf 后需 tBL 等）、PEE 与 bank 级 SRAM buffer 行为模型；控制器新增 PEQ/PRWQ、IWE、PIM scheduler、Command Arbiter。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：artifact 公开于 Zenodo（https://doi.org/10.5281/zenodo.19660293），含修改版 Ramulator2 源码（核心改动文件：src/dram_controller/impl/plugin/pim/pim_arbiter_cpu_first_o3_pred.cpp（idleness-aware 调度 + PEQ/PRWQ + 命令仲裁）、src/dram/impl/LPDDR5-PIM.cpp（低干扰 PIM 控制接口））、Python trace 生成脚本（DeepSeek-R1-1.5B LLM trace）、真机采集的移动应用 trace、run_script.sh、Excel 绘图模板。依赖 GCC 12+（C++20）、CMake 3.30+、Python 3.12+，建议 x86_64 8 核 + 64GB 内存、5–10GB 磁盘。
  - 模拟原理与全过程：输入 = PIM 侧 LLM trace（BLOOM-1B1/DeepSeek-R1-1.5B/Qwen2-0.5B，16-bit 输入/8-bit 权重量化）+ CPU 侧 trace（TM/Browser/X/Note/YouTube/Music 六款移动应用、Floyd/Ludcmp/Covariance 三个 PolyBench、519.LBM/511.Povray/520.Omnetpp 三个 SPEC CPU2017）→ `./build.sh [并行度]` 编译 → `cd simulations && ./run_script.sh figure8|figure10 [并行度]` 批量跑 baseline 与 COSM 组合 → Ramulator2 逐 cycle 推演（trace 回放 CPU 请求 + PIM 命令注入 + IWE 窗口预测 + 仲裁）→ 输出 CSV（simulations/scripts_result_processor/summary_figure8|10.csv）→ 粘贴进 Excel 模板 plot_figure8|10_ae.xlsx 复现 Fig. 8/10（PIM 吞吐最高 2.8×、CPU 降速 <5%）。指标 = PIM 吞吐（tokens/sec）、CPU 性能降速。
