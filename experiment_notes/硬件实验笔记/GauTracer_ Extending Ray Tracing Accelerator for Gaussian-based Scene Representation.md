## GauTracer: Extending Ray Tracing Accelerator for Gaussian-based Scene Representation

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现 = 在 Vulkan-Sim 的 RTA（Ray Tracing Accelerator）微架构模型上扩展高斯原语的一等公民支持，具体包括四部分：(1) Gaussian 叶节点编码：叶节点直接存逆变换矩阵 T'（式 6，仅 12 个元素 + opacity + Gaussian ID + 2B descriptor = 64B/叶，与三角形叶大小一致），避免 [27] 的 icosahedron 网格代理（每高斯展开 20 三角形，BVH 体积大 26×、构建慢 1.5×）；(2) 可重构 Ray-Gauss Intersection Unit（RGIU）：单 bit 模式开关在 3DGS/2DGS 间复用计算单元（3 个 vec3 点积单元 + 1 个倒数单元 + 1 个标量乘法器组成浮点除法器 + 1 个 MAC，2DGS 用点积实现 MAC），支持 3D 椭球（单位球空间原点在射线上的投影 = 响应最大点）与 2D 平面椭圆（射线与 z=0 平面交点）两种交点求值，响应（alpha）经分段线性近似指数单元计算，alpha 直接前送 Hit Gauss Buffer，避免重复计算；(3) Max-heap 的 Any-Gauss-Hit Unit（AGHU）：按命中距离 t_hit 为 key 维护每射线 16 项的 Hit Gauss Buffer（每线程寄存器实现），支持 shift-up/shift-down 插入与堆弹出排序，closest-hit 采用 back-to-front 混合（式 7，C^p_{i+1} = α_i c_i + (1−α_i)C^p_i），按 round 级更新透射率实现提前终止；(4) treelet 化 BVH 遍历 + far-node pruning：树簇含 256 节点（64B/节点 = 16KB，ping-pong 双缓冲适配 L1），遍历时以 Hit Buffer 满后的最大命中距离为几何屏障（barrier flag），裁剪射线盒命中距离超过该阈值的节点子树，减少冗余节点访问；两层级遍历栈（treelet stack + node stack）存于每射线寄存器，溢出时按 short-stack 策略溢到 local memory。
  - 实验比较：baseline GPU-RTA（含 [48] 的 treelet prefetching，Gaussian 作为 procedural primitive 由软件 shader 处理）vs GauTracer 增量消融（RGIU、RGIU+AGHU、+PRUNE、+PRUNE+SORT），3DGRT 与 2DGRT 两种算法模式。指标：traceRay 加速比（3DGS 平均 5.8×，范围 4.1~9.6×；2DGS 平均 7.3×，硬件 shader 贡献 5.6×）、指令削减（RGIU 14.7×，+AGHU 再 38.9×）、每射线访问节点削减（PRUNE 1.2~1.9×，遍历延迟降 1.4~3.0×）、内存流量（1.7~2.7×）、能量效率（AccelWattch trace-driven 功率模型，3DGS 6.6×、2DGS 7.5×）、面积开销（RGIU 27 cycles/34710.2 µm² 为 baseline 一组 RBIU+RTIU+TRAN 的 21.8%；AGHU+PRUNE 2~12 cycles/825.6 µm² 增量仅 0.7%；Hit Gauss Buffer 与遍历栈用每线程寄存器无显式面积）、渲染质量（PSNR baseline 33.40 dB → GauTracer 33.32 dB，几乎无损）、warp 发散（活跃线程比 27.5%~40.1%）、Hit Gauss Buffer 大小 K 敏感性（K=16 平衡每射线性能与 SIMT 效率，K≥32 假命中近线性增长且 barrier 难触发）。RGIU 等单元延迟由 Agner Fog 指令表推导，28nm 商用标准单元库同时序约束综合。RTX2060→RTX3090 缩放讨论（30→82 SM、L1/L2 加倍）下 7.2~11.3× 加速。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 性能模拟器 = Vulkan-Sim（cycle-accurate GPU 模拟器，基于 GPGPU-Sim + Mesa 的 Vulkan 光线追踪模拟器，MICRO 2022）：https://github.com/ubc-aamodt-group/vulkan-sim（zenodo: https://zenodo.org/records/6941619）；treelet prefetching 参考实现（MICRO 2023）：https://github.com/ubc-aamodt-group/treelet-prefetching-for-rt。功率模型 = AccelWattch（MICRO 2021 trace-driven GPU 功率建模）：https://github.com/accel-sim/accelwattch。面积/延迟 = 28nm 商用标准单元库综合 + Agner Fog 指令表（https://www.agner.org/optimize/instruction_tables.pdf）。BVH 构建 = Intel Embree（https://github.com/RenderKit/embree）。实机验证 = NVIDIA RTX 3090 + OptiX 部署 3DGRT。
- 模拟器模拟什么的性能，修改了什么。
  - Vulkan-Sim 模拟含 RTA 的完整 GPU：SM 调度（GTO warp 调度器）、warp 级光线遍历（RT warp buffer 4 项）、固定功能运算单元（RBIU/RTIU/TRAN）、L1/L2 cache 层次、内存系统；配置匹配中端 RTX2060（Table II：30 SM、32 warps/SM、65536 regs/SM、128KB I-cache、64KB L1+SMEM、3MB L2、core/interconnect/L2 1365MHz、mem 3500MHz、1 RT unit/SM、RT warp buffer 4）。
  - 修改内容：(1) 遍历逻辑集成 treelet-based stack loop（counter table 按 treelet 追踪 ray 数量调度）；(2) BVH 节点打包与解码（叶 descriptor 的 node type 从 1 bit 扩到 2 bit：triangle/procedural/3D Gaussian/2D Gaussian；operation destination table 增加 TRAN→RGIU 顺序派发，无新增仲裁阶段）；(3) 复用 TRAN 单元做 ray 到单位球空间的矩阵向量变换（两次矩阵向量乘）；(4) Ray buffer 扩展 Hit Gauss Buffer（16 项：t_hit、alpha、GID）+ hit counter（每次 traceRay 前复位）；(5) 实现 RGIU、AGHU、far-node pruning 全套 ray-Gauss 交互功能。

  - 模拟器输入→输出全过程（以一次 traceRay 评估为例）：输入 = (a) 自定义 Vulkan 光线追踪程序（论文按 [27] 3DGRT 算法流程用 Vulkan API 实现 Gaussian ray tracing：Gauss Param Buffer、Closest Hit Buffer（Nray×K 2D 数组）、Hit Count Buffer 三个 SSBO 绑定到 shader，procedural 叶节点与 BVH 由 Intel Embree 以分支因子 6 构建）+ (b) NeRF-Synthetic 数据集的 8 场景高斯点云（性能评估用早训练迭代点云以减少仿真时间，质量评估用 30,000 次迭代点云、800×800 分辨率渲染、采样中央有效渲染区域射线子集）+ (c) Vulkan-Sim 配置（Table II RTX2060 参数 + 自定义运算单元延迟 Table III）。模拟推进：ray-gen shader 每像素发主射线 → while(Ray.trans > threshold && thit > 0) 循环内 traceRayEXT → 射线进 RTA warp buffer → 树簇遍历（treelet stack 处理当前 treelet，node stack 处理子节点，barrier flag 触发后按最大命中距离裁剪远节点）→ node decoder 判别节点类型 → TRAN 读 T' 做两次矩阵向量乘把 ray 变换到单位球空间 → RGIU 按模式求交点（3D：原点在 ray 上投影距离 t_hit^g；2D：ray 与 z=0 平面交点）与响应 alpha（r_hit²/2 → 分段线性 exp → ×opacity → 与 1/255 阈值比较）→ 命中则 AGHU 把 (t_hit, alpha, GID) 插入 max-heap（不满则 shift-up，满则与根比较决定丢弃/替换后 shift-down），与遍历异步重叠 → 遍历完成后 closest-hit 按堆弹出 far-to-near 序列做 back-to-front 混合（式 7），更新 C、T、thit，ray origin 前进 thit 进入下一 round → 直到透射率低于阈值或 miss。输出 = 每射线/每 traceRay 的延迟分解（BVH 遍历 vs shader）、shader 指令数（ALU/memory/other）、访问节点数、内存流量、warp 活跃线程比、每射线命中数；再经 AccelWattch trace-driven 功率模型得能耗与能量效率；28nm 综合得 RGIU/AGHU/PRUNE 面积。作用：在可配置的 cycle-accurate 环境下隔离量化 RGIU/AGHU/PRUNE 各自对指令数、访问节点数、延迟、流量、能耗的贡献，并验证面积/质量代价。
