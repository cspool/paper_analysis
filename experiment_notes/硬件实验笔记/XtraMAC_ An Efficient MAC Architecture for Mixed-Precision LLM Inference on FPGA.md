## XtraMAC: An Efficient MAC Architecture for Mixed-Precision LLM Inference on FPGA

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 XtraMAC（ISCA 2026，NUS + HUST）：一个数据类型自适应的 MAC 微架构，统一支持整数、浮点与混合精度（INT×FP）MAC 及运行时数据类型切换，全部基于单个 DSP48E2 slice。核心设计：① 统一处理模式公式化（Eq.1/Eq.4）——把 FP×FP、INT×FP、纯整数乘法都分解为共享的整数尾数乘积 + 轻量符号/指数处理，DSP 只做纯整数乘法；② 数据位映射与多 lane 打包（Eq.9-12）——把 P 个低精度操作数的尾数/幅值按非重叠位区间 (a_i<<s_i, b_j<<t_j) 打包进 DSP48E2 的 27-bit A 口与 18-bit B 口，一次宽乘法后按固定 shift-and-mask 提取各 lane 乘积（式 10/11），stride S≥W_lane+G 保证无跨 lane 干扰，并行度受 min(⌊27/S⌋,⌊18/S⌋) 约束；③ 四阶段固定流水线（Stage1 操作数解释/位映射、Stage2 DSP 乘法+逐 lane 后处理、Stage3 分离式 INT/FP 累加、Stage4 输出选择），全数据类型恒定 4 cycle 时延、II=1，datatype-select 信号经匹配延迟切片贯穿流水线，运行时只做 MUX 切换、不重配置；④ 分离式累加通路——整数加法走进位链（线性成本），浮点加法用 barrel shifter 对齐/归一化（超线性成本），避免统一 INT-FP adder 为整数路径白白承担 shifter 面积；⑤ 特殊值处理（FTZ/DAZ、canonical qNaN、∞、overflow 饱和）以状态标志随匹配寄存器切片转发，输出端纯组合逻辑选择结果，无 stall/刷新。RTL 用 Verilog 编写，含 49 个固定数据类型 MAC + 4 个运行时双模可重配置 MAC（mode 位切换，如 bf16_int4_shared），每个设计恰好用 1 个 DSP48E2（尾数打包在 A 口），三种流水线变体（4c/5c/6c，II 恒为 1）。
  - 实验比较：① 混合精度评估——遍历全部 A×B+C→P 数据类型配置测 LUT/FF/DSP 与并行度（FP4/FP8 最高 4 lane/DSP、BF16 2 lane），恒定 4 cycle/II=1；② 运行时切换评估——Table III 四种代表组合（Config I-IV：INT4×BF16+BF16 / INT8×INT8+INT32 / FP8×FP8+BF16 / FP4×BF16+BF16，各自叠加 BF16×BF16，对应 Qwen3-8B-AWQ、Llama-3.1-8B-W8A8、Qwen3-8B/LLama-3.1-8B-FP8、GPT-oss-20B），量化相对 naive 独立 MAC 实例的资源共享收益（Config I 加法逻辑降 ~50%，Config III 部分复用降 ~30%，Config IV 近完全复用）；③ 可扩展性——从 BF16/FP16 基线逐步使能 INT8/FP8(E4M3)/FP4(E2M1)，DSP 恒为 1、LUT 缓增、Fmax 483→462 MHz；④ 与 SOTA MAC IP 对比——baseline 为 AMD Xilinx Floating-Point Operator IP [1]（PG060，配开源 int-to-float 转换模块 [10]/[17] 支持混合精度输入），按并行度归一化资源：XtraMAC 平均降 LUT 30.0%、FF 47.9%、DSP 50.0%，计算密度提升 1.4–2.0×；Fmax 平均比 vendor IP 慢 22%（周边 LUT/FF 与路由拥塞），但全部 >400 MHz，且 2× 并行度带来每 DSP 有效吞吐 ~1.56×；⑤ 运行时切换对比——baseline 为 vendor IP 空间复制（INT8+BF16 双 datapath）与 TATAA [38]（BF16 分解为 4 个 INT8 微操作的时间共享），XtraMAC 相对 TATAA 降 LUT 59.7%/FF 72.5%/DSP 93.8%，相对 vendor IP 降 LUT 35.5%/FF 58.7%/DSP 75.0%（Table V：每 BF16 操作 142.0 LUT/128.3 FF/0.25 DSP）。

- 模拟器模拟什么的性能，修改了什么。
  - iverilog/xsim 仿真：验证 MAC RTL 功能正确性——自检 testbench（tb_mac）检查 4c/5c/6c 三种流水线变体输出 bit-exact 一致，覆盖全部 49+4 配置，输出 RESULT=PASS；数值语义 FTZ/DAZ、RN-even、qNaN 传播、饱和。
  - Vivado 综合：输出每配置 LUT/FF/DSP 数量（每设计 DSP=1）、WNS、Fmax（verification/synth_all.csv 覆盖 51 配置×3 变体=153 行；6c 变体同精度 FP16/BF16 路径可达 ~500 MHz），对应 Fig.6/7/8/10、Table III/IV/V。XtraMAC 结果为 bit-exact 匹配 NVIDIA A100/H100 Tensor Cores 与 AMD Floating-Point Operator。
  - 端到端 analytical 仿真（ref [7] 框架）：把 transformer 层建模为交替的计算/访存阶段（理想 streaming + weight-reuse 假设），所有 Table VI 模型（Qwen-3-8B-AWQ、Llama-3.1-8B-W8A8、Qwen-3-8B-FP8、Llama-3.1-8B-FP8、GPT-oss-20B）在 AMD Alveo V80（2.6M LUT、10,848 DSP、300 MHz、810 GB/s HBM）上模拟，baseline 实例化 vendor FP IP（Table IV 资源 profile），XtraMAC 配置替换为 XtraMAC 单元，其余（数据打包规则、checkpoint MAC 计数、tiling）固定，输出 decode-stage 执行时延（context 512、batch {1,8,32}，Fig.14）：batch=1 时 memory-bound（权重流 4.4–10.0 ms 主导、计算差异可忽略），batch=8/32 时 compute-bound，batch=32 时 XtraMAC 端到端降时延 1.5–1.8×。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：是。GitHub https://github.com/Xtra-Computing/XtraMAC（Apache-2.0，ISCA 2026），arXiv 2605.06052，配套网站 https://xtramac.com/。仓库结构：User_spec/（IP picker：generate_mac_bundle.py + library/{rtl,tb}）、User_spec_mixed/（可重配置 MAC 的 IP picker）、common/dsp_usage.v（DSP48E2 wrapper）、mac_cores/（参数化原语 fp32/fp16/bf16/fp8e4m3/fp8e5m2/int32/mixed_precision）、mac_configs/（1lane/2lane/4lane）、runtime_reconfig/（4 个双模 MAC：a_bf16_int4_shared、b_int8_bf16_dual、c_fp8_bf16_dual、d_bf16_fp4_dual + synth_results.csv）、verification/（run_one.sh、run_one_synth.sh、dsp_usage_sim.v、synth_all.csv、synth_500mhz.csv）。前置依赖：iverilog ≥11（sudo apt install iverilog）+ Vivado 2022.2；先 source <XILINX>/Vitis/2022.2/settings64.sh。
  - 使用例子（MAC RTL 输入到性能输出的全过程）：① 生成 IP bundle——`python3 User_spec/generate_mac_bundle.py --list` 浏览配置 ID，`python3 User_spec/generate_mac_bundle.py "FP8e4m3*FP8e4m3+FP16"` 或按 ID 生成指定 MAC，脚本把 rtl/、tb/、manifest.json 输出到 exports/<module>/；混合双模 MAC 用 `python3 User_spec_mixed/generate_mixed_mac_bundle.py 2`；② 功能仿真——`cd verification && bash ./run_one.sh 2lane int_fp16_fp32`（iverilog 用行为级 DSP stub，输出 RESULT=PASS），或 Vivado xsim：`xvlog -sv ../common/dsp_usage.v $(find ../mac_cores -name '*.v') ...` → `xelab -L unisims_ver ... tb_mac glbl -snapshot s` → `xsim s -R`，自检 testbench 验证 4c/5c/6c 变体输出 bit-exact 一致；③ 综合——`bash ./run_one_synth.sh 2lane int_fp16_fp32 4c`（默认 PERIOD_NS=2.222 即 450 MHz，CSV_OUT=verification/synth_all.csv，TAG 标记 run 目录），结果以 `OK|2lane|int_fp16_fp32|4c|...|1054|377|1|-1.866|244.62` 形式追加（LUT/FF/DSP/WNS/Fmax）；④ 输出——资源/时序表（Table IV/V、Fig.6-10）。作用原理：XtraMAC 把 DSP48E2 45-bit 乘法器当作"可分区的位空间"而非不透明单 lane 原语，通过位级打包把低精度 lane 并行塞进同一乘法器，综合工具报告的面积/频率直接量化"资源紧凑性 vs 运行时切换灵活性"的权衡，验证相同 DSP 预算下 XtraMAC 相对 upcasting（vendor FP IP 平均 32.4% DSP 位利用）、空间复制（26.7%）、时间共享（TATAA BF16 仅 8.9%）baseline 的 1.4–2.0× 计算密度提升。
