## μRNG: A Framework for Assessing Randomness in Intermittent Computing Devices

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 µRNG（ISCA 2026，Virginia Tech，Prakhar Sah & Matthew Hicks）：一个评估间歇计算设备 RNG（随机数发生器）鲁棒性的系统性框架。不是新的硬件 RTL 或模拟器修改，而是对 9 个商用 UlSWaP（Ultra-low Size, Weight, and Power）MCU 家族（共 189 台设备，SiFive FE310-G002 / TI MSP430FR59x/69x / TI MSPM0 L-Series / Microchip SAM D21 / SAM L10/L11 / TI TM4C123x / TI MSP432Px / Ambiq Apollo3 / Apollo4）上 RNG 实现的实测评估方法论。框架分 5 个实验阶段：(1) ground-truth 配置发现——捕获硬件/软件后处理之前的原始 RNG 输出（无 API 直接暴露原始输出的设备如 Apollo4 需反汇编固件、单步调试定位 TRNG 内存映射输出寄存器并打补丁）；(2) 连续模式统计测试——名义条件下连续采集 RNG 输出，用 NIST SP 800-22（15 项测试）分析；(3) 间歇模式采集——每次电源循环后取 RNG 首次输出的高 16 bit，跨 65,536 次电源循环拼接成 128 KB 位流再做统计测试（模拟 boot-time entropy hole 下密钥/nonce 生成的真实场景）；(4) 环境极端 corner 采集——在每设备工业温度范围（-40°C 到 +85°C，实测可低至 -68°C、高至 +215°C）与电压范围内重复阶段 3；(5) 弱点发现测试——在 NIST 之外补充碰撞测试（生日悖论期望碰撞数 vs 实测偏差）、熵估计（min-entropy 与 Shannon 熵）、Moran's I 空间自相关（量化位图聚类），检测环境与 RNG 输出质量的关联。根据各阶段结果把 RNG 分类：Insecure / Class 1（名义连续）/ Class 2（名义间歇）/ Class 3（极端间歇，软件可信）/ Class 4（极端间歇，可能弱）/ Class 5（极端间歇，推荐）。
  - 实验比较：比较对象是 9 个设备家族的 RNG 类型（PRNG / 片上 TRNG / 片外 TRNG / 混合 HRNG）、熵源（无 / System Uptime / Device-Specific Seed / Thermal Noise / 未披露）、PRF（LCG、Yasmarang、AES-128-CTR、Stream Cipher+Bitwise XOR、SHA512+AES-CTR）、吞吐量（0.0001-1.0000 bits/cycle）、NIST 通过情况、间歇/环境敏感性、攻击面（软件状态访问、总线嗅探、环境操控）。baseline 是传统 RNG 评估方法（NIST SP 800-22 / Diehard / TestU01 统计测试套件）在连续供电、攻击者访问受限假设下的分析——论文证明这类方法在间歇环境会产生虚假安全感。结果：189 台中 132 台无片上 RNG（5 个家族 88 台仅有 rand() LCG 类 PRNG），44 台（MSP430FR59x/69x）用固定设备级种子，27 台 RNG 在间歇+攻击者环境控制下不安全，仅 23 台（MSPM0 L-Series）提供可信熵源（Class 5）。MSPM0 L-series TRNG 用 Johnson-Nyquist 热噪声源 + delta-sigma 调制器数字化 + 内部 LDO 供电抗电源攻击 + 流密码条件化 + 可配置抽取（rate 1-8），含启动/持续健康测试；Apollo4 HRNG 由 TRNG 24 字节种子×2 → SRAM → SHA-512 哈希 → AES-CTR PRNG，逆向发现原始种子经 SRAM 中转可被攻击者截获，计数器（0x400c0134）随温度偏离（-40°C 6/65536 次 → +85°C 666 次）指示 NIST SP 800-90B 硬件健康测试反复失败；SAM L10/L11 片上 TRNG 32-bit/84 cycles，温度升高时碰撞偏差指数增长（+85°C 3.3V 时 4.2% 偏差），+215°C 热风枪下 15 项 NIST 中 8 项失败；SAM L10/L11 Xplained Pro 的片外 ATECC508A TRNG 经 I2C 总线可被示波器探针嗅探；参考熵源研究——SRAM（MSP432P401R 上 4KB 上电态，名义 0.149 bits/bit 熵，-68°C 数据保持使熵降至 0.004，+85°C 慢压摆率下布局不对称导致 Moran's I 0.127 条带化）与 5 级 CMOS 反相器 RO TRNG（温度升、电压降时振荡频率下降、熵下降，Table III 频率 6.27 kHz-4.00 MHz，Class 4）。
  - 真实世界攻击验证：针对 MSP430FR59x/69x CTR-DRBG（TLV 0x1A30 固定 128-bit 种子 + 0x1A0A 64-bit nonce，.infoD FRAM 保存工作状态与 instantiated_flag 0xAA），工作站软件重建算法复现 2048-bit 随机流推导 Diffie-Hellman 共享密钥；利用 .infoD 可写性打补丁重置 instantiated_flag 强制重新实例化，使两台 MSP430FR5994 重复相同位流立即恢复共享密钥。Adafruit Metro M0 Express（SAM D21）uptime 种子（误差 ~100ns）产生 121 个重复共享密钥。Apollo4 截获 SRAM 中 48 字节 TRNG 种子、SAML11 I2C SDA/SCL 探测，均重建 2048-bit 随机流。

  - 无传统性能模拟器（不评估性能/面积/功耗；评估对象是真实商用 MCU 硬件）。测试台硬件：电源控制器 = TLP222AF 单刀单掷固态继电器（Toshiba，https://tinyurl.com/TLP222A）+ MCP4725 12-bit DAC（Microchip，I2C，0-5V 可调输出电压，https://www.microchip.com/en-us/product/MCP4725），Raspberry Pi 3B 通过 GPIO 控制继电器通断（每周期 2s 断电 + 1s 上电）并经 I2C 控制 DAC 输出电压，同时充当外部存储与自动化脚本宿主机；TE-123H 温湿度箱（TestEquity，-68°C 到 +175°C，<25% 湿度，https://www.testequity.com/category/Environmental-Chambers-Ovens/Temperature-Humidity-Chambers/TestEquity-123H-Temperature-Humidity-Chamber-North-America-Version-17267-1）；热风枪（+215°C 极限测试）；示波器（I2C 总线嗅探）；板级 5 级 CMOS 反相器 RO（Raspberry Pi 3B GPIO 内存映射寄存器直接采样）。统计工具：NIST SP 800-22 统计测试套件（https://doi.org/10.6028/NIST.SP.800-22r1a）。被评估的 MCU 平台：FE310-G002（SiFive HiFive1 Rev B 板，https://www.sifive.com/document-file/freedom-e310-g002-datasheet）、MSP430FR59x/69x、MSPM0 L-Series（https://www.ti.com/lit/ug/slau847e/slau847e.pdf）、SAM D21、SAM L10/L11 Xplained Pro（ATECC508A，https://ww1.microchip.com/downloads/aemDocuments/documents/OTH/ProductDocuments/DataSheets/20005928A.pdf）、TM4C123x、MSP432Px（MSP-EXP432P401R LaunchPad）、Apollo3、Apollo4 Blue Plus。

- 模拟器模拟什么的性能，修改了什么。
  - 无性能模拟器。测试台"模拟"的是间歇供电与极端环境的真实物理条件：电源控制器通过固态继电器周期性通断 DUT 供电（65536 次电源循环，2s 断电放电消除残余电导），DAC 在 0-5V 范围设定电源平面电压（SRAM 实验经外部 RC 电路直接接入 SRAM 电源轨旁路片上稳压器，控制压摆率）；TE-123H 温箱在 -68°C 到 +215°C 控制环境温度（DUT 置于密封袋防霜冻短路，电源控制器置于箱外因组件工作范围受限）；热风枪做超出标称范围的极限升温。
  - 修改内容（相对被测平台的固件/软件）：① Apollo4 静态链接 cryptocell/mbedtls 库，无法改源码取原始 TRNG 输出——反汇编二进制、单步调试定位 TRNG 硬件填充内存映射寄存器（0x400c0114 处 24 字节种子）的指令，打补丁把 LLF_RND_TRNG_ReadEhrData() 宏重定向到自写插桩代码，复制 24 字节原始种子到片上 NVM，并读取 0x400c0134 计数器；② 采集脚本：Raspberry Pi 上自动化调度 DUT 上下电 + 每次上电读取 RNG 首次输出高 16 bit（按设备选最优存储策略：片上 NVM 行写入（行大小填充 16-bit 值、MSPM0 因 ECC 防重写写 shadow 地址空间）或 UART 外传，65,536 样本 × 3s/循环 最长 55 小时）；③ 电源控制器固件：Raspberry Pi I2C 写 MCP4725 设目标电压、GPIO 触发 TLP222AF 继电器；④ 板级 RO TRNG：自定义 C 程序内存映射 GPIO 实时采样 5 级反相器振荡输出。
  - 弱点发现工具实现：碰撞测试按 k≈√(2·2^n·ln(1/(1-p))) 与 E=C(k,2)/2^n 对比期望碰撞数随环境 corner 的偏差；熵估计用 min-entropy=-log2(max p(xi)) 与 Shannon 熵；Moran's I=(N/W)·(ΣΣ w_ij(x_i-x̄)(x_j-x̄))/Σ(x_i-x̄)² 用共享边界 + k 近邻计算空间权重，量化 SRAM 位图聚类/条带化。

  - 使用例子（测试台输入到输出全过程，以 MSPM0 L-Series 为例）：① 搭建电源控制器——Raspberry Pi 3B GPIO 接 TLP222AF 继电器控制 DUT 电源平面，MCP4725 DAC 经 I2C 挂在电源平面设定 Vdd；② 部署 DUT 采集固件——写线填充 16-bit 随机值到 flash 行（MSPM0 用 shadow NVM 地址规避 ECC 重写限制），每次上电读 TRNG 内存映射寄存器 trng->DATA_CAPTURE（32-bit，取高 16 bit，丢弃启动确定性首字）；③ 运行 Raspberry Pi 脚本——循环执行「2s 断电（TLP222AF 断开、DAC 保持目标电压）→ 1s 上电 → 读回 16-bit 样本」，共 65,536 次，样本写回 Raspberry Pi（外部存储）；④ 按设备切换环境 corner——TE-123H 设 -68°C/+25°C/+85°C、DAC 设 1.62V-3.6V，每 corner 重跑步骤 3；⑤ 统计后处理——把每次上电首 16 bit 拼接成 128 KB 位流，NIST SP 800-22 15 项测试判定 pass/fail，再跑碰撞/熵/Moran's I 弱点测试比较各 corner 偏差；⑥ 输出设备 RNG 分类（Class 1-5/Insecure）与吞吐量（bits/cycle）。作用原理：传统统计测试只验证连续长位流的均匀性，µRNG 通过在"每次电源循环首输出"（boot-time entropy hole 下的真实密钥生成时机）与"攻击者可控制的温度/电压 corner"两个维度重新组织采集，把传统方法掩盖的间歇熵损失与环境相关性暴露出来——MSPM0 在所有 corner 下 NIST 全通过且无弱点（Class 5），而 SAM L10/L11 温度升高时碰撞偏差指数增长（+85°C 4.2%、+215°C 时 8/15 NIST 失败，Class 2）。
