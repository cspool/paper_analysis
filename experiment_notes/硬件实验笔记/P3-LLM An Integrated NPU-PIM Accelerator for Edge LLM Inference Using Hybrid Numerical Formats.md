## P3-LLM An Integrated NPU-PIM Accelerator for Edge LLM Inference Using Hybrid Numerical Formats

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 P3-LLM 的 NPU-PIM 集成加速器，核心是构建在 HBM-PIM [49] 之上的低精度高吞吐 PCU（PIM compute unit）微架构与 throughput-enhanced PCU (TEP)：(1) PCU 微架构——1 个 PIM channel 含 8 个 PCU，每 2 个 bank 共享 1 个 PCU 摊销面积；因权重/KV 量化为 4-bit，每个 PCU 配 64 个乘法器匹配 HBM 256-bit 列访问粒度（相对 HBM-PIM 的 16 个 FP16 乘法器计算吞吐 4×）；为规避 SIMD 设计每乘法器配 32-bit 累加器的寄存器开销，保持与 HBM-PIM 相同的输出寄存器数量、仅增加 16-bit 输入寄存器带宽；PCU 含 16 个 PE，计算 1×4×16 GEMV tile（消费 4 个 8-bit 输入、64 个 4-bit 权重、产生 16 个 32-bit 输出）；每个 PE 计算 4-way dot product：6-bit 定点乘法器（signed 输入尾数 5-bit 含隐藏位 + 符号位=6 bit；INT4-Asym KV 加 4-bit zero-point 后 5-bit；BitMoD 权重 6-bit 定点）+ 4-bit 输入指数移位乘积 + 4:2 压缩树 + 32-bit 定点累加，去掉 FP16/FP32 MAC 的高精度乘法器与指数对齐模块；(2) TEP——利用低精度 PCU 面积小、频率可达 HBM-PIM 的 2×，把操作时钟从 tCCD_L（4 个内存总线周期）提升到 tCCD_S（一半），使同一 256-bit 权重切片在同一 tCCD_L 窗口内被两个不同输入各复用一次（temporal input reuse），双倍吞吐而无需增加乘法器；(3) 系统级——4 个 NPU core（每 core 128×128 systolic array、128-way vector unit、16MB on-chip scratchpad）+ 16 个 pseudo HBM channel。实验比较：decoding 阶段速度（batch 1-8、context 4K）对比 NPU-FP16、HBM-PIM-FP16、Ecco（W4A8KV4 k-means codebook + Huffman 编码），平均 speedup 7.8×/4.9×/2.0×（batch=2 时最高，得益于 TEP 在单个 tCCD_L 内处理两个输入向量）；与低精度 PIM Pimba（8-bit microscaling）对比平均 3.4×（含 8-bit weight-activation 增强版 Pimba 仍低 3.4×）；能量效率平均 6.3×/3.5×/2.1× 优于 NPU/HBM-PIM/Ecco；与 SmoothQuant/AWQ 软件量化在 NPU 上对比吞吐 3.9×/3.0×；memory 分析：权重+KV 4-bit 使 decode 内存占用相对 FP16 降 3.7×（Ecco 3.8×）；context length 2K-16K 单 batch 敏感性；batch 2-64 大规模解码适用性（与 Ecco 对比，attention 层 GQA 仍受益）；架构消融（Fig 15）：HBM-PIM FP16 → +W4A8KV4（3.3×）→ +TEP（额外 1.6×）→ +8-bit attention-score 全 attention 上 PIM（额外 1.2×）。
  - 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - (1) 论文自研 cycle-level simulator 建模整个 P3-LLM 系统（4 NPU core + 16 pseudo HBM channel），PIM 子系统按 Newton [23] 的方法论扩展建模所提出 PCU 的计算流；(2) PCU 用 SystemVerilog 做 RTL 级建模，Synopsys Design Compiler 在 TSMC 28nm 综合，面积/功耗结果用 DeepScaleTool 缩放到 HBM-PIM 的 20nm 工艺，并按 DRAM 工艺相对逻辑工艺同特征尺寸下 10× 低晶体管密度修正；(3) NPU on-chip scratchpad 用 CACTI [5] 建模；(4) 频率设定：NPU 1 GHz、PCU 500 MHz（考虑 HBM2 的 tCCD_S=2 个 DRAM 时钟周期）。模拟器与 RTL 均未开源（web 确认 GitHub 仅含量化算法代码）。
- 模拟器模拟什么的性能，修改了什么。
  - cycle-level simulator 模拟 decode 阶段端到端延迟/吞吐/能耗：NPU 侧建模 systolic array GEMM 与 vector unit、scratchpad 访存；PIM 侧建模 bank 级并行、256-bit 列访问、PCU 计算流（4-bit 权重×8-bit 输入 MAC、tCCD_S/tCCD_L 命令时序、TEP 的权重复用）、DRAM row activation 与能耗。修改/扩展了 Newton 的 PIM 方法论来支持低精度混合格式 PCU 的计算流程与 TEP 时序（论文未给出模拟器源码）。能耗建模含 DRAM 单元访问与列译码切换（TEP 在 tCCD_S 下 PIM 功耗 +28%，但能量效率 1.56× 更好）。输出：Fig 9/11/12/16 的归一化 decode speedup/latency、Fig 10 的 energy breakdown、Fig 15 的架构消融、Table VII/Table VIII 的面积功耗。关键面积结果：P3-LLM HBM 面积开销 17.5%（PCU compute 8.4mm² + buffer 6.2mm²），低于 25% 逻辑占比上限，相对 HBM-PIM FP16 仅 +1.1% 面积；PE 对比：P3-LLM 4 MACs/cycle、1109.2 µm²（1.08×）、0.18 pJ/MAC（0.26×），优于 BitMoD（2 MACs、1291.6 µm²、0.61 pJ/MAC）与 MANT（2 MACs、717.3 µm²、0.40 pJ/MAC）。

  - 开源情况：硬件（SystemVerilog RTL、cycle-level simulator、综合脚本）未开源；仅量化算法开源（https://github.com/yc2367/P3-LLM，MIT，含 wkvaq_quant/、3rdparty/ AWQ 与 LM-Eval 子模块）。可复用开源组件：HBM-PIM 为 Samsung 商用 PIM 器件、Newton [23] 是公开 PIM 模拟方法论、CACTI（https://github.com/HewlettPackard/cacti）估算 scratchpad、DeepScaleTool 做工艺缩放。模拟器输入到性能输出全过程（以 Llama-3.1-8B decode 为例）：输入为模型架构参数（层数/head 数/head 维度/隐藏维度，含 GQA group size 4）、W4A8KV4P8 量化参数（BitMoD 权重索引、INT4-Asym KV 与 smoothing factor、FP8 激活/注意力分数）、工作负载（batch size 1-8、context 4K）与系统配置（4 NPU core 128×128、16 pseudo HBM channel、每 channel 8 PCU、频率 1GHz/500MHz）→ simulator 按 decode 迭代推进：attention/linear 层判断 offload 到 PIM（GEMV 在 256-bit 列粒度读权重/KV，PCU 每 cycle 计算 1×4×16 tile，TEP 在 tCCD_S 窗口内复用同一权重切片的两个输入）或留在 NPU（RoPE/Softmax/元素级操作与 pre-RoPE 方案的 Q·K^T）→ 按 DRAM 命令时序（tCCD_S/tCCD_L）与 bank 状态累计 cycle 与 DRAM/PCU 能耗（RTL 综合的 0.18 pJ/MAC 等参数标定）→ 输出归一化 decode 吞吐、能量 breakdown、面积（17.5% HBM 开销）与 speedup 曲线（Fig 9-16）。模拟原理：cycle 级事件驱动 + 基于 RTL 综合（28nm→20nm）标定的面积/功耗模型 + CACTI 片上存储模型，decoding 主导端到端延迟（edge 场景）。
