## R-Max: Extending Bélády's MIN with Prefetching to Bound Realistic Cache Performance

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是对 ChampSim 微架构模拟器的修改：(1) 新增 R-Max prefetcher 模块（代码在 ./prefetcher，可独立或同时放在 L1D/L1I、L2、LLC），实现"oracle 未来访存知识 + 现实带宽/MSHR/容量/延迟约束"的近似理想预取+替换；(2) 新增 MIN（Bélády's）replacement 模块（无预取的理想替换 baseline）；(3) 新增 SPP-Max/Berti-Max 配置（第一相记录 SPP/Berti 预测的地址列表，第二相用 R-Max 的 oracle 时序与替换决策重放，隔离"预测能力"的影响）；(4) 修改缓存/MMU 路径以跨迭代保持虚拟-物理页表翻译一致（va_to_pa.txt、page_table.txt）并记录访存流（cache phy acc.txt）与 R-Max 预取时序（oracle pf timing.txt）。R-Max 的软件数据结构（Cache Status Map、Pending Prefetch Queue、Delayed Prefetch List、λ Queue、Do Not Fill Queue）论文明确说明是纯软件实现（该算法不可在真实硬件预取器中实现，故不优化其大小）。
  - 实验比较（相对无预取 LRU baseline 的 IPC speedup 为主线）：R-Max(L1D/L2/L3/L1D+L2) vs SPP+PPF(L2)、Berti(L1D、Berti(L1)+PPF(L2))、AMPM(L2)、IPCP(L1)、IP-Stride(L1)、无预取 MIN(L1D/L2/L3)、Always Hit(L1D/L2/L3)、SPP-Max/Berti-Max(L1D/L2)。次要指标：prefetch coverage（表 VI：R-Max L2 93.2%–97.7% vs SPP 13.7%–41.9%）、accuracy（Fig.9：R-Max 95.75%–99.99%）、timeliness（Fig.10，cycle 分布，范围宽但平均更高）、DRAM utilization（Fig.7：R-Max 相对 baseline -47.93%，SPP 反而 +21.43% 因错误预取污染）、×100 容量与 ×100 MSHR 消融（Fig.8，仅增 MSHR 收益不大，大容量逼近 R-Max）、收敛性（Fig.6，≤12 轮，每轮耗时约 baseline 的 37%–118%）。主要结论：R-Max(L2) 平均 72.6%、最大 299.6%，超 SOTA 60.8%；GAP/XSBench 等新兴负载潜力最大，现有预取器集中于同一小批负载（SPP/Berti 获利负载高度重合）；多核 LLC 不收敛，留作未来工作。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - ChampSim（trace-driven 微架构模拟器，https://github.com/ChampSim/ChampSim，论文引用 [8]）。论文使用其修改版：https://github.com/wilsonwang881/53rd ISCA 2026 R-Max Artifact（论文附录提供，Source Code DOI 10.5281/zenodo.19688265，Apache-2.0，GCC/11.3.0、11.4.0 + vcpkg 依赖）。
- 模拟器模拟什么的性能，修改了什么。
  - ChampSim 逐条消费指令 trace，模拟乱序流水线（ROB 512、6 发射、load/store queue 192/114）、分支预测（Hashed Perceptron）、三级 TLB（ITLB/DTLB/STLB）与缓存层次（L1I/L1D/L2/LLC）的命中/未命中、MSHR 合并与 tag 检查带宽，并接 DDR4 内存模型（1 channel/1 rank/8 banks/65536 rows×128 columns/3200 MHz/8-byte 通道），输出 IPC、各缓存层访问类型统计与 DRAM 利用率。论文修改点：(1) prefetcher 目录加入 R-Max oracle prefetcher 实现（record/process/replay 与四队列结构）；(2) 加入 MIN replacement 策略（用记录的下一访问时间做"最远未来使用"替换）；(3) SPP-Max/Berti-Max 两相流程：phase 1 跑原 SPP/Berti 配置记录 va_to_pa.txt（页表翻译）与 pf acc.txt（发出的预取地址列表），phase 2 R-Max 只用记录的翻译与地址列表重放（配置为只发列表中地址的预取），把"预测能力"与"预取时机/替换决策"解耦；(4) 编译与运行脚本：./sim_compile/compile_all.sh 编译所有配置、./sim_run/generate_commands.sh <trace目录> <binary目录> 生成 phase_1_jobs.txt / phase_2_jobs.txt（每行一个可并行 job，CVP-1 需 cvp_public_trace_length.txt）、./sim_run/copy_translations.sh 复制翻译/预取列表；(5) 分析脚本 ./sim_analyze/process_log.py（输出 speedup/coverage/accuracy/DRAM utilization csv，非 CVP 需 weights.csv 权重文件）与 ./sim_analyze/process_conv.py（收敛检查）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：R-Max 修改版 ChampSim 公开（GitHub + Zenodo DOI 10.5281/zenodo.19688265，Apache-2.0）。trace 开源：CVP-1（10.5281/zenodo.15298021）、SPEC CPU2017（https://dpc3.compas.cs.stonybrook.edu/champsim-traces/speccpu/）、GAP/XSBench（10.5281/zenodo.20043527，Jamet et al. 捕获）。
  - 使用例子（复现 L2 R-Max 一次评估）：①git clone 仓库，vcpkg 装依赖，./sim_compile/compile_all.sh 编译全部配置（no-prefetch LRU baseline、MIN-L2、SPP-L2、Berti-L2、RMax-L2、SPP-Max-L2、Berti-Max-L2 等）；②建 benchmark 目录，./sim_run/generate_commands.sh <trace目录> <binary目录> 生成 phase_1/phase_2 两个 job 文件（CVP-1 需 trace 长度文件）；③并行提交并等待 phase_1 全部完成（跑 baseline、普通 SPP/Berti，输出 va_to_pa.txt、page_table.txt、cache phy acc.txt、pf acc.txt）；④在根目录 ./sim_run/copy_translations.sh 复制翻译与预取列表给 R-Max/MIN/SPP-Max/Berti-Max；⑤并行提交并等待 phase_2（跑 R-Max 等配置），本轮生成的 cache phy acc.txt 作为下一迭代输入，迭代直到收敛（≤12 轮；少数 CVP-1 L1D R-Max IPC 振荡则取高值）；⑥./sim_analyze/process_log.py（非 CVP 传 weights.csv）输出 speedup/coverage/accuracy/DRAM utilization 的 csv，process_conv.py 查收敛。
  - 模拟器输入到性能输出全过程：输入 = 指令 trace（+ 首轮录得的页表翻译与访存/预取记录）→ ChampSim 逐周期模拟 OoO 流水线与缓存/MSHR/DDR4（demand 与预取流同走 MSHR、支付带宽/延迟/容量代价）→ 输出 log.txt（IPC、每层访问类型、DRAM 利用率）+ cache phy acc.txt（本轮访存流，喂给下一轮）→ process_log.py 汇总相对无预取 LRU baseline 的 speedup 等指标。作用：在单核 3 级缓存 + DDR4 的现实约束下量化"预取+替换"的现实上界（L2 geomean 72.6%），并归因剩余差距（预测准确率/覆盖/带宽/MSHR/容量/时效），指导新预取器设计（特别是 GAP/XSBench 等新兴负载）。
