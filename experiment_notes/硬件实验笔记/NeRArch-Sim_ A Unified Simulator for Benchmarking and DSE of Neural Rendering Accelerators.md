## NeRArch-Sim: A Unified Simulator for Benchmarking and DSE of Neural Rendering Accelerators

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 NeRArch-Sim：面向神经渲染加速器的统一开源模拟器（SystemC/HLS），由三大组件构成：(1) 模块化软件工作流（modular software workflow）——用轻量运行时钩子插桩已有算法框架（Nerfstudio），拦截函数调用（函数标识符、调用次数、张量形状、张量值、caller-callee 关系）生成算子图（execution_dag.pkl），保留函数依赖/输入输出数据量/调用频率，且不修改原算法；另可在 GPU 上做算子特性分析（如 roofline）作为开发者参考；核心是模块化算子库，按统一分类学封装计算原语并提供统一可扩展接口（如 neurex_pipeline 用 UniformSampler+HashEncoding+MLP 搭建）。为保证不漏算子，还会重放提取的算子图并与原 pipeline 输出对比验证无质量退化。(2) 模块化硬件加速器（modular hardware accelerator）——基于统一分类学（Field Sampler/Encoding/Field Computation/Blending 四阶段）组织的 20+ 可复用 SystemC 模块库，配可配置头文件（数据类型、精度、memory binding）；支持两级硬件表征：HLS 综合（快速 PPA 估计）与全 ASIC post-layout 流程（精确 PPA，含互连/布线开销）；内存子系统为可配置 SRAM 块（容量/组数/端口数/访问延迟）+ 经 Ramulator 2.0 建模的 DRAM 后端。(3) 模块化数据流调度器（modular dataflow scheduler）——三层分解：mapping engine（算子-硬件绑定，输出 mapped IR）、operator-level scheduler（各硬件模块内局部优化）、system-level scheduler（跨模块全局编排），输出端到端 PPA，端到端调度在 workstation-class CPU 上秒级完成。
  - 实验比较什么：(a) 复现 11 个已有神经渲染加速器（ICARUS、MetaVRain、NeuRex、CICERO、SRender、GSCore、GS Processor 等）在 2 个数据集上的建模误差 ≤9.4%，改动极小；(b) 与已有模拟方法对比（Tab. I：RTI 类分析模型/周期级模拟高精度低速度、低扩展性 vs NeRArch-Sim 高精度+高速度+高扩展性+高可实现性）；(c) DSE 案例研究：引导新加速器设计取得最高 1.3× 效率提升；(d) 内存行为分析：ICARUS/NeuRex/GSCore 在 Lego 场景的 per-SRAM 数据流剖析（如 GSCore 每 tile 从 DRAM 流式读取约 79MB 高斯特征）；(e) 模块复用分析：跨 SRender、Lumina、GS Processor、Instant-3D、GSArch；(f) 案例集成：SRender 接入仅需 2-3 天工程、<300 行 C++；4DGS 扩展在 Flame Steak 场景上 FPS 误差 5.9%、PSNR 误差 0.3%；SRender 复现相对面积误差 5.3%。
- 硬件平台是什么，配置是什么。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟神经渲染加速器在给定渲染 pipeline 与硬件配置下的端到端性能：延迟（周期）、吞吐（FPS）、面积、功耗（PPA），以及各 SRAM/DRAM 块的访存流量与带宽（memory-aware duration 模型：SRAM 容量/组/端口/延迟 + Ramulator 2.0 DRAM 时序）。修改/构建：按统一分类学用 SystemC 实现 20+ 模块——Sampling（Culling conversion unit、Skipping controller、Sampling unit）、Encoding（Position encoding unit、Address generator、Tree reducer、Index generation/computation unit、Distance computation unit、Comparison unit、Sensitivity prediction engine、Feed forward mapper、Backward update merger）、Field Comp（MLP 引擎 4 变体：SSA/MONB/SONB/Systolic array、Adder tree）、Blending（Volume rendering units 3 变体、Bitonic/Quick sort unit、PE arrays 3 变体、LuminCache 等）；可配置架构参数包括综合指令（pipelining II、loop unrolling、array partitioning）、精度（任意整型/浮点/定点）、实现方式（CORDIC、分段线性 exp）、模块规模（systolic 阵列尺寸、PE 数、buffer 深度）、并行因子、通道深度/流宽/握手协议。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：MIT 协议，https://github.com/GATECH-EIC/NeRArch-Sim；提供 CLI、NeRArch-Sim Studio 图形界面（WebApp，`./nerarch_sim gui`）、tests（端到端/mapping/scheduler/latency/PPA 测试）、Hardware/examples/hardware_configs/ 下 icarus/neurex/neurex_server/cicero/gscore/gsarch/instant3d/lumina/fourdgs/gbu 等 *_config.json 示例。
  - 使用例子（ICARUS 端到端）：(1) 安装：conda 建 Python 3.8 环境，装 torch 2.1.2+cu118/tiny-cuda-nn/graphviz/nlohmann_json，`pip install -e .`，`git submodule update --init --recursive`，克隆 Ramulator 2.0 到 Hardware/，`./build_cpp.sh`；(2) 采集 trace：checkout Nerfstudio 指定 commit，拷贝 Instrumentation/nerfstudio_vendor 下 tracing.py/trace_config.json/eval.py/train.py/eval_utils.py 等，训练后 `ns-eval --load-config <config> --render-output-path $OUT --enable-trace --trace-config-path .../trace_config.json --eval-image-indices 0`，得到 $OUT/execution_dag.pkl（记录每个算子的函数标识、调用次数、张量形状/值、调用关系）；(3) 端到端：`./nerarch_sim analyze $OUT/execution_dag.pkl output_icarus_ppa --hardware Hardware/examples/hardware_configs/icarus_config.json --report-format html`，或分步 `map`（→mapped_ir.json）→ `schedule --hardware`（→scheduled_ir.json，可选 --no-ppa 跳过 PPA）→ `report`；(4) 模拟原理：输入算子图（.pkl）与硬件 JSON → mapping engine 按统一分类学把每个算子匹配到兼容硬件单元（多个候选取最高吞吐，多实例均衡绑定避免瓶颈；不匹配则报告 mismatch），输出 mapped IR（算子信息、taxonomy 属性、硬件绑定、资源需求、优化技术）→ operator-level scheduler 给每个硬件模块内任务排 start_cycle/duration、资源分配与数据搬移 → system-level scheduler 跨模块全局编排执行计划，按 memory-aware 时长模型（SRAM+Ramulator DRAM 时序）累加周期 → 输出 PPA 报告（FPS、面积、功耗、per-SRAM/DRAM 流量）；(5) 校验：`./nerarch_sim validate` 检查 DAG 无环、四阶段覆盖/顺序（SAMPLING→ENCODING→FIELD_COMPUTATION→BLENDING）、重放捕获的 field 输出渲染成图并与 Nerfstudio 渲染/ground truth 三方对比（强制重算 PSNR 门限 35dB、阶段消融 ≥10dB、GT 一致性 ~1dB），输出 PASS/FAIL；`./nerarch_sim topo` 生成交互拓扑视图。

#### 补充：完整评估设定与数值（来自论文 Sec. IV-B~IX，主 .md 截断部分）

- **评估设定（Sec. V-A）**：算法基础设施框架 = NerfStudio [55]；模块化硬件加速器 = Catapult HLS [50] + SystemC [1]；调度器 C++；硬件配置用商用 28nm HPCP 工艺节点，基线经 DeepScaleTool [48] 归一化到 28nm；SRAM 分析用该节点 SRAM compiler；DRAM 时序用 Ramulator [18]；全 ASIC 参考流程 = Synopsys Fusion Compiler [53] + PrimePower [52]（post-layout）。数据集：NeRF-Synthetic [39]（小场景）+ Unbounded360 [3]（大场景，含 Garden/Bicycle/Stump）。端到端基线：ICARUS [44]、NeuRex [23]、CICERO [12]、GSCore [25]、GBU [65]、Uni-Render [26]。
- **单模块验证（表 VI）**：17 个模块延迟 NeRArch-Sim 与全 ASIC flow 完全一致，面积/功率相对误差 4.72%~9.33%（ICARUS Pos Encoding 6714/5200 µm²、NeuRex Systolic Array(32×32) 5.4×10⁵ µm²、CICERO NPU(24×24) 3.1×10⁵ µm²、GSCore CCU 1.7×10⁵ µm²、GBU Row Processing 41253/45345 µm²、Uni-Render PE Array(16×16) 13.2/14.2×10⁶ µm²）。
- **端到端复现（表 VII，Lego/NeRF-Synthetic）**：PSNR 复现 ICARUS 29.4/NeuRex 29.8（报告 27.0）/CICERO 23.5/GSCore 34.4/GBU 33.3/Uni-Render 33.0（平均误差 2.6%）；面积平均误差 6.5%（ICARUS 6.9/NeuRex 20.3/CICERO 0.33/GSCore 3.6/GBU 1.9/Uni-Render 15.66 mm²）；FPS 平均误差 3.4%（ICARUS 0.02/NeuRex 18.6（报告 19.7）/CICERO 326.4/GSCore 182.2（报告 190）/GBU 172（报告 180）/Uni-Render 63（报告 65））。
- **资源利用率（图 12，Bicycle/Unbounded360）**：ICARUS 访存极低、MLP 为持续瓶颈；NeuRex 由 IGU 与 systolic array 主导、偶发 memory miss；GSCore 短暂预处理后由 VRU 主导。
- **per-SRAM 数据流（表 VIII/IX，Lego）**：ICARUS Input FIFO(4KB) 每帧流 1.4GB 采样坐标、权重 MONB/SONB 加载一次复用 ~100K 次、激活 ping-pong（48KB×2，SRAM Rd/Wr 234.4GB）；NeuRex position streaming 469MB、Grid Cache 64KB 服务 9.8GB 读、Subgrid Buffer 128KB 不规则哈希查找（bank conflict 7.7M、stall 开销 2.25%）；GSCore 每 tile 流 78.8MB 高斯特征、排序缓冲 12.4MB 读写、Pixel Out 3.1MB，bank conflict 开销 0.01%。
- **跨加速器对比（表 X，Unbounded360）**：除 3DGS 外多数 pipeline 在复杂场景下达不到 30 FPS（ICARUS 7×10⁻⁴~9×10⁻⁴ FPS、NeuRex 0.68~0.73、CICERO 9.57~10.92、GSCore 61.3~81.77）；CICERO 资源最少却 FPS 相对高；CICERO+（放大到 3DGS 级）比 GSCore-（缩到相似 FPS）更省资源（1.320 vs 2.953 mm²）。
- **调度延迟（表 XI，NeRF-Synthetic）**：单设计点总耗时 47.7~79.2s = instrumentation 22.8~45.2s + graph construction 0.4~0.8s + mapping 2.0~5.3s + op-level 7.1~24.1s + sys-level 1.0~21.1s；硬件特性离线预计算成查找表；硬件-only DSE 复用算子图，每点仅调度器约 1 分钟。
- **DSE 案例（Sec. VI，GSCore/Unbounded360）**：Simulated Annealing 搜索五参数 (Culling Conversion Units, Quick Sorting Units, Bitonic Sorting Units, Volume Rendering Cores/VRCs, Buffer sizes)，最优 (16,8,4,32,4) vs GSCore 原 (4,8,4,64,8)：1.3× energy-delay product 下降、1.6× 面积下降、相对穷举 2.8× 加速。
- **扩展案例（表 XIII/XV）**：SRender（面积误差 5.3%，FPS 55.3→52.2 误差 5.6%，2-3 天接入）、Lumina（FPS 218→201 误差 7.8%，NRU 复用 + LuminCache/LuminCore 新增）、GS Processor（373→343 延迟误差 8.0%，对真实流片芯片验证）、Instant-3D 训练（1.65→1.80 s/scene 误差 9.1%，backward 属性扩展）、GSArch 训练（180→191 误差 6.1%，动态算子图需逐变体插桩）、4DGS 工作负载（GBU 上 Flame Steak 场景：FPS 67→63 误差 5.9%、PSNR 33.71→33.8 误差 0.3%，新增 Temporal Culling/Temporal Projection 算子）。
