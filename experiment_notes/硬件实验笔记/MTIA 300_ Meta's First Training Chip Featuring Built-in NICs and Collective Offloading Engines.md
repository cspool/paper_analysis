## MTIA 300: Meta's First Training Chip Featuring Built-in NICs and Collective Offloading Engines

- 属于硬件架构的实现是什么？实验比较什么？
  - 属于硬件架构的实现：MTIA 300 是 Meta 首款训练芯片（DLRM 优化），chiplet 架构的真实流片 AI 加速器（ISCA 2026），核心硬件创新三件套：(1) **内置 NIC chiplet**——封装内集成 2 个网络 chiplet，每 chiplet 6 个定制 800 Gbps RDMA NIC（共 12 NIC、合计 1.2 TB/s I/O），避免 PCIe 数据通路与 host 参与；(2) **集体通信卸载（Message Engine, ME）**——compute chiplet 内 16 个专用 ME 处理 collective，与计算引擎同吞吐但仅用 1/3 面积（相对 PE 核的归约面积效率）；(3) **近内存计算（NMC）**——ME 放在 HBM/cache/I/O 旁，NMC 归约块 128 B/cycle（归约或 DMA）、全并发时 96 B/cycle，最高 2.8 TB/s 归约带宽（>2× I/O 带宽 1.2 TB/s），硬件加速 Reduce/AllReduce/ReduceScatter。compute chiplet：12×6=72 PE 网格 + 16 ME，2D mesh NoC（cluster router 本地连 6 PE 降跳数、L-routing 均匀分布流量、虚拟通道防死锁，无 memory crossbar），东西侧 SRAM bank（LLC/LLS，共 192 MB 片上），每侧 3 个十二高 HBM3E stack（共 216 GB、6.1 TB/s）。PE 内含 2 个 64 B 宽 RISC-V 向量核（异步 dataflow 执行模型）+ DPE（GEMM，双 32×64B×32 MAC tile，7.82 TFLOPS/PE，FP16/BF16 输入 FP32 输出，支持 FP8/TF32）+ RE（跨 PE 专用归约网络）+ SFU SIMD（128 元素/cycle，FP8/FP16/BF16/FP32，硬件 radix-sort 加速 embedding 反向，min/max/clamp/stochastic rounding）+ MLU（transpose/reshape/slice/concat）+ Command Processor（CB 抽象、依赖跟踪）+ Fabric Interface（DMA，字节对齐 tensor 切片 DMA + 硬件索引 DMA scatter/gather）+ 512 KB 软件管理 local memory（CB）。时钟 1.9 GHz、7.2B gates、TDP 912W（典型 667W）、FP8 1120 TFLOPS / FP16/BF16 560 TFLOPS、GEMM:SIMD 16:1。
  - 实验比较什么：与 NVIDIA H100/H200 对比（Table III 测试台：H100 定制 500W cap、780 TF/s BF16、96 GB、2.4 TB/s；H200 1000 TF/s、141 GB、4.8 TB/s、700W）：(a) 计算微基准——table-batched embedding（TBE）前向 2.0×/1.6×、反向 2.1×/1.6×（几何均值 vs H100/H200，靠高内存/cache 带宽 + radix-sort/索引 DMA 专用单元）；BF16 加法 kernel 内存带宽 5.57 TB/s（91% 峰值）vs H100 2.26 TB/s（94%）vs H200 4.40 TB/s（92%）；BF16-GEMM vs roofline——大矩阵算术强度 >400 bytes/FLOPS 时 H100 63%、MTIA 300 59%、H200 54% 效率（MTIA 300 受峰值 FLOPS 限制、小 memory-bound GEMM 靠高带宽占优）；(b) 集体通信微基准——AllGather/AllReduce/AllToAll 归一化延迟在 16+ 加速器或 >16 MB 消息时显著优于 H100（归因于 16 节点 scale-up 域与 2.2× 更高 scale-up 带宽），小消息 HCCL 弱于 NCCL（未优化，占比小）；(c) 计算-通信重叠微基准——1000 次 TF32 4K×4K×4K GEMM 并行执行各种代表消息大小 collective（16 加速器），MTIA 300 双 ~100% 效率、H100 因 SM 争用明显退化；(d) 生产 DLRM 训练——150B 参数（99% 稀疏）模型、40 加速器、local batch 6144、Shampoo 优化器，通信性能超 H100 3.9×（AllReduce 入站 1.6 GB、AllGather 2.1 GB、35 次 AllToAllv 1 KB-1 GB），端到端 Perf/TCO 比 H100 高 1.42×（Table IV：40×H100=1.00、40×MTIA 300=1.39、24×MTIA 300 local batch 10240=1.42）；(e) LLM 推理——DeepSeek-R1、8 加速器、InferenceMax benchmark + vLLM runtime，TP8-TP8 与 DP8-EP8 两种分片，高并发（>64）下优于 H200（decode 主导、靠高 HBM 带宽），低并发差距小（小 batch 通信开销 vs H200 NVLink 与 PE 并行度不足）。
- 硬件平台是什么，配置是什么。
  - MTIA 300 实机：1.9 GHz；compute chiplet 25.6×31.4 mm + 2 网络 chiplet 25.6×9.3 mm，封装 77.5×77.5 mm（50.3×51.9 mm 3.2× interposer），2.5D CoWoS，0.85 V，TDP 912W（典型 667W），液冷（对比 MTIA-2i 85W 风冷）；16× PCIe Gen5 host 接口（64 GB/s）；216 GB HBM3E（6 stacks、6.1 TB/s R/W）、192 MB 片上 SRAM（11.4 TB/s）、每 PE 512 KB local memory（1.9 TB/s）；12 个内置 800 Gbps RDMA NIC（RoCE，第三方 NIC IP 定制），scale-up 网络 800 GB/s（可选至 1000 GB/s、16 节点域）、scale-out 200 GB/s（4096 节点 L1）；1:1 host:accelerator（compute blade = 单 CPU 512 GB RAM + 单 MTIA 300）。对比平台：NVIDIA H100（500W power cap 定制）与 H200 实机。软件栈：PyTorch 原生（TorchDynamo + AOTAutograd + TorchInductor + Triton，支持 FSDP2/DTensor/TorchRec/XFormers），CUDA 兼容 runtime API，C++/Triton kernel，HCCL 集体通信库（PyTorch Distributed + torchcomms 接口，RDMA verbs 驱动网络 chiplet）。

  - 使用例子（基于论文架构描述，一次 DLRM 训练迭代的硬件数据路径）：CPU-C（RISC-V quad SMP 控制核）收到含 compute+communication 任务的工作包 → 按依赖把 compute 子图派发到 PE 网格、communication 子图派发到 16 个 ME（CPU-M 经每 ME 单个共享大 CQ 收 WQE，免多队列轮询）→ HCCL 把 collective（如 AllReduce ring）翻译为 WQE 数组（SEND/RECV/WRITE/WAIT/SET/REDUCE，带 wqe_sync/fence/rx_sync/sync 流控字段）→ ME 的 NIC interface 经单 FIFO 把 work request 分发到 12 NIC 的 express doorbell（WR 本身即 doorbell 写、省 800 ns HBM ring-buffer 读）→ 数据经 112G SerDes + die-to-die 接口到网络 chiplet 的 RoCE NIC 发出/接收 → NMC 在 HBM 旁做 128 B/cycle 归约（ReduceScatter 阶段累加、AllGather 阶段转储）→ ME 完成后向 CPU-C 报告解阻塞后续工作 → PE 的 DPE/RE 完成梯度计算继续下迭代。作用：计算与通信在硬件级解耦（collective 不占用 PE 与主机），MTIA 300 在计算+通信并发时保持双 ~100% 效率（H100 因 SM 争用退化），通信性能超 H100 3.9×，Perf/TCO 1.42×。
