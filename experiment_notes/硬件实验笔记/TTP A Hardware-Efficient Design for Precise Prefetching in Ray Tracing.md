## TTP A Hardware-Efficient Design for Precise Prefetching in Ray Tracing

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 TTP（Tree Traversal Prefetcher），一个在 GPU RT unit 内部新增的硬件预取器，完全利用 RT unit 中每个线程已有的遍历栈来生成预取，无需预测地址：(1) DFS 模式——每个线程的遍历栈旁挂一个 2-bit 有限状态机（FSM），监控栈的 push/pop 操作：第一个连续 pop（相对上一次 push）生成 1 个预取（取栈顶节点地址），第二个连续 pop 生成 2 个预取（栈顶 2 个），第三个连续 pop 生成最多 16 个预取（栈顶 16 个）；一次 push 重置 pop streak 并停止预取。因为向上/同层遍历（连续 pop）时"下一个要读的节点"已在栈中，预取地址零推测、100% 确定；(2) BFS 模式——遍历队列 FIFO 时，每次从队头 pop 就同时从队头起预取 N 个节点，N 为固定预取距离（实验 1/2/4，N=4 最优）；(3) 实现细节——warp buffer 中每线程新增 2-bit FSM 字段 + 一个预取指针（指向下一个待预取栈项）+ 比较器（指针到 T−k 停止，k 为预取距离 1/2/16），push 时指针重置回栈顶 T，防止连续 pop 重复预取；也可为每个栈项加 flag bit 记录已预取；(4) 预取请求默认仲裁为 demand read 优先（空闲时发预取），实验也评估了预取优先方案；节点数据大于 32B 时预取请求按 32B sector 块拆开发送，每周期一个。
  - 实验比较：主要指标为 cycles 比（baseline cycles / prefetcher cycles）。对比对象：(1) baseline = Vulkan-sim 默认 RT unit（无预取）；(2) 最先进的 Ray tracing 专用 Treelet prefetcher（MICRO 2023，克隆 ubc-aamodt-group/treelet-prefetching-for-rt 未修改，开启 treelet based traversal + treelet prefetch + keep accepting warps），在 32x32/64x64/128x128 分辨率下对比；(3) Park et al.（2013）的 leaf-node intersection test 期间预取方案（在 Vulkan-sim 中建模复现）；(4) DFS vs BFS 各加/不加 TTP；另有 limit study（perfect upward/downward traversal）、更大 L1（64KB/128KB）、更大 GPU 配置（30 SM/64KB L1/3MB L2）、更高分辨率 256x256 与 AO/SH shader 实验。关键结果：DFS+TTP 平均 1.48x（峰值 1.89x）、功率 1.35x、能量 0.91x（-8.70%）；L1/L2 accuracy 98.92%/89.81%，coverage 31.54%/33.46%，prefetcher efficiency 58.56%/64.85%；L1/L2 RT read MPKI 降 28.28%/40.01%；BFS+N=4 相对 BFS 平均 1.85x/2.05x/2.20x（N=1/2/4），L1/L2 miss 降 44.10%/92.04%，且 BFS+TTP 反超 DFS+TTP（相对 DFS 无 TTP 平均 1.61x）；TTP 在全部场景优于 Treelet（Treelet 128x128 平均仅 1.00x，32x32 为 1.14x vs TTP 1.44x，64x64 为 1.00x vs TTP 1.49x），Treelet DRAM 流量增 1.38x 而 TTP 不变；Park et al. 方案平均仅 1.04x。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - Vulkan-sim 2.0（https://github.com/ubc-aamodt-group/vulkan-sim，论文 https://ieeexplore.ieee.org/document/9923844）：基于 GPGPU-Sim + Mesa（Lavapipe 软件 Vulkan 驱动）的周期级 GPU 架构模拟器，专门模拟 Vulkan ray tracing，每个 SM 内建模专用 RT unit（BVH 遍历 + ray-box/ray-triangle 交点测试）。论文在其上扩展实现 TTP。
  - 论文声称 TTP 修改版开源托管于 github.com/yavuz650/vulkansim（论文原文）；artifact 提供 Docker 镜像 ttp-isca2026-ae:1.0（Zenodo，DOI 10.5281/zenodo.19394324）。联网搜索（2026-08）确认 Vulkan-sim 官方仓库为 ubc-aamodt-group/vulkan-sim（版本 2.0 配合 LumiBench/IISWC 2023 发布），但 yavuz650/vulkansim 的 TTP 分支无法从搜索结果直接验证，以论文声明为准。
  - GPUWattch（https://github.com/accel-sim/gpuwattch，Vulkan-sim 内置）：功率分析。
  - FreePDK45（https://eda.ncsu.edu/freepdk/）：用于综合 2-bit FSM 评估面积开销。
  - 应用/benchmark：RayTracingInVulkan（https://github.com/ubc-aamodt-group/RayTracingInVulkan）+ LumiBench 场景集；BVH 树由开源 Embree（https://www.embree.org/）构建（Vulkan-sim 默认）。
- 模拟器模拟什么的性能，修改了什么。
  - Vulkan-sim 模拟 Vulkan ray tracing 管线在 GPU 上的周期级行为：从 RayTracer 应用发起 trace ray 指令，到 RT unit 执行 BVH 遍历（per-thread 遍历栈 push/pop、内存请求 coalescing、L1/L2/DRAM 访存、ray-box/ray-triangle 交点测试），统计总 cycle 数、cache miss（MPKI）、MSHR 状态、DRAM 带宽、GPUWattch 功率/能量等。修改点：在 RT unit 的 warp buffer 中新增每线程 2-bit TTP FSM 字段、预取指针、比较器与预取请求发送/仲裁逻辑（demand 优先，可选 prefetch 优先阈值 25/50/100 cycles），以及 BFS 队列预取逻辑；预取按 32B sector 拆块发送（匹配 sector cache 模型）。
  - 硬件配置（表 III）：8 SM，最大 16 TB/SM，warp 32；指令缓存 128KB/20 cycles；L1D 32KB 全相联 LRU 20 cycles 256 MSHR；L2 512KB 16-way LRU 160 cycles 768 MSHR；core/interconnect/L2 时钟 1365 MHz，内存时钟 3500 MHz；每 SM 1 个 RT unit，RT unit warp buffer 4。额外配置：30 SM + 64KB L1 + 3MB L2（鲁棒性验证）。

  - 使用例子（输入到性能输出的全过程）：① 环境——docker load < ttp-isca2026-ae.tar.gz；docker run -it ttp-isca2026-ae:1.0；② 启动模拟——cd /home/root/vulkan-sim-root && source init_vars.sh；cd RayTracingInVulkan/build/linux/bin；./RayTracer --scene 20 --width 32 --height 32 --samples 1 > ship_pt.log（--scene 选 LumiBench 场景、--width/--height 分辨率、--samples 每像素采样数，128x128、1 sample 为默认）；③ 模拟原理——RayTracer 经 Mesa/Lavapipe 驱动把 Vulkan RT 指令（trace ray）转发到 Vulkan-sim 的 GPGPU-Sim 核心，核心按 8 SM × 每 SM 1 RT unit 的配置周期级推进：RT unit 维护 per-thread 遍历栈，从 L1D（32KB/20 cyc）读 BVH 节点（Embree 构建的树），miss 后经 L2（512KB/160 cyc）到 DRAM（3500 MHz），RT unit 用固定功能单元做 ray-box/ray-triangle 测试并按结果 push/pop 栈；TTP 的 FSM 在 pop 序列上生成预取请求（拆 32B sector 块），经仲裁插入访存队列提前隐藏 100-300 cycles 的 miss 延迟；④ 输出——模拟结束得到总 cycle 数（性能=baseline cycles/TTP cycles）、L1/L2 miss 计数与 MPKI、DRAM 读/写回计数、GPUWattch 功率/能量；⑤ 出图——python3 figure1.py（及其他 figure 脚本）读 ttp_raw_simulation_logs 下的原始日志生成论文图；仿真总耗时约一周（并行）；park 场景 128x128 下 72h 超时改为 64x64 运行，chsnt 在 Treelet 下崩溃故排除。
