## Omni-LUT Energy-Efficient LUT-based Accelerator with Hardware-Aware KV Cache Quantization

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 Omni-LUT LUT-based GEMM 加速器（ISCA 2026，NYCU，软硬件协同），把高效低位 LUT 执行从 AW-GEMM（linear 层 weight×activation）扩展到 AA-GEMM（attention 的 QK^T 与 Attn×V，两个操作数均为运行时激活）。片上结构（Fig. 5）：on-chip unified buffer（激活）、weight buffer、LGU（Scale-aware LUT Generation Unit）、32×4 PE array（systolic，可重构 1D）、accumulator、BQU（Binary-coding Quantization Unit）。关键模块：(1) LGU 两段流水（Fig. 8）——scaling stage 用 4 个 FP 乘法器把 4-element 激活组内每个激活乘其 row-wise（row-/channel-/token-specific）缩放因子，table generation stage 用 reuse-oriented 加法/减法网络（6 加 6 减）生成 8 个基础条目（half-LUT [T-MAC]，PE 用符号对称补全），并内嵌 zero-point 补偿（首 bit-plane 算激活组×per-row zero-point 向量的点积加到每个表项），与 PE 并行生成、不 stall——解决 post-lookup 单一 scale 只支持 column-wise 方向、而 Weights/Keys/Values 精度最优方向均为 row-wise 的问题；(2) BQU（Fig. 6）——TSE（Token-Scale Estimator，pipelined reduction tree 并行求 x_min/x_max → zp_v/δ_v）+ BEA（BCQ Encoder Array，贪心残差编码 x≈zp+Σα_i⊙B_i），Key path 用离线 per-channel 参数、Value path 用在线 per-token 参数，BQU 宽度 128 匹配最大 head dimension（OPT/LLaMA2/LLaMA3/Mistral/Mixtral/Qwen3），一个 head 向量一次量化完成、不增加 cycle；(3) hybrid-stationary systolic array——WS（weight-stationary，prefill：权重存本地寄存器、psum 沿 systolic 链传播）与 OS-V（GEMV-optimized output-stationary，decode：LUT broadcast 到全部 M 行 + 每行独立并行 Weight FIFO 绕过垂直 PE-to-PE 权重路径 + psum 本地累加，全阵列 GEMV 并行），PE 微架构（Fig. 9）由 mode register 控制，WS/OS-V 切换 1 cycle（每 query 在 prefill/decode 边界切一次，延迟可忽略）；每个 PE 含 4 激活组 LUT、32 个 binary weight 同时 Read-and-Accumulate（参考 FIGLUT [52]）。实验比较：能量分解（DRAM/SRAM/compute）、能效 TOPS/W、面积效率 TOPS/mm²、端到端 latency/energy，对比 FPE（W16A16KV16 FP baseline，64×64）、FIGLUT（W4A16KV16，LUT 只做 AW、AA 回退 FPE FP 后端）、Tender（W8A8KV8 纯 INT8 multi-scale systolic，64×64，1-bit intra-PE shifter 动态 psum 重缩放）、Omni-LUT-KV4（W4A16KV4）与 Omni-LUT-KV3（W4A16KV3）。结果：等峰值吞吐下能效比 FIGLUT 高 1.25×-1.91×；8192 output tokens（decode 主导）下总能量比 FPE/Tender/FIGLUT 低 59%/54%/46%；8192 input tokens（长上下文）下低 50%/32%/38%（每 query 绝对省 170/109/129 J）；有效 GEMM 吞吐 1.78 TOPS vs FIGLUT 0.96 TOPS；面积效率比 FPE 高 2.8×-3.9×。
  - 硬件配置（Table I，500 MHz，TSMC 7nm，等峰值吞吐对比）：FPE 64×64、4.1 TOPS、0.64 mm²；Tender-int8 64×64、4.1 TOPS、0.20 mm²；FIGLUT 32×4、4.1 TOPS、0.39 mm²（仅 LUT core）/1.03 mm²（含 AA 所需 FPE FP 后端）；Omni-LUT-KV4 32×4、4.1 TOPS、0.53 mm²；Omni-LUT-KV3 32×4、4.1（AW）/5.46（AA）TOPS、0.53 mm²。Compute power（Table VI）：Omni-LUT 1.65 W（prefill WS）/1.83 W（decode OS-V）；FIGLUT 1.5 W（AW LUT core）/1.75 W（AA FPE 后端）。compute core 分解（Table VII，OPT-6.7B 8192/512）：LUT PE Array 0.459 mm²/86.34% 面积、57.68 J/90.09% 能量；LGU 0.017 mm²/3.11%、3.43 J/5.36%；BQU 0.014 mm²/2.63%、0.16 J/0.25%；FIFOs 0.030 mm²/5.55%、2.48 J/3.87%；Control 0.013 mm²/2.37%、0.27 J/0.43%；合计 0.532 mm²/64.02 J。数据流分析（Fig. 10，OPT-6.7B 4096 in/512 out）：prefill GEMM 主导下 LUT WS 吞吐比 OS 高 1.3×；decode 下 OS-V 比 OS/WS 高 1.49×/1.68×，故采用 hybrid。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 论文未采用现成开源模拟器，自建 calibrated latency/energy model + roofline-style performance model（同时计 compute time 与 DRAM access time）。参数来源：所有单元用 Synopsys Design Compiler 综合（TSMC 7nm，500 MHz）得面积报告；Synopsys PrimeTime PX 估功耗；用 Synopsys VCS 对真实推理张量实例化的 kernel 做门级仿真得 cycle 数与 switching activity，注解到功耗工具估 per-kernel energy，测量结果用于参数化模拟器；片上 buffer 用同工艺 SRAM macro；片外 DRAM 能量用 DRAMPower（开源，http://www.drampower.info）配置 LPDDR5 设备（51.2 GB/s peak）。FlashAttention（https://github.com/Dao-AILab/flash-attention）算法用于模拟 realistic serving：中间 attention 矩阵不物化到 DRAM，attention 以 tile 256 流式分块计算。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 LLM 推理（prefill/decode 两阶段、batch size=1 edge-serving）的 GEMM kernel latency/energy 与 KV cache 内存流量，两个 scope：(i) kernel-level——只关注 GEMM kernel 与相关 KV cache 内存流量（Omni-LUT 的主要目标）；(ii) system-level——额外包含在公共 VPU（vector processing unit，所有设计相同）上执行的 non-GEMM 算子（Softmax、LayerNorm、RoPE），输出端到端总推理延迟与总推理能量。roofline 模型同时计 compute time 与 DRAM access time；FlashAttention 以 tiled streaming（tile 256）计算 attention，中间矩阵不落地 DRAM。
