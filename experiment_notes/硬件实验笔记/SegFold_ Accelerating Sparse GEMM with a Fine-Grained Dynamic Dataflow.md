## SegFold: Accelerating Sparse GEMM with a Fine-Grained Dynamic Dataflow

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 SegFold：面向广义稀疏矩阵乘（SpGEMM，双端稀疏、非结构化稀疏）的专用加速器，其核心是一个新型动态数据流 Segment，由两条动态机制组成：(1) SELECTA——动态调度：内存控制器维护一个覆盖 K 维的 active window（默认 32 个 k 值），逐周期扫描 A 的列主序 bitmask 元数据，贪心选择 (m,k) 对（Algorithm 1）：优先选取共享同一 k 的 m（最大化 B 行复用），同时避免同 m 不同 k 的对（防止 C 行约简冲突），并在窗口内把已完成全部交集的 k 退休、补入新 k（inter-tile 滑窗 + intra-tile mk-dynamic 重排序）；(2) SEGMENTBC——动态映射：把 B 元素按列索引注入一个虚拟坐标空间 V=X×Y（行饱和、列有序、时升），通过自适应 merge network（每个 PE 一个 merger，比较 b 与 c 决定转发/插入/累加，Fig.6）在片内即时定位/创建 C 部分和位置，并按注入点 ft_in（由 Index-to-PE Mapper，IPM，树形 LUT 二叉搜索，Fig.7）到最终位置 ft_out 的位移作为 segment，动态在 PE 间重分配部分和以平衡负载。配套机制：folding——空间折叠（PE router 按 {右,上,下,左} 优先级把超长虚拟 C 行折到相邻 PE 行）与时间折叠（PE 行 spad 溢出存储、提前完成的 partial sum 卸入 spad 腾出 PE）；hybrid interconnect（PE 级 mesh + 每 PE 行 row shifter + 跨行 vector multicast network，4 路 B 行/cycle 的向量化 crossbar）。矩阵 A 列主序、B 行主序（DCSR + 每活动行 start pointer）、只存非零，内存控制器带 coalescing unit。
  - 实验比较：(1) Spada [24]（runtime-adaptive，window-adaptive dataflow，直接使用其开源模拟器 spada-sim 作 baseline；非方阵实验加同一 Ramulator2 HBM2 后端）；(2) Flexagon [28]（reconfigurable 多数据流加速器，用开源 STONNE 模拟器建模 + 同一 Ramulator 内存后端；原为 1D 128-PE，扩展到 2D 2×128 PEs、复制片上 cache、共享 offchip DRAM、按 M 维 tiling 分配）。主指标：simulated cycles 与加速比。结果：SuiteSparse 15 矩阵上 geomean 1.95× over Spada、5.3× over 最佳 Flexagon 配置；高度稀疏矩阵 1.08×–5.75× over Spada（唯一例外 ca-GrQc 0.59×，无标度图极密行压垮 per-row PE 分配）；非方阵 tall 矩阵 1.42× geomean over Spada，wide 矩阵因 K 不 tile 而落后（换乘向可恢复 2.4–3.0×）；消融：固定 k 序→性能降至 0.670±0.065（动态调度重要），LUT 映射 vs Zero-Offset 1.20× geomean、vs 理想 oracle 仅 1.2% 平均开销，增量消融 3.1× geomean over base（SELECTA 贡献最大）；RTL 综合（ASAP7 7nm）总面积 0.160 mm²、功耗 385.7 mW（28nm 估计 ~1.35 mm²/~2.3 W，与 Flexagon 1.35mm²/856mW 可比）。
- 硬件平台是什么，配置是什么。
  - 16×16 2D PE 阵列，1 GHz 时序收敛；每 PE 含 ALU、匹配未消费 B 值 FIFO、四口 router（任一时刻仅一个方向激活）；每 PE 行独立硬件：row shifter、spad bank、IPM LUT bank；active B window 大小 32；片上 cache 1.5 MiB、16-way、128 B 行；offchip HBM2-8Gb @ 2 Gbps（Ramulator2 建模，逐周期）；vector multicast 带宽 4 B 行/cycle；IPM 二叉搜索 O(log P)（P=每行 PE 数），merge network 最坏 O(P) 位移；面积/功耗用 Design Compiler + compile_ultra、ASAP7 7nm 标准单元库综合，2D mesh 综合单个 PE/switch/FIFO 再 ×256 缩放，spad 按 bank ×16 行，内存控制器单独综合。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - csegfold：论文自研 cycle-accurate C++ 模拟器，精确建模 SegFold 微架构与动态数据流（SELECTA 调度、merge network、IPM、folding、memory controller），通过 CMake FetchContent 自动拉取 Ramulator2 作为 DRAM 后端。开源（https://github.com/PolyArch/SegFold-AE，Zenodo DOI https://doi.org/10.5281/zenodo.19453259，MIT）。
  - Ramulator2（https://github.com/CMU-SAFARI/ramulator2）：cycle-accurate、模块化 DRAM 模拟器（IEEE CAL 2023），配置 HBM2 @ 2 Gbps 模拟 offchip 内存，集成进 csegfold 与 Spada（非方阵实验）内存后端。
  - STONNE（https://github.com/stonne-simulator/stonne）：Flexagon baseline 的片上组件建模模拟器（Cycle-level DNN 引擎模拟，支持 SpGEMM/SparseDense、MK/KN stationary dataflow），与同一 Ramulator 后端集成。
  - spada-sim（https://github.com/MachineLearningSystem/spada-sim，原 tsinghua-ideal/spada-sim）：Spada 官方开源模拟器，论文"使用其开源模拟器不变"作为 baseline（非方阵实验时接入同一 Ramulator2 HBM2）。
  - 综合工具：Synopsys Design Compiler（compile_ultra 时序驱动优化）+ ASAP7 7nm PDK（https://github.com/The-OpenROAD-Project/asap7 类 7nm 标准单元库）。
- 模拟器模拟什么的性能，修改了什么。
  - csegfold 模拟 SegFold 微架构在 SpGEMM 执行中的逐周期行为：SELECTA 的 active-window 扫描与 (m,k) 选择、B 行经 vector multicast + row shifter 分发、merge network 中每个 B 元素的比较/转发/插入/累加与 segment 位移、IPM 二叉搜索映射与 LUT 更新（写端口受限排队，可能把元素映射到真实最右合法点左侧但正确）、空间/时间 folding、片上 cache 与 HBM2 访存、tiling（M/N 维静态 tile，K 不 tile）。输出：simulated cycles（每矩阵、每配置），换算为相对 Spada/Flexagon 的 speedup；能量/面积来自 RTL 综合而非模拟器。修改点：整机为新实现；Ramulator2 仅配置 HBM2-8Gb 2Gbps 参数并接入；STONNE/spada-sim 未修改本体（Spada 仅非方阵时换内存后端）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：完整 artifact 开源（GitHub https://github.com/PolyArch/SegFold-AE + Zenodo 10.5281/zenodo.19453259，MIT）。硬件依赖：CPU ≥4 核（推荐 16+）、RAM ≥64 GB（推荐 256 GB，breakdown/mapping 消融单进程可到 50 GB）、磁盘 2–5 GB；软件：Ubuntu 22.04+、GCC 10+（C++20）、CMake ≥3.15、Python ≥3.8（numpy/scipy/matplotlib/pandas/pyyaml），可选 Docker；数据集：~20 个 SuiteSparse 矩阵（~50MB，下载脚本自动获取，https://sparse.tamu.edu/）+ 运行时生成的合成矩阵。实验规模：209 个仿真 run，16 核约 2 小时。
  - 使用例子（基于 AE 仓库）：① `cmake -B build && cmake --build build -j` 编译 csegfold（Ramulator2 经 FetchContent 自动拉取）；② 下载 SuiteSparse 矩阵（15 矩阵 baseline 套件 + 消融子集）；③ 运行主实验生成 fig8/9/10/11/12 对应的 per-experiment CSV（fig8_overall_results.csv 等），`scripts/collect_results.py` 汇总；④ 运行 window size（1,4,8,16,32,64）与 crossbar width（1,2,4,8,16）敏感性 sweep 及 K-reordering 消融（tab4_k_reordering_results.csv）；⑤ plot_overall.py/plot_nonsquare.py/plot_breakdown.py/plot_ablation.py 生成 PDF/PNG 图（Fig.8–12）；⑥ 用 Design Compiler + ASAP7 综合 RTL 得 Table IV 面积/功耗/时序。
  - 模拟原理与输入到输出全过程：csegfold 以稀疏矩阵（SuiteSparse MatrixMarket + 合成矩阵，密度 0.05–1.0、尺寸 256–1024 或真实规模）+ 硬件配置（Table II：16×16 PE、window 32、cache 1.5MiB、HBM2）为输入 → 内存控制器逐周期跑 SELECTA：扫描 A bitmask active window 贪心选 (m,k) 对 → B 行经 vector multicast（≤4 行/cycle）与 row shifter 注入各 PE 行 → 每个 B 元素进 merge network：IPM 二叉搜索定注入点，merger 比较 b/c 决定转发（b>c）、右移插入（b<c）、累加（b=c），C 部分和驻留 PE 或折叠/溢出到 spad，spill 回 spad/重注入 → Ramulator2 对 HBM2 请求逐周期计时（bank/row 冲突、带宽）→ 输出每矩阵 cycle 计数与访存统计 → 相对 Spada/Flexagon 归一化得 speedup → 绘图；RTL 侧：SystemVerilog RTL → Design Compiler compile_ultra → ASAP7 7nm 综合报告（面积/功耗/1GHz 时序）。
