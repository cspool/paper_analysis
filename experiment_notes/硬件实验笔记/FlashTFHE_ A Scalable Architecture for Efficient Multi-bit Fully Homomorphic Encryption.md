## FlashTFHE: A Scalable Architecture for Efficient Multi-bit Fully Homomorphic Encryption

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为面向 multi-bit TFHE（FHE over Torus）的 ASIC 加速器 FlashTFHE，核心创新是 temporal（时间域）round-robin key-reuse 数据复用策略：不再像空间架构那样把整个 BSK 一次性流式扫过 PE 阵列，而是外层循环每次只从 DRAM 载入一个 BSK chunk（≤0.8 MB chip-wide）到片内 SRAM，在所有并行 bootstrapping（round-robin 调度，最多 48 个 ciphertext）间时间复用后再驱逐，从而把计算吞吐与 DRAM 带宽解耦。架构为 4 个 vector-core 型 compute core，每 core 含两个专用功能单元：(1) Blind-rotation Unit（BRU）——单片宽深流水线执行 external product（GGSW □ GLWE），单 core MAC 吞吐 512 coefficients/cycle（为同带宽下空间架构的 8×），采用 48-bit 定点复数数据通路（保证 TFHE-rs 与 Concrete Optimizer 全部参数集正确性），两个 BRU 共享一个 I-FFT（FFT:I-FFT 操作数比约为 l_b:1）；BRU 内部署异构混合基双实数 FFT 集群——FFT-A（256-point，对称设计）与 FFT-B（128-point，非对称、拆成 4×32-point 再拆 8-point tile）经 transpose 单元互联，支持多项式最高 2^16 度（10-bit ciphertext、128-bit 安全）；(2) LWE Processing Unit（LPU）——8-lane 向量引擎（每 lane 32 个 64-bit 值，可独立寻址/独立时钟门控），执行 key-switching、sample extraction 与 LWE-native 元素级运算，64-bit 宽度匹配 2^64 torus modulus。内存子系统为层级片内存储：core 共享 global buffer（存 BSK/KSK chunk，经 NoC 分发）+ per-core private buffer（BRU 独占的 GLWE accumulator buffer，复数类型，9.2MB；BRU/LPU 共享的 GLWE/LWE buffer），总片内 SRAM 45MB；顺序访问模式用 16KB read/store FIFO 隐藏 DRAM 延迟。配套编译器（Section V）与 Concrete 工具链集成，实现 KS-dedup（key-switching 结果复用给多个 blind rotation，最多省 47.12% key-switching 操作）与 ACC-dedup（共享 GLWE accumulator，存储减少 91.54%）两级去重及 adaptive batching。
  - 实验比较对象：CPU（AMD EPYC 7R13，48 Zen3 核 3.4GHz，256GB DDR4-3200；高带宽对照组双 AMD EPYC 9654 921.6GB/s）、GPU（双 NVIDIA RTX A5000）、以及既有 TFHE ASIC 加速器 Morphling（HPCA'24）、Strix（MICRO'23）、MATCHA（DAC'22）、Matrix、Trinity 与 UFC（混合 CKKS/TFHE）。主结果：相对 CPU 最高 2529×、相对 GPU 最高 1320×、相对 Morphling（扩展至 multi-bit 的 Morphling'）约 7× 加速；单 ciphertext bootstrapping 延迟 6.16–34.67ms（高 bit-width）与 0.28/0.85ms（CNN-20/50 单 batch）；KNN 经 adaptive batching 端到端延迟降低 41.7%、利用率 32.7%→56.2%。还与 Trinity/Trinity'（把 NTT 换成 FFT 的 TFHE 定制版）比较 per-area 性能，FlashTFHE 在面积仅 Trinity 26.3% 下性能相当或更好；消融实验（Fig.20）按 temporal 设计→异构 FFT→adaptive batching→两级去重逐步叠加，量化 delay/EDP/EDAP 改善。
- 硬件平台是什么，配置是什么。
  - RTL 用 Chisel HDL 实现，功能单元 RTL 正确性在 Xilinx Virtex VU47P FPGA（Beethoven 框架）上验证；Chisel 编译为 Verilog 后用 Synopsys Design Compiler 在 TSMC N16（16nm）综合，目标 1GHz（所有 worst-case negative slack 0.00ns）。片内 scratchpad 用 Arm Artisan physical IP compiler 建模，activity factor 取 worst-case 参数集。总面积 108.08 mm²（16nm）、总功耗 132.98W，核心组（Core Group）52.40mm²/65.65W，其中 BRU 11.01mm²/22.29W、Acc buffer（9.2MB）9.83mm²/3.11W、2×FFT-A 1.57mm²/2.95W、FFT-B 1.88mm²/4.12W、I-FFT 4.25mm²/12.59W、VecMAC 4.27mm²/8.41W、LPU 1.32mm²/0.61W。默认 4 core/16nm；8 core 时两栈 HBM2E 仍满足带宽。对比表中 Trinity/UFC 为 7nm（16nm 归一后 411.81/637.74mm²），Strix 28nm、Morphling 28nm、MATCHA 16nm。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 性能评估用自研 cycle-accurate simulator（基于已验证的 Chisel 实现构建），论文未给开源链接；片外内存用 DRAMSim3（https://github.com/CMU-SAFARI/DRAMSim3，开源 cycle-accurate DRAM 模拟器）模拟两栈 HBM2E（819GB/s 带宽，对比 Trinity 时按其报告校准，吞吐差异 <0.1%）。对 Morphling 的对比实现为把 R2MDC FFT 扩展到 multi-bit 参数集的 Morphling' 变体（仿真验证 key-switching 非瓶颈）；对 Trinity 另开发 cycle-accurate simulator 并校准到其报告数值。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟器模拟完整 TFHE 程序（bootstrapping + key-switching + LWE-native 运算）在 FlashTFHE 上的 wall-clock 执行时间、硬件利用率、DRAM 带宽需求（BSK/KSK/GLWE/LWE 流）与 buffer 大小，覆盖从 4-core 到 8-core 扩展、round-robin ciphertext 数量（最优 12）、accumulator buffer 大小（9216KB 临界点，低于则 swap 到 DRAM 停顿流水线）等设计空间探索，并验证 key-switching-first 与 blind-rotation-first 顺序对数据复用的影响。DRAMSim3 模拟两栈 HBM2E 的时序/带宽行为；模拟器相对 CPU/GPU 基准（TFHE-rs/Concrete 工具链实跑）报告 speedup。相对基座模拟器的修改：论文未明确说明模拟器是否为某开源模拟器修改版；关键建模为 temporal round-robin 调度、BSK chunk 复用、BRU/LPU 流水线与 48-bit 定点数据通路、lane-partitioned adaptive batching。

  - 模拟原理与输入→输出全过程（一次 Decision Tree 的 9-bit PBS）：输入 = (a) 电路级参数（Table II 参数集，如 n=1070、l_b=8、N=65536、k=1，Lattice Estimator 保证 128-bit 安全与 p_err≤2^-14）+ (b) Concrete Compiler 从 MLIR FHELinAlg dialect 展开后的指令流（per-ciphertext primitives、batch 分组与依赖关系、adaptive batch size、lane masking 配置）+ (c) 每 BSK/KSK chunk 从两栈 HBM2E 的访存 trace。模拟推进：外层循环逐 BSK chunk 载入（≤0.8MB，芯片级）→ BRU 内 round-robin 遍历 12–48 个 ciphertext 的 decomp GLWE，FFT-A/FFT-B 流水线每周期产 chunk 输出、与对应 BSK subchunk 在 VecMAC 做 tiled multiply-accumulate 并累计到 9.2MB Acc buffer → (k+1)·l_b 次累计后转发 I-FFT → LPU 的 key-switching/sample extraction 与 BRU 交错，依赖允许时重叠下一 batch → 每周期沿 1GHz 流水线推进并统计 MAC 吞吐、BSK 带宽、buffer 占用；DRAMSim3 提供两栈 HBM2E 的带宽/延迟。输出 = 每 workload 的 wall-clock 时间（Table II，如 Decision Tree 409.19ms vs CPU 645.40s vs GPU 522.2351s）、利用率曲线（Fig.18）、带宽-吞吐-面积 Pareto（Fig.15）、PBS 吞吐/能量对比（Fig.21/23）、相对 Morphling'/Trinity'/CPU/GPU 的 speedup 与 per-area 归一化性能。作用：验证 temporal key reuse 在 multi-bit 参数集（N 至 2^16、key 达数 GB）下的带宽解耦、利用率与面积收益，证明 10-bit ciphertext 可实用化。
