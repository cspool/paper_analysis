## LOONG: Utilizing Long-Stride Reprogramming to Enhance the Performance of SSDs

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 SSD 固件/FTL 层的长跨度重编程（long-stride reprogram）编程机制 LOONG，无任何硬件修改，仅通过固件更新部署。核心：第一步用 pSLC（pseudo-SLC）编程——仅使用最低两个电压态（E、P1），对 block 内全部 1280 个 WL 顺序编程以最大化速度（pSLC 延迟 114 µs/page，接近标准 SLC 96 µs）；第二步用长跨度 reprogram 把整 block 从 E/P1 态统一重编程回 TLC 全 8 态（P1→P7，955 µs/page，接近 OSP 1100 µs），恢复容量。编码实现（coding-based，用标准 OSP）：将用户页补两个 dummy 页组成 3 页组，第一次 OSP 只编码前两个电压态，随后把已存页与新两个用户页组成新 3 页组，第二次 OSP 完成全态重编程。关键物理洞察：通过实验量化 BPD（背景图案依赖）的两个因素——stride 长度与已编程单元电压，发现 programmed cell voltage（channel pinch-off 效应）比 stride 引发的串联电阻更关键（P3→P7 时错误飙升 24576 倍），因此第一步限压到 P1 即可把 stride 推到整 block。FTL 修改：物理页地址 i×3/i×3+1/i×3+2 中 pSLC 只映射 i×3（其余两个 PPN 在 reprogram 时复用）、新增 Reprogrammable Block Pointer（RBP）、每重编程块两个活动指针 pSLC Page Pointer（SP）与 Reprogrammable Page Pointer（RP）、每页 1 bit 标记 reduced-state 编码（决定 MLC 读还是 TLC 读）。
  - 实验比较两组方案 + 一个扩展案例：(1) GC 优化 pSP-GC——vs Baseline（OSP 同 plane 顺序迁移 valid 页）、SP-GC（[38] 用 SLC 加速 valid 页迁移）、HS（Hotness Separation，热度阈值 1 分钟）、8-stride（重编程 + SP-GC，stride 限 8 WL [19]）、pSP-GC（LOONG+SP-GC），各自带/不带 HS；指标含平均延迟、GC 总数、平均 GC 时间、95/99 百分位读写尾延迟、IOPS。结果：pSP-GC 平均延迟较 baseline 降 37.5%（vs SP-GC 降 27.8%，vs HS 降 20.7%），GC 数较 baseline 降约 20%，99 百分位读尾延迟降 20%、写尾延迟降 18%，IOPS 提升 1.8×（最高 2.9×）。(2) 编程优化 TSP-LOONG——vs Baseline（OSP 一次写 3 页）、TSP（两步编程 stride=2 WL）、Midas-Touch [37]（按第一编程步后 invalid 页数选择第二编程策略）、TSP-LOONG；指标为平均写/读延迟。结果：TSP-LOONG 平均写延迟降至 baseline 的 81.3%（TSP 95.1%、Midas 91.4%），读延迟降至 80.4%（TSP 93.1%、Midas 89.7%），平均延迟较 baseline 降 18.1%；invalid 页数较 TSP 增 8.8 倍、较 Midas-Touch 增 3.3 倍。(3) 扩展案例 SLC Caching：LOONG 弹性 SLC 缓存 vs 无 SLC 缓存 vs 传统固定 SLC 缓存（5% 容量），LOONG 版平均延迟降 36.2%（传统 26.1%），写放大最多降 13%。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟 SSD 端到端 I/O 性能：从请求发起到完成的时间（事件驱动天然包含排队延迟与 GC 阻塞时间，为主要指标）、GC 频率与开销（总 GC 次数、页迁移与擦除时间、单次 GC 平均成本）、95/99 百分位读写尾延迟（QoS）、IOPS。SSD 配置（Table IV）：8 通道、每通道 2 chip、每 chip 2 plane、每 plane 278 block、每 block 1280 WL、320 层、页 16 KB、传输率 1.2 GB/s、TLC OSP 写 1.1 ms、SLC 写 96 µs、pSLC 写 114 µs、重编程 955 µs、擦除 3 ms、LSB/CSB/MSB 读 25/50/100 µs。
  - 修改内容：在原版 flash 模拟器上加入 LOONG 相关机制——pSLC 编程操作（延迟 114 µs）、长跨度 reprogram（955 µs，含读取 pre-programmed 数据的开销）、基于实测芯片的程序/重编程延迟作为模拟器参数（确保可靠性导致的延迟开销已被计入）、FTL 修改（RBP/SP/RP 指针、reduced-state 编码 1 bit/页、validity table 检查）、以及两种重编程类型（E/P1→前 5 态 4/7 电压 ≈710 µs，或 E/P1→全 8 态）。无冷数据最坏场景与 GC 不敏感场景也通过修改模拟配置（全热数据、降低 warm-up 比例）评估。

  - 模拟器使用例子与原理：模拟器输入 = I/O workload trace（即真实 SSD 把 host 请求转换为设备命令时的同一输入）。事件驱动引擎按 trace 时间戳推进：一条写请求到达 → SSD 控制器经 FTL 逻辑地址映射为物理页（本论文中 FTL 含 LOONG 扩展：检查 RBP 定位重编程块、SP/RP 指针确定 pSLC 编程或重编程位置）→ 若命中 pSP-GC 重编程块则调度 pSLC 编程（114 µs/页），否则标准 OSP（1100 µs/页）或触发 GC（GC 时 valid 页以 pSLC 迁移 + 冷数据/bg-GC 数据参与 reprogram 恢复容量）→ 控制器按 channel/chip/die/plane 四层并行性派发到闪存阵列，事件驱动模拟器以实测芯片延迟参数累计每个操作的耗时，排队与 GC 阻塞自然计入端到端延迟 → 输出平均延迟、GC 次数/平均成本、95/99 百分位尾延迟、IOPS。示例（PRN_1 一类写密集 workload）：host 写 → pSLC 快速落盘（114 µs）→ 后续数据在第二编程步前被更新而 invalid → reprogram 时该 WL 仅编码前 5 态（E→P4，约 710 µs），较 OSP 全 8 态更快，模拟器据此累计得到 TSP-LOONG 的写/读延迟下降。模拟原理：基于真实 TLC 芯片的延迟/误码参数（含 1K P/E 周期、1 年保留期的 ECC 纠错余量）驱动的事件驱动性能模型，而非 RTL 周期精确仿真。
