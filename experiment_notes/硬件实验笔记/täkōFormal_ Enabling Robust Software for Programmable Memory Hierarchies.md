## täkōFormal: Enabling Robust Software for Programmable Memory Hierarchies

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 täkōFormal（ISCA 2026，University of Michigan）：为 täkō 可编程内存层级（PMH）建立首个 cache-aware 的 ISA 级内存一致性模型（MCM），并构造参数化的 täkō 微架构形式化实现模型（operational model），用机器可检查证明（machine-checked proof）证明"实现模型的所有执行都被 ISA 级 MCM 允许"（soundness）。这是形式化验证论文而非性能/面积评估论文——"实现"是 täkō 硬件的 Dafny 状态机模型 + Alloy 编码的 MCM 公理与 litmus tests，评估指标是证明验证成功与 litmus 测试预期结果一致，而非吞吐/面积/功耗。täkō 硬件本体（tiled chip：每 tile 含 core、L1、私有 L2、共享 L3 bank 分片、运行回调的 engine；用户为虚拟地址范围注册 OnMiss/OnEvict/OnWB 回调，由 cache miss/eviction/writeback 触发；支持无主存背衬的 phantom addresses 与 FlushRange 同步原语）来自原 täkō 论文 [55]（见 REFERENCES），täkōFormal 只做其接口的形式化与验证。
  - 两个组件：(1) ISA 级 MCM——新增事件（Rcb/Wcb/RMWcb=phantom 地址读写、Ms/Me=OnMiss 起止、Es/Ee=OnEvict/OnWB 起止、Fl=FlushRange；E 事件带 dirty bit 区分 OnEvict/OnWB）与新关系（cbo=单地址所有回调事件全序，反映 täkō 对同地址回调的串行化；viscb=phantom 写/OnMiss 结果对 phantom 读/eviction 回调的可见性；vf/ef/eb=OnMiss 结果->phantom 访问、OnMiss 结束->eviction 开始、eviction 结束->FlushRange 等 hb 扩展），以及一组前缀封闭（prefix-closed）公理（VfWf、EbWf、CboWf1/2、CboM/CboE/CboVal、EvDirty/WbDirty、OEInt/OMInt/MeInt/EeInt、OMThd/OEThd、ThdM/ThdE、DirtyWf、VfWf、EfWf、EbWf、Hb、Vis、VisCb、race 定义等，图 6）。(2) 参数化实现模型——在 Dafny 中实现的分层迁移系统：每个 tile 是 Core+L1、Engine+L1、L2、L3 slice 各状态机，加单个 Memory 状态机和 Network 状态机（保存所有 in-flight 消息；coherence 消息无序集合以过近似各种 NoC 设计，engine 回调请求按地址 FIFO）；cache 为 inclusive，用分层 directory-based MSI 一致性协议（上层 L2 为 directory、Core/Engine L1 为子，下层 L3 shard 为 directory、L2 为子，HieraGen 式 proxy L2 桥接两层）；用 environmental transitions 过近似 prefetching/替换策略/回调任意触发；模型参数化于 cache 容量、程序、core 数、地址到 L3 bank 映射、prefetching/replacement/NoC 细节，保证证明对任意参数配置成立。模型支持 Load、Store、RMW、Flush、Branch 指令。
  - 实验比较：① Dafny 机器检查证明（run_dafny_verification.sh）——验证 ISM（中间状态机，构建部分执行图）+ 归纳证明（inductive invariant，119 clauses + 61K LoC 证明注解）+ refinement 证明（operational model 的每条 trace 经 abs() 抽象映射到 ISM 的合法迁移）组成端到端 soundness 证明，证明"对任意程序，operational model 的任何执行都被 ISA MCM 允许"；② Alloy litmus tests（run_alloy_tests.sh）——把图 6 全部公理与论文 litmus tests 编码进 Alloy，逐个确认论文声称的结果：test_paper_ex（图 4a，r1=2,r2=0 forbidden）、test_mp（图 5a，r1=1,r2=0 allowed）、test_mp_rmw/test_mp_rmwcb（图 9a 常规/phantom RMW 同步）、test_icb_sb（图 10a，回调内指令重排 allowed）、test_wbrace（图 11a 无 FlushRange，racy）/test_wbflush（w/ FlushRange，no race，r1=0 forbidden）、test_phir（图 12a w/ OnWB(1)，racy）/test_phinr（w/ OnWB(2)，no race，r1=0,r2=0 forbidden）、test_hatsr（图 13a 无 i9，racy）/test_hatsnr（w/ i9，no race，r1≠r2 forbidden）；③ 案例研究——用 MCM 分析 täkō 的 HATS（Hardware-Accelerated Traversal Scheduling）图处理应用，识别 OnEvict 副作用何时可接受（hatsR racy vs hatsNR race-free，Alloy 大 bound 搜索无 race）。
- 硬件平台是什么，配置是什么。
  - 工具运行平台（artifact 测试环境）：Windows 11 Enterprise 23H2，12th Gen Intel Core i7-1280P 笔记本，32 GB RAM。软件依赖：Dafny 4.11.0（Windows 上需 .NET；Dafny 把性质转成 SMT 查询交给 Z3 验证）、Alloy 6.2.0（需 Java JVM 17+，测试用 JVM 24.0.1）。磁盘 ~180 MB，准备 ~15 分钟，实验 ~1.5 小时。被验证的"硬件"是 täkō 微架构模型本身（上述分层状态机），不是真实芯片。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 无传统性能模拟器（不评估性能/面积/功耗）。验证工具链为：Dafny 4.11.0（https://github.com/dafny-lang/dafny，SMT 引擎 Z3）做机器检查证明；Alloy 6.2.0（https://alloytools.org/，Java 程序分析工具）做 MCM 公理与 litmus tests 的模型检查。täkō 硬件本体参考原 täkō 论文的 closed-source 模拟器（论文未给链接，无法确认）。
- 模拟器模拟什么的性能，修改了什么。
  - Dafny：模拟 täkō 分层状态机（operational model）与 ISM 的合法迁移，机器检查归纳不变量与 refinement 证明，输出所有证明义务验证通过；修改内容即论文主体——Dafny 实现 Core+L1/Engine+L1/L2/L3 slice/Memory/Network 各组件 Next 谓词、环境迁移、MSI 一致性协议与 61K LoC 证明注解。
  - Alloy：模拟 ISA 级 MCM 公理对执行图的约束，对每个 litmus test 搜索满足/违反公理的执行，输出论文声称的 allowed/forbidden/racy 结果（表见 E.-Evaluation-and-expected-results.md）；修改内容为把图 6 的每个公理翻译为 .als 谓词并编码各 litmus test。

  - 开源情况：是。GitHub https://github.com/GenericMonkey/takoFormal（MIT License），归档 DOI https://doi.org/10.5281/zenodo.19444275（v1.1.1），Bash 脚本做 workflow 自动化。安装：装 Dafny 4.11.0 与 Alloy 6.2.0（README 含安装链接与详细说明）；除依赖外无需额外安装，直接用仓库内 bash 脚本验证。
  - 使用例子（输入到输出的全过程）：① 安装 Dafny（Windows 需 .NET）与 Alloy（需 JVM 17+）；② 运行 `run_alloy_tests.sh`——脚本遍历仓库内 litmus test 的 .als 文件（test_paper_ex、test_mp、test_mp_rmw、test_mp_rmwcb、test_icb_sb、test_wbrace、test_wbflush、test_phir、test_phinr、test_hatsr、test_hatsnr），对每个模型执行 Alloy 搜索（给定 bound），确认输出与论文声称的 allowed/forbidden/racy 结果一致并打印到 console；③ 运行 `run_dafny_verification.sh`——脚本验证组成 §VII 端到端证明的全部 Dafny 文件（图 6 每个公理翻译到对应文件的映射在 README 中），Dafny 把证明义务转成 SMT 查询交 Z3，验证脚本成功即证明成立。作用原理：ISA 级 MCM 把 täkō 执行建模为事件（Rcb/Wcb/Ms/Me/Es/Ee/Fl）+ 关系（cbo/viscb/vf/ef/eb/hb）+ 公理（前缀封闭）的执行图，公理约束非法执行（如 phantom 读必须先有 OnMiss、两次 OnMiss 间必须有 eviction、OnEvict/OnWB 与 dirty bit 的对应、FlushRange 与 eviction 的同步语义）；程序员无需理解 täkō 微架构细节，即可用 litmus tests 判断程序某结果是否可达/是否 racy；Dafny operational model 用环境迁移过近似 prefetching/replacement/NoC，经 ISM+归纳+refinement 证明其所有执行都被公理允许，从而验证 MCM 忠实刻画 täkō。
