## DIAMoND Dynamic Inference for Adaptive Edge MoE with Heterogeneous In-NAND and Near-DRAM Compute Architecture

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现：面向边缘 MoE 解码的异构 ASIC（in-NAND 计算模块 + near-DRAM 计算模块经 2.5D 封装集成，Fig.5），RTL/电路部件：① in-NAND die 外围新增 ADC（7-bit，单 ADC 经 buffering + 时分复用共享多 BL）、Shifter、Adder（均堆叠于 NAND die 上方）；INT8 权重 2's complement 存 SLC cell，激活位并行：每 bit 分配到一个 die、权重矩阵跨 8 die 复刻，单次 read cycle 完成 8-bit VMM；② near-DRAM 逻辑 die：4 个 tile（对齐 DRAM 2×2 tile 布局与带宽），每 tile 含 PE 阵列（每 PE 十六个 1×16 MAC 阵列，8-bit VMM，1 GHz 峰值 2 TOPs）+ SRAM I/O buffer + I/O 控制器 + softmax/SiLU 专用单元；③ Dynamic Mask Selector 专用 ASIC（Sec.VI-B）：Priority Queue（专家按路由分数排序入队）+ Conflict FIFO（暂存因冲突被推迟的专家）+ Mask Pattern RAM（专家 ID → 兼容 mask 位向量，如 4'b1001 表示兼容第 1/4 个 mask）+ Pattern State Handler（4 个寄存器跟踪各 Expert Group 可用 mask，512 并行度需 4 个 mask 覆盖全平面）——AES 算法的硬件执行通路；④ QKV-Attention Joint Caching Pipeline：W_Q 放 DRAM、W_K/W_V 留 NAND，Q 投影先出结果让 near-DRAM 提前算 Softmax(QK^T)（K 缓存驻 DRAM）与 NAND 上 K/V 投影重叠，延迟降至多 13.5%。实验比较：(1) 消融 Base/Mask/AES 速度分解（Mask 至多 1.73×、AES 至多 1.52×、合计 1.95×）；(2) 解码速度 vs A100（2.54~10.30×）、Jetson Orin（9.48~208.59×）、Cambricon-LLM（4.97~11.72×）、Lincoln（1.72~5.81×）、3D-AIMC（1.71~3.86×）；(3) 能效 vs Cambricon-LLM（2.39~11.36×）、A100（9.47~146.25×）；(4) 功率/面积：总 149.02mm²，DIAMoND-L 功率仅 0.09× A100、0.61~0.74× Jetson/Cambricon/Lincoln；单 die 功率对比（Fig.17b）。
- 硬件平台是什么，配置是什么。
  - 无真实硬件；模拟对象配置（Tab.I/II）：3D-NAND 64GB、16 dies、每 die 4 planes、页 16kB、tR 30µs、面积 50.51mm²、带宽 9.6GB/s——SSD 包 8 die 垂直堆叠（每 die 256Gb SLC）、2 通道 × 8 die、ONFI 6.0/JESD230G 每通道 4.8GB/s，Control Die 经 TSV（类 HBF）连 8 die 含加法树，die 采用 YMTC 232L QLC 工艺配置；3D-stacked DRAM 1.5GB、4 层、每层 2×2 tiles、每 tile 96MB、3.6W、48mm²、1620GB/s（hybrid bonding + mini-TSV）。RTL：PE、加法单元、mask selector 用 Verilog HDL + Synopsys Design Compiler 28nm 商用 PDK 综合；SRAM buffer 用 CACTI 建模；7-bit ADC 采 [31]（28nm）；softmax/SiLU 单元采 [46][62]。三档配置 DIAMoND-L/M/H = 输入并行度 512/1024/2048（对应每 die 279~1118 GOPS@8bit）。面积/功耗分解（Tab.III）：ADC 0.480mm²/360mW、Shift&Add 0.018/13.93、In-NAND 合计×16 7.968/5982.88、PEs 0.445/269.18、SRAM 1.559/1372.42、SFU 0.025/58.76、Mask Selector 0.006/0.76、Near-DRAM 合计 2.035/1701.12。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 修改的模拟器：SSDsim（开源 SSD 模拟器，HUST 信息存储实验室，官方仓库 https://github.com/jiangyu718/ssdsim；论文引用 [17] Hu et al., MSST 2010）——在其基础上构建 in-NAND 模块的 cycle-accurate 模拟器，注入 D2D 变差/Vth 漂移/ADC 量化噪声的可靠性模型，并按 Tab.I/II 配置 NAND/DRAM 时序与能耗；near-DRAM 模块按 3D-stacked DRAM 配置 [8][40][63] 建模。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 in-NAND/near-DRAM 上 MoE 解码的逐 cycle 时序与能耗。修改：(1) 加 OU（Operation Unit）抽象——H=min{ρ_in,d_min}, W=min{ρ_out,d_min·QB}（ρ_in/ρ_out 为平面硬件可用输入/输出维，d_min 为模型最小矩阵维 4096、QB=8）；Mixtral@512 并行度 → 每 OU 512 TSG × 4096×8 BL、每平面 4×4 OU 阵列；(2) 建模 mask-based 计算：两层 WL 同选（一层权重、一层 mask），利用 NAND string 串接"全导通才成通路"的 AND 特性门控电流（Alg.1 mask 生成：方阵用对角线/反对角线循环模式，矩形先归一化——C<R 补列、C>R 拆多个方阵）；多 WL 激活不改计算结果（电流由 ~1MΩ string 电阻主导）；(3) 建模 Round-Robin + Mask-Guided 子矩阵映射（Alg.2）与基于 List Scheduling 的权重部署（HLS 风格调度：Transformer 数据流图顶点=权重矩阵、边=依赖，按拓扑序贪心逐 cycle 调度，同 cycle 矩阵子矩阵拼接后联合映射，同 plane 专家组成 Expert Group）；(4) 建模 ADC 7-bit 转换、tR=30µs 读时序与平面内所有 BL 通电的能耗假设。输出：tokens/s、tokens/J、功率/面积分解。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：DIAMoND 修改版模拟器与 RTL 未开源（论文无链接，联网未发现仓库，无法确认）；基座 SSDsim 开源（链接如上，C 语言 trace-driven：输入 trace 文件 + page.parameters 配置，`./ssd <tracefile.trace>`，输出 raw/ 目录 gc.dat/io.dat 等统计）。
  - 模拟原理与全过程：输入 = MoE 模型权重矩阵集合 + 路由决策 trace + NAND/DRAM 配置 → 权重分区（d_min=4096、QB=8 分 OU）→ Alg.1 生成 mask（4~64 额外 NAND 层、占 1.7%~27.6% 存储，比 sparse mapping 省 2~4× 存储）→ Alg.2 Round-Robin 轮转分配 + mask 引导放置子矩阵，List Scheduling 调度同 cycle 矩阵联合部署 → 每 token 解码：路由出 top-k 专家 → AES 硬件（Priority Queue/Conflict FIFO/Mask RAM/State Handler）输出无冲突专家组合 → 模拟器按 tR=30µs、输入并行度、ADC 7-bit 转换逐 cycle 累加 in-NAND 计算时间，near-DRAM 并行执行 attention 与 KV cache 管理（QKV Joint Caching Pipeline 重叠）→ 输出 tokens/s（in-NAND 占 76% 工作负载、near-DRAM 24%）与能量。作用：Mixtral-8x7B 197.3 tokens/s、5.8 tokens/J；mask+AES 合计 1.95× 加速；较大模型更受益于并行（等效内存带宽更高）。
