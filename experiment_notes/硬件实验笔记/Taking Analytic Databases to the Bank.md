## Taking Analytic Databases to the Bank

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是面向 OLAP 数据库负载的 BLIMP（Bank-Level In-Memory Processor）PIM 硬件架构评估与参数化仿真：在 DDR4 DRAM bank 内放置 200MHz 通用 RISC-V 处理器（BLIMP-S 标量 RV64GC / BLIMP-V 向量 RV64GCV，后者含 32×64b vALU 向量引擎），核心通过本地 1KB row buffer 访问 32MB bank 数据，512 core 提供约 12.5TBps bank 内带宽；无 bank 间直连，跨 bank 数据移动需 host 读-写中转，DIMM 分 memory mode / compute mode（compute mode 下 host 不能访问该 bank）。实验比较：BLIMP-S 与 BLIMP-V 相对 host CPU（2× Xeon Silver 4114）与 DuckDB 在算子级（select/join/aggregate）与 SSB 端到端上的性能/时延；研究 bank 级并行、row buffer 命中、数据布局（host format vs BLIMP format 软件 relayout，host 侧 29GBps/90GBps 峰值）、物化与 join 顺序等架构-系统交互。
  - 关键数字：select 位图输出 BLIMP-S/BLIMP-V 2.0×/12.9×（低列宽时 BLIMP-S 反降速，因弱核算力占比高）；值输出 2.0×/4.2×；semijoin 1.4×/2.1×、join 2.1×/3.0×（低选择性时 host 哈希表可入 cache 占优，高选择性时 row buffer 切换惩罚 < host cache miss）；非分组 SUM 2.1×/33.7×、分组 1.9×/2.1×；端到端 SSB SF100 相对手调 C++ 基线 1.4×/2.3×、相对 DuckDB 3.1×/5.8×；PIM 感知规划 vs CPU 规划平均 28%（最大 40%）时延差；Q4.1（四维表全 join）中 BLIMP 因就地计算不受 join-in 维度表的 host 传输成本影响而高于平均表现。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 论文使用 validated cycle-level simulators from prior work [25]（ISCA'22 "To PIM or not for emerging general purpose processing in DDR memory systems"，同组）与 [2] riscvovpsim（Imperas RISC-V 指令集模拟器，https://github.com/riscv-ovpsim/imperas-riscv-tests），配合 DRAMSim2（cycle-accurate 内存系统模拟器，https://github.com/umd-memsys/DRAMSim2，论文 ref [66]）的详细 DDR4 timing。同组开源 BLIMP 框架：dovedevic/blimp（https://github.com/dovedevic/blimp，含 /simulation 仿真框架与 /compilation、/relayout、/chronometry、/benchmarks）。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟器模拟 BLIMP 核在 DDR4 bank 内的指令级执行 + DRAM 时序行为：以 cycle 精度推进 200MHz RISC-V 核（RV64GC / RV64GCV 向量扩展）的 fetch/execute/store，1KB row buffer 粒度访存，DDR4 参数 tRP=tRCD=21ns、tRFC=640ns、tREFI=7.8us、16 banks/chip、2 ranks、2 channels、2133 DDR4；每次 offload 只模拟单个 bank 内核执行，假设数据同质、计算对称、总时延=最慢 bank。修改/配置：定义 BLIMP-S（标量）与 BLIMP-V（向量引擎）两种核、1KB row buffer + 32MB subarray 的 bank 组织、512 core 拓扑，以及数据库内核（select/semijoin/join/aggregate）在核上的指令执行路径；host 侧 kernel 不在模拟器中模拟，而在真实 Xeon 硬件上运行。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：riscvovpsim（Imperas）、DRAMSim2、dovedevic/blimp 均开源；本文 DBMS 侧仿真脚本未声明开源（论文未明确说明）。使用例子（结合 dovedevic/blimp 框架的 /simulation 与论文流程）：输入——一个可运行在 BLIMP 上的 kernel 二进制（RISC-V/RISC-V-V 汇编或经 /compilation 交叉编译）、PIMDT 列分区数据、hash 表等辅助数据、DRAM/核参数配置；host 经 /relayout 例程把数据字节 shuffle 到目标 bank（软件 relayout 使硬件地址映射"撤销"软件 shuffle，整字落在单 bank，写入 64-bit 字需 8 次内存写、读取需 8 次读）；模拟器读入配置（2 channel/2 rank/8 chips/rank/16 banks/chip、1KB row buffer、tRP=tRCD=21ns、BLIMP-S 或 BLIMP-V 核）后周期级推进单 bank 执行：每周期取指/执行 RISC-V 指令，访存按 row buffer 命中/切换/预充电/刷新惩罚计周期（参考 DRAMSim2 时序模型），向量指令由 32×64b vALU 并行执行；输出——该 bank 的 cycle 数（=内核性能，系统对称故取最慢 bank）、隐含的访存/row buffer 切换统计；host 侧等价 kernel 在真实 Xeon（AVX512、40 线程）上计时；最终把 relayout（29GBps）、hash build、数据加载、编排、post-processing 叠加得到端到端时延，与 DuckDB 及手调 C++ 基线对比输出加速比。
