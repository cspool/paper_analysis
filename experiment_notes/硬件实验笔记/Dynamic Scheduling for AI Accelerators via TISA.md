## Dynamic Scheduling for AI Accelerators via TISA

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 TISA（Tile-level Instruction Set Architecture）驱动的语义感知动态 tile 调度硬件：在 Epoch AI 加速器每核内集成一个硬件调度器（RTL 实现，随 Epoch 芯片 tape-out 流片），消费编译器产出的 TISA 指令中的 OpType/UnitMap/TileMem 语义字段，对 tensor（Matrix Engine, ME）、vector（Vector Engine, VE）、DMA（Data Engine, DE）三类异构单元做动态重排、冲突消解与跨算子/跨迭代重叠。调度器为五级流水微架构：① Reception 指令解码 → ② 按 OpType/UnitMap 语义路由到各单元的等待队列 WQ（每单元独立语义队列对，防异构单元间无关阻塞）→ ③ 在就绪窗口 W 内对候选与 in-flight 语义表 Fu 做依赖检查（Algorithm 2：不同 scope 跳过；OpType 语义兼容可重叠；内存区间重叠且真依赖且不可安全重排才判冲突）→ ④ 无冲突者从 WQ 提升到 issue queue IQ → ⑤ dispatch IQ 到执行单元。四步协同机制：Semantic Routing / Dependency Resolution / Adaptive Issue / Feedback（完成时退休 Fu 条目、唤醒依赖指令、按观测到的竞争/延迟自适应调整每单元调度优先级）。Fu 条目 = (idx, start_addr, end_addr, access_type, unit, inst_ptr)，即语义化 scoreboard；依赖类型 RAW/WAR/WAW 由 TileMem 区间重叠分析自动导出，condition 字段支持部分就绪（子区域有效即提前唤醒依赖 tile）。指令 run-to-complete、非抢占，调度决策只在 tile 边界做（tile >10³ 运算，控制开销低）。
  - 实验比较：① Epoch 上三配置消融——Naive TISA（仅接口 + fence 手工依赖、无重排）vs TISA+Static（编译期静态软件流水，fence + 重排）vs TISA+Dynamic（硬件调度器），比较执行周期与 Accumulated Overlap Score；② 与 GPU 基线对比：Epoch(TISA) vs A100/H100 上 TensorRT/TensorRT-LLM 端到端延迟；③ FlashAttention-3 硬件利用率：Epoch(TISA BF16，向量:矩阵计算比 1:8/1:16/1:32) vs H100 FA3（1:8），seq 512–16K、带/不带 causal mask；④ 调度器 RTL 综合可扩展性：窗口 W=8/16/32/64/128/256 的 latency/gates/area/power（表 IV）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 非模拟器：Epoch 为 EVAS Intelligence（奕行智能/ESWIN）商用 AI 加速器，1 GHz 已流片硅片（tape-out，W=8），论文全部 Epoch 性能结果在真实硅片上测量。调度器为 RTL 综合评估：7~9 cycles @1GHz 每 tile dispatch；W=8 时 1.5M gates / 0.25 mm² / 100 mW（占每核面积 1.5%）；W=256 时 6.8M gates / 1.13 mm² / 300 mW，面积亚二次方增长（4.5× 面积换 32× 条目）靠对数 CAM 结构 + W≥32 流水仲裁；功耗 <0.3% 核功耗（dispatch 稀疏，~5% slots/cycle）。论文未给出模拟器或 RTL 开源链接。
- 模拟器模拟什么的性能，修改了什么。
  - 非模拟器评估（真硅片周期计数）：Epoch 32 核，每核集成 ME（张量算术）+ VE（元素级/规约）+ DE（DMA 异步搬移）三引擎，每核 1.5 MB 本地存储，片上共享 SRAM 支持核间 tile 复用，NoC 互连，48 GB DDR 与主机共享；峰值 256T FP16、带宽 1 TB/s。硬件修改：ME 增加自定义 block 张量指令、VE 扩展 tile 友好向量指令、DE 暴露 DMA 风格异步非阻塞描述符、每核集成 TISA 硬件调度器（直接读二进制中 TISA 元数据做调度决策，无需软件屏障）。多核执行用编译期空间划分：独立 tile 组（attention head、batch 维）静态分配核，每核本地 TISA 调度器独立运行（各自 Fu），核间同步用共享 SRAM bank 更新触发的轻量 NoC 信号；核间负载均衡在 kernel 调用间由软件做（tile 调度器内不做）。

  - 原理与输入→输出：编译产物二进制嵌入每 tile 的 TISA 描述符（OpType/UnitMap/TileMem/Deps）→ 运行时每 tile 描述符进入 Reception Buffer → 调度器解析语义并按 OpType/UnitMap 路由到对应单元 WQ → 从 WQ 选就绪窗口 W，逐候选与 Fu 做区间重叠 + scope 隔离 + 语义兼容 + 资源可行性检查（Hazard(I,Fu) = ∃r∈Fu: SemanticConflict(I,r)；复杂度 O(U·W·|F|max)，典型 W≤8、|Fu|≤16 时 ≈O(U)/cycle，优于 Tomasulo 的 O(N²) 全局比较）→ 通过者进 IQ，依赖清除即乱序发射（如 S_i 与 M0_{i+1} 并发）→ 完成后退休 Fu、唤醒依赖 tile、反馈调整优先级。作用：消除静态流水（FA3 式 bar.sync）的隐式迭代屏障，实现跨算子、跨迭代紧凑重叠。结果：Epoch 上 Dynamic vs Naive 1.52–1.92×（ResNet50 1.52×/BERT 1.79×/GPT-J 1.74×/LLaMA2 1.92×，表 VI）、vs Static 再高 1.14–1.63×；Accumulated Overlap Score（DM/DV/MV/DMV 累加，表 VII/VIII）Dynamic 达 Naive 的 2.60–32.64×；FA3 对比：head dim 128 主流配置硬件利用率（Achieved GFLOPs/Peak GFLOPs）比 H100 高 26.4%，1:8 匹配比下全序列长高 >10%——且 Epoch 带宽仅 H100 的 1/3.35，证明增益来自调度而非算力。
