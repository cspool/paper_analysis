## TensorPrism: Rethinking Sparse High-order Tensor Acceleration via Co-occurrence Graph

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 TensorPrism，一个基于共现图（Co-occurrence Graph）抽象的高阶稀疏张量收缩（Sparse Tensor Contraction，即 $C_{f_1,f_2}=\sum_c A_{f_1,c}B_{c,f_2}$）专用加速器，含三层核心设计：(1) 共现图表示——把 r 阶稀疏张量变换为加权无向共现图 CoG(V,E)，每个顶点是一个张量索引，边权 $W((i,j))=nnz(A[..;i;..;j;..])$ 编码两个索引在所有非零元素中的共现次数（超边的 pairwise 投影，数学上与超图等价但显式暴露跨模式索引重叠），用于量化输入/输出复用（复用度量式 3：contraction 模式共享顶点 → 输入复用 B[K,:]，free 模式共享顶点 → 输出复用 C[I,J,:]）并作为图划分/数据流优化的理论基础；(2) CoGTP 划分算法——把高阶张量 tiling 重新表述为修改版 Prize-Collecting Steiner Tree (PCST) 问题，目标函数式 6 $\max\{\alpha\sum_i\sum_{e\in P_i}W(e)-\lambda_{cut}\sum_{e_{cross}}W(e)-\lambda_b\sqrt{\sum_i(\sum_{v\in P_i}(D(v)-W/N)^2)}\}$（α=2.0、λ_cut=1.0、λ_b=1.0），BFS 多种子初始化 + 类 Kernighan-Lin 迭代边界单顶点迁移细化（Algorithm 1，每轮复杂度 $O(\sqrt{|V|}d)$，d 通常 1-10），同时优化图内复用、跨图连接代价（cut 惩罚）与负载均衡（按加权度 D(v) 估计工作量，λ_b 惩罚偏斜）；(3) 共现图数据流——按图遍历顺序在 contraction 顶点 PUSH（外积式，把稠密行 B[K,:] 广播到目标顶点集并时间复用）与 free 顶点 PULL（内积式，目标顶点从剩余源顶点拉取特征累加）之间动态切换，同时实现 intra-mode（同维内 push/pull 交替）与 inter-mode（一个 contraction 顶点向不同模式的目标顶点集广播）复用。
  - 硬件架构（Figure 8）：由多 bank 全局缓冲 GLB（2.5MB，1MB 稀疏张量元数据 + 1MB 稠密张量操作数 + 512KB 共现图元数据/中间缓冲）、任务控制器、共现图调度器（CoG Scheduler：权重计算单元 weight computation unit、图生成器 graph generator、成本分析器 cost analyzer + 分区索引缓冲，把划分好的负载/元数据/共现图/稠密操作数分派给 PE 阵列）与 16 个 PE（4×4 mesh 互连）组成，经 DRAM 控制器接片外 HBM2，PE 与 GLB 之间用 crossbar 互连，中央控制单元 + 请求调度器（request dispatcher 编译请求为指令、指令分派器跟踪在途指令、生成 buffer 地址）。每个 PE 内含 8 组取数单元（fetch unit，带 fetch sequencer 把分区索引转成地址流，稠密张量按取数单元分片缓存、跨单元经 ring 网络请求转发）、收缩引擎（contraction engine：feed unit + 寄存器堆（单端口 SRAM + 小 cache）+ 算子控制器 + 8 个 MAC unit，每 MAC unit 8 个 MAC、每引擎 64 MAC、每 PE 512 个 FP32 MAC；feed unit 把同一稀疏输入广播给 8 个 MAC 并连续周期重发实现时间复用，多累加器保存不同部分和）、中间结果缓冲 IR buffer 与提交单元（commit unit + 多维地址生成器 MAG 把张量索引映射到物理地址）。负载均衡两级：CoGTP 目标函数式 6 的 λ_b 静态惩罚 + 算子控制器经 DMUX 把局部 buffer 条目重分配给欠利用的 MAC 单元（运行时动态均衡）。
  - 实验比较：与 5 个 baseline 对比——(1) SPADE（tile 调度 + barrier 同步的 SpMM 加速器，经 matricization 扩展到张量收缩）；(2) HotTiles（稠密/稀疏异构分区的 SpMM 加速器，matricization 扩展）；(3) GSpTC（GPU 端张量原生框架，contraction-mode chunking）；(4) TCP（动态张量划分 + 通信感知 tile 尺寸 + 电路交换取数网络）；(5) HyperSB（基于 KaHyPar 超图划分的算法级 baseline）。全部 baseline 缩放到与 TensorPrism 相同计算资源（8K MAC），各自只实现论文核心算法贡献，归一化硬件参数。指标为端到端执行时间（含张量加载、共现图构建、kernel 执行、结果写回 host）、吞吐量、DRAM 访问、能耗/面积。关键结果：几何平均加速 2.22×/2.40×/1.71×/1.76×/1.49×（vs SPADE/HotTiles/GSpTC/TCP/HyperSB，特征长度 k∈{64,128}、收缩阶 f∈{1,2}）；能耗降 44.6%/42.3%/26.9%/15.7%；片外 DRAM 访问仅为 SPADE/HotTiles/GSpTC/TCP 的 1/2.18/2.11/1.27/1.53（平均片外能耗 47.4% vs TCP 79.1%）；吞吐量平均 2.07×/1.71×/1.55×（vs GSpTC/TCP/SPADE&HotTiles）；复用效率平均 67.86%（比 SPADE/HotTiles/GSpTC/TCP/HyperSB 高 56.5%/57.4%/33.8%/42.6%/23.7%）；轻度稀疏 LLaMA 注意力数据集上最高 2.41×（vs SPADE）。
- 硬件平台是什么，配置是什么。
  - 仿真平台：论文自研 cycle-accurate 模拟器（遵循 [18,49,69] 等既有加速器研究方法论），集成 Ramulator 建模 HBM2（307.2 GB/s 带宽），周期级刻画所有计算、访存与控制组件。TensorPrism 配置：16 个 PE 组成 4×4 mesh，每 PE 一个收缩引擎 512 个 FP32 MAC（总计 8K MAC），工作频率 650 MHz；GLB 2.5MB（1MB 稀疏元数据 + 1MB 稠密操作数 + 512KB 共现图元数据与中间缓冲）；每 PE 48KB 局部存储（寄存器堆 + 累加器）。
  - ASIC 评估：Verilog RTL 用 Synopsys Design Compiler 在 TSMC 28nm 综合；功耗用 Synopsys PrimeTime PX（功耗翻转活动从 post-synthesis 波形提取）；片上 SRAM 能耗与面积用 CACTI 7.0 建模。面积构成（Figure 17）：GLB 占加速器面积 50%、PE 阵列 46.6%；PE 内收缩引擎占 86.2%（其中本地 buffer/寄存器 77.4%、MAC 15.1%）；共现图调度器仅占 1.9%（其中成本分析器占调度器面积 62.9%）。
  - 数据集（FROSTT 真实张量，Table III）：Uber（183×24×1140×1717，3.3M NNZ）、Nips（2482×2862×14036×17，3.1M NNZ）、Nell-1（2902330×2143368×25495389，143.6M NNZ，密度 9.1e-13）、Nell-2（12092×9184×28818，76.9M NNZ）、Flickr（319686×28153045×1607191×731，112.9M NNZ）、LBNL-Networks（1605×4198×1631×4209×868131，1.7M NNZ）、Chicago-Crime（6186×24×77×32，5.3M NNZ）、Amazon-Reviews（4821207×1774269×1805187，1.74B NNZ），阶数 3-5、密度跨 14 个数量级（1e-14 到 1e-2）。另有轻度稀疏 LLM 注意力数据集：LLaMA-8B（batch 2、32 head、seq 512、per-head dim 128）与 LLaMA-2.7B（per-head dim 80）的中间注意力张量，按 SparseGPT 方法幅值剪枝稀疏化为 1%/10%/20% 密度。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟器以周期精度模拟 TensorPrism 加速器执行稀疏张量收缩的完整数据路径：从 host 经 request dispatcher 下发请求 → 指令分派器生成地址/指令 → 共现图调度器（权重计算单元从稀疏张量元数据提取索引共现对、图生成器构造共现图、成本分析器按式 6 评估划分质量、分区索引缓冲存 PE 映射）分派分区 → PE 阵列各取数单元按 fetch sequencer 从 GLB 取共现图条目与稠密行（跨单元经 ring 转发）→ 收缩引擎做标量-向量乘 + 向量累加（feed unit 广播 + 寄存器堆时间复用，8 个 MAC 共享稀疏输入、各收不同稠密输入）→ 提交单元 + MAG 把部分和/结果映射回张量坐标写 GLB → 经 Ramulator 建模的 HBM2 访存。修改点：整套模拟器为论文新构建（非对既有模拟器的修改），仅在访存侧集成 Ramulator；baseline 侧按各自论文算法贡献在归一化硬件参数下实现（SPADE barrier tiling、HotTiles 异构调度、GSpTC chunking、TCP 动态划分、HyperSB KaHyPar 划分）并缩放到 8K MAC。
  - 模拟输出：端到端执行时间（tensor loading + 共现图构建 + kernel 执行 + 结果写回）、吞吐量（feature 128-2048B）、片外 DRAM 访问次数（与理论最小 0.11× 对照）、复用效率、能耗（片外/片上分解）、预处理开销与图存储开销、面积分解。

  - 使用例子（按论文描述从输入到性能输出的全过程）：① 输入——稀疏张量 A 的 COO/CSR 类元数据（如 FROSTT 的 Amazon-Reviews 1.74B NNZ）、稠密张量 B、目标分区数 N=16（PE 数）；② 权重计算单元/图生成器把索引共现对聚合为共现图 CoG(V,E)（|V|=各模式索引数之和，边权为共现次数，用 CSR 存，足迹 $M_{CSR}=(\sum|r|+1)\times4+E\times4$ 字节），并按式 5 的 DRAM 访问模型在 GLB 容量 $M_{cap}$ 约束下确定各模式 tiling 因子（$f_1$ 影响输出 C 存储、c 影响 B 存储、$f_2$ 的 $M_t$ 决定稠密行片上驻留数）；③ CoGTP：BFS 多种子初始化分区 → Kernighan-Lin 式边界单顶点迁移迭代（对每个边界顶点尝试移到邻居所在分区、按式 6 计算 ΔF、保留正增益迁移，直到 ΔF<ε），把高权值边/高度数顶点聚到同分区（如 nel1 上 2KB feature 时 2.95× 加速）；④ 数据流执行——每个 PE 按分区执行：contraction 顶点（如 K0）PUSH 特征到目标顶点集 {I2,J0}/{I0,J0}，即稠密行 B[K0,:] 与稀疏切片 A[J0,:,K0] 逐非零相乘（B[K0,:] 时间复用）、部分积行 C[J0,:,:] 存 IR buffer；沿 I/K 列向遍历后转 PULL（目标顶点从剩余源顶点拉特征，等效 row-wise）；K2 向不同模式的 J1/J2 目标顶点集广播实现 inter-mode 复用；完整子图（clique）对应一个非零张量元素，PUSH 到不同输出地址保证无写冲突（消除 GSpTC 的归约序列化）；⑤ 结果经 commit unit + MAG 写回 GLB → HBM2；⑥ 输出——端到端 cycle 数（加速比 = baseline cycles / TensorPrism cycles）、DRAM 访问统计（Ramulator HBM2 307.2GB/s）、能量（CACTI SRAM 参数 + PrimeTime 翻转活动）→ 得 Fig.9-17 各对比图。作用原理：共现图在划分前统一分析所有张量维度的索引交叠，预测性地把频繁共现索引放同分区，最大化片上复用、最小化跨分区通信与 DRAM 流量，替代 unfold 后 2D 划分（复用距离从 I×J 膨胀到 I+J）与超图划分（不直接优化边数=非零计算量与复用）。
