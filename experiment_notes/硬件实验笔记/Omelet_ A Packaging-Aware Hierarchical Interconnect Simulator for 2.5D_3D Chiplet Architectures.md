## Omelet: A Packaging-Aware Hierarchical Interconnect Simulator for 2.5D/3D Chiplet Architectures

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现：Omelet 是面向 2.5D/3D chiplet 系统的封装感知分层互连周期级模拟器（Georgia Tech，ISCA 2026）。把片内 NoC（Network-on-Chip）、interposer 级 NoI（Network-on-Interposer）与垂直层间 NoL（Network-on-Layer）统一进同一个 flit-level cycle-level 仿真框架（Network-on-X / NoX engine），并给每条链路挂上从 Ansys HFSS 3D 电磁提取 + SPICE 电路仿真得到的物理技术参数元组 ⟨W, t_cyc, E_bit⟩。5 阶段端到端流程：①输入配置（technology library / network configuration / system configuration）→ ②技术感知链路建模（technology lookup table，链路参数来自离线 EM+SPICE 表征）→ ③逻辑放置（Placement Engine，未提供放置时用 force-directed 自动放置，执行 beach-front / 垂直重叠 / TSV 密度 / interposer span 可行性检查）→ ④NoX 网络构建 + 周期级仿真（5 个自动化阶段：系统与节点实例化；放置感知链路构建——按 router 对 x,y,z 坐标判 2.5D lateral 或 3D vertical 连接并打技术标签；技术参数转换 W=floor(λ·R_lane(ℓ)/(f_clk·F_bits))；自动 adapter 插入——检测带宽/频率失配插入 PHY transition + SerDes 序列化 + CDC 1 cycle 开销；路由合成——按连接链路最低带宽 dimension router、按 delay-bandwidth product 自动配置 buffer 深度、传播 turn prohibition 等路由约束）→ ⑤DSE 引擎（穷举 ≤10³ 点，更大空间用模拟退火；输出 Pareto 最优设计集 + 瓶颈归因 latency breakdown）。论文明确：集成修改 gem5 的 Garnet NoC 模拟器（gem5 v21.1），将其周期级仿真扩展为异构、层次化、封装感知的 2.5D/3D 互连。
  - 实验比较什么：①隔离 vs 统一层次建模（4 种配置：isolated/tech-agnostic XX、isolated/tech-aware XO、unified/tech-agnostic OX、unified/tech-aware OO，7 种 interposer 拓扑 × shuffle 流量）：unified 与 isolated 无一致偏移/缩放关系，load-latency 曲线斜率和饱和行为都不同；isolated 因 NoC/NoI 各自独立累积最坏 pipeline/队列行为而更早饱和；tech-agnostic 低估端到端延迟平均 32.9K cycles（比 Omelet 低 53.5%），且过度估计可持续吞吐；cross-layer path diversity（mesh/cmesh 的多横向路径可在拥塞垂直接口前重路由）只能由 unified 模型捕获；②interposer 材料（silicon 0.5µm L/S vs organic 2µm L/S）：硅零负载延迟更高（intrinsic link delay 大）但布线密度高 → 高注入率 shuffle 下反而更低延迟（平均差 40.9K cycles）；能量比较 intrinsic EPB vs traffic-activated energy——mesh per-link 最省但激活大量短链路致总能耗高，Kite 家族集中到少数长距离路径反而网络总能耗低；③bonding 技术（solder ball 30µm、µbump 10µm、Cu-Cu TCB 5µm、hybrid bond 1µm）：更高密度 bonding 在低负载下因固定边界适配/打包开销反而零负载延迟更高，深饱和下靠更宽 NoI 链路提高边界端口 service rate 缓解延迟增长（Takeaway 4）；④3D stacking（2-tier 8 chiplet、3-tier 12 chiplet）：垂直链路快但跨 stack 流量仍共享 interposer，interposer 链路/路由器成全局吞吐限制器（Takeaway 5）；⑤DSE：7 拓扑 × 2.5D/3D × 硅/有机的 Pareto 分析（Fig.13），拓扑最优性随封装技术改变（硅下 mesh 优、有机下 DoubleButterfly/Kite 优）。
- 硬件平台是什么，配置是什么。
  - 评估主机：Red Hat Enterprise Linux 7.9、64 核 Intel Xeon Gold 6226R、502 GiB RAM；gem5 v21.1，每次运行分配单 CPU 核。被模拟系统（Table III）：chiplet 数 1/4/8/12、每 chiplet 16 核（4×4 grid）、stacking depth 1(2.5D)/2/3、2×2 chiplet grid 基线（参照 Intel Sapphire Rapids 4 chiplet、AMD MI250X、AMD MI300/EPYC 8–12 chiplet）；router pipeline 4 级、VC 4；NoC 2D Mesh、link latency 1 cycle、link width 16B、NoC unit latency 10/50/100 ps/mm；NoI/NoL 拓扑 mesh/cmesh/dblbut/butdon/Kite-S/M/L、link width tech-aware；router-to-router pitch 1mm（由 Kite 原 2.2mm 缩放以保证 7 拓扑封装可行）；技术：silicon interposer 0.5µm L/S、organic 2µm L/S；bonding solder ball 30µm / µbump 10µm / Cu-Cu TCB 5µm / hybrid bond 1µm；TSV pitch=same as bond、AR=15；µVia pitch=same as bond、diam=pitch/2；dielectric oxide 1µm / polyimide 6µm；wire 0.5–5mm；clock 3GHz；流量 uniform random/shuffle/transpose/tornado/neighbor；NoC router 4 flits/VC 缓冲、NoI router 8 flits/VC（PHY/credit 往返更长）。运行时间：单 chiplet 2D NoC 14.2s、4 chiplet NoC+NoI 96.4s、8 chiplet（NoC+NoI+NoL）428.7s、12 chiplet 1216.5s；技术感知链路建模离线完成，运行时占比 ≤0.011%。

- 模拟器模拟什么的性能，修改了什么。
  - Garnet 模拟 flit-level 片上网络性能：packet 逐周期经 router（routing、arbitration、buffering、serialization、link traversal），输出平均 flit latency、峰值吞吐、per-link utilization、每链路 EPB 与 traffic-activated energy、crossing overhead。Omelet 修改：把单一 on-chip 网络扩展为 NoC/NoI/NoL 三层异构层次化网络图——放置感知链路构建（按 router 对 x,y 坐标 + z 层号判断 2.5D lateral / 3D vertical 连接并分配技术标签，如 on-die wire / interposer RDL / vertical TSV）；技术参数转换（物理 Gb/s、ps、pJ/bit → 架构参数 ⟨W flits/cycle, t_cyc cycles, E_bit⟩：lane 数 λ=可用 bonding perimeter/bump 或 TSV pitch，数据率 R_lane(ℓ) 按长度 ℓ 查表（RC 衰减），flit F_bits=128、时钟 f_clk，W=floor(λ·R_lane(ℓ)/(f_clk·F_bits))）；自动 adapter 插入（检测 router 输入/输出技术域失配 → PHY transition queuing adapter + 数据聚合/序列化 SerDes 延迟按数据率比建模 + CDC 固定 1 cycle）；router 按连接链路最低带宽 dimension、buffer 深度按 delay-bandwidth product 自动配置（长 interposer 链路防 starvation、短垂直链路防过度配置）；路由约束传播（拓扑特定 turn 限制、层间垂直转换限制、NoC/NoI/NoL 间通信规则）。链路建模细节：component-level RC 提取（RDL/vias/bonding tier 参数化 3D 结构，0.1–7GHz，按 pitch 重复提取保持 realistic aspect ratio）→ Elmore delay 模型（长度相关条目如 interposer 走线作为分布式元素随几何距离缩放，bond/µvia 作为 lumped 元素固定值）→ 链式 SPICE 仿真 → latency（rise/fall delay 平均、VDD/2 阈值、equal rise/fall <1ps 差）→ BW_link=6/τ → EPB（I×V 积分 over 1 clock cycle）→ 存回技术表。还与 gem5 Full-System 集成（KVM 引导 → Timing CPU 详细执行，boot script 启动 PARSEC 应用生成 coherence/memory 流量注入 Omelet 网络），FS 模式比合成流量慢 42×–3126×，故仅用于验证选定设计点。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：Omelet 公开于 https://github.com/sharc-lab/Omelet（论文脚注 1，with documentation and examples）；gem5/Garnet 开源（BSD）；HFSS/SPICE 为商业 EDA 工具。用法（基于论文流程，具体 CLI 论文未给出）：用户提供三类输入配置——(1) technology library 参数（interposer 材料、bonding 类型与间距、TSV/µVia 几何、RDL 材料与 L/S、line length）；(2) network configuration（每层拓扑、路由算法、router 尺寸与位置）；(3) system configuration（chiplet 数、stacking depth、每 chiplet core 数、D2D 距离、逻辑放置坐标或省略以自动放置）；Omelet 顺序执行 Technology-Aware Link Modeling → Logical Placement → NoX 构建 → cycle-level simulation → DSE。
  - 模拟性能原理 + 输入到输出全过程（一次跨 chiplet 的 128-bit flit 传输）：chiplet0 内 core 经 NI 注入 packet → NoC router（4 级流水、4 VC、4 flits/VC）→ 到达 chiplet–interposer 边界 → adapter 检测 NoC（快、窄、1 cycle/16B）→ NoI（慢、宽、tech-aware W flits/cycle）失配，插入 PHY transition + SerDes 聚合/序列化（延迟 ∝ 数据率比）+ CDC 1 cycle → packet 在 NoI router 间经 interposer RDL 链路逐 hop 传输：每 hop 延迟 t_cyc 与每周期带宽 W 由技术表按该 hop 长度 ℓ 索引（如 hybrid bond 1µm pitch → λ 大 → W 宽；solder 30µm → W 窄），RC 衰减通过 R_lane(ℓ) 体现 → 边界 adapter 反序列化 → 目标 chiplet NoC → 目标 core。每周期各 router/链路按 W 与 t_cyc 推进，缓冲/仲裁/拥塞/背压跨层自然传播（NoI 拥塞可回压至 NoC 注入端，体现 Takeaway 1）。输出：load-latency 曲线、饱和点、per-link utilization、EPB/traffic-activated energy、crossing overhead；DSE 模式下附链路/路由器物理与架构元数据做瓶颈归因（latency breakdown），输出 Pareto 最优设计集 + 对应 placement/network 配置文件。
