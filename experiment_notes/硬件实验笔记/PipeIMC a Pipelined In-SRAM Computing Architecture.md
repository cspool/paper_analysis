## PipeIMC a Pipelined In-SRAM Computing Architecture

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 PipeIMC，一个两级流水（memory 阶段 + calculation 阶段）的存内 SRAM 计算架构，把 CPU cache 阵列改造为 SIMT 风格的可计算向量引擎。核心硬件实现：(1) 双端口计算 SRAM——在计算 SRAM 上额外增加一组 bitline/wordline 形成真双端口（类似 true dual-port SRAM），新端口（calculation port）带独立计算外围电路与微码 sequencer 且只能执行计算阶段，原端口（memory port）执行 memory phase 并在空闲时执行计算 phase；每个 IMC 执行单元一个 8KB 256×256 dual-port 计算 SRAM slice（256 wordline × 256 bit，32 并发线程，每 4 条 wordline 一个物理寄存器，hybrid-8 数据布局、每线程 64 GPR）；8-bit 计算外围电路（8 组 1-bit 外围电路跨 8 bitline，由 EVE 计算阵列修改）；微码执行模型——加法/逻辑 8 cycles（奇周期多行访问、偶周期写）、乘法 32 次 shift-and-add（105–634 cycles）、除法 145–1174 cycles（Table III）。(2) 显式物理寄存器重命名（renaming unit：alias table + wordline usage counter + free list）消除三类端口冲突（write-first read-write 数据依赖、双端口写冲突、read-first read-write 冲突——in-situ 计算使源 wordline 在计算期间不可被修改）。(3) 乱序执行 dispatcher（Algorithm 1：16 条目的操作表、每操作至多一个 on-fly phase、端口冲突检查、barrier/fence 必须到表顶才能执行、memory phase 与控制流 phase 作为 special phase 优先调度）。(4) 细粒度 issue 机制——sequencer 在 memory phase 完成地址生成步骤后即把后续步骤交给 memory unit 释放端口，sense amplifier 加 latch 支持计算 phase 冻结/恢复。
  - 实验比较：在自研 cycle-approximate 模拟器上对比 SIMT-EVE [2]、Duality Cache [11] 与 PipeIMC 六个配置（Pipe-1/2/1r/2r/3r，后缀=计算端口数、r=重命名；EVE/Duality/PipeIMC 使用相同数量的 8KB 计算 SRAM 阵列、相同计算能力、in-order SIMT 或乱序控制），指标为相对 SIMT-EVE 归一化 speedup（Table VIII）、计算 SRAM 利用率（Table IX）、执行时间 breakdown（Fig. 9：compute/memory/sync/cross move/port conflict/control hazard）、能耗 breakdown（Fig. 10）与 per-area/energy 归一化性能。结果：Pipe-2r 平均 speedup 155%/113% vs SIMT-EVE/Duality Cache，利用率 2.15x–3.96x / 1.13x–4.77x，per-area 性能 2.17x/1.68x、能效 1.92x/1.60x；额外计算端口与重命名机制分别带来 12.7%/30.7% 平均提速；transformer 任务上 Pipe-2r 1.88x/2.04x vs EVE/Duality。
- 硬件平台是什么，配置是什么。
  - 模拟架构（Table IV）：LLC 128 个 256×256 8KB SRAM @1GHz；计算 SRAM 32 个 256×256 8KB；cache mode 4-cycle-hit、4-way、512KB、32 MSHRs；每 control block 64KB shared memory；每 control block 16 个 data transpose units（每单元 256B，hybrid-8 数据重排）；单通道 DDR4-2400。PipeIMC 架构（Table V）：4 个 control block、每 block 8 个 IMC 执行单元、每执行单元 32–64 线程（hybrid-8 需 64 寄存器/线程以支持重命名）、1–3 个计算端口、操作表 16 条目。EVE 重实现用 hybrid-4 布局（32 GPR/线程、64 线程/单元），Duality Cache 保留 bit-serial 布局（256 线程/单元）。基准 kernel 用 32-bit 定点数实现（同 EVE）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 自研 cycle-approximate 模拟器（论文未命名、未提供链接，联网检索未发现公开仓库，截至 2026-08）；计算 phase 周期由 cycle-accurate 计算 SRAM 模拟器得出（Table III）并实现为模拟器内 sequencer 模型；ISA 基于 Vortex GPU 编译器 [35]（https://github.com/vortexgpgpu/vortex，开源 RISC-V GPGPU 全栈，RV32IMAF/RV64IMAFD、OpenCL 1.2）通过自定义 intrinsics 扩展；能耗/面积用 GPUWattch [20]（https://github.com/darchr/gpuwattch，运行时能耗）+ McPAT [22]（https://github.com/HewlettPackard/mcpat）+ 原论文数据 [2][11] + 综合。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 PipeIMC 的完整执行流水：frontend pipeline（schedule-fetch-decode 前端，SIMT control stack 处理分支分歧、IPDOM stack 支持 split/join）、IMC 执行单元（memory stage 与 calculation stage 各含 sequencer + SRAM port + 微码 ROM、memory unit 含 data transpose unit/request buffer/request coalescer）、乱序 dispatcher、renaming unit、operation table（16 条目）、commit unit；模拟 dual-port 计算 SRAM 的端口冲突与微码周期。输出各 benchmark 执行周期与 breakdown（compute/memory/sync/cross move/port conflict/control hazard idle）、计算 SRAM 利用率，并产出运行时 trace 交给 GPUWattch 做能耗分析。修改/新增：dual-port 计算 SRAM 组件、乱序 dispatcher（Algorithm 1）、显式寄存器重命名、细粒度 issue（sequencer 释放端口 + SA latch 冻结/恢复）、operation table；重实现 EVE/Duality Cache（同 SRAM 阵列组织、in-order SIMT 控制，并修改两者外围电路以支持 Vortex 工具链编译的 SIMT IMC 程序）。

  - 开源情况：PipeIMC 未开源（论文无代码链接，联网检索无公开仓库）；Vortex 开源（https://github.com/vortexgpgpu/vortex），POCL-Vortex 工具链开源（https://github.com/vortexgpgpu/pocl，PoCL 的 Vortex 分支，OpenCL 1.2 驱动），prebuilt 工具链 https://github.com/vortexgpgpu/vortex-toolchain-prebuilt，新编译器框架 VOLT（https://github.com/vortexgpgpu/Volt，扩展 PoCL/CuPBoP/LLVM）。使用例子（模拟器输入到性能输出全过程，matmul 512×512）：输入 = OpenCL kernel（Rodinia/自写 transformer kernel，如 matmul/stencil3d/backprop/bfs/kmeans/pathfinder/matvec/attention/ffn/layernorm，32-bit 定点或 INT8 量化 attention/ffn，Table VI/VII）用自定义 IMC intrinsics 编写 → POCL-Vortex（Vortex LLVM/RISC-V 后端 + 自定义 intrinsics）编译为 SIMT IMC 指令序列（如 dest := IMC(src1, src2, op)，每操作解释为至多三 phase：load/compute/store；R/I 型编码含 memory flags 区分地址/操作数）预写入 tag array → 模拟器前端逐 warp 取指/解码/派遣到对应 IMC 执行单元 → renaming unit 分配物理 wordline 并插入操作表 → dispatcher 每周期至多派发一个 phase（双端口防竞态）到 memory port（如 O3 的 load 与 O2 的 compute 重叠）或 calculation port → sequencer 按 Table III 周期执行微码（add 9、sub 17、mul 105–634、div 145–1174 cycles）→ commit unit 提交、更新 usage counter、释放旧寄存器；memory unit 的 transpose/coalescer 与 DDR4-2400 交互 → 输出执行周期 breakdown（Fig. 9）与 GPUWattch 能耗 trace（Fig. 10）→ 计算相对 SIMT-EVE 的归一化 speedup 与 SRAM 利用率（Table VIII/IX）。作用：在无真实芯片情况下公平比较 in-order（EVE/Duality）与流水线乱序（PipeIMC）存内计算架构的性能/利用率/能耗，指导计算端口数与重命名机制的权衡。
