## Dorado: Clustered Hardware Cache Coherence for 1,000+ Cores

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现：面向 1024 核的目录式缓存一致性协议（MESI 扩展 MS 状态），在 SST 模拟器中按周期精度建模，目录-LLC 分片另做 RTL 实现并用 OpenROAD 综合布局布线评估面积/功耗。三大机制：(1) Two-Level Homes（TLH）——每行除 Global home 目录分片（物理地址哈希决定）外，在被引用的簇内按需分配/释放 Temporary home 目录分片与目录项，使事务尽量在簇内完成；(2) Dynamic Apportioning——Traditional Directory（TD，与 LLC 项一一对应）+ Extended Directory（ED，非包容层级所需 snoop filter）统一为单一目录项结构，LLptr/LRptr/RLptr 三种共享者指针（5b ID+1b 类型位）与本地/远端数据行共用同一存储并动态竞争空间；(3) SetOverflow——每个目录 set 配 PointerSpace（SharerPointer 数组 + OwnerWay 数组，T1=6、T2=2），目录项 2 个内建指针溢出时置 O 位按 way 粒度借用指针，PointerSpace 耗尽则置 B 位退回广播失效。
  - 实验比较：同面积 4 种设计——Dir2B（baseline 扁平目录，2×10b 指针，23b/项）、TLH-Dir4B（4×5b 指针，60% 远端条目/40% 本地条目静态划分）、TLH-Dir3B-Dynamicity（3×6b 指针，21b/项）、Dorado（2×6b 指针 + 每 set 12 指针 PointerSpace，24b/项）；上界 UpperBound（63b 全位向量，66b/项）；多共享者设计对比 SCD、Way Combining（同为 TLH-Dir3B-Dynamicity 底座）；层次化机器 Hier2/Hier4/Hier16（1024 核，L2 外 12/8/6MB per core）；TSO vs RC 一致性模型。指标：IPC（图/生物/数据分析应用）或平均请求延迟（KV/FaaS/ML 服务/微服务）、load 平均延迟、失效消息数、L2-miss 远端访问占比、PointerSpace 使用/溢出率、目录面积与功耗。
- 硬件平台是什么，配置是什么。
  - 被建模系统：1024 个 6-issue 乱序核 @3GHz（仿 IceLake）、352 项 ROB；默认 32 簇×32 核，簇内外均 2D mesh（簇内 5 cycles/hop，跨簇往返 60 cycles，按 chiplet 建模）；L1 D/I 64/32KB 8-way、L2 2MB 16-way（80 MSHR）、L3 分片 6MB/core 12-way（60 cycles RT、160 MSHR）；每核 200 项 LSQ，支持投机 load 与 write-exclusive prefetch；主存 512GB DDR @1GHz、32 个内存控制器、每控制器 100GB/s；首触式页分配，页内行经类 Intel 哈希函数落到本地 LLC 分片。
  - trace 生成平台：48 核 SkyLake 服务器（单 NUMA 域）上 1024 线程交织运行，Pin 采集全指令与数据访问（含同步），不采集 OS 指令；对微服务/FaaS/KV 另用 QEMU 全系统仿真 64 核交叉验证。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - SST（Structural Simulation Toolkit，https://sst-simulator.org）+ DRAMSim2（https://github.com/umd-memsys/DRAMSim2）+ Pin 采集 trace；SST 的 Ariel 乱序核模型（https://sst-simulator.org/sst-docs/docs/elements/ariel/intro）在 TSO 内存一致性模型下被作者修改以提高精度。面积/功耗：OpenROAD（https://theopenroadproject.org）综合布局布线 + Verilator（https://www.veripool.org/verilator/）翻转活动采集。协议正确性：TLA+ 规格 + TLC 模型检验。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 1024 核下目录一致性事务的周期级性能：每核执行自己线程的指令流，同步点保证互斥区单线程进入、barrier 同时离开；在 start-warmup/start-measure/stop-measure 标记间预热约 50M 指令/核、测量约 500M 指令/核。修改：Ariel 核模型改为高精度 TSO（load 投机执行、地址已知即发 exclusive prefetch、store buffer 按序 drain），并在其上实现 Dir2B/TLH-Dir4B/TLH-Dir3B-Dynamicity/Dorado/UpperBound/SCD/WayC/Hier 等协议与 TD/ED 目录、PointerSpace 的周期级建模。RTL 侧：OpenROAD 综合布局布线完整目录-LLC 分片，Verilator 采集代表访问模式与溢出事件的翻转活动做后综合功耗分析。输出：IPC/请求延迟与 speedup、L2-miss 远端访问占比、失效消息数、PointerSpace 溢出 set 比例（默认 32cl_32co 下仅 2% 数据 set 溢出、16cl_64co 下 3%）、面积/功耗增量。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - Dorado 协议代码/修改后的模拟器与 TLA+ 规格：论文未给出开源链接，web search 无法确认是否公开。所用工具均开源：SST（组件化并行架构模拟器）、DRAMSim2、Pin（https://www.intel.com/content/www/us/en/developer/articles/tool/pin-a-dynamic-binary-instrumentation-tool.html）、QEMU（https://www.qemu.org）、OpenROAD、Verilator、TLA+/TLC。
  - 模拟原理与输入→输出（SST 流程）：输入 = Pin 采集的 1024 线程指令/数据访存 trace（含同步）+ 架构参数（簇拓扑、目录配置、cache 层级、网络延迟）+ 首触式页映射 → SST 按周期调度每核乱序执行，访存逐级经 L1→L2→本地目录分片（TD/ED，查 Temporary home 条目）→（无本地条目时）跨簇访问 Global home（2D mesh：簇内 5 cycles/hop、跨簇 60 cycles RT）→ S 态多共享者且 O 位为 1 时访问 PointerSpace（写路径 +3 cycles）→ DRAMSim2 主存 → 每核统计 IPC/load 延迟/失效消息数/远端事务比 → 归一化 speedup。作用：验证 TLH 使可本地满足的远端 home 读 miss 留在簇内，令 L2-miss 远端访问降 89.6%、load 平均延迟降 46.1%、失效消息降 39%、平均 1.36× speedup（TLH 单独 1.17×、加 Dynamicity 1.24×），且距全位向量 UpperBound 性能 ≤1% 而目录存储少 2.75×；面积 +0.44%、漏电 +2.3%、动态功耗 +1.8%（代表负载）/4.2%（最坏溢出）。
