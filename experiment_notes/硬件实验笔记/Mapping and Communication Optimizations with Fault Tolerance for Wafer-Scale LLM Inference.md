## Mapping and Communication Optimizations with Fault Tolerance for Wafer-Scale LLM Inference

- 属于硬件架构的实现是什么？实验比较什么？
  - 属于硬件架构（自研事件驱动模拟器 + 层次化映射）：论文（ISCA 2026，HKUST-GZ，BusyBarn）开发自研 cycle-level 事件驱动后端模拟器（10K+ 行 Python），以 ASAP 调度同时建模计算事件、通信事件与 off-die DRAM 访问，链路用 alpha-beta 成本模型 [67]，据此评估 wafer-scale 系统上 LLM 推理的映射与通信优化。硬件架构侧的实现是层次化模拟退火（SA）映射：Inter-die Mapping——用 SA 在 die 组间构造 Hamiltonian Loop（对比 ZigZag [Tangram]），最小化相邻 die 组（尤其最后一个与第一个）间的通信距离，适配自回归解码（每次迭代等待前次输出作为输入）；Intra-die Mapping——第二个 SA 迭代器采用 Gemini [10] 的移动策略（算子对交换、算子重分配、HBM 数据重分配），损失函数为四元混合 loss：总通信距离、最大链路负载、最大 tensor workload、最大 vector workload（遍历事件线性时间计算，无需 cycle 级仿真，加速 SA 迭代）。
  - 实验比较什么：(a) 映射敏感性（一个 OPT-30B Transformer block 映射到不同 die 组）：die 数量敏感（8 种 die-group 形状 1×1、1×2、1×3、1×4、2×2、2×3、2×4、3×3，相对 Gemini 端到端延迟降低 1.25–1.75×）；core 形状敏感（5×5、4×8、6×6、6×8、7×7、8×8、9×9、10×10，相对 Gemini 1.18–1.80× 加速）；计算能力敏感（8/16/32 TFLOPs/core、1 core 故障，无故障 1.19–1.31×、1 个故障 core 1.24–1.30×）；缺陷率敏感（20×20 mesh、10%/15%/20% 缺陷率、cluster/random 故障模式，相对 Gemini 1.24–1.53×）。(b) 收敛性——Qwen2.5-7B 在 2×2 mesh 上（FFN 分割度 16，搜索空间 (4!)^16≈1.21×10^22）1000 次迭代内达到 100 万随机搜索参考值的 12.4% 以内。(c) 模拟器校准——2×2 TPUv5e 集群（vllm-tpu v0.13、TP=4）跑 Qwen2.5-7B prefill（bs=1、seq=512）实测 17.22 ms vs 模拟 16.6 ms（3.6% 偏差）。
- 硬件平台是什么，配置是什么。
  - 目标平台：wafer-scale chiplet 集成系统（层次化两级 2D mesh）。Table I 默认配置：baseline in-die fabric 4×4 2D mesh of cores、baseline peak compute 16 TFLOPs/core（BF16）、on-chip link 1 ns/256 GB/s、D2D link 20 ns/256 GB/s、off-chip HBM 100 ns/256 GB/s per die（8 GB）、每 core 1 tensor core + 1 vector unit + 16 MB SRAM、计算与链路 1 GHz。端到端用三个 wafer 拓扑：HW1 5×5（类 Dojo）、HW2 7×12（类 Cerebras）、HW3 8×8（自设计）；ablation 用 6×8 die 阵列、每 die 16×16 core、1.02 TFLOPs/core、每 die 边 1.5 TB/s D2D（DOJO 风格 WSC-LLM）。运行模拟器的主机：Ubuntu 22.04.5、Intel i9-13900K 24 核 @3.0GHz 或 Xeon Gold 6348H @2.6GHz、DRAM 64 GB/1.5 TB。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 自研事件驱动后端模拟器（论文称 event-driven backend simulator），10K+ 行 Python，非修改开源模拟器；随 artifact 开源：https://github.com/redbird-arch/isca2026-busybarn-artifact.git（Zenodo: https://doi.org/10.5281/zenodo.19686855）。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟 wafer-scale 系统上 LLM 推理的端到端延迟/吞吐：计算事件（tensor core/vector unit 按输入数据 shape 计时）、通信事件（链路 alpha-beta 模型）、off-die DRAM 访问（100 ns 延迟）；ASAP 调度在设备空闲且依赖满足时立即派发事件，自动重叠计算与通信。修改了什么：构建 LR（Location Relationship）数据流记号（算子级 TP/SP + 层间 PP 的数据位置/生产者/消费者标注）生成计算事件 → 层次化 SA 映射（die 级 Hamiltonian Loop + core 级四元损失 SA）分配执行单元 → BALD 通信调度分配链路 → 事件驱动后端评估。为校准精度，模拟器建模 TPUv5e 配置（4 个 1.5 GHz systolic array、16 GB HBM 819 GB/s、片间 800 GB/s）并对比真实 2×2 TPUv5e 集群（vllm-tpu v0.13、TP=4）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：GitHub https://github.com/redbird-arch/isca2026-busybarn-artifact.git，Zenodo https://doi.org/10.5281/zenodo.19686855；`conda create -n busybarn python=3.9` + `pip install -r requirements.txt` + `bash run_all.sh 16` 运行全部 12 图实验（`bash run_quick_test.sh 16` 快速验证 <3 小时）；输出 output/ 下 12 张 PDF 图与 summary.txt；SA 种子 --seed 123；可选 SLURM。
  - 使用例子（模拟器输入→性能输出全过程，以 HW1 5×5 上 GPT-NeoX-20B、seq 512 端到端为例）：输入 = 硬件配置 JSON（5×5 die 拓扑、每 die core 布局、各链路带宽/延迟、HBM 容量/带宽）+ 模型参数 JSON（GPT-NeoX-20B 层数/头数/hidden size 等 LLM 规模描述）+ 框架设置（SP/CP/TP/PP 混合并行策略、SA 超参）。执行：Topology Profiling 生成初始计算图并计算全对最短路径 → Notation Building 用 LR 记号把每层算子展开为数据切片与依赖（函数并行计算 DAG）→ Hierarchical Mapper：die 级 SA 构造 Hamiltonian Loop（交换 die 组位置最小化相邻距离、含故障与层-die 数不匹配约束）→ core 级 SA 四元损失（总通信距离、最大链路负载、最大 tensor/vector workload）分配算子与 HBM 数据 → Communication Scheduler 依数据依赖生成通信事件并用 BALD 分配链路 → Event Synthesizer 输出完全调度事件集 → 事件驱动后端按 ASAP 逐事件推进：计算事件按数据 shape 在 tensor/vector 单元计时、通信事件按 alpha-beta 模型在链路上计时（片上 1 ns、D2D 20 ns、HBM 100 ns）、依赖满足即派发实现通信-计算重叠。输出：端到端延迟（相对 Tangram ZigZag inter-die + Gemini intra-die + XY-YX-FT baseline 的加速比 1.17–1.84× on HW1 / 1.08–2.14× on HW2 / 1.17–1.88× on HW3，几何均值 1.40×）、纯通信/纯计算/重叠时间分解（Fig.14 绿/蓝/紫）、runtime breakdown（Fig.15：mapping 79%、backend 14.3%）。作用：在无真实 wafer-scale 硬件下量化层次化映射与 BALD 通信调度联合优化的端到端收益与容错鲁棒性。
