## NS-FPS: Accelerating Farthest Point Sampling via Neighbor Search in Large-Scale Point Clouds

- 属于硬件架构的实现是什么？实验比较什么？
  - 属于硬件架构的实现：**NS-FPS ASIC 加速器**（28nm，Verilog 实现、RTL 仿真验证 + Synopsys 综合），两阶段工作：Data Preprocess（Morton-Ordered Builder 按 Morton 码把点云分组）与 Sampling Loop（基于邻居搜索的迭代 FPS）。三大核心模块：(1) **Morton-Ordered Builder**——受 OS 内存管理启发的三阶 Morton 码页表系统：Occupancy Table（每 cube 14-bit：1-bit 非空标志 + 13-bit 指向页表项）+ Page Table（28-bit 起始/结束地址 + 4-bit 末页点数）+ Page Memory（DRAM 中每项存 16 个点的 (x,y,z) 坐标与缓存距离 + 14-bit 下一页指针），按需分配、单遍构建（4 级流水：坐标量化 15/15/11-bit→取 7/7/3 MSB→17-bit Morton 码→查 Occupancy Table→分配/追加页）；(2) **Neighbor Search Engine**——Morton Cube Searcher（由 s_k 与 d_k 生成搜索半径对应的 Morton 码范围并周期性产生 Morton 码）+ Distance Update Module（4 级流水：Fetch Data→Update Distance（16 点并行算距、仅更小值更新距离缓存）→Update Max-Value Cache1（16→1 比较器）→Record Address（1K-bit Record Table 保证每轮每地址只入 FIFO 一次））；(3) **Hierarchical Max Finder**——四级片上 max 缓存（1K/64/4/1 深度，16:1 压缩），Cache Change FIFO 追踪待更新项，top-down 更新求全局最大 + bottom-up 查回点索引。存储分层：页表/Occupancy/Record Table/层级缓存/Cube Buffer 在片上 SRAM，Page Memory 与 Point Buffer（原值+已采样点）在 DRAM；32 项 Morton Cube Buffer 缓存最近 cube（LRU、脏回写、预取隐藏 DRAM 延迟）。实验比较什么：与 GPU（RTX 3090 OpenPCDet CUDA FPS）比，16k–120k 点加速 17.2×/28.1×/42.2×/81.6×、内存访问降 1700×；与 QuickFPS-ASIC 比加速 2.1×/2.1×/1.7×/2.9×、内存访问降 8.4–13.4×；归一化缩放趋势（16k→120k 即 8× 输入：GPU 41.29×、QuickFPS-ASIC 12.08×、NS-FPS-ASIC 仅 8.74×，亚二次增长）；功耗/面积（Table II：逻辑 168.25 mW/0.168 mm²，SRAM 307.38 mW/1.907 mm²，DRAM 2066.69 mW，总 2497.43 mW、2.075 mm²；120k 25% 采样 26.69 mJ/帧，较 QuickFPS-ASIC 节能 38.9%）；敏感性（Morton 码长 (5,5,1)/(6,6,2)/(7,7,3)：32k 用 (6,6,2)、120k 用 (7,7,3) 最优；Page Memory 块大小 8/16/32/64/128：16 点匹配 DDR4 64B burst、配满 16 路 PE 阵列、保持 16:1 压缩比，为默认）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 论文采用 RTL 仿真 + 综合 + DRAM 行为仿真组合：(1) Verilog RTL 仿真验证功能；(2) Synopsys 工具以 28nm 工艺、typical corner（25°C、0.9V）综合得到面积/功耗/时序；(3) **DRAMsim3**（https://github.com/umd-memsys/DRAMsim3，Li et al., IEEE CAL 2020，cycle-accurate DRAM 模拟器，支持 DDR3/DDR4/LPDDR 等协议与热模拟），使用 Micron 8GB DDR4-2400 参数建模 DRAM 行为。全部距离计算保持 fp32 精度。
- 模拟器模拟什么的性能，修改了什么。
  - DRAMsim3 模拟 NS-FPS 加速器访存流下的 DRAM 周期行为（DDR4-2400 时序/带宽/功耗），评估内存访问量与延迟；RTL 仿真给出每轮采样迭代的周期数（搜索半径与每轮周期正相关，Fig.11）；Synopsys 综合给出 28nm 下逻辑/SRAM 面积与功耗。论文未将 ASIC RTL 开源到可综合公开仓库（repo 的 hardware/ 目录存在但无构建/复现说明）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：ASIC 代码未公开可复现；CPU 算法开源（https://github.com/satreeby/ns-fps/，C++17 + pybind11，`pip install -e .`）。DRAMsim3 开源：`git clone https://github.com/umd-memsys/DRAMsim3 && cd DRAMsim3 && make`，用 ini 配置文件指定 DDR4 时序参数、trace/内存请求文件输入。
  - 模拟器输入→性能输出全过程（NS-FPS-ASIC + DRAMsim3）：输入 = 点云帧（SemanticKITTI 16k–120k 点，(x,y,z) 浮点坐标）+ 采样率（默认 25%）+ 配置（Morton 码 (7,7,3)、16 点/页、32 项 Cube Buffer、四层 max 缓存 1K/64/4/1）。执行：Morton-Ordered Builder 单遍把点按 17-bit Morton 码桶排序写入 DRAM Page Memory（经 32 项 Cube Buffer：命中写缓存、miss 从 DRAM 载入、LRU 驱逐脏块回写、终了 flush）；Sampling Loop 每轮由 Morton Cube Searcher 按半径 d_k 生成候选 Morton 码集合，Distance Update Module 逐 cube 从 Page Memory 取 16 点并行算距并更新距离缓存与 Cache1 局部最大，Cache Change FIFO + Record Table 记录被改块地址，Hierarchical Max Finder 自底向上传播局部最大、顶层得全局最大后自顶向下查回点索引、从 Page Memory 取坐标加入采样集；全部 DRAM 访问请求送 DRAMsim3 按 DDR4-2400 时序排队。输出：每轮迭代周期数（Fig.11 半径-周期曲线，前 100 轮占 27.3% 迭代时间）、端到端延迟（120k 25%：预处理 1.02ms + 邻居搜索/距离更新 9.23ms + 最远点选择 1.65ms）、内存访问总量（较 GPU 降 1700×、较 QuickFPS 降 8.4–13.4×）、综合后面积 2.075 mm² 与功耗 2497.43 mW（DRAM 占 82.7%）。
