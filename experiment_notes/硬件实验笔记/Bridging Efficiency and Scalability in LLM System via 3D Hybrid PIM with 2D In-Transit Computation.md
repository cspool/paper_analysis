## Bridging Efficiency and Scalability in LLM System via 3D Hybrid PIM with 2D In-Transit Computation

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现 = CompAir：32 设备经 CXL switch（CXL.io+CXL.mem）互联的可扩展混合 PIM 系统，单设备 32 通道 × 16 bank，每 bank 由 DRAM die（1Y-nm 32MB DRAM-PIM bank、16 输入 BF16 MAC 单元、global buffer 承担跨 bank 通信）与逻辑 die（4× 8KB SRAM-PIM 宏 + 4 个 router 组成 2D-mesh NoC）经 hybrid bonding（每 bank 256 bonds）1:1 堆叠；设备控制器只负责指令下发、不含非线性执行单元。三大硬件组件：(1) 解耦列译码器——把 DRAM-PIM 的 32:1 列选 MUX（Newton [17] 式）拆为 8:1（供 SRAM）+ 4:1，提升 bank 读带宽以匹配 SRAM-PIM 需求（面积 +15%、扩 bonds 占单 bank 面积 20%，CACTI 7.0 评估；Llama2-13B 端到端 1.15–1.5× 收益）；(2) CompAir-NoC（基于 SWIFT [39] 优化 NoC：4×16 2D-mesh、每 router 2 个 BF16 Curry ALU、flit 72b）——在 flit 级"flit compute"阶段（与 switch traversal 并行、零额外流水级）做 in-transit 计算：Curry ALU 由单操作数驱动（flit 动态携带 InputOp+InputVal、内部 ArgReg 静态存右操作数、IterArg/IterOp 支持 ArgReg 迭代更新，借鉴 Lambda Calculus Currying），支持 16 宽归约树（4 层二叉、ArgReg 作非叶节点累加器）/广播树、RoPE 数据重排（4 router 五阶段交换 + DRAM-PIM EWMUL）、exp（Taylor 展开：ArgReg=6 为迭代轮数，逐轮 *=X、/=IterRound、+=1，每通道 32 路并发）/sqrt（Newton 迭代）等 BF16 非线性；(3) 分层 ISA——Row-Level ISA（SIMD、DRAM bank 粒度，用户接口：NoC_Scalar/NoC_Access/NoC_BCast/NoC_Reduce/NoC_Exchange/SRAM_Write/SRAM_Comp）+ Packet-Level ISA（MIMD、router 粒度：Type 4b/Data 16b BF16/IterNum 4b/Path[0..3]×12b），host 侧编译器静态 row→packet lowering，path generation 按 DST→SRC 生产者-消费者链融合依赖 NoC_Scalar 指令，router 自动把 DRAM 行粒度数据串行化/反串行化为 flit。
  - 实验比较：baseline (i) 纯 DRAM-PIM CENT [13]（GDDR6-PIM、CXL GPU-free 系统、PNM 集中 NLU/CPU，32/96 设备）；(ii) SRAM-PIM stacking passive DRAM；(iii) AttAcc [57]（4×80GB A100 + 4×16GB HBM3-PIM 混合，AttAcc 原版模拟器 + ramulator2.0 模拟 HBM-PIM + A100 性能公式推导）。消融链：DRAM-PIM only（CENT）→ CENT_Curry_ALU（纯 DRAM-PIM + 本地 Curry ALU）→ CompAir_Base（启用 SRAM-PIM 但不改列译码器）→ CompAir_Opt（完整）。指标：prefill/decode 吞吐与延迟、energy/token、面积与功耗（DC/Vivado 综合）、perplexity（近似激活验证）。

- 模拟器模拟什么的性能，修改了什么。
  - cycle-accurate 联合模拟 CompAir 端到端 LLM 推理：ramulator2.0 推演 DRAM bank 时序（tRCD/tRAS/tCL/tRP，含解耦列译码器后的读写带宽）、Booksim 推演 4×16 2D-mesh 上 flit 逐跳路由（论文把 Curry ALU 的 flit compute 建模为与 switch traversal 并行的计算阶段）、CENT 模拟器负责 CXL 设备间通信与 DRAM-PIM 指令执行、sram_pim 按 [14] 宏规格建模矩阵延迟/功耗。修改：booksim2 加入 Curry ALU 计算与 ArgReg/IterArg/IterOp 寄存器状态机及归约/广播/交换路由行为；ramulator2.0 侧实现 32:1→8:1+4:1 解耦列译码器的带宽模型；自研 translate/ 做 row→packet 静态降级与 path generation。DRAM-PIM 基于 AiM [43] 及衍生 [13][17] 的流片规格，论文不自改 DRAM 工艺模型。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 全开源（https://github.com/Man0xbfc00380/comp-air.git）。模拟原理：输入 = 模型（Llama2-7B/13B/70B、Llama3、Qwen-72B、GPT3-175B）+ 系统配置（devices/channels/batch/seqlen）+ 开关（--use-noc/--use-sram-pim）。全过程（decode 一个 transformer block）：translate/ 把 row-level ISA 程序降级为 packet-level ISA 并做 path generation → cent_pim 生成 DRAM-PIM 指令流与 CXL 通信事件 → ramulator2.0 逐周期推演 DRAM 行激活/读写（解耦列译码器决定 bank 读带宽）→ sram_pim 对 Q/K/V、FFN 等 batched FC 层计算矩阵延迟（权重驻留宏内、仅输入/输出经 DRAM 搬运、跨 batch 权重复用）→ booksim2 逐周期推演 flit 路由与 Curry ALU in-transit 计算（Softmax 的 exp、归约树、RoPE 重排）→ 汇总到 compair_summary.json 输出 latency/throughput/energy。结果：prefill 1.83–7.98×（0.5K 长度：仅 SRAM-PIM 3.29–5.46×、加解耦列译码器 4.1–7.89×）、decode 1.95–6.28×（batch=64 时 2.67–6.28×、batch=1 无收益）、128K 长上下文 decode 2.13–2.73×（GPT3-175B/Qwen-72B）；96 设备吞吐与 AttAcc-4-A100-HBM 相当、4K 上下文每 token 延迟/能耗仅为其 20.2%/28.5%，相对 GPU-PIM 混合整体 3.52× 低能耗；TP≤8 最优（TP 过高 bank 利用率骤降）；Curry ALU 面积为 router 的 2.94%、非线性总延迟 -30%、长上下文延迟 -25%、path generation 33–50%；SRAM-PIM+router 0.8195mm²/bank 满足 3D 堆叠要求；DRAM-PIM/SRAM-PIM 比值需权衡（跨 die 通信使能耗略高于纯 DRAM-PIM）。
