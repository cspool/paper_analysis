## ConBin: A Performance-Convergence Framework for Wafer-Scale Chip Binning

- 属于硬件架构的实现是什么？实验比较什么？
  - 近似匹配（微架构级设计 + 系统级仿真评估，无 RTL 实现）。实现 = 故障相关感知的冗余互连微架构（Fig.8a）：每个 router 保留 5 个逻辑端口，4 个方向端口经 MUX 扩展为"近邻 + 多跳候选互连"（R-R 链），router-PE 接口同样冗余化——PE 可有多个候选 router 连接，修复后每个方向/PE 恰好激活一条互连；全片统一冗余模板（R_max=6：2 条 P-R 链一近一远 + 2 短程 R-R + 2 长程 R-R）。设计指标：D_low（最低 α=0.3 比例 router 的平均度，度量连通性下界，通信瓶颈由下界而非均值决定）与 R_PE（接入度 >β 的 router 的可接入 PE 比例，度量算力抢救能力），联合构成适应度 F=λ·D̃+(1-λ)·R̃（λ=0.9）。制造后修复两阶段：core 配置（C^h/C^r/C^p/C^f 四类核，沿 P-R 链 BFS 最短 replacement chain 重绑定 PE 到健康 router，链止于 PE-only 故障 core）+ 互连配置（每端口先 mesh 链、否则最短冗余链）；路由用 turn-prohibition 最短路径 [50]。实验比较：Cerebras 专利冗余架构（每 core 六条 2-hop 冗余链、仅短程 R-R）vs ConBIN 冗余（F_norm 四种故障模式 2.0–2.8×）；CB*+SK vs CB*+Ours-SW* vs Ours-WM vs Ours-ALL* 的性能方差与 speedup（Ours-ALL* 方差降幅最高 79.21%、speedup 最高 2.39×）；面积 McPAT 估计 <8%@128×136。
- 硬件平台是什么，配置是什么。
  - 无真实硬件；模拟对象为 stitched-die 2D mesh WSC：每 die 8×8 核、每核 8MB SRAM、die 尺寸 16.66×22.17mm；四种规模 [5×6, 8×9, 12×13, 16×17] dies = [40×48, 64×72, 96×104, 128×136] 核（默认 128×136）。运行开销（128×136）：冗余设计 6.28 min、制造后修复 7.12 s；F_norm 各规模 86.43%–88.19%。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 自研系统级仿真 = ScaleSim（https://github.com/ARM-software/SCALE-Sim，32×32 阵列、8MB SRAM、Output Stationary）核级 + BookSim 2.0（https://github.com/booksim/booksim2，Tab.III：8 VC、buffer 8、flit 32b、packet 16 flits、4 级 router 流水、每 mesh hop 1 cycle）NoC 互联；面积/功耗 McPAT [36]（https://github.com/HewlettPackard/mcpat）。优化器 Geatpy（https://github.com/geatpy-dev/geatpy）：EGA（冗余设计，种群 50）、SEGA（映射，种群 100）、NSGA-III（调度，种群 120）。
- 模拟器模拟什么的性能，修改了什么。
  - ScaleSim 按 Output Stationary 数据流模拟核内 GEMM/attention 计算周期；BookSim 模拟故障修复后非规则 mesh 拓扑上按 turn-prohibition 路由的逐 cycle NoC 行为；修改：拓扑注入故障核/链、多跳冗余 R-R 链与 P-R 重绑定后按新距离更新 PE-router 延迟（冗余链延迟按 hop 数成比例）；两者联合输出每 chip 端到端 latency。Fig.9 用 BookSim 隔离 hop 数与任务间 contention 对延迟的影响：hop 延迟 5–6 跳后饱和（流水摊薄），任务间 contention（链路/目的端/混合）近线性增长——contention 才是故障下主要延迟源。

  - 开源情况：ConBIN 代码未开源（论文未给链接，联网未发现官方仓库，无法确认）；ScaleSim/BookSim/Geatpy/McPAT 均开源（链接如上）。模拟原理与全过程：输入 = (a) 故障图（Gaussian 簇 + 随机噪声、Local/Scratch/Edge-Local/Donut 模式、故障率 0.05–0.4、每模式 512 实例），(b) EGA 搜索出的冗余设计模板（R_max=6、L_max=4），(c) 目标负载（LLaMA 6.7B / GPT-2.7B / GPT-Large 760M / GPT-SMALL 125M / GEMV+GEMM 32k×32k，映射为依赖图 WG）→ 先 core/互连修复把故障图转成近 mesh 修复拓扑（P-R 链重绑定 + 端口择优）→ bin 感知映射（SEGA 最小化 MLCC_exp 直到命中 bin 目标）→ 通信序列调度（NSGA-III 最小化 CAP 内最大 contention Φ，三粒度批处理 + 历史传播因子 μ）→ ScaleSim 逐核计算周期 + BookSim 逐 cycle 推演 flit 传输/VC 仲裁/链路竞争 → 输出每 chip 平均 latency → 汇总性能分布，DP 分 bin 得 premium-bin yield 与 SECC。作用：证明"硬件近 mesh 修复 + 软件 bin 感知收敛"可将同一功能良率转化为更集中的性能分布（premium-bin yield 2.80×、SECC 2.64× vs CB*+SK*）。
