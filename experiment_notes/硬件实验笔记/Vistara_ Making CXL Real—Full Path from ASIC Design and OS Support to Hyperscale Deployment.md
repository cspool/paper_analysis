## Vistara: Making CXL Real—Full Path from ASIC Design and OS Support to Hyperscale Deployment

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现是 Vistara CXL 内存扩展系统的硬件架构 + 系统集成：① 内存控制器流水线精简（减少 pipeline 级、通用事务 fast-path）降低排队/仲裁时延；② 协议级 CXL 栈与 PCIe Gen5 PHY 直接耦合减少协议翻译开销；③ 主机侧 CPU host-bridge 以 256B 粒度把访问交错映射到 2 个 Vistara 设备，设备内再跨 DIMM/rank/bank 交错最大化并行、均衡 CXL link 负载（Table VI）；④ MemServer 平台：单路 AMD Turin（Zen5，158 核/316 线程 ≈3GHz，TDP 300W），768GB DDR5-6400（12 通道、614 GB/s、空闲时延 ≈130ns）+ 2× Vistara ASIC（各 PCIe Gen5 x8）+ 256GB DDR4-2400（8×32GB RDIMM）= 1TB，总功耗 450–560W；⑤ 软件侧内核内存分层（TPP + TMO + NUMA demotion/balancing），CXL 以 CPU-less NUMA 节点暴露、ZONE_MOVABLE 隔离非可迁移内核分配、cpuset.mems cgroup 实现 opt-out、per-container Fair Share 内存公平。
  - 实验比较：A/B 测试（同配置 MemServer 仅 cpuset.mems 是否含 CXL 节点，生产负载均衡器均分流量，运行 ≥1 周）比较服务级（吞吐/QPS、p50/p99 时延、命中率、OOM 率）与系统级指标（本地/CXL 带宽、CPU 利用率、TPP promotion/demotion 速率、NUMA hint faults）；另做 iso-capacity 敏感度（3:1/2:1/1:1 本地:CXL，保持总容量不变）与多租户公平性（两 CacheA 容器同 host）实验。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 无模拟器。硬件架构评估基于真实生产部署的 MemServer（AMD Turin Zen5 + Vistara 硅片）与 Intel MLC 微基准（https://www.intel.com/content/www/us/en/download/736633/intel-memory-latency-checker-intel-mlc.html）；软件"运行环境"为 Linux 内核（TPP 的 memory tiers/NUMA demotion、drivers/cxl、NUMA balancing、weighted interleave 自动调优），代码在 upstream Linux kernel。联网搜索（2026-08）确认 Vistara 无开源仓库、无模拟器发布。
- 模拟器模拟什么的性能，修改了什么。
  - 无模拟器。说明真实系统测量内容：MLC 测各 tier 峰值带宽（ALL-Read 本地 497 GBps vs CXL 48 GBps）与负载时延（Table IV：60% 利用率本地 234ns vs CXL 372ns）、并发时延 CDF（Fig.5）；生产监控采集本地/CXL 带宽（Table VIII：本地 2–300 GB/s、CXL 0.5–13 GB/s、MRS 94 MB/s）、TPP promotion/demotion 速率、NUMA hint faults、OOM 率。软件"修改"（对应修改了什么）：在 upstream TPP 之上调优内核参数（numa_demotion_enabled=1、numa_balancing=2、zone_reclaim_mode=7）；新增并上游化 cache-pages-prefer-remote-node 策略（file cache/tmpfs 冷页直接分配 CXL，warmup 期 20GB 本地+76GB CXL 达到 96GB 全本地同吞吐）与 weighted interleave 自动调优；cgroup cpuset.mems 实现 opt-out；per-container memory-tier accounting（Fair Share：容器本地 DRAM 超过 local_high 即 demote 到 CXL，两容器 local fraction 从 90%/70% 失衡变为 74%/71% 平衡，P99 时延提升 1.6×/1.8×，noisy-neighbor 下 QPS 跌幅 65%→12% 且消除 OOM）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：硬件架构/ASIC 专有未开源（联网搜索 2026-08 无法确认公开仓库）；Linux 内核侧改动已/将上游（upstream：mm/memory-tiers、mm/vmscan NUMA demotion、drivers/cxl、NUMA balancing、sysfs memory policy）；MLC 免费下载；HHVM（https://github.com/facebook/hhvm）开源，用于 Web（HHVM）负载的 iso-capacity 敏感度实验。生产 A/B 流程：MemServer 同配置节点分 test/control 组（cpuset.mems 是否含 CXL 节点）→ 负载均衡器均分流量（相同请求混合与昼夜模式）→ 运行 ≥1 周 → 对比服务级+系统级指标。
  - 使用例子（一次 CacheB 请求在 MemServer 上的数据路径，即"模拟器输入到性能输出"的等价全过程）：请求到达 → 查内存缓存：命中 hot 对象 → 本地 DDR5-6400（≈130ns 空闲时延）直接响应；对象冷、已被 TPP 经 minor page fault 检测并 demote 到 CXL → CPU 内存控制器 → host-bridge 256B 交错 → PCIe Gen5 x8 → Vistara CXL 控制器（空闲时延 ≈50ns）→ DDR4-2400（≈250ns 空闲时延）读取返回；TPP 通过 minor page fault 追踪页面热度、DRAM 压力触发 reclaim demotion（NUMA demotion）、TMO 主动 demote 冷页，hot 页从 CXL 反向 promote 回本地；期间遥测采集本地/CXL 带宽、promotion/demotion、hint faults。作用：缓存容量 590→820GB，2.3% 命中从 flash 移回内存 → 平均查询处理时间 -29%、flash 磨损降低；CacheA 缓存 680→890GB → 可持续 QPS +33%、retention age 1min→5–10min。
