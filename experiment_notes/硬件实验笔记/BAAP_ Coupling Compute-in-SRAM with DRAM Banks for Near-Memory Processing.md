## BAAP: Coupling Compute-in-SRAM with DRAM Banks for Near-Memory Processing

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现 = 将 UPMEM 商用 DDR4-PIM 每 bank 的 64 KB SRAM scratchpad（WRAM）按 25%/50%/75%/88% 比例替换为 6T push-rule 可重构 SRAM（Jeloka 等 JSSC'16 [30]：BCAM/TCAM/SRAM 三态可切换），构成银行级关联处理器（AP）：每 BL/BLB 对加 1 个 AND 门 + tag 寄存器使 32x36 子阵列可作 CAM；多个子阵列拼成传播链，以位切片布局做位并行/位串行算术；扩展 UPMEM ISA 14 条指令（表 IV：SIMD 模式 ap_and/ap_or 3 周期、ap_xor 4、ap_add/ap_sub 8n+2、ap_mul 4n²+4n、ap_redsum n、ap_eq n+4、ap_merge 4；DirectAP 模式 ap_search 1、ap_searchacc 2、ap_update 1、ap_set_tags 1、ap_regex <m−k 周期）；解码逻辑加 Associative Sequencing Unit（ASU，缓冲指令并存储优化的 AP 微码 [57]），DMA 引擎与 AP 数据通路间加 Vector Prefetching Unit（VPU，非投机预发射下一向量 load/store 与计算重叠）；写 CSR 切换灵敏放大器差分↔单端实现 Scratchpad/SIMD/DirectAP 三模式。实验比较：UPMEM 基线（uPIMulator，16 tasklets，等面积容量折算）、主机侧 AP（PUMICE 版 CAPE [52]，2.72 GHz + 4×4H HBM）、Intel Xeon W-1390P OoO CPU；指标 = 单 DPU 与整 DIMM（128 DPU）加速比、roofline 模型、每 DPU 功耗（按 Stillmaker-Baas 缩放方程 [49] 悲观缩至 65 nm 平面 CMOS，对比 150 mW TDP）、频率 225–350 MHz 与 VL 扫描、scratchpad 容量 25–100% 灵敏度、VPU 消融。
- 硬件平台是什么，配置是什么。
  - UPMEM DIMM（表 III）：DDR4-2400 8 GB、16 芯片×8 bank=128 DPU；每 DPU = in-order CPU 500 MHz（14 级 Revolver 管线、24 HW 线程、1 周期 ADD / 32 周期 MUL、无 bypass 无 stall）+ 24 KB IRAM + 64 KB WRAM + 64 MB DRAM bank（1 GB/s，聚合 128 GB/s）。BAAP 配置（表 VI）：25%/50%/75%/88% WRAM → VL=96/224/320/384、剩余 scratchpad ≈48/32/16/8 KB，AP 逻辑 350 MHz（保守低于 UPMEM 500 MHz）；32 个 32-bit 向量寄存器 + 4 个元数据寄存器，单 bank 可同时算 32×96 元素，单 DIMM 同时操作 12,288 个 32-bit 结果。主机基线：Xeon W-1390P 3.5 GHz（AVX-512、5 发射、352 ROB、L1I 48 KB/L1D 32 KB/L2 512 KB/L3 2 MB、4×32 GiB DDR4-3200）；主机侧 AP 2.72 GHz、VL=49,152、4× 4H HBM（16 通道/128 伪通道、256 GB/s）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - uPIMulator（https://github.com/VIA-Research/uPIMulator，HPCA'24 KAIST，cycle-approximate、对真实 UPMEM 硬件验证：单 DPU 相关性 98.4%/MAE 12.0%，multi-DPU 83.6%/26.9%）跑 UPMEM 近存基线；gem5（https://github.com/gem5/gem5）建 BAAP 前端（SRAM AP + 微型 in-order 控制 CPU，参照 CAPE [8] + PUMICE [52]/Hyper-AP [57] 优化）。面积/能量：FN-CACTI（https://github.com/SLAM-Lab-Gatech/FN-CACTI，7 nm）建普通 SRAM scratchpad 基线；Synopsys Design Compiler + ASAP7 PDK（https://github.com/The-OpenROAD-Project/asap7）综合 AP 链 RTL，辅以 32x36 6T push-rule 子阵列（含 tag/累加/归约/中间结果传播外围）的 SPICE 仿真 [30]；AP 化存储面积开销 1.2281×。
- 模拟器模拟什么的性能，修改了什么。
  - uPIMulator 把 UPMEM kernel 编译为机器级指令后逐周期模拟 DPU 流水线/MRAM/WRAM/DMA 访问，论文用其评估 UPMEM 基线（16 tasklets、取每 benchmark 最佳变体）与 scratchpad 容量灵敏度（UPMEM 性能在 50%–25% 容量间开始显著退化）。gem5 前端模拟 BAAP：每条向量指令的延迟按表 IV 的 CAM 搜索/更新序列周期建模，内存后端采用与 uPIMulator 相同的 UPMEM 实测延迟/带宽 [21]；VPU 消融经开关"下一向量 load 预发射"实现。论文未说明对 uPIMulator 内部机制的修改。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - BAAP 自身 RTL/模拟器补丁未开源（论文无链接，联网搜索无法确认官方仓库）；uPIMulator/gem5/FN-CACTI/ASAP7 开源。模拟原理：uPIMulator 输入 = UPMEM kernel 源码 + 工作负载 → 编译为 UPMEM ISA → 逐周期模拟 24 线程交织的 14 级流水线与 MRAM/WRAM 访问 → 输出执行周期（UPMEM 基线）；gem5 输入 = BAAP 扩展 ISA 指令流 + 表 IV 每指令 AP 周期数 + UPMEM 实测内存时序 → 逐周期模拟 ASU 展开 CAM 搜索/更新微码 + VPU/DMA 重叠 → 输出周期与功耗估计。全过程例子（PrIM REDSUM 单 DPU）：host scatter 数据到 bank → DMA 载入位切片向量到 AP 化 WRAM → ASU 把 ap_redsum 展开为 n 次 CAM 搜索/累加（每次 1–2 周期、n 位元素并行）→ VPU 预取下一段 → gather 回 host → 与 UPMEM 标量归约对比。结果：PrIM 单 DPU 加速比最高 7.9×（25% 配置，平均 2.29×）、13.97×（75%，平均 4.95×）、14.33×（88%，平均 5.73×）；整 DIMM（128 DPU、75%）再平均 4.1×；roofline：75% 配置位运算 ≈37 GOPS、32-bit add ≈0.43 GOPS、32-bit mul ≈0.027 GOPS（UPMEM 单 DPU 峰值 ≈0.35 GOPS，其 ADD/MUL 实测距屋顶差 2–12×）；功耗 65 nm 悲观缩放下仍低于 150 mW/DPU。
