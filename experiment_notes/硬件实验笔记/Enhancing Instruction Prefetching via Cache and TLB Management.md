## Enhancing Instruction Prefetching via Cache and TLB Management

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 IP-CaT（Instruction Prefetch Centric Cache and TLB Management），一个协调 TLB 与 L2 缓存管理的微架构方案，用于放大 L1I 预取器收益，包含两个模块：①tPB（translation Prefetch Buffer）——位于 sTLB 旁的小容量 set-associative 结构，存储由 L1I 跨页预取发起的 page walk 取回的指令 PTE（vpn 索引 + ppn + 属性位）。仅在 iTLB 与 sTLB 都 miss 时被查询；tPB 命中则按 sTLB 插入策略将条目移入 sTLB 并失效 tPB 条目，从而减少 demand 页表走查；由 L1I 跨页预取触发的 page walk 结果存入 iTLB 与 tPB（而非 sTLB），避免污染 sTLB。sTLB MSHR 新增 1-bit cross-bit（cb）区分翻译请求是否来自 L1I 跨页预取。tPB 也可按相同 associativity 直接集成进 sTLB（额外 set）。②TIPRP（Trimodal Instruction Prefetch Replacement Policy）——决策树驱动的 L2C 替换策略，针对 L1I 预取取回的代码行，动态在三个 RRPV 基策略间选择：PIP（优先保护预取代码行，在 eviction 时操作）、NPIP（不优先、插入时置 RRPV=3 底部，插入时操作）、BIP（完全 bypass 预取代码行不插入 L2C，插入时操作）；两级决策树由两个饱和计数器 PSEL1/PSEL2 驱动，L2C set 静态划分为 4 类（PIP/NPIP/BIP 的 Leader Sets + Follower Sets），PSEL1/PSEL2 在 demand L2C hit 与 eviction 事件上按 prefetch bit（pb）不对称更新（训练不对称：PIP Leader 只在 pb=1 时更新、NPIP/BIP Leader 只在 pb=0 时更新）。存储开销 0.79KB（64 项 tPB 6452b + sTLB MSHR cb 16b + PSEL1/PSEL2 各 10b），仅占 L2C 容量 0.08%。
  - 实验比较：以三种 SOTA L1I 预取器（EPI、Barça、FNL+MMA，均配置跨页预取）为前端基础，比较 IP-CaT 与 SOTA TLB/缓存策略：TLB 侧 CHiRP（TLB 替换）、Morrigan（指令 TLB 预取器）；L2C 侧 CLIP、EMISSARY；LLC 侧 PACIPV、PACMAN、DRRIP、SHiP++、Mockingjay；以及 SRRIP(L2C)、TIPRP/tPB 独立消融与 tPB+各策略组合。指标为 IPC geomean speedup（对比 baseline，表 I）、L2C/LLC/sTLB MPKI 与平均 miss 延迟。主要结果：TIPRP 单组件对 EPI/Barça/FNL+MMA 分别 +2.9%/+4.8%/+5.0%；IP-CaT（tPB+TIPRP）对三者分别 +6.1%/+8.3%/+7.9%，优于全部对比策略且超过组件和（tPB+TIPRP=5.8%<6.1%，源于 tPB 减少 page walk 降低 L2C 争用）；sTLB MPKI 降 31.6%/18.2%/32.3%；tPB 命中率 36.2%（64 项全相联），ISO-storage 对比胜过 sTLB+128 项方案；LLC 敏感性 1MB→4MB 时 speedup 12.7%→2.6%；多页尺寸（4KB+2MB）下 2MB 占比 0%→100% 时 speedup 7.5%→1.8%；4-core 160 个 workload mix 与 75 个 SMT workload 下 IP-CaT 均最优（如 EPI 下超 CLIP/PACIPV/PACMAN 7.1%/9.3%/10.3%，SMT 场景）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - ChampSim（https://github.com/ChampSim/ChampSim；论文引用 https://crc2.ece.tamu.edu/，官方描述见 arXiv:2210.14324 "The championship simulator: Architectural simulation for education and competition"），trace-based 乱序处理器 + 三级缓存层次模拟器。论文在 ChampSim 上额外集成 decoupled frontend + FDIP [13]、5 级 radix tree 页表、x86 硬件页表走查器、MMU Caches [57]，并扩展 SMT 支持。论文 arXiv: https://arxiv.org/abs/2605.12433（ISCA 2026）。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟单核/4 核/2 线程 SMT 下，前端（L1I 预取 + 指令翻译）与缓存/TLB 层级在 server workload 上的 IPC、L2C/LLC/sTLB MPKI、平均 miss 延迟与 speedup。修改：①在 sTLB 旁实现 tPB 结构（含 sTLB MSHR 的 cb bit、tPB 查询/插入/失效逻辑、page walk 结果分流）；②在 L2C 实现 TIPRP 替换策略（pb bit、PIP/NPIP/BIP 三策略、PSEL1/PSEL2 决策树与训练逻辑）；③ChampSim 扩展 SMT 支持；④配置三种 L1I 预取器（EPI/Barça/FNL+MMA）跨页预取模式与表 II 中 10+ 种对比策略的 L2C/LLC/sTLB 变体。baseline 配置（表 I）类 Intel Cascade Lake：4GHz、6-wide、128-entry FTQ、352-entry ROB、TAGE-SC-L 分支预测、8K BTB、64-entry RAS；iTLB 64 项 4-way、sTLB 1536 项 12-way、4 级 split PSC（MMU cache）；L1I 32KB 8-way、L1D 48KB 12-way（Berti 预取器）、L2 1MB 16-way、LLC 1.375MB/core 11-way（SHiP）、DRAM 4GB/core 25.6GB/s。

  - 模拟原理与输入→输出全过程（一次 L1I 跨页预取的 IP-CaT 数据路径）：输入 = 指令 trace（x86 指令流，含虚拟地址/分支信息）+ ChampSim 配置（表 I 基线 + tPB 64 项全相联 + TIPRP + EPI 预取器）→ ChampSim 逐周期推进乱序流水线：前端 fetch 产生 L1I 访问，EPI 预取器在虚拟地址域预测未来指令块 → L1I 预取请求先查 iTLB（1cc），miss 则查 sTLB（8cc），再 miss 且为跨页预取时查 tPB：命中则将翻译按 sTLB 插入策略写入 sTLB 并失效 tPB 条目（避免 demand page walk）；tPB miss 则触发页表走查（4 级 radix tree + MMU PSC），cb=1 的走查结果写入 iTLB+tPB 而非 sTLB → 翻译后的物理地址访问 L1I/L1D，miss 后查 L2C，TIPRP 依据 pb bit 与 PSEL1/PSEL2 决策树选择 PIP/NPIP/BIP 驱动 L2C 插入（RRPV 位置/是否 bypass）、提升与替换，命中/淘汰事件按图 6(c) 训练规则更新 PSEL1/PSEL2 → 逐周期统计 L2C/LLC/sTLB 访问、MPKI 与 miss 延迟 → 输出每 workload 的 IPC 与 speedup（对比 baseline），跨 105 个单核 workload 求 geomean 得图 8 等的 box plot。作用：验证 IP-CaT 通过 tPB 隐藏跨页预取的翻译延迟、通过 TIPRP 减少 L2C 死代码行污染，从而放大三种 SOTA L1I 预取器性能。
