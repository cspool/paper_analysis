## Lembas: Cost-Efficient Genome Alignment with External Memory and FPGA Acceleration

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为长读长基因组比对加速系统，将 Minimap2 的 seed-chain-extend 三阶段各用专门 FPGA 加速器在真实硬件（Xilinx Alveo U50）上实现，三个加速器时分复用同一批 FPGA（同一时刻所有 FPGA 加载同一 bitfile，全系统同步执行三步之一，无需三块 FPGA）：
    1. **外部内存 columnsort 播种加速器**（论文新颖点①）：去除 seed 阶段驻留内存的 minimizer 哈希表，把 reference/query 的 minimizer 流经 PCIe 溢出到 NVMe SSD，用外部内存 columnsort 算法排序（16 个 16-to-1 单发射 merge-sort kernel，占用 U50 全部 32 个 HBM pseudo-channel，每 kernel 250 MHz/4 GB/s，合计饱和 U50 ~8 GB/s 双工 PCIe）；排序后 anchor 匹配退化为两个有序列表的流式 zip，得到 〈idxQ,idxR〉 anchor 流后再按 idxR 二次 columnsort。minimizer 解析与 anchor 匹配简单，与 columnsort 共享同一 bitfile。columsort 网格约束 r≥2c²（256 MB HBM bank 限制下可排序 ≤512 GB，超出按 512 GB 分块后软件合并）。
    2. **流式 chaining 加速器**（复用 Guo et al. FCCM'19 设计，不声称新颖性，clean-room 复现）：把软件 1D DP"回看 N 个前驱算 max reduction"改为"每个 anchor 把分数前向传播、增量更新后续 N 个 anchor"，打破单次宽 max-reduction 关键路径，II=1 全流水；4 个 kernel（每 kernel 单 PE）即可饱和 PCIe。
    3. **tiled Smith-Waterman-Gotoh（SWG）extend 加速器**（论文新颖点②）：banded SWG + affine gap penalty，16 个 kernel × 16 个 PE 的 1D 脉动阵列算分数矩阵（每 PE 每 cycle 算 S/E/F 三值，F 缓存在 PE 内、E/b 经 E,b 寄存器链、S 经 2 元素 FIFO 传递），并实现新颖的 **8×8 tile 位并行 traceback**：每个 tile 边缘单元（灰色单元）存从相邻 tile 外起始的完整跨 tile 路径编码（2-bit x/y 偏移，8×8 tile 路径最长 16 步、15 个边缘单元 → 32×15=480 bit，正好对齐 512-bit HBM 接口），traceback 每 cycle 前进一整 tile（popcount x/y 位定位下一 tile），克服 FPGA 低时钟下 traceback 紧依赖瓶颈；HBM 访问延迟用每次预取 4 个 tile 缓解。
  - 实验比较：Lembas（i7-8700 16 线程 + 32 GB DDR4 + 4×1TB M.2 NVMe + 2×Xilinx U50 8 GB HBM，购买价 $8,000）vs (a) 软件 Minimap2（mm32/mm64：AMD EPYC 7742 128 线程 384 GB DDR4）；(b) NVIDIA Parabricks GPU-accelerated Minimap2 beta（Xeon Gold 6248R + A100 80 GB HBM）；(c) 论文已发表数据 G³SA（GPU，A6000，128 线程 Threadripper）与 Cheng24（FPGA，XCKU115，40 线程 Xeon E5）——两者软件 artifact 未在线提供，用发表数字 + mm32/mm64 公共基准换算（20 kbp band，与 Minimap2 默认一致）。指标：端到端运行时间（reference-based 与 all-to-all）、成本效率（$归一）、功耗效率、内存峰值、stepwise breakdown（seed/chain/extend）、FPGA 资源利用率（LUT/BRAM）、多 FPGA 扩展性、extension 加速器单独对比（band width 512–25K，vs Cheng24/Li21/Liao18/Turakhia18/Teng23）。
  - 主要结果：内存需求 7× 降低（恒定 ~8 GB 系统内存，Minimap2 用 memory chunking 限在 ~60 GB 且降低输出质量）；extend 48 GCUPS/FPGA（双 FPGA 96 GCUPS，mm64 为 27.21）；chaining 单 FPGA 2.21× vs mm64；100× 人类基因组比 mm64 快 1.8×、洋葱（A. Cepa）基因组快 27×（比 Parabricks 快 2.4×）；all-to-all 成本效率约 3× vs mm64；实测功耗 230 W（mm64 320 W、Parabricks 420 W），功耗效率 ≥2.3× vs mm64。注意：Lembas 不做 Minimap2 的启发式 anchor 过滤（避免随机访存），导致下游工作量放大（人类基因组 7.06× 更多 chains），但整体性能与成本效率仍最优。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 无模拟器。Lembas 是真实 FPGA 原型评估（非仿真器/RTL 仿真）：硬件为 2× Xilinx Alveo U50（16 nm UltraScale+，8 GB HBM2、32 个 pseudo-channel、PCIe Gen3x16 ~8 GB/s 双工、~250 MHz），RTL 用 Xilinx Vivado 综合/布局布线生成 bitfile（表 IV 给出各阶段 LUT/BRAM 占用），软件 orchestrator 运行时编程 bitfile、调度 PCIe 上 NVMe↔HBM 数据移动与少量计算。软件基线 Minimap2（开源 https://github.com/lh3/minimap2）；Parabricks minimap2 beta（https://docs.nvidia.com/clara/parabricks/latest/documentation/tooldocs/man_minimap2.html）；NextDenovo（https://github.com/Nextomics/NextDenovo，all-to-all 工作流参数）；PBSIM3（https://github.com/yukiteruono/pbsim3，长读模拟器生成合成 reads）。

- 模拟器模拟什么的性能，修改了什么。
  - （无模拟器，真实原型）评估的"性能"即真实系统端到端/分步运行时间、内存峰值占用、实测功耗（平均功耗取整到 10 W：Lembas 230 W、mm64 320 W、Parabricks 420 W；G³SA/Cheng24 分别按 Parabricks/Lembas 保守估计）。资源利用率来自 Vivado 布局布线报告：Seed 361,624 LUT (41.53%) / 517 BRAM (38.47%)；Chain 273,951 LUT (31.46%) / 200 BRAM (14.88%)；Extend 431,957 LUT (49.61%) / 105 BRAM (7.81%)。修改内容：三个阶段各自独立综合成 bitfile；sorting kernel 尝试 32 个但无法布局布线，最终 16 个（PCIe 已是性能瓶颈）；host 端 orchestrator 处理 columnsort 转置后多 KB 大块 memcpy 重组；数据规模超过 512 GB 时软件合并多个排序块。

  - 原型使用例子与原理（一次 reference-based 人类基因组比对，输入→输出）：输入 = reference 基因组 + PBSIM3 从真实参考基因组（TAIR10/HG16/DHCU066619）生成的 PacBio CLR 风格合成 reads（coverage 15×–100×）→ ①seed：host 把 reference/query 送入 minimizer parse kernel（滑动窗口取字典序最小 k-mer，输出 16B 〈minimizer,index〉 元组）→ 经 PCIe 溢出存 NVMe → columnsort 加速器 4 轮列排序（每轮：NVMe→HBM 256 MB 列→16 个 16-to-1 单发射 merge-sort kernel 排序→转置写回 NVMe，PCIe 8 GB/s → 有效端到端 ~2 GB/s）→ 两有序流经 anchor matching kernel 流式 zip 得 〈idxQ,idxR〉 anchors 存 NVMe → 再 columnsort 按 idxR 排序 → ②chain：anchor 流读回，4×单 PE 前向分数传播流水输出 chains 存 NVMe → ③extend：每 chain 序列送入 16×16 PE 脉动阵列算 SWG 分数矩阵（affine gap，band 20 kbp），8×8 tile 位并行 traceback（历史寄存器编码跨 tile 路径，popcount 跳转，每 cycle 1 tile，HBM 预取 4 tile）→ 输出 SAM 格式结果。全流程中间数据（minimizer 流、anchors、chains）驻留 NVMe 而非 DRAM/HBM，故内存恒定 ~8 GB。作用：证明低成本桌面主机 + 中端 FPGA + NVMe 可达到/超过 3× 价格的 GPU/高端 FPGA 系统的端到端性能与成本效率（3× vs G³SA、5× vs Parabricks 的成本效率；1.8×/27× vs mm64 的性能）。
