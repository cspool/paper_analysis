## DS-ISA: Instruction Set Architecture for Dynamical System Units

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现：面向 Dynamical System Unit（DSU，连续时间模拟演化的动力学系统处理器）的第一个标准化指令集 DS-ISA 及其配套数字控制器微架构（SystemVerilog RTL）。三条实现线：(1) 执行模型——load-lock-evolve-store 统一执行模型（connectivity configuration / data loading / component clamping / evolution management / results retrieval 五个可组合阶段，支持线性推理、迭代训练、退火优化、时变边界 DE 求解等流程，Fig.5）；(2) ISA——极简 9 指令：节点生命周期 N_LOAD/N_LOCK/N_EVOLVE/N_STORE，耦合生命周期 C_LOAD/C_LOCK/C_EVOLVE/C_STORE，加连接配置 CFG_CONN（Fig.6）；64-bit 定长指令格式分 E/N/C 三型（Opcode 1B + Imm_address 4B + Imm_time/Imm_NGID/Imm_CGID_col+row 2B + Reserved 1B），采用间接控制：大尺度 mask（NLM/CLM/CM/GM）存片上 SRAM、指令只携带 32-bit 地址指针，2B 立即数字段装 NGID/CGID/Time 等对数规模量，实现可扩展性；(3) 微架构——前端（Instruction Buffer + Instruction Decoder + 带 scoreboard 的 Instruction Scheduler）、Data Path（Data Memory + DAC/ADC 阵列 + NGID/CGID Select + Input/Output Bus）、Control Path（Mask Memory SRAM + Control Registers：NLM/CLM/CM/GM/Time Registers + Idle Registers，Fig.10）。关键机制：label-and-trigger（N_LOCK/C_LOCK 只是把锁存掩码写入标签寄存器，_EVOLVE 才原子切换选择逻辑触发同步集体演化）；组级执行 + 两级掩码（inter-group GM 管组间同步演化、intra-group NLM/CLM/CM 管组内细粒度）；timer-based time-controlled evolution（Time 总线写 Time Registers 倒计时，归零切回 Idle Registers 锁存结果）；C_EVOLVE 对称部署 1D GM 同时作行/列组选择激活耦合子矩阵，省去第二个地址指针并支持碎片化资源分配/磨损均衡。
  - 实验比较（四类代表应用：ML inference / ML training / optimization / DE solving）：(1) 单任务延迟 vs 问题规模（Fig.11，32 组固定）；(2) 多任务并行延迟与指令 workload 分解（Fig.12，三种容量配置小/中/大 DSU）；(3) 演化并行度（Fig.13：平均每周期活跃节点/耦合数，1024 节点上平均 >60 节点、>3K 耦合同时演化）；(4) stall 占比（Fig.14，迭代类负载 <25% 且随规模下降）；(5) 功耗/面积（Table I：8×8 375.6mW/15.42mm²、16×16 3097mW/37.46mm²、32×8 2714mW/28.16mm²、32×16 3254mW/37.64mm²、32×32 4642mW≈4.6W/79.58mm²）；(6) 与既有模拟 DSU 对比（Table II：BRIM 2000 节点/45nm/250mW、DS-GL 8000/45nm/550mW、DS-TPU 2000/45nm/5.7W、DS-TIDE 4608/45nm/1.5W，DS-ISA 控制器成本按节点数线性折算后对比）；(7) 调度效率（Fig.15）：hazard-aware blocking policy vs 每指令后全阻塞的 serialized baseline。
- 硬件平台是什么，配置是什么。
  - 无真实芯片，采用全开源 EDA 流程实现数字控制逻辑：SystemVerilog 描述 → Yosys 逻辑综合 → OpenROAD 物理设计 → SkyWater 130nm（SKY130）工艺。评估配置：节点组数 32，每组节点数 8（小）/16（中）/32（大 DSU，1K 节点 + 1M 耦合）；ADC/DAC 数量与每组节点数匹配，支持活跃组并发读写；控制器 200 MHz；inference 演化 100ns；optimization 循环 100 次、每次演化 10ns、每轮 10% 节点退火；DE solving 演化-加载循环 100 次、每次 10ns（时变边界条件）；training 100 次迭代、每次 10ns；输入（条件）节点数 = 输出（演化）节点数。混合信号接口按 130nm 同类设计估算：8-bit ADC 1 GS/s、0.72mm²、13.3mW（引 [40]）；DAC 600 MS/s、0.27mm²、2.4mW（引 [6]）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 无模拟器；以 RTL 综合 + 物理设计 + 周期级控制器性能建模评估。开源 EDA 工具链：Yosys（https://github.com/YosysHQ/yosys ）、OpenROAD（https://github.com/The-OpenROAD-Project/OpenROAD ）、SkyWater SKY130 PDK（https://github.com/google/skywater-pdk ）。周期级延迟/并行度/stall 评估的具体仿真手段论文未明确说明（推断为 SystemVerilog 仿真，未给工具名）。
- 模拟器模拟什么的性能，修改了什么。
  - 不适用（无修改模拟器）。评估的是 DS-ISA 控制器本身的性能/开销：综合+布局布线得功耗面积；200 MHz 下按指令周期建模单任务/多任务延迟、每指令 workload（Σ n(t)，t 周期内活跃组件数求和）、演化并行度（Σ n(t)/T）、stall 周期占比；对比对象为 serialized baseline（模拟先前无重叠执行控制的 DSU 控制器，每指令后强制阻塞）。

  - 开源：DS-ISA RTL 与评测代码未开源（论文无链接，联网搜索未发现公开仓库，无法确认）。工具链开源：Yosys 综合 + OpenROAD 布线的脚本化使用（Yosys 读入 SystemVerilog 网表生成 → OpenROAD 做 floorplan/placement/routing/STA → GDSII），SKY130 PDK 提供标准单元与工艺参数。
  - 评估原理与输入→输出全过程：输入 = 9 条指令组成的应用指令流（如 ML 推理：CFG_CONN[CM Addr,NGID] → C_LOAD[Data Addr,CGID] → N_LOAD[Data Addr,NGID] → C_LOCK[CLM Addr,CGID] → N_LOCK[NLM Addr,NGID] → N_EVOLVE[GM Addr,Time] → N_STORE[Data Addr,NGID]）+ DSU 配置（32 组 × 8/16/32 节点、200 MHz、演化时长）+ 应用参数（inference 100ns；optimization/DE/training 10ns × 100 循环）→ 指令流进控制器前端，scoreboard 按 blocking policy（data 类间红阻塞结构冒险；evolve 对访问演化组件的后续指令黄阻塞；CFG_CONN 对 data/evolve 红阻塞防全局扰动；LOCK 类绿放行、仅对后续 _EVOLVE 黄阻塞保证 RAW 语义）调度 → Data Path 经 DAC 写/ADC 读节点与耦合、Control Path 应用两级掩码 + Time Registers 倒计时触发演化 → 逐周期累计每指令活跃组件数 n(t) 得 workload 分解与演化并行度，累计 stall 周期得 stall 占比 → 综合/物理设计输出面积与功耗（32×32 全配置 4.6W、79.58mm²）。作用：证明 9 指令 ISA 与组级两级掩码控制器能以 4.6W 数字开销管理 1K 节点/1M 耦合 DSU，迭代类负载 stall <25%、延迟低于 serialized baseline，支撑其上的编译器/软件栈构建。
