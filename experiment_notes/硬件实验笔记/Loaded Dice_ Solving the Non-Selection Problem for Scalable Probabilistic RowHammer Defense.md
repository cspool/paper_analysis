## Loaded Dice: Solving the Non-Selection Problem for Scalable Probabilistic RowHammer Defense

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 in-DRAM 概率性 RowHammer 缓解方案 PrISM（Probabilistic Intersection-based Sampling Mitigation）：在 DRAM 内部（每 bank）放置三个小型 SRAM 结构——Sampled Slot Queue (SSQ，缓冲已采样激活槽的行地址)、Sampled History Queue (SHQ，保留前 L 个 mitigation window 内"已采样但未选中"的行作为交集历史)、Pending Mitigation Queue (PMQ，缓冲已选中但尚未执行的缓解行，每项含行地址 + 3-bit 饱和激活计数)。每个 mitigation window 内随机采样 R 个激活槽位写入 SSQ，与 SHQ 比对产生"交集"（intersection，即新采样行已在历史中出现过）的行入 PMQ 申请额外缓解；窗口结束再随机选一个非交集采样行作为默认缓解候选。PMQ 满或某项计数超过 tardiness threshold (TPMQ=4) 时通过现有 JEDEC Alert Back-Off (ABO) 协议请求额外缓解（每个 Alert 一个 RFMab，350ns 停通道）。论文还评估 PRAC（以 QPRAC [101] 为安全 baseline：每个 Alert 触发 1 个 RFM + 5-entry 优先级服务队列）和 MINT [72]（固定概率缓解，带延迟缓解队列支持 refresh/RFM 推迟）。设计参数：窗口 W、每窗口采样槽 R、回看窗口 L（SHQ 条目 = (R−1)×L）；默认配置见表 II：TRH-D=1000（W=72,R=4,L=12,SHQ 36）、750（W=72,R=7,L=11,SHQ 66）、500（W=72,R=7,L=41,SHQ 246）、250（W=48,R=9,L=79,SHQ 632）；PMQ 16 项、TPMQ=4、SSQ 13 项（S_SSQ ≥ (2R−1)−⌊(2R−1)/4⌋，R=9 时需 13）；W ≥ 4R 约束保证 ABO 排空速率；ultra-low TRH-D≤250 时启用 Rubix 风格随机地址映射（把邻近 cache line 打散到不同行，减少良性交集，TRH-D=250 时 Alert 率从 312.3 降到 50.3/1K tREFI，6.2×）；所有概率缓解（含 MINT、PrISM）使用 fractal mitigation 防御 transitive attacks。安全分析用 circular-X-rows 最坏攻击模型 + Saroiu-Wolman 模型 + 5M-epoch Monte Carlo 验证，目标每 bank MTTF 10,000 年。
  - 实验比较：PrISM vs PRAC(QPRAC) vs MINT，在 TRH-D=250/500/1000 下的性能（weighted speedup over 无安全 DDR5 baseline）、每通道每 tREFI 的 RFM 频率（Fig.8）、TRR 频率敏感性（Fig.9）、PMQ 大小敏感性（Table VI）、与 MOAT/Chronus/MoPAC 的对比（Fig.10）。结果：TRH-D=500 时 PrISM 平均 slowdown 0.2%（PRAC 14%、MINT 7.1%）；TRH-D=250 时 PrISM 1.5%（MINT 10.7%，7.1× 降低，MINT 在 470.lbm/434.zeusmp/520.omnetpp 上甚至超过 PRAC）；PrISM 每 tREFI RFM：500 时 0.03、250 时 0.45（MINT 对应 4 和 10）；最坏单 workload slowdown 9.4%（510.parest @250）；无 TRR 时 PrISM slowdown 升到 3.2%（每 72 激活一个 RFM）；PMQ 16 项性能饱和（0.2%）。DoS 分析：circular-X 攻击下最坏 slowdown 1.39×/1.68×/2.31×（TRH-D 1000/500/250），吞吐损失 ≈ 7R/(W+7R)。
- 硬件平台是什么，配置是什么。
  - 无真实硬件，纯模拟器。系统配置（Table IV）：8 核 OoO（4GHz、4-wide、512-entry ROB）、共享 16MB LLC（8-way、每核 32 MSHRs）、Minimalist Open-Page (MOP) 地址映射 [38]、FR-FCFS 调度器（cap 1）、单通道单 rank 32Gb DDR5-8000B（4 bank × 8 bank group × 1 rank × 1 channel，每 bank 128K 行、行 8KB）。DRAM 时序（JEDEC DDR5 规范）：tRCD=tCL=16ns、tRAS=32ns、tRP=16ns、tRTP=7.5ns、tWR=30ns、tRC=48ns、tRFC=410ns、tREFI=3.9µs、tRFMab=350ns、tRFMsb=190ns。默认每个 tREFI 提供一次 TRR 机会（每两个 tREFI 一次，敏感性见 Fig.9），proactive RFM 用 Same-Bank RFM (RFMsb)。PRAC 计时开销：tRP 16→36ns (2.25×)、tRC 48→52ns。
- 模型是什么。数据集和bench分别是什么。
  - 无机器学习模型。Workload：57 个开源 workload（Ramulator2 自带 trace [77]），来自 SPEC2006/2017、TPC、Hadoop、MediaBench、YCSB，按 row-buffer misses per kilo-instruction (RBMPKI) 分三类（Table V）：High 17 个（RBMPKI≥10：429.mcf、470.lbm、434.zeusmp、519.lbm、549.fotonik3d、459.GemsFDTD、450.soplex、462.libquantum、433.milc、437.leslie3d、510.parest、520.omnetpp、483.xalancbmk、wc_8443、wc_map0、482.sphinx3、tpch2）、Medium 21 个（[1,10)：471.omnetpp、grep_map0、473.astar、505.mcf、tpch17、436.cactusADM、jp2_decode、507.cactuBSSN、557.xz、tpcc64、jp2_encode、ycsb_aserver、ycsb_eserver、ycsb_beserver、ycsb_dserver、500.perlbench、523.xalancbmk、tpch6、ycsb_abgsave、456.hmmer）、Low 19 个（[0,1)：401.bzip2、502.gcc、435.gromacs、458.sjeng、445.gobmk、525.x264、508.namd、531.deepsjeng、544.nab、526.blender、403.gcc、464.h264ref、h264_encode、447.dealII、444.namd、481.wrf、541.leela、538.imagick、511.povray）。8 核同构混合，每核 250M 条指令（每次运行共 2B 条）。Benchmark 输出为加权 speedup（weighted speedup over 非安全 DDR5 baseline）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源情况：PrISM 完整开源 https://github.com/STAR-Laboratory/prism （MIT license），仓库含 perf_analysis/（Ramulator2 仿真，复现 Fig.7/8/9 与 Table VI）与 security_analysis/（纯 Python 解析模型 + Monte Carlo 验证，复现 Fig.5/6）。模拟器为 Ramulator2（https://github.com/CMU-SAFARI/ramulator2，cycle-accurate trace-based DRAM 模拟器）；论文使用 Ramulator2 内部 OoO core 模型，并引用开放源码的 ChampSim–Ramulator2 集成（https://github.com/STAR-Laboratory/PRAC_TC_ISCA25）做交叉验证（两种设置在 3200–8000MT/s DDR5 下性能差异 <1.2%）。
  - 使用例子与模拟原理：性能实验入口 `cd perf_analysis && ./run_artifact.sh --method slurm --artifact all`（支持 SLURM 与单机执行）；安全分析 `cd security_analysis && python3 prism_circular_security_analysis.py figure8 --w 72 --output-dir ./results --mc-windows 1000000 --mc-seeds 5 && python3 plot_scripts/plot_figure5.py`。模拟器输入 = 各 workload 的 DRAM 访存 trace + 系统/DRAM 配置 + 缓解方案参数（PrISM 的 W/R/L、PMQ 大小；MINT 的窗口大小 11/24/48 对应 TRH-D 250/500/1000；QPRAC 的 Back-Off 阈值按目标 TRH-D 调）。原理：Ramulator2 按 cycle 精确推进 DRAM 命令时序——CPU core 模型产生访存请求 → 内存控制器按 FR-FCFS 调度并经 MOP 地址映射到 bank/row → 每次 ACT 更新该 bank 的 PrISM 采样逻辑（窗口内随机采样 R 个激活槽，SSQ 记录行地址并与 SHQ 比对产生交集入 PMQ；窗口末选默认缓解候选）→ 默认缓解机会（TRR 或 proactive RFMsb）服务 PMQ 中计数最高项；PMQ 满或计数超 TPMQ 时置 Alert → 控制器暂停正常请求并发 1 个 RFMab（350ns）→ 模拟器累计各命令时序与停顿 → 输出加权 speedup 与每 tREFI RFM 频率。作用：在无真实 DDR5 硬件的情况下 cycle 精确量化概率性缓解的带宽/性能开销，验证 PrISM 在低 TRH-D 下保持低 slowdown、RFM 频率远低于 MINT 的结论。
