## Lotus A Multi-FPGA Task Dataflow Architecture to Accelerate Cycle-Level Simulation

- 属于硬件架构的实现是什么？实验比较什么？
  Lotus 是一个多 FPGA 的循环级（cycle-level）仿真加速架构，用于加速 RTL/周期级数字设计仿真。核心思想：不把逻辑像仿真器那样"空间映射"到 FPGA，而是把设计编码为同步数据流图（SDF），由数千个通用 RISC-V 核以"时间映射"（temporal mapping）方式在多个 FPGA 上执行图上的小任务，多个任务随时间复用同一核。实现内容包括：①task unit（输入单元/调度器/输出单元），静态存储整个数据流图（函数指针、输出 token 目的、任务输入存储，永不溢出到内存），按 taskId 索引；②基于 taskId 的分层位图优先级队列（prioritized execution，聚焦关键路径）；③基于 Chandy-Misra-Bryant 保守同步的非投机选择性执行（selective execution，输入不变则跳过任务并发送 null token，逻辑仅占 1%）；④FPGA 内 25×25 两阶段蝶形 token 交换机；⑤跨 FPGA Aurora 通信 shim（滑动窗口重传+流控）；⑥定制 RV32IM 4 级流水线核（1474 LUT）与 128KB L2。实验比较：Lotus（8 FPGA）vs 硬件仿真器 emulator（以 FireAxe 800KHz 估计）vs 128 核 CPU 服务器（2×64核 AMD Zen 3 EPYC 7763 @2.45GHz，128 线程）。结果：Lotus 在 DSL benchmark 上比 emulator gmean 快 42%（NTT 3.09×、MatMult 1.82×、Cores 1.19×、Multicore 0.61×），FPGA 数减少 gmean 2.85×（NTT 7.5×）；每 FPGA 性能提升 gmean 4.05×（NTT 23.2×）；比 CPU 快 gmean 8×。评估指标：仿真速度（KHz）、相对速度、emulator 所需 FPGA 数、每 FPGA 速度、FPGA 资源利用率（LUT 66%/BRAM 61%/URAM 57%/DSP 12%）、功耗（8 FPGA 共 420W，整机 1050W）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  论文本身构建的是真实硬件原型而非模拟器。原型：8 块 AMD Alveo U55C FPGA（每块 68 tile、272 核、400 MHz、HBM2 16GB 17 端口、25×25 蝶形交换机），分布在两台服务器（各 4 FPGA + 2×64核 Zen 3 + 1TB 内存），QSFP28 光链路经 1:4 breakout 线全互联（dancehall/all-to-all，不用交换机），350GB/s 对分带宽，200ns FPGA 间延迟，总成本 $86K。硬件用 Bluespec SystemVerilog 编写，Vivado + RapidWright 手动 floorplan（每 tile 独立形状后复制），400 MHz 运行（实际最高 470 MHz，留 15% 裕量）。emulator 基线估计使用 FireAxe [42]（开源多 FPGA 仿真器，取 cycle-exact 模式 800KHz 速度，乐观估计）。CPU 基线使用并行 Verilator（https://www.veripool.org/verilator/）。
- 模拟器模拟什么的性能，修改了什么。
  Lotus 原型在真实 FPGA 上执行 6 个仿真负载，测量每模拟周期可推进的仿真速度（KHz）：NTT 2474、MatMult 1452、Cores 953、Multicore 485 KHz（DSL）；Vl-NTT 116、Vl-Chronos 165 KHz（Verilog）。修改/构建内容：在每 tile 内实现 task unit（1024 tasks/tile、8K 元素输入/输出 token 存储、最多 15 输入值/63 输出 token/255 输入 token、双版本奇偶周期存储以重叠连续周期）、分层位图优先级队列（1024×2 bit，32 元素/区域，全流水化每周期入队出队）、选择性执行 4 级流水线（比较奇偶周期输入，null token 复制旧值）；核内实现数据/PC 旁路（load-to-use 与 taken branch 最多 1 stall）、指令预取器、输入任务缓冲（任务单元可在当前任务执行时派发下一任务）；L2 采用 write-through L1 + 任务结束时自失效（DeNovo 风格）实现 tile 内一致性；token 网络 4 tile 组集中共享 1 内存通道/交换机端口。

  论文声明开源：http://lotus.csail.mit.edu（web search 未能确认公开仓库，可关注 MIT CSAIL Sanchez 组 GitHub/实验室页面；当前未能确认链接可用性）。使用流程（以 NTT 为例）：①输入：用 Lotus DSL（C++ 嵌入式）或 Verilog（改版 Verilator）描述设计 → ②Lotus 编译器分层映射：PaToH 超图划分先把任务分到 8 个 FPGA、再分到每 FPGA 的 68 个 tile；约束：same-cycle 边通信的任务必须同 FPGA，经内存通信的任务必须同 tile；coarsening + temporal unrolling（2×/4×）提升计算/通信比 → 生成 task unit 配置数据（每个任务的 taskId、函数指针、输出 token 目的地）+ 每 tile 可执行代码 → ③host 经控制接口加载程序并启动 → ④每个模拟周期：token 网络把带 (cycleId, taskId) 的 token 送入输入单元 → 输入单元把值写入输入内存并计数剩余 token，全部到达则该次调用就绪入 ready queue → 调度器按优先级（taskId 序）出队，把输入从输入内存流式送入核 → RISC-V 核执行任务函数（计算 + stream_outputs + finish_task）→ 输出单元为每条输出边产生一个 token（复制输出值），经 FPGA 内蝶形交换机、跨 FPGA 经 Aurora 光链路（200ns）送达消费者 → 各 tile 的核并行执行，选择性执行跳过输入不变的调用并广播 null token → 性能计数器/仿真结果经控制接口返回。作用：用 900 GIPS、每秒 2000 亿次任务派发的并行度，把软件仿真速度推到与硬件仿真器相当（gmean 比 emulator 快 42%）且少用 2.85× FPGA，同时保留软件仿真的编译速度（秒级）与灵活性（支持 RTL 之外的 cycle-level 建模）。
