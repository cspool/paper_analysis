## Hierarchical Wakeup Logic of the Issue Queue for High Scalability

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现为 HWL（Hierarchical Wakeup Logic，层级唤醒逻辑），一个针对超标量乱序处理器 Issue Queue（IQ）唤醒关键路径的微架构设计：将 IQ 逻辑划分为多个 segment，每个 segment 配一个小型、快速、非流水化的 level-1（L1）唤醒矩阵；在 L1 之后放置一个全尺寸、流水化的 level-2（L2）唤醒矩阵（默认 3 级流水）。生产者与消费者位于同一 segment 时用 L1 单周期完成 wakeup-select；跨 segment 时用 L2 流水化唤醒（多出 2 个额外周期）。配套两个调度方案：(1) HSD（HWL-structure-aware dispatch）——按 dataflow graph（DFG）把指令切成 chunks（切边规则：用 last-ready predictor LRP 切掉先就绪父节点的边、生产者执行已完成的边、生产者执行延迟大于 L2 额外流水深度的边），尽量把 chunk 内节点派发到同一 producer segment 以多用 L1；(2) 混合派发模式——按 dispatch failure rate（DFR）在 stalling 与 no-stalling 策略间运行时切换（DFR 每 10k 周期测量，超过 10% 阈值切到 stalling，每 200 个 max stall periods 探测一次 no-stalling 是否可恢复）。额外硬件：segment allocation circuit（DCL/LBMUX/SMUX1/SMUX2/SMCL，支持 bundle 内并行重命名的目标 segment 分配）、LRP（last-ready predictor，类 gshare，8K-entry 4-branch history PHT）。
  - 实验比较什么：(1) IQ 周期时间——HSPICE 测不同 L1 尺寸（12/25/50/100）与 L2 流水深度（2/3）下的 wakeup matrix + select 延迟，相对 200-entry 基线（Fig. 10）；(2) 周期时间 vs IPC 退化权衡曲线（Fig. 11），默认配置取 (N,P)=(25,3)（IPC 仅退化 0.9% 且周期最短）；(3) HWL 使能的微架构 scaling——1.5× 均衡配置（300-entry IQ，前后端 1.5×）IPC 平均 +17.2%、最大 +43.1%（Fig. 12），及 2× 各种非均衡组合（仅 IQ 2×:-0.7%、IQ+frontend 2×:+3.1%、IQ+backend 2×:+6.2%）；(4) HSD 有效性——HSD vs noHSD（不用 LRP、不检查长延迟生产者）在 no-stall/stall 两策略下的 IPC 退化与 producer-segment 派发失败率（Fig. 13/14）；(5) 混合派发——HSD-no-stall（平均退化 1.7%）、HSD-stall（4.6%）、HSD-hybrid（0.9%）对比（Fig. 15），并给出派发尝试分解（成功/失败/阻塞/非 chunk 派发，Fig. 16），难点程序 *deepsjeng/xalancbmk/xz/fotonik3d* 的 chunk 偏大或 IQ 常满；(6) 与 prior 方案对比——在相同周期时间下与 narrowing [3]（IPC 退化 3.2%）、H-SW [11]（3.6%）比 IPC（HWL 0.9%，Fig. 17）；在相近 IPC 下与 MS-rel [9] 比周期时间（MS-rel 仅降 18%，HWL 降 53%，Fig. 18），并测 CAM 广播三类占比（broadcast heard 59% 平均）支持 MS-rel 列压缩受限的解释。
- 硬件平台是什么，配置是什么。
  - 无物理硬件，纯模拟 + 电路仿真。基线处理器配置（Table I，按 Apple M1 与 Intel Alder Lake P-core 的窗口/发射宽度选取）：前端 6-wide、后端 12-wide；512-entry ROB；12-issue 200×200 matrix scheduler IQ；200-entry load/store queue；物理寄存器 512(int)+512(fp)；TAGE 分支预测（64KB 代价）2K-set 4-way BTB、15-cycle 误预测惩罚；功能单元 6 iALU + 1 iMULT/DIV + 3 AGU + 4 FPU；L1 I/D 各 32KB 8-way 64B line（D-cache 3 port、4-cycle hit、non-blocking）；L2 1MB 16-way 64B、14-cycle；L3 4MB 16-way 64B、40-cycle；主存 3200MT/s；stream prefetcher。HWL 默认参数（Table II）：L2 流水深度 3、segment 数 8（L1 尺寸 25）、LRP 8K-entry 4-branch history、DFR 测量间隔 10k cycles、max stall periods 200、DFR 阈值 10.0%。ISA 为 Alpha。
  - 电路延迟评估环境：HSPICE + 亚利桑那州立大学 22nm predictive technology model (PTM)；线延迟（单位长度电容/电阻）基于 ITRS roadmap 投影；版图在 MOSIS λ-based scalable design rules 下手工画到晶体管级。

- 模拟器模拟什么的性能，修改了什么。
  - 模拟一个 Alpha ISA 超标量乱序核的 cycle-accurate 性能（IPC），覆盖 fetch/decode/rename/dispatch/issue/execute/commit 全流水线、随机队列+age matrix IQ、TAGE 预测器、三级 cache、stream prefetch 与 ChampSim DRAM 时序。修改了什么：1) 移除原 SimpleScalar 的 Register Update Unit [34]，加入 reorder buffer、物理寄存器堆、IQ（random queue with age matrix）与 RMT；2) 加入高级分支预测与内存层次特性（TAGE 预测器 [35]、L3 cache、stream prefetcher）；3) 集成取自 ChampSim [36] 的 DRAM 时序代码。HWL 相关新增：IQ 逻辑分 segment + 每 segment 物理独立的 L1 唤醒矩阵 + 全尺寸流水化 L2 矩阵、HSD 派发（RMT 扩展 segment 号/segment offset/长延迟 flag 字段）、LRP 预测器、混合 stalling/no-stalling 派发模式、bundle 内 segment 分配电路。电路侧用 HSPICE 评估 wakeup matrix/select/segment-allocation 的延迟。

  - 模拟器使用示例与原理、输入→输出全过程（以一个 SPEC2017 基准的一小段依赖链为例）：输入 = (a) Alpha 二进制（每个基准用 SimPoint 从 reference input 选出单个代表性的 100M 条指令区域）；(b) 微架构配置（Table I 基线 + Table II HWL 参数：8 segments、L1 25 项、L2 3 级流水、LRP 8K、DFR 10%）；(c) 派发策略开关（HSD on/off、no-stall/stall/hybrid）。模拟推进：fetch 取指解码后进入 rename——RMT 读出每个源寄存器的 producer IQ entry 号、segment 号与 segment offset（bundle 内依赖经 DCL 比较器+优先级编码器、LBMUX/SMUX/SMCL 在第二 rename 级解析，该级延迟经 HSPICE 测得为 sparse-tree adder 的 88%）；HSD 判定该指令是否属于 producer 的 chunk（LRP 预测 last-ready 源寄存器、busy-bit 表查生产者是否已完成、RMT 长延迟 flag 查生产者延迟是否 > L2 额外深度）；若属于 chunk 则派发到目标（producer）segment 的 L1 矩阵并在 L1 写 cell，否则随机选非目标 segment 并在 L2 写 cell（随机选择在派发级前至少一周期投机完成以不增加派发电路复杂度）。执行时：生产者 grant 信号广播 wordline——同 segment 消费者经 L1 bitline 单周期就绪并 select 发射（back-to-back）；跨 segment 消费者经 L2 3 级流水唤醒（第 1-2 级唤醒、第 3 级 select，比基线多 2 个周期）。混合模式：no-stall 下统计 DFR（目标 segment 因容量失败派发数/派发总数，每 10k 周期），>10% 切 stalling（阻塞到目标 segment 有空位），每 200 个 max stall periods 回探一次 no-stall。模拟器每周期推进各部件并统计周期数与 IPC。输出 = 相对基线的 IPC 退化（默认配置平均 0.9%，17/19 基准 LRP 准确率 >95%）、DFR 分布、chunk 尺寸分布（Fig. 8：平均 91% 动态指令属于 ≤16 项 chunk）、1.5×/2× scaling 下的 IPC 变化。电路侧：把 wakeup matrix（L1 25×25 或 L2 200×200）+ select 逻辑版图按 MOSIS λ 规则画到晶体管级，HSPICE 22nm PTM 仿真得延迟——200-entry 基线矩阵+select 延迟归一为 1.0，L1 25 项时 HWL IQ 周期降为基线的 47%（53% 缩减），其中 (25,3) 配置下周期由 L2 3 级流水单级延迟界定。作用：无需流片即可验证"用小型 L1 + 流水化 L2 打破 wakeup-select 关键路径"能否在几乎不损失 IPC（0.9%）的前提下把 IQ 周期缩短 53%，从而解除宽发射/大指令窗口扩展的时序瓶颈。
