## PhaseWeave Phase-Aware Execution on Heterogeneous Chiplet Architectures for Datacenters

- 属于硬件架构的实现是什么？实验比较什么？
  - 实现：异构多 chiplet 服务器架构 + 硬件 Phase Predictor 模块 + Load State 模块 + 收益感知线程迁移（硬件-OS 协同）。四种 chiplet（high-compute / fast-memory / near-network / low-power），全部同 x86 ISA（iso-ISA），线程可透明迁移无需重编译。核心硬件部件：(1) Random Forest Phase Predictor——每 core 一个，Decision Storage SRAM（条目=4-bit feature id + 16-bit 比较阈值 + 12-bit 左右子节点索引，叶子存 2-bit phase label，1-bit 区分内部/叶子节点），feature sampler 聚合 15 个特征（IPC、cache/TLB/branch MPKI、分类后的系统调用频率），并行 traversal engine（15 棵树×深度 5 并行比较器/取指），voting unit 聚合选最高票 phase；每 100µs epoch 末触发，推理 <100 cycles、75 次比较/epoch，占 core 面积 0.02%，异步于应用核、不在关键路径；(2) Load State 模块——读各 chiplet 的软件可写 task-count 寄存器，导出 runqueue 长度给调度器；(3) 迁移调度器运行 benefit-aware 算法（Algorithm 1：U(t,c')=S(p,c')-S(p,c)-λ·Q(c')-C_switch，仅当 U(c*)>θ 且 residency>T_min 才迁移）。实验比较：Baseline（28 核同构 EMR 服务器，iso-area）vs PhaseWeave 无迁移算法变体 vs 完整 PhaseWeave；指标=P99/P50 端到端请求延迟（低/中/高负载=25%/50%/75% baseline CPU 利用率）、SLO（100ms @P99）下最大吞吐（QPS）、面积/功耗/Perf-Watt；另对照 big.LITTLE 类单片异构基线（bigL / bigL-OoO / bigL-Opt，性能核:效率核 1:1/1:2/1:4）、PinToCores 静态映射、单服务独立部署。
  - 结果：P99 延迟平均 -28%/-42%/-65%（低/中/高负载），P50 -30%/-33%/-46%；吞吐 +1.56×（PhaseWeave-NoMigrationAlg 仅 +1.26×）；Perf/Watt +1.92×（99% 面积、82% 功耗）；53.2% epoch 迁移≥1 线程、其中 18.5% 因最优核满载迁往次优核；硬件预测器在未训练过的 DeathStarBench 上平均 91% 准确率；硬件 vs 软件预测器对照：硬件 <100 cycles，软件 50–数百 µs/次（PMU 采集 2-5µs + 上下文切换 4-6µs + RF 推理 40-250µs），AdSim/Django 每请求 250/390 个 epoch → 每请求 >10ms 附加延迟、最大吞吐降 >20%。
- 硬件平台是什么，配置是什么。
  - 全系统仿真平台：QEMU + SST（Ariel core，论文 modified for high-accuracy）+ DRAMSim3 主存 + McPAT（32nm 缩放到 7nm）面积/功耗。PhaseWeave 配置（Table III，共 38 核，iso-area 缩放至约 99% baseline 面积）：10 compute（3.0GHz，6-wide，ROB 512，Ld/StQ 192/114，L1D 48KB，L2 512KB，LLC slice 2.5MB，Mem Lat 15 cycles，BW 17.06GB/s）+ 9 fast-memory（2.5GHz，4-wide，ROB 256，L2 2MB，LLC slice 5MB，Mem Lat 22 cycles，BW 25.60GB/s）+ 9 near-network（2.5GHz，4-wide，L2 512KB，集成 NIC）+ 10 low-power（2.0GHz，2-wide，ROB 128，L2 256KB，Mem BW 17.06GB/s）；L1I 全 32KB；L1 ITLB 256/192/192/32，DTLB 96/64/64/32，L2 TLB 全 2K。片内 2D mesh 3 cycles/hop；chiplet 间 all-to-all 60 cycles 延迟、1Gbps/link。真实系统（Section IV.D 软件模拟）：Intel Emerald Rapids（28 核 2-way SMT 3GHz，128GB DRAM=8×16GB 5600MT/s RDIMM，dual-port Intel E810-XXV 25Gb + dual-port Intel E810-C 100Gb NIC），cpu-freq-utils 调频、Intel CAT/pqos 控内存带宽与 L2 容量（way partitioning 128KB-2MB）。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - QEMU（https://www.qemu.org/）全系统模拟，捕获用户态+内核态指令、访存与系统调用，转发给 SST Ariel core（SST Structural Simulation Toolkit，https://sst-simulator.org/，Ariel 为其中 CPU 模型，论文 high-accuracy 修改）做 cycle 级建模；DRAMSim3（https://github.com/UMD-MEMS/DRAMsim3）建模主存；McPAT（https://github.com/HewlettPackard/mcpat，32nm 技术节点、缩放至 7nm）估面积/功耗。PhaseWeave 本身未提供代码/模拟器链接，联网检索未发现公开仓库（截至 2026-08）；公开材料为微软研究院 PDF（https://www.microsoft.com/en-us/research/wp-content/uploads/2026/04/phaseweave.pdf）。
- 模拟器模拟什么的性能，修改了什么。
  - 模拟完整软件栈（Ubuntu 22.04 + Linux 6.8.0-85 + runtime 库 + DCPerf 负载）的 cycle 级执行，输出端到端请求延迟（P50/P99）、SLO 下吞吐（QPS）、面积/功耗、phase 预测准确率。修改：SST Ariel core 高精度化；新增硬件 Phase Predictor（Decision Storage SRAM、feature sampler、并行 traversal engine、voting unit）、Load State 模块、chiplet task-count 寄存器接口、迁移调度器（Algorithm 1）；DRAMSim3 建模每 chiplet 专属异构内存分区（带宽/延迟按 phase 需求配置）；McPAT 按 Table III 逐核配置计算面积功耗。软件预测器对照实验：PMU 采集 + 上下文切换 + 软件 RF 推理替换硬件模块。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？至少具体到模拟器模拟性能的原理和模拟器输入到性能输出的全过程。
  - 开源：PhaseWeave 未开源（论文未给链接，联网检索无公开仓库，截至 2026-08）；底层基础设施均开源（QEMU、SST、DRAMSim3、McPAT、DCPerf https://github.com/facebookresearch/DCPerf 、DeathStarBench https://github.com/delimitrou/DeathStarBench）。模拟器输入到性能输出全过程：输入 = 工作负载请求流（DCPerf 五应用 Django/Mediawiki/FeedSim/AdSim/TaoBench，Poisson 到达间隔，25%/50%/75% baseline CPU 利用率三档负载）+ 微架构参数表（Table III）+ 互连参数（mesh 3 cycles/hop、跨 chiplet 60 cycles、1Gbps/link）+ 负载 trace → QEMU 逐指令捕获用户态/内核态执行与系统调用 → SST Ariel 按 chiplet 类型对每指令做 cycle 级流水线/缓存/TLB/ROB 建模（compute 宽发射大 ROB；fast-memory 大 L2+高带宽；near-network 集成 NIC 减 PCIe 开销；low-power 精简核）→ 每 100µs epoch 末硬件 RF 预测器采样 15 个特征并遍历 15 棵树（并行比较器）投票输出 4 类 phase → Load State 报告各 chiplet runqueue 长度 → 调度器按 Algorithm 1 计算 U(t,c')，若超阈值则标准 context switch 把线程移入目标 chiplet runqueue → DRAMSim3 建模异构 DRAM 分区的带宽/延迟（含 NUMA 式页迁移）→ McPAT 按 Table III 逐核估面积功耗 → 汇总输出 P99/P50 延迟、SLO 吞吐 QPS、Perf/Watt，从而量化 65% 尾延迟降低、1.56× 吞吐与 1.92× Perf/Watt。
