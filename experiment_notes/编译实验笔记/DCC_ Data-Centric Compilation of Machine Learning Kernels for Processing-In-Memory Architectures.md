## DCC: Data-Centric Compilation of Machine Learning Kernels for Processing-In-Memory Architectures

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为 DCC：首个面向 PIM 系统的 data-centric ML 编译器，在统一 tuning 流程中联合协同优化"数据重排策略（tensor 数据如何在 PIM core 间分区）"与"loop 级计算调度（嵌套循环如何拆分并分配到 PIM core）"。五个组件：(1) Multi-Layer Abstraction 多层抽象——把 PIM 内存层次映射为计算层次：System 级（Host xPU + Host 内存空间 + PIM 设备）、PIM Group 级（同 channel/rank 的多 PIM core，支持 group 级广播指令与组级专用计算单元）、PIM Core 级（单个处理单元 + 其本地 bank），把编译器与后端语义解耦；(2) Data-Centric Schedule Generator 数据优先调度生成器——先枚举数据张量在 PIM 组/core 上的所有候选数据分区（data tiles），再映射到循环划分（compute tiles）生成 tiling drafts，四阶段 = ①Dimension Set Construction（张量维度经 loop 变量映射为映射函数 F(b)=b+1、F(i)=i*2 等，收集 reference set，共享同一 loop 变量的维度合并为 complex dimension set）→ ②Data-Tile Construction（对每个 dimension set 做 [1,k] 组 × [1,m] 核的全分配穷举 DFS + memoization，递归 avail_resources_{i+1}=avail/allocated，每个 draft 每 part 记 [组数, 核数, representative mapping]）→ ③Draft Pruning（3 条规则：等价 representative mapping 的冗余 draft 去重；SIMD 对齐——d-way SIMD 下每核分配的维度集大小非 d 倍数即剪枝，如 16-way MUL 下 4 核分 16 元素每核 4 非 16 倍数被剪；执行性能等价——各组 worst per-core 性能相同则去重）→ ④Data-Tile to Compute-Tile Mapping（core 级 data-tile 大小=dimension_size/(groups×cores)，compute-tile=映射函数结果落在 data-tile 内的 loop 变量范围，再导出全部张量数据索引；索引非连续时两条策略：扩展为连续区间 vs 保持原索引集，二者都生成由 predictor 选择）；(3) PIM-Specific Code Optimizer——数据重排优化：利用可控片上内存（GPU shared memory）做 staging，块大小 B=on-chip_memory/N（N=PIM channel 数），串行 N 次 Host 读入片上后并行 N 路写 PIM channel，使 Host 读与 PIM 写都获得 channel 级并行（无片上内存则用 PIM 后端默认 copy/DMA 接口）；计算代码优化：分级命令生成——优先 group 级广播指令（对组内各 core 数据 padding 到相同大小保证相同地址偏移，一条命令驱动全组，减少内存控制器命令瓶颈），无 group 支持或偏移不同则退化 bank 级并行命令；(4) Coupled Performance Predictor——XGBoost（learning_rate=0.1、max_depth=8、num_boost_round=5000）联合预估数据重排+计算端到端时间选最优 draft：静态尺寸离线训练查 lookup table，动态尺寸（LLM token 变化）运行时在线生成 draft 并预测（可选在线增量训练）；(5) Data-Centric IR——complex_dimset/data_tile/compute_tile/tensor_tile/rearrange[to_PIM_core|to_host]/parallel_PIM/loop 等构造，随后 lowering 到后端 PIM 指令。
  - 实验比较（5 个对比点）：(1) GPU（A100 全部 kernel 跑 GPU）；(2) AttAcc 默认开源实现（batch/head 分布到 16 pCH、第一维分到每 pCH 16 bank group、第二维分到每 bank group 4 bank 的固定分布）；(3) AttAcc+DCC；(4) HBM-PIM（沿用 AttAcc 数据分布）；(5) HBM-PIM+DCC。另在 §2.2 动机实验比较 TVM 式 compute-centric 编译方案（T，公平复刻 ATiM）vs 手工最优（B）vs DCC（D）：TVM 方案数据重排占 kernel 时间 64.68%、比手工最优差 1.28×；DCC 达 1.27× 反超 T 并逼近 B。附加实验：剪枝/预测器消融（Table 3/4）、在线动态预测（MT-NLG 2000 批未见 shape 查询）、能耗分析、编译时间评估。
- 硬件平台是什么，配置是什么。
  - Host：NVIDIA A100 GPU + 5 个 PIM-enabled HBM 类设备（对应 80GB GPU 显存，配置与 [28,33] 一致）；HBM3，5.2Gbps/pin、333MHz；每 HBM 16 pseudochannel(pCH)、每 pCH 2 rank、每 rank 2 bank group、每 bank group 4 bank（每 pCH 64 bank）；时序 tCK=0.79、tRCD=19、tRP=19、tCL=19、tCCD=4、BL=2。后端微架构：AttAcc——每 bank 一个 GEMV 单元、每 channel 一个 softmax 单元；HBM-PIM——每两 bank 共享一个 16-way FP16 FPU 和两个 16×256-bit GRF 寄存器（每 bank 一个）。大规模实验：8×A100（DGX 级）每 GPU 5 HBM 设备（MT-NLG-310B、batch≤64、FP16/FP8）。编译服务器：32-core AMD EPYC 7513 + 128GB DDR4 + A100。
- 开源编译框架是什么。修改了什么。
  - DCC 为作者自研编译器（Python 前端 + PyTorch 集成 + data-centric IR + 后端指令生成），不基于 TVM/MLIR 修改；TVM [61] 仅作为动机实验（§2.2）中的 compute-centric baseline 被复现，非 DCC 基座。评估所用仿真器为修改的开源 AttAcc 模拟器 [28]（基于 Ramulator 2.0 [81]，见硬件架构层条目）。
- 开源情况。基于开源文档和论文，使用例子解释编译框架如何使用？作用是什么？至少具体到编译框架输入到输出的全过程。
  - 开源：GitHub https://github.com/SPIN-Research-Group/DCC（MIT license）；Zenodo 存档 https://doi.org/10.5281/zenodo.19442321（DCC_Artifact.zip）。Artifact 环境：Ubuntu 20.04+、Python 3.8、gcc/g++ 11.4.0（严格要求）、CUDA 12.3+、CMake 3.16.3（严格要求）、Anaconda 25.6.1+、scikit-learn 1.3.2+、XGBoost 2.1.4+；`bash setup.sh` 建环境、`bash run_experiments.sh` 跑三组实验（kernel 性能 Fig.8/9、LLM 推理 Fig.11），结果 CSV 存 results/、PDF 图存 figures/；完整流程约 7–10 天、trace 文件约 90GB；结果与论文偏差预期 ±4%（predictor 离线训练的随机性）。自定义负载：src/test_configs.py 中 custom_kernel_sizes(name,batch,input,output,nhead)（name∈"ATTN"/"GEMV"/"RED"/"VA"/"RELU"）或 custom_inference_sizes(batch,input,output) + run_experiments.sh 追加 conda run -n dcc 命令。
  - 编译框架输入到输出全过程：输入 = 标注 @DCC_kernel 的 Python kernel（仿射 loop 嵌套 + 算术/条件运算，参数与返回值必须是 torch.Tensor 或标量；经 DCC.Layer 替换模型层、DCC.initKernel 初始化尺寸、DCC.Kernel.preLoad() 预载权重，forward() 返回 torch.Tensor）→ ①维度集构建：对张量引用（如 A[b][i]、A[b+1][i*2]）建立映射函数与 reference set，共享 loop 变量的维度合并 complex dimension set → ②数据 tile 构造：DFS+memoization 枚举各 dimension set 的 [组数×核数] 分配与 representative mapping 组合 → ③剪枝：冗余/等价映射、SIMD 宽度对齐、执行性能等价三类规则裁剪（实验：搜索空间平均减 9.01×、编译时间减 5.97×，如 ATTN 5 设备 batch 4 从 32186 草案剪到 4274、9.57s→2.96s）→ ④data-tile→compute-tile 映射：core 级 data-tile 按 dimension_size/(groups×cores) 切分，反解映射函数得 loop 范围，导出全部张量索引（非连续时二选一：扩展连续 or 保持原索引）→ ⑤每个 draft 经 PIM-specific 优化（片上内存 staged 重排 + group/bank 分级命令生成与 padding）→ ⑥Coupled XGBoost 预测器评估全部 draft 端到端时间（15% 样本训练/85% 测试；全部 workload 离线编译仅 ~67s；单 kernel 2–10s 级：ATTN 单 shape 2.96s、272 shape 4.74s；预测器使编译提速平均 3.81×；单 kernel 最优识别准确率 89.28%、LLM 97.37%，选错时仍有真最优 96.56% 性能）→ ⑦最优配置编码进 data-centric IR（complex_dimset→data_tile→compute_tile→tensor_tile→rearrange→parallel_PIM→loop）→ ⑧lowering 到后端指令（AttAcc 的 GEMV/softmax/accumulator 指令或 HBM-PIM 的 16-way FP16 FPU DRAM 计算指令）→ 运行时按 lookup table 选配置执行：input 重排入 PIM bank → PIM 计算 → output 重排回 Host 布局 → 返回结果。目标后端不支持某算子时 DCC 报编译错误。
