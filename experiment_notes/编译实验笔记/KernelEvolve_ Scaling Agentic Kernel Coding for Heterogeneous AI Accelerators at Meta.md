## KernelEvolve: Scaling Agentic Kernel Coding for Heterogeneous AI Accelerators at Meta

- 属于编译框架的实现是什么？实验比较什么？
  - 近似匹配（论文本体为 agentic kernel 生成框架，不直接修改编译器；此处覆盖其作为"编译栈前端服务"消费 Triton/MLIR 流水线自动产出 kernel 的部分）：LLM synthesizer 生成 Triton kernel → Triton 编译器经渐进式 MLIR lowering（平台无关 Triton-MLIR → GPU/AMDGPU/MTIA 专属 dialect → LLVM-IR）→ 生成 NVIDIA PTX/CUBIN、AMD AMDGCN/HSACO、MTIA RISC-V 二进制（多目标编译架构，图 2）。它把"编译器的输入"从手工 kernel 变成检索增强 prompt 合成的产物，并集成编译器生态工具：(1) Triton MPP（Meta 内部 Multi-Pass Profiler，基于 compiler transform 的联邦 profiling 框架：以 job graph 组合 MLIR 级插桩、profiling pass、trace synthesis，在 TTGIR 层以最小扰动 profile warp-group 操作/async copy/TMA 传输，融合多遍结果归因）(2) MTIA-Triton 的 emit_cxx=True 编译选项暴露中间表示（RISC-V vector intrinsics、circular buffer 读写指针管理、SFU 初始化、core affinity），replay_cpp 免全量重编译快速迭代（constexpr/编译选项已 bake in）。
  - 实验比较：无 compiler-to-compiler 直接对比；以"生成 kernel vs torch.compile 编译的 PyTorch 基线"验证自动化生成端到端有效性（160 ATen 算子×3 平台=480 配置 100% 正确；KernelBench 250 题 100% pass；生产 1.25-17× speedup；开发时间从周级降到小时级）。
- 硬件平台是什么，配置是什么。
  - NVIDIA A100/H100、AMD MI300/MI350、MTIA v2i/v3，经 Bento 解释器环境（meta_kernel_gpu/amd/mtia_interpreter，Conveyor CD 每日重建部署）执行编译+验证；生产 Triton 为 Meta 内部 trunk 版本（与开源版略有差异）；MTIA 编译目标为 RISC-V。
- 开源编译框架是什么。修改了什么。
  - 底层编译框架：Triton（https://github.com/triton-lang/triton）、Meta Triton fork / TLX（https://github.com/facebookexperimental/triton）、OpenAI Gluon（triton-lang/triton 内）、MTIA-Triton（triton_mtia，含 eager launcher mtia_triton_launcher）。修改了什么：KernelEvolve 不修改编译器本身；它新增的是生成端（LLM synthesizer + universal operator + 图搜索状态机）、检索端（持久知识库 hardware/{nvidia,amd,mtia}/、guidance/、constraints/ 分层文件系统 + index.md 导航 + BigGrep/Glean 代码搜索）、评估端（evaluation code generator 确定性生成 TritonBench/Torch Profiler/NCU/Proton/MTIA Insight harness；Triton MPP 集成）——整体构成 compiler-as-a-service，kernel 评估在 FaaS 上远程执行。
- 开源情况。基于开源文档和论文，使用例子解释编译框架如何使用？作用是什么？至少具体到编译框架输入到输出的全过程。
  - 开源情况：KernelEvolve 未开源（无代码链接，无法确认）；Triton、TritonBench（https://github.com/meta-pytorch/tritonbench）、TLX fork 开源。编译框架输入→输出全过程（GEMM on H100 为例）：输入 = kernel 规格（算子语义 + 生产 shape 分布）→ LLM synthesizer 由 context memory sub-agent（分析 profile/错误/正确性产物、动态 prompt 合成，token 预算 64K-1M）与 deep search sub-agent（按 index.md 两级检索：先按平台/瓶颈/阶段查 index，再取硬件文档，如 hardware/nvidia/arch/tensor_cores.md → hardware/nvidia/tlx/{overview,warp_specialization,async_tensor_core_operations}.md → code_samples/{hopper-gemm-pipelined,hopper-gemm-ws}.py）合成 prompt → 外部 LLM（Claude 4.5、GPT-5）或内部（Meta CWM、Llama on Twine）生成 Triton kernel 候选 → 评估代码生成器把标准双实现接口（PytorchModel/TritonModel/get_inputs）确定性转为各工具 harness → 解释器环境编译执行：Triton 源码 → 多层 MLIR lowering → 目标二进制（PTX/AMDGCN/RISC-V），TritonBench 校验正确性（torch.allclose 容差）与 speedup，MPP/NCU/Proton/MTIA Insight 采集跨层 profile → 结构化结果写回 metadata store（node id/pid/score/is_buggy/path_ref，SQL CTE 支持图遍历/跨 session 复用/崩溃 checkpoint）→ context memory sub-agent 生成 overview.md（瓶颈诊断与优化建议）并更新下一轮 prompt → 图搜索按 fitness 选择/扩展/终止。输出 = 生产可部署优化 Triton kernel + 验证/profile 报告 + 搜索历史。作用：把"专家 2-8 周手工 kernel 开发"降为"小时级自动化"，并让编译流水线对 LLM 训练语料中缺失的私有架构（MTIA，通过 knowledge injection 教 LLM 用 SFU/LUT、cb_multiplier、use_dual_core、cross-PE broadcast/reduction、pe_runtime_barrier 等）也能产出正确高效 kernel。
