## Dynamic Scheduling for AI Accelerators via TISA

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为语义保持编译器（semantics-preserving compiler）：端到端保留算子边界、类型化依赖（RAW/WAR/WAW）与资源亲和性，把高层模型逐层 lower 为硬件可消费的 TISA tile 指令。五级流水：① Framework bridge——用 torchxla 前端接入 PyTorch/JAX/TensorFlow，导出框架图到 XLA/StableHLO dialect，TISA 的 OpType 分类与 StableHLO 算子抽象对齐；② Graph compiler（GC）——MLIR 基础上消费 StableHLO IR，做 fusion、tiling（64×64 tile，贴合 Epoch 256 KB staging buffer；不可整除边界生成 edge tile，用精确 Shape/TileMem 免 padding）、locality 重排，输出带算子边界与类型化依赖边的软件调度 tile 图（自定义 MLIR dialect）；③ Fusion compiler（FC）——把融合子图特化为 TISA 兼容算子，定义自定义 TISA dialect（tisa.gemm、tisa.softmax），OpType 编码算子语义、UnitMap 编码资源意图（执行单元类）、TileMem 编码符号化内存范围/scope；④ TISA generator + 后端——虚拟 tile 级 ISA 统一多后端，OpType 静态绑定张量/向量/DMA 单元类；⑤ Runtime interface——编译产物每 tile 输出描述符（OpType/UnitMap/TileMem）组成就绪集填充运行时 WQ/IQ。关键设计：编译器在 tile 粒度截断 lowering（不再 lower 到细粒度 ISA 指令），ping-pong 缓冲只需分配两 buffer + 交替发射 TISA tile，无需循环展开/指令重排（运行时调度器负责重叠）。
  - 实验比较：① Epoch 上三配置消融隔离编译器与调度器贡献——Naive TISA（仅接口+fence 手工依赖）vs TISA+Static（编译期静态软件流水+fence+重排）vs TISA+Dynamic（同编译器优化+硬件动态调度），比执行周期（表 VI）与 Accumulated Overlap Score（表 VII/VIII）；② 与 GPU 编译栈对比——Epoch(TISA 编译产物) vs A100/H100 上 TensorRT 10.3.0（ResNet50/BERT）与 TensorRT-LLM 0.12.0（GPT-J/LLaMA2/DeepSeek-R1）端到端延迟（表 IX）；③ 可移植性——CPU 上 Triton-TISA（语义指导编译优化：kernel 融合、循环序、内存局部性）vs Torch-Manual（标准 PyTorch 算子组合），比层级/全模型执行时间（图 7）；④ FA3 案例——编译器自动生成的 TISA FA3 kernel vs 手调 CUDA FA3（代码量 -30%、同步频率 -50%、性能在手调基线的 5% 内）。
- 硬件平台是什么，配置是什么。
  - 编译目标：Epoch AI 加速器（TISA-NPU 后端，LLVM 定制 lowering 把 TISA 元数据嵌入最终二进制）+ CPU（TISA-CPU 后端，功能验证/参考执行，tile 串行但语义描述符一致）。实验平台：Epoch（32 核、1 GHz 真硅片）、NVIDIA H100（132 SMs、80GB HBM3）、NVIDIA A100（108 SMs、40GB HBM2）、Intel Xeon 6348（56 核、512GB DDR4）。GPU 软件栈：driver 550.127.0、CUDA 12.1、cuDNN 9.1.0、TensorRT 10.3.0、TensorRT-LLM 0.12.0。CPU 对比实现基于 PyTorch 算子库 + Triton。
- 开源编译框架是什么。修改了什么。
  - 基于开源编译基础设施：MLIR（https://mlir.llvm.org/，GC 与 FC 均 built atop MLIR，FC 定义自定义 TISA dialect）、StableHLO（IR 消费）、torchxla（https://github.com/pytorch/xla，框架桥前端）、LLVM（TISA-NPU 后端 lowering 路径）。修改/新增：在 MLIR 上新增语义丰富的自定义 TISA dialect 与 GC/FC pass 管线（保留算子边界、类型化依赖边、UnitMap/TileMem 语义），TISA 生成器与 NPU/CPU 双后端；未修改 StableHLO/MLIR 本体语义。对比侧 Triton（https://github.com/triton-lang/triton）与 PyTorch 算子作为 CPU 可移植性实验基线。

  - 论文未给出 TISA 编译器/GC/FC/TISA 生成器代码开源链接，联网搜索未找到公开仓库（Epoch 为商用芯片）；依赖的开源组件 MLIR/StableHLO/torchxla/LLVM/Triton 均可公开获取。
  - 输入到输出全过程（以 FA3 融合注意力为例）：输入 PyTorch 模型（Q/K/V）→ torchxla 前端导出到 StableHLO（XLA 方言）→ GC 在 MLIR 上做 fusion（QK^T、softmax、AV 融合为 M0/S/M1 三 tile 类型）与 64×64 tiling（不可整除边界生成 edge tile，精确 Shape/TileMem 免 padding 开销）→ 输出软件调度 tile 图（带类型化依赖边）→ FC 把融合子图特化为 TISA dialect 指令：tisa::gemm<me>(s_P,s_Q,s_K)、tisa::softmax<ve>(s_S,s_P,state)、tisa::load<de>(s_Q,Q) 等（Fig.5 右），每条携带 OpType/UnitMap/TileMem/依赖描述符 → TISA generator 统一表示后经 TISA-NPU 后端 LLVM lowering 嵌入 TISA 元数据生成最终二进制；运行时可执行二进制发射每 tile 描述符填充 WQ/IQ 由硬件调度器消费。作用：把 CUDA 式 8 处手工同步（bar.sync/wgmma::wait/warpgroup_commit_batch）全部消除为语义感知依赖解析；TISA 生成的 FA3 代码量 -30%、同步频率 -50%、性能在手调基线 5% 内；在 Epoch 上 Dynamic vs Naive 达 1.52–1.92×、vs Static 再高 1.14–1.63×（表 VI）；CPU 上语义指导编译（Triton-TISA vs Torch-Manual）ResNet50 1.13–1.19×、BERT 1.02–1.20×、LLaMA2 1.14–1.18×（图 7）。
