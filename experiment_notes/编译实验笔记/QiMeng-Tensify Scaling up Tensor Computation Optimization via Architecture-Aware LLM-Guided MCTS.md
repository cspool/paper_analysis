## QiMeng-Tensify Scaling up Tensor Computation Optimization via Architecture-Aware LLM-Guided MCTS

- 属于编译框架的实现是什么？实验比较什么？
  - QiMeng-Tensify（中科院计算所/中国科大，ISCA 2026）是一个图级（graph-level）张量计算自动优化编译框架：把张量计算图的调度问题形式化为 MDP P=(S,A,T,M,R)——状态 S(G,n) = 计算图 + 调度节点（按逆拓扑序规范化处理），动作 A(r,p) = 调度规则 + 参数配置（7 条规则：A1 MultiLevelTiling(tiling factors)、A2 AutoInline、A3 ParallelizeVectorizeUnroll(loop,unroll length)、A4 CrossThreadReduction(split factors)、A5 ComputeAtLocation(compute locations)、A6 AutoBind、A7 InlineConstantScalar），通过无约束图变换扩大变换空间；用 architecture-aware LLM-guided MCTS 求解（LLM 生成 7 规则上的先验概率分布引导 Selection/Expansion，Gumbel 噪声保持探索，Simulation 阶段用 XGBoost 成本模型 + guided local search 做细粒度参数规格，真机执行奖励 R=flops(p*)/t_best 回传），并引入离线 Architecture-aware Prior Adaptation（用 7 个代表子图收集 12,500 次性能测量，蒸馏自然语言启发式自进化 prompt + 离线训练 XGBoost cost model）。实现：~16,000 行 Python + ~1,500 行 C++ 低层调度原语；LLM 用 gpt-5-preview (2025-07-01) via OpenAI API（temperature 0.8、8192 token、失败回退随机游走）；数值验证：候选 kernel 与高精度 Golden Reference 对比，超阈值 ϵ 或 NaN 给零奖励。
  - 实验比较（两层）：①Subgraph 级 9 个子图（LoRA-LLaMA3-lora、GatedMLP-Falcon-7B、GQA-LLaMA3-70B、QKNorm-Chameleon-7B、nTrans-nGPT-1B、RMSNorm-LLaMA2-7B、LayerNorm、SelfAtten、NSA）vs PyTorch v2.7.0、TensorRT v10.8.0.43、TVM(MetaSchedule) commit 567eeed3、Triton v3.2.0、FlashAttention v2.7.3、Welder commit af53ab1、Mirage v0.2.4、Reasoning Compiler commit 1390945；FP32(CUDA core) 与 FP16(TensorCore) 两种精度。结果：FP16 上平均加速 PyTorch 6.49×、TensorRT 2.86×、TVM 1.68×、Triton 2.64×、FlashAttention 1.27×、Welder 13.49×、Mirage 1.29×、Reasoning Compiler 1.31×；FP32 上 vs PyTorch 3.23×、vs MetaSchedule 2.05×。②Network 级 4 个 LLM（Chameleon-7B、LLaMA3-8B、GPT-3-7B-LoRA、nGPT-1B），batch 1/8、seq len 4096，vs PyTorch、TensorRT-LLM v1.1.0、Mirage；A100 平均 1.56×/1.22×/1.30×，H100 平均 1.78×/1.29×/1.30×。另做：prompt 进化/离线 cost model 消融（4 组合）、LLM prior 消融（MCTS vs MLP/RandomForest priors vs DeepSeek-V3.2/Qwen3-max/GPT 5.0，LLM prior 高 20%-30%）、可移植性分析（L0 软件版本 CUDA 11.8→12.4 差距 0.7%、L1 A100→A30 同代 SKU 差距 1.3%、L2 A100→H100 跨代差距 7.7%）。
- 硬件平台是什么，配置是什么。
  - 目标 GPU：NVIDIA A100 with TensorCore（40GB PCIe）、NVIDIA H100 with TensorCore（80GB PCIe），FP32 用 CUDA core、FP16 用 TensorCore。主机端搜索编排（MCTS 逻辑、任务调度）在 Intel Xeon Gold 6330 CPU（112 cores @ 2.0GHz）上运行；MCTS 控制开销用 JAX 并行实现保持 <8%。
- 开源编译框架是什么。修改了什么。
  - 基础是开源 TVM 的 TensorIR：程序定义用 TensorIR 表达，作为初始 IR 捕获算子计算语义。修改/扩展了什么：①新增 7 条图重写调度规则（含参数化规则如 MultiLevelTiling 的多级 tile factors、ComputeAtLocation 的融合位置——限定在满足结构/依赖约束的 top-level 单消费者 untiled 中间 block、CrossThreadReduction 的 split factors），代替 TVM 手工硬编码规则应用策略（如 Table I 的 Tiling+Fusion 固定策略）；②新增 LLM 模块（自进化 prompt 工程 + 语义知识注入编译流程）；③新增 MCTS 搜索引擎（Gumbel-augmented 选择 a*=argmax[g(s,a)+π(s,a)+σ·Q(s,a)]，Q 用移动平均 Q←Q·α+R*·(1-α) 更新，500 迭代/early stopping K=200）；④新增细粒度参数规格模块（XGBoost cost model 预测排序 + TopK 真机测量 + Manhattan 邻域局部搜索）。配套约 1,500 行 C++ 实现低层调度原语。

  - 使用例子（编译框架输入到输出全过程，GatedMLP: O = SiLU(X·W1) ⊗ (X·W2)）：输入 = TensorIR 计算图（初始未调度程序）→ ① MDP 状态化：S=(G,n)，n 为逆拓扑序调度节点，动作空间 A = 7 条调度规则及其参数 → ② LLM-Guided MCTS 迭代（最多 500 次）：Selection 用 Gumbel-augmented 分数沿树下钻（π(s,a) 为 LLM prior logit，σ 平衡先验与经验值）→ 到达未完全展开叶节点时 Expansion：把含 7 规则描述的 prompt（Fig.6：structural characteristics 描述 + 8 条 hardware-aware learned principles + "Return ONLY a 1x7 probability list"）发给 LLM，得到 7 规则概率分布并采样出新规则序列（sketch）→ Simulation：GenerateProgramSketches 生成具体程序，XGBoost cost model 预测排名取 TopK，真机测量执行时间并回填更新 cost model，对 top 候选做 Manhattan 邻域局部搜索微调 tile size/unroll length 等参数（tuning time 预算内）→ 奖励 R=flops(p*)/t_best → Backpropagation 沿路径移动平均更新 Q(s,a) → 输出 = 最优 CUDA kernel 程序 p*。GatedMLP 工作示例（Fig.4 S0→S5）：初始为 4 个分离 kernel（GEMM1、SiLU(exp/add/div/mul)、GEMM2、mul）+ 中间 buffer O1/O2/O3；LLM 识别 SiLU 可融合式 x/(1+e^-x) → AutoInline 融合 SiLU 为单 block（S1）；识别 GEMM1/GEMM2 共享输入 X → MultiLevelTiling + ComputeAtLocation 在共享 tiling loop (i0,j0,k0) 下融合两 GEMM（S2-S3）；compute_at(SiLU, GEMM1)（S4）；再把 MUL 提升进 GEMM2 reduction loop 实现全融合单 kernel、无中间存储（S5）。作用：把"手工硬编码规则策略 + 受限变换空间"改为"可搜索的 policy space π + 扩大空间 + LLM 语义先验引导 + 真机反馈"，自动发现规则系统/模板系统无法表达的跨算子融合（如 SiLU 融合进第二个 GEMM 的 partial reduction），GatedMLP 最终 kernel 比 TVM MetaSchedule 快 2.80×、比 Mirage 快 1.47×；编译时间 A100 上 1.17h~1.92h（GatedMLP 1.37h/SelfAtten 1.83h/LoRA 1.92h/QKNorm 1.17h/nTrans 1.69h，vs TVM 3.08/3.66/2.98/1.53/2.57、Reasoning Compiler 4.53/5.23/5.19/4.29/4.81），另有一次性 ~30h 离线 prior adaptation 开销。
