## AutoFHE: An Automatic Hardware Generation Framework for Domain-Specific FHE Accelerators

- 属于编译框架的实现是什么？实验比较什么？
  - 实现为 AutoFHE：基于 Chisel + FIRRTL 编译栈的 FHE 加速器自动硬件生成框架，把普通领域专用 RTL 加速器设计自动转换为对 TFHE 密文运算的加速器。四步流程：(1) Chisel 加密信号注解——设计者用 `Secure(io.vec1)` API 声明式标记密文信号，AutoFHE 自定义 SecureAnnotation 类（继承 ChiselAnnotation）在 Chisel elaboration 阶段记录注解，序列化阶段由 FIRRTL 后端产出 `.fir`（FIRRTL IR）与 `.anno.json`（Target 字符串定位被注解信号，如 `VecUnit|VecUnit>io.vec1`）；(2) 自动加密组件识别——以设计者注解为种子在 FIRRTL 图（Chisel diagrammer 生成）上 BFS 追踪，标记所有直接/间接依赖密文信号的下游逻辑：算子级（c=Mul(a,b) 中 a 加密则乘器与输出 c 标密）、模块级（复杂模块整体作一个节点）；(3) 基于 CPE 模板的架构翻译——按算子到 CPE 映射规则替换：逻辑/关系运算与算术/密文-明文运算→ciphertext arithmetic 模板（密文×密文用模板内 external product），两输入 MUX→HMUX 模板；bootstrapping 模板按 TFHE 协议自动置于 arithmetic CPE 下游（仅实例化硬件单元，算法级 bootstrapping 时机由算法设计者定）；用 CPE-virtualization 策略让 K 个物理 CPE 时序共享全部逻辑 PE，硬件调度器固化离线搜出的调度策略在线执行；(4) 自动 DSE——双层嵌套优化：外层枚举硬件参数（CPE 微架构参数 PoV/PoD/BFU/IBFU/PoE/PoC/PoK + 物理 CPE 数 K），内层对每个候选用遗传算法搜时空调度（chromosome=|V| 个基因编码节点调度优先级，critical-path-first 初始化种群、order crossover、swap mutation、tournament selection、依赖校验），解析模型评估：latency=max(计算周期,访存周期)、面积=DC 预表征原语线性组合、能量=off-chip/on-chip 访存+计算+片上通信四源聚合，目标可切 Latency 或 EDP（Latency×Energy）。
  - 实验比较：与专家手工 FHE 加速器在同约束下对比——Strix（eNPU，142 mm²、300 GB/s）、MATCHA（加密逻辑/关系，37 mm² 14nm、640 GB/s）、PPGNN（加密查找引擎，57 mm² 14nm、512 GB/s），另比 CPU（Intel Xeon 6148 @2.5 GHz + TFHE 库）与 GPU（NVIDIA A100 + cuFHE/nuFHE）。附加实验：可扩展性（Strix 8→48 CPE、面积预算至 400 mm²）、灵活性（riscv-mini 3 级 / KyogenRV 5 级 RISC-V ALU 生成加密 ALU，200 mm²、640 GB/s）、GA 调度 vs round-robin、unrolling 因子 r∈{1,2,3,4} 扫描、EDP 目标、设计空间可视化、生成耗时开销（每设计编译 20 次取平均）。
- 硬件平台是什么，配置是什么。
  - 生成目标硬件用 Synopsys Design Compiler + TSMC 28nm 综合评估面积、时钟 1 GHz（跨工艺对比做等效面积缩放：MATCHA 的 PTM 16nm 36.9 mm² 等效 TSMC 28nm 156 mm²）。TFHE 参数三组（表 I）：Set1 n=500/N=1024/L=2/k=1（80-bit）、Set2 n=630/N=1024/L=3/k=1（110-bit）、Set3 n=592/N=2048/L=3/k=1（128-bit）。
- 开源编译框架是什么。修改了什么。
  - 基座为开源 Chisel（chisel-lang.org，注解机制类比 dontTouch 特性）与 FIRRTL 编译器：扩展 `firrtl.annotations.Annotation` 实现 SecureAnnotation，自定义 transformation 经 `--custom-transforms` 注入 FIRRTL 编译流程；用 Chisel diagrammer 把 HCL 转 FIRRTL 图。AutoFHE 自身组件（加密组件识别、DSE、调度搜索、硬件模拟器）用 Python 编写。

  - AutoFHE 源码论文未给开源链接，联网搜索未找到公开仓库（IEEE Xplore 11617778 仅有论文，ISCA 2026）。基座与案例输入设计开源：Chisel（https://www.chisel-lang.org）、Vector MulAdd Accelerator（https://github.com/meton-robean/Vector-MulAdd-Accelerator，eNPU 案例的明文 Chisel 起点）、riscv-mini（https://github.com/ucb-bar/riscv-mini）、KyogenRV（https://github.com/panda5mt/KyogenRV）。
  - 编译框架输入到输出全过程：输入 = 设计者按明文语义写的 Chisel RTL（如 Vector MulAdd Accelerator），仅对密文输入端口加 Secure 注解 → Chisel elaboration 记录 SecureAnnotation → FIRRTL 后端产出 `.fir` + `.anno.json` → 自定义 FIRRTL pass 按 Target 字符串定位注解信号 → FIRRTL 图上 BFS 传播加密标记（算子级/模块级）→ 按算子-CPE 映射规则把加密算子绑定到 CPE 模板（arithmetic/bootstrapping/key-switching/HMUX），bootstrapping 置于 arithmetic 下游 → CPE-virtualization：FIRRTL 图抽象为 DAG，GA 搜 PE→物理 CPE 时空调度（依赖约束 j>i、资源约束 |St|≤K、最大化利用率 |V|/(K·(Tmax+1))）→ DSE 外层枚举 (CPEmicro, K) 查面积模型超预算跳过、内层逐候选跑 GA 调度 + 解析性能模型评 latency/EDP → 输出 = 全局最优 (硬件参数, 调度策略)，调度固化为硬件调度器 RTL 与 CPE 池一起生成最终 FHE 加速器。生成耗时（表 IV）：eNPU 203.5 s（Chisel 编译 5 s + FIRRTL 图生成 1 s + 组件识别 0.1 s + DSE 197.4 s）、ALU1 335.1 s、ALU2 672.1 s。
