## æSIP μArch-aware ASIP-ISA Co-Design via Program Synthesis, Equality Saturation, and External Don't Cares

- 属于编译框架的实现是什么？实验比较什么？
  - 实现是 æSIP（ISCA 2026，University of Michigan）的硬件感知程序重写框架（编译优化层，工作流 Fig.4/Fig.6）：输入为自包含 RV32IM 汇编（库函数已手工 inline、伪指令已展开为 canonical 真实指令序列、无外部符号），输出多种语义等价但指令多样性更低、可直接汇编成可运行二进制（.s）的重写变体。四部分：(1) 重写规则发现——扩展 Greenthumb 超优化器框架（Fig.5）：RISC-V 验证引擎（程序状态 State=R×M，指令序列复合状态转移，Z3 SMT 证明 S_spec≡S_synth）＋四个搜索算法（继承 Greenthumb 的 symbolic/stochastic/enumerative 三算法 + 新增 LLM-guided 神经符号搜索，用 Claude Opus 4.5，以 RV32I 软件仿真库中 mul/div/rem 例程作 warm-start，反例喂回 LLM 形成 CEGIS 循环）；候选指令集排除原指令以强制合成替代序列、优先利用不同硬件单元的指令子集以便后续裁剪硬件。共得 51 条重写规则覆盖 26 条指令（Table II：I-type 8 条、Arithmetic 17 条、Branch 14 条、Mult/Div 8 条、Ld/St 4 条；如 or→xor(xor,and)、add→sub rs2 (sub x0 rs1)、mulh→Karatsuba/convolution 风格 mul 序列、lh→lw+slli+srai、blt→bge+jal）。传统三算法对 mulh/div 等 12 小时超时，LLM 搜索几轮内收敛。(2) 分治 equality saturation——用 egglog（egg）e-graph：按 CFG 把程序切成 basic block，每 block 局部饱和（pseudo-root e-class 锚定），orphan e-class（不参与本 block 主表达式树但被其他 block 消费的值）显式链回 block pseudo-root 防误判死代码；局部饱和子图并入单一全局 e-graph（global root），捕获全程序等价空间且避免整体饱和的组合爆炸。(3) ILP 全局提取——把提取建模为 Gurobi ILP（目标 λ·Σw_o·y_o + (1-λ)·Σc_e,n·x_e,n：第一项最小化 distinct 指令类型集合（硬件感知权重 w_o，乘/除法远大于 ALU），第二项最小化指令总数；约束：每激活 e-class 恰选一个 e-node、pseudo-root/orphan 强制激活、父子一致性、opcode 使能变量 y_o 绑定、Big-M 线性化的 level 无环约束）；各 block 共享全局 y_o 变量实现隐式块级并行，全局提取从小时级降到秒级。(4) 后处理——重建表达式图、后序遍历发射汇编，自动跟踪/继承 rd 寄存器，轻量线性扫描寄存器分配器处理重写引入的临时寄存器（live range 不重叠即复用、耗尽 spill 到栈）。λ 扫 27 值（细粒度靠近 λ=0 面积主导区）生成变体族，探索 area-latency 权衡（latency 用 spike 预估、RTL 仿真后精确化）。
  - 实验比较：baseline 是未重写的原程序（PDAG 类方法只 profiling、不改程序）与全局 monolithic equality saturation（受控 e-node/e-class 规模下 1 小时超时）。重写后 distinct instruction 数平均降 31.8%（最高 md5 46.4%，Fig.8）；重写使 ASIP 面积平均多降 17.0%（SKY130 无约束，Table III）；运行时 saturation 1.2-32.4s、extraction 0.3-78.4s（中位 21.9s，Fig.11）；消融（Fig.9）ISA-level only vs +µArch-aware 约束在保留复杂指令的 workload 上差距最大；可扩展性：Rocket 5-stage core 上重写+裁剪面积降 24.6% 无约束 / 13.0% 1.2× 约束（Fig.13）；code size（Fig.12）：32-bit 定长编码平均 2.27× 膨胀（mont64/basicmath 最大），但熵编码（Huffman，距下界 0.5% 内）下平均 0.60×、均匀编码 ⌈log2 N⌉ 开销很小；Turing completeness 保持（每条规则保留同功能类至少一条指令，不会清空某个功能类）。
- 硬件平台是什么，配置是什么。
  - 全部实验 CPU-only：AMD EPYC 9575F 64-Core server（论文报告）；Docker 镜像 polasip/esip:rv32im（Ubuntu 24.04）或 Conda 环境 esip（Python 3.12）；无 GPU/特殊硬件要求（artifact 建议 ≥16 核多核服务器做 variant 并行评估）。软件依赖：egglog 11.4.0（Rust/Cargo 构建）、Rosette v1.1 + Racket 6.7（程序合成）、riscv32-unknown-elf-gcc（GCC 15.1，-O3）、Z3、Gurobi 12.0.x（商用 ILP，需许可）、spike+pk、numpy/scipy/pandas/matplotlib/gurobipy/scikit-learn/networkx。多进程并行后 22 benchmark×27 variant 的 Pareto 探索 44 分钟内完成；artifact 全文扫 ~2 小时，RTL 仿真 ~3 小时、PnR ~6 小时。
- 开源编译框架是什么。修改了什么。
  - 基础框架：egglog（https://github.com/egraphs-good/egglog，MIT，equality saturation/datalog 引擎，版本 11.4.0，论文 ref [79][85]）——重写引擎核心；Greenthumb 超优化器框架（https://github.com/upenn-acg/greenthumb，论文 ref [56]）——提供寄存器/内存/程序 flag/指令语义库与 symbolic/stochastic/enumerative 三搜索算法；Rosette（https://github.com/emina/rosette，solver-aided language，Racket 6.7 实现，ref [72]）；Z3（https://github.com/Z3Prover/z3，SMT 求解器，ref [27]）；Gurobi（商用 ILP）。
  - 修改了什么：①在 Greenthumb 语义库之上新建 RISC-V simulator+validator（RV32IM 状态 R×M、指令序列状态转移、Z3 等价证明），并实现 LLM-guided 第四搜索算法（Claude Opus 4.5 神经符号 + 反例引导闭环）；②用 egglog 构建分治 saturation：basic block 切分、pseudo-root/orphan 链接、局部饱和图并入全局 e-graph；③ILP 提取扩展硬件感知变量——新增指令类型使能变量 y_o 与硬件权重 w_o（现有 e-graph extractor 多为局部贪心）；④后处理发射器 + 线性扫描寄存器分配。框架三段模块化（规则发现/重写/裁剪可独立替换），换新 ISA 只需 4 个 ISA 特定输入：ISA 语义模型、egglog 指令语义、可综合 baseline core、硬件成本模型（Greenthumb 已支持 ARMv7 与 GA 18-bit stack ISA，扩展只需实现对应 ISA simulator/validator）。
- 开源情况。基于开源文档和论文，使用例子解释编译框架如何使用？作用是什么？至少具体到编译框架输入到输出的全过程。
  - 开源情况：是。GitHub https://github.com/CrucibleComputingGroup/aesip（GPL-3.0，README 五阶段 pipeline，frontend/、Saturation/、Extractor/、backend/、program_synthesis/、PdatScorrWrapper/ 目录结构）；Zenodo https://zenodo.org/records/19560118（artifact.zip，稳定存档）；Docker 镜像 polasip/esip:rv32im；artifact_evaluation.ipynb 自包含复现 Fig.8/9/10 与 Table III/IV 四实验；scripts_pipeline/run_pipeline.sh 跑单程序或 benchmark 类别。
  - 使用例子（编译框架输入到输出的全过程）：输入 = 自包含 RV32IM 汇编（如 MiBench bitcnts，含少量 mul/mulh 调用，已 inline 库函数、展开伪指令）→ ① 预处理：CFG 分析切 basic block；② 局部饱和：每个 block 内 51 条重写规则同时应用（mul→add/slli/srai/andi/beq/jalr 组成的 callmul 序列、mulh→Karatsuba/convolution 风格 mul 序列、blt→bge+jal、lh→lw+slli+srai），e-graph 编码全部等价程序空间，orphan e-class 链接保跨 block 值；③ ILP 全局提取：Gurobi 在 27 个 λ 值下选指令类型集与 e-node 组合，硬件权重 w_o 使乘除法单元尽量不被选中 → 每 λ 一个重写变体；④ 后处理：重建表达式树、后序发射汇编、线性扫描寄存器分配（临时寄存器复用/栈 spill）→ 输出可直接汇编运行的 .s 变体；⑤ spike 验证与原程序输出一致 → 变体进入硬件裁剪（见硬件架构条目）。作用：把"减少指令多样性以便裁剪 ASIP 硬件"建模为等式饱和（同时应用所有规则，规避传统编译器的 phase-ordering 问题——重写顺序不再影响结果）+ 硬件感知 ILP 提取（指令类型集与总指令数联合最小化），使程序重写与硬件面积/时延权衡联合优化——同一程序产生一族 (程序, 面积, 频率, 时延) 变体构成 Pareto 前沿，支撑后续 don't care 裁剪与 ecosystem 级 ISA 共享。
