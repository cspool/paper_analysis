## Loaded Dice: Solving the Non-Selection Problem for Scalable Probabilistic RowHammer Defense

- 属于芯片设计的实现是什么？实验比较什么？
  - 实现为 DRAM 芯片内部的概率性 RowHammer 缓解结构优化（PrISM，Probabilistic Intersection-based Sampling Mitigation）：与 PRAC 的"每行激活计数器 + 每次激活读改写更新计数器"的 DRAM core 改动方案（tRP 16→36ns、tRC 48→52ns，核心面积增约 9%）形成对照，PrISM 不做 DRAM array/接口改动，仅在每 bank 增加三个小型 SRAM 队列——Sampled Slot Queue (SSQ，13 项)、Sampled History Queue (SHQ，36–632 项按目标阈值)、Pending Mitigation Queue (PMQ，16 项)——复用现有 JEDEC Alert Back-Off (ABO) 协议（Alert 后控制器发 1 个 RFMab，每 RFM 350ns 停整个通道）请求额外缓解；随机采样由 in-DRAM 7-bit TRNG（290µW：90µW 静态 + 200µW 动态）实现，也可用 DRAM 随机现象驱动的 in-DRAM TRNG 设计（QUAC-TRNG 等）。每 SHQ/SSQ 项存 17-bit 行地址 + valid bit（18 bit），PMQ 额外 3-bit 饱和激活计数；每选中 aggressor 最多刷新 4 个 victim 行（fractal mitigation 抗 transitive attacks）。ultra-low TRH-D≤250 时在芯片层启用 Rubix 风格随机行地址映射（把空间局部性打散到多行）。配置（表 II）：TRH-D=1000（SHQ 36 项）、750（66）、500（246）、250（632，W=48/R=9/L=79）。
  - 实验比较：存储与功耗开销 vs 安全 counter-based in-DRAM 缓解（Mithril [46]、ProTRR [58]）；性能 vs PRAC(QPRAC)、MINT、MOAT、Chronus、MoPAC。结果：TRH-D=500 时 PrISM 每 bank 仅 625B SRAM（TRH-D=1000 时 152B），比 Mithril（1082×27-bit 项）小约 20×、比 ProTRR（>16K 项）小约 170×（TRH-D=500/250 时分别 20×/13× 与 170×/154×）；PrISM 每选中 aggressor 刷新 ≤4 victim 行，Alert 触发的缓解平均每 20 tREFI 一次（@250），刷新功耗占比 0.14%（若每 tREFI 发则 2.8%）；PrISM SRAM 动态功耗 CACTI-7.0 估计 1.5mW（@500）/2.4mW（@250），为 Micron 功率计算器估计的 245mW DRAM 芯片功耗的 0.6%/1.0%；TRNG 290µW 比 DRAM 芯片功耗低三个数量级；per-activation 逻辑落在 tRC 内、无 DRAM 时序开销。
- 模拟器名，模拟器链接（web search），或论文修改的模拟器。
  - 性能/时序用 Ramulator2（cycle-accurate trace-based DRAM 模拟器，https://github.com/CMU-SAFARI/ramulator2），论文在 Ramulator2 中加入 PrISM 的 SSQ/SHQ/PMQ 逻辑与 ABO 交互，并用 Ramulator2 内部 OoO core 模型（与开源 ChampSim–Ramulator2 集成 https://github.com/STAR-Laboratory/PRAC_TC_ISCA25 交叉验证，差异 <1.2%）。面积/功耗评估用 CACTI-7.0（https://doi.org/10.1145/3085572，估计 SRAM 动态功耗）与 Micron System Power Calculator（https://www.micron.com/support/tools-and-utilities/power-calc，估计 DRAM 芯片功耗与刷新功耗）。安全/容量分析用论文自带纯 Python 解析模型（SHQ 占用稳态固定点模型 + Saroiu-Wolman 模型）与 5M-epoch Monte Carlo 模拟。PrISM 完整开源：https://github.com/STAR-Laboratory/prism （MIT license）。
- 模拟器模拟什么的性能，修改了什么。
  - Ramulator2 模拟 DDR5-8000B 单通道内存系统在 8 核 OoO workload（57 个开源 trace）下的时序/性能（weighted speedup、每 tREFI RFM 频率、Alert 率）。修改内容：在 Ramulator2 的 DRAM 模型中实现 per-bank 概率采样与缓解逻辑——mitigation window 内随机采样 R 个激活槽（SSQ），与 SHQ 交集检查，PMQ 排队与计数，ABO Alert 触发（PMQ 满或计数>TPMQ=4），默认缓解（TRR/RFMsb）服务最高计数项；MINT 与 QPRAC baseline 按原论文设计在模拟器中实现（MINT 窗口 11/24/48 对应 TRH-D 250/500/1000；QPRAC 5 项优先级队列 + Back-Off 阈值调优）。CACTI-7.0 输入 SRAM 容量/工艺估算动态功耗；Micron 功率计算器输入 DRAM 配置与刷新频率估算芯片功耗。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？
  - 开源情况：PrISM 开源（STAR-Laboratory/prism，MIT），perf_analysis/ 复现性能实验（Fig.7/8/9、Table VI），security_analysis/ 复现安全模型（Fig.5/6）；Ramulator2、CACTI-7.0、Micron 功率计算器均为公开工具。使用例子（性能复现）：`git clone https://github.com/STAR-Laboratory/prism && cd prism/perf_analysis && ./run_artifact.sh --method slurm --artifact all`（SLURM/单机均可）→ 按 Table II 配置各 TRH-D 的 (W,R,L) 与 16 项 PMQ → 输出各 workload 的加权 speedup 与 RFM 频率，复现"TRH-D=500 时 0.2% slowdown、625B/bank"结论。作用：证明无需 DRAM array/接口改动、仅靠每 bank 数百字节 SRAM + 现有 ABO 协议即可在低 TRH-D（500、250）实现安全且近零性能开销的 RowHammer 缓解，存储比 Mithril/ProTRR 少一到两个数量级，为 DDR5（PRAC 为 optional 特性）提供低成本替代路径。
