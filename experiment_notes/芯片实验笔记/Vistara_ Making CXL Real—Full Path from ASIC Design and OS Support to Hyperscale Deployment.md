## Vistara: Making CXL Real—Full Path from ASIC Design and OS Support to Hyperscale Deployment

- 属于芯片设计的实现是什么？实验比较什么？
  - 实现是 Meta 自研的第一代 CXL 内存扩展器 ASIC「Vistara」，属 CXL 2.0/1.1 Type-3 Memory Expander 芯片结构。核心设计目标：在严格功耗/面积约束下最大化内存容量与效率，通过桥接退役 DDR4 DIMM 到新一代主机实现"近零成本"内存扩容并降低碳足迹。芯片关键结构（Table II）：PCIe Gen5 x16 主机接口（生产部署为 x8）、2 个独立 72-bit DDR4 通道（最高 3200 MT/s，生产 2400 MT/s）、每芯片最大 256GB（4×64GB；生产 4×32GB=128GB）、RS(36,32) 2-symbol 纠错 + x4 chip-kill、3 个 RISC-V 管理核（secure/control/boot）、CCI/SMBus/PCIe FW 更新接口、≈9W 功耗、先进工艺节点 + 激进 clock/power gating。芯片级优化把 ASIC 空闲往返时延压到 ≈50ns（CXL/DDR controller IP 低时延配置、最小化时钟域穿越、关键路径 tight floorplanning + selective low-Vt）。
  - 实验比较（在真实 MemServer 上刻画，非仿真）：本地 DDR5-6400（768GB/614GBps/130ns）vs CXL 附加 DDR4-2400（256GB/≈76GBps/≈250ns）——① 峰值带宽（MLC 微基准：ALL-Read 497 vs 48 GBps，3:1/2:1/1:1 读:写下 41–42 GBps）；② 不同带宽利用率下访问时延（60% 利用率本地 234ns vs CXL 372ns，Table IV）；③ 1/10/50/100 并发时延线程下的时延 CDF 尾分布（Vistara 与本地 DRAM 接近，反驳 [19] 中 FPGA 的不稳尾时延，Fig.5）；④ 功耗/成本（Power/GB 0.7×、Cost/GB 0.13× 相对本地 DRAM，Table V）；⑤ 生产 A/B 测试（同配置 MemServer 仅 cpuset.mems 是否含 CXL 节点，运行 ≥1 周）下各服务级指标（CacheA QPS +33%、CacheB 查询时延 -29%、MRS 服务器数 -25% 等，Table VII）。

- 模拟器模拟什么的性能，修改了什么。
  - 无模拟器。对应说明真实芯片刻画方法：MLC 流式微基准在单路 MemServer 上测量——线程固定到目标 NUMA 节点（本地 DRAM 或 CXL）以隔离各 tier；扫描读:写比例（ALL-Read/3:1/2:1/1:1）与并发度；CPU 频率 2.3GHz、本地 DDR5 6400MT/s、CXL DDR4 2400MT/s；warm-up 后取 60 秒稳态平均，输出峰值带宽（Table III）、不同带宽利用率下的访问时延（Table IV）、并发时延线程下的时延 CDF（Fig.5）。生产 A/B 测试 + 遥测（TPP promotion/demotion、NUMA hint faults、本地/CXL 带宽、OOM 率）验证端到端效果。
  - 芯片层面"修改/设计"（流片设计而非模拟器修改）：大 completion buffers + 宽 flow-control window + 充足 replay depth 优化 loaded latency；DDR 子系统 multi-channel access、bank-level parallelism、深 read-data/command 队列；memory controller pipeline 减少流水级 + 通用事务 fast-path；CXL 栈与 PCIe Gen5 PHY 紧耦合减少协议翻译开销；firmware mailbox 命令加速（CXL.io/CXL.mem）、中断限速防 error interrupt storm；错误恢复（CXL/DDR controller/内部互连协调复位）。
- 开源情况。基于开源文档和论文，使用例子解释模拟器如何使用？作用是什么？
  - 开源情况：Vistara ASIC 为 Meta 专有芯片，未开源（联网搜索 2026-08 无公开仓库，无法确认任何 RTL/文档）；论文 camera-ready 公开：https://aisystemcodesign.github.io/papers/isca26/vistara_camera_ready.pdf。评估工具 Intel MLC 免费下载（链接见上）；Linux 内核 CXL 驱动代码已/正在上游化（upstream Linux：drivers/cxl、mm/memory-tiers、NUMA demotion 等）。
  - 使用例子（MLC 输入到性能输出的全过程）：MLC 以工作负载描述（-X 读/写比例、-t 并发线程数、-n 目标 NUMA 节点、流式/随机访问模式）为输入，对指定内存区域生成读写流并统计带宽与时延分布；论文用 MLC 得到 Table III（ALL-Read：本地 497 GBps=80% 理论峰值、CXL 48 GBps=62%）与 Table IV（60% 带宽利用率：本地 234ns、CXL 372ns），作为"CXL 带宽/时延虽低于本地但足以支撑容量受限负载（生产运行点：本地 ~60% 利用率、CXL <10%）"的量化证据；再用 Fig.5 的并发时延线程 CDF 证明生产级 ASIC 尾时延稳定（对比 [19] 的 FPGA 设备因 SRAM/credit buffer 不足出现异常尾时延）。作用：为"为什么把冷页放在 CXL 不影响端到端性能"以及"为何 ASIC 而非 FPGA/市售模块"提供可复现的带宽/时延/功耗/成本数据支撑。
