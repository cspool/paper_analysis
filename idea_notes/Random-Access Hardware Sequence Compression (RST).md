## Random-Access Hardware Sequence Compression (RST)

- baseline方法是什么？
  - Baseline 是页级序列压缩（LZ 家族）在硬件内存压缩中的应用，以 TMCC [24] 的 ASIC Deflate（LZ77+Huffman）为代表，也是 Hyperscale Tiered Memory Expander 规范 [5] 强制的页级 LZ。压缩时把整个 4KB 页当作一个单元，用页内所有更早的数据作为隐式字典（block 0..i−1 压缩 block i），字典不存储在压缩输出中（解压器按相同顺序动态重建）。因为最大化压缩率需要"用请求块之前的一切做字典"，解压一个 64B 块必须从页首开始：先取字典数据（平均 704B，即请求页中间块时页首到该块的所有数据），再串行解压到请求块。
  - Baseline 全栈执行例子（算法-系统-硬件；本文是内存压缩算法+硬件 IP 论文，编译框架/kernel 层论文未明确说明）：一条 64B 缓存行 miss 指向压缩页 → 内存控制器（硬件压缩层）按压缩页位置元数据定位 → 从 DRAM 取请求块之前的所有压缩数据（平均 704B）→ ASIC Deflate 解压器从页首开始：LZ77 匹配解码（⟨offset|length⟩ 对从滑动窗口复制）+ 截断 Huffman 解码，串行重建字典与数据直至请求块 → 块数据返回 LLC → 之后命中未扩展页。结果：250ns 级块访问延迟（行业规范），并发访问不同压缩页时排队叠加到 ~1µs。朴素随机访问方案（限制字典为 128B）会把压缩率从 3.3× 打到 1.75×（容量增益损失约 3×）：小字典装不下足够序列，且 48B 位置元数据（每块 6-bit 偏移）+ 每页符号字典会吃掉大部分字典空间。

- 论文方法是什么？如何对应解决Baseline的缺陷？
  - RST 用"top-utility 序列选择"压缩算法 + 三部分字典缩减 + 并行硬件，把每页总字典空间降到 128B 而压缩率不降反升（3.4× vs Deflate 3.3×），实现任意 64B 块随机解压：(A) 序列字典——不再用隐式全页字典，而是对页内所有 2~5 符号序列全局计算 utility（utility=入选字典可带来的总节省/消耗的字典空间）并迭代挑选 top-utility 序列显式存入 128B 字典（字典本身再做序列压缩；LZ 家族只按最长匹配/局部贪心选序列，对 utility 不敏感且只识别极小子集，Fig.6 显示基本 utility-aware 选择远低于 top-utility）；(B) 位置元数据 48B→8B——把 6-bit 块内字节偏移嵌进每个 DRAM 块头部，页级元数据降为 64-bit 逐块 0/1 向量（"0"=与前任同 DRAM 块、"1"=下一块，前缀和 ~1ns 定位）；(C) 符号字典→0B——静态符号字典（零最重要、reuse codes 编码"重复 i 位置前的符号"提供动态适配，Table 1；最坏 12.5% 字面量开销，不可压页走每页翻译项原样存储）。硬件上把重活全放到压缩侧：压缩器三模块并行（substitution：CAM 匹配+overlap filter 去 run 内重叠冒险+替换+compaction；update generator：splice-and-cancel 防相邻位点双计数；table update：32-bank set-associative SRAM+sorting network+FIFO），每页 >3×10^5 次操作在 2.5GHz 下单页压缩可并行完成；解压器只需取 128B 字典+目标块，静态符号解码+展开表+多 LIFO 并行展开嵌套索引，平均 18ns vs Deflate 140ns。
  - 论文方法全栈执行例子：一条 64B 缓存行 miss 指向压缩页 → 内存控制器读 8B 位置元数据（64-bit 向量前缀和 ~1ns）→ 只从 DRAM 取 128B 字典+目标 64B DRAM 块（共 192B vs Deflate 平均 704B）→ RST 解压器：静态符号字典解码（~8 cycle）→ 展开表把每个字典索引映射回 2~5 符号序列 → 多 LIFO expander 并行展开嵌套索引（如 [2*,1*]→2*=Z1*Y→展开为 ZXYYXY），最坏 <128 cycle → 块数据返回 LLC（~18ns 计算+一次 192B 取数）→ DyLeCT 随后再扩展整页，或排队延迟高时跳过扩展；写回时用页内现有字典+目标 DRAM 块局部重压缩被写块（不更新字典），装得下则跳过页 fetch/expansion。压缩侧每页：COUNTSEQS2TO5 建 utility 表 → 迭代选 top-utility 序列入字典 → 替换+更新，三模块并行硬件支撑，最后静态符号编码 → 输出 (字典, 压缩页)。全栈对比：Deflate"取 704B+串行解压 140ns"→RST"取 192B+并行解压 18ns"，压缩数据访问延迟从 260ns~1µs 降到 ~110ns，平均性能 +15%，readStride-1K 最坏情况 5.1×（硬件压缩内存系统从 ASIC Deflate 换 RST）。
