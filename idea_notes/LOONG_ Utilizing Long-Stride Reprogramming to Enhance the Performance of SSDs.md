## LOONG: Utilizing Long-Stride Reprogramming to Enhance the Performance of SSDs

- baseline方法是什么？
  - Baseline 是 SSD 标准的顺序编程约束 + 现有两步编程方案。NAND flash 要求 block 内 WL 严格自下而上单向顺序编程（BPD 背景图案依赖导致的可靠性约束）。GC 场景：valid 页迁移必须以 One-Shot Programming（OSP）一步写入全 8 电压态（TLC 1100 µs/页），编程期间阻塞 host I/O。改进方案 SP-GC 用 SLC 模式（96 µs/页）加速迁移，但 SLC 只占 1/3 容量，需额外补偿 GC 回收浪费空间（GC 数增 1.25 倍）。两步编程方案（TSP、[19] 的 8-WL stride）把 OSP 解耦成快速第一步 + 慢速第二步，但时间-空间窗口极窄（TSP 仅 2 WL、[19] 限 8 WL），导致 GC 迁移的 valid 页中近 1/3 仍须执行高延迟第二步；且窗口窄意味着第一步写入的数据在第二步触发时大多仍有效，无法利用 invalid 数据减少电压态（Midas-Touch [37] 部分缓解但窗口受限）。
  - Baseline 全栈执行例子：host 发写请求 → SSD 控制器 FTL 逻辑-物理映射 → 写满的块触发前台 GC → victim block 的 valid 页在**系统/控制器层**以 OSP 同 plane 顺序读出并写入空闲块（1100 µs/页，host I/O 阻塞）→ **硬件架构层**（编程引擎）对每个 cell 做 ISPP 迭代充电到目标 8 态之一，BPD 使已编程 cell 抬高串电阻、阻碍下方 cell 电子注入 → GC 结束前 host I/O 被阻塞；编程场景：TSP 第一步粗编程后若数据被更新 invalid，因 stride 仅 2–8 WL，invalid 页占比低，第二步仍须全 8 态精细编程。模型推理算法层/编译框架层/kernel调度层：论文未明确说明（本论文为存储系统固件/编程机制研究，不涉及 ML 推理、编译框架或 GPU kernel 调度）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - LOONG 把两步编程的 stride 从 2–8 WL 推到整 block（长跨度重编程）。核心洞察：通过真机量化 BPD 的两个因素（stride 长度 vs 已编程 cell 电压），发现 programmed cell voltage 引发的 channel pinch-off 效应是可靠性主因（P3→P7 重编程误码较 baseline 飙升 24576 倍，而 P1→P7 接近 baseline），因此第一步把电压限制在最低两态（E、P1）即可消除 pinch-off，把 stride 扩展到全部 WL。LOONG 工作方式：(1) 第一步以 pSLC 模式（114 µs/页，SLC 级延迟）顺序编程整 block 全部 WL，最大化速度；(2) 第二步长跨度 reprogram（955 µs/页，P1→P7，接近 OSP）把整 block 统一重编程回 TLC 全 8 态，恢复容量。编码用标准 OSP 实现（用户页+2 dummy 页→3 页组，第一次 OSP 编码前两态、第二次 OSP 重新编码），无硬件修改，仅固件更新（FTL 增加 RBP/SP/RP 指针、跳过未用 PPN、1 bit reduced-state 标记）。
  - 对应解决 Baseline 缺陷：(1) 解决 OSP 迁移慢——GC valid 页以 pSLC 快速迁移（114 µs vs 1100 µs），且长 stride 使 pSP-GC 中 51.9% 的 valid 页受益于 pSLC 编程（8-stride 仅 26%）；(2) 解决 SP-GC 容量损失/补偿 GC——pSLC 页通过 reprogram 恢复 TLC 容量，无需补偿 GC（GC 数较 baseline 降约 20%），pSP-GC 平均延迟较 baseline 降 37.5%；(3) 解决窄窗口下第二步高延迟/无效优化——整 block 窗口使两步间 invalid 页增 8.8 倍（vs TSP），reprogram 时这些 WL 只用前 5 个电压态（E→P4，约 710 µs = OSP 的 4/7），写/读延迟分别降至 baseline 的 81.3%/80.4%（平均降 18.1%）；(4) 解决可靠性——低电压态抑制 channel pinch-off/BPD，1K P/E + 1 年保留期下误码 96/页，远低于 ECC 纠错上限（1280 bit/页），且两步编程降低平均 Vth、减少 FN 隧穿泄漏，可靠性不降反升。
  - 论文方法全栈执行例子：host 写请求到达 → **系统/控制器层** FTL 查 RBP 定位当前重编程块，SP/RP 指针决定写入位置 → **硬件架构层**编程引擎以 pSLC OSP 把用户页+2 dummy 页编码进 E/P1 两态（114 µs，快速落盘）；期间该页被更新而 invalid（整 block 窗口内大量 invalid 积累）→ 触发 GC 时，victim block 的 valid 页以 pSLC 模式迁入重编程块（不损失容量，无需补偿 GC）→ 第二步长跨度 reprogram：对无 invalid 页的 WL 从 P1→P7 全 8 态（955 µs）恢复容量；对含 invalid 页的 WL（validity table 判断）只把 E/P1→前 5 态（710 µs），FTL 1 bit 标记使后续读走 MLC 读而非 TLC 读 → 模拟器（事件驱动）累计各操作延迟与 GC 阻塞，输出平均/尾延迟与 IOPS 提升。模型推理算法层/编译框架层/kernel调度层：论文未明确说明（不适用）。
