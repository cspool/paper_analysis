## ECC Enabled Reliable and Performant Processing-in-Memory

- baseline方法是什么？
  - Baseline 为三类 PIM 可靠性方案：(1) 仅靠 on-die ECC 的 bank-PIM——DDR5 用 SEC(136,128) Hamming 码（128-bit 数据 + 8-bit 冗余，只纠单比特错误），HBM3 用 symbol-based RS(19,17)（2× DDR5 冗余，纠错能力受故障隔离边界约束）。问题：SEC 对多比特错误（运行故障、突发）检测率极低（双位错误仅 53.7%），HBM3 RS 对超出 MAT-kill 隔离边界的故障模式无法保证检测/纠正，DUE/SDC 率高；(2) rank-PIM——计算单元放 rank 级，天然继承 rank 级 chipkill ECC（容一个 x4 器件完全失效），可靠但放弃 bank 内部带宽，性能损失最高 8×；(3) 直接把传统两层 ECC（如 XED）搬到 bank-PIM——bank 级检测 + rank 级纠正，看似两全，但因 VRT 弱单元错误频繁且随机出现（Scaling 下每单元进入亚标称驻留态概率 >10⁻⁸ 且持续上升），每出现一次都要触发 rank 级纠错（顺序读 17 个单 bank 请求重构 codeword + chipkill + 写回 + 重试），10,000 个 VRT 单元即可使 PIM 性能下降 >20%。
  - baseline 全栈执行例子（LLM GEMV token decode，bank-PIM + on-die SEC）：模型推理算法层 = self-attention 表达为 GEMV（权重 W 分布在 bank 内、激活驻留 PIM SRAM）；系统框架层 = host 发 all-bank PIM 命令（Samsung/SK Hynix 风格紧凑 SIMD 命令集），无可靠层；编译框架/kernel 调度层 = host 端生成 kernel trace，PIM 单元按 bank 带宽执行 4 FPU MAC（论文未明确说明 kernel 级调度细节）；硬件架构层 = 每 bank 旁 on-die SEC 解码器：单比特错误可本地纠正，但 W 中任一双比特/突发多比特错误检测概率仅 53.7% → 静默数据损坏（SDC）→ 5 年运行期 SDC 率比 rank-PIM 高两个数量级以上，LLM 推理精度下降 30-50%，在 VRT 10⁻⁵ 下接近随机猜测。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = reliable bank-PIM，三大设计逐一对应：(1) 两层 ECC（对应"on-die 纠错不足 / rank-PIM 牺牲性能"缺陷）——第一层 bank 内 on-die CRC（CRC8(136,128) 或 CRC16(144,128)）在 PIM 访问时纯 detect-only，最大化检测覆盖（CRC8 比 RS8 检测好一个数量级、CRC16 在等冗余下超 RS16 一个数量级以上）；第二层 rank 级 chipkill ECC 只在纠错/写时访问。检测到错误用现有 ALERT_n pin 通知内存控制器，控制权保留在 host，接口改动最小。因 PIM 应用读为主、写缓冲在 SRAM，避免频繁跨 chip 重编码与写放大；(2) Codeword Flip（对应"VRT 频繁触发 rank 纠错拖垮性能"缺陷）——利用 VRT 单向性（电荷泄漏 1→0，翻转后该单元不再重复出错）在 rank 纠错后把整个 codeword 按故障 chip 位取反写回，无翻转元数据：配对 bank 的两个 CRC 解码器并行做 F_CRC 双解码（Table I 四结果判定），把重复 VRT 错误从"每次都要 rank 纠错"变成"本地静默屏蔽"，开销 <2% 即便最恶劣 10⁻⁵ VRT 率（而无屏蔽时 >20% 损失）；(3) Odd/even bank pipelining + 页面退役（对应 tFAW 空泡与运行故障累积缺陷）——奇偶组交错执行消除 all-bank 命令 idle bubble（PIM 利用率 55%→91%，纠错只需扫一半 bank），对超过 1 个逻辑行/列的重叠运行故障页面主动退役（5 年吞吐损失 <2%，DDR5 FIT ~45/chip 下极少触发），退役由 host 处理。
  - 论文方法全栈执行例子（同一 LLM GEMV token decode，reliable bank-PIM）：模型推理算法层 = 同一 GEMV 映射（self-attention 上 PIM、feed-forward GEMM 批处理留 host），算法不变；系统框架层 = host 经配置寄存器切 PIM/non-PIM 模式发 all-bank 命令，CRC 检测出错时 ALERT_n 中断通知内存控制器（硬件状态机或带 fence 的软件 handler 二选一），控制器对出错 all-bank 命令涉及的 bank 顺序读重构 rank codeword → chipkill 纠错（基线 63.75ns，nominal VRT 率 99.9998% 落此路径）→ 翻转写回 → 重试 PIM 命令，仍失败则换单比特纠错模式解码、再失败 host 端模拟执行 + 页面退役；编译框架层 = 论文未明确说明（kernel trace 生成在 host 侧）；kernel调度层 = bank-PIM 单元（4×BF16/FP16 MUL/ADD FPU、64-bit 数据通路、1KB scratchpad、每 tCCDL 16 发一条指令）以 204.8GB/s/rank 片内带宽（8× 片外）执行 GEMV，读结果在 PIM SRAM 聚合后 host 读取并做 rank 级 ECC 更新（写为主时退化为 rank 级 RMW）；硬件架构层 = 每 bank 对共享 ECC 引擎（主 CRC 解码器 + 配对 bank 取反输入 F_CRC，~13 级门关键路径，面积 ~2.6%），奇偶组交错激活消除 tFAW 空泡。效果：5 年 SDC 率比 DDR5 bank-PIM baseline 低 400×、比 HBM3 bank-PIM 低 2-10×（总失败率低 30-80K×），性能开销 <2.1%，GEMV 比 rank-PIM 快 1.5-4×，端到端 LLM（OPT-13B，16K token）200 tokens/s = 2× A100、2K token 延迟 9ms vs A100 17ms，精度全程保持无错误。
