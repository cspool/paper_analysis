## LoRA: Towards Improved Applicability of Reconfigurable Architecture for Versatile Nonlinear Functions

- baseline方法是什么？
  - Baseline 是通用 CGRA 对非线性函数的三种现成处理方式：①直接卸载到 host CPU 执行（CPU 执行非线性→性能退化）；②为每个非线性函数加 off-the-shelf IP（硬件开销随函数数增长，且面向误差容忍应用时过精确、浪费）；③SOTA 方案 PICACHU（ASPLOS'25）：用 Taylor 展开逼近非线性函数 + FP2FX（浮点转定点）模块 + 算子融合（把 Taylor 引入的 MAD 运算融合进单个 PE 的专用模块以减少 PE 数）。NX-CGRA 则用编译器把复杂非线性拆成基本算术在 VLIW CGRA 上并行执行（资源多、延迟与功耗高）。系统级对比的 SOTA baseline 是 PICACHU。
  - Baseline 全栈执行例子（一次 LLM Swiglu/SiLU 激活的 PICACHU CGRA 执行）：算法层：PICACHU 用 Taylor 展开逼近非线性函数（如 e^x），精度靠提高 Taylor 阶数（4/5 阶），FP2FX 把浮点输入转定点后进 Taylor 计算；系统框架层：CGRA 编译器把 loop kernel 编译成 DFG 并映射到 PE，非线性函数的 Taylor MAD 序列作为普通算子参与 DFG 映射；编译框架层：论文未明确说明（PICACHU 自带编译流程，非线性以 Taylor 展开的 MAD 图形式进入 DFG）；kernel调度层：每个 Taylor 多项式 MAD 需要一个 PE 节点——6 阶 exp 至少 6 个 MAD 占 6 个 PE，Mish DFG 36 节点、Swiglu 37 节点，PE 占用大限制了 loop unrolling；硬件架构层：Generic CGRA（6×6=36 PE）的 PE 内集成 FP2FX+MAD 融合模块；sqrt 等不支持的函数被卸载回 CPU 执行（KNN 中 CPU EXE 周期占比极大拖慢端到端），Taylor 精度越高 MAD 越多、PE 占用越大。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法：算法-硬件-框架三层协同设计，逐条对应解决：
    1. **Chebyshev 分段逼近算法**（对应解决 Taylor 的精度/开销与输入范围限制）：Chebyshev 多项式在 [-1,1] 上极小化最大误差、收敛快于 Taylor、避免 Runge 振荡、数值条件好；利用函数奇偶性等代数性质（cos 的 MAE 降 148×）+ 三种分段策略（uniform/curvature-based/equal-error）+ 遗传算法优化各段次数，使"低阶（≤5 次）+ 少段（6-7 段）"多项式即可达到 Taylor 4-5 阶甚至更高精度，且对任意用户定义输入范围通用（PICACHU 只支持有限函数子集）。
    2. **XCore 可重构功能单元**（对应解决 MAD 硬件开销与函数种类受限）：用 LNS 把 c_i·x^(k_i) 变为 2^(log2(c_i)+k_i·log2(x))，乘法/除法/幂/对数统一成 LNS 中的加法/乘法（乘法/除法=log 加/减，幂=乘 log2(x)，对数=乘 1/log2(b)）；混合数制（加/减回普通算术避免 LNS 的复杂加/减）；可编程 30b×30b 乘法器分解为 5×30b×6b 复用硬件算 6 项多项式（k_i 只需 6 bit）；支持定点/FP32/LNS 三种格式与 x^y、log_b(x)；复合函数（tanh(x)+1、sin(x)+cos(x)、ln(sin(x))）可被单个 XCore 直接逼近——一个 XCore 节点顶替 PICACHU 的多个 Taylor MAD 节点，DFG 从 36-37 节点降到 11-15 节点，释放 PE 供 loop unrolling，且 sqrt 等函数由 XCore 在片上执行不再卸载 CPU。
    3. **LoRA 端到端框架**（对应解决"通用 CGRA 如何使用"）：LLVM 前端 + 自定义非线性函数标注（__CGRA__HARDWARE_OP）+ 自动生成 Chebyshev 多项式与 XCore 配置 + 模拟退火空间映射 + 内存分区算法 + RoCC 指令生成，用户只需 #pragma 标注 kernel 与自定义非线性函数即可在 CGRA 上跑非线性函数，无需手工设计硬件。
  - 论文方法全栈执行例子（同一次 Swiglu 激活的 LoRA 执行）：算法层：用户标注自定义函数 tanh_XCore，Chebyshev 算法按输入范围与定点格式生成 {breakpoints, 系数, 次数} 并配置 XCore；系统框架层：LLVM 前端做循环分析/优化/DFG 生成，复合函数 tanh(x)+1 作为单一 XCore DFG 节点（Swiglu 15 节点 vs PICACHU 37 节点）；编译框架层：自定义函数经 __CGRA__HARDWARE_OP 特殊处理成 DFG 节点（原非线性函数被替换），后端模拟退火空间映射 + 内存分区算法分配多 bank SPM 并调度 bank 冲突，生成 CGRA calling function（load 配置/数据→配置 CGRA→激活→写回的 RoCC 指令），替换原 loop 编译成 bare-metal；kernel调度层：6×6 CGRA 中 2 个 XCore-PE 执行非线性（7 cycle 出多项式结果），其余 PE 执行普通运算，IOB 双输入支持 A[B[i]] 等非仿射访问，XCore 内 Pre-Process 查 breakpoint LUT → LOG 对数转换 → LNS 30b×6b 乘加 → ALOG 反log → Output 加法树；硬件架构层：TSMC 40nm ~475MHz，数据经 L2(128KB)↔SPM(12×4KB) 用 TileLink+DMA 传输，loRA 平均 2.18× 性能与 2.13× 能耗效率 vs PICACHU，23.33× vs STM32H750。
