## MXFFP Microscaling Flexible Floating Point Format for Large-Scale AI Model Acceleration

- baseline方法是什么？
  - Baseline 是 MXFP（OCP Microscaling Formats v1.0）——块共享 8-bit 指数（E8M0）的缩放浮点格式：block（默认 32 元素）共享一个 8-bit 指数，block 内元素用固定低比特配置（MXFP4 固定 S1E2M1、MXFP8 固定 E4M3/E5M2）。算法层：每个 block 用共享指数归一化后按固定 E2M1 量化（Eq.2），共享指数扩大动态范围、缓解离群值；系统框架层：OCP compliant 转换管线，推理中所有 MMA 张量转 MX 格式；编译框架层：论文未明确说明；kernel调度层：Tensor Core 按固定格式执行低比特 MMA，8B/block 共享指数元数据随算子搬运，block size 从 32 增到 256 时元数据从 11.7GB 降到 1.46GB（Llama3-405B 例）但同 block 更多元素被迫共享同一指数与位配置；硬件架构层：Tensor Core 原生支持单一固定 MXFP 配置（如 FP4 E2M1 数据通路），乘累加后按 block 指数缩放累加进高精度 accumulator。
  - baseline 全栈执行例子（Llama3-8B 4-bit MXFP4，block 32/256，prefill）：算法层：所有 block 一律 S1E2M1 量化，需要更大范围（如 Block 25）或更高分辨率（如 Block 679）的 block 被截断/欠表示，perplexity 严重退化（Llama3-8B 30.98、OPT-6.7B 88.81）；系统框架层：权重静态转 MXFP4、激活运行时按固定 E2M1 转换；编译框架层：论文未明确说明；kernel调度层：Tensor Core 统一 E2M1 低比特 MMA，block 256 元数据开销低但 block 内值多样性放大精度损失（perplexity 随 block size 单调上升）；硬件架构层：单一 E2M1 FP4 数据通路、固定位映射，无配置灵活性。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法：MXFFP = 在 MXFP 结构上解耦"缩放粒度"与"位配置粒度"，四个设计对应解决固定配置无法适应 inter/intra-block 值多样性的缺陷：(1) **1-bit 配置位（inter-block 优化）**——每 block 加 1-bit configuration 字段，在 E1Mx（分辨率优先）与 E2Mx（范围优先）间按 block 值分布选择；E1M2/E2M1 两配置覆盖 97.2% 的 oracle 最低 MSE 选择，8 个 block 配置位拼成 1B configuration set 保持字节寻址（每 8 block 仅 9B 元数据）。(2) **sub-blocking（intra-block 优化）**——大 block（256）拆 32 元素 sub-block 各自独立选配置位（8 个 sub-block 配置位合成 1B set），但共享单一指数（按 E2Mx 假设计算、E1Mx sub-block 使用时减 1），以 4× 更低元数据（vs block 32）在大 block 下保持精度——block 256 的 MXFFP 仍优于 block 32 的 MXFP。(3) **高效运行时转换（Algorithm 1）**——权重静态离线按两种配置量化选 MSE 小者（oracle，零运行时开销）；激活用相对指数统计近似 oracle（count_E1² vs count_E2 的二次加权计数），把"每 block 最优配置"降到几次计数 + 1 次比较，最终输出 MSE 几乎等于 oracle。(4) **MXFFP Tensor Core**——bit mapper（多路选择器按配置 bit 重排操作数）+ 扩展 dot-product（E2M1 核加宽为内部 E2M2）+ 轻量 converter（Max/Subtractor/Counter/Config Selector/Normalization&Round），单配置位即可解释执行多配置，threadgroup 面积仅 +22.26%（GPU 192 Tensor Core 规模下占 750mm² die 的 0.038%）、配置级 power gating 后有效功耗 ~12%。
  - 论文方法全栈执行例子（Llama3-8B 4-bit MXFFP，block 256 / sub-block 32，prefill 1024 token）：算法层：权重离线逐 sub-block 在 E1M2/E2M1 下量化选低 MSE 配置；激活运行时 Algorithm 1 按相对指数计数选配置、统一指数（E2Mx 基准、E1Mx 减 1）；系统框架层：转换管线在 MXFP OCP 流程上加 block/sub-block 级配置选择（论文未明确说明 Serving 等框架层）；编译框架层：论文未明确说明；kernel调度层：MXFFP block 取入 matrix buffer，threadgroup 按 config 寄存器（每 block set 一次加载、跨 4 step 保留）与 shared exponent 寄存器（每 step 更新）逐 step 执行 4×8 子矩阵 MMA，bit mapper 把 4-bit 操作数按配置重排进扩展 E2M2 算术核，结果按 block 指数缩放累加进 BF16 accumulator；硬件架构层：converter 用 Max→Subtractor→Counter→Config Selector→Normalization&Round 重生成 MXFFP block（大 block 先跨 threadgroup 同步全局 E_b^MAX、E1Mx sub-block 指数减 1）；结果：perplexity 从 MXFP4 的 30.98 降到 10.23（Llama3-8B）、OPT-6.7B 88.81→16.32、Qwen2.5-14B 15.90→6.93、Vicuna-13B 38.13→13.31，zero-shot 平均分相对 MXFP4 提升 16-29%、距 BF16 仅 5-12%，block 256 时仍优于 MXFP block 32，同时保持与 MXFP 相当的硬件性能（4-bit 1024³ GEMM 2.7×、prefill 端到端 2.08× vs BF16），元数据仅 1 bit/sub-block、较 MXFP8/MXFP6 内存需求低 47.8%/29.1%（sub-block 4 时）。
