## Bridging Efficiency and Scalability in LLM System via 3D Hybrid PIM with 2D In-Transit Computation

- baseline方法是什么？
  - Baseline 一（纯 DRAM-PIM 可扩展系统，CENT [13] ASPLOS'25 "PIM is all you need"）：GDDR6-PIM 设备经 CXL 互联 scale-out（device/channel/bank 三级层级），XPU-free；非线性操作与细粒度数据重排由 CXL 控制器中的 PNM 模块（集中 CPU + 大规模专用 NLU，NLU 面积 4.4mm²@7nm ≈ 4× 一个 32MB bank）完成。三大痛点：(1) batch/序列长度变化使 memory-bound 与 compute-bound 算子并存，DRAM-PIM 因 MAC 单元少（16/bank）且被迫用 output-split 映射（input-split 的 inter-bank reduction 受 global buffer 带宽限制、需串行访问 DRAM bank）而在 compute-bound 场景差；(2) 集中 PNM 造成通道级通信瓶颈——4K 上下文时非线性通信+计算 >20% block 时间、最长可达 25%，RoPE 的标量邻居交换与奇数取反被迫回 CPU；(3) 给每 bank 分布式 NLU 则面积不可行。Baseline 二（SRAM-PIM stacking passive DRAM [82] 系）：低延迟（<10ns）矩阵单元但宏容量小（8KB），纯 SRAM-PIM 上 GPT3-175B 需不可行宏数量、功耗超 A100 三个数量级；堆叠 DRAM 后 batch=1 因频繁权重写回无优势，QK^T/SV 的 K^T/V 输入相关、随序列长度动态变化不适配权重驻留。Baseline 三（GPU-PIM 混合 AttAcc [57] ASPLOS'24）：4×80GB A100 + 4×16GB HBM3-PIM，吞吐高但功耗大、LLM 推理整体能耗低效。
  - baseline 全栈执行例子（CENT 上 Llama2-13B decode 一个 token）：算法层：标准 transformer 计算图（BF16）；系统框架层：CXL 控制器把算子映射到 32 设备、TP/PP 并行切分；编译框架层：论文未明确说明（CENT 指令生成方式 CompAir 未详述）；kernel 调度层：集中 PNM 串行处理各 channel 送来的非线性数据（Softmax 归约→广播回各 bank），RoPE 重排数据经 CXL 往返 CPU；硬件架构层：DRAM-PIM bank 内 16 输入 BF16 MAC 以 output-split 映射算 FC（Llama2-13B Q/K/V 每 bank 权重 5120×10、输入输出比 >17:1 形状失衡），global buffer 承担跨 bank 通信与串行归约。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 三组件按"粒度-目标"分工（Table V：DRAM-PIM 管可扩展性/vector/共享内存，SRAM-PIM 管效率/matrix/intra-bank，CompAir-NoC 管灵活性/scalar/inter-bank）。对应三大挑战：(1) Hybrid bonding + 解耦列译码器 → 带宽瓶颈：32:1 列译码器拆为 8:1+4:1 提升 bank 读带宽（+15% 面积、扩 bonds 占单 bank 面积 20%），HB（每 bank 256 bonds、6.4Gbps、10K–100K/mm²、0.05–0.88pJ/b）使跨 die 带宽与 DRAM 内部带宽对等；选 SRAM-PIM 而非加速器因同算力 28nm 脉动阵列面积 5.411×、不满足 HB 上下层面积匹配。(2) CompAir-NoC/Curry ALU → 通信瓶颈：flit 级"边传边算"（计算级与 switch traversal 并行、单操作数驱动避免多 flit 操作数匹配），归约树替代 global buffer 串行归约、RoPE 重排与 exp/sqrt 迭代在传输途中就地完成，去中心化替代集中 NLU（Curry ALU 仅为 router 面积 2.94%）→ 非线性延迟 -30%、长上下文 -25%。(3) 分层 ISA + 自动翻译 → 编程失配：Row-Level ISA（SIMD、用户接口）静态降级为 Packet-Level ISA（MIMD 执行），path generation 按生产者-消费者链（DST→SRC）融合 NoC_Scalar 指令、router 自动把 DRAM 行粒度串行化/反串行化为 flit，避免每 bank 私有控制器（省 17–20% 逻辑 die 面积）；Qwen 8K input-split 的 +27% 本地指令稀释为系统级 +2%。映射策略随之改变：batched FC 交 SRAM-PIM（权重驻留复用，batch=32 Q/K/V 6.3×）、attention（K^T/V）留 DRAM-PIM（能量优势）、归约树使 input-split 成为可行甚至更优映射（2560×20 一致优于纯 output-split）。
  - 论文方法全栈执行例子（同一 Llama2-13B decode，batch=64）：算法层：无算法改动，仅硬件近似 e^x（Taylor n=4..7，perplexity 偏差 <0.3%、不随上下文累积）；系统框架层：CXL 32 设备、设备控制器只发指令（不含 NLU），TP≤8 为最优范围（8 设备 TP=8）；编译框架层：host 编译器把 row-level ISA 离线降级为 packet-level ISA 并做 path generation（自研 translate/ 承担全栈中编译层角色）；kernel 调度层：CompAir-NoC 在数据传输途中完成 Softmax 的 exp 迭代（32 路并发/通道）、16 宽归约树与广播树、RoPE 的 NoC_Exchange 五阶段交换 + EWMUL；硬件架构层：Q/K/V 与 FFN 权重驻留 4×8KB SRAM-PIM（(512,8)/(256,16) 宏配置，输入/输出经 HB + 解耦列译码器搬运），QK^T/SV 由 DRAM-PIM 16 输入 MAC 以 input-split 映射执行、跨 bank 归约由 NoC 归约树完成。结果：decode 1.95–6.28×（batch=64 2.67–6.28×）、prefill 1.83–7.98×、128K 长上下文 2.13–2.73×；96 设备 vs AttAcc-4-A100-HBM：吞吐相当、每 token 延迟/能耗 20.2%/28.5%、整体 3.52× 低能耗；DRAM-PIM/SRAM-PIM 比值需权衡（跨 die 通信使能耗略增于纯 DRAM-PIM，SRAM 过多能量代价高）。
