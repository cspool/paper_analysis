## Early Silicon of Raptor: The First 3D-DRAM Accelerator for Generative Inference

- baseline方法是什么？
  - Baseline 为生成式推理的两类主流内存基板 + 两类 3D/PIM 架构：(1) SRAM-centric 加速器（如 d-Matrix 上一代 Corsair 内计算 chiplet）——片上 ~150TB/s 超高带宽但仅数 GB 容量，装不下大模型权重（Llama-70B 8bit 约 70GB）与 KV cache，被迫用极高并行度分摊：Table II 显示 Llama3.1-70B 在 SRAM 上要 8 卡 TP=8（128GB），DeepSeekV3-671B 要 64 EP×4 卡，Kimi K2 1T 要 1,584 卡（6336GB 聚合内存）→ TP/PP 度越高，每层 all-reduce 参与者与数据量越大，网络延迟/带宽（collective）成为主导，性能对网络极敏感；(2) HBM-based 系统（HBM3/HBM4 级）——容量高（192GB/卡）但带宽 <20TB/s 且受 I/O 功耗限制（HBM3 ~0.9pJ/bit 级、burst 多周期传输 + 每 beat 决策的 PHY 级 DBI 带 sideband pin），decode 是字节搬运主导（每 token 读全部历史 KV），带宽与 I/O 能耗直接压死 TPOT 与 tok/s/card；(3) H2-LLM（混合键合 PIM，单芯片 0.4TB/s channel 带宽、0.28 PFLOPS 存内计算）——带宽/计算双双受限、无多芯片扩展路径；(4) Stratum（Mono3D 1024 层分层 DRAM，片内 NMP 最高 364TB/s 但片外 xPU-DRAM 接口仅 ~0.82TB/s/chip → 36× 带宽悬崖，跨芯片移动后有效带宽仅 10-35TB/s）。baseline 共同痛点：没有一种基板同时提供 SRAM 级带宽/局部性与 HBM 级容量/能效，且 3D-DRAM 集成本身有四大系统级难题（工作负载感知映射、无 burst 结构的功耗优化、高 bank 数下的良率/可靠性、高结温下的热可靠性）。
  - baseline 全栈执行例子（XPU+HBM 解码 Llama-70B 一个 token）：模型推理算法层 = GQA 自回归 decode，每步对累积 KV（80 层×8 KV 头×128 head dim×8bit ≈ 0.16MB/token/用户）做带宽受限的注意力读 + 新 KV 写；系统框架层 = unified 部署、TP=8、batch≤32，HBM 192GB 可容大 batch 但带宽成瓶颈；编译框架层 = 论文未明确说明；kernel调度层 = 论文未明确说明（decode GEMV/注意力 kernel 从片外 HBM 经 burst 接口 + DBI sideband 拉取权重/KV，多周期 burst 提升延迟）；硬件架构层 = 2.5D HBM 卡（~20TB/s、I/O 功耗受限、PHY 级 DBI），SRAM 变体则片上数 GB 容量迫使 8 卡 TP=8，每层 2 次大 all-reduce 跨卡同步，网络敏感。结果：TPOT 高、tok/s/card 低，网络延迟上升时 SRAM 因大 collective 最先崩溃。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = Raptor：以原生 3D-DRAM（logic-on-DRAM，非外挂设备）为核心重建整个内存子系统，四项机制逐一对应四大集成挑战与 SRAM/HBM 缺陷：① stream blocking（对应"3D-DRAM 高 bank 数下工作负载感知映射 + decode 带宽瓶颈"）——软件栈把权重与 KV cache tile 成 per-channel 近单位步长 128B flit 流（16KB tile，匹配 paged-attention ≥4KB page），每 channel 3 bank 用固定两步访问（96B aligned 列 + 96B partial 缓冲合并）消除 overfetch、最大化 row-buffer 局部性，16 个 channel/slice 独立并行，刷新/scrub 不跨 channel 停顿 → 700MHz 下 2.5ns flit 延迟、105TB/s/card（12.5× HBM3）；② stream flipping（对应"无 burst/无 DBI pin 的单周期 µbump 接口上的功耗优化"）——逐 flit 与前一 flit 比较、选择性翻转 + 每 flit 1bit metadata 共置 DRAM，读时条件翻转，I/O 能耗降 18%（0.455→0.376 pJ/bit，比 HBM3 低 ~6×），无 PHY 改动、仅 0.8% 容量开销；③ topology-preserving redundancy / bank chaining（对应"高 bank 数良率 + 不降有效 channel 宽度"）——N 功能+M 冗余 bank 链式分布、逻辑 die 轻量 mux 选连续 N-bank 窗口（N=24/M=2 → 8 个 3-bank channel），保持全宽对称 channel、布线局部化；④ thermal-aware refresh + 交错 ECC（对应"105°C 结温热可靠性"）——4ms 刷新（比 HBM 32ms 密 8×）但每 bank 仅 1364 行（16-32× 少于常规）→ 仅 1.37% 带宽损失，且 4ms<8.8ms RowHammer 窗口天然缓解；每 bank 末 8 列存 [144,140] RS codeword 与 DBI metadata 共置 + 背景 scrub。缺陷→设计映射：SRAM 容量小 → 3D-DRAM 32GB/卡（比 SRAM 高一个量级）→ 更少卡/更低 TP/PP → collective 更小、对网络不敏感；HBM 带宽与 I/O 功耗 → 100TB/s + 0.45pJ/bit µbump 直连；decode 内存受限 → 整个 channel 化/映射/可靠性机制围绕 KV cache 流量共设计。
  - 论文方法全栈执行例子（同一 Llama-70B decode token，Raptor minimal-card 单卡，batch=32）：模型推理算法层 = 同一 GQA 自回归 decode（算法不变，仍是带宽受限的 KV 读 + 新 KV 写）；系统框架层 = unified 部署且 TP=1/PP=1 单卡即可（3D-DRAM 32GB 容量），DP=32 并发序列，batch=32，每层 only 一次小规模 all-reduce（TP=1 时更少），网络延迟/带宽敏感性大幅下降；编译框架层 = 论文未明确说明完整编译框架，但软件栈把权重与 KV 按 slice/16 channel 切成 16KB stream-blocked tile（128B flit、tile 边界与 paged-attention page 对齐，分配/逐出在 page 边界、不破坏 row-buffer 局部性）；kernel调度层 = 每 slice 的 4×4 TE 经专属 3D-DRAM channel 顺序流式读取权重/KV tile（开行→走完 124 列→激活下一行），stream flipping 读 metadata 条件翻转后进 weight buffer，注意力/FFN GEMV 就地完成，16 channel 独立并行、refresh 不打断其他 channel；硬件架构层 = F2F 3D-DRAM 卡（N4P 逻辑 + 840 bank 3D-DRAM die、100TB/s/32GB）：stream blocking 两步访问合并 128B flit、bank chaining 保持全宽对称 channel、4ms 刷新 + 交错 RS ECC + DBI metadata 共置、逻辑在上 DRAM 在下使 DRAM 比逻辑低 3.5°C（热反转），TE 热点 ~92°C 在 106W/chiplet（422W/MCM）下处于 105°C 裕量内。效果：tok/s/card 比 HBM 高 4.71×、比 SRAM 高 2.44×，TPOT 比 HBM 低 9.96×，且因低并行度对网络延迟/带宽更不敏感（4K 上下文现实网络 4.38× vs HBM、3.15× vs SRAM；MoE 上 3D-DRAM 优于 SRAM，speech 短上下文 448 token 时带宽主导、SRAM 仍略优）。
