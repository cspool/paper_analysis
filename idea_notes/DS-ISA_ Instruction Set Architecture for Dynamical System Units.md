## DS-ISA: Instruction Set Architecture for Dynamical System Units

- baseline方法是什么？
  - Baseline = 先前 DSU 系统（BRIM [1]、DS-GL [30]、DS-TPU [36]、DS-TIDE [15]）中与具体应用绑定的 ad-hoc 控制方式：以 BRIM 式 selector 逻辑（pull-down 网络按列激活 + 共享 programming bus 广播参数）为底层接口，逐应用定制控制序列，无标准化编程模型与 ISA。其隐含假设：(1) uniform coupling configuration——仅按列配置耦合、共享控制信号，耦合只以参数值区分，无子集选择性控制（无 masking）；(2) global coupling evolution——耦合演化经全局控制信号/开关集体施加，整块 DSU 专用于单一应用，无法分区复用；(3) one-time node initialization——节点状态只作初始条件，运行中无法捕获/复用中间状态；(4) lack of overlap-aware execution control——不暴露重叠执行机制，各指令阶段事实上串行。
  - baseline 全栈执行例子（以 BRIM/DS-GL 跑一个 ML 推理任务为例）：模型推理算法层 = 应用被整体映射到特定 DSU 硬件（DS-GL 把图学习映射到实值 Ising 哈密顿量，权重编码为耦合电导、特征编码为节点电压），无统一抽象可跨应用复用；系统框架层 = 无编程模型/ISA，开发者直接操作实现特有的 selector 序列（论文未明确说明，属 ad-hoc 主机控制）；编译框架层 = 论文未明确说明（无编译器/IR/软件栈）；kernel 调度层 = 无指令级调度：selector 按列激活 → 参数经共享 programming bus 串行广播 → 全局控制信号一次性触发全局演化 → 全部耦合集体演化（无法只演化子集，也无法分区并行多任务）；硬件架构层 = 节点电压存电容、耦合参数存可编程电导，pull-down selector 网络 + 共享总线完成全部配置。缺陷：新应用 = 新硬件/新控制方案；多任务无法分区并行；fine-tuning 无法只演化部分耦合；节点中间态不可复用（多阶段 PDE 求解需另起一套流程）；指令阶段串行导致性能浪费（serialized baseline 的延迟高于 hazard-aware 调度，Fig.15）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 三层抽象（执行模型 → ISA → 微架构）：① load-lock-evolve-store 统一执行模型（Connect/Load/Lock/Evolve/Store 五个可组合阶段，覆盖线性推理、迭代训练、退火优化、时变边界 DE 求解的循环模式）；② 9 指令 DS-ISA（N_LOAD/N_LOCK/N_EVOLVE/N_STORE、C_LOAD/C_LOCK/C_EVOLVE/C_STORE、CFG_CONN），64-bit 定长三型格式，label-and-trigger 机制（_LOCK 打标签、_EVOLVE 原子触发同步集体演化），间接寻址（4B Imm_address 指向 SRAM 中的大尺度 mask，2B 立即数字段装 NGID/CGID/Time）；③ 数字控制器微架构：组级执行 + 两级掩码（inter-group GM 管组间同步演化、intra-group NLM/CLM/CM 管组内细粒度配置）、scoreboard 驱动的 hazard-aware blocking policy、timer-based time-controlled evolution（Time Registers 倒计时）、C_EVOLVE 对称部署 1D GM 激活耦合子矩阵。
  - 缺陷→设计映射：uniform coupling configuration → CFG_CONN + CM 连接掩码在指令级选择性配置耦合子集；global coupling evolution → GM 组掩码 + 分区，同块 DSU 多任务/多阶段并行（B2/C2 模式）；one-time node initialization → N_STORE/N_LOAD 显式存取节点中间态，多阶段工作流内复用；serialized execution → 四类指令（data/evolve/config/lock）间红/黄/绿分级 blocking policy 允许独立指令重叠执行，延迟低于 serialized baseline；控制复杂度/同步/细粒度三挑战 → 组级 lockstep 执行 + 两级掩码 + 定长 64-bit 指令（mask 不嵌入指令而是间接寻址，规模可扩展）。
  - 论文方法全栈执行例子（DS-ISA 执行一个 ML 推理请求，Fig.7）：主机（传统处理器）产生指令流 → 控制器前端 Instruction Buffer/Decoder/Scheduler（scoreboard 按 blocking policy 调度：CFG_CONN 对 data/evolve 红阻塞、data 类间红阻塞、_LOCK 对 _EVOLVE 黄阻塞等）→ CFG_CONN[CM Addr,NGID] 从 Mask Memory 取 Connection Mask 写入 CM Registers 定义输入组→输出组拓扑 → C_LOAD[Data Addr,CGID] 经 DAC 把权重写入耦合组电导、N_LOAD 把输入特征写入节点电容 → N_LOCK/C_LOCK 把 NLM/CLM 写入标签寄存器（Idle Registers 默认锁定）→ N_EVOLVE[GM Addr,Time] 取 Group Mask 切换选中组的选择逻辑到标签寄存器、Time Bus 写 Time Registers 倒计时，非锁定节点按 dσ_i/dt ∝ Σ(J_ij+J_ji)σ_j − h_i σ_i 连续时间同步演化（100ns）→ 计时归零切回 Idle Registers 锁存演化结果 → N_STORE 经 ADC 读回节点电压即层输出；多层模型按 A2 cascading 重复此序列。算法层 = 模型变量映射节点、权重编码耦合（哈密顿量 H_DS）；系统框架层 = 统一 load-lock-evolve-store 模型取代逐应用定制流程；编译框架层 = 论文未明确说明（DS-ISA 为未来编译器/IR 提供目标 ISA，本工作未实现编译器）；kernel 调度层 = 控制器 scoreboard 指令调度 + 两级掩码选择演化子集；硬件架构层 = SystemVerilog 数字控制器（Yosys + OpenROAD + SKY130）。结果：4.6W/79.58mm² 管理 1K 节点/1M 耦合；单任务延迟随问题规模近似线性；inference 多任务亚线性扩展（耦合加载一次复用）、training O(N²)（耦合读写主导）、optimization/DE 线性；1024 节点上平均 >60 节点、>3K 耦合同时演化；迭代类负载 stall <25% 且随规模下降；hazard-aware 调度延迟低于 serialized baseline；与 45nm 的 DS-TPU 相比 130nm 控制器功耗同量级。
