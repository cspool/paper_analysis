## NasZip Software and Hardware Co-design to Accelerate Approximate Nearest Neighbor Search with DIMM-based Near-Data Processing

- baseline方法是什么？
  - Baseline 分两类：(1) 软件/常规平台 ANNS——HNSW（CPU，多层级图 + BFS 搜索，efSearch/M 控制）与 SCANN（SOTA CPU 实现）；CAGRA（NVIDIA A100 GPU，单层图，最高百万级 QPS）；还有基于部分距离的特征级早退（FEE，如 ANSMET 的 bit-level FEE）与 naive PCA 降维（feature 使用仅减 6%）。(2) NDP 上部署 ANNS 的 naive 方案与 SOTA ANSMET——三层流程：host CPU 下发改距离命令 → NMA 取向量算距离 → CPU 收集结果并查邻居表决定下一跳。瓶颈分解（Fig.4a）：距离计算占主导（尤其 GIST 960 维）；跨 sub-channel 内存访问显著（邻居与向量跨通道时需经处理器中转，占 >50% ANNS 延迟）；CPU 侧邻居表查找占 31.7% 且重复访问。现有 EE 用 d_part^k 与 threshold 比较，收敛太慢只带来 ~20% 提升；naive PCA 仅减 6% feature；PQ 压缩有精度损失、RabitQ 保留候选还需全维精确重排。
  - Baseline 全栈执行例子（一次 HNSW 查询，naive NDP 方案）：算法层：BFS 每 hop 对候选邻居做全 D 维（如 960 维）L2 距离计算，d_part^k 增长慢、FEE 触发晚，大部分向量算到 200+ 维才退出；系统框架层：CPU 执行 HNSW 图遍历主循环，每 hop 把一批向量地址经 DDR 控制器命令下发给 NMA，等全部结果返回再查邻居表决定下一跳（CPU 侧邻居表查找在关键路径上、重复访问）；编译框架层：论文未明确说明（无自定义编译流程）；kernel调度层：NMA 从本地 sub-channel 取向量、跨通道向量要经 CPU 中转（Fig.4b 红色路径），带宽利用率低；硬件架构层：距离计算在 NMA 并行 4 device 流水，但 GIST 960 维每向量需大量 burst，DRAM 内部带宽被低效特征访问浪费；结果：距离计算 + 跨通道访问 + CPU 查找三者串行叠加，实际吞吐远低于 NDP 理论内部带宽。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法：NASZIP = 软硬件协同，四组设计逐一对应 Baseline 缺陷：(1) FEE-sPCA（对应解决 EE 收敛慢）——PCA 变换使前 k 维集中信息，用 α_k·d_part^k/β_k 估计全维距离，估计距离 ≥ threshold 更早触发；β_k 由 Chebyshev 不等式（Eq.6，P≥90%）校正避免误杀候选，保持 recall。feature 计算平均减 ~50%（GIST 80% 早退发生在 193 维内）。(2) Dfloat（对应解决 burst 内特征数少）——按特征段自适应 n_exp/n_man 位宽（12~32 bit，SIFT 三段 18/14/16 bit），每个 DRAM burst 装更多特征，FPU 前零填充回 FP32，不改计算单元、兼容 ECC。(3) DaM（对应解决跨通道通信与 CPU 邻居查找）——邻居表按与向量同 sub-channel 共置切分（NLT 表管理变长条目），邻居检索卸载到 NDP、消除跨通道通信；两 VPE 共享优先队列合并只回传 top 候选。(4) LNC + 预取（对应解决重复邻居访问与 hop 间隙空闲）——LNC-T（8KB，TLB 式）+ LNC-D（256KB，8-way）缓存 NLT 与邻居表，hop 间隙预取下一 hop 邻居表，batch=16 时隐藏 CPU 合并等待。结果：同 recall 下相对 CPU SCANN 8.4×、GPU CAGRA 1.4×、ANSMET 1.69×、能量效率较 ANSMET 1.5×。
  - 论文方法全栈执行例子（SIFT 1M 查询，NASZIP 6 通道 48 sub-channel）：算法层：查询经 PCA 变换（在线开销 0.149ms、占 3.6%）后进入 HNSW 搜索，每候选向量按 Dfloat 配置（18/14/16 bit 三段）每 burst 读 2 维，2 步后 d_est^k 超 threshold 即早退（约 50% 维数省掉）；系统框架层：HNSW 图遍历主循环仍在 host CPU，但邻居表查找卸载到 NDP（NLT 表），CPU 只做跨 sub-channel 的全局优先队列合并，hop 间隙被预取填充；编译框架层：论文未明确说明（Dfloat 打包与 PCA 为离线预处理，非在线编译）；kernel调度层：每 sub-channel VPE 4 路并行解码+算距+累加，FEE 模块逐 burst 判断早退，LNC-T/LNC-D 命中时免 DRAM 访问，prefetch 在 hop 间隙预取 q0/q1 的下一邻居表（batch=16）；硬件架构层：DDR5-4800 每 sub-channel 19.2 GB/s（聚合 921.6 GB/s），DaM 保证邻居与向量同 sub-channel 无跨通道中转，VPE/LNC/共享优先队列/控制器封进 DB chip（面积 0.7091 mm²，28nm），UniNDP 周期精确模拟得 QPS/延迟/recall；结果：同 recall@10≥90% 下 8.4×（CPU）/1.4×（GPU）/1.69×（ANSMET）加速，GIST 上增益最大（80% 维数早退）。
