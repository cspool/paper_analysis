## MC-ORAM: A Mask-Assisted and Counter-Based Non-Deterministic ORAM inside VM-Based TEEs

- baseline方法是什么？
  - baseline 有两层：(1) 无额外非确定性的 TEE+ORAM（Menhir 式）——把 ORAM 树/暂存直接放进 TDX/SEV-SNP 的 TME 加密内存，利用 AES-XTS 的确定性加密省去 ORAM 客户端逐块重加密，效率最高（带宽 1×）。痛点：AES-XTS(addr,D) 对同一物理地址同一明文产生同一密文 → 密文侧信道。攻击者可观察树/暂存密文是否变化：⟨Read 0, Read 0⟩ 第二次读时数据块 0 以概率 1/2 留在根节点导致整棵树密文不变，而 ⟨Read 0, Read 3⟩ 第二次读必改变某路径密文 → 区分优势 1/4；暂存条目内容不变则密文不变，暴露暂存占用与 dummy 位置，破坏 ORAM 访问模式不可区分性。(2) Obelix 式 64 位交错计数器——每 64 位数据配 64 位计数器、每次访问递增，保证同位置密文必变。痛点：ORAM 存储足迹与 DRAM 流量都翻倍（每 64 位访问多带 64 位计数器读-更新-写），带宽 2×，端到端比 TME 无计数器方案慢约 1.99×。
  - Baseline 全栈执行例子（PathORAM 一次逻辑访问，64 位交错计数器方案，N=2^14、B=256B、Z=4、L=14）：算法层：ORAM 块 D 布局为 64 位 data∥64 位 counter；系统框架层：TDX 内 ORAM 客户端查位置图 → 沿路径 P(l) 读 L×Z 个块入暂存 → 目标块处理 → 随机新叶子 → 驱逐写回；编译框架层：论文未明确说明（不涉及编译框架）；kernel调度层：CPU 对每个 64 位字执行"读计数器→更新→写回"，每字多带 64 位计数器读写，单次访问 DRAM 流量 = baseline 的 2 倍（计数器流量与数据流量等量）；硬件架构层：Intel Xeon + TDX TME 引擎按物理地址对 128 位 AES 块做 AES-XTS 加密，DRAM 带宽被翻倍的计数器流量吃满 → 平均访问延迟约为 TME 无计数器方案的 2×（Obelix 方案实测拖慢 PathORAM/RingORAM 约 1.99×）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - MC-ORAM：把 128 位 AES 块重排为 112 位 masked data + 16 位 counter，同一树节点/暂存内的所有 112 位块共享同一个 112 位随机掩码；每次访问计数器 +1（即使内容不变也递增），计数器到达 2^16−1 溢出时对整个节点/暂存执行轻量 Refresh（新随机掩码+计数器清零）。对应解决：① 16 位替代 64 位计数器 → 元数据从 1:1 降到 16/128=12.5%，带宽仅 baseline 的 1.125×（对比 Obelix 2×），存储减少 43.75% → 直接消除"计数器翻倍流量"痛点；② 共享掩码+计数器组合：同一掩码周期内两次访问计数器必不同（概率 1），跨周期掩码独立（概率 1−2^−112 不同）→ 加密前 128 位值必变 → AES-XTS 密文必变，消除密文侧信道（对应 baseline 第 1 层痛点），且避免纯 masking 每块每次重算 OTP 的高昂 AES 开销（纯 masking 实测慢 13.5×）；③ 刷新频率只依赖公开参数（节点刷新期望 3.05×10^−5/访问、暂存每 2^16/(2ZL)≈585 次访问一次）与访问模式无关、摊销开销 <1% → 不引入新泄漏，且不修改底层 ORAM 协议的任何树/暂存访问序列 → 完整继承 PathORAM/RingORAM 的访问模式不可区分性（对应 baseline 第 2 层"元数据翻倍"之外还保持了安全证明）。
  - 论文方法全栈执行例子（PathORAM+MC-ORAM 一次逻辑访问，B=256B=16 个 AES 块/ORAM 块、Z=4、L=14）：算法层：ORAM 块布局为 112 位 masked data∥16 位 counter，节点/暂存各持一个 112 位 mask；系统框架层：TDX 内客户端查位置图 → 读路径 P(l)（L×Z 块，TreeToStash 掩码写+全暂存计数器 +1）→ 处理目标块 → PosM[d]=Rand() → 驱逐写回（StashToTree，树+暂存计数器双 +1）；编译框架层：论文未明确说明；kernel调度层：对每个 128 位 AES 块执行 dst=(data⊕node.mask⊕stash.mask)∥ctr+1 的掩码写（暂存↔树掩码域转换），任一计数器=2^16−1 时 Refresh 整节点/暂存（new_mask=Rand()，每个块 data⊕mask⊕new_mask、ctr 清零）；PathORAM 读路径不递增树节点计数器（整路径末尾一次写回）；硬件架构层：TME AES-XTS(addr, ·) 对每个 128 位块加密写 DRAM——掩码+计数器保证同一物理地址两次访问的加密前值不同 → 密文每次变化，无密文侧信道；DRAM 流量仅 baseline 的 1.125×（每块多带 16 位而非 64 位计数器）→ 端到端 1.82× 加速（MC-ORAM 0.87ms vs PathORAM 1.48ms @N=2^14/cacheline），且 Qwen-8B 安全嵌入 1.41×、DLRM 1.66×。
