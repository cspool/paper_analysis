## COSM: A Cooperative Scheduling Framework for Concurrent PIM and CPU Execution on Mobile Devices

- baseline方法是什么？
  - Baseline 是共享内存 CPU/PIM 并发系统的既有控制接口 + 调度策略：(1) All-Bank Command（ISSCC'21 HBM2 FiM [42]）：单条命令触发全部 PIM 单元，执行期间所有 bank 被占用、CPU 无法访问 → 论文以 95% CPU/5% PIM 时间片轮转（含理想化零切换开销）近似，外部带宽在 PIM 阶段空转、PIM 命令须等全部 bank 就绪（Fig. 3b ①②）；(2) CPU-first（Chopim [39]，ISCA'20）：bank 的 CPU 请求队列非空即阻塞 PIM 命令、命令长=tBL——CPU 延迟保住但 ACT 与数据访问之间的 bank 空闲、跨 bank 命令串行化的内部带宽被浪费（Fig. 3c③；随机访问下内部带宽利用率上限 <15%），且短命令使命令总线饱和；(3) row-hit-aware（AsyncDIMM [38] HPCA'25 / F3FS [40] ISPASS'25）：PRE 命令时切换 CPU/PIM 队列以最大化行命中率，但对随机访问的 compute-intensive CPU 任务延迟恶化（实测 AsyncDIMM-Bank 使 CPU 性能 -89.9%）；(4) 所有 baseline 均无 CPU-mediated 传输的专门调度：传输与 CPU 访问同走 FR-FCFS 请求队列，传输的突发高行缓冲局部性使 CPU 任务降速 >80%（传输占 DeepSeek-R1-1.5B 解码注意力推理时间 50%–60%）→ 折合整体 CPU 性能 -40%；且输入传输→PIM 执行→结果收集三阶段由 CPU 软件串行控制，内部/外部带宽无法同时使用（Fig. 7a）。
  - baseline 全栈执行例子（DeepSeek-R1-1.5B 注意力层 KQV 生成，LPDDR5-6400 2ch×2rank）：模型推理算法层 = 标准 attention GEMV/MAC + softmax（16-bit 输入/8-bit 权重量化）；系统框架层 = 无并发调度框架，CPU 软件串行执行三阶段（传输→执行→收集）；编译框架层 = 论文未明确说明；kernel 调度层 = Chopim CPU-first（bank 队列非空即停 PIM、命令长=tBL 饱和命令总线）或 AsyncDIMM PRE 切换（随机访问 CPU 任务延迟恶化）；硬件架构层 = 单主机 bank 级 PIM 单元 + 标准 DRAM 读/写命令做 CPU-mediated 传输。结果：Chopim CPU 降速 3.0% 但 PIM 仅 1.9×（较 All-Bank）、Chopim(128) PIM 3.44× 但 CPU 降速 13.5%、AsyncDIMM-Bank PIM 4.2× 但 CPU -89.9%——固定长度命令下 PIM 吞吐与 CPU 延迟不可兼得。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = COSM，从 PIM 控制接口与内存调度两层协同：(1) 对应"长命令高吞吐 vs 短命令低延迟"矛盾——可抢占 PIM 执行命令：PIM_Exec(nPTL=128) 让 PIM 单元按 tCCD 自主逐列执行（命令总线占用降 nPTL/tCCD 倍），CPU 请求到达时 PIM_Pause 在列边界原子暂停（完成当前列、冻结 CSC/PC、释放总线），仲裁器用 PC_inf=(clk-clk1)/tCCD 推断进度、CPU 访问后重发原命令从冻结列恢复；(2) 对应"CPU-mediated 传输干扰 CPU"——带宽解耦传输命令把一次传输拆成外部总线段（PIM_RdBuf/PIM_WrBuf，控制器↔bank buffer）与内部带宽段（PIM_LdBuf/PIM_StBuf，buffer↔bank），分别利用 bus/bank 空闲窗口，不再要求内外同时空闲，配套每 bank 1kB SRAM buffer；(3) 对应"空闲窗口利用不精确"——IWE 模拟 FR-FCFS 顺序估计每 bank 最早服务周期（Algorithm 1）输出 window_bank/window_bus，Command Arbiter 严格优先级（CPU/refresh > PIM_Pause > PIM 命令）：推迟过早 ACT 把 PIM 执行塞进 ACT→数据访问窗口、把总线传输塞进 window_bus 前空闲、把 PIM_Pause 延迟到不推迟 CPU 访问的最后周期；(4) 对应"三阶段串行浪费带宽"——overlapped scheduling 把 workload 切成无依赖 tile，跨 tile 并行传输与执行（收集 T_i 时执行 T_{i+1}），PIM_Barrier 隔离阶段；(5) 对应"软件栈改造代价"——编译器把 MAC/softmax 直接翻译成 PIM_Exec(L/S)、把读写分解为 PIM_WrBuf&PIM_StBuf / PIM_LdBuf&PIM_RdBuf 命令对、在 tile 边界插 PIM_Barrier，不改用户程序与 OS，权重预组织在 bank 内静态常驻。
  - 论文方法全栈执行例子（同一 DeepSeek-R1-1.5B 注意力层）：模型推理算法层 = 同一量化 attention（权重在模型加载时预组织进 bank、推理期静态常驻）；系统框架层 = 内存控制器驱动层命令翻译 + tile 切分，无 OS/程序改动；编译框架层 = 编译器辅助翻译 GEMV/softmax → PIM_Exec(L/S)、读/写序列 → 命令对、tile 边界 → PIM_Barrier；kernel 调度层 = IWE 预测 bank/bus 空闲窗口 → PIM scheduler 按"总线命令 > buffer 命令 > 执行命令"优先级跨 tile 重叠调度 → Command Arbiter CPU 优先仲裁 + 极限延迟 PIM_Pause；硬件架构层 = Ramulator2 内 PEQ/PRWQ + IWE + PIM scheduler + Command Arbiter，LPDDR5-PIM 模块带 PEE（CSC/CR/PC）与 bank 级 SRAM buffer（16 PIM 单元/rank，1GHz 6.4TFLOPS）。结果：PIM 吞吐较 All-Bank 6.0×、较 Chopim 2.8×，CPU 降速 <2.0%；较固定 32-cycle 命令 PIM 性能 2.02×（CPU 干扰 <5%）；能量较 AsyncDIMM-Bank/Chopim 降 1.34×/1.61×；控制器面积开销 0.069 mm²（7.4%）。
