## Lotus A Multi-FPGA Task Dataflow Architecture to Accelerate Cycle-Level Simulation

- baseline方法是什么？
  三类 baseline：(1) 多核 CPU 软件 RTL 仿真器：Verilator 把电路编译为多线程 C++ 程序，节点静态调度到线程，靠共享内存同步保证依赖；RepCut 通过复制节点、限制通信只发生在模拟周期之间，也只能扩展到几十线程。执行例子：Verilog 设计 → 提取数据流图 → 节点映射到线程 → 同周期边（wire）导致频繁共享内存通信/同步 → 多核 CPU 因同步开销几乎不扩展 → 仿真速度远低于 1 MHz。(2) 硬件仿真器 emulator（ZeBu/Protium/Palladium 等）：RTL → 综合成门 → 空间映射到多个 FPGA → 每模拟周期跨芯片锁步通信值。执行例子：设计分到 10–60 个 FPGA → 每周期各 FPGA 间传递信号，跨芯片延迟数百 ns → 速度被限制在几 MHz（每 FPGA 只用可达速度约 1/100）；编译耗时数天到数周，系统规模限制可仿真电路大小，只支持 RTL。(3) 单芯片任务数据流加速器：ASH（动态展开数据流图 + 投机选择性执行，硬件复杂，难扩展多芯片）、Manticore（全局可门控时钟，无法多芯片）——都只到单芯片、数百核，达不到 emulator 速度。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  Lotus 的关键洞察：多 FPGA 仿真器被跨芯片通信瓶颈拖累，空间映射没有意义；改为"时间映射"——把设计编码为静态同步数据流图，数千个通用 RISC-V 核在 8 块 FPGA 上随时间执行图上的小任务，多个任务复用同一核，通信与计算解耦、隐藏跨芯片延迟。具体设计对应关系：①静态数据流图 → task unit 在配置时存好全部图信息（函数指针、输出 token 目的地、输入存储，永不溢出），taskId 直接索引避免关联查找 → 比 ASH 动态展开省 17× 逻辑；②优先级执行：taskId 作为优先级 + 分层位图队列（每周期入队出队）→ 聚焦关键路径，替代 ASH 昂贵的流水线堆；③选择性执行：CMB 保守同步（比较奇偶周期输入，不变则跳过并发 null token）→ 非投机，仅 1% 逻辑，避免 ASH Time Warp 的 2× 开销；④400MHz 高主频 + 异步 token 通信 → 弥补用核代替直接映射的开销，使每 FPGA 利用率远超 emulator；⑤编译器分层 PaToH 划分 + 同周期边强制同 FPGA + coarsening/temporal unrolling → 最小化昂贵的跨芯片流量并提高计算/通信比。全栈执行例子（以 NTT 为例）：(a) 算法层：2048 点 NTT 表示为 11 级流水线、11264 个模乘任务节点的数据流图；(b) 系统框架层：Lotus DSL（或改版 Verilator）描述图，编译器分层映射到 8 FPGA/544 tiles，同周期边不跨 FPGA；(c) 编译框架层：coarsening 合并小任务、temporal unrolling 2×/4×、插入 order edges、生成 task unit 配置；(d) kernel调度层：每模拟周期 task unit 按 (cycleId, taskId) 收 token，就绪任务按优先级派发到 4 核执行任务函数，输出单元产生输出 token；(e) 硬件架构层：token 经 FPGA 内 25×25 蝶形交换机、跨 FPGA 经 Aurora 光链路（200ns）送达，选择性执行跳过不变调用，每秒派发超 2000 亿任务、约 900 GIPS → NTT 仿真 2.47 MHz，比 emulator（800KHz）快 3.09× 且少用 7.5× FPGA。
