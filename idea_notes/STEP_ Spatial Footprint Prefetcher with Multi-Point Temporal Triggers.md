## STEP: Spatial Footprint Prefetcher with Multi-Point Temporal Triggers

- baseline方法是什么？
  - baseline 是传统空间足迹（spatial footprint）预取器家族（SMS/Bingo/Gaze/DSPatch/PMP 等，及 ISO-storage 增强版 eBingo = Bingo + dense-PC 流检测）：SMS 引入 FT/AT/PHT 通用框架，页足迹按位向量记录、以事件 key 查 PHT 预测；Bingo 在单触发点靠更丰富的匹配（特定历史可用时用、不可用时 fallback 到粗历史、多候选聚合）提升精度；Gaze 把触发推迟到第二访问点以利用 offset 间短时相关；DSPatch/PMP 用双模式/模式合并提升覆盖。它们共同的组织原则：每个内存区域只在单一固定时间点（首访问 FO 或后续某点）做一次预取决策，把触发时机、精度、存储三者锁死在固定 trade-off 中——早触发机会多但上下文少，需更 rich key、fallback 或更大的元数据表维持精度且易污染；晚触发证据足、更准但必然错过早期机会（如页上下文在第二访问前就消失的短命页）。算法pipeline/系统框架/编译框架/kernel调度/芯片设计层次：论文未明确说明（无 ML/软件栈/编译器/GPU kernel 成分）。
  - baseline 全栈执行例子（eBingo 在 ChampSim 中，一个 4KB 页首次被访问）：算法层——页首访问以 PC+Address 作 key 查 PHT，得到历史足迹候选，必要时 fallback 粗历史、多候选聚合后一次性下发；系统框架层——ChampSim OoO 流水线把该访问送到 L2 预取器回调；编译框架层——论文未明确说明；kernel调度层——预取器把候选足迹直接作为预取请求插入 L2 预取队列/MSHR，无论当前证据是否充分，单次决定、无后续修正；硬件架构层——FT/AT/PHT 在固定触发点完成匹配→下发，早触发时靠大表（Bingo 类 >100KB）维持质量，晚触发（Gaze 式）则丢失首访问即消失的短命机会（如 mcf-192 单 PC 快速跨大量页、FT 条目在二次访问前被逐出）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 STEP：把"单点触发 + 候选选择"重构为"序列化触发决策"问题——在一个页的 cache 生命周期内设置三个触发点 FOE/SOE/TOE，每点用轻量 prefetch-confidence evaluator 判断当前匹配历史是否足够收敛（最近 N=3 个匹配足迹的 Jaccard 相似度全 > T=0.75），足够才下发交集 footprint，否则等待下一触发点累积证据。设计逐条对应 baseline 缺陷：① 早期机会（晚触发丢失）→ FOE 在首 offset 事件即可行动，hashed PC 低代价消歧调用上下文 + maturity 标志防止冷启动单匹配被误信，使短命页上下文消失前就能发预取（mcf-192 场景）；② 后期精度（早触发污染）→ TOE 用满 3 offset 的精确 tag 消除歧义（mcf-484 region 0xfe3 场景，避免选错候选带来的 30/12 条无用预取与 11 条漏取），把决策推迟到证据充分；③ 精度-覆盖-存储矛盾（baseline 靠大表）→ 统一 PHT（TOE 蕴含 FOE/SOE，按事件截断 tag 复用同一表）+ Jaccard 收敛测试 + 交集下发 + N=3/T=0.75 轻量逻辑，总量仅 10.5 KB，即达 eBingo 需 >100 KB 才逼近的性能；④ 流式模式占历史容量 → 复用 Gaze 的 DPCT dense-PC 流检测，把流处理与 footprint 学习解耦（正交组件）。消融（STEP-D1/D2/D3/STEP-FULL）显示 FOE 主要贡献 SPEC06 早期机会、TOE 主要恢复精度、SOE 平均冗余（最终配置禁用 SOE 下发），但 cactuBSSN/sphinx3/roms 等需中间触发点——说明无单一固定触发点普遍最优，这正是多触发动机。算法pipeline/系统框架/编译框架/kernel调度/芯片设计层次：论文未明确说明。
  - 论文方法全栈执行例子（STEP 在 ChampSim，mcf-192 的短命页）：算法层——页首访问以 FOE（first offset + hashed PC）查 PHT 取最近 N=3 个匹配足迹；系统框架层——ChampSim 流水线把 L1-L2 总线上的访问送 L2 旁的 STEP 硬件；编译框架层——论文未明确说明；kernel调度层——confidence evaluator 对 3 个足迹两两算 Jaccard，全 >0.75 则下发交集 footprint 到 L2 预取队列（队列满时暂存 PB 待重发），否则推迟 SOE/TOE；FOE 单匹配时检查 maturity 标志（hashed PC 与同位置被逐条目一致才成熟）；硬件架构层——FT(256)/AT(128)/PHT(512)/PB(32)/DPCT(8) 共 10.5 KB，作为 L2 旁 add-on 监听总线插入预取；结果：SPEC CPU2006 1.49×/SPEC2017 1.40×/CloudSuite 1.07×，总几何均值 1.28× 超 eBingo 1.26× 与 Gaze 1.24×，L1 级同样最佳（1.28×），1-8 核同构/异构领先，受限 way 预取下仍 1.263×。
