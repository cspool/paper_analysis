## Omelet: A Packaging-Aware Hierarchical Interconnect Simulator for 2.5D/3D Chiplet Architectures

- baseline方法是什么？
  - Baseline 是现有 chiplet/互连模拟器（解析式：RapidChiplet、3D-CIMlet、Gemini、HISIM；周期级：Kite、CNSim、SIAM）。共同三大缺陷（论文归纳为 L1–L3）：L1) 解耦分层通信建模——把 NoC、NoI、NoL 当作独立通信域分别仿真、事后相加延迟（SIAM 逐域跑 NoC 与 NoP 再 sum；CNSim 把 chiplet 间通信建模为 NoC 的直接 PHY-bridged 扩展而非独立路由的 NoI），丢失跨层 backpressure、边界队列耦合与拥塞跨层传播；L2) 技术无约束手动参数化——用户手工给 latency/bandwidth 常数，或从不相容来源拼凑参数（一个论文的 wire RC + 另一个的 driver energy），物理上不自洽、可能不对应任何可实现的物理结构，还加重架构师负担；L3) die-to-die 链路整体抽象——把 off-chip 链路建模为单一抽象链路、延迟只随距离缩放（Fig.2c：0.5mm 与 15mm interposer hop 都算 1 cycle），掩盖 driver/wire/via/bonding 各自不同的延迟与带宽贡献。HISIM 虽含 TSV/wire RC 但漏 driver 与 bonding，端到端行为对 bonding 选择不敏感。
  - Baseline 全栈执行例子（一次 2.5D 4-chiplet 系统跨 chiplet 数据移动，Kite/SIAM 风格）：算法层：core 计算产生需跨 chiplet 传递的数据（如 DNN 中间张量）；系统框架层：gem5 全系统/合成流量把数据注入 NoC 网络；编译框架层：论文未明确说明（模拟器无编译流程）；kernel调度层：论文未明确说明（无 kernel 概念）；硬件架构层：packet 走 NoC router（Garnet 风格）→ 越 chiplet 边界时用统一常数 hop_latency("noi", ℓ)=1（距离无关，Fig.2c）或单一解析式 off_chip_latency=2*length → 事后把 NoC 延迟 + NoI 延迟 + NoL 延迟相加为端到端延迟；由于各域独立仿真（仅回放注入），NoI 拥塞无法回压 NoC，NoC 注入率持续上升 → 过早饱和、过度估计吞吐；换 bonding 技术（solder→hybrid bond）链路参数不变，无法反映物理带宽差异。芯片设计层：chiplet 排布在 interposer 上但链路参数与 bonding pitch/interposer 材料/TSV 几何无关，无 beach-front/重叠区物理约束。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法：Omelet 用统一周期级框架（Network-on-X / NoX）把 NoC–NoI–NoL 整合为单一 flit-level 网络图，以物理推导的组件级链路参数驱动仿真，三大贡献直接对应解决 L1–L3：
    1. Unified Hierarchical Network Modeling（解 L1）：单一 cycle-level 框架内实例化三层网络；NoX engine 按 3D 放置坐标（x,y,z）自动判 2.5D lateral / 3D vertical 连接并分配技术标签；检测到技术域失配时自动插入 PHY transition queuing adapter、SerDes 序列化/聚合延迟（∝数据率比）与 CDC 1 cycle；拥塞/背压跨层自然传播（NoI 饱和回压 NoC 注入端），消除"独立仿真+事后相加"的错误叠加（实验显示 unified/isolated 的 load-latency 曲线无一致偏移关系，isolated 更早饱和）。
    2. Physically-Derived Technology Input（解 L2）：用户只指定集成技术（interposer 材料、bonding 类型/间距、TSV 几何、RDL L/S），Omelet 从预表征技术表（HFSS EM 提取 + SPICE 电路仿真，0.1–7GHz 按 pitch 扫描）取回 latency/BW/EPB，无需手工调参；保真度经与 TSMC CoWoS RDL RC scaling（平均差 3.5%）与 SuperCHIPS 实测链路（-2.49% ~ +11.75%）交叉验证。
    3. Component-Based Die-to-Die Link Modeling（解 L3）：链路建模为 driver→RDL/interposer 走线→vias→bonding 的组件链（Elmore delay + SPICE 链式仿真；长度相关条目作分布式元素缩放、lumped 元素固定；BW_link=6/τ），带宽按 bonding perimeter/bump pitch 得 lane 数 λ 与 W=floor(λ·R_lane(ℓ)/(f_clk·F_bits))；beach-front 共享周长、垂直重叠区、TSV 密度、interposer span 等物理约束由 Placement Engine 检查并参与带宽核算。
  - 论文方法全栈执行例子（同一次 2.5D 4-chiplet 跨 chiplet 数据移动）：算法层：core 计算产生跨 chiplet 数据；系统框架层：gem5 全系统或合成流量注入，chiplet 作流量端点；编译框架层：论文未明确说明；kernel调度层：论文未明确说明；硬件架构层：packet 进 NoC router（4 级流水、4 VC、4 flits/VC）→ chiplet 边界 adapter 检测 NoC（快窄）→ NoI（慢宽）失配，插入 PHY transition + SerDes 聚合/序列化（延迟∝带宽比）+ CDC 1 cycle → NoI router 间经 interposer RDL 链路逐 hop 传输，每 hop t_cyc 与 W 由技术表按长度 ℓ 索引（hybrid bond 1µm pitch → λ 大 W 宽；solder 30µm → W 窄），RC 衰减经 R_lane(ℓ) 体现 → 拥塞跨层传播（NoI 拥塞回压 NoC，延迟饱和点更晚且端到端延迟更低）→ 目标 chiplet adapter 反序列化 → NoC → 目标 core；DSE 引擎同时扫描 topology×placement×packaging（穷举 ≤10³ 点或模拟退火），输出 Pareto 最优集与 latency breakdown 瓶颈归因。芯片设计层：Placement Engine 执行 interposer span/TSV 密度/beach-front/垂直重叠约束并输出逻辑+物理坐标 place map，bonding/interposer 参数直接驱动系统级延迟与能耗。
