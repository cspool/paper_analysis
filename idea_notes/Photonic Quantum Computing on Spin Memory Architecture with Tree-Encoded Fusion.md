## Photonic Quantum Computing on Spin Memory Architecture with Tree-Encoded Fusion

- baseline方法是什么？
  Baseline 分两组：(1) 同架构（spin memory）的 boosted-fusion 方案——redundantly-encoded fusion [25]（m 个叶量子比特冗余编码逻辑量子比特，m 次融合尝试，逻辑失败率 P_fail=p_fail^m 下降，但逻辑擦除率 P_eras=1-(1-p_eras)^(2m) 随 m 指数恶化）与 repeat-until-success (RUS) fusion [40]（类似但成功后终止，P_eras=Σ_{i=0}^{m-1}p_fail^i·2p_eras，消耗更多 ancilla 与时间）；(2) 跨架构 SOTA MBQC 编译器——OneAdapt [74]（all-photonic 架构，迭代生成资源状态层 RSL 并 normalization 成有效 2D 图态层，只处理融合失败、忽视融合擦除；normalization 光子利用率极低——从 84×84 RSL 只 normalize 出 4×4 2D 层）与 RLGS [38]（emitter-based，确定性发射但 emitter-CZ 未实验演示，评估基于理论假设，与近端 PQC 有差距）。
  Baseline 全栈执行例子（OneAdapt 执行 36-qubit VQE，p_eras≈1%）：算法层：量子程序经 MBQC 编译为图态，融合错误仅按融合失败建模（失败 = 已知图变换，可 normalization 恢复）；系统框架层：论文未明确说明（MBQC 编译栈，无 serving 概念）；编译框架层：OneAdapt 迭代生成 14n×14n RSL → normalization 成有效 2D 图态层，光子源利用率 ~0.03%；kernel调度层：资源层生成与融合按 time-like 模型调度（虚拟层 D_f=30、PL=4 物理资源层、time-like 边 960 ns），融合失败重试；硬件架构层：all-photonic 线性光学（PsiQuantum 平台，125 MHz 源泵浦、T2=2.04 μs、σ_fus=99.75%、t_cycle=8 ns）；结果：生成 84×84 RSL 需 >10^5 次融合，整个 RSL 不经历擦除的概率极低 → 执行时间指数增长、decoherence/CZ 误差累积、QAOA 需更多调优迭代。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  论文方法 = tree-encoded fusion + MemTree 编译框架 + quantum spin memory 架构（硅基量子自旋内存，InGaAs QD 发射器生成 caterpillar 态，已小规模实验验证 [29]），三处设计逐点对应 baseline 缺陷：
  1. 树编码融合（对应缺陷：baseline 只抗失败不抗擦除）：逻辑量子比特编码为根 + b 分支（每分支 3 qubit 线性图 {q_i^a,q_i^b,q_i^c}），叶子 q_i^c 做融合测量，q_i^a/q_i^b 做间接测量辅助——融合擦除时用 stabilizer X_i∏Z_j 做间接 Z 测量无损消除被擦除 qubit（区别于 baseline 只能丢弃结果），融合失败时 Z 测量移除 q_i^b 并留 q_i^a 备份。每个分支的擦除影响被限制在单分支内，逻辑成功率 S_tree=1-(1-(1-p_eras)^2+p_fail)^b 在 p_eras 升高时远优于 P_eras 指数恶化的 redundancy/RUS（Fig.4(f) 10^3 次试验验证）；树结构可轻松从 caterpillar 态组装（主路径 q_root + 叶 qubit + Z 测量分离的 4-qubit 线性图融合）。
  2. MemTree 编译器（对应缺陷：OneAdapt normalization 光子利用率极低 + 全图一次性融合成功率不可行）：两个 MIP 模型（Gurobi）——MIP-1 把目标图态划分为最小融合数的线性子图（约束 deg(v)≤2，min 切割边），MIP-2 递归二分构建平衡二叉树 BBT（平衡约束 + min 每层切割）最小化临界路径；融合失败只重试子树而非整图；caterpillar 生成 program-agnostic、结构按需确定 → 光子利用率 ~10%（vs OneAdapt 0.03%）、光子源 0.18×、编译时间 0.14×、执行时间指数级下降。
  3. realistic 模拟器 + 真实硬件验证（对应缺陷：RLGS 基于未验证的 emitter-CZ 假设）：模拟器噪声配置全部来自已演示实验（[25][29][30][43][52]），并在 Quandela 云端 PQC + Perceval 上做了 6~12 qubit QAOA 真实硬件实验（树编码融合光学电路 + FFCircuitProvider feed-forward），相对 RUS+photonic（PST 2.68×/IST 3.23×）和 Qiskit+IBM Torino 超导（PST 2.20×/IST 2.91×）均提升——证明 PQC 低 crosstalk、CZ 操作高并行度的优势在擦除问题解决后真正释放。
  论文方法全栈执行例子（36-qubit VQE 在 MemTree + spin memory 上执行）：算法层：程序图态 g_prog（顶点=qubit、边=CZ 纠缠），融合错误同时按失败与擦除建模；系统框架层：论文未明确说明；编译框架层：MIP-1（Gurobi）划分线性子图（deg≤2、min 切割边、后处理切环/适配 30-qubit）→ MIP-2 递归二分构建 BBT（min 每层切割 L、平衡约束）→ 输出分层融合计划（每时间步融合数）；kernel调度层：等价于融合执行调度——每时间步 BBT 一层并行 Type-II 融合，树编码分支测量模式（成功：X,X 连根；失败：Z+备份；擦除：X+Z 间接 Z 测量）由 feed-forward（<5 ns，SNSPD + 组合逻辑 + 延迟模块）决策，失败 → 兄弟子图延迟下一时间步；硬件架构层：InGaAs QD 发射器 12 ns 初始化 + 0.6 ns/qubit 生成 caterpillar（≤30 qubit、t_cycle=30 ns），融合用 HWP+PBS 线性光学（σ_fus=99.75%、1-p_fail=0.75、T2=2.34 μs、p_eras~1%），Perceval 电路在 Quandela 云平台验证；结果：执行时间 1.5×10^-2×（vs OneAdapt）、光子源 0.18×、编译时间 0.14×、fidelity 3.64×，F_de/F_CZ 相对 RLGS 亦提升（QFT/QAOA 指数级）。
