## PipeIMC a Pipelined In-SRAM Computing Architecture

- baseline方法是什么？
  - Baseline 是两类 in-order 存内 SRAM 计算架构：SIMT-EVE [2]（bit-hybrid 数据布局、in-order vector engine 控制方案，把 cache 阵列变成大 SIMD 式寄存器文件）与 Duality Cache [11]（in-order SIMT 控制、bit-serial 数据布局、VLIW 式机制，数组要等整个 VLIW 指令完成才能执行下一条）。共同缺陷：in-order 执行机制强制操作严格串行——每个操作必须等前驱操作完成；单端口计算 SRAM 无法同时取数与计算，操作间无数据依赖时也无法重叠；复用相同 wordline 引入迭代间依赖；分支/控制流（control hazard）与 barrier 进一步造成长 idle；且计算 SRAM 在 memory step（地址生成/访存/写回）期间端口空闲。
  - Baseline 全栈执行例子（Rodinia matmul，一个 512×512 分块乘法的 in-SRAM 执行）：算法层：SIMT 程序（如 for 循环内 A1*B1）编译为 IMC 操作序列 O1..O4+Branch（O1 = load A1/B1 + 乘；O3/O4 操作数已在 wordline 上，无 memory phase），32-bit 定点；系统框架层：CPU 发 compute request 配置 cache 分区（compute/cache ways），FSM 失效/写回脏行保一致性；编译框架层：OpenCL + 自定义 IMC intrinsics 经 POCL-Vortex 编译成 IMC 指令；kernel调度层：论文未明确说明（FSM 按序逐条执行 IMC 操作）；硬件架构层：单端口计算 SRAM 按 in-order FSM 执行——memory phase（地址生成→访存→写回三步）完成后再执行 calculation phase，O1 的计算与 O2 的取数严格串行，关键路径覆盖整个操作序列，计算期间取数端口空闲，数据依赖/分支造成大量 stall；芯片设计层：256×256 计算 SRAM + 1-bit 外围电路（logic/add/shift/writeback 四层）。结果：SRAM 利用率低（对比 PipeIMC 仅约 1/2.15–1/3.96）。

- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 = 两级流水（memory/calculation stage）+ dual-port 计算 SRAM + 显式寄存器重命名 + 乱序调度（dispatcher）+ 细粒度 issue。对应关系：
    1. 双端口计算 SRAM ↔ 单端口串行取数/计算：calculation phase 占用 calculation port 时，memory port 可同时执行下一条无依赖操作的 memory phase 取数，操作间重叠、关键路径缩短；
    2. 显式物理寄存器重命名 ↔ 数据依赖/端口冲突（含迭代间 wordline 复用）：alias table + free list 运行时分配物理 wordline，消除 write-first、双端口写、read-first 三类冲突，同窗口内无依赖操作不会冲突，调度更自由；
    3. 乱序 dispatcher（Algorithm 1）↔ in-order 串行与 control hazard：操作表（16 条目）+ 每周期选发可调度 phase（每操作至多一个 on-fly phase、barrier/fence 到表顶、memory phase 与控制流 phase 优先），计算可跨过内存等待与分支提交（操作不会回滚），减少 control hazard stall；
    4. 细粒度 issue + SA latch ↔ memory step 期间计算端口空闲：memory phase 地址生成后即移交 memory unit 释放端口，sense amplifier 的 latch 支持计算 phase 冻结/恢复，memory port 在空闲期也能执行计算 phase，最大化流水利用率。
  - 论文方法全栈执行例子（同一 matmul 请求，Pipe-2r 配置）：算法层：同一 IMC 操作序列（O1..O4+Branch），INT32 定点/INT8 量化（attention/ffn）；系统框架层：CPU compute request → controller 把 cache 分区为 compute/shared/cache ways + 一致性 FSM，kernel 结束恢复关联度；编译框架层：Vortex ISA + 自定义 intrinsics（R/I 型编码含 memory flags，操作编译为 ≤3 phase：load/compute/store）预写入 tag array；kernel调度层：论文未明确说明（模拟器内 warp 调度 + SIMT control stack + IPDOM stack 的 split/join 处理分歧）；硬件架构层：frontend pipeline（取指-解码-派遣）→ renaming unit 分配物理 wordline 并插入操作表 → dispatcher 乱序选发（O2 计算 phase 上 calculation port 时，O3 的 memory phase 在 memory port 并行取数；barrier/fence 到表顶才执行；特殊 phase 优先）→ dual-port 256×256 hybrid-8 SRAM 微码执行（add 9、sub 17、mul 105–634、div 145–1174 cycles；memory port 空闲时执行计算、SA latch 冻结/恢复）→ commit unit 更新 usage counter、释放旧寄存器并通知 warp scheduler；芯片设计层：TSMC 40nm 双端口计算 SRAM（面积 +55.7%/+18.2%、静态功耗 +48.1%，SNM 单端口读 192.9mV/双读 134.6mV/写 409.3mV）→ 端到端 Pipe-2r 平均 speedup 155%/113% vs EVE/Duality Cache，利用率 2.15x–3.96x/1.13x–4.77x，per-area 性能 2.17x/1.68x、能效 1.92x/1.60x。
