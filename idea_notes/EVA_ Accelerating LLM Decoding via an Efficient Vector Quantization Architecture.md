## EVA: Accelerating LLM Decoding via an Efficient Vector Quantization Architecture

- baseline方法是什么？
  - Baseline 为 VQ-based LLM decoding 的两类实现：(1) 软件框架——AQLM [15]、QuiP# [58]（PyTorch），把权重聚成码本 WC + 索引 WI，在线 1-to-1 查表重建权重后做 GEMV；通常比 FP16 推理更慢 [41]；(2) LUT-based 加速器——GOBO、LUT Tensor Core、LUT-DLA、FIGLUT，靠复制（duplication）或广播（broadcast）码本到多个 PE 缓解 bank 冲突。共同痛点：①计算低效——decoding 仍是 M=1 的 GEMV，现代加速器按大 GEMM 优化，GEMV 下大多数 PE lane 空闲（32×32 阵列 batch=1 时仅 1 lane 活跃；FIGLUT 用 4-input LUT 广播也只达 4.34% 利用率），且算术强度低、权重反复从 DRAM 取；②访存低效——1-to-1 查表不规则/非合并，bank 冲突严重（同 bank 索引同时访问被串行化），广播/复制代价高昂：FIGLUT 广播 16×32×(8×16bit) 带宽、LUT-DLA 需 256×(16×16bit) 复制寄存器，码本有效规模被限制在 ≤16 条目；③VQ-LLM [41] 只靠 profiling 把索引分 hot/cold 缓解冲突，未消除根本问题。
  - baseline 全栈执行例子（FIGLUT，batch=1，LLaMA-2-7B FC 层一个 token）：模型推理算法层 = 权重按 4-input LUT 模式聚簇（BCQ 二元编码），decoding 为 GEMV y=xW，激活 FP16/权重 4bit；系统框架层 = 论文未明确说明（LUT 加速器无 Serving 框架）；编译框架层 = 论文未明确说明；kernel调度层 = 4-input LUT 查表（激活作输入、权重模式作索引取预计算部分和）广播到 32 PE 列，多次查表串行化——索引落同一 bank 时阻塞（Fig. 1b 中索引 5 与 3 同 bank 冲突）；硬件架构层 = LUT 加速器：16×32×(8×16bit) 广播带宽，bank 冲突限制并行度与 cache 效率；结果：带宽压缩明显但吞吐仅 44.49 GOPs（2.82×SA），解码利用率 4.34%，WikiText-2 ppl 5.58（4bit）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = EVA，两步 aha insight 的软硬件协同架构，直接消除"计算低效 + 查表冲突"两个缺陷：Step1 codebook dot product（对应"GEMV 计算低效 + 查 WC 重建权重"）——不重建权重，直接算输入向量×WC：X∈R^{(K/d)×d} 与 B∈R^{d×2^n} 做 GEMM 得 OC∈R^{(K/d)×2^n}，把 decoding 从 GEMV 变 GEMM（M 维从 1 扩到 V=K/d>512，填满阵列），计算量从 K×N 降到 K×2^n（N=4096、2^n=256 时约 16× 少），访存规则化/合并化；Step2 conflict-free OC lookup（对应"查表 bank 冲突"）——以 WI 从 OC 查找而非从 WC 查找，OC 行按 V 维映射到独立 bank，同列不同索引自动落不同 bank（索引 5/3 对应 v0/v1 不同 bank），彻底消除冲突，且每次访问带宽从读 d 个 FP16 降为 1 个 FP16；硬件侧：混合精度 PE（32×32 INT8 重配 32×8 FP16，FP16 由 4×INT8+6-bit adder+XOR 重构）兼容 prefill INT8 与 decoding FP16，轻量 EU（add-only 加法树 + 对角累加）承接查找+归约并与 GEMM 流水重叠（EU 为关键路径、仅加法器，扩展代价极小）。缺陷→设计映射：GEMV 利用率低 → VQ-GEMM 扩 M 维（V=K/d）；查 WC 冲突 → 查 OC 冲突无关；码本复制/广播带宽贵 → OC 查找天然跨 bank 分布、无需复制；FP16 硬件贵 → INT8 阵列重配。
  - 论文方法全栈执行例子（EVA-A16W2，batch=1，同一 LLM FC 层一个 token）：模型推理算法层 = AQLM-2×8 量化（d=8,n=8,C=2,q=2bit），decoding 变 VQ-GEMM：O=X·B 后 ŷ=Σ_c Lookup(O_c, I_c)；系统框架层 = 论文未明确说明（无 Serving 框架修改）；编译框架层 = 论文未明确说明；kernel调度层 = input tile（32×8）与 WI（32×N）流式从 DRAM 流入，WC/output 片上静止，GEMM 产出 OC 直接片内送 EU（无片外往返），与下一 tile 重叠；硬件架构层 = 32×8 FP16 重配阵列 256 cycles 完成 VQ-GEMM，4 个 EU 做冲突无关查找 + 加法树累加（每 EU 32 加法器处理 32×8/C=128 权重元素），DDR4 64GB/s 流式喂 WI；结果：EVA-A16W2 对 SA/ANT/FIGNA/FIGLUT 分别 31.56×/32.53×/33.50×/11.17× 加速（Fig. 10a），能效 7.17× vs FIGLUT（Fig. 10b），2-bit 精度 ppl 6.69 保持竞争性（FIGNA-INT2 崩到 2.2e5，Table V）。
