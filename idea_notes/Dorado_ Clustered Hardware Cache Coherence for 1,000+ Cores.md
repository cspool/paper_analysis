## Dorado: Clustered Hardware Cache Coherence for 1,000+ Cores

- baseline方法是什么？
  - Baseline 为 Dir2B：扁平目录式 MESI 协议，每目录项 2 个 10b 共享者指针 + Broadcast(B) 位。每个 cache line 由物理地址哈希固定到唯一 home 目录分片（可能位于远端簇），L2 miss 事务必须先到 home 串行化再转发/响应，跨簇事务延迟与流量随核数增长；指针只有 2 个，共享者超 2 个即置 B 位、写时广播失效并等待所有 ACK，流量大且 clean 驱逐不能静默；目录各类型条目/指针按固定结构静态分派，无法适配不同负载的本地/远端访问比例（Redis 以远端为主、FaaSFunc 以本地为主）。
  - baseline 全栈执行例子：簇 1 的 core A 对 home 在簇 2 的 line 读 miss → L2 miss → 簇内 mesh → 跨簇 60 cycles RT → 簇 2 home 目录查找 → 数据跨簇返回；当该行共享者 >2 个时 B 位置位，随后任一核写该行 → 目录向 1024 核广播失效并收集 ACK → 写延迟与网络流量随共享者数放大。算法-系统框架-编译框架-kernel 调度层：论文未明确说明（负载为图分析/KV/FaaS/ML 推理服务/微服务等云应用，MLPerf DLRM/CNN 仅作为 benchmark 工作负载，论文无模型算法、Serving 框架或 GPU kernel 的改动）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法一 Two-Level Homes（对应 baseline 远端 home 串行化缺陷）：line 在 Global home 之外，于每个被引用的簇内按需分配 Temporary home 目录分片（物理地址哈希选本地分片），本地事务在簇内完成；Global home 仍是最终串行化点——先锁 Global home 才能锁 Temporary home，避免不一致与死锁。配套三种指针：LLptr（本地 core ID）/LRptr（远端 cluster ID，一个指针覆盖远端簇 32 核）/RLptr（Temporary home 中本地 core ID）；簇化后 5b 指针节省的存储换成更多指针；新增 ModifiedShared(MS) 状态让本地两核共享脏远端行而不回写 Global home。
  - 方法二 Dynamic Apportioning（对应 baseline 静态结构分派缺陷）：TD/ED 统一为单一目录项结构，LLptr/LRptr/RLptr 与本地/远端数据行动态竞争同一存储，按负载共享模式自适应（Redis 自动给远端条目更多空间、CNNSrv 给本地条目更多）；1 个类型位区分 core ID/cluster ID。
  - 方法三 SetOverflow（对应 baseline B 位广播缺陷）：目录 set 内 PointerSpace 提供细粒度溢出指针，多共享者条目按需 claim OwnerWay 条目获得 T2=2 个指针，耗尽才置 B 位；写路径收集指针 +3 cycles，读路径不阻塞。相比 SCD（set-associative 下目录冲突多、需 root/leaf 层级遍历）与 Way Combining（须整个借用同 set 未用行的全部指针、cache 高占用时失效），SetOverflow 细粒度、无未用行限制、无连续分配/压缩/迁移逻辑，平均多获 10.5% speedup（vs SCD 3.1%、WayC 5.8%）。
  - 论文方法全栈执行例子：簇 1 的 core 对远端 home 行读 miss → 先查本地目录分片的 Temporary home 条目：有 RLptr 条目 → 从本地 LLC/L2 取数并加 RLptr，零跨簇事务；无条目 → 访问 Global home（加 LRptr）→ 数据回本地并新建 Temporary home（RLptr，D=0）。同簇第二核写该脏远端行 → 两核转 MS 状态、目录保持 D=1，不访问 Global home。S 态多共享者行写 miss → 置 O 位 → 并行比对 T1=6 个 OwnerWay 取回全部 SharerPointer → 发失效并后台清空 PointerSpace。层次覆盖：系统框架层（协议事务与目录管理，无软件框架改动）→ 硬件架构层（TD/ED 目录分片、PointerSpace、2D mesh 簇组织、目录-LLC 分片 RTL 实现）；算法/编译框架/kernel 调度层：论文未明确说明。结果：平均 1.36× speedup、load 延迟 -46.1%、失效消息 -39%、L2-miss 远端访问 -89.6%、PointerSpace 溢出仅 2% 数据 set；目录存储仅为 UpperBound 的 1/2.75 且性能差 ≤1%；面积 +0.44%、漏电 +2.3%、动态功耗 +1.8~4.2%。
