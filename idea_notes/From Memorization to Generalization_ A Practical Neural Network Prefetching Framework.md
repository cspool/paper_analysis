## From Memorization to Generalization: A Practical Neural Network Prefetching Framework

- baseline方法是什么？
  现有 L1D 预取器分两派：①记忆式（memorization）表驱动预取器（baseline 主阵营）：IPCP（DPC3 冠军，指令指针分类器把访问流按 PC/IP 分类后查表预测）、Berti（本地 delta 预取器，2.55KB，按 IP 定位分析 delta 序列特征）。它们把当前访问流与先前观察到的精确模式匹配，紧凑到能放进 L1D（几十 KB），但只覆盖简单重复序列；对复杂/不规则/指针追逐模式（omnetpp、GAP 图遍历）容易链断裂，覆盖率低。②泛化式（generalization）ML 预取器：Pythia（L2C 强化学习）、Hermes（L1D 感知机）、Pathfinder 等，能学底层特征预测未见模式，但需要 MB 级存储与多周期推理延迟，只能放 L2/LLC，看不到 L1D 过滤后的完整请求流且预取注入太晚。
  全栈执行例子（Berti baseline，一次预取，IP 定位+本地 delta）：① LSU 产生地址，按 PC 索引 IP 表找到该 IP 的 delta 历史 → ② 本地 delta 计算（当前地址-上一地址）在按 IP 分流的流内进行 → ③ 查表匹配已知 delta 模式（如 +64 stride）→ ④ 命中则按偏移生成预取地址注入 L1D；表项只记住精确见过的（IP, delta 序列），新模式/噪声导致查表失败 → 链断裂无预取；模型在 L1D 内 2.55KB。Pythia+Hermes（泛化式）：L2C 的 Pythia 用 RL 观测已被 L1D 过滤的 decimated miss 流（时序上下文残缺）训练价值函数选预取策略，Hermes 在 L1D 用感知机预测 off-chip DRAM 访问并过滤下游预取，两者合计 29.5KB、多周期延迟，预取注入距请求远，许多预测太晚失效。编译框架/kernel 调度/芯片设计层次：论文未明确说明。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  Moirai 用三层协同设计把泛化式神经网络塞进 L1D 的几 KB/几周期预算：①全局流 delta 特征 + Window-based Extended Delta 预处理：不花几百字节到 KB 的 PC 流分裂表（Berti/IPCP 的做法），而是在 5 地址小窗口内找同页/8KB 空间约束的下一相关访问算局部 delta，一次机制同时滤掉交替页访问的伪 delta 与 delta 稀疏长尾 → 干净、稠密、语义化的全局 delta 流喂给网络（省下 PC 表存储；TCN 的时序感受野容忍偶发"假 delta"噪声，不像表式预取器单点噪声即断链，直接对应解决记忆式预取器对新模式脆弱的缺陷）。②CaPNet 二值化 TCN（[8,4,2] 三层，≈380 参数）：1-bit 权重/激活把 MAC 换成 XNOR+popcount（FCC），在线训练用混合精度潜在权重 Wraw（首层 7-bit/其余 4-bit）+ STE 反向传播 + 梯度共享（BCC），前向 1-3 周期、共 780 Bytes（比 Pythia+Hermes 小 97%、比 Berti 小 70%）；TCN 卷积并行与空洞感受野解决 RNN/LSTM 的串行延迟瓶颈，能预测未见模式（泛化），对应解决泛化式预取器存储/延迟不可落地 L1D 的缺陷。③Adaptive Control Unit：以平均 loss L_avg 与访问计数器双指标切换训练/推理相位（L_avg>0.5 或计数>Ntrain 触发重训练并暂停预取防污染，L_avg<0.01 且计数>Ninf 进入稳定推理），推理期按置信度三档（1/5/9 个预取）调激进性 → 用轻量自调节取代 Pythia 的显式带宽感知 agent，多核争用下 loss 上升自动节流，对应解决无污染控制的缺陷。
  全栈执行例子（Moirai，沿一个 delta 数据路径）：① LSU 产生 speculative VA（与 L1D/dTLB 并行）→ Input Processing Unit 在 5 地址窗口内做 window-based extended delta（位运算判断同页 (aw[0]>>13)⊙(aw[i]>>13)==1，返回 Δ=aw[i]-aw[0]，否则 abnormal 丢弃）→ ② 10 个连续 delta 进 CaPNet FCC 3 周期 XNOR+popcount 前向（式 1，[8,4,2] 通道）输出预测 delta → ③ 控制器按置信度发 1/5/9 个预取（含硬连线 block+1）进 PRQ → 经标准流水线填充 L1D（92.37% timely）；④ ROB retired PA 流异步喂 BCC（STE+7/4-bit Wraw 更新，式 2，3 周期）；⑤ L_avg 超 Ltrain 或计数超 Ntrain → 切训练相位暂停 CaPNet、辅助 stride 预取器兜底防性能悬崖。整个设计在 780 Bytes 内自包含（无跨层同步），把"泛化"带到 L1D：对 omnetpp 11.53%、GAP bfs 70.65% speedup，多核 7.8%，面积/功耗仅 A13 核心的 0.05%/0.28%。编译框架/kernel 调度/芯片设计层次：论文未明确说明。
