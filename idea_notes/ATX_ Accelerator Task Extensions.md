## ATX: Accelerator Task Extensions

- baseline方法是什么？
  - Baseline 是两种已有 CPU 集成加速器抽象。(1) ICA（In-Core Accelerator，如 Intel TMUL/AMX、AVX 向量单元）：在核流水线内作高级功能单元，从架构寄存器读输入、写回架构寄存器、调用无状态，可乱序/推测调用、与核细粒度交错；但数据经核通用访存硬件（LSQ、预取器）供给，MLP 有限——论文实测 perfect ICA 下 SDDMM 核心计算周期降 55%+，总周期却只降 25%，62%+ 周期仍是 memory-bound，核无法按加速器所需速率供数。(2) OCA（Out-of-Core Accelerator，如 Intel DSA/IAA/NPU）：挂缓存子系统，专用访存硬件高带宽取数；但可写内存、任务可留状态，无法推测/乱序调用——调用是 MMIO store，必须到 ROB 头才发出（非推测）、一次只能启动一个任务、且调用 store 与后续轮询 load 之间要 fence（fence 还会挡住无关的普通 load）。长任务无碍，小任务与核细粒度交错时通信开销致命。
  - baseline 全栈执行例子：SpMM 一行处理——CPU 遍历 CSR 观察稀疏模式、动态切任务 → ICA 路径：普通 load 指令经 LSQ/L1/L2 把稀疏行与稠密 tile 搬进寄存器再喂给核内加速单元；OCA 路径：MMIO store 非推测调用 DSA 式加速器 + 轮询状态 + fence，结果写回内存再由核读回。算法层：无新算法（SpMM/SDDDMM/GeMM/解压均为负载，CPU 侧用 MKL/TACO/libxsmm）；系统框架层：论文未明确说明（库直接调用，无服务框架）；编译框架层：论文未明确说明（AVX512/AMX 由库内嵌 intrinsic）；kernel 调度层：论文未明确说明（OpenMP 跨核并行，无 GPU/kernel 调度）；硬件架构层：ICA 走核 LSQ/预取器，OCA 走 MMIO 轮询+fence。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = NCA 抽象 + ATX 指令 + UTE。(1) NCA 取 OCA 之长（独立内存读接口、专用访存硬件高 MLP——对应 ICA 的访存瓶颈）与 ICA 之长（只写核寄存器、无状态——对应 OCA 不能 undo 执行效果故无法推测调用的缺陷），从而可推测/乱序调用 + 高性能供数。(2) ATX 指令把整个任务编码为一条"长延迟 load"：输入寄存器携带 VAccId + 运行时常量，输出写回 PRF；错预测时核通知 UTE 中断任务、不破坏架构状态——对应 OCA 的 ROB 头阻塞、任务启动串行、fence 三宗罪。(3) UTE 作核-NCA 虚拟化层：VAcc→PAcc 映射使核只对单一 ATX Port 编程、新增 NCA 不改核流水线、软件 fallback 保持二进制兼容——对应每加一个加速器就要改核接口的扩展性问题。(4) UTE 作数据供给引擎：stream 抽象 + bexp 边界表达式支持 CSR 式父-子流依赖树（间接寻址/指针追逐），LDQ/Common Bus 以远高于核 LSQ 的 MLP 供数——对应 ICA 供数瓶颈；Assisted/Predicted 任务预取把"预测访存地址"降维为更简单的"预测任务运行时常量"（stride 预测，核来不及产生任务时也能提前取数）——对应核产生任务慢导致 MLP 不足的障碍。(5) UTE 位置选 L2 旁，共享核 L2 TLB/MMU 与 L2 缓冲复用，缩小 scratchpad——对应全私有访存结构的面积成本。
  - 论文方法全栈执行例子：同一 SpMM——CPU 遍历 CSR、每 16 行组一个任务 → 一条 ATX V1V1 指令把 {VAccId, row_ptrs 边界, vals 基址} 打包进向量寄存器 → 经 ATX Port 进 UTE InTaskQ → VAcc→PAcc/Streams 查表分配 SPADE-like NCA 与 2 个 Stream Unit（S1 父流取 row_ptrs、经 PDQ 驱动 S2 子流取 vals）→ LDQ 并发向共享 L2 发读（L2 miss 走 HBM 4TB/s）→ Common Bus 写入 2×32KB scratchpad 双缓冲 → NCA 计算 → 输出经 OutQ/ATX Port 写回核寄存器；同类型后续任务被 Task Predictor 按 stride 预测并 prefetch 到 L2。结果：vs Core 2.7–4.0×、vs ICA 1.3–2.3×、vs L2 OCA 1.4–3.9×、vs LLC OCA 2.6–18×（解压用例小任务 512B–2KB 细粒度交错达 18×）；默认 UTE {32,128,128B,1KB} 达 Inf UTE 80% 性能、0.90% SPR die 面积、4.37% TDP。算法层：无新算法；系统框架层：论文未明确说明（OpenMP 并行 + 手写 kernel + C/C++ 配置库）；编译框架层：论文未明确说明（内联汇编，自动生成 ATX 程序留作 future work）；kernel 调度层：论文未明确说明（任务/流调度在 UTE 硬件内完成）；硬件架构层：NCA+UTE 微架构、ATX ISA 扩展、CACTI 面积/功耗评估。
