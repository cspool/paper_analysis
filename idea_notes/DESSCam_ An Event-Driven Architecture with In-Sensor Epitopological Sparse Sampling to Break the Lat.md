## DESSCam: An Event-Driven Architecture with In-Sensor Epitopological Sparse Sampling to Break the Latency-Power Tradeoff in Eye Tracking

- baseline方法是什么？
  - Baseline 一（SOTA 主对标）= BlissCam [47]（ISCA'24）：帧式图像传感器 + learned in-sensor 随机稀疏采样（每帧刷新 10-bit in-pixel SRAM 随机数、只控制总体稀疏度不指定有效像素位置）+ 片内 ROI 预测 NPU，像素体积最多减 95%、功耗比既有眼动追踪系统低 8.2×，但固定帧率 + 全帧曝光后再 eventification，延迟高达 9.4 ms，不满足 AR/VR 实时要求（MPL 需 <5 ms）。全栈执行例子：帧周期开始 → 全帧曝光（固定曝光时间，快速眼跳时拖影/延迟）→ 片内 NPU 预测 ROI → 随机掩码采样 → 稀疏数据经接口传给 host NPU 做 gaze 估计。算法层 = 随机稀疏采样 + 常规 gaze 算法；系统框架层 = 论文未明确说明；编译框架层 = 论文未明确说明；kernel 调度层 = 论文未明确说明；硬件架构层 = 3D 堆叠 CIS + in-pixel SRAM 随机数 + 片内 NPU。
  - Baseline 二 = 标准 DVS（如 DAVIS346 [2]、Samsung [117]）：像素 always-on 连续 eventification，比较器占每像素功耗至多 98.4%（DAVIS346 实测），像素功耗可达帧式像素的 10×；每个像素经 AER 握手仲裁异步输出（事件输出延迟典型 120 ns），仲裁/总线驱动开销大；低事件活动下仍耗几十 mW。全栈执行例子：像素比较器持续比较 Vdiff 与阈值 → 事件产生即握手仲裁、驱动高容负载事件总线逐像素异步读出 → AER 包 → host 算法处理全部事件（含背景噪声/热像素噪声、空间孤立冗余事件）。算法层 = 事件帧 gaze 算法（全事件输入）；系统框架层 = 论文未明确说明；编译框架层 = 论文未明确说明；kernel 调度层 = 论文未明确说明；硬件架构层 = 2D DVS 像素阵列 + per-pixel 握手 + 事件总线。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 事件驱动（DVS 范式解决时间维度）+ 空间稀疏（ESS 解决空间维度）三重设计，同时击破"帧式固定采样导致延迟-功耗权衡"与"DVS always-on 像素高功耗"两个缺陷：
    ① ESS 像素级相关性稀疏采样——离线用 Pearson 相关矩阵（全局数据相关性）生成二值掩码写入每像素 1-bit SCtrl SRAM，只使能约 2% 像素做 eventification，直接在像素内抑制事件生成（省数据搬移与 MAC，且天然抑制背景噪声与热像素）——对应 BlissCam"随机采样只控制总体稀疏度、忽略像素重要性与每帧刷新 10-bit SRAM"与标准 DVS"全部像素 always-on 比较器耗电"缺陷（像素功耗比标准 DVS 低至 5.26×、系统功耗比 2D-V 低 5.1×、比 BlissCam 低 2.7×）。
    ② PAC patch 激活 + patch 级握手——16×16 patch 事件计数超阈值（=2）才经 ReqX/ReqY 握手读出（in-sensor token pruning，最多减 61% host MAC），以共享 PAC 握手替代标准 DVS per-pixel 握手（免复杂仲裁逻辑）——对应"逐像素握手 120 ns 延迟 + 空间孤立冗余事件"缺陷（端到端延迟比 BlissCam 低 15.2×、比 2D DVS 低 2.6×，亚 1 ms；等效帧率 13.56–5,347.56 Hz 随眼动速度自适应，眼跳快则快、注视慢则省电）。
    ③ Robust ViT——conv stem/conv enhancement 在 transformer 前增强局部纹理与跨 patch 交互，卷积层占主要计算量并在全分辨率生成稀疏 token，transformer 只处理少量 token 提取全局相关性——对应"高稀疏度下精度崩塌"（同 50× 压缩率下 PAC-only 无 ESS 为 4.7°，ESS+ViT 为 0.5°）。
    硬件落地：3D 堆叠（顶层 PSC + 底层 SSPL hybrid bonding，仅 Vdiff + SCtrl 两条键合信号），SSPL 每像素仅加 1 个 6T + 2 个 8T SRAM 单元，SCtrl 门控切断比较器、SDP SRAM 就地锁存事件 + 全局 Spulse 复位免 per-pixel 握手，底层像素面积开销仅 0.6%（36.97 vs 36.76 μm²），346×260 整芯片 3.414 mm²；off-sensor 用 STM32N6x7（Neural-ART NPU，INT8 LSQ 量化 + STM32Cube.AI 部署）。全栈执行例子（一次 gaze 估计，12 个激活 patch）：算法层 = ESS 掩码（离线 A100 生成）→ PAC 阈值 2 过滤 → ViT 前向（早期卷积层为主、transformer 只处理稀疏 token）；系统框架层 = 论文未明确说明（事件驱动采样循环：12 patch 即触发推断 + Spulse 复位）；编译框架层 = STM32Cube.AI 异构部署（ONNX + INT8，卷积/线性在 Neural-ART NPU、非线性在 Cortex-M55，未修改编译框架本体）；kernel 调度层 = 论文未明确说明（NPU 执行以卷积层为主，无自定义 kernel）；硬件架构层 = 顶层 PSC 检测光强变化 → Vdiff 经 hybrid bonding → 底层 SSPL 门控采样、SDP SRAM 锁存 → PAC 加法树计数、patch 级握手 → ping-pong 行 buffer → AER 打包 → MIPI CSI-2（2.5 Gbps）→ STM32N6x7 NPU 推断输出 gaze 坐标。
  - 效果对照（缺陷→设计→结果）：帧式固定曝光高延迟 → DVS 事件驱动自适应采样 → 峰值延迟 15.2× 低于 SOTA、0.19–73.75 ms 随眼动速度自适应；DVS always-on 高功耗 → SCtrl 门控 + ESS 2% 使能 → 像素功耗 5.26×↓、系统功耗 2.7×（vs BlissCam）/5.1×（vs 2D DVS）↓；per-pixel 握手慢 → patch 级握手 + 片内 SRAM 采样 → 事件输出延迟 120 ns → 数 ns；稀疏掉精度 → 相关性掩码（保留全局结构）+ Robust ViT → 50× 压缩率 AE 0.5°；泛化：ini-30 瞳孔追踪 2.76±0.15 px 优于无稀疏 Retina（3.24±0.79），证明 ESS 管线可迁移到单目标追踪任务。限制：无约束环境性能未评估、代码未开源。
