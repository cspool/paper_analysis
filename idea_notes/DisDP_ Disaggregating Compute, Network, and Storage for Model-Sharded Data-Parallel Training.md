## DisDP: Disaggregating Compute, Network, and Storage for Model-Sharded Data-Parallel Training

- baseline方法是什么？
  - Baseline 是 ZeRO-Infinity 为代表的 MSDP（模型分片数据并行）：模型状态（参数+梯度+优化器状态）按 worker 均分，每层前向/反向各执行 1 次 AllGather + 1 次 ReduceScatter（peer-based NCCL ring），优化器状态放 worker 本地 CPU 内存/SSD。缺陷是 GPU 上"计算(GEMM)+网络(集合)+存储(优化器)"聚合执行：GPU 非抢占调度下占满 SMs 的 GEMM 阻塞后续集合 kernel 启动；GEMM 与集合 kernel 争内存带宽/L2（并发时 NCCL algorithm bandwidth 降 30%）；OPT-175B 在 8×A100+100Gbps 下 65% 集合时间不可重叠、迭代多 41%，仅 15% MFU。SmartSwitch 增强 MSDP（SwitchML/ATP 思路）救不了 AG/RS：AG 只能减发送流量、RS 只能减接收流量，集合时间被另一方向主导而不变，且仍由 GPU 侧 NCCL 管数据分块。MiSDP（参数服务器）流量少 1/3，但 16 worker 需 13~29 台额外 CPU 机器做 PS 才能线速聚合，且 GPU 直连 NIC（IBGDA）路径仍有算通干扰。
  - baseline 全栈执行例子（ZeRO-Infinity 训 OPT-175B 一次反向迭代）：模型推理算法层 = OPT-175B transformer（bf16、激活重计算、Adam，算法不变）；系统框架层 = DeepSpeed 0.9.3 ZeRO-Infinity：模型状态分片存 worker CPU/SSD，每层调度 2×AG+1×RS；编译框架层 = 论文未明确说明（NCCL 2.20.5 为集合通信库而非编译框架）；kernel调度层 = 同一 GPU 上 CUDA 调用序列 AG1→GEMM1→AG2→RS1→GEMM2→RS2：GEMM1 占满 SMs 阻塞 AG2 启动、AG2 完成前依赖它的 GEMM2 无法发射，集合与 GEMM 争内存带宽；集合 kernel 只占 <10% SMs 却把迭代拖慢 41%；硬件架构层 = A100 40GB + CX-5 100G NIC + SN2700 常规交换机，计算/网络/存储聚合在 GPU-CPU 上。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 计算、网络、存储三者彻底解耦：①网络解耦——集合整体卸载到 FPGA SmartNIC（on-path 硬件流水线，规避 BlueField 类 SoC SmartNIC 的 Arm-switch 链路争用与内存带宽瓶颈），GPU 只跑 GEMM；②存储解耦——优化器搬到单台 PS，SmartSwitch 把梯度 many-to-one 聚合、参数 one-to-many 广播，使 PS 每心跳周期只收发 1 个确认包（心跳 Ack/Credit + 交换机 min 聚合 + 超时重传的 many-to-one 可靠协议），PS 数量从 13~29 台降到 1 台；③PS 内 step-centric pipelining——CPU 线程按优化器步骤而非层分配（CPU Adam 步骤 32 线程、其余步骤 1 线程、共 37 线程即满流水），SSD↔CPU Adam↔SmartNIC 深度流水，单 PS 线速消费 100Gbps 聚合梯度。缺陷→设计的直接映射：GPU 非抢占/带宽争用 → SmartNIC DMA 直访 GPU 显存 + 收发全在 FPGA 流水线（实测 GEMM 与 PCIe DMA 双向几乎零干扰，图 4）；SmartSwitch 优化不了 AG/RS → 改 push/pull 语义把聚合/广播搬进交换机，流量最多减半且双向对称可并发（contention-free 双流）；PS 数量爆炸 → 交换机聚合后单 PS 即可承载 100B Adam 状态；集合被 GEMM 阻塞 → 集合与计算完全重叠、无 SM/内存争用。
  - 论文方法全栈执行例子（同一反向迭代，DisDP）：模型推理算法层 = 同一 OPT-175B/自定义模型（bf16、激活重计算、Adam），算法不变、收敛曲线与 ZeRO-Infinity 重合（OPT-66B rm-static 微调验证）；系统框架层 = DisDP 两方运行时 API：worker 逐层 push 梯度 / pull 参数（异步 handle + wait），PS 端反向同步调用，支持参数预取；编译框架层 = 论文未明确说明；kernel调度层 = worker CPU 调 push → MMIO 提交 FPGA push 单元 → DMA 直读 GPU 显存（GPU 虚拟地址）→ 格式转换（bf16→整数）→ 线速发包 → SmartSwitch 聚合 N 路部分梯度为一份 → PS SmartNIC DMA 写 CPU 内存 → step-centric 流水：SSD 读 12B 模型状态 → CPU Adam（17 FLOPs/参数）→ 写回 SSD 并把 2B 参数副本 push 广播回各 worker（pull 为对称反向路径，forward 同理）；硬件架构层 = A100 GPU（纯计算）+ Xilinx U50 FPGA SmartNIC（集合）+ Edgecore Wedge100BF-32X Tofino SmartSwitch（聚合/广播/心跳聚合）+ 单台 Xeon Gold 5320+12 SSD PS（优化器）。效果：175B 吞吐 3.98× ZeRO-Infinity（134 tokens/s）、1.3B 达 14.1K tokens/s（2.90×/2.33×/6.28× vs ZeRO-Infinity/ZeRO-3/ATP）、276B 达 59% MFU、最大可训 1T 常数（ZeRO-Infinity 8 机仅 175B、ATP 仅 1.3B）、DP=256 扩展 2.0×（PAT）/15.1×（ring）、NVLink 机上 2.22× ZeRO-Offload、吞吐/美元 1.96×（成本仅 DGX 的 60%）。
