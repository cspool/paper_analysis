## RUNLTS Branch Prediction with Register-Value Correlations and Hierarchical Table Orchestration

- baseline方法是什么？
  - Baseline 是 TAGE-SC-L（Seznec 系列，CBP2025 由 Sheikh 等适配到 192 KiB 预算），是目前公认最准确的历史型分支预测器之一，也被 AMD/ARM/Apple/IBM/Intel 等商用 CPU 采用。结构：① TAGE：bimodal 基础预测器 + 多张 tagged 表，每张表按不同长度的全局分支历史索引（长度呈几何级数），每条目含 ~10-bit tag、3-bit 饱和预测计数器（-4..3，MSB 为方向，其余为置信度）、1-2-bit usefulness(u) 计数器；预测取 tag 匹配中历史最长的 entry；新 entry 只在短历史预测失败时分配到更长历史表；只有最长匹配 entry 被更新，u 在"覆盖短历史且预测正确"时增加、与短历史同向且正确时清零；② SC（统计修正器）：多个 hashed-perceptron（GEHL 型）组件，只在 TAGE 预测与真实方向分歧或低置信度时起作用：sB Bias（偏向 TAGE 预测）、sG 全局、sP 路径、sL/sS/sT local、sI IMLI-SIC、sIM IMLI-OH，加 loop predictor(L)；每个组件配 UT usefulness-tracking 表（仅按 PC 索引的饱和计数器，为正时该组件加权和乘固定 gain 放大）。权重只在预测错误或正确但 |sum|<阈值时训练，防止过拟合和别名偷取。
  - Baseline 全栈执行例子（模型推理算法-系统框架-编译框架-kernel调度-硬件架构；本文是纯硬件架构/微架构论文，算法-编译-kernel 层不适用）：一条条件分支（如 qsort 的 n<7、或 fp_8_trace 的 R32>R33，即典型 hard-to-predict 数据依赖型分支）在 16-wide、10-cycle 前端的乱序核中被取指 → TAGE 用全局历史长度集合 {6,9,12,...}（几何级数）分别 hash 索引各 tagged 表、比较 tag → 选最长匹配 entry，3-bit 饱和计数器给出方向与置信度 → SC 各 hashed-perceptron 组件（全局/路径/局部/IMLI/调用栈历史）并行取权重求和，sB 用强权重把结果拉向 TAGE 预测 → 加权和符号决定最终方向 → 若预测错误，CTR+u 更新、各表按 perceptron 规则训练（阈值/错误触发）→ 错误预测导致 1024-entry ROB 中数百条在飞指令被 flush、前端重取，整核性能与功耗受损。Baseline 的痛点（论文 I1-I4）：(I1) 每次 misprediction 固定分配 entry 数量，无法检测 entry thrashing（Michaud 指出仍有 headroom）；(I2) 几何历史长度集非最优——相邻短历史（6/9/12）服务重叠过多、最长历史表几乎闲置，各表负载严重不均衡；(I3) 复杂 SC 中各组件贡献不透明、无法针对性优化；(I4) 完全没有利用后端寄存器值与分支结果的相关性——对"结果由近期计算出的数据值决定、与历史相关性弱"的分支（qsort 递归划分子数组大小、浮点比较后的级联分支）只能靠运气或更长历史，而现有基于值的预测方法要么需显式分析数据依赖图（Chen et al. 依赖寄存器集合哈希、Heil et al. 操作数差值），要么依赖 pre-execution（Branch Runahead、Opportunistic Early Re-steering）在乱序后端重建依赖图并预执行，实现成本高、普适性差。

- 论文方法是什么？如何对应解决Baseline的缺陷？
  - RUNLTS = TAGE-SC 结构精修 + 全新的值相关性组件 RBias，四项设计分别对应四个痛点：(P1) 针对 (I1)：thrashing 检测与分配节流——保留原始 TAGE counter 格式（BATAGE 改动 counter 格式在 192 KiB 大容量下会导致替换控制问题、精度不达标），把稀有状态组合 ctr∈{0,-1}+u=1（实际仅约 0.02% 条目，强制清零无精度损失）复用作 newly-allocated 标记，跟踪 newly_useful（标记条目首次正确预测，清除标记）与 newly_decayed（标记条目被逐出前从未预测），按 newly_decayed ≤ 2×newly_useful → 4 个/次、>4× → 2 个/次、中间 → 3 个/次分配（192 KiB 经验映射）；64 KiB 下为 3/1/2 并设 counter 宽度 log2(表条目数)。(P2) 针对 (I2)：新历史长度集合——短历史用二阶等差（相邻差递增，如 6 之后至少 12，补偿短历史覆盖重叠）、中历史保持几何（切换点取几何增长率超过二阶等差处）、长历史用"比率成等差"（假设最大有效历史长度的对数近似均匀分布，比率等差使每张长历史表服务的期望分支数均衡）；规则化由模拟退火最优集的简单结构规律提炼而来，并验证可迁移到 GEHL（3.338→3.316 MPKI）与 BATAGE-SC。(P3) 针对 (I3)：SC 精修——IMLI 组件在判定 useful 时 gain 2→3、WT 更新步长×3（抗别名、快速适应方向变化）、UT 条目 8→256；用 call-stack-based 历史 GEHL 组件（sC 6.053 KiB）替换部分全局 GEHL 容量——分析发现即使无函数调用区域它也能改善精度（此时等价于全局历史 GEHL，但 TAGE 只更新最长匹配 entry 而在数组逐代变化时丢失所学，GEHL 同时训练所有历史长度、短历史条目仍有效），从而同时服务"跨调用边界相关"与"互补 TAGE 学习行为"两个目的（call-stack GEHL +0.43% vs 全局 GEHL +0.13%）。核心 (P4) 针对 (I4)：RBias——不加任何显式数据依赖跟踪，把全部逻辑寄存器（AArch64 65 个）一视同仁作为候选，直接学习"寄存器值 digest ↔ 分支结果"相关性，作为 SC 的扩展组件。digest 生成：整数寄存器 = trailing/leading zeros/ones 计数按位 XOR + 值低 6 位（区分对齐指针、舍入值、小整数）；FP = 符号位+指数高位（粗略量级）；flag = 位模式重复拼接（增大 Hamming 距离、减少 digest 空间冲突）。digest table 每逻辑寄存器一项，decode 时写 ROB index、执行完成时按广播的 ROB index 匹配后换成 digest+valid。预测时对每 bank（8 bank，WT 单端口化）选出 UT（gskew 3-hash，按 PC 索引）usefulness 最高的有 digest 寄存器访问共享 WT（3 表 3-hash，全用同一 digest 防干扰，gskew 式），加权和 ×2.5 gain 加入 SC 总输出；训练时被访问的 bank 更新预测所用寄存器，未访问的 bank 随机选有 digest 的寄存器训练（利用空闲端口探索相关性），UT 按"RBias 输出 0 vs 2.5×sum 是否翻转 SC 符号"来增减。两个变体：Log-RBias（逻辑寄存器组织，需要 ~1 Kbit/checkpoint 的 digest table checkpoint 恢复，每 checkpoint 持续监听 completion 通知）；Seq-RBias（fetch 时顺序分配 ring buffer 条目、按动态距离索引 UT，flush 只需回滚指针、保留 wrong-path 内容并利用之，buffer 可缩到 ROB 1/4 无精度损失）。整体效果：MPKI 相对 TAGE-SC-L 降低 5.0%（CBP simulator）/ 5.25%（gem5），CBP2025 673 条 trace 中 597 条优于 baseline；RBias 平均贡献 -2.46%（64 KiB 预算下替换 6.6 KiB 容量仍 -2.83%）；Seq-RBias 在 4/8/16-wide 上降低整核 EPI 0.19%/0.74%/1.08%，面积开销 +0.35%/0.14%/0.04%。
  - 论文方法全栈执行例子（算法-系统-编译-kernel 层论文未明确说明，本文为纯硬件架构实现）：以 fp_8_trace 的 R32>R33 分支及其后级联的 X1>0、X2<0 分支为例，在 16-wide/10-cycle 前端 + 1024-entry ROB 的乱序核上：① 执行单元完成 X1=*p1 等 load 后，把结果值与 ROB index 广播到 digest table（Log-RBias 写回对应逻辑寄存器条目，覆盖原 ROB index 为 digest 并置 valid）或 Seq-RBias 的 ring buffer（fetch 顺序分配、仅回滚指针）；② R32>R33 被预测（TAGE/SC 历史机制）→ 首个误预测不可避免、触发 flush，前端 lookahead 缩短，但已广播的 X1 值不被 squash，digest 在时间上可见（Log-RBias 靠 checkpoint 恢复、Seq-RBias 指针回滚后 wrong-path 写入的 X1 digest 仍留在 buffer）；③ 后续 X1>0 分支预测时，RBias 在 X1 所在 bank 经 UT（按 PC 索引、gskew 3-hash）判定其 usefulness 为正 → 以 X1 的 digest 访问共享 WT 三个表 → 加权和 ×2.5 加入 SC 总输出 → 预测正确，避免误预测级联；qsort 的 n<7 则利用"调用者 n_caller 或其中间结果（line 8/10）与 n_callee 粗略半分成相关"的隐式值相关（不要求同一寄存器），Log-RBias 学到与 line 8 中间结果（动态距离远但不被覆盖）的相关，Seq-RBias 学到 line 10 中间结果（距离近但被同一逻辑寄存器覆盖、恰在 ring buffer 中可见）的相关；④ 训练阶段对未访问 bank 随机选寄存器补训，持续探索新的值-分支相关；⑤ 在 192 KiB 预算内按 Table II 重新分配各表容量（bimodal 40→20 KiB、long-history tagged 90→106.25 KiB、新增 sC 6.053 KiB 与 sR 6.576/7.112 KiB，削减 sB/sG/sP 并去掉 loop predictor），CBP simulator 上 673 条 trace 平均 MPKI -0.137，gem5 + McPAT 下 16-wide 核 EPI -0.20%（Seq-RBias），证明无需数据依赖跟踪、无需 pre-execution，仅用后端值摘要即可系统性修复数据依赖型分支的预测瓶颈。
