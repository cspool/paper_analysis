## SATIC: An Optimizing Ising Compiler for SAT(isfiability)

- baseline方法是什么？
  - Baseline 是通用的 QUBO 级问题分解器（Ising 编译的"常见做法"）：先把整个 SAT 实例从 CNF 数学公式化为 QUBO/Ising 形式（引入大量不直接对应问题变量的 ancillary 变量，如 Chancellor's 公式化下 n 变量 m clause 的 3SAT → n+m spins；k>2 经 kSAT→3SAT 转换后 → n+m(2k−5) spins），再在 QUBO 层做子问题形成（decomposition），把超容量的大 QUBO 切成能装进 Ising 机器的小 sub-QUBO，迭代求解并合并。代表：D-Wave qbsolv / D-Wave EID（Energy Impact Decomposer，按能量影响选变量切 QUBO）以及 Cilasun et al. [46] 的 SAT 分解器。痛点：① 公式化先于分解发生，QUBO 里多了大量 ancillary，需处理的变量数膨胀（50 变量/200 clause 3SAT → Chancellor's 下 250 变量 QUBO），分解器面对更大的图；且 ancillary 通常是低度节点（只连本 clause 变量），按"能量/度优先"选变量时最易被排除在子问题之外 → 违反 ancillary-awareness：子问题把 clause 的 ancillary 落在外面，solver 只能给被排除变量定固定值，无法再优化该 clause 的 penalty-reward 语义，能量景观与原始目标错位（Table I：a1 固定 0 时满足赋值 i=7 与唯一不满足赋值 i=0 能量同为 0），transition region 硬实例中显著降低求解概率；② 按变量随机/能量挑子问题会把含某变量的部分 clause 排除 → 违反 clause-completeness：不同子问题优化同一变量的不同约束子集，产生冲突赋值，拖慢或阻止收敛；③ 公式化系数超出硬件系数范围 [−14,+14] 被截断，能量精度受损。
  - Baseline 全栈执行例子（算法pipeline-编译框架-kernel调度-硬件架构；SAT 为符号组合优化，无 ML 推理/Serving，系统框架层论文未明确说明）：以 Eq.(5) 的 F=C1∧C2=(x1∨x2∨x3)∧(¬x3∨x4∨x5) 在 4-spin 机器为例：① 算法pipeline 层：问题本身是 NP-complete 的 3SAT，无学习模型、无 ML 算法 pipeline（不适用，论文未涉及）；② 编译框架层：先把 5 问题变量 + 2 ancillary 公式化为 7 变量 QUBO（Chancellor's，H_F=H_C1+H_C2），再在 QUBO 图上选 4 变量子问题——C(7,4)=35 种选法里仅 {x1,x2,x3,a1} 与 {x3,x4,x5,a2} 保持 clause 目标完整，多数选法（如 {x1,x2,x3,x4}）把两个 ancillary 都排除，被排除变量冻结成固定值，每个 clause 的 penalty/reward 语义失真（能量景观错位），这是 D-Wave EID 等 QUBO 层分解器的典型行为；③ kernel 调度层：无 GPU kernel，子 QUBO 直接调度到 Ising 硬件（不适用）；④ 硬件架构层：4-spin Ising 机器对 7 变量 QUBO 的 4 变量子问题退火，因能量景观错位常停在错误低能态，返回的局部解冲突/不收敛，需大量重复（实测 D-Wave EID 在 UF20 以上常触 500 迭代上限而失败）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 SATIC/SATIC++：把"子问题形成"提前到数学公式化之前，直接在 CNF 原生表示上做变量选择——用 VIG 图结构 + BFS 邻域选变量 + 变量冻结（freeze，取值自全局解向量）+ 单元传播化简，按构造保证 ancillary-awareness 与 clause-completeness，再对已化简、更小的子 CNF 做 QUBO 公式化，配合整套启发式技巧（Limited Neighbors、Neighbor Shuffling、NLI、Clause Based Formulation Mix、Ancillary Estimation、Bulk Freeze、Local Search、Adaptive Spin Merging、Dynamic Upscaling）。对应缺陷：① 对应"分解发生在公式化后、ancillary 膨胀"——在 CNF 层（尚无 ancillary 变量）选变量，按构造不可能漏掉 ancillary（ancillary-awareness 自动成立）；且 freeze 未选变量 + 单元传播把 clause 宽度降下来（3SAT→2SAT/1SAT 时零 ancillary），公式化后 QUBO 更小、留出更多 spin 给问题变量 → 45-spin 芯片解 73× 容量问题；② 对应"clause-completeness 被破坏"——变量沿 VIG 的 BFS 邻域选取，含被选变量的全部 clause 都进子 CNF，同一变量的约束全集在子问题内一致考虑，避免冲突赋值；③ 对应"公式化能量景观失真/系数截断"——NLI 反转负文字为主的变量极性平滑能量景观（系数不对称导致的局部极小）、Clause Based Formulation Mix 按 k 选最小 ancillary 公式化（Chancellor's 适合 k≤3、ILP 适合 k>3，Flat ILP 摊平 2^k 权重适配系数范围）、Adaptive Spin Merging 动态合并未用物理 spin 扩大系数范围、Dynamic Upscaling 自适应缩放系数；④ 对应"QUBO 层分解软件开销大"——VIG（50 节点）远小于 QUBO 图（250 变量），遍历/选择成本低；Ancillary Estimation 用查表替代重复公式化（size check 快约 9×）；Bulk Freeze 减少重复单元传播；端到端 69.3ms vs D-Wave EID 18877ms。
  - 论文方法全栈执行例子：同一 F=C1∧C2 在 4-spin 机器：① 算法pipeline 层：无 ML 模型（不适用，论文未涉及）；② 编译框架层：输入 CNF → 构建 5 节点 VIG → 随机根（如 x1）BFS 得 {x1,x2,x3,x4,x5} 序 → 冻结 x4=0、x5=0（取值 S_global）→ 单元传播得子 CNF (x1∨x2∨x3)∧(¬x3)，公式化后仅 4 变量（C1 引入 1 ancillary，单文字 clause 无 ancillary）恰好装满 4 spin，ancillary-awareness 与 clause-completeness 按构造成立 → Machine Embedding（Adaptive Spin Merging/Dynamic Upscaling）→ IsingHardware 退火解子问题 → 回收局部解更新 S_global → CheckSolution 未满足则换根 BFS 重来（Neighbor Shuffling 增加多样性、Limited Neighbors 限 N=10 邻居、Local Search 间隔重启）；③ kernel 调度层：无 GPU kernel（子 QUBO 直接入 Ising 硬件，不适用）；④ 硬件架构层：45-spin all-to-all CMOS 环形振荡器芯片（200μs/4.8μJ 每次退火）经 FPGA+PCIe 由 Python 3.8 主机驱动，8 卡并发 repeats；⑤ 系统框架层：论文未明确说明。效果：Batch-4-100-1000 全 100 实例解出（基础 SATIC 仅 67），unseen SATLIB UF 到 UF175 全解（23× 容量）、UF250 解 92/100，平均 9.4 迭代 vs 最接近 baseline 约 250 迭代，端到端 22.2×（vs SATIC）/272.4×（vs D-Wave EID）加速。
