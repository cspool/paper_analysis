## Omni-LUT Energy-Efficient LUT-based Accelerator with Hardware-Aware KV Cache Quantization

- baseline方法是什么？
  - baseline 分量化侧与硬件侧两层：(1) 量化侧——SOTA KV cache 量化方法（KIVI per-channel Key + per-token Value 2-bit、KVQuant 非均匀量化、Oaken dense-and-sparse 离线-在线混合编码）普遍依赖 outlier 隔离/保留高精度子集（KIVI/KVQuant/Oaken 有效 KV 位宽达 4.8–5.0 bit），这些被隔离的 outlier 需要额外 dequantization 或高精度侧处理，计算回退到低能效的 FP×FP GEMM；且 KV 激活是推理时在线生成，运行时量化开销必须极小。SOTA LUT-based 加速器 FIGLUT 只支持 AW-GEMM（linear 层 weight×activation 的 FP-INT mpGEMM），AA-GEMM（attention 的 QK^T、Attn×V，两个操作数都是运行时激活）必须回退到与 FPE 相同的 FP systolic 后端（FIGLUT 面积 0.39→1.03 mm²）；且现有 LUT 加速器用 post-lookup 单一 scale，只支持 column-wise 量化方向，而 Weights/Keys/Values 的精度最优方向都是 row-wise（weights 见 prior work [73]、Keys per-channel [46]、Values per-token），方向不匹配导致精度损失。Tender 是纯 INT8 整数 baseline（sub-4-bit 下无 outlier 保留时精度崩坏，PPL 123.1）。
  - baseline 全栈执行例子（FIGLUT 处理 long-context decode 请求）：请求 token 到达 → linear 层 AW-GEMM 走 LUT datapath（4 个 FP16 激活 × 4-bit 权重查表累加）→ attention 的 QK^T 与 Attn×V 是 AA-GEMM，两个操作数均为运行时激活 → KV cache 为 16-bit FP16（或需 outlier 高精度侧处理 + dequant）→ AA-GEMM 切换到 FPE FP systolic 后端做 FP16×FP16 MAC（dequant 开销 + FP 乘法能耗）→ decode 阶段每个 token 读全量 KV cache（FP16 流量 O(T)）+ 2D systolic array 上 GEMV 只有单行/列 PE 活跃、利用率低 → 长上下文下 AA-GEMM O(T²) 计算与 KV 流量 O(T) 成为能量与延迟主导。Serving 调度层、编译框架层、kernel 调度层：论文未明确说明（无 Serving/编译框架/kernel 软件栈内容）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法：硬件-量化协同设计的 Omni-LUT，把 LUT 执行从 AW-GEMM 扩展到 AA-GEMM。量化侧：(1) hardware-aware binary-coding 量化框架（BCQ/BC-UQ）——把 K/V 量化成 {±1} bit-planes + power-of-2 缩放因子，直接被 LUT PE 消费，无需 outlier 高精度保留与 dequant 回退；Key 用 offline-calibrated per-channel BCQ（交替优化学缩放因子）+ AS-Bit（按 E[Q²]_d·(MSE_bℓ−MSE_bh) 边际增益把 top 25% 高敏感通道分配高位宽，有效 Key 位宽仅 4.25 bit），Value 用 online per-token BC-UQ（TSE 在线算 min/max 得 zp/δ）——消除"精度 vs LUT 兼容性"矛盾且运行时开销小（BQU 宽度 128 匹配 head dim，不增 cycle）。硬件侧：(2) scale-aware LGU 在 LUT 生成阶段用 4 个 FP 乘法器把组内每个激活乘其 row-wise scale、并内嵌 zero-point 补偿（首 bit-plane 点积加进每个表项），用 6 加 6 减生成 half-LUT，与 PE 并行不 stall——支持 Weights/Keys/Values 的精度最优 row-wise 方向，AA-GEMM 全程留在 LUT datapath；(3) phase-adaptive hybrid WS/OS-V LUT systolic array（32×4）——prefill GEMM 用 WS（权重驻留、psum 链式传播，比 OS 高 1.3×），decode GEMV 用 OS-V（LUT broadcast 到 32 行 + 每行独立并行 Weight FIFO + psum 本地累加，全阵列 GEMV 并行，比 OS/WS 高 1.49×/1.68×），mode register 1 cycle 切换、每 query 只切一次。
  - 论文方法全栈执行例子（Omni-LUT 处理同一 long-context decode 请求）：请求 token → linear 层 AW-GEMM 走 LUT datapath（W4A16，4 激活组查表）→ attention：新生成 token 的 K/V 激活进 BQU 在线量化（Value：TSE 归约树求 min/max → zp_v/δ_v → BEA 贪心编码为 4 个 bit-plane；Key：用离线校准的 per-channel zp/α + AS-Bit 位分配编码）→ 3/4-bit KV cache 写回（内存流量相对 FP16 降 4×）→ QK^T 与 Attn×V 的 AA-GEMM 直接在 LUT datapath 执行：LGU 生成 scale-aware LUT（内嵌 row-wise scale 与 zero-point 补偿，与 PE 并行），PE 按 bit-plane 查表累加（KV3 只处理 3 个 bit-plane，AA 计算比 KV4 省 25%）→ decode 阶段阵列重配置为 OS-V（LUT broadcast + 并行 Weight FIFO，全阵列 GEMV 并行）→ 输出 token 并 append 新 KV。端到端效果：等峰值吞吐下能效比 FIGLUT 高 1.25×–1.91×，8192 input tokens 下总能量比 FPE/Tender/FIGLUT 低 50%/32%/38%，面积 0.53 mm²（含 AA 能力，仍小于 FIGLUT 含 FPE 后端的 1.03 mm²），精度与 SOTA KV 量化方法相当（KV4-BCQ 平均 PPL 仅增 0.17）。
