## HiT: A Unified Sparsity-Adaptive Architecture for High-Throughput Matrix Multiplication

- baseline方法是什么？
  - baseline 为覆盖不同稀疏度段的稀疏矩阵乘法加速器，重点是 Trapezoid（ISCA'24，首个大规模统一稀疏矩阵乘法加速器，128×128 MAC，基于 Gustavson 行驻留数据流 + 多级存储层级：4 个 cluster × 32 PE 行共享 4MB 32-bank cache、经 32×32 crossbar 互连），以及 TPU-like（内积 2D systolic、仅适合稠密）、Sigma（IP 数据流、只利用 A 单边稀疏）、Flexagon（多数据流 MS 专用）、SpArch/OuterSPACE（HS 外积）、Spada（自适应数据流）。痛点：(1) 窄稀疏度范围专用——TPU 对稀疏输入浪费周期/能量在无效 MAC 上，Sigma 无法处理 HS；(2) Gustavson 数据流（Trapezoid）在大规模并行下对 Matrix B 产生大量并发随机访存，PE 行增多时 bank conflict 加剧（cache/crossbar 复杂度与成本二次增长），HS×HS 只达到峰值吞吐的 3.125%（512/16K MAC/cycle）、MAC 利用率在 256 行时降到 ~10%，内存子系统成为瓶颈；(3) 朴素外积数据流虽消除随机访存，但产生随 PE 行数超线性增长的未合并 psum——OuterSPACE 需 off-chip 累积、SpArch 依赖大规模 comparator merge tree，片上累积压力成为新瓶颈。
  - baseline 全栈执行例子（Trapezoid 处理 HS×HS 的一次 M×M^T）：算法层——稀疏矩阵乘 C=A×B 用 CSR/CSC 表示，Gustavson 算法按 A 行迭代、每个 A 非零取对应 B 行做行级相交；系统框架层——论文未明确说明（无 Serving/OS 框架）；编译框架层——论文未明确说明（无编译器，tiling/数据格式化离线完成）；kernel调度层——每 PE 子行映射 A 的一行，每周期每子行只做 1 次乘法，各 PE 行并发向共享 32-bank cache 请求所需 B 行；硬件架构层——128×128 MAC 分 4 cluster，每 cluster 32 PE 行共享 4MB 32-bank cache 经 32×32 crossbar 访问，两个 PE 同时请求同一 bank 即发生 bank conflict 强制 stall（图 5 示例：两个 PE 都访问 Bank 1，只执行 1/4 的乘法），HS×HS 实际仅 512 MAC/cycle 有效；芯片设计层——论文未明确说明。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - HiT 提出统一稀疏自适应架构（HSparse + MSparse 两个外积数据流 + 内积数据流），逐条对应解决 baseline 缺陷：(1) HSparse 对应解决"Gustavson 随机访存/bank conflict 瓶颈"——改外积数据流按列处理 A、顺序流式 B（无并发随机访问），PIDU 用轻量 comparator + leading-zero-count shifter（每 Compute Group 64 比较器、4 级流水）替代 Trapezoid 功耗密集的 intersection unit 与 crossbar 路由网络，两层空间并行（列内多非零 + 列间多列，每周期 4 个 A × 64 个 B）使吞吐随计算并行度扩展；(2) HSparse + DMAccum 对应解决"朴素外积 psum 爆炸"——HS×HS 利用高输出稀疏性把 psum 以压缩格式存片上（binning-compare-update 用 modulo 分 bin 减少比较器数），支持更大 tile 提升交叠率与计算密度，PSum Router + ring network 把 psum 路由到目标 Row 片上归约（避免 OuterSPACE 的 off-chip 累积，比 SpArch 的 merge tree 轻量可扩展），B 列交错解决非零聚类导致的缓冲低利用率（降 14×）；(3) MSparse 对应解决"HSparse 在更高交叠率下环网 psum 数据移动过大"——MS 下把 A 行映射进单个 Compute Row 使 psum 立即本地累积（绕过环网），B 经 cluster-local broadcast 通道广播共享（部分同步开销 ≤12%）；(4) D×D 内积数据流对应解决"稀疏部件在稠密下浪费面积功耗"——关闭/时钟门控稀疏部件、power-gate Local Buffer，架构重构为 128×128 systolic array 保持稠密最优计算效率（面积比 TPU-like 大 1.82× 但只导致 D×D performance/area 低 1.23×）。数据流按密度启发式（<10% HS、10-90% MS、>90% D）每个 dataset 静态选择一次，重配置固定周期、占执行时间 0.009% geomean。
  - 全栈执行例子（HiT 处理 HS×HS 的 p2p-Gnutella24，与 Trapezoid 对比同一 M×M^T）：算法层——稀疏矩阵乘用 COO-like 片上格式（非零显式存 tile 相对行列索引、按列再行连续排列），off-chip 保持 CSR/CSC 由轻量 converter 在线转换，稠密用稠密格式；系统框架层——论文未明确说明（无 Serving 框架）；编译框架层——论文未明确说明（tiling/数据格式化离线 host CPU 完成，HS 预处理 3.47s、MS 0.009s，一次性摊销）；kernel调度层——A 沿列分 tile 映射到 4 Cluster 的 128 Compute Row（每 Row 经专属通道静态连接 4 个 Global Memory bank）、B 沿行分 tile；每周期每 Row 从专属 bank 流式读 4 个 A 非零 + 64 个 B 非零，无 bank conflict；硬件架构层——PIDU 4 级流水并行比较列-行索引（64 比较器/Group），leading-zero shifter 把匹配 B 元素对齐到 32 个乘法器，乘法器输出经 PSum Router 本地累积或经 ring network 路由到目标 Row，DMAccum 用 binning 压缩格式片上累积（溢出才 spill 到 Global Memory，平均 3.30% 输出行）；D×D 时稀疏部件关闭、重构为 systolic array 走内积流。芯片设计层——论文未明确说明（单芯片 22nm + 2TB/s HBM）。结果：HS×HS performance/area 比 Trapezoid 高 3.24×、全谱 1.93×、能耗低 1.64×、HS×HS MAC 利用率高 3.46×、HS 下 MAC 利用率比 TPU-like 高 3933×，验证了以"消除随机访存 + 片上 psum 归约 + 双层空间并行"实现全稀疏度谱高吞吐的设计思路。
