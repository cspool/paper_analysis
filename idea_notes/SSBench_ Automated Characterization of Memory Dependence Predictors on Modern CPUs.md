## SSBench: Automated Characterization of Memory Dependence Predictors on Modern CPUs

- baseline方法是什么？
  - baseline 是"人工手动逆向 MDP 微架构"：安全研究者用自定义微基准逐个猜测 MDP 行为，手工分析状态机、表组织与索引机制。具体 baseline 实现：Intel 侧 [35][51] 人工测得 Intel MDP 为 direct-mapped 结构并恢复状态机参数，构建 Spectre-V4/MDPeek 攻击；AMD 侧 [37] 人工逆向出 AMD Zen 3 的 MDP 用五个计数器与十个转移函数（PSFP 与 MDP 重叠），实现跨进程 Spectre-V4 变体；Arm/Apple 侧 [36] 人工逆向仅考虑 load-indexed 的 L-nS 型 MDP（ARMeD channels），只能实现低精度攻击（如网站指纹）。通用工具侧 baseline 是面向其他部件的自动逆向工具（X-Ray 提取 cache/TLB 参数、Plumber 分析 Arm cache、FetchBench/StrideRE 识别预取器），它们面向"无状态机、无多 IP 索引"的存储系统部件，无法处理 MDP 的复杂状态机与多 IP 索引表。
  - baseline 全栈执行例子（以手工逆向 Intel MDP 为例）：研究者先假设 MDP 用 load IP 索引，写一段含"延迟 store + load"的汇编微基准（用乘法链延迟 store 地址生成）→ 在 CPU 上反复运行并测时延（rdtscp），人工观察 load 是被阻塞（block）还是回滚（rollback）→ 逐个改 store/load IP 观察时序变化猜测索引位 → 靠枚举与直觉猜测状态机转移表 → 用概率性启发式验证（如 Spectre-V4 gadget 验证预测行为）→ 最终得到 MDP 组织与状态机参数。局限：跨平台每颗 CPU 都要重新手工分析；遇到非对称状态机（AMD 5 计数器/10 转移函数）时人工枚举空间爆炸；对 SL 型（store+load 双 IP 索引）设计会漏判（如 Apple 的 SL-S 型被误判为 L-nS），导致攻击精度低；方法不可扩展、易出错、无置信度。算法pipeline/系统框架/编译框架/kernel调度层次：论文未明确说明（本文对象是真实 CPU 微架构，无 ML/软件栈成分）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 SSBench：把"人工逆向"变成"平台无关的自动逆向框架"，逐条对应 baseline 缺陷：(1) baseline 无系统分类 → workflow-based taxonomy 把 20 个 MDP 设计按两维度（表项选择 L/SL/HSL × 状态机 S/nS）归入 6 类，识别算法按类派发对应表征流程（解决"每个 CPU 从头猜"）；(2) baseline 手动测时延猜状态 → 定时侧信道 + DBSCAN 聚类自动判定 S/B/R 时延分布，自动判定 MDP 存在性与设计类型（解决"不对称预测代价导致状态机非对称、人工难解"）；(3) baseline 人工猜状态机 → counter-based model solver 把状态机建模为计数器 + 阈值 + 7 参数（upd_{0t}/upd_{1f}/upd_{0f}/upd_{1t}/bnd/ovf/unf/ths），Algorithm 1 自动搜索边界条件构造不等式组用 pulp 求解（解决 AMD 5 计数器 10 转移函数人工爆炸）；(4) baseline 人工猜表组织 → store-load bounce 用 JIT 生成不同 IP 的 store-load pair，自动反推 hash 函数（差分矩阵 nullspace）、表大小、相联度、index/tag 位与替换策略（Algorithm 2 + 置换模式匹配 Table I）；（5）提供抽象 primitives（定时/核绑定/JIT）跨平台实现，30 颗 CPU 全自动识别出 3 类设计 14 种配置，并支撑三个新攻击：MDP-Gates（Intel，利用 MDP 状态传播 + 512 项 direct-mapped 表构建 μWM，吞吐较 cache-gates 高 100×）、MDP-CF（AMD，利用"无前置 store 的 load 也能更新 MDP" + 物理 IP 索引，98% 成功率恢复 WolfSSL invmod 输入）、MDP-CC（Apple，利用 speculative 更新 + 无用户/内核隔离，构建首个 cache/TLB-free 隐蔽信道）。
  - 论文方法全栈执行例子（以 Apple M2 性能核 SL-S MDP 表征为例）：方法/算法层——SSBench 按 taxonomy 识别 Apple MDP 用 store+load 双 IP 索引且有状态机（SL-S），选择对应表征流程（baseline 漏判此设计）→ 系统框架/原语层——macOS 用 pthread_set_qos_class_self_np 绑核、内核修改启用 S3_2_c15_c0_0 定时、mmap/mprotect 做 JIT 生成 store-load pair → 状态机层——counter solver 输出 store_sm=[0,-1,7,1,7,1,0,0]（3-bit 计数器：dependence 加 1、independence 减 1、ths 阈值）→ 组织层——store-load bounce 收集碰撞地址、差分矩阵求 nullspace 得 hash 函数（虚拟 IP 低位分组 [2],[3],...,[7,14],...）、eviction set 测 90 项、LRU 替换、全相联 → 安全测试层——构造跨特权碰撞对测隔离性，发现无用户/内核隔离且可被 speculative store-load 更新 → 攻击层——实现 MDP-CC 隐蔽信道（M2 真容量 59887 bps、cache miss/inst 0.01、TLB miss 0.00），覆盖 M1-M4；并实现用户→内核 kext 信道（M2 真容量 159578.30 bps）。对比 baseline 手工法：人工仅识别 L-nS 型、无法实现细粒度攻击。硬件架构/芯片设计层次：对象为真实 CPU 微架构（无 RTL 修改，RISC-V 侧用 gem5/SonicBOOM、OpenC910 作 ground-truth 验证）。
