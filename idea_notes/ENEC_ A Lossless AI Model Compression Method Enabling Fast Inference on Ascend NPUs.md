## ENEC: A Lossless AI Model Compression Method Enabling Fast Inference on Ascend NPUs

- baseline方法是什么？
  - Baseline 有两类：(1) 在 Ascend NPU 上直接移植的现有无损压缩算法（ANS 熵编码、LZ77/LZ4、Huffman 等，对应 nvCOMP/ZipNN/DietGPU/HANS 的思路）——作者实测把 ANS 移植到 NPU 后吞吐惨淡（Figure 1b），LZ77 类似；GPU 侧 DietGPU 的指数-尾数分离虽压缩比好，但指数部分仍用变长编码（ANS），依赖 gather 查表与条件分支，在 Ascend 上退化为极慢的不规则访存/控制流；(2) 朴素无压缩部署——Qwen3-32B 权重 61–65GB 超过单张 910B2 的 64GB HBM，需把部分权重 offload 到 CPU 并在计算时反复搬运，内存访问占 prefill/decode 阶段 78%–85% 的执行时间，AIC 矩阵算力被 I/O 瓶颈边缘化。
  - baseline 全栈执行例子（Qwen3-32B BF16，一个层权重从 CPU 传到 NPU 并参与前向）：模型推理算法层 = BF16 权重全量传输不压缩（或 ANS 压缩但 NPU 上解压吞吐 MB/s 级）；系统框架层 = HuggingFace Transformers + CPU offload，层权重按需从 CPU 经 NPU-CPU 带宽拉取；编译框架层 = 论文未明确说明（CANN/AscendC 直接编译，无额外编译优化描述）；kernel调度层 = GPU 式压缩 kernel（gather 查表、条件分支、变长前缀和）在 AIV 上因无条件分支/scatter/线程同步而串行退化执行，吞吐极低；硬件架构层 = 910B2 HBM 装不下全量权重 → HBM 与 CPU 之间频繁 DMA 传输权重，占执行时间 78%–85%，AIC 计算闲置。结果：TTFT/TPOT 比 ENEC 高 4.1×/3.3×（Qwen3-32B），Falcon-40B 层权重传输 batch=4 时占近 80% 执行时间。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = ENEC，算法-硬件协同设计的无损压缩器，用「块式定长编码 + 只压指数 + 三个 NPU 友好优化」逐条绕过 Ascend 架构约束：①bit-width quantization with hierarchical halving bit-packing（V1，对应 baseline 的 reduction max 占压缩 40% 开销）：用阈值位宽量化（组内最大值 ≤m 位则整组 m 位、否则 n 位，1-bit mask）+ 纯 bitwise OR/shift 的 lane folding 分层打包，把乘除与 max 规约换成向量 OR/移位，压缩吞吐 +30%；②vectorized branch-free integer transformation（V2，对应 baseline 的 gather 查表占压缩 35%/解压 45%）：依据 Observation 5（指数值-频率排名负线性，可拟合 Y=-1.00X+123.00）用线性映射 y=(2^n-x+b)%2^n 把查表换成向量加减乘移位，吞吐近翻倍；③intra-segment dependency decoupled scan / IDD-Scan（V3，对应 baseline 前缀和占解压 30%）：用转置+列方向前缀和+层级行扫描把 Ascend 32 字节段内禁止的相邻元素依赖解耦成硬件友好操作，解压吞吐较 V2 近 +100%。参数由三阶段搜索（式 1-4 最小化期望位长 B_exp）确定 (b*,n*,m*,L*)，且 DeepSeek 参数可零损失迁移到其他模型。压缩/解压 kernel 只跑 AIV，与 AIC 模型算子构成协作流水线（逐层解压与当前层 forward 重叠），消除 CPU-NPU 权重传输瓶颈。
  - 论文方法全栈执行例子（同一 Qwen3-32B，压缩后的层权重从 CPU 到 NPU 前向）：模型推理算法层 = 权重离线无损压缩（CR 1.35，bit-identical 重建），传输量减约 26%；系统框架层 = HuggingFace Transformers 集成 ENEC，逐层解压（下一层解压与当前层 forward 重叠，解压吞吐 217 GB/s 覆盖传输需求）；编译框架层 = AscendC/CANN 8.2.RC1.alpha002 编译 csrc/ kernel（.so 算子）；kernel调度层 = 解压 kernel 在 48 个 AIV 上并行处理 16K 元素块：bit mask→转 0/1→IDD-Scan 前缀和（8×16 half 转置+列扫描+行扫描）→逆 gather 取低位→OR 高位→逆变换还原指数→Combine 重组 BF16，与 AIC 前向并行（协作推理流水线）；硬件架构层 = 910B2 HBM 只存压缩权重，AIV 实时解压喂给 AIC 矩阵单元，消除 CPU-NPU 权重搬运。效果：TTFT 最高 6.3×（Falcon-40B）/4.1×（Qwen3-32B），TPOT 4.9×/3.9×，比 HANS 低 1.7–1.8×；压缩吞吐 263–523 GB/s（vs DietGPU 3.43×、vs nvCOMP 压缩比 1.12×），是首个达到 SOTA GPU 压缩器性能的开源 Ascend 无损压缩器。
