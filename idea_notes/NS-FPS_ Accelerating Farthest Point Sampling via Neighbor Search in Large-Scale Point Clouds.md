## NS-FPS: Accelerating Farthest Point Sampling via Neighbor Search in Large-Scale Point Clouds

- baseline方法是什么？
  - Baseline 有两类：(1) **vanilla FPS**（OpenPCDet CUDA 实现跑在 RTX 3090、C++17 跑在 AMD Ryzen AI 9 365）——维护 N 长距离缓存 T，每轮迭代全量扫描所有点、更新 T[p]=min(T[p],d(p,s_k))，再全量扫 T 找全局最大；复杂度 O(MN)，120k 点 25% 采样需 >900ms、95% 时间耗在内存事务（profile：600M 次请求、164.65GB L1 + 74.81GB L2 请求、缓存吞吐 95.62% vs SM 指令吞吐 27.17%，纯内存受限）。(2) **QuickFPS-ASIC**（SOTA 点云采样加速器）——两级 k-d 树动态剪枝距离比较，保证 FPS 精确，但建树初始化慢、树遍历引入控制开销与冗余内存访问，无法消除大规模点云的高内存访问根本问题；另有近似方案 PNNPU/TiPU 把全局 FPS 拆成块内局部 FPS（复杂度降到 O(N²/g) 但牺牲采样均匀性、块边界出现伪影）。
  - Baseline 全栈执行例子（一次 120k 点帧 25% 采样，GPU vanilla FPS）：算法层：第 k 轮对全部 N 个未采样点算 ||p−s_k||² 并与缓存 T 比较，再全量 scan 找 argmax；系统框架层：OpenPCDet 的 CUDA kernel 由 PyTorch 算子下发，每轮一个 kernel launch；编译框架层：论文未明确说明（CUDA 编译器常规优化）；kernel调度层：GPU 每 SM 并行处理点块，但每轮都要重新遍历全部 120k 点，距离缓存 T 反复读写，L1/L2 被 600M 次请求打满（缓存吞吐 95.62%）、SM 算术单元 27% 空闲；硬件架构层：全局内存带宽成为瓶颈，cache-line 取整放大细粒度访问，层级 argmax 需全局内存同步。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法：NS-FPS = 硬件-软件协同设计，把 FPS 重述为邻居搜索，三个设计对应解决 baseline 缺陷：(1) **Voronoi 部分更新**（对应解决全量遍历）——用 VD 几何证明：新一轮采样只影响落在新采样点 s_k 的搜索球 B(s_k,d_k)（半径=到已采样集最近距离，该球严格包住真实 Voronoi cell）内的点；把每轮更新点数从 O(N) 降到 O(N/k)、总复杂度从 O(N²)/O(MN) 降到 O(N log N)，同时数学上保证与 vanilla FPS 采样结果完全一致（lossless，vs PNNPU/TiPU 的近似牺牲）。(2) **Morton 码邻居搜索**（对应解决 QuickFPS k-d 树开销）——坐标 7/7/3-bit 交织成 17-bit Morton 码 + 桶排序线性时间重排（免比较排序/免建树），页表式三级存储按 cube 按需分配，邻居查询只枚举与搜索球相交的 cube。(3) **层次最大缓存**（对应解决全量 argmax 与全局同步）——距离缓存 16:1 逐级压缩成 1K/64/4/1 四级 max 缓存，Cache Change FIFO 只刷新被更新块，全局最大 top-down 常数级遍历得到，消除 GPU 层级 argmax 的全局内存同步。
  - 论文方法全栈执行例子（120k 点帧 25% 采样，NS-FPS-ASIC + PCIe 卸载进 PointRCNN/3DSSD/IA-SSD）：算法层：Morton 桶排序一次预处理（1.02ms），随后每轮只在搜索球内更新 T 并刷新受影响块的最大候选；系统框架层：FPS 从 GPU 卸载到 NS-FPS-ASIC（PCIe 19.2 GB/s 建模搬运开销 <2%），其余网络层仍跑 RTX 3090；编译框架层：论文未明确说明；kernel调度层：Neighbor Search Engine 4 级流水（取数→16 路并行算距→16:1 局部最大→地址记录），32 项 Morton Cube Buffer 预取隐藏 DRAM 延迟，Hierarchical Max Finder top-down 更新 + bottom-up 查坐标；硬件架构层：页表/层级缓存/FIFO 在片上 SRAM，Page Memory 在 DRAM，DRAMsim3（DDR4-2400）建模的访存只触及搜索球相关 cube，120k 帧邻居搜索 9.23ms + 最远点选择 1.65ms；结果：较 GPU 加速 81.6×、内存访问降 1700×，较 QuickFPS-ASIC 加速 2.9×、降 13.4×，端到端 IA-SSD 加速 2.7×，26.69 mJ/帧、较 QuickFPS-ASIC 节能 38.9%。
