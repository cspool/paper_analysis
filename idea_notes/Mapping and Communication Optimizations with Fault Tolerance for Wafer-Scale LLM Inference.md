## Mapping and Communication Optimizations with Fault Tolerance for Wafer-Scale LLM Inference

- baseline方法是什么？
  - Baseline 是面向 switch-based 分布式 GPU 集群的 LLM 部署栈移植到 wafer-scale 层次化 2D mesh 上的方法组合：(1) 通信用 XY/XY-YX-FT 路由（论文端到端 baseline = Tangram ZigZag inter-die 映射 + Gemini intra-die 映射 + XY-YX-FT 路由）——XY 路由先沿 x 轴再沿 y 轴，是 mesh 上通用、最短路径的选路，XY-YX-FT 加入回溯规则覆盖更多故障；(2) 映射用 ZigZag（Tangram）inter-die 分配（Transformer block 按 ZigZag 蛇形分配到 die 组，多 die 组用 folding 折行）与 Gemini 的 intra-die SA 映射（只优化通信距离/hop 数，每 core 至多 2 算子）；(3) 通信优化方法如 TidalMesh [42]、WaferLLM [24]、TTO [37]、2D AllReduce [77] 面向理想对称 mesh 的 AllReduce，MultiTree [26]/TACOS [70] 拓扑无关但主要面向 AllReduce；(4) 容错靠冗余硬件（Cerebras WSE 备用 core/互连）或简单重路由。核心痛点（论文 case study 4×4 mesh 揭示）：(a) 自回归解码使 ZigZag 最后一个与第一个 die 组间出现近直径通信路径（Fig.1 黄箭头），长距离、高争用；(b) Gemini 式仅最小化通信距离的映射忽视计算负载均衡——attention 块在 2×2 core 上数据依赖被忽略时 tensor MM 不平衡、Softmax 冗余通信、K 与 K^T 长距离（Fig.6），核心成为瓶颈；(c) 多个并发 multicast 在 XY 路由下共享链路 (9,10)(10,11)(11,7) 造成热点争用；detour/多路径路由要么加长路径要么源端口饱和（Fig.7）；(d) 故障打破 mesh 对称性后，XY/对称优化方法失效、恢复性能的映射又引入复杂非均匀点对点/multicast 流量，进一步恶化；(e) 对称网络优化的方法（TidalMesh 等）在故障下无法保持性能。
  - Baseline 全栈执行例子（一次 Llama-3-70B decode 迭代，HW2 7×12 die 阵列，ZigZag+Gemini+XY-YX-FT）：算法层：Transformer 自回归 decode 逐 token 依序经过全部 70B 参数层，TP 激活同步在每层 MLP/attention 末尾做 All-Reduce；系统框架层：论文未明确说明（无开源 Serving 框架，BusyBarn 框架本身为 mapping/通信优化器）；编译框架层：论文未明确说明；kernel调度层：ZigZag 把层分配到 die 组后，最后一组算完输出经 XY 路由穿越大半个 mesh 送回第一组（近直径路径），每 token 迭代重复该长距离通信；同时层内算子按 Gemini 只压 hop 数的方式放置，少量 core/链路被压成热点（Fig.11 热力图）；XY 路由下多个区域 multicast 共享链路争用带宽；硬件架构层：数据沿 on-chip 1ns/256GB/s 链路与 D2D 20ns/256GB/s 链路逐跳转发，长路径 + 争用使纯通信时间占比高、计算-通信无法重叠，故障 core/link 后 XY-YX-FT 的回溯 detour 进一步拉长路径，端到端延迟显著劣化。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法：BusyBarn = LR 数据流记号 + 层次化 SA 映射 + BALD 通信调度，故障容错内建于映射与通信中。两大技术对应解决 baseline 缺陷：
    1. **层次化模拟退火映射（对应解决 ZigZag 长路径与 Gemini 负载不均）**——(a) Inter-die：Hamiltonian Loop 策略把 die 组排成哈密顿环，使每对相邻 die 组（尤其最后↔第一）距离最小，适配自回归 decode 的递归数据依赖；用 SA 在拓扑约束、硬件故障、层-die 数不匹配下探索 Hamiltonian/近 Hamiltonian 映射（交换两节点位置最小化加权距离）。分层（die 组间 PP、组内 SP/CP/TP 混合并行）把 NP-hard 搜索空间大幅压缩（TP/CP 通信比远高于 PP [41]）。(b) Intra-die：第二个 SA 采用 Gemini 移动策略（算子交换/重分配/HBM 数据重分配），但损失函数从"仅通信距离"扩为四元混合 loss——总通信距离 + 最大链路负载 + 最大 tensor workload + 最大 vector workload，线性时间可算（无需 cycle 级仿真），直接消除 Fig.6 中 core 计算不平衡、冗余通信、K/K^T 长距离三类缺陷。
    2. **BALD 通信调度（对应解决 XY 争用、detour 路径拉长、故障失效）**——三步：(i) Dijkstra Path Profiling 记录全对最短距离与唯一路径映射（处理非对称节点度/异构带宽）；(ii) Path Scheduling 按 priority=α·branch_cost+β·link_load+γ·neighbor_distance 逐任务分配链路，均衡链路负载同时最小化距离（α/β/γ 可调：首轮 γ 大偏好最短路径、后续 β 大均衡负载）；(iii) Heuristic Backtracking 用 tabu 机制对过载链路 l* 上的任务按概率 ρ 重分配（成功回退进 tabu candidates、失败进 tabu forbiddens），进一步消除随机选择的链路争用。BALD 基于 BFS/DFS 拓扑无关，只要存活图连通即可容忍任意节点/链路故障，路由实现为可重配置 LUT（类似 TPUv4），主机每推理任务加载/更新，同时适配制造缺陷与运行期故障。
  - 论文方法全栈执行例子（同一次 Llama-3-70B decode 迭代，HW2 7×12，BusyBarn）：算法层：同自回归 decode 逐层推进，TP 部分和 reduce-scatter 可提前到单个 compute tile 产生部分和时（数据流执行，vs bulk-synchronous 延迟到整矩阵乘完）；系统框架层：BusyBarn 输入硬件配置 JSON + 模型参数 JSON + 框架设置，输出完全调度事件集（LR 记号 → 映射 → 通信调度），无开源 Serving 框架参与；编译框架层：论文未明确说明；kernel调度层：Inter-die SA 把层排成 Hamiltonian Loop，最后 die 组输出只需一跳邻居距离回到第一组（消除近直径路径）；Intra-die SA 四元损失把算子/HBM 数据放成计算-通信双均衡布局（Fig.11 热力图不再有热点 core/link）；BALD 为每层 TP reduce-scatter/multicast 与跨组 PP 通信分配均衡链路（避开故障 core/link 的 detour 也用最短距离），LUT 下发给路由器；硬件架构层：数据沿 on-chip 1ns/256GB/s 与 D2D 20ns/256GB/s 链路逐跳转发，ASAP 事件驱动模拟器让计算与通信自动重叠（如 attention 计算 Q 时广播 K 权重）；结果：通信典型模式最高 2.55× 加速（All-to-All 故障下），端到端相对 baseline 加速 1.08–2.14×（HW1 1.17–1.84×、HW2 1.08–2.14×、HW3 1.17–1.88×，几何均值 1.40×），1000 次 SA 迭代达 100 万随机搜索参考值的 12.4% 以内，映射/通信/容错一体化设计在 10–20% 缺陷率、1–2 节点/链路故障下保持 1.24–1.53× 相对 Gemini 的加速。
