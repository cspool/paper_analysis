## M100: An Orchestrated Dataflow Architecture Powering General AI Computing

- baseline方法是什么？
  - Baseline 分两类：(1) 通用 GPGPU（NVIDIA Orin/Thor-U 系，SIMT + tensor core + cache 一致内存层次）——Li Auto 早期 AD 系统基于此开发部署；(2) 领域专用架构 DSA（Tesla FSD chip 等）——把 NN 算子硬连线成固定流水线。痛点：GPGPU ① 效率与 TCO 劣势——非定制 AD 软件栈、常含未用特性、总拥有成本高；② cache-based 内存层次带来优化挑战与执行不可预测性，流式性能受挫；③ 峰值性能、定制化与可扩展性受限。DSA ① 固定流水线难以跟上快速演进的 AI 算法（尤其端到端 VLA 模型），生命周期短；② 重工程成本高。传统 dataflow 架构（TPU/TSP/Cerebras/SambaNova/Tenstorrent/Dojo 等）虽高效，但设计复杂度与硬件开销大。
  - Baseline 全栈执行例子（一次 UniAD 感知推理，Thor-U 实机）：算法层：CNN 主干提取图像特征 → BEVFormer 生成 BEV 特征 → TrackFormer 用 900 query token 做检测跟踪；系统框架层：NVIDIA 软件栈（CUDA/TensorRT 等）经驱动调度任务；编译框架层：CUDA kernel 编译与优化（论文未明确说明细节）；kernel调度层：SIMT 与 tensor core kernel 在 SM 上调度，数据经多级 cache 层次搬运，访存延迟/缓存失效不可预测；硬件架构层：Thor-U（TSMC N4、273 GB/s DDR）执行，perception 仅 7.9 FPS，未达高速自动驾驶实时要求；LLM decode 阶段受 273 GB/s DDR 带宽限制。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法：M100 "orchestrated dataflow"（编排式数据流）——以 tensor（大或小）为指令粒度，编译器/固件编排数据在计算单元与片上/片外存储间的流动，几乎完全消除多级 cache（以软件管理的数据流 + 硬件同步计数替代 cache 一致性），计算由"数据就绪"触发而非指令流顺序。关键设计选择：①同构计算块（tensor TCU/vector CVU/scalar RISC-V + 共享 2 MB HBSM + 同步）经可扩展网络互联，14 cluster×4 TPB；②显式 DMA 控制的 TPB HBSM ↔ NPU SRAM ↔ DDR 数据搬运，计算与搬运重叠；③tensor 级流式指令消除 register file 与显式 load/store，延迟被大 tensor 摊薄；④生产者-消费者同步计数（SU 硬件计数，软件控制同步粒度），支持 barrier/broadcast/reduction，可跨 NPU；⑤集中式指令分发（ICB 广播）+ 同元素保序/跨元素乱序，同步依赖交给软件——把复杂度从硬件转移到编译器/运行时（"orchestrated"）。对应解决：GPGPU 的 cache 低效/不可预测 → 显式数据流 + DMA 重叠，编译器静态调度规律可预测的数据移动；DSA 的算法僵化 → tensor 粒度通用指令 + 可重构 CVU，编译器映射任意新模型；传统 dataflow 的硬件复杂 → 编排式设计使硬件简单、可扩展、成本低、良率友好（12/14 cluster 即可用）。
  - 论文方法全栈执行例子（一次 UniAD 感知推理，M100 8 cluster）：算法层：RegNet+FPN 提取特征 → BEVFormer 生成 BEV → TrackFormer 900 query 检测跟踪；系统框架层：AI inference runtime（ARM Cortex-A78AE）准备输入、加载模型、按资源分配踢发任务，NPU driver 作 HAL，NPU firmware（RISC-V）JIT 动态生成优化 TPB 指令；编译框架层：space-time scheduler 把子图映射到 4 个 TPB 并把 tensor 分解为 mini-tensor 按时相流动，graph compiler 做 fusion/layout/动态内存分配，backend compiler 生成 intrinsic；kernel调度层：固件经 ICB 以 destination mask 广播 TPB 指令到目标 TPB，指令队列按数据就绪+同步条件派发到 TCU/CVU/DTDU/CSU，TWU 生成嵌套循环地址序列流式访问 HBSM，SU 维护生产者-消费者计数，跨 cluster 经 Mesh（256 GB/s/对）与 DRB（256 GB/s 广播）通信；硬件架构层：CCB 4 核 RISC-V 编排、2 个 DMA 从 DDR（273 GB/s）取权重经 DRB 广播，TPB 内 2 MB HBSM（32 bank×32 B/cycle，~20 cycle 延迟被流式掩盖）共享，TCU 8×64 MAC（4 元素点积/cycle）双缓冲跑 conv/GEMM 满吞吐，CVU 配置 softmax 等流水。结果：RegNet 13.1ms、BEVFormer 7.92ms、TrackFormer 1.27ms，perception 30 FPS vs 7.9 FPS（同功率 3.8×）；LLM decode（W4A16）21.34ms 与 Thor-U 相当（同为带宽受限），prefill（W8A8）79ms vs 154ms（1.95×）。
