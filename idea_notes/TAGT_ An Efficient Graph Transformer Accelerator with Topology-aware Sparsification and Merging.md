## TAGT: An Efficient Graph Transformer Accelerator with Topology-aware Sparsification and Merging

- baseline方法是什么？
  - Baseline 为三类：(1) 通用 GT 软件实现 DGL（v2.4.0，CPU）——保留原始 O(N²) 全局注意力，每个顶点 attend 全图所有顶点，导致平方级计算与 O(N²) 中间注意力矩阵（N=256K 时无法片上缓存、必须高延迟 off-chip spilling）以及 O(N·D_feat+Nd) 大特征/权重工作集的持续流式搬移；(2) TorchGT（GPU，SOTA GT 训练框架）——dual-interleaved 稀疏注意力，但依赖 Hamiltonian path 这一 NP-complete 验证且现实图常不满足的结构前提，前提失败即回退 O(N²) 全局注意力，且选择性注意力显著掉准确率；profiling（Fig.3）显示 off-chip 访问占 60.5% 执行时间、SM 利用率 <25%、60.3% 取回数据不必要、cache line 利用率仅 18.27%；(3) GNN 加速器 FlowGNN / MEGA / BingoGCN——为稀疏 message-passing（GCN/GAT 的 CSR/CSC 遍历、邻居聚合、负载均衡）优化，不适配 GT 的稠密全对注意力；Attention/FFN 共占执行时间 91.61%。
  - baseline 全栈执行例子（DGL-CPU/TorchGT 推理一个图 Transformer 层，N 个顶点、D_feat 维特征）：① 算法pipeline 层——每个目标顶点 v 对全图 N 个顶点做式1 注意力（QK^T/√d_K + softmax + PV），物化 N×N 注意力矩阵（Graphormer 还加最短路径距离偏置 bias_φ，使注意力矩阵不规则、块矩阵优化失效）；② 系统框架层——DGL/TorchGT 按 CSR 遍历全图、非连续取顶点特征（空间局部性差，cache line 利用率 18.27%），TorchGT 检查 Hamiltonian path 前提、不满足则回退全对注意力；③ 编译框架层——论文未明确说明（无 GT 专用编译优化，仅通用 PyTorch kernel）；④ kernel 调度层——FlashAttention 类 IO-aware 注意力 kernel 用 tiling+online softmax 降低显存流量，但不消除 O(N²) 顶点对交互次数；⑤ 硬件架构层——CPU/GPU 上 O(N²) 中间注意力矩阵溢出到 off-chip（HBM/DRAM），大特征矩阵持续流式搬移饱和内存带宽、SM 饥饿利用率 <25%，60.5% 执行时间耗在 off-chip 访问上。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 = 拓扑感知稀疏化与合并（TDS 算法）+ 专用加速器 TAGT（算法-硬件协同设计）。TDS 把每个目标顶点的注意力邻域从全图 O(N) 缩到 O(m·log_m N) 并保留全局信息：original 边保留局部拓扑（解决局部保真）；fusion 边（自底向上按 1D 顺序分层合并 m 个连续顶点成高阶代理顶点，含全局根）与 association 边（逐层左右各取 m 个关联顶点提供多粒度远程上下文）不直接丢弃远处顶点而是把它们"合并"成代理顶点，任意两点最多 2-hop 可达——对应解决 baseline (1)(2) 的"朴素剪枝断掉高阶交互路径/全注意力平方开销"矛盾：用 O(N log N) 稀疏注意力替代 O(N²) 全局注意力，准确率下降 <1pp 且高于 TorchGT。硬件侧把 TDS 构造与注意力映射到专用流水：TDL 的 MAPE 6 级流水线 + 复制取数单元对应解决"不规则 gather 与内存延迟"；TCU 的 FUU（对 SE/PE 编码无关）+ MOU 去重（共享 fusion 祖先只算一次）对应解决"TDS 构造的冗余计算与软件 runtime overhead（69.8%–86.1%）"；Task Dispatcher 合并共享 Associated ID 打包对应解决"跨顶点数据复用缺失"；FAU（UPE 流式分数 + VPE 聚合）不物化注意力矩阵 + SCU 块级异步 softmax（ECU 并行局部分子/分母 + 64 CRU 按 TID 异步累加 + Divider Pool 归一化）对应解决"O(N²) 中间数据爆炸与全局 softmax 数据依赖导致的低并行"；可配置 Switch 的 Reconfigured MM 模式让 FFN 复用全部 MAC 资源。
  - 论文方法全栈执行例子（TAGT 推理同一层）：① 算法pipeline 层——先自底向上聚合出全部 fusion 顶点特征（O(N log N)），再对每个目标顶点在其 TDS 1-hop 邻域（K=O(m·log_m N) 个顶点：局部邻居 + association 上下文 + fusion 祖先/根）做式1 注意力，总边数 O(N log N)，分数流式不物化矩阵；② 系统框架层——TAGT-S（修改 DGL 的软件实现）在 A100 上验证算法收益（比 TorchGT 快 1.8×–2.5×、带宽利用 >60%），但软件 runtime overhead 占 69.8%–86.1% 执行时间，需硬件消除；③ 编译框架层——论文未明确说明（无编译器，m 等 TDS 参数经片上配置寄存器编程）；④ kernel 调度层——TDL 的 MAPE 6 级流水线按 CSR 分阶段取邻域/特征/权重/编码（复制 Fetch_Neighbors/Fetch_Features 掩延迟）→ TCU 的 FUU 拼接特征+编码生成叶子嵌入、MOU 并行加法树聚合 fusion 顶点（查 TDS-CSR 去重共享祖先）→ Task Dispatcher 合并共享 Associated ID 任务打包 → 16 FAU 并行：UPE 算原始注意力分数流式送 SCU，SCU 的 BPM 分段 → ECU 并行算局部分子/分母 → 64 CRU 按 TID 异步累加 → Divider Pool 归一化 → AU（ReLU），VPE 聚合 value，FFN 用 Reconfigured MM 模式；⑤ 硬件架构层——Alveo U280 @280MHz、1MB Feature + 1MB Weight + 512KB Partial + 512KB TDS-CSR + 128KB Task FIFO + 128KB Output Buffer 片内缓冲 + ping-pong 缓冲隐藏延迟，HBM2 460GB/s 只搬必要数据（off-chip 流量降 42.1%–81.6%）；结果：vs DGL-CPU 175.4×、vs TorchGT 18.6×、vs FlowGNN/MEGA/BingoGCN 8.2×/6.9×/4.7× 加速，217.2×/24.8×/9.3×/7.5×/5.2× 节能，准确率下降 <1pp。
