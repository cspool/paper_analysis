## BAAP: Coupling Compute-in-SRAM with DRAM Banks for Near-Memory Processing

- baseline方法是什么？
  - Baseline 是 UPMEM 商用 DDR4-PIM（DDR4-2400 8 GB DIMM、16 芯片×8 bank=128 DPU；每 DPU 一个 500 MHz 14 级流水 in-order 标量 CPU + 24 KB IRAM + 64 KB WRAM scratchpad + 64 MB DRAM bank，16 tasklets 多线程标量执行），对比主机侧 Xeon W-1390P（Rocket Lake 3.5 GHz OoO + AVX-512）与主机侧 AP（PUMICE 版 CAPE [52]，2.72 GHz + 4×4H HBM）。痛点：UPMEM 标量核受 DRAM 工艺约束（约 3 层金属、逻辑密度 1/10、pitch 4×、晶体管慢 3×）只能做单周期位运算/移位/整数加减、乘法 32 周期软件仿真，一旦 DMA 消除数据搬移瓶颈，模式匹配/向量/图三类内存受限应用在 bank 级重新变成 compute-bound（单 DPU roofline 峰值 ≈0.35 GOPS，INT32 ADD/MUL 实测距屋顶差 2–12×）；Samsung FIMDRAM/SK hynix AiM 等固定功能方案（FP16/BF16 SIMD MAC）只覆盖 AI 一类负载；主机侧 AP 频率高 7.8× 但远离数据，访存延迟高约两个数量级，频繁访存负载（如 reverse_index）被访存拖垮。
  - baseline 全栈执行例子（PrIM REDSUM 归约，单 DPU）：算法层：标量循环逐元素累加；系统框架层：host 用 UPMEM SDK scatter 数据到 bank、boot DPU kernel、gather 结果；编译框架层：host 侧编译 DPU 二进制并 offload，指令流从 DRAM bank 经 IRAM 供 DPU 取指；kernel 调度层：无 SIMD/专用算子，乘法由软件例程模拟，24 线程细粒度多线程填流水线空泡；硬件架构层：单 decode 14 级 Revolver 流水线、无 bypass/stall、2-split 寄存器堆，DRAM bank 经 DMA 与 WRAM 交换数据——结果 compute-bound、远离 0.35 GOPS 屋顶。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 把每 bank 的 WRAM 部分（25–88%）替换为 6T push-rule 可重构 SRAM（Jeloka JSSC'16：差分/单端灵敏放大器切换、每 BL/BLB 一个 AND 门 + tag 寄存器）构成银行级关联处理器 AP，与残存标量 CPU 组成三模式引擎：Scratchpad 模式（保留原 UPMEM 功能）、SIMD 模式（位切片布局、位并行/位串行算术，VL 96–384）、DirectAP 模式（列连续布局、直接暴露 CAM 搜索/更新），扩展 14 条 ISA 指令（表 IV），ASU 展开微码、VPU 预取与 DMA 重叠。(1) 对应"bank 级 compute-bound"：位并行（3–4 周期）与位串行（add 8n+2、mul 4n²+4n）算术并行到整列元素，75% 配置位运算 ≈37 GOPS（vs 0.35 GOPS 屋顶），关闭 INT32 ADD/MUL 的 2–12× 空档、把大量 kernel 推入带宽受限区。(2) 对应"乘法软件仿真"：位串行乘法虽需数百周期，但并行吞吐 + VPU 与 DMA 重叠（decode GEMV 关 VPU 损失 39%）使长延迟算术不暴露。(3) 对应"固定功能只覆盖一类负载"：DirectAP 整字单周期 CAM 匹配 + ap_regex（<m−k 周期）覆盖模式匹配/直方图计数/图遍历（BFS 算法 1），一套硬件覆盖三大类负载。(4) 对应"主机侧 AP 访存远"：AP 移到 bank 旁，访存延迟低约两个数量级，内存密集 Phoenix 负载超主机侧 AP 一个数量级以上、strmatch 超 OoO CPU 近 3 个数量级；代价是频率 350 MHz（最低 225 MHz 仍有平均收益），计算密集负载回退，靠 VL 补偿。面积开销 1.2281× 折算容量、功耗 65 nm 悲观缩放下仍低于 150 mW/DPU。
  - 论文方法全栈执行例子（同一套负载）：算法层：DirectAP BFS（算法 1）把图遍历写成关联查询——ap.search/ap.searchacc 找当前前沿（CURR∧¬PROC）、tag popcount 判空、ap.update 批量标记、tag 读出后清零、对新发现节点批量 searchacc 累积成新前沿；系统框架层：host 用扩展 scatter/gather（带 layout 参数）做初始布局，DPU 运行时库 baap_set_mode(mode, m) 做 drain-flip-reload 换布局（最坏 0.171 ms、约 2–15 次 SIMD 乘法摊平）；编译框架层：kernel 主模式编译期声明、编译器可发 BAAP intrinsics，ISA 允许隐式换模（完整编译器论文未明确说明）；kernel 调度层：ASU 把每条 AP 指令展开为 CAM 搜索/更新微码，VPU 非投机预发射下一向量 load/store 与 DMA 重叠（周期三分类 Overlap/Idle/Compute-only）；硬件架构层：CSR 控制灵敏放大器差分↔单端切换（同一晶体管仅控制信号变化），32x36 子阵列链位切片执行位串行进位传播，128 bank 并行。结果：PrIM 单 DPU 最高 14.33×（88% 配置，平均 5.73×）、整 DIMM 再平均 4.1×；基因组 k-mer 计数对 UPMEM 2–38×、图遍历 1.1–2.8×（k>21 回退主机）；Phoenix 内存密集负载超主机侧 AP 一个数量级。
