## Transpiler-Architecture Co-Design to Curb Clifford Costs in Fault-Tolerant Quantum Computing

- baseline方法是什么？
  - Baseline 是 PBC（Pauli-Based Compilation，[51] Litinski 的框架）：把所有 Clifford 门（尤其 CNOT）穿过非 Clifford 门换到电路末尾、吸收进最终测量，从而消除显式 Clifford 门；配合两个 PBC 架构——Compact（1.5n+3 tile，每逻辑量子比特只暴露一条边，Y-edge 操作需 3 个额外 ancilla 与最多 9 cycles）与 Fast（2n+√(8n)+1 tile，暴露所有边、每 cycle 一个 multi-qubit π/4 旋转）。单比特旋转合成用 Solovay-Kitaev（Qiskit 默认，c≈3.97，序列极长）或 GridSynth（Ross-Selinger）。
  - baseline 全栈执行例子：QASMBench 18 比特 QFT（783 门）→ 编译层：Qiskit/Solovay-Kitaev 合成 Clifford+T（104,217 门，约 60% 为 Clifford）→ PBC 把所有 Clifford 门（含 CNOT）穿过非 Clifford 门换到末尾，非 Clifford 门纠缠成最高 16 比特的 multi-qubit π/4 旋转（40,777 个门、深度 37,756、每层仅 1.08 门）→ 硬件层：Compact 架构上每个 multi-qubit 旋转先做 patch rotation 暴露所需边（Y 边最多 9 cycles）再与 magic state 做 lattice surgery，单个 distillation block 每 9 cycles 供一个 magic state → 28,783,535 QEC cycles、code distance 21、总体积 1.0×10^12（MSD）；Fast 架构用 11 个 distillation block 把 cycle 数降到 2,382,355 但 tile 数升到 170。算法-编译层：Clifford 消除已由 PBC 做到极致但牺牲门并行；kernel 调度层：论文未明确说明（FTQC 无 GPU kernel 概念）。缺陷：multi-qubit 旋转权重高（最高 16 比特）→ 门级并行度坍塌（深度近 4 万）；多比特逻辑操作错误率上升、需更高 code distance（21 vs 19）→ 物理量子比特与空间-时间体积大增；且 PBC 每层仅一个操作，无路由优化空间。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 TACO = Transpiler–Architecture 联合设计，三策略：(1) 硬件感知 Clifford 优化——关键洞察是"不把 CNOT 穿过电路"（保住并行），只对 Toffoli 分解（8 个 Clifford 门经交换 C3/C4 后按自逆对两两相消）与单比特序列（MA Normal Form 下用 TS=T†Z 消 S 门、交换律合并 Pauli 门、引入硬件原生 Rx(π/4) 门用 HT=Rx(π/4)H 消 H 门）做局部 Clifford 消除，全部操作权重 ≤2；(2) FTQC 感知转译——动态分解先降 Rz 门数（QPE 最优）、GridSynth 最优 T-count 合成（ε=10^-10），QFT 全转译 <1s（GridSynth 单独 16.1s、Qiskit 34.73s）；(3) 资源局部性驱动架构——优化后电路的高 π/4 旋转局部性（同一量子比特上连续几十到几百个旋转）→ compute block（4-tile、X/Z 双边暴露直连 distillation）+ memory block（三行 1.5n 紧凑布局、CNOT 经共享 ancilla 层）+ super-block 工厂分布，用模拟扫 magic state 吞吐做 space-time volume 最小化（18 比特 QFT 最优 4 个/cycle，体积比单 block 降 57%）。
  - 全栈执行例子：QASMBench 18 比特 QFT → ① 算法/编译层：动态分解降 Rz → GridSynth 合成 Clifford+T（104,217 门）→ MA Normal Form 的 Clifford 消除（Clifford 降 98.6%，剩 1,080 Clifford + 40,777 T，深度 6,598，比 PBC 浅 5.9×，门并行与原始 Clifford+T 一致，权重 ≤2）→ ② 硬件层：长 π/4 旋转序列的量子比特驻留 compute block（每 QEC cycle 一个 π/4 旋转，X/Z 边按轴激活连 distillation），空闲量子比特存 memory block（三行 1.5n 布局），qubit 转移 1 cycle、patch rotation 3 cycles；4 个 compute&distillation super-block 围绕中央 memory 分布（363 distillation tiles + 12 compute + 29 data = 404 tiles，MSC 下 4 个/cycle）→ ③ 模拟/评估层：cycle-accurate 模拟器（greedy 或 LSQECC 路由）逐层推进得 595,604 QEC cycles（MSC）、code distance 19、物理量子比特 2d²=722/逻辑 tile、体积 3.8×10^10（MSC）→ 相对 PBC Compact/Fast 体积降 95%/63%，执行时间最高 21.9×（几何平均 4.4×）加速。对比 baseline：PBC 用"消除 Clifford 但毁并行 + 面积换速度"；TACO 用"保住并行 + 用架构局部性吸收 Clifford"同时压低 cycles 与体积，且仅需 1.5n+4 逻辑 qubit tile（vs PBC Fast 2n+√(8n)+1），并为 LSQECC 等路由优化留出空间（slices 减半、体积再降 1.7×），使现有 T 门优化（如 MSC）在 TACO 上收益更大。
