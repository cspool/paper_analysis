## PhaseWeave Phase-Aware Execution on Heterogeneous Chiplet Architectures for Datacenters

- baseline方法是什么？
  - Baseline 是同构 monolithic 服务器：28 核 Emerald Rapids 全高性能计算核（相同微架构、相同工作点、均匀内存带宽与延迟）。数据中心负载（微服务架构 + datacenter tax 连接操作 + 单服务内多阶段操作）在毫秒/亚毫秒尺度上高频交替 compute-/memory-/network-/low-power 类 phase，且各 phase 对硬件资源敏感性不同（GEMM/加密吃高频率宽发射、DeepCopy/压缩吃内存带宽、PtrChase/RPC 吃缓存容量与低 I/O 延迟）。同构硬件无法同时满足冲突的资源需求 → 要么过供给（轻 phase 时计算闲置）要么欠供给（compute phase 时性能/功耗状态受限）→ 尾延迟膨胀、吞吐与能效次优。对照还评估了 big.LITTLE 类单片异构（两类核，仅沿 compute-energy 轴，OS 启发式/程序员标注、task 级粗粒度）、PinToCores 静态映射（按主导 phase 钉微服务到 chiplet）。
  - Baseline 全栈执行例子（一次 AdSim 请求）：算法层：ML 推理 = GEMM（compute-bound，FP 密集）+ 输出张量 DeepCopy（memory BW-bound，LLC MPKI 高数倍）+ 指针追逐（memory latency-bound）；系统框架层：请求经 TCP/SSL/TLS + RPC + Protobuf (de)serialization + Zstd (de)compression（datacenter tax）在 Nginx/HHVM/Memcached/MySQL 等微服务间流转，全部共享 28 个同构核、均匀内存带宽；编译框架层：论文未明确说明（无编译框架修改）；kernel调度层：OS 调度器把各微服务线程放到任意同构核，无 phase 感知、静态 affinity，粗粒度 OS 启发式抓不到毫秒级 phase 变化；硬件架构层：GEMM phase 需高频率宽发射，但同构核无法同时给 DeepCopy 高带宽、PtrChase 大缓存，只能取折中，且排队延迟在爆发期放大尾延迟；芯片设计层：单晶片 monolithic，无芯片级异构，无按 phase 匹配的物理内存分区。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法：PhaseWeave = 异构多 chiplet 服务器（4 类 chiplet 各针对一类 phase：compute 高频率宽发射大 ROB/SIMD、fast-memory 大 L2+高带宽 DRAM 通道、near-network die 内集成 NIC、low-power 精简低功耗核）+ 硬件 Random Forest phase predictor（每 100µs epoch、15 特征、<100 cycles、占 0.02% 面积、离线 WDLBench 训练、未训练负载上 91% 准确率）+ benefit-aware 迁移算法（U(t,c')=S(p,c')-S(p,c)-λ·Q(c')-C_switch，看负载与切换代价）+ 异构物理内存（每 chiplet 专属 DRAM 分区 + NUMA 式页迁移）+ 两级 MESI 目录一致性 + iso-ISA/OS affinity 集成。对应解决 baseline 缺陷：(1) 硬件异构 ↔ 各 phase 资源敏感性——"每核专精一类"代替"每核兼顾全部"，同面积装更多核（38 vs 28）缓解排队，专用核加速瓶颈 phase；(2) 硬件内预测 ↔ 软件预测开销（50-数百 µs）已超过 phase 时长（数十-数百 µs）且落在关键路径——亚微秒、离关键路径、异步推理；(3) 收益感知迁移 ↔ 盲目迁移到满载 chiplet 造成的排队/上下文切换浪费（无算法 1.26× → 有算法 1.56×），T_min 防振荡；(4) iso-ISA + OS 原生 affinity ↔ 无需用户改代码/重编译、兼容现有 OS 调度器，透明部署。
  - 论文方法全栈执行例子（同一 AdSim 请求）：算法层：请求内含 GEMM→DeepCopy→PtrChase 等 phase 交替，应用无改动；系统框架层：请求经 datacenter tax 与微服务流转，每线程每 100µs epoch 由硬件预测器分类为 4 类 phase，OS 周期性读硬件 recommendation 并设 affinity 迁移；编译框架层：论文未明确说明（iso-ISA 无需重编译）；kernel调度层：调度器跑 Algorithm 1（Load State 报 Q、离线表给 S(p,c)、λ/C_switch 折算），GEMM phase 迁向 compute chiplet、DeepCopy 迁向 fast-memory chiplet、网络密集迁向 near-network、空闲迁向 low-power；标准 context switch（平均 23.8µs << phase 时长）入队目标 chiplet runqueue；硬件架构层：预测器 Decision Storage SRAM 中 15 棵树并行遍历、voting unit 输出 phase；GEMM 在 3GHz 6-wide 核执行、DeepCopy 用 25.6GB/s 带宽与 5MB LLC slice、PtrChase 靠 2MB L2 提命中；芯片设计层：线程跨 2D mesh 组核的 chiplet 经 60 cycles all-to-all 迁移，热页 NUMA 式迁移到主导 chiplet 的 DRAM 分区，两级目录（intra/inter-chiplet）维持一致性 → 端到端 P99 -65%、吞吐 1.56×、Perf/Watt 1.92×。
