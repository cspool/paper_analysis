## Hierarchical Wakeup Logic of the Issue Queue for High Scalability

- baseline方法是什么？
  - baseline 为现代超标量乱序核的常规整体式 IQ：random queue with age matrix（如 matrix scheduler），单个全尺寸（默认 200×200）RAM 型 wakeup matrix + select 逻辑，wakeup-select 必须单周期、非流水化完成以保证依赖指令 back-to-back 发射。痛点：(1) 增加 IQ 尺寸（为追求更高 IPC 而扩大指令窗口）使 wakeup matrix 的平方规模电路延迟与 select 广播延迟同步增长，wakeup-select 成为处理器关键路径之一，时序收敛下难以扩大窗口/发射宽度；(2) 直接对 wakeup-select 流水化虽能降周期时间，但会阻止依赖指令背靠背发射，显著退化 IPC，因此不能采用通用流水化手段。
  - baseline 全栈执行例子（一条依赖链 add→mul→sub，200-entry IQ）：算法pipeline 层 = 论文未明确说明（纯处理器微架构研究，无算法级加速/稀疏/量化）；系统框架层 = 论文未明确说明（无 Serving/调度框架）；编译框架层 = 论文未明确说明（无编译器参与，指令由编译器静态生成后进入 OoO 核）；kernel调度层 = 论文未明确说明（本论文的"调度"是硬件指令调度器，非 GPU kernel 或运行时算子调度）；硬件架构层 = rename 阶段把 add 写入 IQ 第 10 行并把 producer 位置记入 RMT；mul 的源寄存器经 RMT 得到 add 的 IQ 行号，在 wakeup matrix 的 cell(11,10) 写 1（同样 sub 写 cell(12,11)）；执行时 add 的 grant 信号（grt）驱动 wordline10 向全部 200 行的 bitline 广播，cell(11,10)=1 使 mul 的 ready 拉高，随后 select 在就绪指令中仲裁（age matrix 选出最老就绪者），grant 反馈回 wakeup matrix 的 wordline11 触发 sub 的就绪——全部在单周期内完成，mul 可背靠背发射。当 IQ 扩到 300/400 项时，200×200 矩阵需扩为 300×300/400×400，wordline 扇出与 bitline 长度、comparator/select 延迟同步上升，单周期时序无法闭合，处理器只能被迫停止扩大 IQ 与发射宽度，IPC scaling 受限（论文测得资源翻倍本可 +36% IPC 而基线被时序卡住）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法为 HWL（层级唤醒逻辑）+ HSD（HWL-structure-aware dispatch）+ 混合 stalling/no-stalling 派发模式。HWL 把 IQ 逻辑切成 8 个 25 项 segment，每个 segment 配一个小型非流水化 L1 唤醒矩阵，其后放一个全尺寸（200×200）3 级流水化的 L2 唤醒矩阵：同 segment 生产者→消费者用 L1 单周期完成 wakeup-select（保住 back-to-back 发射），跨 segment 用 L2 流水化唤醒（多 2 个周期，但只影响跨 chunk 依赖）；周期时间由 min(小 L1 延迟, L2 流水单级延迟) 决定，因此既降低周期又不动摇关键依赖链。HSD 在 dispatch 时按 DFG 切 chunk（LRP 预测 last-ready 源、切掉先就绪父边/已完成生产者的边/长延迟生产者的边——长延迟被执行隐藏故跨 segment 也不亏），尽量把 chunk 内节点派到 producer segment 以多用 L1，用 25 项小 L1 承接 91% 属于 ≤16 项 chunk 的动态指令。混合模式按 DFR 在 no-stall（容量高效但 L2 惩罚）与 stall（无惩罚但容量浪费）间自适应切换，处理 chunk 偏大的难点程序（deepsjeng/xalancbmk/xz/fotonik3d）。关键机制与 Baseline 缺陷的对应：整体式矩阵延迟随 IQ 尺寸平方增长 → 拆成小 L1（25×25 矩阵延迟远低于 200×200）+ 流水化 L2（把剩余大矩阵延迟摊进 3 级流水单级）；直接流水化 wakeup-select 破坏背靠背发射 → 用 L1 承接关键的同 chunk 依赖、L2 只处理非关键跨 chunk 依赖；L1 容量有限导致跨 segment 唤醒惩罚 → HSD 用 DFG 切 chunk + LRP 把依赖留在同一 segment，混合模式再兜底高竞争场景。结果：IQ 周期缩短 53%（(25,3) 配置），IPC 仅退化 0.9%（narrowing 3.2%、H-SW 3.6%），并让 1.5× 均衡微架构 scaling（300-entry IQ，前后端 1.5×）在无额外时序惩罚下平均 +17.2% IPC（最大 +43.1%）。
  - 论文方法全栈执行例子（同样的 add→mul→sub 依赖链）：算法pipeline 层 = 论文未明确说明；系统框架层 = 论文未明确说明；编译框架层 = 论文未明确说明；kernel调度层 = 论文未明确说明；硬件架构层 = rename 时 HSD 判定 mul 属于 add 的 chunk（LRP 预测 add 是 last-ready 生产者、busy-bit 显示 add 未完成、长延迟 flag 为假），故把 mul 派发到 add 所在的 segment（如 segment 2），在 L1 矩阵 cell(11,10)（列=segment offset）写 1，不在 L2 写 cell；sub 同样派到同一 segment 写 L1 cell(12,11)。执行时 add grant 驱动 wordline10 只广播到 segment 2 的 25 行 L1 矩阵（扇出从 200 降到 25），mul 单周期就绪并 select 发射，mul 的 grant 再经 L1 wordline11 唤醒 sub——关键依赖链全程单周期背靠背，周期时间由 L1(25 项)+select 或 L2 流水单级中较大者决定（默认 (25,3) 下由 L2 单级界定），比 200×200 整体矩阵延迟短 53%。若某个 chunk 的父节点是长延迟（如 cache miss 的 load）或 L1 已满（DFR 升高触发 stalling 模式），则该消费者跨 segment 派发、在 L2 写 cell，经 3 级流水唤醒（多 2 周期但被长延迟隐藏或仅在竞争期发生），混合模式按 10k 周期窗口的 DFR 在两种行为间切换以平衡 L1 利用率与额外周期惩罚。作用：在几乎不损失 IPC 的前提下把 IQ 周期缩短 53%，解除 wakeup-select 关键路径对宽发射/大窗口微架构 scaling 的约束，支撑 1.5× 资源均衡扩展获得 17.2% 平均 IPC 提升。
