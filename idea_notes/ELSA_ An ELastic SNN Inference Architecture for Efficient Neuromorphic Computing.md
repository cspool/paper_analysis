## ELSA: An ELastic SNN Inference Architecture for Efficient Neuromorphic Computing

- baseline方法是什么？
  - Baseline 为既有 SNN 加速器的两种执行模式：LBL（layer-by-layer，如 C-DNN/SpinalFlow/SASAP/Prosperity/Phi）——每层跑完所有 T 时间步 × N 个 spine/token 才进下一层，输出只能在整网完成后出现，与弹性推理天然不兼容；TBT（time-step-by-time-step，如 TrueNorth/Darwin/MorphIC/PAICORE）——每时间步评估所有层，支持弹性推理，但采用粗粒度层间流水，必须等一层所有 N 个 spine/token 缓冲并同步后才前进，完成的个体不能立即前传，首响应被层内同步延迟到 O(L×N)；TrueNorth 还有 1kHz 全局 tick 同步屏障。通信用 vanilla AER（每 spike 一个多 bit 包，如 32-bit，含空间位置/时间步信息），头部开销大，TrueNorth 相对 QANN 基线多 8× 流量（图 6）。计算用 inner-/outer-product 数据流：inner-product 读满整个稠密权重矩阵（权重 buffer 能耗占 76.2%）、outer-product 反复读写高精度 12-bit 膜电位 buffer（占 70.3%）。
  - baseline 全栈执行例子（PAICORE 式 TBT，4-bit ResNet50，一帧）：模型推理算法层 = IF/ST-BIF 神经元在 T=32 时间步内积分-激发，spike 二/三元序列；系统框架层 = 每时间步所有层被顺序遍历，层输出按时间步对齐；编译框架层 = 论文未明确说明（映射由硬件/工具链完成，无公开编译器）；kernel调度层 = spike 级异步计算 + 层内所有 N 个 spine 完成后才同步前传（layer-wise pipeline barrier），粗粒度 NoC 用 AER 每 spike 一包逐时间步重复传输；硬件架构层 = 近 SRAM 多核 TBT 芯片（PAICORE 1024 核、TrueNorth 4096 核 + 1kHz 全局 tick，SRAM-only 存权重与膜）。整体痛点：层内同步屏障使完成 spine/token 无法立即前传，首响应延迟 O(L×N)；AER 每 spike 独立包头放大 NoC 流量；inner/outer product 膜/权重访存大。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 三层协同设计把弹性推理的早期响应潜力释放到硬件：① spine/token 级细粒度流水（核心贡献）——每个完成的 spine（CNN 的 Z^{1×1×C}）或 token（Transformer 的 Z^{1×D}）立即前传下一层，连续流式流水把首响应从 O(L×N) 降到 O(L)，配合置信度早停（分类 max class prob、检测 objectness score）提前终止时间步；② bundled AER（BAER）——同行 spike 捆绑进一个 flit（256-bit 替代 17 spike × 25-bit = 425 bits），头部只存一次，与 spine/token 粒度天然对齐；③ mini-batch spiking Gustavson-product——BAER 提供行对齐 mini-batch，每 mini-batch 只读一次膜行、并行累加多权重行、写回一次，恢复 Gustavson row-wise 低访存（vs inner/outer product），且不打同步屏障、维持流水。映射层用贪心分区（按通信量排序合并层，Algorithm 2）+ Hilbert 曲线放置 + 多路径路由（遗传算法优化传输概率）减 NoC 拥塞与 RPB。缺陷→设计映射：层内同步屏障 → spine/token 级异步流水 + Output Scheduler 依赖顺序调度；AER 流量放大 → BAER 行捆绑（NoC traffic 平均比 TrueNorth 低 20.5%）；inner/outer 访存大 → mini-batch Gustavson（平均比 inner 省 2.7×、比 outer 省 1.9×）。
  - 论文方法全栈执行例子（同一 4-bit ResNet50，ELSA）：模型推理算法层 = 同一 ST-BIF SNN（精度与 QANN 一致 75.60%），推理按 spine 粒度推进，max class prob 阈值 0.55 早停；系统框架层 = ELSA_Algorithm（PyTorch）生成 spike trace，置信度超阈值即终止（平均减 21.9% 延迟，FCR 比稳定输出早 82%）；编译框架层 = 论文未明确说明（无编译框架，由 ELSA 三段式 mapping 完成：partition→Hilbert mapping→multi-path routing）；kernel调度层 = spine/token 级计算与通信（异步粒度 S./T.，时间步在 PE 级推进，表 XI 对比 Loihi/SpiNNaker/PAICORE 的 spike 级 + 层同步），完成 spine 经 Output Scheduler 立即调度，BAER flit 多路径转发；硬件架构层 = 6×6 神经核 2D-mesh NoC（36 核、72MB 片上 SRAM、100.23 mm²、200-500 MHz、28nm、82490 µW），每核 4 PE × 128 ST-BIF 电路（每周期 1024 加）。效果：vs ANT 3.4× 吞吐 + 13.6× 能效；vs PAICORE 2.9× 吞吐 + 22.1× 能效；4135.4 GOPS / 25.55 TOPS/W / 0.032 pJ/Sop；vs Eyeriss 9.2×（ResNet50）~2.1×（ViT-S）能量；早停显著目标响应更快（VOC2007 2.38→1.88 ms）。
