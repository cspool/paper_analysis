## Optimizing 3D Gaussian Splatting with Axis-Shared Rasterization and Order-independent Transmittance

- baseline方法是什么？
  - Baseline 是 3DGS 标准渲染管线（GPU 上如 Gsplat；加速器上如 GSCore 的 PE 阵列 + 32 并行 bitonic 排序网络）：projection（3D→2D Gaussian 投影、深度 d、SH 颜色）→ 每 tile 按深度升序排序（O(N log²N) bitonic 排序网络，硬件面积随并行度 k 按 k·log²k 增长）→ 逐像素独立光栅化（α 计算 8 MUL+4 ADD+1 EXP、α-blending 5 MUL+4 ADD）。全栈执行例子：MipNeRF-360 一个场景 → 设备接收相机位姿与场景 Gaussian → projection kernel 生成 2D Gaussian（μ, Σ, d, RGB）映射到 16×16 tiles → 排序引擎（GPU 用 Radix sort、加速器用 bitonic 网络）对每 tile Gaussian 按深度排序，tile 间 Gaussian 数 80~10000+（两个数量级波动）→ 光栅化 PE 阵列每个像素一个 PE，独立重算 X/Y 二次项与交叉项（同行/同列像素间大量冗余 MAC）→ 按序 α-blending 输出像素颜色。痛点：(i) α-computation 冗余——每像素 8 MUL+4 ADD，X 轴二次项在同列、Y 轴二次项在同行被重复计算；(ii) 排序 O(N log²N) 与光栅化 O(N) 复杂度异构，且 tile 负载波动两个数量级，固定并行度排序模块在小负载下闲置、大负载下成为瓶颈，pipeline 失衡；(iii) 既有工作 GSCore/MetaSapiens 只减 Gaussian 数不解决光栅化冗余与排序，GBU 靠行序差分/顺序计算减 MAC 但引入像素依赖破坏并行度，Lumina 只适用于移动视角。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法为算法-硬件 co-design，三项设计直接映射 baseline 缺陷：(1) axis-shared rasterization 对应缺陷(i)——把 α 指数分解为 X 二次项/Y 二次项/交叉项，用 16 个 X-PE 与 16 个 Y-PE 线各算一次共享项并广播到 16×16 PE 阵列，每 PE 只需 1 乘法+2 加法合成指数，α-computation 从 8 MUL+4 ADD 降到摊销 2.31 MUL+2.13 ADD/PE、总 MAC 减 38%，且保持像素级全并行；(2) MLP-based OIT 对应缺陷(ii)——用 2 层 10 参数 MLP（输入深度 d_i + 视角 (x,y,z)，视角推理时折入 bias，输出指数激活）直接预测透射率 F(d_i)，把排序整体替换为顺序无关加权合成 C=ΣF(d_i)α_ic_i/ΣF(d_i)α_i，消除排序硬件与 pipeline 失衡；训练仅 ~30min/场景（预训练 checkpoint 初始化、MLP lr=0.005、Gaussian lr×0.01、关闭 cloning/splitting 保稳定），PSNR 仅降 0.3（26.90 vs 27.21），优于 sort-free weight-sum [18] 且加入视角信息（OIT+d+view 26.90 vs OIT+d 26.17），相对 bitonic 排序 21.1~32.4× 加速；(3) 统一可重构 PE 阵列 + fine-grained interleaved pipeline 对应缺陷(ii)的硬件侧——同一 16×16 阵列经 MUX 在光栅化/MLP 模式间切换，复用 MAC 与 EXP 单元（可重构仅 +5% 面积/+6% 功耗），MLP 推理用 subtile 级 interleaved pipeline 与下一 subtile 光栅化重叠，隐藏 memory-bound 的深度装载/推理延迟。全栈执行例子：相机位姿与场景 Gaussian → projection 在 edge GPU 执行（论文把投影延迟/能耗计入端到端）→ 加速器：GS-feature cache（9 参数/GS，28-bit GS ID + 4-bit tile 计数 tag）按 π 轨迹（8×8 tile block 内 Hilbert/格雷码连续轨迹、块间 S 轨迹）调度 tile → depth buffer 供 PE 阵列做 MLP 推理（每周期 256 深度值、256 个 F(d) 写回，与下一 subtile 光栅化重叠）→ 同一阵列切到光栅化模式：X/Y-PE 线算共享项广播，256 PE 每周期处理一个 GS 的 16×16 tile，α-blending 用广播寄存器中的 F(d) 与 RGB 累加分子分母 → 除法阵列归一化输出像素 → 结果：相对 edge GPU 光栅化 4.6~7.9×、端到端 4.0~5.5× 加速、16.2~31.9× 能耗节省，相对 GSCore/MetaSapiens/GBU 1.33~1.88×，以 3.85mm²/1.64W（28nm）把 edge GPU 上仅 ~20 FPS 的场景提升到 150+ FPS 实时渲染。
