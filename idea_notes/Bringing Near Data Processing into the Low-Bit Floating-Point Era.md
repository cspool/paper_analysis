## Bringing Near Data Processing into the Low-Bit Floating-Point Era

- baseline方法是什么？
  - Baseline 是面向低比特 FP 的朴素 NDP 编译策略：把面向 INT 的 NDP 编译流程（operator partition → loop tiling → DRAM mapping → instruction generation，如 OptiPIM/ATiM/UniNDP [42][49][63]）最小化扩展——按 AiM [33] 风格沿输出通道把算子划分到各 PU；scale 与 value 分离、各 QGroup 的 scale 连续密集存储在 DRAM 独立区域（沿用 Cost-Effective [30] 与 Triton [57] 的 GPU 惯例）；SRAM 缓冲按 scale:value 容量比例匹配分配；固定 Order1 循环序、tile 尺寸对齐缓冲。缺陷：① 不同 QConfig（组粒度/精度/量化方式）偏好不同编译策略，同一 QConfig 下策略差距最高 70%（Motivation Fig.4b）；② scale 与 value 分离使计算中频繁在 value 区与 scale 区之间切换 DRAM 行，行切换较粗粒度 INT 增加 2.4~11.6×、延迟 +1.34~4×（scale 相关额外开销 75% 来自行切换、仅 25% 来自 scale 访问本身）；③ 细粒度 QGroup 触发高频高精度 dequant（NVFP4 每 16 个 FP4 元素要乘激活 scale 与权重 scale 各一次），约占执行延迟 35%（W-A 最高 40%），且仅约 10% 的 dequant 天然落在行切换空闲窗口。
  - baseline 全栈执行例子：LLaMA2-7B 解码一个 token 的 MVM（M=1,K=4096,N=4096，W4A4S8）：算法层——group-wise FP4 量化、QGroup(1,16) 每 16 元素配一个 FP8 scale；系统框架层——论文未明确说明（无 serving 框架，离线编译器生成指令、主机经 PCIe 调度）；编译框架层——AiM 式输出通道划分 + 分离 scale 布局 + 比例缓冲分配 + Order1 循环；kernel 调度层——值从 DRAM 流式读出、与缓冲中的驻留操作数在 PU 做 MAC 流水，每消费完一个 DRAM chunk 后 PU 用缓冲 scale 对部分和做高精度 dequant 并写回，dequant 期间 DRAM 空闲（缓冲无 ping-pong 结构）；硬件架构层——GDDR6-AiM 每 bank 一个 PU + 5Kb SRAM，dequant 复用 MAC 单元执行高精度乘法。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = FlexQ-NDP 编译框架，三件套逐一对应 baseline 三缺陷：① QConfig 感知的编译空间裁剪 + 代价模型 DSE——编码划分×缓冲四元组×循环置换×DRAM 映射，两条 guideline（划分对齐 QGroup 防 padding 与跨 PU 指令流发散；缓冲分配随组粒度偏斜），padding 与列利用率裁剪（空间降 4~5×），两阶段解析代价模型（行切换区分自然/缓冲 miss 引发并做重合抵扣）替代逐策略仿真——对应"不同 QConfig 偏好不同策略、空间巨大"缺陷（DSE 3 小时→1 分钟/算子，LLaMA2-7B 10 分钟；W-Only 最优性 99.66%、W-A 95.97%）。② scale-value 交织布局——把多个 QGroup 的 scale 区与 value 区打包成 itBlock 连续排布，交织比/步长按 QConfig 与 loop tiling 自适应（Eq.1–9），scale 区前置、value 按内层循环迭代序存放——对应"scale/value 分离导致频繁行切换"缺陷（行切换降约 2×）。③ 去量化隐藏指令重排——把 dequant 指令前移进 DRAM 行切换/buffer refill 的 48-cycle PU 空闲窗口（dequant 仅 8 cycle），受依赖、partial-sum 缓冲容量、空闲窗口容量三约束（Alg.1 逆序贪心）——对应"dequant 占 35% 延迟且造成 DRAM 空闲"缺陷（消融贡献 ×1.18，W-A 受益最大）。
  - 论文方法全栈执行例子：同一 LLaMA2-7B MVM（W4A4S8, Q1）：算法层——分组 FP4 量化、QGroup(1,16) 配 FP8 scale；运行时激活量化由主机聚合中间结果、跟踪各 QGroup 最大幅度推导 scale，随数据分发到各 DRAM bank，PU 用高内部带宽完成值量化（开销计入端到端）；系统框架层——论文未明确说明；编译框架层——FlexQ-NDP 按 guideline 编码并裁剪编译空间→代价模型选策略→按 Eq.1–9 构造交织 itBlock（scale 前置）并映射逻辑列到物理行列；kernel 调度层——指令生成后对 dequant 做 Alg.1 重排，dequant 移入行切换/缓冲 refill 空闲窗口与值读取、行切换重叠；硬件架构层——多精度 PU（24→4×12→4×6 bit 尾数乘法器分解、L1 FP8/L2 BF16 加法树、单周期 FP32 设计点 0.0185 mm²/8.72 mW @0.4 GHz 14nm）在 GDDR6-AiM 每 bank 上执行 MAC 与 MUL 型 dequant。结果：算子级最高 3.29×、端到端最高 2.73×、相对 FP16 解码最高 15×（7.17× 量化 + 2.09× 编译）、能耗平均降约 1.31×、最高 1.78×。
