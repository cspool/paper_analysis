## DynoPipe: Heterogeneous Edge-Cloud LLM Serving with Dynamically Orchestrated Pipeline Boundaries

- baseline方法是什么？
  - Baseline 为三类边云 LLM 部署范式：(1) Cloud-only（SP=0）：全模型在云端单 GPU 串行执行，单请求最优（LLaMA2-7B 179ms），但高负载下排队爆炸（QPS=5 时排队占 62% 总延迟 295/478ms，单 GPU 容量 ~5.6 rps 在 89% 利用率下对 Poisson 突发敏感）；(2) Edge-only（FlexNN，SP=32）：静态层分配全在边缘，内存墙 + 30% 边缘 GPU 性能降级使容量仅 ~3.9 rps，QPS=5 时平均延迟 4498ms（15.4× 差于 SP=12），LLaMA3.1-8B 下 2-8 QPS 的 TTFT 从 19.68s 恶化到 68.53s、>8 QPS 内存耗尽不可用；(3) 静态边云划分（EdgeShard）：固定 split point 离线优化，但最优 split point 随负载与网络状态在数分钟内漂移（静态 SP=12 在网络争用 QPS=4 下劣化 36%、静态 SP=4 在 QPS=5 下劣化 82%），且状态迁移（KV cache 重建）需数十秒造成服务中断。结构性根因：边云计算（0.48×）、内存（65× 带宽）、通信（80× 带宽 / 10,000× 延迟）三维不对称导致 94% pipeline 空闲、边界 stage 82% 空闲（LLaMA2-70B prefill），同构 pipeline 假设被违反，瓶颈还在边缘节点/边界 stage/网络链路间动态迁移。
  - baseline 全栈执行例子（EdgeShard 静态 SP=12，一个 LLaMA2-7B 请求，QPS=5）：算法层 = transformer 推理被切成边缘 0-12 层 + 云端 13-32 层（残差在块内、切点安全）；系统框架层 = 固定 pipeline 配置，边界 stage 序列化 + 10 Gbps uplink 传激活，无动态调整；编译框架层 = 论文未明确说明；kernel调度层 = 边缘 RTX 3090 与云端 A40 各跑各自层的 GEMM/attention kernel，边缘 attention 因 DRAM 带宽受限延迟放大 2.7×，云端因 pipeline 同步空转，边界 stage 缓冲激活造成内存级联；硬件架构层 = 异构 GPU 直连，无状态预置/重叠。效果：网络争用下 428ms（QPS=4），排队与边界 stage 空闲主导。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 边界感知的动态 pipeline 编排三机制：(1) 边界约束 pipeline 构建（§4.1）——把划分建模为 min max{T_exec+I_boundary·T_boundary}（Eq.1），DP（Eq.2）生成 3-5 个覆盖不同资源 regime 的边界组合（bandwidth/compute/memory-constrained），对应 cloud-only/edge-only 的"单一静态最优"缺陷；残差在块内解析保证跨域只传 resolved hidden state，规避跨域激活语义不一致与额外 buffering；(2) 主动多配置编排（§4.2，LRP Algorithm 1）——遥测驱动 + hysteresis/cooldown 的 O(|K|)（|K|≤5）表查找选边界、决策 sub-ms，对应"最优 split point 动态漂移 + 在线重解 O(n) 超 sub-ms 预算"缺陷；(3) 层次化状态管理（§4.3）——三 tier 状态分解（KV cache/中间激活/元数据）+ 参数重叠缓存 + 差分 KV cache + 带宽感知分区（利用下行富余带宽异步流式）+ <1Gbps recomputation fallback，对应"状态迁移需数十秒重建 cache、迁移成本陷阱"缺陷。缺陷→设计映射：三维异构导致 pipeline 空闲 → 边界 stage 显式建模 T_boundary（序列化/反序列化 + 跨域传输 + 状态同步 + 格式转换）+ 组合化配置覆盖各 regime；资源波动使静态划分失效 → 500ms 遥测 + 组合切换而非重解全局；迁移开销陷阱 → L1/L2/L3 预置 + 差分状态 + 压缩，迁移从秒级到毫秒级（P99 85ms）。
  - 论文方法全栈执行例子（同一 LLaMA2-7B 请求，DynoPipe 动态选 SP，QPS=5 网络自由→争用场景）：算法层 = transformer 按 block 边界切分（SP=12→8 随网络切换），残差在块内解析，跨域只传 resolved hidden state（数值一致性 <10⁻⁶ 相对误差，WikiText-103 perplexity 变化 <0.3%）；系统框架层 = LRP 编排器：500ms 遥测采样带宽/负载/内存 → SelectBoundary 按触发阈值从预计算组合选 SP → hysteresis δ 与 cooldown 防振荡（QPS=5 下 <2 次重配置/min），在线决策基于 <30KB/模型 profiling 查找表（128 token、batch=1/4/8 的 per-layer 时间 + 激活大小）；编译框架层 = 论文未明确说明；kernel调度层 = 边缘 RTX 3090 跑 0-8/12 层（含 embedding，隐私敏感部分留本地）、云端 A40 跑其余层，两侧流水并行（edge 96ms ∥ cloud 112ms），激活经 10 Gbps uplink 传（优先 attention sparsity/quantization 压缩点，图 7）；硬件架构层 = 层次化状态：L1 GPU 热边界缓存（~150MB）预置参数 + L2 host-RAM（~500MB）+ 差分 KV cache 同步（P99 72ms）+ 参数重叠 re-staging（13ms），带宽<1Gbps 时 recomputation fallback（<120ms、计算 +15-25%）。效果：排队从 62% 降到 26%，容量 ~8.9 rps，E2E 292ms；吞吐 10.1× vs edge-only / 1.6× vs cloud-only，TTFT 降 98.9%，MAF 下 P99 较基线降 54-76%。
