## AutoFHE: An Automatic Hardware Generation Framework for Domain-Specific FHE Accelerators

- baseline方法是什么？
  - Baseline 是专家手工设计的领域专用 FHE 加速器：Strix（eNPU，8 个 1D CPE、无 bootstrapping unrolling、141.37 mm² 28nm 1.2 GHz、300 GB/s）、MATCHA（加密逻辑/关系加速器，手工选定 unrolling r=3）、PPGNN（基于 HMUX 的加密图查找引擎），及纯软件 CPU/GPU（Xeon 6148 + TFHE 库、A100 + cuFHE/nuFHE）。手工流程：双领域专家在 RTL 层手工实现复杂 CPE（密文乘法 CMul、FFT/IFFT、分解、external product、key-switching），逐一改写所有涉密信号，再凭经验手工做微架构参数与 CPE 数量的 DSE；高级优化如 bootstrapping unrolling 需手工实现并穷举找有效配置。两大痛点（Barrier ➊➋）：CPE 微架构与 FHE 算法紧耦合，非 FHE 专家无法实现；设计空间爆炸——bootstrapping 单元含 polynomial/FFT/IFFT/decomposition/vector MAC 五个独立参数维度、各约 8 个离散候选 → 至少 8^5≈10^4× 膨胀，手工穷举不可行。
  - baseline 全栈执行例子（DeepCNN100 隐私推理）：算法层：TFHE 方案（programmable bootstrapping 同态评估非线性激活；DeepCNN 网络为 ZAMA 设计，论文不改算法）；系统框架层：无 serving（专用加速器裸机执行；CPU/GPU 经 TFHE/cuFHE/nuFHE 库）；编译框架层：无（手工 RTL，无自动生成流程）；kernel 调度层：论文未明确说明（GPU baseline 用 cuFHE/nuFHE kernel，调度细节未述）；硬件架构层：Strix 8 个 CPE 与逻辑 PE 1:1 绑定（PE 独占 CPE），bootstrapping 串行执行 n 次迭代（无 unrolling），密文经 300 GB/s 接口搬运；随 PE 数扩展面积线性增长（48 PE 超 400 mm² 预算出界），固定 CPE 数与无 unrolling 限制性能。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 加密信号抽象 + FIRRTL 自动识别 + CPE 模板化 + CPE-virtualization + 嵌套 DSE。(1) Secure 注解机制——对应"手工定位改写全部密文信号"缺陷：Chisel 层声明式标注顶层密文输入，SecureAnnotation 走 Chisel 原生注解基础设施（类比 dontTouch）传至 FIRRTL（Target 字符串定位），设计者不改底层硬件。(2) FIRRTL 图 BFS 自动识别——对应"加密意图传播易漏标错标"缺陷：从注解种子自动传播密文标记，算子级/模块级双粒度。(3) CPE 模板库 + 算子-CPE 映射规则——对应"CPE 与 FHE 算法紧耦合、非专家无法实现"缺陷：arithmetic/bootstrapping/key-switching/HMUX 四类预优化模板（bootstrapping 模板内置 unrolling 阵列支持 r 展开，Strix 不支持），bootstrapping 按 TFHE 协议自动置于 arithmetic 下游。(4) CPE-virtualization + GA 调度——对应"1:1 PE-CPE 实例化面积爆炸"与"固定 CPE 数欠优化"缺陷：K 个物理 CPE 时序共享全部逻辑 PE，GA（critical-path-first 初始化、order crossover、swap mutation、tournament selection、依赖校验）在依赖/资源约束下搜最优时空调度（最大化利用率 |V|/(K·(Tmax+1))），离线固化进硬件调度器，48 PE 规模仍满足面积预算。(5) 嵌套 DSE 联合优化 (CPEmicro, K, Sched)——对应"手工穷举设计空间不可行"缺陷：外层硬件参数 + 内层 GA 调度，解析 latency/area/energy 模型快速评估，可切 EDP 目标，自动发现最优 unrolling 因子（Strix 场景 r=2、MATCHA 场景 r=3——带宽不同最优值不同，专家调好的配置无法跨场景迁移）。
  - 论文方法全栈执行例子（同一 DeepCNN100 隐私推理）：算法层：TFHE 同 baseline，bootstrapping unrolling 作为模板参数并入 DSE 自动选优（禁用后性能降 39.5%）；系统框架层：无 serving，生成加速器 = CPE 池 + 硬件调度器，调度离线搜好固化成控制器；编译框架层：Chisel + Secure 注解 → .fir/.anno.json → FIRRTL 自定义 pass 识别加密组件 → 算子映射 CPE 模板 → DAG 抽象 → GA 时空调度 → DSE 选 (16 CPE, r=2, ...) → 生成 RTL（eNPU 全流程 203.5 s vs 手工数月）；kernel 调度层：GA 时空调度等价于硬件内 PE→CPE 的确定性静态调度（替代专家手工映射；vs round-robin +12.9%–31.6%）；硬件架构层：16 个 bootstrapping 单元（vs Strix 8）、unrolling r=2、139.1 mm² 28nm 1 GHz、PE 分时复用 CPE 池。结果：vs Strix 2.6×、vs CPU 86.8×、vs GPU 33.2×；EDP 目标下自动选 24 个 bootstrapping 单元配置、vs Strix EDP 2.9×；MATCHA 场景 1.4× 延迟/1.7× 吞吐；PPGNN 场景 1.6×。
