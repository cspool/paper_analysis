## QED Scalable Consistency Verification of Memory Instruction Reordering in Hardware

- baseline方法是什么？
  - Baseline 是三类先前硬件一致性验证/测试方法：(1) litmus 测试驱动（Intel litmus tests，每个通常 4-8 条访存、2-4 线程；"*check" 系列 PipeCheck/RealityCheck/RTLCheck/CCICheck/TriCheck 等把全部微架构执行交错套到一批测试程序上）——只检测给定测试暴露的 bug，测试未覆盖的 bug 检测不到（测试≠验证）；(2) 穷举最小测试集（[39]，自动合成穷举但最小的测试，跨所有线程共 n 条指令）——实践上 n>7 即爆炸，远小于现代指令窗口（数百条 in-flight）；(3) 无界 SMT/模块化验证（PipeProof——把 happens-before 传递性编码成 SMT，探索越来越长的指令序列、可能需正确性已证明的人工不变量才能终止；Kami——Bluespec 模块化验证），但都只验证 in-order-issue 流水线，无法覆盖乱序处理器的 LSQ 重排/重叠；(4) 动态验证（Meixner-Sorin 重试 load 方案）需额外硬件且新硬件自身也要验证。共同痛点：无法对现代乱序核的访存指令重排做无界、完整、可扩展的验证。
  - Baseline 全栈执行例子（一条访存指令走 BOOMv3 LSQ 的验证路径）：算法pipeline：论文未明确说明（非 ML/推理论文）；系统框架：论文未明确说明（无 serving/运行时框架）；编译框架：论文未明确说明（不涉及编译框架；Kami 用 Bluespec 写硬件规格属验证输入而非编译框架）；kernel调度：论文未明确说明（无软件 kernel 调度；litmus 测试由 diy 工具生成并跑在硬件/模拟器上，非 kernel 调度）；硬件架构：litmus 测试在目标系统上以特定交错执行 4-8 条访存（如两线程 st A; ld B），检查是否出现禁止结果——未覆盖的交错（如缺失某个 invalidation 到达时机）即漏检；穷举测试把 n 条指令的所有交错全试（n=7 已是实践极限），对 128-entry LSQ 的 in-flight 组合 n! 完全不可行；PipeProof 把更长指令序列编成 SMT 需人工不变量且只对 in-order 流水线成立；芯片设计：论文未明确说明。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 = QED，核心是 two+two 可扩展性结果 + 环检测 + 谓词决策树 + JasperGold 无界 RTL 验证 + FSM fast-forwarding 状态缩减。逐点对应解决 baseline 缺陷：
    1. two+two 之"直接序对定理"（Theorem 1，传递归约）↔ 穷举全部指令交错/长指令序列爆炸：由 MCM 序的传递性，任何违反必落在直接序对之间，只需按指令类型对枚举（O(m²e²) 棵树，m≤5、e<10），谓词数与程序长度、in-flight 指令数无关——把 n! 降到常数级，从"要验证几百条 in-flight 指令"变为"验证所有类型对"；
    2. two+two 之"多事件定理 + 传递折叠引理"（Theorem 2）↔ 核心数/事件数爆炸：每指令只需考虑一个相关外部事件、且只在乎事件间的排序不在乎来源核心（实现本就不看 invalidation 来源），多线程传递路径可折叠为单边且不丢环——谓词数与核心数无关，把"任意多核任意代码"变成"枚举事件排序"；
    3. 环检测（cycle detection）↔ litmus 测试只查特定例子：对探索树所有叶 trace 穷举查环，自动发现反例（图 9 红色违反 trace），与 litmus 的"检查具体例子"形成根本反转（图 5(a) 蕴含存在某个合法对抗样例，而非反之）；
    4. 谓词决策树 + SVA + JasperGold 无界验证 ↔ 有界（≤7 指令）或 in-order-only：谓词是简单二值问题（重排？squash？命中？），翻译成 cover/assert/assume SVA，JasperGold 对 RTL 全部可达状态无界证明，覆盖乱序 LSQ 而非仅 in-order 流水线；shadow logic 辅助（综合时 elided），backward-slicing 剪掉 83% 无关输入；
    5. FSM fast-forwarding（自身被断言验证）↔ RTL 状态空间爆炸（7^N 状态）：验证某直接序对时把其余 load/store 条目直接快进到终态 observed，利用 valid 条目形成连续前缀、invalid 形成连续后缀的自然结构（连续分配 + squash 作废后续）使可达状态可数，并对"FSM 仅含合法迁移、条目间无直接影响"加断言保证缩减正确——无界验证在 128ld/64st 的实用尺寸下 10 天内完成。
