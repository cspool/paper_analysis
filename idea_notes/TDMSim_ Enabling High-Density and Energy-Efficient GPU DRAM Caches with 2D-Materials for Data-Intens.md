## TDMSim: Enabling High-Density and Energy-Efficient GPU DRAM Caches with 2D-Materials for Data-Intensive Applications

- baseline方法是什么？
  - Baseline 是三类 GPU LLC 方案：(1) 6T-SRAM LLC（NVIDIA H100 50MB L2、AMD MI300X 256MB Infinity Cache 等商用主流）——访问延迟低、带宽高，但 cell 面积大导致容量扩展性差，增大容量时面积/静态功耗/延迟同时恶化；(2) Silicon-1T1C DRAM cache（Intel Sapphire Rapids、Loh & Hill 的 die-stacked DRAM cache 研究线、LH-cache 组织）——密度高，但必须有周期 refresh（JEDEC DDR4 64ms 周期），refresh 造成额外能耗与访问干扰（请求映射到正在刷新的 bank 而无法服务），容量增大时 refresh 开销随 cell 数量与互连 RC 恶化（512MB 时静态功率约 2~3× SRAM baseline），且 refresh 周期只能按最弱 cell 保守设置；(3) 更先进的硅 DRAM cache 技术（TDRAM [63] in-DRAM tag 探测、NDC [35] 子阵列内原生 cache、BEAR [64] 带宽优化）——优化 tag/数据组织与 cache 管理，但都受制于硅 DRAM 的泄漏/刷新本质。更根本的 barrier：2D-material DRAM 的评估缺乏跨层仿真工具——HSPICE+2DFETs 只到 device/cell、CACTI/NVSim/DESTINY 只到 cell/array 且不含 2D 材料特性、NVMExplorer 无 device 层、gem5 只支持无刷新 cache，各层割裂导致器件 retention/peripheral/controller 交互只能靠简化解析估计。
  - baseline 全栈执行例子（GPU 上处理一个数据密集型请求，如 KMeans 1e6×10d 点或 Llama decode token，经 32MB SRAM LLC 或 Si-1T1C DRAM cache）：① 算法pipeline——KMeans 聚类中心与数据点、Llama 权重与 KV cache 是数据密集型访存流，容量越大命中率越高（32MB→256MB 时 KMeans 2.46×、Llama 1.8×），但 baseline 容量受密度约束；② 系统框架——论文未明确说明（通用 GPU 驱动/运行时，无 serving 框架）；③ 编译框架——论文未明确说明（无编译器改动，KMeans/Llama/图分析 kernel 为通用 CUDA/HIP 编译）；④ kernel 调度——GPU kernel 发起的 LLC 访问按 LH-cache 组织（16-way、16 bank、单 DRAM row 一组）映射，tag 访问需先 activate+read 整行到 row buffer；Si-1T1C 中命中时若 bank 正在 refresh 则该请求被阻塞（access interference），造成平均访存延迟升高与性能回退，刷新 64ms 周期下 512MB 阵列 RC 寄生高、刷新功耗大；⑤ 硬件架构——32MB 6T-SRAM LLC（30nm、CGP 与 2D tape-out 匹配、treePLRU、200 cycles）或 Si-1T1C DRAM cache（64ms 刷新）：SRAM 扩展容量面积爆炸（256MB/512MB 不现实），Si-1T1C 提供 4× 容量但在多个 workload 上因刷新干扰反而降速、总能耗约 2×（刷新+静态主导），两者都达不到"高密度+高能效"的理想交点。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 = TDMSim 跨层仿真工具包（TDM-Transistor + TDM-Memory，打通 device→circuit→system）+ 2D-material DRAM cache 系统集成 + retention-aware 刷新策略。核心洞察：2D 材料（MoS2 等）原子级厚度与超低泄漏（off-current ~10^-17 A/μm）带来更长 retention 与更高集成密度，使 1T1C/3T0C DRAM cell 在 SRAM 等面积下做到 128MB-512MB 且 refresh 极少（2D-1T1C 0.5s 周期、约 20× 实测最小 retention 裕量，而硅需 64ms）；同时实测发现 2D 阵列存在径向 retention 梯度（边缘 cell retention 短至 10s、内部长至 700s，多数 >30s），据此设计 retention-aware policy：refresh scheduling（边缘行 0.5s、中心行延长到 1.5s，边缘弱 tier 合并为只存 clean block 的 clean ways，配合每行 validity counter 防 retention 违例，Murphi 形式化验证）对应解决"保守统一刷新周期浪费头部空间与刷新干扰"；cyclic replacement（把行最左/最右弱 tier 环接合并成单一 cyclic way、tag 严格映射到非循环 way）对应解决"边缘 tier 预留 clean ways 的空间开销"；hot-page remapping（Index Location Judge + PHT 表 + Range Scalar 把 hot page 从高刷新 HighRef sets 动态重映射到低刷新 LowRef sets，PHT 计数器每 10K 次访问减半老化、升迁时失效旧映射保一致）对应解决"热数据驻留高刷新区域导致的刷新停顿"。2D 材料收益与 TDRAM/NDC/BEAR 正交可叠加（与 TDRAM 结合再 +5% 性能、-15.6% 能耗）。
  - 论文方法全栈执行例子（同一 KMeans/Llama 数据流经 2D-1T1C 128MB DRAM cache + retention-aware policy）：① 算法pipeline——LLC 容量从 32MB 提到 128MB，KMeans 全部聚类中心与数据点、Llama 部分权重与 KV cache 可驻留，命中率提升直接反映为 speedup（2D 1T1C 128 平均 28.8%）；② 系统框架——论文未明确说明（gem5 MI300X 模型在 OS 下运行 workload，无 serving 框架）；③ 编译框架——论文未明确说明（workload 为既有 Pannotia/Rodinia/AMDSDK/Llama/MLPerf 应用直接运行）；④ kernel 调度——kernel 访存经 MI300X 内存层级（L1 32KiB→L2 4MiB→2D-DRAM LLC）按 LH-cache 组织映射到 16 bank；内存控制器发 activate+read 载整行入 row buffer，命中保留 row buffer；retention-aware 控制器按行位置选刷新周期（边缘 0.5s、中心 1.5s），clean ways 只放指令/预取数据（无需 snoop/写回），hot-page remapping 单元（四阶段流水线 RTL、Index Location Judge 判 HighRef 集、PHT 查热度、Range Scalar 计算重映射 set index）把热页移出高刷新区，刷新停顿大幅减少（访问干扰率 -75.6%、refresh energy -65.4%）；⑤ 硬件架构——128MB 2D-1T1C DRAM cache（30nm 外围电路、面积与 32MB SRAM 相当）：静态功率仅为 SRAM 同容量约 30.6%、动态能量低于 SRAM 直到 256MB，gem5 统计访问/刷新事件结合 TDMSim 参数输出能耗；最终相对 32MB SRAM baseline：性能 +42.1%、总能耗 -79.4%，相对同容量 Si-1T1C：性能 +25.4%、能耗 -42.7%。
