## P3-LLM An Integrated NPU-PIM Accelerator for Edge LLM Inference Using Hybrid Numerical Formats

- baseline方法是什么？
  - Baseline 分算法与硬件两侧：(1) 算法侧——weight-activation 量化 SoTA：QuaRot/QoQ 用标准整数格式 + Hadamard 变换/校准数据集（Wikitext-2、Pile）离线近似激活动态，对 C4 等未见数据集过拟合（QoQ 用 Pile 校准在 Wikitext-2/C4 上 key-cache 量化误差最高）；KV-cache-only 的 Oaken 靠离线校准确定 key outlier 阈值、保留 ~10% outlier 高精度，有效精度高达 4.8 bit 但压缩有限；MANT 用自适应数值类型但无 outlier 处理、精度掉、且分解乘法需昂贵高位宽加法器；Ecco 用 k-means codebook + Huffman 编码需要复杂在线解压回 FP16 计算，硬件开销大、无法直接用于低精度 PCU。(2) 硬件侧——HBM-PIM [49] 用 16-way SIMD FP16 MAC PCU（AiM 用 BF16 adder-tree），DRAM 工艺晶体管密度比逻辑低 ~10×，高精度 PCU 面积功耗大（DRAM die 面积 20-27%），限制计算吞吐，仅对早期 MHA 且 batch=1 有效；Pimba 用 8-bit microscaling 改善面积但只量化 KV-cache（线性层保持 FP16）、FP32 累加流水限制效率。全栈执行例子（HBM-PIM 跑 Llama-3.1-8B 低 batch decode）：token → 权重/KV 以 FP16 存 DRAM，PCU 每 tCCD_L 读 256-bit（16 个 FP16 权重）做 1×1×16 GEMV → 每 decode 迭代线性层与 attention 全是 FP16 内存密集 GEMV，PCU 只有 16 个 FP16 乘法器、面积受限无法扩展 → GQA（group 4）数据复用 NPU 才能利用、PIM 用不上 → batch≥4 或 GQA 下 HBM-PIM 相对 NPU 优势消失（roofline：HBM-PIM 峰值吞吐低 4× 带宽优势被 compute 卡死）；attention-score 保持 FP16 时 P·V 只能回 NPU 用 FP16 单元。Serving 调度层、编译框架层：论文未明确说明。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法：算法-硬件 co-design 的 W4A8KV4P8 + 低精度 PCU。算法侧逐操作数定制数值格式，直接对应 baseline 缺陷：(a) KV-cache outlier → dynamic input-aware smoothing（无校准数据集，prefilling 按通道绝对最大值计算平滑因子、decoding 复用，内存开销 <1%、运行时 <2% TTFT），配合 per-head INT4-Asym（128 元素共享 16-bit scale + 4-bit zero-point，有效 4.16 bit，比 Oaken 4.8 bit 更低却更准）；(b) 整数格式不匹配激活/注意力分布 → 激活用 FP8-E4M3 per-token（宽数值范围容纳 outlier，无需 Hadamard 在线开销/平滑迁移难度到权重）、attention-score 用无符号 FP8-S0E4M4（softmax 后 [0,1] 无需符号位、4-bit exponent bias −15 足够覆盖 [−14,−1]、省下 4-bit 给 mantissa，near-lossless）；(c) 权重 4-bit → BitMoD 格式（负零编码重映射为 {±5,±8} 特殊值，group 128，比 INT4 更准）。硬件侧对应 PIM 面积/吞吐缺陷：(d) 低精度 6-bit 定点乘法器（5-bit 尾数含隐藏位 + 符号位）替换 FP16 乘法器，去指数对齐模块，每 PCU 64 个乘法器（4× HBM-PIM），HBM 面积开销仅 17.5%（vs HBM-PIM 16.4%，总逻辑占比 <25% 上限）；(e) TEP——低精度 PCU 面积小 → 频率 2×（tCCD_S vs tCCD_L）→ 同一权重切片被两个输入 temporal 复用，吞吐再 2×，总 roofline 相对 HBM-PIM 8×；(f) 8-bit attention-score 使 self-attention（Q·K^T、P·V）全模块可上低精度 PCU，避免 value cache 搬回 NPU；(g) operator fusion 把 SSF 融进 query、S^V/S^V_max 融进 attention-score、线性层 dequant 后置，最小化 NPU 上高精度 dequant 开销；(h) pre/post-RoPE 感知映射：短序列模型（Llama-1/2）pre-RoPE 量化 key 缺位置信息 → Q·K^T 留 NPU + 在线 RoPE；长序列模型（Llama-3/Mistral）post-RoPE 量化 → Q·K^T 上 PIM。全栈执行例子（同一次 Llama-3.1-8B batch=2 decode）：请求 token → 权重 BitMoD 4-bit 索引 + KV INT4-Asym（平滑后）存 DRAM → 线性层 GEMV 在 PCU：256-bit 读 64 个 4-bit 权重、4 个 8-bit FP8-E4M3 query 输入、TEP 在 tCCD_S 窗口内复用权重处理 batch 内两个输入 → 结果回 NPU 做 RoPE/Softmax（FP16）→ query 融合 SSF 后 FP8 量化 → Q·K^T 上 PCU（post-RoPE 直接乘）→ softmax 分数截 FP8-S0E4M4、融合 S^V/S^V_max → P·V 在 PCU（value cache 按 head INT4 读出、temporal 复用）→ 乘回 S^V_max → W_O 线性层（PCU）→ dequant 后置 → 下一层。效果：平均 4.9×/2.0×/3.4× 相对 HBM-PIM/Ecco/Pimba，7.8× 相对 NPU，energy 6.3×/3.5×/2.1×，PPL loss 0.25（Wiki）/0.31（C4），reasoning 准确率比 QuaRot/QoQ 高 2.57%/3.05%，内存降 3.7×。
