## IroKnight: Ownership-Preserving Neural Acceleration for Inference Serving

- baseline方法是什么？
  - baseline 有两类所有权保持方案：(1) FHE（Fully Homomorphic Encryption）NPU——直接在加密数据上做 ALU 运算（如 F1/CraterLake/SHARP [6]-[13] 等专用加速器），理论上保证加密所有权，但每次乘加都产生噪声、需反复 bootstrapping，且权重需以明文多项式形式存储（密文化更贵），非线性算子（softmax/layernorm/ReLU）只能近似；LLM 规模下运行时开销 713×–1793×、能量 871×–7396×（表 III/IV），单个 Llama3-70B query 需 10.9 小时/0.59 kWh；(2) TEE（NPU 版，如 TNPU/MGX/sNPU [48]-[51], [119]）——片外加密、片上明文，靠 enclave 假设 + scratchpad 清除来保护，但明文驻留在片上存储（register/cache/buffer/SRAM），不保有所有权，且 NPU 是纯软件管理（host CPU/驱动/运行时），Samsung/Qualcomm/Huawei/AMD NPU 驱动漏洞可任意代码执行泄漏明文 [52]-[63]；GPU/NPU TEE 的 scratchpad 清除（tile/layer 级）还需每次计算后清空，layer 级清除甚至违反 SLO（19.6% 运行时开销）。
  - baseline 全栈执行例子（FHE NPU 处理一个 MoE 层 softmax 之前的 QK^T MatMul，token 走完一整个数据路径）：算法层 = 密文多项式表示：权重为明文多项式、激活为密文多项式，MatMul 变为多项式乘/累加，softmax 用近似多项式逼近；系统框架层 = 论文未明确说明（FHE serving 无成熟框架，需把模型整体转为 FHE 程序）；编译框架层 = 类 CHET 的 FHE 编译器做多项式运算调度与噪声管理（bootstrapping 插入点），权重密文化则额外翻倍开销；kernel调度层 = FHE 加速器专用功能单元执行 NTT/多项式乘法/KeySwitch，每若干层乘法后插入 bootstrapping（占绝大部分延迟），权重从 180MB 片上 SRAM/片外反复搬运（明文多项式，但尺寸巨大）；硬件架构层 = FHE NPU：每个 ALU 直接在密文多项式上做同态运算，中间密文全存片上/片外、无明文暴露但噪声随运算增长，靠 bootstrapping 刷新。结果：单个 query 数小时、能量 0.6 kWh 量级。TEE 路径：数据在片外加密、进 enclave 时解密成明文驻留片上存储，计算后需 scratchpad 清除防泄漏，但微架构攻击（cache/寄存器/SRAM 侧信道）与软件漏洞仍能取走明文，且所有权不成立。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - IroKnight = 一个新 NPU 设计点：明文只在 ALU 内部线网/组合门中短暂存在（纳秒级），所有片上存储（pipe-register、buffer、SRAM）与片外保持 AES-GCM 加密 + 完整性保护。两个域特定洞察把加密/认证开销摊平：(a) 洞察 1——LLM 细粒度 tiled/vectored 算子（MatMul tile、SIMD 仿射 walk、vector reduction）访问模式规则、地址可编译期确定，因此 pad（= f(key, 地址, 版本号)，与数据无关）可在独立的流水化 PadGen 里提前生成，加解密退化为同周期 XOR，PadGen 流水线填充延迟之外零额外延迟；(b) 洞察 2——AES-GCM 认证的 ⟨Galois-Field 乘, XOR 累加⟩ 与 GEMM 的 MACC 流同构，于是把认证做成旁挂的镜像数据路径（脉动阵列中权重在写 WBUF 时认证、输入激活在首列 PE、输出激活在末行 PE；向量引擎每个写子bank 的字都过 ⟨GF-multiply, XOR⟩ 累加 hash），hash 与 MACC 并行、仅多出 hash 的片外读写流量。TCB 只含 ALU + 片上 key/pad 生成电路；端到端 serving 用非对称 RSA 私密通道分发 AES-GCM 计算 key（Model Provider/Data Owner 各自独立 key）、轻量 in-order CPU 做逐芯片 attestation、芯片间建立 RSA 私密通道交换 AES-GCM key 支持多 NPU 协同、计算 key 物理上不可从 PadGens 读出（首列重加密、key 直接写入无观测路径）。
  - 对应解决 Baseline 缺陷：(1) 解决 FHE 的"在加密数据上做 ALU 运算"巨大开销（1110× 运行时 / 2872× 能量量级）——IroKnight 在明文上做 ALU 运算但明文不落地任何存储（仅组合逻辑内瞬态），把加密成本降为 pad 预计算 + XOR（0.2% 运行时、LLM 能量 ≤14%，认证后 3.3% / ≤18%），同时所有权保证接近 FHE（存储全加密）；(2) 解决 TEE 的"片上明文不保有所有权 + 软件攻击面"——IroKnight 明文从不驻留片上存储，即使 NPU 软件栈被攻破、片上 buffer/SRAM 被读也只拿到密文，且认证路径在每写入时校验、篡改即报警，无需 scratchpad 清除、不违反 SLO；(3) 解决通用 ALU-only 解密方案（EDAP/Sequestered Encryption/Mojo-V）需要明文缓存/寄存器驻留或降频的问题——利用 LLM 特有的 tile/vector 规则访问做到无明文缓存的同周期加解密、关键路径保持 SRAM 读、不降频。
  - 论文方法全栈执行例子（一个 MoE 层的 QK^T MatMul tile + softmax，用户 query 的一次 token 数据路径）：算法层 = Fully-State Encrypted 计算范式：所有矩阵/向量/中间结果（Q、K^T、attention 输出 O、路由权重 W）在所有存储中保持密文（widetilde 记法），每个输出元素按 R_{i,j} = Σ_k ((Õ_{i,k}⊕Pad^O_{i,k})·(W̃_{k,j}⊕Pad^W_{k,j})) ⊕ Pad^R_{i,j} 计算——明文只在乘累加瞬间出现于 ALU 组合逻辑；系统框架层 = DeepSpeed tensor-parallel/expert-parallel 把模型分发到多 NPU，芯片间先 attestation、再经 RSA 私密通道交换 AES-GCM key，加密中间数据跨片流动；KV cache（加密的 K^T/V）复用、投机解码（draft token 索引的等值比较为规则仿射访问）、token pruning（Top-K 顺序扫描）均保持规则性、无需特殊处理；编译框架层 = 神经编译器功能不变（tiling/fusion 照旧），仅额外用访问模式知识提供 tile 基址/stride/offset 与版本号给 PadGen 预计算；kernel调度层 = 脉动阵列 kernel：Run-Ahead Index Generator 提前出地址喂流水化 PadGen（128-bit/cycle，16 个 8-bit PE 共享一个）与 Run-Ahead FIFO（深度=PadGen 流水级数），PE 内 MACC 输入输出各一行 XOR；向量引擎 kernel：Run-Ahead Address Generator 提前出源/目的地址，3 个 PadGen 服务 4 组 memory-ALU 对；认证 kernel 路径与 MACC 并行（权重写 WBUF 即认证、输入首列 PE、输出末行 PE、向量引擎每写一 bank 过 ⟨GF-multiply, XOR⟩）；硬件架构层 = 128×128 脉动阵列 + 128-lane 向量引擎的 IroKnight NPU（1 GHz、18MB scratchpad、16GB HBM 1TB/s、INT8），明文纳秒级闪烁于 MACC/Galois-Field 组合逻辑内，所有 pipe-register/buffer/SRAM/HBM 与片间链路均为密文 + hash，面积/TDP 加密 1.79×/1.76×、认证 1.95×/2.18×，关键路径仍为 SRAM 读、不降频。结果：LLM 端到端运行时加密 0.2% / 认证 3.3%、能量 ≤14% / ≤18%，对比 FHE（713×–1793× 运行时、871×–7396× 能量）与 NPU TEE（清除式 19.6% 且不保有所有权），确立了"近 FHE 级所有权、近明文性能"的新设计点；芯片设计层——论文未明确说明（无 chiplet/Wafer-Scale/DRAM 结构优化）。
