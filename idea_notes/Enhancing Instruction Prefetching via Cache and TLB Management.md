## Enhancing Instruction Prefetching via Cache and TLB Management

- baseline方法是什么？
  - Baseline 为前端 L1I 预取（EPI / Barça / FNL+MMA 三种 SOTA 方案，均启用跨页预取）+ 标准 TLB/缓存管理（iTLB/sTLB 按 LRU 管理，L2C 按 LRU/SRRIP 类替换，sTLB 翻译全部走页表走查）。L1I 预取器在虚拟地址域工作（L1I 是 VIPT 结构），预测未来指令块；允许跨页的预取请求命中 iTLB/sTLB 之外的翻译时触发页表走查。两个痛点：①L1I 跨页预取的翻译延迟——翻译未命中 sTLB 时，预取请求必须等待 4 级 radix tree 页表走查（长延迟）才能获得物理地址并发出预取，走查延迟拖垮预取的及时性，抵消跨页预取的收益；同时由 L1I 预取取回的翻译若直接塞进 sTLB 会污染 TLB（挤占 demand 数据/指令翻译条目）；②L2C 对预取代码行管理低效——L1I 预取取回的代码行复用行为高度可变：大量行 dead-on-arrival（一次未用即被淘汰）、部分行有限复用、极少数行服务大量 demand 访问；标准 LRU/SRRIP 与 set-dueling 等策略无法预判这种可变复用，导致预取行在 L2C 中污染（死行占用容量挤出有用行）或过早淘汰（高复用行被提前逐出）。
  - baseline 全栈执行例子（EPI 预取器，一个跨页预取请求）：模型推理算法层 = 论文未明确说明（server workload 执行，非模型推理）；系统框架层 = 论文未明确说明（纯微架构研究，无 Serving/OS 框架修改）；编译框架层 = 论文未明确说明；kernel调度层 = 论文未明确说明（无 kernel，硬件前端自动预取）；硬件架构层 = 核心 fetch 阶段 L1I miss → EPI 在虚拟地址域预测下一指令块（跨页）→ 预取请求查 iTLB（miss）→ 查 sTLB（1536 项 12-way，miss）→ 触发页表走查（4 级 radix tree + MMU PSC，~100+ cycle）→ 翻译返回后才发出 L1I 预取访问 → 取回代码行按 SRRIP/LRU 插入 L2C（1MB 16-way）→ 多数行 dead-on-arrival 占用 L2C 直到被逐出。结果：跨页预取翻译延迟使预取及时性受损；L2C 被死代码行污染，EPI 仅发挥部分收益。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = IP-CaT，两个协同模块逐一对应两个缺陷：①tPB（对应"跨页预取翻译延迟 + sTLB 污染"）——在 sTLB 旁增设 64 项小容量 tPB，专门收纳由 L1I 跨页预取触发的页表走查结果（cb bit 标识翻译请求来源）；L1I 预取 miss 在 iTLB/sTLB 后先查 tPB，命中即把翻译按 sTLB 插入策略移入 sTLB 并失效 tPB 条目，避免重复页表走查；demand 指令访问 miss 在 sTLB 后也查 tPB，命中同样移入 sTLB，从而用 tPB 的预取翻译直接服务 demand miss（sTLB MPKI 降 31.6%）；预取走查结果只进 iTLB+tPB、不进 sTLB，避免 TLB 污染。②TIPRP（对应"L2C 预取代码行可变复用、死行污染"）——决策树 L2C 替换策略，针对 L1I 预取行在三个 RRPV 基策略间动态切换：PIP（eviction 时保护预取行）、NPIP（插入时置 LRU 底部）、BIP（插入时完全 bypass 不占 L2C）；两个饱和计数器 PSEL1/PSEL2 + Leader/Follower Sets 两级决策树在运行期按 pb（prefetch bit）不对称训练事件（L2C hit/eviction）选择当前阶段最优策略，比 set-dueling 的单计数器更细粒度；只对预取行做差异化管理（demand 指令行仍走 SRRIP），避免破坏 demand 行的复用模式（IP-CaT D+P 消融显示对 demand 行也应用 TIPRP 反而 -10.1%）。协同：tPB 减少页表走查 → 降低 L2C 争用 → TIPRP 更有效（IP-CaT 6.1% > tPB 2.9% + TIPRP 2.9% 之和 5.8%）。
  - 论文方法全栈执行例子（同一 EPI 跨页预取请求 + IP-CaT）：模型推理算法层 = 论文未明确说明；系统框架层 = 论文未明确说明；编译框架层 = 论文未明确说明；kernel调度层 = 论文未明确说明；硬件架构层 = 核心 fetch 阶段 L1I miss → EPI 虚拟地址域预测跨页指令块 → 预取请求查 iTLB（miss）→ 查 sTLB（miss）→ 查 tPB：①命中 → 翻译按 sTLB 插入策略写入 sTLB、tPB 条目失效（免页表走查）→ 立即发出 L1I 预取；②tPB miss → 页表走查 → cb=1 的翻译结果写入 iTLB + tPB（不进 sTLB）→ 预取代码行取回后按 TIPRP 决策树进入 L2C：若 Follower Set 且 PSEL1<T1、PSEL2≥T2 选 NPIP（置 RRPV=3 底部，易被淘汰），PSEL2<T2 选 BIP（不插入直接绕过 L2C），PIP Leader 或 PSEL1≥T1 选 PIP（eviction 时优先逐出非预取行保护预取行）；随后 demand L2C hit/eviction 按 pb 不对称更新 PSEL1/PSEL2 驱动策略随程序阶段切换。效果：IP-CaT+EPI geomean +6.1%（Barça +8.3%、FNL+MMA +7.9%），超 CHiRP/Morrigan/Emissary/SHiP++/Mockingjay 等全部对比策略，接近"理想 TLB+缓存协同"上界。
