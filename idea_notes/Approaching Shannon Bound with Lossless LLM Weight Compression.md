## Approaching Shannon Bound with Lossless LLM Weight Compression

- baseline方法是什么？
  - Baseline 一：未压缩 LLM 推理（SGLang + CUTLASS GEMM）——权重以名义位宽（bf16 等）常驻显存，GPU 内存容量决定最大可部署模型与 batch size；GEMM 沿 M 维推进时每 M_t tile 都要从 HBM 重载整个 W tile（全局流量 V_B^(uncompressed) = (M/M_t)·K·N），内存容量瓶颈限制 batch、吞吐受限。
  - Baseline 二：SOTA 无损压缩方案 NeuZip / DFloat11 / ZipNN——层粒度 decompress-store-compute：先整层解压写回全局内存再跑 GEMM，产生层间同步屏障、额外解压显存、冗余全局内存流量且无法与计算重叠；且面向 FP16/BF16 设计，不支持 int8/fp4/awq4/sq8 等现代格式。KTransformer 在 OOM 时把权重放 CPU、经 PCIe 流式传输（带宽瓶颈）；nvCOMP 只暴露 host 驱动的粗粒度 API，无法从 kernel 内部触发解压或与 GEMM 融合。
  - baseline 全栈执行例子（一个 decode step 的 QKV 投影）：请求 → SGLang 调度组批（batch 受显存约束）→ CUTLASS GEMM：SM 沿 M 维循环、每 M_t 块从 HBM 重读 K×N 权重 tile（未压缩、消耗全带宽）→ tensor core 计算；NeuZip 路径：调度 → 先整层解压写回全局内存（解压延迟 + 冗余流量 + 层同步屏障）→ GEMM 再读解压后权重（无重叠）→ 激活/输出。算法层：无损熵编码（NeuZip/DFloat11 针对 FP 格式，非 FP 格式无支持）；系统框架层：SGLang（默认 CUTLASS 后端）；编译框架层：论文未明确说明；kernel 调度层：分离的解压 kernel + GEMM kernel（两次全局内存穿越）；硬件架构层：NVIDIA A100/H200 GPU（无硬件修改）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 信息论驱动 + tile 对齐 ANS 无损压缩 + on-the-fly 融合解压 GEMM。(1) 熵分析定上限（对应"名义位宽虚高"）：逐层实测 Shannon 熵发现 bf16 实熵仅 10–12 bits、int4 仅 0.6–1.0 bits，且该冗余跨 bf16/fp8/int8/fp4/int4/sq8/awq4 全格式成立（对应 NeuZip/DFloat11 只覆盖 FP 的缺陷——rANS 对任意符号表通用）；(2) tile-addressable ANS 编码（对应"熵编码流不可随机访问"）：离线按 GEMM tile 几何切分、每 tile 独立初始状态独立编码、层共享 codebook + 4B/tile offset 表——rANS 是唯一同时满足"近 Shannon 码率（>99%）、tile 级随机访问、GPU 并行解码"三点的编解码族（Table I：字典式/LZ77 不可随机访问、算术编码串行仅几 GB/s、Huffman 离熵界远）；(3) 融合执行（对应"decompress-store-compute"缺陷）：解码直接写 shared memory（不落全局内存），解码 warp（整数/LSU 管线）与 GEMM warp（tensor pipeline）在物理分立管线上 co-issue，双缓冲 + 原子标志 + 四阶段 ring buffer 重叠——对应层粒度同步屏障与冗余流量，V_B^(on-the-fly) = (M/M_t + α − 1)·K·N 且每个权重只取一次压缩形式；(4) 系统集成（对应"压缩停留在存储优化"）：SGLang 投影算子替换 + EP 多卡，权重 footprint 缩小直接放大 batch 上限——对应内存容量瓶颈（Qwen-14B batch 47→60/75、Mixtral-176B 20→95）。
  - 论文方法全栈执行例子（同一 decode step）：请求 → SGLang 调度（权重 27.5→18.1 GB，释放显存给 KV-cache，batch 上限提高）→ ANS GEMM 后端：层开始 warp 0 把 codebook 拷入 shared memory T̃ → 每 tile 循环：warp 0 按 offset 表取压缩 substream、各 lane 独立 rANS（x←s mod R → 查 T̃ → 写 shared memory swizzle 布局 → s←f·⌊s/R⌋+(x−c) → 阈值重归一化 coalesced 补位）与 warp 1..W 的 tensor-core GemmTile 经 ready 原子标志双缓冲交替 → C 累加输出；无层间屏障、无解压权重落全局内存、解码与矩阵乘同 SM 重叠。算法层：rANS 无损熵编码（bit-exact，与量化/剪枝正交叠加）；系统框架层：SGLang 修改（dense GEMM 后端替换 + EP）；编译框架层：论文未明确说明（plugin 式 kernel 手工集成于 CUTLASS，无自动 kernel 生成/编译改造）；kernel 调度层：fused 解压-GEMM 微内核 + warp 生产者/消费者调度 + tile swizzle 确定性驱逐 + 双缓冲管线；硬件架构层：A100/H200 的 SM shared memory / tensor core / LSU 管线利用（无硬件修改）。结果：ANS 与 Shannon 界差 0.01–0.1 bits/weight；Qwen-14B 吞吐 1.1–1.2×、Mixtral-176B 1.6×；vs NeuZip 最高 ~10×、vs DFloat11 ~6–7×（摘要称最高 11×）；A100 大 batch 接近 CUTLASS、H200 最高 1.2× 超 CUTLASS；vs KTransformer prefill 7.7× / decode 18.1×；元数据开销 0.015%–0.108%。
