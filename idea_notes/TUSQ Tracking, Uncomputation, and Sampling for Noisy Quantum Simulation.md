## TUSQ Tracking, Uncomputation, and Sampling for Noisy Quantum Simulation

- baseline方法是什么？
  - Baseline 分三类：(1) 朴素 noisy SVS（Qiskit 2.1.0 / CUDA-Q 0.11.0，后端 cuStateVec v1.12.0）——对每个 shot 的电路实例顺序做完整 SVS，S 个 shot 就要 S 次完整矩阵向量乘，计算开销 O(S·|E|·h)，时间随电路规模/噪声门数/shot 数急剧膨胀，且不消除任何冗余；(2) 缓存/记忆化方案（TQSim，Wang et al. ISCA 2025）——BFS + memoization，把中间 statevector 缓存到内存复用，但速度依赖可用内存（30-qubit statevector ≈8GB，40GB GPU 最多缓存 5 个），内存饱和时必然损失 fidelity，且用统计方法找速度-保真度折中点、无中间表示；(3) DMS（density matrix simulation）——一次电路执行即可模拟噪声，但内存 O(2^2n) 呈平方增长，El Capitan 级超算也只能 25 qubit，不可扩展。
  - baseline 全栈执行例子（模拟一个 30-qubit noisy circuit、10^6 shots 的 Adder）：① 算法pipeline 层——把 depolarizing/measurement 噪声通道按 shot 采样展开成固定噪声门电路实例（ER），每个实例做一次完整 SVS（矩阵向量乘 |ψ'⟩=U|ψ⟩），平均 10^6 个实例的输出；② 系统框架层——CUDA-Q/Qiskit 的 noisy simulation API 把电路经 CPU 编译到 cuStateVec kernel，逐实例串行提交；③ 编译框架层——论文未明确说明（Qiskit transpile 到单比特门+CNOT 基，无自定义编译器）；④ kernel 调度层——cuStateVec kernel 每次从 |0⟩ 开始做整个电路的矩阵向量乘（S 次全量计算），GPU 上计算密集、无中间态复用；⑤ 硬件架构层——单 NVIDIA A100 40GB：30-qubit statevector 8GB，TQSim 式缓存最多放 5 个中间态，缓存策略失效；结果：CUDA-Q/Qiskit 该 benchmark 需 >10 小时，DMS 方案内存直接不可行。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 = ECM（ER Tallying + ER Commutation + Pruning）+ DFTT（含 DFTT+Caching），全部为算法级优化，后端仍用 cuStateVec/cuTensorNet kernel、零额外内存占用。核心洞察：noisy 模拟的 S 个电路实例存在大量冗余——ER Tallying 用轻量中间表示 ER 直接识别"同一 ER 的电路最终 statevector 相同"（无需真算），只算一次、按频次重复采样（采样远便宜于矩阵向量乘），对应解决 baseline(1) 的"S 次全量计算"；ER Commutation 用 per-qubit 栈 + Pauli 穿通规则把噪声门右移，识别"不同 ER 但输出等价"的实例并合并 shot（无 fidelity 损失），进一步消除冗余；Pruning 利用 ER 频率随 Hamming weight 指数衰减（低权 ER 占绝大多数）的特性做重要性采样，丢弃 insignificant 电路、只采 β 个代表保持集体贡献，把 fidelity 损失做成用户可调旋钮（α、β），对应解决 baseline(1) 的不可控计算量与 TQSim 的"内存饱和才损失 fidelity"；DFTT 把剩余唯一电路按共享前缀建成树、DFS 计算+uncompute 回滚复用公共计算，操作数从 O(|E|log_b|E|) 降到 O(|E|)，纯算法加速、不依赖可用内存（vs TQSim 的 BFS+memoization 依赖内存、内存饱和即掉保真度），对应解决 baseline(2) 的"速度=内存函数"缺陷；DFTT+Caching 用 LIFO 缓存 pre-MCM 状态处理 mid-circuit measurement/erasure 等非幺正通道（K=3 恢复 60%-100% 性能），扩展支持 FTQC 逻辑级模拟与 TNS。综合效果：198 benchmark × 1M shots 平均 59.06×/13.38×（vs Qiskit/CUDA-Q）、最大 7878.03×/439.38×，同误差下 vs TQSim 平均 39.32×/最大 3134.31×。
  - 论文方法全栈执行例子（同一 30-qubit noisy Adder × 10^6 shots）：① 算法pipeline 层——CPU 预处理（平均 3.97s、最大 18.52s）：先对噪声通道预采样 10^6 次得 ER 频次表 → ER Tallying 合并同 ER 电路 → ER Commutation 把噪声 Pauli 门右推合并等价 ER → Pruning 保留 p_i≥0.01·p_max 的显著电路并采 β=100 个 insignificant 代表 → 最终待算电路 S_final ≪ 10^6；② 系统框架层——TUSQ 自身作为模拟器框架（backend agnostic），把剩余电路实例以树组织，逐树 DFS；③ 编译框架层——论文未明确说明（电路先 transpile 到单比特门+CNOT 基，无自定义编译流程）；④ kernel 调度层——DFTT 树遍历调度 cuStateVec kernel：沿边正向乘 U 计算、反向乘 U† uncompute 回滚到共享节点再走下一分支，每个中间 statevector 只算一次、不缓存（内存 O(2^n) 单份），共享前缀计算被整体复用，30-qubit Adder 约 820 秒完成；⑤ 硬件架构层——单 NVIDIA A100 40GB（CUDA_VISIBLE_DEVICES=0），多 GPU 时按子向量切分 statevector、跨 GPU 门做振幅搬移，33-qubit 多 GPU 时间仍拟合单 GPU 指数曲线（无显著串行开销）；结果：vs CUDA-Q/Qiskit >10 小时收敛到约 820 秒。
