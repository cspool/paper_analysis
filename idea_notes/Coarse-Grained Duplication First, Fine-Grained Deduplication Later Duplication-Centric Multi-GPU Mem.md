## Coarse-Grained Duplication First, Fine-Grained Deduplication Later Duplication-Centric Multi-GPU Memory Management

- baseline方法是什么？
  - Baseline 是 UVM 多 GPU 系统上的细粒度页迁移/复制方法：(1) GPS：订阅式页复制，远端写以批量方式广播给订阅者；(2) GRIT：在 on-touch 迁移、访问计数迁移（如 Volta 上计数阈值 256）、复制三种策略间动态选择；(3) CoarseDup：论文自建消融 baseline，仅做 32MB 粗粒度复制 + 远程更新（无细粒度去重）。前两者以 4KB/64KB 小页为单位传输以降低传输量与 NVLink 争用，但带来频繁迁移/复制及 TLB 失效、SM 流水线 flush、cache flush 等管理开销。
  - baseline 全栈执行例子：GPU0 的 SM 访问驻留 GPU1 内存的页 → L1/L2/L3 TLB 依次 miss → GMMU 页表走查失败 → far-fault 中断交 CPU 侧 UVM driver → driver 复制/迁移一个 4KB/64KB 小页（先 flush 源 GPU 的在飞指令/cache/TLB 再传输）→ 后续访问变本地可缓存；重复页上的写触发去重或向订阅者批量远程更新（GPS），或按访问计数/触碰模式在迁移与复制间切换（GRIT）。由于 NVLink 延迟-大小非线性（4KB 与 32MB 延迟相当）、小页带宽利用率极低（8 GPU 下 4KB 仅 1.12 GB/s、64KB 仅 17.12 GB/s），GPS/GRIT 的复制/迁移开销分别占执行时间 37%/38%，平均带宽利用率仅 0.1 GB/s。算法层：负载含 BERT/GPT-2 等模型与 HPC benchmark，但本工作不修改模型算法；系统框架层：UVM driver + 页放置策略；编译框架层：论文未明确说明；kernel 调度层：论文未明确说明（无 GPU kernel 改动）；硬件架构层：GPU TLB/GMMU 标准结构（NVIDIA L2/L3 TLB 为 16 sub-entries/项），无复制专用硬件。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = CDFD 两阶段 duplication-centric 管理：(1) 粗粒度复制优先——远端读触发 32MB 大页复制，一次传输充分利用 NVLink 高带宽（约 250 GB/s 需 ≥1GB 传输才接近峰值），摊薄 flush/TLB 失效开销，对应"细粒度传输带宽利用率仅 0.1 GB/s、管理开销占 37-38% 执行时间"的缺陷（复制/迁移次数降 >99%）；(2) 细粒度去重后置——Access Count Monitor + CDB 统计每个 2MB/64KB 子页的本地访问数与远程更新数，收益 = 本地访问数 − 远程更新数，最低者优先去重，对应"粗粒度复制盲目复制不必要页导致远程更新/广播开销（CoarseDup 远程访问开销 11%）"的缺陷（组合开销较 CoarseDup 降 58%）；(3) duplication ratio 反馈——current/target duplication ratio 经 LRU 采样自适应调节，平衡重复页与常规页占用，对应"多 GPU 内存不足以复制"的假设（工作集 100ms 窗口内仅占约 11% 物理内存，空闲容量可承载复制；oversubscription 2.5×/3× 下仍 +63%/+55% vs GPS）；(4) 硬件支撑——duplicated TLB + sharer table 使写重复页的远程更新 off critical path，CDB sub-entry 结构对齐 NVIDIA TLB 32MB/1MB/64KB 页大小分级去重（32MB→2MB→64KB），代价仅 12,800 B/GPU 存储 + 66.9K–114.9K NAND2 门。
  - 论文方法全栈执行例子：GPU0 SM 远端读 → far-fault 交 DDU runtime → 检查 current vs target duplication ratio：超 target 则先从 CDB 取收益最低的 2MB（或 64KB）子页去重（经 UVM runtime 通知其他 GPU 更新 sharer table、腾出空间），随后向 UVM runtime 发 32MB 复制请求（必要时 LRU 常规页换出到 CPU 内存）；写重复页时 L1 TLB 识别 1-bit 重复标志 → duplicated TLB 命中（miss 则查内存 sharer table）→ GMMU 向持有副本的各 GPU 发远程写更新（off critical path）；32MB 页去重过半后裂分为 1MB 页继续监控 64KB 子项。算法层：无模型算法改动；系统框架层：UVM driver 扩展 DDU runtime（far-fault 分流、复制/去重请求转发、ratio 维护）；编译框架层：论文未明确说明；kernel 调度层：论文未明确说明（复制/去重为页级数据移动，无 compute kernel 改动）；硬件架构层：duplicated TLB + DDU(CDB) + Access Count Monitor。结果：端到端性能 +66% (GPS)/+65% (GRIT)/+8% (CoarseDup)；NVLink 4.0 下 +56%/+52%/+7%；8/16/32 GPU 下增益稳定（约 +66%/+65%/+8%）；复制页中 32MB 占约 91%（ST 中 2MB 升至约 20%）；平均 duplication ratio 约 24%；每 32MB 重复页平均 21,565 次 coherence 广播中约 68% 有用；平均额外功耗 +5.58 W（vs CoarseDup +5.74 W）。
