## Lembas: Cost-Efficient Genome Alignment with External Memory and FPGA Acceleration

- baseline方法是什么？
  - Baseline 是 Minimap2 软件实现的 seed-chain-extend 三阶段长读基因组比对（多线程 CPU 版本，64 线程 AMD EPYC 7742/384 GB DDR4），以及其 GPU/FPGA 加速变体（NVIDIA Parabricks minimap2 beta、G³SA、Cheng24 等）。Baseline 的两大痛点：① **seed 阶段内存容量瓶颈**——anchor 发现依赖驻留内存的 minimizer 哈希表，哈希访问不可预测随机，表必须整体驻留内存（容量随基因组规模增长）；Minimap2 靠 memory chunking 分块建多个哈希表降内存（限在 ~60 GB），但跨 chunk 不做匹配检查 → 大基因组下输出质量下降。② **extend 阶段计算吞吐瓶颈**——SWG 分数矩阵易并行（已有大量 FPGA/GPU 加速），但 traceback 每步依赖前一步决策、串行紧依赖，需要 GHz 级高频，FPGA 低时钟（数百 MHz）下效率极低，多数已有加速器省略或低效实现 traceback，只能"子集加速"（chaining 或分数矩阵）→ 端到端收益有限。③ 已有加速系统只加速单阶段、硬件昂贵（A100 级 GPU 或高端 FPGA），归一化到成本后不显著优于多核 CPU——论文实测没有任何已发表加速系统在成本效率上明确胜过 64 核 Minimap2。
  - Baseline 全栈执行例子（Minimap2 64 线程一次 reference-based 比对）：reference 基因组 → **算法/软件层**：seed 阶段把 reference/query 切成滑动窗口取 minimizer（字典序最小 k-mer），建内存哈希表随机查询匹配 → anchor 列表 → chain 阶段 1D DP 每 anchor 回看至多 N 个前驱算 chaining score（单次宽 max reduction 是关键路径）→ extend 阶段对每 chain 做 banded SWG 分数矩阵（SIMD 向量化）+ 逐单元 traceback → 输出 SAM。系统框架层：论文未明确说明（无 Serving 框架）；编译框架层：论文未明确说明（CPU SIMD 编译器自动向量化）；kernel调度层：CPU 多线程 + SSE/AVX SIMD，GPU 变体（Parabricks）把 DP 单元更新映射到线程束（受 warp divergence、不规则访存、动态终止限制，且 Parabricks 不支持 all-to-all）；硬件架构层：64 核 CPU + 384 GB DRAM 容纳哈希表；FPGA 变体受 HBM/PCIe 容量限制只加速子集。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法：Lembas 用"FPGA 加速 + 外部内存算法"同时消除 seed 的内存瓶颈与 extend 的吞吐瓶颈，构建低成本端到端比对机（桌面 i7-8700 + 2×Xilinx U50 + 4×1TB NVMe + 16–32 GB DRAM，$8,000），三个加速器时分复用同一批 FPGA：
    1. **外部内存 columnsort 播种加速器**（对应解决 seed 内存瓶颈）：把"内存哈希表随机查找"替换为"全量外部排序 + 流式 zip"——minimizer 元组流（16B）经 PCIe 溢出到 NVMe，16 个 16-to-1 单发射 merge-sort kernel 在 FPGA 上做 columnsort（4 轮列排序 + 转置，饱和 8 GB/s 双工 PCIe、有效 ~2 GB/s），排序后两有序流 zips 出 anchors，再按 idxR 二次排序。内存需求从"随基因组增长"变为恒定 ~8 GB（7× 降低），并因始终处理完整哈希（不做 memory chunking）避免 Minimap2 的跨 chunk 质量损失；刻意不做启发式 anchor 过滤（避免随机访存）换取端到端内存恒定，代价是下游工作量放大（人类基因组 7.06× 更多 chains）。
    2. **Tiled SWG extend 加速器**（对应解决 extend/traceback 吞吐瓶颈）：16×16 PE 脉动阵列算 affine-gap SWG 分数矩阵（每 PE 每 cycle 算 S/E/F，F 缓存 PE 内、E/b 走寄存器链、S 走 2 元素 FIFO）；核心创新是 **8×8 tile 位并行 traceback**——每个 tile 边缘单元完整编码跨 tile 路径（2-bit x/y 偏移，480 bit/tile 对齐 512-bit HBM 接口），traceback 每 cycle 前进一整 tile（popcount x/y 位定位下一 tile），把"每 cycle 1 单元"变成"每 cycle 1 tile"，克服 FPGA 低时钟下 traceback 紧依赖；HBM 延迟用预取 4 tile 缓解。extend 达 48 GCUPS/FPGA（≈4× mm64 的 27.21），W=2048 时 traceback 开销比次优设计低 1.77×。
    3. **流式 chaining 加速器**（复用 Guo et al. FCCM'19，非新颖）：分数前向传播打破单次宽 max reduction 关键路径，II=1 全流水，4 kernel 饱和 PCIe，单 FPGA 2.21× vs mm64。
  - 对应解决 Baseline 缺陷：内存容量 7×↓（可扩展性脱离 DRAM 容量缩放，且无 chunking 质量损失）；traceback 以 tile 粒度每 cycle 跳转（低时钟 FPGA 高效）；三阶段全部加速 + 任务级并行近线性扩展到多 FPGA（端到端可扩展）；成本 $8,000 vs $20,000–$24,500（GPU 系统 3× 价格），性能相当/更优 → 2–5× 成本效率、≥2.3× 功耗效率（230 W vs 320/420 W）。保持 Minimap2 算法语义（无精度/近似折衷，结果包含 Minimap2 全部结果）。
  - 论文方法全栈执行例子（一次人类基因组 reference-based 比对）：reference + reads → **算法层**：minimizer 解析 → 外部排序（替代哈希表）→ 流式 anchor 匹配 → 前向 chaining DP → banded SWG + 8×8 tile traceback（不改变 Minimap2 算法语义）；**系统框架层**：论文未明确说明（无 Serving 框架；软件 orchestrator 管理 bitfile 编程与数据移动，NVMe 作为阶段间持久中间存储而非缓存）；**编译框架层**：论文未明确说明（Vivado 综合 bitfile，非编译框架研究）；**kernel调度层**：16 排序 kernel/4 chaining kernel/16×16 extend kernel 实例化与 PCIe/HBM 调度，orchestrator 按阶段切换 bitfile、搬运 NVMe↔HBM 数据（列排序转置后 host 大块 memcpy 重组）；**硬件架构层**：2×Xilinx U50（8 GB HBM/32 pseudo-channel）+ 4×1TB NVMe，seed 饱和 8 GB/s 双工 PCIe、extend 16×16 脉动阵列 + 8×8 tile traceback（480 bit/tile 对齐 512-bit HBM，预取 4 tile）、三加速器时间分片共享 FPGA，输出 SAM。
