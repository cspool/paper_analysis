## Cassandra: Enabling Reasoning LLMs at Edge via Self-Speculative Decoding

- baseline方法是什么？
  - Baseline 1：低 batch 边缘推理下 BF16 原生自回归解码，配合损失压缩（量化/剪枝）加速。全栈执行例子：单个请求（GPQA-Diamond prefill 约 222 token）→ prefill GEMM 后进入 decode 逐 token 自回归；每 token 从 HBM 加载全部 FFN 权重与 KV cache（RTX 4090 上 decode 占端到端延迟约 98%，推理 LLM 输出长度是普通模型 2.99–5.20×）；SmoothQuant W8A8（vLLM 官方 INT8）需在线激活量化与 scale 乘加，低 batch 下 decode 收益仅约 1.3×；更激进的 Wanda/SqueezeLLM/QoQ/DuQuant 在推理 benchmark 上精度崩塌（Wanda 应用于 Deepseek-R1-Distillated-Llama3-8B 在 AIME2025 得 0 分）。kernel 层为 vLLM INT8 kernel；编译框架层论文未明确说明；硬件层为消费级 GPU/NPU 原生内存系统（无格式转换硬件）。
  - Baseline 2：现有 speculative decoding。训练型 Eagle-3 需 4×A100 约两天训练草稿权重，且独立草稿模型带来显存开销；训练无关的 Draft&Verify 用层跳过（32 层中跳 18 个 attention 层但仅跳 9 个 FFN 层，草稿仍须加载 70.7% 参数）；MagicDec 靠 KV cache 稀疏检索（低 batch 下有时比 baseline 还慢）；Lookahead Decoding 靠 n-gram 预测（LongBench/LiveCodeBench 收益低）。全栈：草稿模型前向 → target 并行验证；压缩粒度粗（层/结构化/KV 级），而低 batch 时 FFN 权重加载才是主要瓶颈，故收益有限且不跨任务鲁棒。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法：训练无关 self-speculative decoding = 位级细粒度数据选择（Wanda 激活感知权重剪枝 + KV per-token 剪枝 + mantissa 截断 + unary/MX 指数压缩）把目标模型拆成 speculation/verification 两份数据；草稿只加载 speculation 部分（带宽 ∝ 压缩率，zero-padding 重建后标准 FP 执行），验证加载全量重建原模型（无损、无额外显存）；配套 encoder/decoder 硬件做在线格式转换与 superblock 内存管理。对应关系：粗粒度层跳过/KV 压缩 → 位级细粒度选择（FFN 权重同样压缩，直击低 batch 瓶颈）；训练成本 → 训练无关（仅约 128 样本校准 + 约 5 分钟 grid search，vs Eagle-3 96–192 A100 GPU 小时）；显存开销 → 严格比特子集，显存低于 BF16 原模型；精度损失 → Cassandra-1 无损（精度与 BF16 一致），Cassandra-2 轻微损失（≈SmoothQuant）。
  - 论文方法全栈执行例子：同一 GPQA-Diamond 请求 → 算法层：权重/KV 经 Wanda+per-token 剪枝（默认 40%）、4-bit 截断、unary 指数编码（平均约 2.85 bits，指数熵约 2.6/2.7 bits）拆分 speculation/verification，γ=5 生成草稿 token；系统框架层：草稿推理只从主存加载 speculation 数据（标准 FP GEMM，无草稿模型副本），target 加载全量做并行验证 + rejection sampling 接受（接受率 0.74–0.88），格式类型经页表/TLB 备用位区分、无额外开销；编译框架层论文未明确说明（无编译修改，压缩数据经 superblock 内存映射直通硬件）；kernel/运行时层：draft 与验证 GEMM 仍为标准 FP kernel，解压对 kernel 透明；硬件架构层：superblock 单位加载进 L2 → Cassandra decoder（mantissa concatenator → dynamic shifter → parallel zero counter → LUT → bitmap de-sparsification）恢复 FP 数据供 SM；KV cache 每 token 经 encoder（top-k 分组 + 指数编码）在线写回（NPU 中在 DMA 内）。结果：1.78×–2.41× vs BF16（高于 INT8 量化的 1.3×）、训练无关方法中最优且跨任务方差小、固定内存预算下比 Eagle-3 多生成 1.81× token、decoder/encoder 面积开销约 2%。
