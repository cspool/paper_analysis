## AQuant: Repurposing CODEC for VLM Acceleration via Adaptive Quantization

- baseline方法是什么？
  - Baseline 一：GPU 全精度 VLM 推理（PyTorch 跑 Jetson AGX Xavier，GPU-Full 为按面积预算缩放核数的变体）：单帧图像/视频产生 0.5K–4K 个 FP 视觉 token（文本 prompt 仅 40–60 token），prefilling 阶段对长视觉 token 序列做 QKV projection/注意力/FFN 的 GEMM（compute-bound），decoding 阶段逐 token 做 GEMV 并反复加载整块 FP KV-cache（memory-bound）；FP16/FP32 计算成本随视觉 token 数线性膨胀，成为实时 VQA/场景理解/图像描述等应用的延迟瓶颈。
  - Baseline 二：prior 量化加速器（OliVe、ANT、BitFusion、DRQ、Tender 等）：只在 NPU 内静态量化权重矩阵，忽视输入视觉 token 间的高相似性（Fig. 2：视觉 token 两两 L1 距离远小于语言 token），且线性层量化后精度敏感的非线性算子（GELU/Softmax/LayerNorm）仍需 FP 激活，FP↔INT 反复 cast 的乘法/加法/clamp 硬件开销不可忽视（Table I：FP32 相似检测+量化占 43% 片上面积）。
  - Baseline 三：CODEC 加速 LLM 系统——CMC（ASPLOS'24）用 CODEC ME 模块做整数域相似检测，把相似 token 判为冗余整行剔除以加速 prefilling，只省 prefilling 且有信息损失；LLM.265（MICRO'25）用 CODEC 压缩权重与 KV-cache 加速 decoding，只省 decoding 内存带宽。二者均只覆盖单阶段，且 CMC 是整数域 token 剔除而非量化，不适用于 FP 视觉 token。
  - baseline 全栈执行例子（VQA 请求）：图像 → ViT-L/14 视觉编码器产出 N 个 FP16 视觉 token + 文本 embedding 拼接 → LLM 每层 QKV projection GEMM（FP 权重 × FP 激活）→ Softmax(QK^T)V → FFN GEMM → 下一层，prefilling 全 GEMM 在 GPU CUDA kernel 上串行执行，K/V 以 FP 精度写 KV-cache；decoding 每步 GEMV 从 LPDDR4x 全量加载 FP KV-cache。算法层：静态权重量化（量化 token 本身不动）；系统框架/编译框架层：论文未明确说明（GPU 经 PyTorch/CUDA 执行）；kernel 调度层：FP GEMM/GEMV kernel；硬件架构层：GPU SM 或专用 NPU 张量核（量化加速器在 NPU 内 FP cast）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法：AQuant 算法-硬件协同框架——把 SoC 里推理期间闲置的视频 CODEC 改造成视觉 token 动态量化引擎，配混合精度 NPU 端到端加速。(1) 指数相似检测（对应"忽视视觉 token 相似性"缺陷）：base-delta 量化 T≈B+δ，用 sign+exponent 的 INT10 整数移位/减法近似 L1 距离（D̄(i,j)=Σ_k|sgn(T_k^i)·2^Ē_k^i−sgn(T_k^j)·2^Ē_k^j|），利用视觉 token 指数窄分布 [0,8]（99.7% 在 [0,7]，2^exponent∈[1,256] 9 bit），免去全 FP 运算——对应 CMC 整数域相似检测不适用 FP token 的缺陷（用指数近似桥接 FP 语义与整数硬件）。(2) workload-balanced 自适应量化（对应"量化保精度与硬件利用率"缺陷）：每行 delta top p=25% 元素 INT4、其余 INT2，base token INT8，p:q 与 NPU 高低精度 MAC 阵列 1:4 配比对齐使两阵列 lockstep 无 stall（对应固定精度量化要么掉精度要么浪费算力）。(3) 结果重构（对应"非线性算子需 FP 输入"缺陷）：W_q·B 对 M 个候选 base 预计算查表，W_q·δ 低精度 GEMM，二者相加重构 FP 激活送入 GELU/Softmax/LayerNorm，全程无 FP cast 风暴。(4) CODEC 微架构扩展（对应"FP 量化硬件昂贵"缺陷）：ME 模块复用 subtract-and-abs 树改 INT10 指数检测、4×4 粒度可重构 PE 阵列适配 M 候选；量化路径截断 mantissa 23→16 bit 复用现有乘法器/加法器、不做归一化，轻量 fp-to-int + QuickSelect top-k 单元出 bitmask——增强 CODEC 仅 0.26mm²（省 36% 面积转投 NPU MAC）。(5) 解码 KV-cache 重量化（对应 LLM.265 只压 KV、CMC 只压 prefill 的单阶段缺陷）：KV projection 后重新量化 KV-cache 再写 off-chip、使用时在线重构，以计算换带宽，实现"所有矩阵乘都受益"的 unified + "prefilling/decoding 都受益"的 end-to-end。
  - 论文方法全栈执行例子（同一 VQA 请求）：视觉 token 从 LPDDR4x 读入增强 CODEC → ME 模块指数相似检测（INT10 减法+比较树，M=18 间隔选 base，输出 (T^i,T^j) 表）→ 量化模块 fp-to-int+top-k 生成 INT2/INT4 delta 与 bitmask → bitmask 路由到 NPU：75% INT2 delta 进 4×32×32 INT2×INT16 低精度阵列、25% INT4 delta 进 1×32×32 INT4×INT16 高精度阵列（row-wise product 并行 lockstep）→ 累加 → 重构引擎（base buffer 查表 + delta buffer 相加 → recovery buffer 写回）恢复 FP 激活 → 非线性算子；decoding 时 KV-cache 经同样流程重量化压缩存储、在线重构加载。算法层：动态 base-delta 混合精度量化（与静态权重量化正交）；系统框架/编译框架层：论文未明确说明（自研 cycle-level 模拟器 + Python/PyTorch 算法评估，无服务框架/编译器改造）；kernel 调度层：GPU 上验证算法不可行（INT2 需 pad 到 INT4、INT4×INT16 拆 4 个 INT4×INT4 kernel 难重叠，GPU-AQuant 反慢 15.7%），故调度下沉到 CODEC+NPU 硬件流水（ME/量化/重构占 MAC 阵列 47.8%/24.3%/7.8% 并被流水隐藏）；硬件架构层：28nm 500MHz Verilog（DC 综合）、增强 CODEC 0.26mm² + NPU MAC 0.714mm² + 重构引擎 0.183mm²。
  - 结果：平均准确率损失 0.7%；加速比 vs GPU-Full 6.9×、vs GPU-Full-unscale 2.1×、vs GPU-Mixed-precision 2.2×、vs CMC 2.8×、vs LLM.265 4.6×、vs OliVe 2.5×、vs GPU-VisPruner 2.8×，AQuant+VisPruner 8.3×；prefilling 与 decoding 两阶段均优于 CMC/LLM.265（端到端覆盖）；能耗效率 vs GPU-Full 7.2×、vs LLM.265 14.0×；CODEC 同时解码视频仍 6.8×。
