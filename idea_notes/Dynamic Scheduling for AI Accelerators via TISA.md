## Dynamic Scheduling for AI Accelerators via TISA

- baseline方法是什么？
  - Baseline 为静态 tile 级流水调度（compile-time orchestrated pipeline templates）：当前 AI 加速器（NVIDIA/AMD GPU、TPU、Ascend、Tenstorrent）普遍由编译器在编译期产出确定性指令流，用显式同步屏障（GPU 的 PTX bar.sync / NPU 的 compiler-placed fence）把 tensor/vector/DMA 异构单元协调成固定阶段的软件流水，代表如 CUDA、XLA、TensorRT、手调 FlashAttention-3。局限：① 编译期跨单元依赖协调与重排探索对应最小 makespan / bin packing 两个 NP-hard 问题，只能靠架构相关启发式 + 手工调优；② 抽象粒度失配——CUDA stream/图级运行时粒度太粗（遮蔽 tile 边界与数据依赖），warp 指令级粒度太细（语义丢失）；③ 无法适应运行时变动——静态调度假设固定延迟与带宽，但真实系统有 DMA backpressure、cache/SPM bank 冲突、热节流、OS 效应导致的单元失同步，临界路径漂移后静态模板无法重新定长/重排；④ 历史先例——超标量 CPU 靠动态调度获高 ILP，静态 VLIW/IA-64 因无法泛化到工作负载与微架构变动而失败。
  - baseline 全栈执行例子（FlashAttention-3，seq 长注意力一次迭代）：模型推理算法层 = flash attention 把 QK^T/softmax/AV 融合并按 KV 维分块迭代（M0/S/M1 三 tile 类型，head dim 128）；系统框架层 = CUDA kernel（CUTLASS 风格），thread-block 分解 + 共享内存 staging + warp 级 collectives + 手调预取；编译框架层 = 编译期静态调度，发射 PTX 指令流并固定同步屏障（bar.sync）位置，双阶段/三阶段软件流水模板（图 2b/d）；kernel调度层 = 循环内 tma_load_k_next + wgmma::mma_async 预取、wgmma::mma_sync、softmax_warpgroup、rescale_warpgroup，8 处显式同步（wgmma::wait/warpgroup_barrier_arrive/warpgroup_commit_batch）把 S_i 与 M0_{i+1} 这类数据独立且资源不冲突的 tile 序列化；硬件架构层 = H100（TMA + WGMMA + warp-specialized 静态流水），TMA 停顿则依赖消费者序列无条件阻塞，同步仍是静态固定。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 语义感知动态 tile 调度框架，软硬件协同设计三组件把"调度语义"恢复到运行时：(1) 语义保持编译器——从框架桥（torchxla→StableHLO）经 MLIR 图编译器（GC：fusion/tiling/locality 重排，保留算子边界与类型化依赖边）到融合编译器（FC：自定义 TISA dialect）全程不丢算子身份、类型化依赖（RAW/WAR/WAW）、资源亲和性，输出 TISA 指令；(2) TISA tile 级 ISA——正交于现有每单元执行 ISA 的调度语义层：OpType（计算语义，对应张量/向量/标量单元）、Operands+TileMem（数据语义，区间 [start_addr,end_addr] + scope {Private,Local,Shared} + AccessType，依赖由区间重叠分析自动导出）、Attributes+UnitMap（调度语义，重排约束/资源指定），类比 CPU ISA 的寄存器名之于 scoreboard；(3) 冲突感知运行时调度器——每核 RTL 硬件调度器（五级微架构：解码→路由到每单元 WQ→就绪窗口内与 in-flight 语义表 Fu 做语义冲突检测→提升 IQ→乱序发射），四步机制 Semantic Routing/Dependency Resolution/Adaptive Issue/Feedback，复杂度 O(U·W·|F|max)（典型 ≈O(U)/cycle，优于 Tomasulo O(N²)），RTL 综合仅 7~9 cycles/tile dispatch、W=8 时 1.5M gates/0.25mm²/100mW（占每核面积 1.5%）。缺陷→设计映射：NP-hard 编译期调度 → 把重排决策移到运行时、编译期只做分层 lower 与软件调度 tile 图；粒度失配 → tile 级粒度（>10³ 运算的语义相干单元）平衡可见性与可调度性；无法适应运行时变动 → 硬件调度器按瞬时就绪/资源状态乱序发射、反馈调整优先级；静态同步保守 → 区间重叠 + scope 隔离 + 语义兼容 + 资源可行性四规则区分真冲突与良性重叠，消除隐式迭代屏障。
  - 论文方法全栈执行例子（同一 FA3 注意力，TISA 版，图 5 右）：模型推理算法层 = 同一 flash attention 分块算法（M0/S/M1），算法不变；系统框架层 = 编译器自动生成、声明式 TISA kernel（tisa::gemm<me>/tisa::softmax<ve>/tisa::load<de>/tisa::store<de>），无手工同步（代码量 -30%、同步频率 -50%、性能在手调基线 5% 内）；编译框架层 = torchxla 导出 StableHLO → MLIR GC 融合+64×64 tiling（edge tile 免 padding）→ FC 特化为 TISA dialect → TISA-NPU 后端 LLVM lowering 把 TISA 元数据嵌入二进制；kernel调度层 = 每 tile 描述符经 Reception Buffer 路由到 ME/VE/DE 各自 WQ → 与 Fu 语义冲突检测 → 依赖清除即乱序发射，S_i 与 M0_{i+1}、M1_i 与 S_{i+1} 并发（图 2c/e），完成退休唤醒依赖 tile；硬件架构层 = Epoch 32 核，每核 ME/VE/DE 三引擎 + 1.5 MB 本地内存 + 片上共享 SRAM + NoC + 48GB GDDR6，每核集成 TISA 硬件调度器（1 GHz 硅片，7~9 cycles/dispatch）。效果：Epoch 上 Dynamic vs Naive 1.52–1.92×（ResNet50 1.52×/BERT 1.79×/GPT-J 1.74×/LLaMA2 1.92×）、vs 最强静态 tile 流水再高 1.14–1.63×；Accumulated Overlap Score 达 Naive 2.60–32.64×；FA3 head dim 128 硬件利用率比 H100 高 26.4%（带宽仅 H100 的 1/3.35）；vs A100 TensorRT 平均延迟低 1.46×；语义保持单独消融即贡献 1.2×。
