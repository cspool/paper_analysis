## GRAINS: Enabling High-Performance and Low-Cost Graph-Based Genome Analysis via Storage-Aware Algorithm-Architecture Co-Design

- baseline方法是什么？
  - Baseline 是两类最先进软件工具 + 一个理想化硬件加速基线：(1) Fulgor——节点中心（node-centric）DBG 工具，用 SSHash 最小完美哈希字典存储 k-mer，查询时逐个 k-mer 提取 minimizer→索引 Sizes→读 Offsets→在 Strings 中比对，节点内隐式定义边；(2) MetaGraph——边中心（edge-centric）DBG 框架，存 (k-1)-mer 节点+显式边；(3) IdealAccMem——无主存开销的理想硬件加速器（零延迟/无限带宽/无限容量，可代表理想 PIM）。这些 baseline 都把大规模图数据（659–822 GB，含颜色）从 SSD 经 PCIe 接口整体搬到主机 DRAM，再逐层搬进缓存与计算单元。由于图数据低复用、低局部性（图拓扑带来的随机依赖访问），DRAM 缓存无法摊薄搬运开销：实测 No-I/O（去掉存储 I/O 开销）比 SSD-G4（G5）在 Fulgor/MetaGraph 上分别快 16.7×（9.3×）/7.5×（4.5×），且图越大 I/O 开销占比越高（2.7×→9.2×）。抽样压缩会损失准确率，全图常驻 DRAM（已需数百 GB 且随测序成本下降快速增长）不节能、不可扩展。
  - baseline 全栈执行例子（k-mer set lookup）：算法层——逐条 read 提取 k-mer，逐个查 SSHash 字典（minimizer→Sizes→Offsets→Strings），无跨 read 批量；系统框架——Fulgor/MetaGraph 把整图作为文件从 SSD 读入主机 DRAM（本评估 DRAM 大于图）或反复按需读页，SSD 以 4-KiB 页粒度经 PCIe 传输低复用页；编译框架层——论文未明确说明；kernel 调度层——主机按 k-mer 哈希随机访问索引与图数据，无跨请求合并/排序，缓存命中率低，I/O 请求呈现随机、依赖、低局部性；硬件架构层——IdealAccMem 把主存/计算瓶颈理想化，但仍需从 SSD 搬数据到主机，证明存储 I/O 是即使消除其他瓶颈仍存在的根本问题。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - GRAINS 提出存储感知的算法-架构协同设计，把基因组图分析搬进 SSD（SCC = ISP + IFP），三个关键机制一一对应 baseline 缺陷：(1) 算法层 Cross-Read K-Mer Batching + Genome-Graph-Aware Query Reordering——利用 Sizes 仅占 <4% 空间的特性，在 host 侧先查 Sizes 拿到 Offsets 索引，将 k-mer 排序分批（同 minimizer 只传一次+差分，传输压缩约 2.3×），把对图的随机访问转成 SSD 内的顺序流并流水线化——对应 baseline 随机、低局部性访问缺陷；(2) 硬件层 die 内轻量 IFP 单元（selection+comparison，复用列解码电路，ECC_LITE）只把命中的窗口/比较结果回传控制器，避免整页搬运——对应 baseline 把整页低复用数据搬出 SSD 浪费通道与外部 I/O 带宽的缺陷；(3) 调度层 GST 每页一行（页内位地址+minimizer+one-hot plane 位图），round-robin 跨 16 channel×8 die×4 plane 发请求、合并同页访问、支持 multi-plane，配合块粒度 L2P（0.7 MB）释放内部 DRAM 存调度表——对应 baseline 无法利用 SSD 高内部带宽（57.6 GB/s vs 14 GB/s 外部）与随机访问在 channel/die 上冲突的缺陷。FTL 仅需少量修改（块标注 genomic/non-genomic、SCC 期间不写故无 GC/磨损均衡，块级 L2P），新增 3 个 NVMe 命令（GRNS_Start/GRNS_Steps/GRNS_Write）。
  - 论文方法全栈执行例子（k-mer set lookup，单批）：算法层——host 提取 k-mer、Sizes 查找、按 Offsets 索引排序分批（同 minimizer 压缩）；系统框架——GRNS_Start 进入 SCC 模式（flush 常规 L2P、加载 GRAINS 元数据），批次经标准 NVMe 数据路径进 SSD 内部 DRAM（不写 flash），GRNS_Steps 触发 FSM 流水线，一批排序与上一批传输/查询重叠；编译框架层——论文未明确说明（SSD 内 FSM 决定执行流，非编译框架）；kernel 调度层——GST 调度器把请求按页归并、round-robin 分发到各 die/plane（multi-plane），die 内页缓冲做 ECC_LITE + IFP selection/comparison，仅结果回传，Colors Bitmap 由 ISP 流式扫描（每 channel 2 个 32-bit 寄存器）直接作用于 NAND 流；硬件架构层——轻量 IFP/ISP 单元（333 MHz，on-controller 0.0025 mm²/0.21 mW）在 NAND die 页缓冲与控制器上完成全部图查询，图数据以块粒度均匀布放、访问顺序化以利用内部带宽。结果：k-mer lookup 平均 8.4×/11.9×（SSD-G4）超 FG/MG，alignment-free mapping 7.9×/11.2× 超 FG/MG，SeGraM+GRN 6.2×/9.0× 超 SeGraM+FG/MG，GRN($) 在 64 GB DRAM 低配系统上仍超 FG($$$)/MG($$$) 4.7×/5.2×，能耗降 3.1×–31.6×。
