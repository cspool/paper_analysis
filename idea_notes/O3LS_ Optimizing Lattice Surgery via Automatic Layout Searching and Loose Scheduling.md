## O3LS: Optimizing Lattice Surgery via Automatic Layout Searching and Loose Scheduling

- baseline方法是什么？
  Baseline 是现有 lattice surgery 编译器：SPC（Litinski "A Game of Surface Codes" [34] 的实现 [32][52]）、LAPBC [25]（locality-aware Pauli-based computation，以最大化电路并行度为目标）、SPARO [28]（自动数据布局设计，但倾向扩大布局以缓解瓶颈）。共同缺陷：(1) 依赖固定/预定义数据布局——compact（顺序放置、按需加列）、sparse/standard（稀疏放置，board 通常 10×10 / 9×15）；布局要么过大增加移动距离与 idle 记忆错误（劣化 LER）、要么过小牺牲并行度，没有自动搜索"时间步-移动距离"trade-off 的 sweet spot（Fig.1）；(2) 调度是静态的——对一切电路上下文统一施加固定调度策略（如 compact 布局下多 patch 测量前必做 patch 旋转对齐 X/Z 算子），忽略可免旋转的场合（Fig.4 只需移动 q_0 并旋转暴露不同边缘，而非整 patch 旋转）；(3) 忽视 Pauli 算子抵消机会——偶数个 Y 门固定分解为 [Z_{π/4}⊗(Z^{⊗N−1})_{π/4}](X^{⊗N})_{−π/8}[Z_{−π/4}⊗(Z^{⊗N−1})_{−π/4}]（Fig.6a），错过分组选择带来的门吸收抵消；(4) 在空间受限/不规则布局中 patch 旋转（3 时间步）成为主要瓶颈（tile 数少时旋转占 >50% 时间步，Fig.7），而 baseline 布局设计不感知各 patch 的旋转需求。
  Baseline 全栈执行例子（一次 adder_28 电路在 10×10 standard 固定布局上执行）：算法层：量子算法经 GridSynth Clifford+T 分解（误差 10⁻⁵）→ Pauli-based transpilation（H=Z_{π/4}X_{π/4}Z_{π/4}、CNOT=(Z⊗X)_{π/4}(I⊗X)_{−π/4}(Z⊗I)_{−π/4}）；系统框架层：论文未明确说明（FTQC 编译栈，无 serving 框架概念）；编译框架层：SPC/LAPBC 在固定 standard 布局上做映射与静态调度——为每次多 patch 测量先旋转 patch 暴露算子边缘、按固定模式顺序执行；kernel调度层：每时间片初始化 ancilla patch A、沿预定义路由空间做 PPM（1 时间步）、patch rotation 3 时间步 / movement 1 时间步，布局大导致 ancilla 路由路径长、旋转频繁；硬件架构层：d=9 表面码、p=10⁻³ 电路级去极化噪声，按 p_layer 模型逐时间片累加 LER——大布局 + 长 ancilla 路径 → idle 记忆错误多 → LER 高；结果：时间步与空间均大，LER 未达最优（未利用"更小布局 + 更短 ancilla 路径"这一 sweet spot）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  O3LS 四个模块逐一对应解决 baseline 缺陷：
  1. Module 1 自动布局搜索（对应缺陷 1）：评分函数 S(B)=C(B)×(N_x(B)+N_z(B)−α_e·N_e(B))——C(B)=路由路径连通存在性（ancilla 的 X/Z 边缘都须连到路由空间以支持 Y 测量）、N_x/N_z=被路由路径连接 X/Z 边缘的 qubit 数、N_e=数据 patch 到路由空间边缘数（α_e∈[0.1,0.3] 为密度因子调节紧凑/稀疏）——迭代把最高分位置放为下一个数据 patch + 单步移动后处理，自动找到"时间步-ancilla 路径长度"的 sweet spot（squeezed 布局），空间减少 28.0%~46.7% 且不增时间步，LER 相对大布局降最高 16.9%。
  2. Module 2 Y-synthesis（对应缺陷 3）：把含偶数个 Y 的 Pauli 算子按"每组奇数个 Y"二分（Y-indices 分组 b_1/b_2），构造左/右 Z 旋转算子并检查分组能否被前驱/后继算子吸收（图 9），选吸收算子最多的分组；配合 O3LS-IR/PDAG 表达依赖与并行——在 squeezed 布局（X/Z 无法同时访问，Y 测量必须分解）下减少操作数，时间步降 18.33%。
  3. Module 3 松散调度（对应缺陷 2/4）：动态重指派 patch 功能（如只移动 q_0 并旋转暴露不同边缘，免整 patch 旋转）；Dijkstra 求最小 bus patch 路径（已占用路径节点视为零成本）；奖励函数驱动选择 patch 操作（优先最大化可执行 patch 数、保持数据 patch 连通、同奖励取低时间开销），消除冗余 patch 移动与不必要操作——时间步相对 SPC 总降 36.07%（compact）/24.76%（standard），相对 LAPBC 平均降 35.10%。
  4. Module 4 边感知初始映射（对应缺陷 4）：用 PDAG 估计每 qubit 旋转需求，旋转需求高的 qubit 映射到同时邻接 ancilla X/Z 边缘的 patch，减少 3 时间步的旋转——相对 greedy mapping 时间步再降 15.0%、LER 降 8.4%。
  O3LS 全栈执行例子（同一 adder_28 在 O3LS 自动生成的 squeezed 布局上执行）：算法层：同 baseline 的 Clifford+T → Pauli-based transpilation 流程；系统框架层：论文未明确说明；编译框架层：O3LS Module 1 以 α_e∈[0.1,0.3] 自动生成 ~7×7 squeezed 布局（board 尺寸显著小于 10×10/9×15）→ Module 2 Y-synthesis 合并相邻同基 Pauli 算子、偶数 Y 门按可吸收分组分解抵消 → Module 4 EA 映射把高频旋转 qubit 放到双边缘 patch → Module 3 松散调度按 PDAG frontier 执行：可执行算子用最短 bus 路径做 PPM，不可执行算子用奖励函数选最低时间开销的 patch 操作；kernel调度层：每时间片动态重指派 patch 功能，ancilla 路由路径显著缩短（ancilla 路由空间降 17.35%~27.17%），patch 旋转次数减少（旋转不再是 >50% 的瓶颈）；硬件架构层：d=9 表面码、p=10⁻³ 噪声、p_layer 模型逐片累加——小布局 + 短 ancilla 路径 → idle 记忆错误少，LER 相对 SPC 降 43.11%（compact）/44.98%（standard），相对 LAPBC 平均降 38.8%、最高 93.95%；资源估计：空间+时间平均双降 23.63%，最大空间减 44%（约省 7000 物理量子比特，d=9 下每 tile 对应一个逻辑 qubit）；编译时间与 LAPBC 相当、快于 SPC，且随 qubit 数多项式扩展；最优性分析显示与暴力枚举最优解 gap 仅 4.20%。
