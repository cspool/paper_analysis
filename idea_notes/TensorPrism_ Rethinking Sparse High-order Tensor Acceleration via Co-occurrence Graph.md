## TensorPrism: Rethinking Sparse High-order Tensor Acceleration via Co-occurrence Graph

- baseline方法是什么？
  - Baseline 分两类：(1) unfold 派（SPADE、HotTiles 等）——把高阶稀疏张量按某个模式展开（matricization）成 2D 稀疏-稠密矩阵乘 SpMM（如 $C_{M,L}=A_{M,K}B_{K,L}$，M=IJ），复用成熟的 SpMM 数据流（inner-product/outer-product/Gustavson row-wise）、矩阵重排（列置换、图 islandization）与自适应 tile 技术来提升数据局部性与并行度；(2) 张量原生派（GSpTC、TCP、HyperSB）——不展开，直接在张量域做收缩优化：GSpTC 用 contraction-mode chunking 细粒度划分调度（outer-product 数据流），TCP 用动态张量划分 + 通信感知 tile 尺寸 + 电路交换取数网络（inner-product 数据流，编译期决定固定数据流），HyperSB/超图派用 KaHyPar 对非零元素超图做最小边割 + 负载均衡划分。Baseline 全栈执行例子（以 SPADE 处理三阶收缩 $C_{i,j,l}=\sum_k A_{i,j,k}B_{k,l}$，unfold 成 SpMM）：算法pipeline 层——A 按 (i,j)→行展开为 (IJ×K) 稀疏矩阵、B 为 (K×L) 稠密矩阵、C 为 (IJ×L) 稠密输出，执行 SpMM（行稀疏 × 稠密）kernel；系统框架层——论文未明确说明（加速器从 host 加载展开后 CSR 矩阵与稠密 B，无张量级调度）；编译框架层——论文未明确说明（按展开模式的固定 kernel 映射，tile 尺寸与数据流编译期确定）；kernel调度层——SPADE 在 PE 阵列上做 barrier 同步的 tile 调度 + row-wise 数据流：每轮取一条稀疏行 A[i,:] 与其对应稠密行流 B[K,:] 做部分积累加到输出行 C[i,:]，tile 间 barrier 同步；硬件架构层——SpMM 加速器 PE 阵列 + 片外 DRAM 取稠密行：因展开把 (i,j) 合并成单维、复用距离从 I+J 膨胀到 I×J、相邻非零邻居从 6 降到 4，跨模式共现信息被抹掉，同一稠密行 B[K0,:] 会被反复从 DRAM 取回（uber 上 SPADE 91% 开销来自稠密行重复取数），且展开后元数据膨胀到 O(IJ+K)。GSpTC/TCP 的缺陷：GSpTC 执行期反应式顺序匹配分区依赖、归约阶段（累加/同步部分和到共享输出地址）线程串行化（chcr 上归约竞争占 73% 执行时间、仅 14.2% 时间花在计算）；TCP 电路交换固定网络与 power-of-2 划分在 irregular/large 张量上需 padding（amre 上浪费 2.89× 带宽）且无法适应不规则形状；HyperSB 只均衡顶点数、不直接优化非零计算量与数据复用。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法（TensorPrism）：以共现图（Co-occurrence Graph）抽象重定义稀疏高阶张量收缩的表示、划分与数据流，并配套专用加速器。核心主张：matricization 拆毁了高维数据复用、抹掉了跨模式非零相关性；超图也不直接暴露索引重叠。因此把高阶张量变换为加权共现图 CoG(V,E)（顶点=张量索引，边权=共现次数 W((i,j))=nnz(A[..;i;..;j;..])），用式 3 量化输入/输出复用，把 tiling 表述为修改版 Prize-Collecting Steiner Tree 划分（CoGTP，式 6 目标：最大化图内复用 α·ΣW(e) − 通信 cut 惩罚 λ_cut·ΣW(e_cross) − 负载失衡惩罚 λ_b·RMS(D(v)−W/N)，α=2.0/λ_cut=1.0/λ_b=1.0，BFS 初始化 + Kernighan-Lin 式边界单顶点迁移，每轮 $O(\sqrt{|V|}d)$ 近似线性），再引入图原生 push/pull 数据流（contraction 顶点 PUSH 稠密行到目标顶点集、free 顶点 PULL 特征累加，同/跨模式交替）实现 intra/inter-mode 复用且 PUSH 到不同输出地址保证无写冲突，最后设计 16-PE（4×4 mesh、每 PE 512 FP32 MAC @650MHz、GLB 2.5MB）加速器 + 共现图调度器（权重计算/图生成/成本分析）与 packet-switched 动态路由取数网络。对应解决 baseline 缺陷：(1) 共现图在划分前统一分析所有维度的索引交叠 → 解决 unfold 派"展开抹掉跨模式相关性、复用距离 I×J 膨胀、稠密行重复取数（SPADE 2.09× 超额执行时间 91% 来自重复取数）、元数据膨胀 O(IJ+K)"的缺陷（TensorPrism 稠密行只取一次，nel1 上 4.74× 加速）；(2) CoGTP 静态图划分预测性放置高共现索引 → 解决 GSpTC"反应式顺序匹配、归约同步串行化（73% 执行时间）、仅 14.2% 时间计算"与 TCP"编译期固定数据流/电路交换网络无法适配不规则形状、power-of-2 padding 浪费 2.89× 带宽"的缺陷（PUSH 写不同地址免同步、packet-switched 动态路由自适应不规则稀疏）；(3) 直接优化边权=计算量与复用 → 解决 HyperSB"只均衡顶点数、目标不含复用"的缺陷（平均 1.49× 加速、复用效率 67.86% 高 23.7%）；(4) 图划分每轮 $O(\sqrt{|V|}d)$ 近线性复杂度 → 解决超图/高维循环变换复杂度随张量阶数爆炸（量子模拟 90% 复用机会丢失）的问题。
  - 论文方法全栈执行例子（同上 $C_{i,j,l}=\sum_k A_{i,j,k}B_{k,l}$，Amazon-Reviews 3 阶 1.74B NNZ）：算法pipeline 层——把稀疏 A 的 NNZ 索引转成共现图（CSR 存储 $M_{CSR}=(\sum|r|+1)\times4+E\times4$），式 5 DRAM 访问模型在 2.5MB GLB 约束下定 tiling 因子（$f_1$ 定输出 C 存储、c 定 B 存储、$f_2$ 的 $M_t$ 定稠密行驻留数）；系统框架层——论文未明确说明（无开源 serving/运行时框架，host 经 request dispatcher 下发请求，无多请求调度）；编译框架层——论文未明确说明（指令由 request dispatcher/指令分派器生成，CoGTP 划分与数据流选择即"编译"步骤，非公开编译框架）；kernel调度层——共现图调度器把分区+共现图元数据+稠密操作数分派给 16 PE；PE 内 fetch sequencer 把分区索引转地址流取 GLB（稠密行按取数单元分片缓存、跨单元 ring 转发），收缩引擎 feed unit 广播稀疏输入 + 寄存器堆时间复用（每取 1 次实现最高 128× 复用），contraction 顶点 K0 PUSH 行 B[K0,:] 到目标集 {I2,J0}/{I0,J0} 乘稀疏切片 A[J0,:,K0]，部分积行 C[J0,:,:] 存 IR buffer，列向遍历完转 PULL，K2 向 J1/J2 不同模式目标集广播实现 inter-mode 复用，完整子图（clique）= 一个非零元素且写不同输出地址无冲突；硬件架构层——16 PE mesh + 多 bank GLB + crossbar + HBM2（Ramulator 307.2GB/s）@650MHz，TSMC 28nm 综合、CACTI 7.0 建 SRAM、PrimeTime PX 功耗；结果端到端加速 2.22×/2.40×/1.71×/1.76×/1.49×（vs SPADE/HotTiles/GSpTC/TCP/HyperSB）、DRAM 访问仅为 1/2.18/2.11/1.27/1.53、能耗降 44.6%/42.3%/26.9%/15.7%、复用效率 67.86%。
