## FlashTFHE: A Scalable Architecture for Efficient Multi-bit Fully Homomorphic Encryption

- baseline方法是什么？
  - Baseline 是空间（spatial）output-stationary 架构的 TFHE 加速器，代表为 Morphling（HPCA'24）与 Matrix（TACO'25）：BSK（bootstrapping key，GGSW 密文矩阵）以严格单遍流从 DRAM 扫过 PE 阵列，每个 PE 行持有部分累计的 GLWE 多项式直到 PBS 结束，BSK 每个系数在一次 bootstrapping 中恰好被消费一次、无法缓存，因此把三种并行度硬映射到阵列几何：coefficient 并行（PE 内多项式的 N 个系数级 MAC）、row 并行（同一 post-FFT 系数广播到一行 PE，做 (k+1) 个独立点积）、ciphertext 并行（不同行处理不同 PBS）。低 bit-width/Boolean TFHE 时有效（N 小、k=2~3、每 PBS 只消耗 MB 级 key），但 multi-bit TFHE 的大参数集（N 至 2^16、key 达 4.7GB、l_b=8~10、k=1）使三维并行全部恶化：加宽流水线让每周期 key 消耗线性增长、迅速打满 DRAM 带宽（两栈 HBM2E 在 16 coefficients/cycle/PE 即饱和）；k=1 使 row 复用塌缩到最小 2×，宽 PE 行利用率低下；ciphertext 并行需复制整套功能单元与随 N 线性增长的 R2MDC FFT 中间状态（N=65536 时单流水线 ~59.5MB），面积不可承受。
  - baseline 全栈执行例子（Boolean/6-bit TFHE 的一次外部乘积，Morphling 式空间加速器）：模型推理算法层 = 6-bit 整数拆成多 ciphertext 的 gate/radix 分解，每个 gate/PBS 一次 bootstrapping，carry 需 bivariate LUT（PBS）；系统框架层 = Concrete/TFHE-rs 生态输出每 PBS 的 LWE 输入与 BSK/KSK key 流；编译框架层 = 论文未明确说明（Morphling 无独立编译器修改，IR 直接调度）；kernel调度层 = 每 PBS：key-switching（LPU 流水线）→ blind rotation 中 BSK 以单遍流逐 chunk 从 DRAM 经 NoC 广播到 PE 阵列，每 PE 行 output-stationary 累计 GLWE 部分积（k+1 个点积复用 post-FFT 系数），FFT 用 8-parallel R2MDC、PE 宽度固定，ciphertext 并行度在设计时硬编码为阵列行数（batch size 固定）；硬件架构层 = PE 阵列 + 每行独立 FFT/累加器（N=4096 时 ~16KB in-flight state），BSK 无法复用 → 每 bootstrapping 必须重新流式取整份 BSK，加宽 PE 即按比例抬高 DRAM 带宽，两栈 HBM2E 很快成为瓶颈；同时多-bit 的 k=1 使每行只有 2× 复用，宽行 PE 空闲。结果：Morphling 只支持 N≤4096/6-bit，扩展到 8–10-bit 参数集时带宽饱和、利用率低、面积随 ciphertext 并行度爆炸。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法 = FlashTFHE：把空间 key 复用换成 temporal（时间域）round-robin key 复用。外层循环每次只把 BSK 的一个 chunk（≤0.8MB chip-wide）从 DRAM 载入片内 SRAM，在整批（最多 48 个）ciphertext 间时间复用后再驱逐；GLWE 累计 buffer 移出 PE 阵列、放进每 core 的稠密 SRAM（9.2MB Acc buffer），彻底放弃 output-stationary。由此：(1) 对应带宽缺陷——coefficient 并行缩放不再与 DRAM 带宽成正比（同一 chunk 喂宽流水线多次），单 core MAC 吞吐可达 512 coefficients/cycle（同带宽下空间架构的 8×），两栈 HBM2E 仍够 8 core；(2) 对应 row 复用塌缩——不再依赖 k+1 点积的阵列内广播，k=1 不再浪费宽 PE 行，MAC 单元按真实复用裁剪；(3) 对应 ciphertext 并行面积爆炸——ciphertext 并行变成软件可调的 batch size，无需复制 FFT 流水线，配合 48-bit 定点双实数异构 FFT（256-point FFT-A + 128-point FFT-B，面积 1.38× 而吞吐 32× 于 8-parallel R2MDC）；(4) 新增机会——LPU 的 8-lane 可独立寻址/门控，编译器 adaptive batching 在低并行度阶段收缩 batch（lane masking）把回收带宽转给 external product 流水线（KNN 延迟 -41.7%、利用率 32.7%→56.2%）；编译器 KS-dedup（key-switching 提前、fanout 复用，最多省 47.12% KS）与 ACC-dedup（共享 accumulator，GLWE 存储 -91.54%）。
  - 论文方法全栈执行例子（9-bit Decision Tree 的一次 PBS，参数 n=1070/l_b=8/N=65536/k=1）：模型推理算法层 = 9-bit 单 ciphertext 承载整个整数，决策节点比较/选择用 LUT（PBS），carry 传播消除，PBS 频率比 4-bit 模拟降低数量级；系统框架层 = Concrete-ML 做 7-bit 量化 + Concrete Optimizer 参数搜索（128-bit 安全、p_err≤2^-14），Concrete Compiler 生成 MLIR FHELinAlg；编译框架层 = FlashTFHE 编译器展开 batch、依赖分析、KS-dedup/ACC-dedup、adaptive batching（决策路径串行段并行度仅 8–46 时收缩 batch），输出指令流；kernel调度层 = 每 PBS：key-switching-first（KS 结果供多 blind rotation 复用）→ 外层循环逐 BSK chunk 载入 0.8MB、round-robin 遍历 12–48 个 ciphertext：FFT-A/FFT-B 每周期产 chunk、VecMAC 与 BSK subchunk 做 tiled MAC 累计到 9.2MB Acc buffer，(k+1)·l_b=16 次后 I-FFT，sample extraction 回 LWE，LPU 的 KS/SE/LWE-native 与 BRU 跨 batch 交错；硬件架构层 = 4 core ×（BRU 512 coef/cycle 单宽流水线 + 8-lane LPU），BSK chunk 片内复用解耦带宽，DRAMSim3 两栈 HBM2E 供 BSK/KSK 流，1GHz/16nm/108.08mm²/132.98W → 结果：Decision Tree 409.19ms（CPU 645.40s、GPU 522.24s），全 workload 相对 CPU 最高 2529×、GPU 最高 1320×、相对 Morphling' 约 7×，并首次实现可用速度的 TFHE GPT-2 decoder layer 推理。
