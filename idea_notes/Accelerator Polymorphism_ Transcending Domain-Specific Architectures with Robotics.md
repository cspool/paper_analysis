## Accelerator Polymorphism: Transcending Domain-Specific Architectures with Robotics

- baseline方法是什么？
  - Baseline 是通用处理器（CPU/GPU）上运行的端到端机器人软件栈：RoWild 六应用（DeliBot 粒子滤波+Raycast、PatrolBot Kalman+YOLOv10、MoveBot-PRM Gunrock/Ligra+nanoflann+PRM+CCCD、MoveBot-RRT RRT+CCCD、HomeBot 点云 SLAM、FlyBot Octree+OSQP+A*），CPU 侧 OpenMP + AVX512（Xeon）/NEON（ARM）编译，GPU 侧 CUDA 12.1（Jetson Orin Nano、RTX 3090），NN 推理走 TensorRT。baseline 痛点：机器人负载跨多个算法域（图搜索、控制、优化、SLAM、神经网络），呈现四类访存模式（regular / data-independent semi-regular 如 raycasting / data-dependent semi-regular 如 SLAM 过滤 / irregular 指针追逐如 occupancy map）与四类并行度（fine/coarse/structured/task-level），无单一形态主导——Amdahl 定律下只加速一种并行度瓶颈必然转移到其余形态；GPU 对顺序 phase（MoveBot-RRT、FlyBot）不饱和、对 MoveBot-PRM warp divergence、对 DeliBot 结构化非连续访存不如 CPU 深 cache；CPU 受 Dark Silicon 限制；逐个 kernel 的 DSA 各立、NRE 高、算法演进即需重新流片。传统 vector 处理队列还有三笔开销：地址计算、寄存器文件 load/store、软件循环控制；predication 让 masked lane 白占流水线。
  - baseline 全栈执行例子（SLAM 点云过滤，逐像素算 3D 点、仅可见子集保留）：CPU 上标量/NEON 逐元素谓词执行——每 lane 执行全部指令含 masked lane（地址计算 + 寄存器文件搬运 + 软件循环控制三笔开销）；GPU 上小规模 kernel 不饱和 SM、warp divergence。算法层：粒子滤波/Kalman/YOLOv10/PRM/RRT/SLAM/OSQP MPC/A*（各域算法库）；系统-编译层：OpenMP + gcc 自动向量化（AVX512/NEON）+ CUDA 12.1 + TensorRT；kernel 层：GPU/CPU 指令经寄存器文件与 L1/L2/L3 cache 层次执行（队列作为软件数据结构经 load/store 进出）；硬件层：Xeon 150 W 32 核 / ARM 10 W 6 核 / Orin Nano 12 W 1024 SM / 3090 350 W 10496 core。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法：Accelerator Polymorphism——单一物理衬底运行时在五种专用执行形态间变形（queue-centric SIMD / graph / tree / vector / systolic），以"跨域复用"对抗 DSA 碎片化，同时不退回通用处理。核心 Morpha Core：① 队列升为一等 SIMD 操作数——interleave 划分 sub-queue 保序并行，指令直接以 queue ID 为操作数（对应 baseline 把队列当串行 FIFO 只能 pop-compute-push）；② 无寄存器文件深流水——每执行 stage = ALU + 8 KB scratchpad sub-bank + Queue Manager（组合逻辑），消除地址计算指令与 RF load/store（对应传统 vector 三笔开销）；③ in-pipeline buddy-tree 内存分配（256 B slice、单周期）+ slice 末字链式管理 + FIFO off-chip spill（对应动态尺寸数据在 baseline 只能静态分配/最坏供给或走 OS/runtime）；④ 队列即控制流——Q_LOOP_UNTIL_EMPTY 前端硬件循环、Q_CONDITIONAL_PUSH 选择性入队，以数据可用性取代 predication（对应 masked lane 浪费）；⑤ 32×4 多核网格 + 仅 4 种路由模式的 circuit-switched 互连 + power gating 组成五 morphas（对应 CGRA 空间编译复杂 / DSA 各立）。结果：vs Jetson Orin Nano 5.5× 加速、6.6× PPW；vs ARM 7.7×/7.7×；vs 理想化 Jetson（CPU+GPU 逐 phase 最优分配且忽略搬运）3.4×/3.6×；vs Xeon 1.9×、28.9× PPW；vs RTX 3090 0.9×（持平）、39.6× PPW；均 10 W TDP。
  - 论文方法全栈执行例子（同一 SLAM 点云过滤）：点云像素 interleave 划分进 8 个 sub-queue（共享 queue ID，sub-queue 本身即操作数）→ Q_LOOP_UNTIL_EMPTY 由前端硬件循环反复发出 ADD/Q_CONDITIONAL_PUSH，程序计数器仅在所有 Queue Manager 报空后前进 → 每 stage Queue Manager 从 scratchpad sub-bank head 取操作数直接喂 ALU、结果写 tail（无 RF、无地址计算、无软件循环），可见性判据为真的元素 push 进下游队列、否则不入队（空 lane 自动 skip，30% pass rate 时 2.4×）→ 队列增长触发分配级 buddy-tree 分配新 slice、超出片上份额按 FIFO spill + 自动 prefetch → 应用阶段切换时 Controller 经 32-bit 控制网络配置 crossbar 2 位路由模式（165/288 cycle）并把余下衬底变形成下一个 morpha（如优化 phase 用 systolic、树遍历用 tree morpha 把全片存储汇成单核可见大内存）。算法层：算法本身不改，仅换执行模型（论文未提出新算法模型）；系统-编译层：in-house tensor compiler 编 regular 部分、自研编译器把软件 queue 语义直接映射为 Morphatron queue 指令（编译仍是 open problem，论文未做编译器评估）；kernel 层：queue-centric SIMD 直接在 scratchpad sub-bank 上执行 + DMA/collective 搬运（vector/systolic 静态编程、queue 阶段由队列统计动态编程）；硬件层：7 nm ASAP7 625 MHz 10 W RTL 综合。
