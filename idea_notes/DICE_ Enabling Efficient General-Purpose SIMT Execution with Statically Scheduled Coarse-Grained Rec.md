## DICE: Enabling Efficient General-Purpose SIMT Execution with Statically Scheduled Coarse-Grained Reconfigurable Arrays

- baseline方法是什么？
  - Baseline = 建模的 NVIDIA Turing GPU SM（RTX2060 Super，Accel-sim/AccelWattch 建模；scale-out 基线为 Quadro RTX5000/RTX6000，更新基线为 Ampere RTX3070）：warp 级 lockstep 的 SIMD 执行后端 + 集中式寄存器文件（RF）+ 全功能 warp 控制流水（fetch/decode/schedule/issue）+ mask-stack 发散处理 + warp 同步访存合并（coalescing）。
  - baseline 全栈执行例子（Rodinia CUDA kernel，如 NN euclid 一个线程块）：CUDA 源码 → NVCC 编译 PTX/SASS → 运行时 kernel 以 CTA 分配至 SM、CTA 内按 warp 组织 → warp 调度器逐指令 fetch/decode/issue → 32 lanes lockstep 执行：每条指令所有操作数从集中式 RF 读出、结果写回 RF（中间值多次往返 RF，还需 MOV/S2R 等数据搬移指令）→ 发散路径按 active mask 屏蔽执行（inactive lanes 空转浪费 ALU 周期）→ 访存时 32 线程同拍发出请求，由 coalescer 一次合并为宽事务进 L1/L2/DRAM。缺陷：(1) RF 访问 + 控制逻辑合计占 SM 动态功耗 >40%（NN 上 RF 占 32.4%、控制占 18.1%，近年 GPU 世代持续如此）；(2) mask 执行在发散频繁 kernel 上浪费吞吐（RTX2060S 每个 SM 160 功能单元但每周期至多 dispatch 128 线程）；(3) warp 级控制流水复杂且反复工作、能耗高。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 静态调度 spatial-only CGRA 替换 SIMD 后端 + CTA 级调度 + p-graph 划分 + 双优化，七项缺陷-设计映射：①空间数据流直连（PE→PE 经静态互连转发中间值）替代 RF 中介——对应 RF 高访问；②以 CTA（数百线程）为调度粒度、轻量 CS/FDR/DE/RE 四阶段控制流水替代 warp 级 frontend——对应控制能耗；③selective dispatch 只派发活跃线程——对应 mask 空转；④p-graph 划分把变延迟访存/控制发散的生产-消费边移到 CGRA 边界（load-to-use 跨 p-graph、LDST Unit 边界访存、BRT 非阻塞 retire、BTFNT+PDOM stack 管发散）——对应"静态调度 vs 运行期动态"的根本矛盾；⑤double-buffered 配置存储（CM0/CM1）+ e-block 复用调度（优先调度同 PC 的 CTA）——对应重配置/元数据开销；⑥编译期 thread unrolling + swizzled bank——对应小 p-graph 的 CGRA 利用率不足；⑦TMCU 时序合并流水线程的访存——对应丢失 warp 同步 coalescing 后的内存效率损失。
  - 论文方法全栈执行例子（同一个 NN euclid kernel）：CUDA 源码 → NVCC → PTX → DICE 编译器建 CDFG 并划分为 p-graph（该 kernel 4 个 p-graph，Table III 各 kernel 4–13 个）→ CGRA mapper 产位流 → kernel 启动后 CTA 分配至 CP，e-block（p-graph × 活跃线程）沿 CS→FDR→DE→RE 推进：位流双缓冲装载后，活跃线程按 tid 升序以 II=1 逐周期流入 CGRA，中间值在 PE 间直连传递（整个 kernel 期间 RF 只做跨 p-graph 交换，MOV/S2R 被空间直连消灭）→ 访存请求逐周期从 LDST Unit 流出，TMCU 按地址对齐缓冲合并连续线程请求再进 L1/L2/DRAM → 发散经 predication 并入单 p-graph 或经 BTFNT 预测跨 p-graph 处理 → e-block 计算完毕后入 BRT 等待访存归账再 retire，CGRA 不停机继续下个 e-block。
  - 效果对照（缺陷→设计→结果）：RF 能耗高 → 空间直连 → RF 访问 −68%，NN 上 RF 能耗占比 32.4%→8.5%；控制逻辑能耗高 → CTA 级调度 + 四阶段流水 → 控制能耗 18.1%→1.3%；mask 空转 → selective dispatch → 发散频繁 kernel（BFS-1/2、BPNN-1）stall-excluded 利用率反超基线；变延迟访存/控制流 → p-graph 划分 + BRT → 无需弹性互连/动态调度硬件即跑通用程序，且访存延迟隐藏更好（2048 threads/CC 对 1024 threads/SM，RF 容量相同）；重配置开销 → 双缓冲 CM → 重配置不打断 CGRA 执行；coalescing 丢失 → TMCU → 1.41–2.45×（NN/BFS-2/BPNN-1/2）且 L1 能耗与基线相当；小图利用率 → unroll → 1.24–1.35×（BPNN-1/GE-1/HS）。总账：性能 1.16×（geomean vs RTX2060S）、CP 动态能效 1.90×、平均功耗 −42.0%；scale-out O48/O72 与 DICE-UO（对 RTX3070）结论一致（1.04–1.05×/性能持平、能效 1.77–1.83×、功耗 −43.0–45.9%、RF −68%）。代价与边界：p-graph 大小受共享内存访问、barrier、资源约束限制时利用率低（相对利用率上限 60%），CGRA 开关+配置存储占 CP 面积 9.7%（+10.7% 面积开销上界），scale-up 收益有限（DICE-U 0.97×）；共享内存访问的流水优化留作未来工作。
