## Intermittence-aware Speculative Page Coloring for Secure NVM

- baseline方法是什么？
  - baseline 有三类：(1) 直接 NVM 主存 + 全数据加密——无缓存 MCU 上每次 load/store 直访 NVM，每次都需解密/加密（慢 NVM + AES 双重开销），且 16B AES 加密粒度 vs 2B 原子写破坏 crash consistency（部分密文残留下无法解密）；(2) 整 SPM JIT checkpoint（NVSRAM [56]、Mapi-Pro [9] 断电前把整个 SPM 加密持久化）——需为整 SPM 加密+checkpoint 预留大量电容能量（图 1：测试负载大部分收割能量被加密与 checkpoint 消耗，仅小部分用于执行），大电容恢复时间长，且主存容量被限制在远小于 NVM 的 SPM；(3) 编译器内存着色 [63]（Memory Coloring）——把页映射 SPM frame 看作图着色（类比寄存器分配），冲突页永久分配不同 frame 或永久 spill 到 NVM，忽略 EHS 频繁断电的短功率周期，导致 SPM frame 压力大、页冲突多；Mapi-Pro [9] 用 profiling + ILP 做 hot/cold 静态映射，同样静态固定、无法适应动态变化的局部性，且整 SPM checkpoint 开销大。
  - baseline 全栈执行例子（NVSRAM/Mapi-Pro 的一次访问 + 断电）：算法层——ML 推理（MNIST/CIFAR 等 intermittent learning [70]）或传感循环，数据存 NVM 或 SPM；系统框架层——无 OS/虚拟内存、无 MMU/TLB，直接物理寻址（JIT checkpoint 由电压监视器触发）；编译框架层——常规编译器把数据段放 NVM 主存；Mapi-Pro 用 profiling + ILP 决定 hot 页放 SPM、cold 页留 NVM，一次映射后不再移动；kernel调度层——无页调度：hot 页驻留 SPM 直达，cold 页每次访问都走慢速 NVM；硬件架构层——MSP430FR5994 无缓存，load/store 直访 NVM（每字加解密），断电时电压监视器触发整 SPM 加密 checkpoint 到 NVM、恢复时整 SPM 解密加载回——大部分能量被整 SPM 加密/checkpoint/恢复消耗，MNIST/CIFAR 等较大负载在 1mF 小电容下无法运行（checkpoint 能量超出电容容量，NVSRAM 仅 10mF 可跑且仍差）；芯片设计层——论文未明确说明。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - MANATEE = 新内存层级（SPM 作主存 + NVM 作二级存储）+ 编译器/运行时协同的 intermittence-aware speculative page coloring。对应解决：(1) 解决"无缓存直访 NVM 全加解密慢"——SPM 作主存、NVM 仅存加密持久态，SPM 内访问零加密开销，仅页交换/断电时加解密（用 AES-XTS，无完整性树开销）；(2) 解决"整 SPM checkpoint 能量爆炸与容量受限"——以 64B 页粒度只持久化 WTQ 记录的脏页（页粒度加密 + 脏页跟踪），不再整 SPM 加密，V_backup 阈值保证每次页管理操作 failure-atomic（能量缓冲覆盖页管理操作 + checkpoint），1mF 电容即可运行且主存地址空间不再限于 SPM（NVM 全容量可寻址）；(3) 解决"传统着色的全局冲突压力"——利用 EHS 短功率周期：只要求冲突页在 T_on 窗口内不同色，滑动窗口（正反向 DFS、C_available = C_total − C_accessed、优先窗口交集颜色、反向优先）窃取窗口外页面颜色，把冲突解决限制在极短窗口、降低 SPM frame 压力与页 miss（miss rate 从 2.05% 降到 0.99%）；misspeculation（实际功率周期长于预期）由运行时 page manager 兜底（BT 判定 + 加密驱逐/解密载入），保证任何环境下正确性；(4) 解决 Mapi-Pro 静态映射无法适应动态局部性——编译器插桩 hint 使每次访问都动态判定页驻留、页随执行流动，天然适应动态局部性，且无 profiling 阶段。
  - 全栈执行例子（MANATEE 处理一次 store + 断电恢复，MSP430FR5994）：算法层——12 个 benchmark 中的 ML/传感负载，数据段存 NVM（加密态）；系统框架层——无 OS/MMU/TLB，纯软件页管理（BT 作软件页表，每次访问 1 次直接索引）；编译框架层——LLVM 插桩：解析 .map → 64B 页划分 → CFG + 别名/liveness 分析 → 干扰图着色，冲突时以 T_on 为滑动窗口正反向 DFS 窃取窗口外颜色（循环/I/O 页留专用颜色）→ 每条 load/store 带 (页号, 颜色) hint 与 metadata；kernel调度层——page manager 运行时：按 hint 索引 BT 判命中/未命中，未命中则加密驱逐旧页 + 解密载入新页，WTQ 记脏页，断电前按 WTQ 原子持久化脏页（AES-XTS，4×16B 块凑 64B 页原子 flush）+ 翻转完成标志；硬件架构层——SPM 内访问零加密、页交换才加解密，V_backup 阈值保证页管理操作 failure-atomic，恢复时读标志位定 checkpoint 有效性（0 则 abort）。结果：页 miss ≈1%，相对 Unsecure 开销仅 1.71×（thermal/RFHome/solar），比 Memory Coloring 快 ~12%，比 Mapi-Pro 快 2–3×、STM32 4MB 数据集场景 5.7×；芯片设计层——论文未明确说明（无芯片结构修改，纯软件方案）。
