## Lit Silicon: A Case Where Thermal Imbalance Couples Concurrent Execution in Multiple GPUs

- baseline方法是什么？
  - Baseline 是当前数据中心多 GPU 节点上的默认做法：同构工作负载（如 FSDP LLM 训练）下所有 GPU 按 TDP 均匀供电、无节点级功率管理，性能波动问题由硬件（DMA 引擎、通信加速器）或软件（优化通信集合、kernel fusion/fission）在 kernel/通信层面解决，且 kernel fission 等方法假设节点内只有单个 straggler。痛点：① 热不平衡 + C3 未被识别为耦合问题——设备级 DVFS 独立导致温度/频率差异（straggler 更热更慢，温度差 1.155×、频率差 1.062×），而 C3（通信与计算重叠）把 straggler 的慢传导给 leader（leader 提前开始通信却要等 straggler，重叠延长、资源竞争加剧反而更慢），形成负反馈循环、迭代间重复，leader 重叠率最高为 straggler 的 1.8×；② 现有方案只优化 C3 效率或只处理单个 straggler，不针对"同构负载下节点级性能波动"这一根因；③ 功率管理在 GPU/集群级是孤立的，节点级没有细粒度功率管理层。
  - Baseline 全栈执行例子（一次 8×MI300X FSDP Llama 3.1 8B 训练迭代）：算法层：FSDP 将权重/激活/梯度按层均分到 8 GPU，每 GPU 执行相同算子序列；系统框架层：PyTorch FSDP 在每层 forward 后发 AllGather、backward 中发 ReduceScatter，与下一层 GEMM 重叠（C3）；编译框架层：PyTorch eager 模式，kernel 由库提供（论文未明确说明具体编译流程）；kernel调度层：计算 kernel（GEMM/flash attention/RMSNorm）与通信 kernel 在同一 GPU 上并发调度共享资源，straggler 的通信起始晚于 leader；硬件架构层：8 个 MI300X 独立 DVFS——热 GPU 频率降低，straggler 通信 kernel 更慢，leader 在同步点等待（straggler wave），迭代末 leader 空等 straggler，straggler 性能低 5-10%，C3 重叠最高被拖到 1.8×。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法：约 200 行 PyTorch 的节点级功率管理运行时层，通过检测与缓解两步消除 *Lit Silicon*。对应解决：① 识别根因（对应解决"未识别耦合"）——用 lead value 检测：解析 trace 计算每 GPU 每 kernel 起始时间与最晚 GPU 的差（straggler wave），sum 聚合识别 straggler/leader；② 运行时按功率上限重分配（对应解决"无节点级功率管理层"）——Algorithm 2 按归一化 lead 计算各 GPU 功率上限增量，Algorithm 3 在节点功率上限/TDP 下均匀调整，支持 GPU-Red（降 leader 功率省电 4%）、GPU-Realloc（功率从 leader 重分配给 straggler，吞吐 +3%）、CPU-Slosh（把闲置 CPU 的约 86.5% 核心功率预算转移给 GPU，吞吐 +4%~6%）；③ 收敛后可停用或长周期采样（对应解决"开销"）——一次收敛约 80 秒，三个月只需调两次，功率分布可跨框架/模型复用。解析性能模型（Insight 5）证明只有对齐 GPU 频率才能解决 *Lit Silicon*（leader 在 varying-overlap kernel 上并不更快），功率模型（Insight 6）量化省电/提频收益。
  - 论文方法全栈执行例子（同一次迭代，启用 GPU-Realloc）：算法层：同 FSDP 均分；系统框架层：PyTorch FSDP + 论文运行时层——profiler 每 10 迭代采样一次（约 4 秒/样本），Chopper 解析 kernel 时间戳；编译框架层：PyTorch eager，kernel 库不变（论文未明确说明）；kernel调度层：不再修改 kernel/通信，而是检测——Algorithm 1 算 lead（straggler GPU4 lead≈0，leader lead>0 动态增长），Algorithm 2 给 straggler 功率上限 +15W（norm_lead×global 衰减），Algorithm 3 在节点 120W 上限下 8 GPU 均匀 -15W/8，amd-smi 设置功率上限；硬件架构层：straggler 频率提升、leader 频率微降并省电，各 GPU DVFS 拉齐频率后 lead 趋于 0、C3 重叠不再拖慢 leader，迭代末无 leader 空等；端到端结果：GPU-Realloc 吞吐 +3%（CPU-Slosh 最多 +6%）且节点功率不变，GPU-Red 节点功率 -4%，预计单客户（6GW AMD 部署、PUE 1.56）年省电费约 $70M。
