## OASIS Outlier-Aware LUT-Based GEMM with Dual-Side Quantization for LLM Inference Acceleration

- baseline方法是什么？
  Baseline 含三条路线的缺陷：(1) WOQ LUT-GEMM（FIGLUT [42]、LUT Tensor Core [37]、LUT-GEMM [43]）：权重 NU 量化（nW=4）但激活保持 FP16，运行时按小 group（μ=4）把"权重索引到 inner-product 结果"的 LUT 用权重作 MUX 选择——缺陷：(a) LUT 依赖流式激活，必须 on-the-fly 生成；(b) inner-product LUT 大小 2^μ·(K/μ)，K 大（LLaMA-7B q_proj 的 K=4096）时 LUT 爆炸，只能靠小 group 抑制，但小 group 使每周期并行归约的激活数仅 μ=4；(c) 跨 group 的 partial-sum 归约引入额外 FLOPs 与延迟，计算并行度受限。(2) INT-WAQ（RTN/SmoothQuant/QuaRot/Atom）：整数等距量化可被现有 INT4 硬件直接执行，但与 LLM 权重/激活的非均匀分布不匹配，W4A4/W4A3 下精度显著下降（如 RTN/SmoothQuant 直接发散）；Atom 靠 group-128 细粒度量化+高位 outlier 保留缓解仍降精度。(3) NU-WAQ 传统执行：K-Means 码本量化精度高，但索引格式与低精度计算单元不兼容，运行时需逐元素查码本反量化回 FP16 再跑 FP16 GEMM，抵消量化收益（dequant 占 GEMM 20-90%）；动态 top-k outlier 检测放在 GEMM 关键路径上（图4a），先扫全向量分 inlier/outlier 再分别 GEMM，检测延迟不可隐藏。
  Baseline 全栈执行例子（LLaMA-7B 一层 q_proj 的 W4A4 GEMM，M=1, K=N=4096）：算法层：FP16 激活做均匀 4-bit 量化（INT-WAQ）或查码本得索引（NU-WAQ），outlier 通道静态保留高位；系统框架层：Transformers/PyTorch 加载 FP16 模型，张量派发到 GPU；编译框架层：论文未明确说明（GPU 路径依赖 cuBLAS/Tensor Core kernel 编译，无独立编译框架）；kernel调度层：INT-WAQ 走 INT4 Tensor Core kernel（group 内归约），NU-WAQ 先逐元素反量化为 FP16 再 FP16 GEMM；硬件架构层：A100 Tensor Core 执行低精度/FP16 GEMM，dequant 开销显著；WOQ LUT 路线在 FIGLUT 上按 group-4 查 inner-product LUT 并跨 group 累加 partial-sum，每周期只并行 4 个激活的归约。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  论文方法：OASIS 用三个设计对应解决 baseline 缺陷——(1) WAQ LUT-GEMM（对应 WOQ LUT-GEMM 的 LUT 大/并行度低，及 NU-WAQ 的反量化开销）：利用 WAQ 特有三大机会：权重与激活质心均离线学习→Cartesian Product LUT 可离线预计算（消除 on-the-fly 生成）；双操作数量化后可能乘积数仅 2^(nW+nA)=256（W4A4）→ 存 Cartesian Product 而非 inner product，LUT 相对 4096×4096 层小 64×；Cartesian Product LUT 与归约长度 K 无关→归约粒度可到整层 K（group size 相对 μ=4 提高 1024×），FLOPs 相对降 16×，消除跨 group partial-sum。(2) Outlier-aware 量化 + look-ahead 误差补偿（对应 INT-WAQ 精度缺陷和动态检测关键路径延迟）：动态识别每 token top/bottom 0.5% 激活保留 FP16（offline/online outlier 阈值 RMSE 高达 0.32-0.38，故不用静态 outlier channel）；主分支先对全激活量化做 look-ahead LUT-GEMM，outlier 分支并行检测+误差补偿，把动态检测移出关键路径（相对 OASIS-C 吞吐高 16-18%）且结果数学等价。(3) Orizuru 轻量 top-k 引擎（对应检测硬件开销）：max/min 双完全二叉树共享叶子，初始化 N-1 次比较、每次 pop log2(N) 次比较、min 树复用 max 树最底层结果省 50% 初始化比较，总 1.5N+2k·log2(N) 次比较（vs SpAtten 的 6N），面积 0.739 mm²/功耗 0.273W，能耗极低。
  OASIS 全栈执行例子（同一 LLaMA-7B q_proj W4A4 GEMM）：算法层：权重离线 K-Means 4-bit 量化（共享质心+每输出通道缩放），激活质心用 16 个 C4 样本 Fisher 加权 K-Means 离线学习，在线 token 级 4-bit 量化 + top/bottom 0.5% outlier 保留 FP16；系统框架层：Transformers/PyTorch 推理，激活经 Memory Controller 流入加速器；编译框架层：论文未明确说明（ASIC 直接执行，无编译框架）；kernel调度层：Clustering Unit 二分查找树聚类激活→Concat Unit 并行拼接 8-bit 索引→Index Counter 统计分布→MAC Tree 加权和（主分支）；Orizuru 并行检 outlier→Dequant 反量化→Error Calc 算残差→MAC 误差补偿（outlier 分支），Memory Controller 双分支流水；硬件架构层：OASIS ASIC（16 PE Line×4096 Concat、32 Index Counter/line、273 Orizuru、2KB LUT、TSMC 28nm/500MHz/15.31mm²/9.66W）按 Fig.14 流水执行 1-4096-4096 GEMM；结果：平均 accuracy drop 1.94%（比 Atom 低 6.34%），相对 FIGLUT 提速 3.00×、能效 1.44×，相对 A100/QuaRot 提速 5.41×/3.12×、能效 198.1×/108.8×（单 batch decoding）。
