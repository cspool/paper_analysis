## LIPPEN: A Lightweight In-Place Pointer Encryption Architecture for Pointer Integrity

- baseline方法是什么？
  - Baseline 是 Arm Pointer Authentication（PAC，Armv8.3-A 引入，Apple arm64e/Android/Windows on Arm 已商用）：把 64-bit 指针高位未用地址位（7–16 bit，Apple M1 为 16 bit）用作认证码，用轻量分组密码对"指针值 + modifier（如 SP）+ 域密钥 K"生成截断 MAC（PACIA/PACDIA 签名、AUTIA/AUTDA 认证），解引用/返回时硬件校验，失败则破坏指针高位（Armv8.3）或同步异常（Armv8.6）。外部元数据方案（CHERI 256-bit/pointer、CCFI 128-bit、ZeRØ tag）提供强保证但带来内存/访存/ISA 复杂度；ASLR 只有单一随机偏移、布局泄露即失效。PAC 的痛点：① 认证码必须塞进未用地址位，有效熵 <24 bit，暴力破解可行（PACMAN 用投机执行 oracle 在 Apple M1 上约 2.94 分钟穷举 16-bit PAC，实现控制流劫持；C3 的 24-bit 也被 Na et al. 绕过）；② 保留原始地址位导致加密空间受限，且 PAC 值参与分支预测/调试依赖裸地址；③ 截断 MAC 在 Spectre 类投机执行下仍可被当作 oracle。
  - baseline 全栈执行例子：一次 arm64e 函数调用与返回 → Clang/LLVM 在 prologue 生成 PACIASP（用 SP 作 modifier，对返回地址签名，16-bit PAC 嵌入高位写回栈）、epilogue 生成 AUTIASP+XPAC → 硬件 PAC 单元（Armv8.3-A，密钥存系统寄存器，M1 按 boot/EL/VM 派生）校验：通过则恢复返回地址供 RET 与 RAS 使用，失败则高位破坏/异常；攻击者 PACMAN 沿投机路径用 cache 侧信道探测"猜测 PAC 是否命中"，2.94 分钟内暴力得到合法 PAC 完成 ROP。算法层：论文未明确说明（非模型推理论文）；系统框架：论文未明确说明（无 Serving 框架，OS/内核负责密钥与上下文）；kernel调度：论文未明确说明（无 GPU kernel）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法：LIPPEN 全指针加密——把整个 64-bit 指针当作密文块，用低延迟轻量级分组密码 PRINCEv2（12 轮、单周期 unrolled datapath、128-bit 密钥）以 ECB 方式整体加/解密：seal = Enc_{k⊕m2}(ptr ⊕ m1)、unseal = Dec_{k⊕m2}(cipher) ⊕ m1，m=m1||m2 为可配置上下文 modifier（SET_KEY/SET_M_SIZE 配置；m1 只放不参与地址生成的未用位 |m1|max=64-A+2，m2 与密钥异或防跨域 key-collision，域分离密钥 128-|m2| bit 唯一 → 最大 2^(128-|m2|) 域）。新增 PTR_SEAL/PTR_UNSEAL 指令，语义/编译器/ABI 完全对齐 Arm PAC（PacTight 移植仅 <50 行）。安全性：暴力空间从 2^16 提升到 2^64（解密后未用位须全 0 才有效，检测概率 1-2^-|m1|），且形式化证明"伪造合法加密指针"可归约为对底层分组密码的选择密文攻击（Adv_LIPPEN ≤ Adv_E + ε(q)），PRINCE 族无全轮实际攻击（PRINCEv2 声称无 <2^47 对 / 2^112 时间攻击），从而同时覆盖常规与投机（Spectre/PACMAN 类）执行下的指针伪造。modifier 与 cipher 协同设计（XOR 注入 plaintext/key 而非 tweakable cipher）避免 QARMA 的 tweak 延迟/面积代价（PRINCEv2+mod 1,522 LUT/1cyc/42MHz vs QARMA-unrolled 1,794 LUT/40MHz）。
  - 论文方法全栈执行例子：同一函数调用与返回 → LLVM v18.1 RISC-V backend 在 call 前插 PTR_SEAL（modifier=SP）、ret 前插 PTR_UNSEAL → 运行于 FPGA 原型（Rocket/BOOM @100MHz + RoCC 上的 PRINCEv2 引擎）：调用时 PTR_SEAL 把 64-bit 返回地址经 RoCC 紧耦合队列送 PRINCEv2 单周期加密得 Enc_{k⊕SP}(ra) 写回栈（无任何元数据开销、无 shadow memory）；返回时 PTR_UNSEAL 解密并校验高 16 位为 0，恢复真实地址供 RAS/分支预测，失败置异常标志 → 攻击者即便任意改写内存，也须猜中 2^64 空间中的合法密文或破解 PRINCEv2 才能伪造，投机路径下的猜测同样失败（无低熵 PAC 可 oracle）。评估：SPEC CPU2017 上 Rocket 动态指令 +1%，geo mean 开销 LIPPEN 2.9% vs PAC 3.6%；nbench 仅 0.2%；BOOM 与 Apple M1 相当甚至更低；FPGA 面积/功耗增幅 <4%（Rocket-LIPPEN 58,137 LUT/4.035W vs Rocket-base 56,311/3.935W）。算法层：论文未明确说明（非模型推理论文）；系统框架：论文未明确说明（无 Serving 框架，FireMarshal Linux 为运行环境、密钥由硬件/OS 管理）；kernel调度：论文未明确说明（无 GPU kernel，加解密由 RoCC 硬件完成而非软件 kernel）。
