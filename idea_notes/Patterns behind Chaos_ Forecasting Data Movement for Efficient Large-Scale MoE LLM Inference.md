## Patterns behind Chaos: Forecasting Data Movement for Efficient Large-Scale MoE LLM Inference

- baseline方法是什么？
  - baseline 分两层：(1) 现有 MoE serving 系统——system-centric、部署特定优化：CPU-GPU offload（MoE-Lightning、CoServe）、多 GPU 通信优化（Comet、MegaScale-Infer，把 attention 与 MoE 拆分到不同机器）、PIM（Duplex）、EPLB 动态专家放置（每 3000+ step 才基于周期 profile 调整一次，初始 ~1000 decode token 无 profile 数据）、SGLang/Qwen 默认专家连续放置（0-15 在 GPU0、16-31 在 GPU1……）；(2) 未来 wafer-scale GPU 上的 naive 方案——Base：EP-like 均匀分专家到各 die，但 wafer 当单一 GPU，传统 command processor 对所有 SM 一视同仁、不感知 die 物理位置与数据放置，任务分配 oblivious；EP：专家计算全部在所在 die 执行（消除 D2D，如 MoEntwine），但负载严重不均。
  - baseline 全栈执行例子（一个 decode token 请求）：gate 在 256 个专家中选 8 个（DeepSeek V3，组合数达 C(256,8)≈4.4×10^12）→ 传统 command processor 无视专家放置把任务分给任意 SM/die → token 被 dispatch 到持有专家权重的远端单元，专家权重经 NVLink（多 GPU）/D2D（wafer，多跳 2D mesh）/PCIe（host offload）远程读取或迁移 → 热门专家所在单元拥塞、其他单元空闲（多数单元空转等重负载单元）→ 每层每 token 重复，数据移动占 MoE 延迟的 60-90%（DeepSeek V3、4K 序列，含 all-to-all 与专家权重）→ 无预测、无缓存、无放置优化，完全被动。编译框架层：论文未明确说明（无编译框架修改）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 论文方法是 model-centric 数据移动 profiling（4 个 2025 年 SOTA MoE 模型 235B-1000B、>24,000 请求、150GB+ trace）→ 提炼 6 个 system-agnostic insight（时序：Insight 1 prefill 预测 decode、Insight 2 跨层次内存管理；空间：Insight 3 专家放置感知分配、Insight 4 热门专家去中心化、Insight 5 共激活专家对分离、Insight 6 负载感知 serving）→ 两个 case study 验证：(1) wafer-scale GPU：两级 Global/Local CP + 任务分配算法（Algorithm 1，考虑专家放置、选择偏斜、D2D 代价，按 50-请求块把负载分给存有专家权重的 die 及相邻 die，均衡负载且最小化 D2D）+ 数据驱动预测器 + ATU/PDU 硬件管理 HBM（把预测的热门远程专家自动复制进本地 HBM，后续访问由 ATU 翻译成本地地址直读，无 D2D 流量）；(2) 现有 GPU 集群：用 prefill 阶段 trace（Insight 1）指导 decode 初始阶段专家放置（Remap 重排 + Dup 复制热门专家，Algorithm 2）。
  - 论文方法全栈执行例子（同一 decode token，wafer-scale GPU 路径）：算法层——prefill 已采集各层专家频率，预测器与分配算法有数据可用（Insight 1/3）；系统框架层——kernel 启动时 Global CP 拿 expert_reqs_dict + expert_die_map 运行任务分配算法，把每个专家的请求以 50-token 块分给本地 die 或相邻 die，预测器从 cross-token heatmap 预测下一 token 热门专家；编译框架层：论文未明确说明；kernel/运行时层——Local CP 把 sub-kernel 派给 SM 并配置 PDU 预测表，DeepEP 式 dynamic dispatch 均分复制专家 token；硬件架构层——D2D controller 的 PDU 拦截远程专家读取，按预测表把热门专家写入本地 HBM 并更新 ATU（is_local=1），之后 SM 再读该专家时 ATU 直接重定向本地 LLC/HBM，跨 die 流量归零；结果：hop 数减少 213x、MoE decode 吞吐提升 6.6x（wafer）；8×H100 上 prefill 引导放置使 MoE 计算最多提速 25%（1.25x）。对应关系：Insight 3→任务分配算法解决 oblivious 分配的负载不均与 D2D 浪费；Insight 1/2→预测器 + 硬件管理 HBM 解决"无法预取/缓存"的随机性假设；Insight 4/5/6→为静态放置/复制/去中心化提供设计规则。
