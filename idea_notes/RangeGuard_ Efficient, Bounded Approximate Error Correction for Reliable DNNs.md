## RangeGuard: Efficient, Bounded Approximate Error Correction for Reliable DNNs

- baseline方法是什么？
  - Baseline 是 GPU/HBM 内存的比特中心 ECC 体系：现代 GPU 每 256-bit block 提供 16 bit parity（6.25%），通常配置为 bit 级 SEC–DED（272-bit codeword 内纠任意单比特、检任意双比特，99.6% 检错覆盖）或 8-bit 符号 RS(34,32) 单符号纠错；HBM3 另有 on-die ECC（O-ECC，16-bit 符号纠正、12.5% 内部冗余）覆盖存储侧，系统侧 S-ECC（如 SEC）处理暴露错误。学术方案同样保护原始比特：Weight Nulling [33]（每个权重借用 LSB 做单 parity，仅检测、错则置零）、VAPI [34]（8-bit 量化权重借未用高位存 parity，DEC(64,50) 纠 2 bit）。痛点：(i) 预算结构性不足——HBM3 sub-wordline（SWL）driver 一次可破坏 32 bit burst，超 O-ECC 16-bit 纠正能力，S-ECC 的 SEC 只纠单比特，Meta 405B 训练 54 天在 16,384 个 H100 上因不可纠 HBM3 错误中断 72 次（~18 小时一次）；(ii) 预算分配错位——DNN/LLM 的真正威胁是极少数 exponent 位翻转制造的天文 outlier（BF16 e[7] 0→1 翻转 ×2^128≈3×10^38），单一位就足以打崩 LLM（Llama-3.2-1B 在 BER=10^-12、平均仅 0.15 flipped bit/trial 时 1/100 trial 崩溃），而 SEC-DED 把纠错预算均匀花在"并不关键"的 mantissa/低阶 bit 上。
  - Baseline 全栈执行例子（算法-系统-硬件；本文为 ECC/内存架构论文，编译框架/kernel 层论文未明确说明）：一次 BF16 LLM 权重/激活读请求 → HBM 中 SWL driver 故障损坏同一 32-bit burst → O-ECC 16-bit 符号纠正能力被 32-bit 故障超出 → 错误以 DUE 暴露到 GPU 侧 → S-ECC（SEC）只纠单比特或上报不可纠 → 未纠错误位落在 exponent e[7] → 0.5 变 2^127≈1.7×10^38 outlier → 经 attention 放大、residual 跨层保留、LayerNorm 稳定化，一个损坏 token 特征级联传播 → logits 与生成序列崩坏 → ARC-Easy 准确率跌向随机。算法-编译-kernel 层：论文未明确说明（无编译框架、无 kernel 算子改动）。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - RangeGuard 把保护对象从"原始比特"换成"每个值的语义元数据 RID"：(1) 元数据压缩（对应痛点 i）——32-bit 值用 4-bit RID 表达，恢复一个 32-bit 值需 ≥64 bit 冗余而恢复 4-bit RID 只需 8 bit，16-bit parity 预算下 RG 4b DSC 用 RS(12,8) 双符号纠错吸收 64 个损坏数据 bit（8× 比特方案的 8 bit），SWL 32-bit 故障被当作单个 RID 符号错误直接纠正；(2) 语义定向（对应痛点 ii）——纠错能力只花在"改变范围"（inter-range）的错误上，intra-range 错误（mantissa 低阶、sign 翻转等良性扰动）不消耗预算，稀缺 parity 花在真正打崩模型的 exponent 类错误上；(3) 有界近似纠错——纠错后不追求比特精确，把值替换为该范围代表值，误差上界为范围宽度，对 DNN 精度影响可忽略；(4) 多格式支持——按 exponent 域构造 MAE 最优 RangeMap（σ=4 保守覆盖 ±3σ≈±12 的 LLM 值域），物理地址未用高位 bit[57:54] 作 Map Tag 实现 per-region 保护模式切换（也兼容 SEC-DED 精确模式）。
  - 论文方法全栈执行例子：同一次 BF16 LLM 读请求 → 写路径：内存控制器用 RangeMap 把每个值映射为 4-bit RID（exponent 查表，256 个 8-bit comparator 并行、1 cycle）→ RS(12,8) 在 GF(16) 生成 4 个 parity 符号（16 bit）→ 丢弃显式 RID、存 256-bit 数据+16-bit parity → HBM 中 SWL driver 故障损坏同一 32-bit burst（值跳范围）→ 读路径：从取回数据重新生成候选 RID → 与存储 parity 过 RS 解码器（syndrome 检错 + Berlekamp-Massey 纠错，+1 cycle 读延迟）→ 该 burst 内损坏的 RID 符号被纠正（t≤2）→ 损坏值替换为该范围代表值 → 误差有界于范围宽度、不出 outlier → 数据返回 SM → attention/residual/normalization 处理数值合理的激活 → ARC-Easy 在 BER=10^-6 保持近 baseline 准确率（无保护在 10^-10 崩溃）。开销：Accel-Sim V100 上 11 个 Rodinia/Parboil workload IPC 仅 -0.008%；encoder+decoder 合计 11,100 μm²（RG 8b SSC）= 21,900 NAND2 ≈ 5e-7 Blackwell die。算法-编译-kernel 层：论文未明确说明。
