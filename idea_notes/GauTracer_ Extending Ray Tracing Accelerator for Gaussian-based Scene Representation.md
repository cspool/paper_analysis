## GauTracer: Extending Ray Tracing Accelerator for Gaussian-based Scene Representation

- baseline方法是什么？
  - baseline = 传统 mesh 导向的 GPU-RTA（Vulkan-Sim 中建模的 RTX2060 级 GPU，含 [48] treelet prefetching）上运行软件高斯光线追踪，Gaussian 作为 procedural primitive（非内置类型）注册进 Vulkan BLAS，交点/响应求值全部走可编程 shader。算法流程遵循 3DGRT [27]：ray-gen shader（一线程一射线，while(transmittance>threshold) 循环内反复 traceRayEXT 并沿 thit 前进）、intersection shader（procedural 叶求值：复杂数学计算 ray-Gauss 响应 alpha）、any-hit shader（按命中距离比较插入到全局内存中的 Closest Hit Buffer，保留最近 K 个命中）、closest-hit shader（front-to-back alpha 混合）。此前的代表方案 3DGRT [27] 还额外用 icosahedron 网格代理（每高斯 20 个三角形）来复用硬件 ray-triangle 单元。
  - 全栈执行例子：像素 →（算法层）相机射出主射线，生成 rayPayload →（系统框架层）Vulkan ray tracing pipeline：ray-gen 在 SM 上发 traceRayEXT，RTA 硬件遍历 BVH（ray-box 测试），命中 procedural 叶后把任务记入 task table（Vulkan-Sim 延迟调度）→（kernel 层）SM 执行 intersection shader：ALU 指令主导（平均占 80.3%），算 T' 变换/二次型响应/alpha，重复计算多 → any-hit shader 对全局 Closest Hit Buffer 做比较插入（shader 侧全局内存流量约占 BVH 遍历的 21%）→ closest-hit shader 混合并更新 thit，ray 前进进入下一 round →（硬件层）RTA 只做 box/triangle 内置测试，Gaussian 求值完全不经 RTA，shader 执行占 RT 总延迟 72.9%（带 treelet 时），RTX3090 实机 3DGRT 比 3DGS 光栅化慢约 7×。痛点：①software shader 指令冗余与线程发散（Shader 调用、RTA-SM 数据交换、全局 buffer 访存）；②3D/2D 双管线支持会导致运算单元重复、面积功耗翻倍；③Gaussian 命中节点大量被访问后因 buffer 容量/提前终止被丢弃，遍历冗余。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - GauTracer = 轻量微架构扩展把 Gaussian 提升为一等公民原语，对应解决三个痛点：①可重构 Ray-Gauss Intersection Unit（RGIU）把 intersection shader 搬进 RTA 固定功能单元（复用现有 TRAN 做世界→单位球空间变换，RGIU 完成交点+alpha 响应，分段线性 exp 近似），消除 shader 调用与全局访存（指令削减 14.7×）；②Max-heap 的 Any-Gauss-Hit Unit（AGHU）把 any-hit 的 hit buffer 管理搬进 RTA（每射线 16 项 Hit Gauss Buffer 用寄存器实现，shift-up/shift-down 维护堆，RGIU 输出直接流式进堆与遍历异步重叠），消除全局 buffer 操作（再削减 38.9× 指令），closest-hit 用 back-to-front 混合（式 7）避免额外排序；③treelet 化 BVH + far-node pruning：buffer 满后以当前最大命中距离为几何屏障（barrier flag），裁剪 ray-box 命中距离超阈值的节点子树，减少冗余访问与内存流量；RGIU 通过单 bit 模式开关复用 3 个点积/MAC/除法单元同时支持 3DGS 与 2DGS，解决痛点②的双管线重复。对比 baseline 得到 3DGS 平均 5.8×（4.1~9.6×）、2DGS 平均 7.3× 加速，能耗效率 6.6×/7.5×，RGIU 面积开销仅 baseline 运算单元组的 21.8%（AGHU+PRUNE 仅 +0.7%），PSNR 几乎无损（33.40→33.32 dB）。
  - 全栈执行例子：像素 →（算法层）同一 3DGRT/2DGRT 算法，Gaussian 仍按 (μ, Σ, o) 定义，叶节点存逆变换矩阵 T'（式 6）与 opacity/GID（64B/叶）→（系统框架层）Vulkan ray tracing pipeline 不变，但 ray-gen/closest-hit 外的 shader 被硬件吸收：traceRayEXT 交给 RTA 后不再回 SM 调 intersection/any-hit →（硬件层）treelet 遍历（256 节点/16KB 树簇 ping-pong）推进，node decoder 判别 2-bit 类型 → TRAN 复用单元把 ray 变换到单位球空间 → RGIU 求交点（3D：原点投影；2D：z=0 平面交点）+ alpha 响应（分段线性 exp，阈值 1/255）→ 命中则 AGHU 堆插入（满则根比较丢弃/替换+shift-down），barrier flag 按最大命中距离裁剪远节点 → closest-hit 在 SM 上按堆弹出 far-to-near 序列 back-to-front 混合（式 7）更新 C/T/thit → ray 前进，透射率低于阈值时提前终止。全程 Gaussian 求值不再经过 SM 通用指令与全局内存，只余 ray-gen 循环与 closest-hit 混合（剩余指令即属这两类）。
