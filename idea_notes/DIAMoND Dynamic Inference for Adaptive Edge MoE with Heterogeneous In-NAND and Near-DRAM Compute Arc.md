## DIAMoND Dynamic Inference for Adaptive Edge MoE with Heterogeneous In-NAND and Near-DRAM Compute Architecture

- baseline方法是什么？
  - Baseline = 三类既有边缘 LLM/MoE 加速方案：(1) GPU：A100（312 TFLOPS FP16/80GB/1.94TB/s）与 Jetson AGX Orin（64GB/30W/TensorRT-LLM）——容量装不下全量专家权重（Mixtral-8x7B INT8 需 47GB）、批量 1 解码带宽受限；(2) near-NAND 计算 ASIC：Cambricon-LLM（NPU + 16~64 近 NAND 计算芯片，3.2~51.2TB/38.4~153.6GB/s）与 Lincoln（LPDDR 封装 + 定制 Lincoln die 近 NAND 逻辑 + SoC NPU）——每 die 仅 1.6 GOPS（Cambricon）/38 GOPS（Lincoln），解码单 token 需 100~300 GOPS 线性运算、边缘需 4~12 tokens/s，故多数计算仍依赖 NPU 且需 256+ die 才够并行度（establish 功率高）；(3) 3D-AIMC：垂直堆叠 NVM 模拟存内计算跑 MoE，但直接映射、无 MoE 感知优化。
  - baseline 全栈执行例子（边缘设备跑 Mixtral-8x7B 单 token 解码，以 Apple A18 Neural Engine + LPDDR5X + NVMe 2.0 手机 NPU 为例）：模型推理算法层 = 标准 MoE 推理（路由对 attention 输出做线性投影取 top-k 专家，激活对应 FFN）；系统框架层 = 专家按需从 SSD 动态加载到 DRAM 再进 NPU（路由结果前向传播中才确定，无法预载）；编译框架层 = 论文未明确说明；kernel 调度层 = 论文未明确说明（NPU 常规算子执行）；硬件架构层 = 专家权重驻留 SSD，单专家单层从 DRAM 到 NPU 的加载延迟是单 token 解码计算延迟的 1.55~3.84×，SSD→DRAM 传输再加 15×。near-NAND 基线（Cambricon-LLM）全栈：算法层同标准 MoE；硬件层每 die 1.6 GOPS + 读延迟 ~20µs，算力不足 → 权重仍需搬出到 NPU 计算，带宽瓶颈依旧。
- 论文方法是什么？如何对应解决Baseline的缺陷？
  - 方法 = 异构 in-NAND + near-DRAM 2.5D ASIC + mask 映射 + AES 动态选专家（四项贡献）：① 存储介质按特性分工——in-NAND 模拟域 VMM 负责 FFN 专家矩阵（权重不出 NAND，每 die 279~1118 GOPS 远高于 near-NAND 的 1.6~38 GOPS），near-DRAM 负责 self-attention 与 KV cache（DRAM 高耐久、低 P/E 延迟，绕开 NAND 10^3 P/E 耐久限制），QKV Joint Caching Pipeline（W_Q 入 DRAM、W_K/W_V 留 NAND，Q 先出使 Softmax(QK^T) 与 K/V 投影重叠，−13.5% 延迟）——对应"near-NAND 算力不足 + NAND 耐久撑不住自注意力动态 KV"的缺陷；② mask-based in-NAND 计算——串行 NAND string 两层 WL 同选做 AND（一层权重一层 mask 门控电流），对角线/反对角线循环 mask 使 4×4 OU 阵列 4 个 read cycle 完成（无 mask 需 16 cycle）——对应"固定 VMM 形状（2048×16384）与 MoE 多样化矩阵尺寸不匹配"的缺陷；③ Round-Robin + Mask-Guided 映射（Alg.2）与 List Scheduling 部署（HLS 风格调度 Transformer 数据流图）——对应"专家随意放置导致被选专家冲突需多 iteration 或浪费存储（补 0）"的缺陷；④ AES 动态专家选择 + 专用 ASIC（Priority Queue/Conflict FIFO/Mask Pattern RAM/Pattern State Handler），阈值 T 权衡精度与并行——对应"动态路由选出的专家在 in-NAND 上冲突（共享输出端口/缺兼容 mask）降并行度"的缺陷。
  - 论文方法全栈执行例子（同一边缘设备跑 Mixtral-8x7B 单 token 解码）：模型推理算法层 = 路由输出专家分数后 AES 在线迭代替换（阈值 T 约束分数差，最高分必选、冲突专家换次高分无冲突者），k 个专家的 Up/Gate/Down 投影均单 read cycle 完成 → FFN 层固定 3 cycles；系统框架层 = 论文未明确说明（动态专家选择由 AES ASIC 电路在线执行，非软件 serving 框架）；编译框架层 = 论文未明确说明（离线部署 = Alg.1 mask 生成 + Alg.2 映射 + List Scheduling，属硬件映射调度而非编译器）；kernel 调度层 = in-NAND VMM：激活 bit 按 die 分配（8 die 位并行）、权重矩阵跨 die 复刻，OU 级子矩阵在 mask 门控下并行执行，输出经 ADC + Shifter + Adder + Control die 加法树聚合 8-bit MAC；QKV 流水让 attention 计算与 K/V 投影跨模块重叠；硬件架构层 = TSG 施加输入电压（1 导通/0 截止）→ WL 激活权重层 + mask 层 AND 门控电流 → BL 汇流 → 7-bit ADC 量化 → near-DRAM 侧 PE 阵列算 attention/KV cache（1620GB/s hybrid bonding 带宽）。结果：Mixtral-8x7B 197.3 tokens/s、5.8 tokens/J；较 Cambricon-LLM/Lincoln/3D-AIMC 提速 11.7×/5.8×/2.6×、能效 11.4×/5.55×/1.74×；较 A100 提速 2.54~10.30×、较 Jetson 9.48~208.59×；面积 149.02mm²、DIAMoND-L 功率仅 0.09× A100；消融 Mask 至多 1.73×、AES 至多 1.52×、合计 1.95×；in-NAND 承担 76% 工作负载。
