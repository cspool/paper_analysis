## Systolic Array（脉动阵列，含 weight-stationary 数据流）

- 脉动阵列（Systolic Array）是一种规则化的硬件计算阵列：多个处理单元（PE）按网格排列，数据沿网格边以固定节奏"脉动"流动，每个 PE 只做简单 MAC（乘累加），通过数据复用避免重复取数，实现高吞吐矩阵乘法。经典代表是 Google TPU 的 256×256 INT8 脉动阵列。数据流有三种典型形态：weight-stationary（权重驻留——权重预载入各 PE 不动，激活与部分和流动）、output-stationary（输出驻留——部分和在 PE 内累加）、input-stationary。ECHO 加速器的计算引擎集成 8×8 PE 的 INT4-FP8 混合精度脉动阵列，采用 weight-stationary 数据流，同时服务 RNN 矩阵乘（权重离线量化后驻留片上 buffer）与位姿优化的矩阵-向量乘。

  - ECHO 中脉动阵列的运转流程：RNN 权重 per-channel INT4 量化后离线存于片上 buffer，运行时按列广播/预载到 8×8 阵列各 PE（weight-stationary：权重固定）；激活与输入数据（FP8）从阵列边缘流入，沿行/列方向在 PE 间传递；每个 PE 内做 INT4×FP8 的 MAC 并把部分和传给下游 PE 累加，浮点累加器汇总结果；部分结果送 SFU（ReLU/Tanh）做非线性。位姿优化中旋转矩阵 R 是动态更新的（每次 Gauss-Newton 迭代变化），故在阵列前设 INT4 量化单元在线量化（缩放 8，指数位调整实现除 8），3D 点经 FP8 E4M3 单元转换后进入同一阵列做大批量矩阵-向量乘 x_i^c=Q_INT4(R)·Q_FP8(x_i)/8+t。weight-stationary 的好处：权重一旦载入即复用，适合权重小、逐帧重复使用的位姿变换与 RNN 推理，减少访存与带宽压力。

- Lembas 补充视角（ISCA'26，1D 线性脉动阵列算 SWG 分数矩阵）：Lembas extend 加速器用 16 kernel × 16 PE 的 **1D systolic array**（cascaded parallel array）算 banded Smith-Waterman-Gotoh 分数矩阵，每 PE 算矩阵一行、交错推进，每 cycle 用一个 cell 的四个输入（S[i−1][j−1]、E[i−1][j]、F[i][j−1]、b^j）算 S/E/F 三值。跨 PE 数据流显式编码流水时延：F 随 PE 从左向右移动**缓存在 PE 内**（无需跨 PE 传递）；E[i−1][j] 与 b^j 由 PE1 产生、PE2 迟 1 cycle 使用 → 走 E,b 寄存器链；S[i−1][j−1] 对角线依赖差 2 cycle → 走 2 元素 FIFO。每 PE 同时带历史寄存器（Hist Reg）支持 tiled bit-parallel traceback（前向算分与路径编码同流水）。效果：extend 48 GCUPS/FPGA（≈4× mm64 的 27.21）。此形态与 ECHO 的 2D weight-stationary 阵列不同：SW 比对是波前（wavefront）依赖、PE 间传递的是 DP 中间值而非权重/激活。

EVA 的脉动阵列用法（ISCA'26）：EVA 采用 32×32 INT8 混合精度脉动阵列，decode 时动态重配为 32×8 FP16 阵列（FP16 乘法分解为 4 个 INT8 乘法 + 6-bit 加法器 + XOR 处理指数/符号，复用 INT32 累加器）；两种数据流切换——32×32 INT8 weight-stationary（prefill/attention）与 32×8 FP16 input-stationary（VQ-GEMM decode）。decode 的 VQ-GEMM（X×码本 B，d=8、2^n=256）直接映射到 32×8 阵列，一块 256 cycles，与 Epilogue 单元流水重叠。相比传统 GEMV（batch=1 时 32×32 阵列仅 1 lane 活跃），VQ-GEMM 的 M 维 = V=K/d>512，阵列利用率大幅提升；Table VIII 显示 EVA 在 28nm/500MHz 下吞吐 498.49 GOPs（31.64× SA）、面积 1.414mm²、功耗 3.117W（FP16 支持是相对纯 INT8 阵列的增量来源）。

HiT 补充视角（ISCA'26，systolic 作为稠密模式的复用）：HiT 在 D×D 数据流下把整个稀疏加速器"重构"为 128×128 内积脉动阵列（TPU-like）：给 Compute Group 之间与 Compute Row 之间、Cluster 内外 DMAccum 之间增加 systolic 连接，把 128 个乘法器/Row 按 4 Group × 32 乘法器重排成 128×4 布局（4 级乘法流水线），Matrix B 空间映射到各 Compute Row（每 Row 一行），A 逐行流经各 Row，psum 沿 y 轴垂直累积形成最终 C；稀疏专用部件（PIDU、PSum Router、ring network）全部 bypass 并时钟门控、Local Buffer power-gated。关键点：systolic 是 HiT 三类数据流中面积/功耗最省的形态（54.6W 最低），但相对纯 TPU-like 多出稀疏部件的面积（166.3 vs ~91 mm²），导致 D×D 的 performance/area 比 TPU-like 低 1.23×——这是"统一架构覆盖全稀疏度谱"的固有折中。

IroKnight 补充视角（ISCA'26，systolic 上实现同周期 in-ALU 加解密与执行中认证）：IroKnight 在 TPU-like 128×128 INT8 脉动阵列（1 GHz、18MB scratchpad、16GB HBM/1TB/s）的每个 PE 上做安全化改造（Fig.3）：(1) 加密——复用原 Index Generator 的逻辑做成 Run-Ahead Index Generator，提前把 WBUF 索引同时喂给流水化 PadGen（每周期产生 128-bit pad，AES 类 10 轮结构）与 Run-Ahead FIFO（深度=PadGen 流水级数，同步 pad 与 ALU 操作）；PE 的 MACC ALU 输入输出各加一行 bitwise XOR——操作数从 WBUF/IBUF 读出后 XOR 出明文、算完再 XOR 回密文写回，明文只在 MACC 组合逻辑中瞬态存在；由于 pad 以 128-bit 粒度生成、操作数为 8-bit，一个 PadGen 可共享给 16 个 PE（128/8=16），pad 直接被 ALU 消耗、不落存储。认证（Fig.3c + Fig.5）——把 AES-GCM 认证的 ⟨Galois-Field 乘, XOR 累加⟩ 做成旁挂镜像路径：权重在写 WBUF 时（write-enable 硬连线触发）算 hash，输入激活在首列 PE 逐 PE 下传部分 hash（避免冗余计算），输出激活在末行 PE 从左到右算 hash（只有左下角 PE 需两组 ⟨GF-multiply, XOR⟩），hash 与 MACC 并行、仅增加 hash 的片外读写流量；关键路径仍为 SRAM 读、不降频。面积/TDP：加密 1.79×/1.76×、加密+认证 1.95×/2.18×（30W/9.4mm² → 52.9W/16.9mm² → 65.5W/18.4mm²），综合用 Synopsys Design Compiler 2023.09 + FreePDK45 + OpenRAM，DeepScaleTool 缩放 7nm。端到端（Tandem/GeneSys cycle-accurate 模拟器 + CACTI 6.0）运行时开销加密 0.2%、认证 3.3%，LLM 能量 ≤14%/≤18%。

L-PCN 补充视角（ISCA'26，systolic 作为 PCN 的 Feature Computation Unit，配合 Islandization Unit 削减 MLP 输入量）：L-PCN 的 FCU 由商用 AI 加速器风格的 16×16 systolic array + Dataflow Controller 组成，与 DSU、Islandization Unit 三者构成完整 PCN 加速器（Figure 5/13）。数据流分两路：Case1（Hub point subset）——32 点的特征 (32,6) 逐点流入 16×16 阵列做 MLP 到 (32,128)（共享权重），结果全部缓存进 Hub Cache；Case2（non-Hub point subset）——Overlap Detection 把 32 点分为 K 个重叠点（从 Hub Cache 取缓存结果，经结果增量补偿后直接进 Pooling）与 32−K 个非重叠点（特征进 16×16 阵列 MLP 得 (32−K,128)，进 Pooling 并回写 Hub Cache）。相比传统 PCN 加速器（每 subset 32 点全量进 MLP），L-PCN 通过减少进入阵列的输入点数本质削减 MLP 计算（feature computation 减 45.4%–80.6%），阵列本身仍是标准稠密 weight-stationary 脉动阵列；MLP 占 FC 步骤计算量 98%+，是岛化收益的主要落点。资源（PointNet++(c) 原型，Table II）：FCU 用 6,229 ALMs / 12,049 registers / 256 DSP / 9,437,184 BRAM，延迟 1,263,176 cycles（对比 Islandization Unit 仅 1,497 cycles）；ASIC 版 TSMC 28nm 1GHz 综合（Synopsys Design Compiler + TSMC memory Compiler SRAM + PrimeTime PX 测功耗）。

Omni-LUT 补充视角（ISCA'26，LUT-based 混合驻留脉动阵列，WS/OS-V 相位自适应切换）：Omni-LUT 是 32×4 LUT-based systolic array（TSMC 7nm @500MHz，0.53mm²，4.1 TOPS，等峰值吞吐对比 FPE/Tender 的 64×64 与 FIGLUT 的 32×4），每个 PE 含 4-激活组 LUT、32 个 binary weight 同时 Read-and-Accumulate（参考 FIGLUT [52]）。核心是 hybrid-stationary + phase-adaptive：prefill GEMM 主导时用 weight-stationary（WS，权重驻留 PE 本地寄存器、psum 沿 systolic 链传播，吞吐比 OS 高 1.3×，Fig.10 OPT-6.7B 4096/512）；decode GEMV 主导时重配置为 GEMV-optimized output-stationary（OS-V）——把 M×N 阵列重构成 1×(M×N) 宽输出 tile：LUT broadcast 从首行 LGU 垂直广播到全部 M 行（其余 LGU 门控省电）+ 每行独立并行 Weight FIFO（绕过垂直 PE-to-PE 权重路径）+ psum 在 PE 本地累加，全阵列 GEMV 并行，吞吐比 OS/WS 高 1.49×/1.68×。PE 微架构 hybrid：WS 模式用本地 weight register + 接收前一个 PE 的 psum 累加后前递；OS-V 模式 bypass weight register、用 row FIFO 流式权重 + psum 本地累加，由 mode register 控制、1 cycle 切换（每 query 在 prefill/decode 边界切一次，延迟可忽略）。计算按 bit-slicing：量化操作数的 bit-plane 数决定工作量（KV3 处理 3 个 bit-plane，比 KV4 的 4 个少 25% AA-GEMM 计算）。对比 FPE/Tender（64×64）/FIGLUT（32×4，AA 回退 FP 后端）：有效 GEMM 吞吐 1.78 TOPS vs FIGLUT 0.96，等峰值吞吐下能效高 1.25×-1.91×。评估链路：Design Compiler 7nm 综合 + PrimeTime PX + VCS 门级仿真校准 + DRAMPower LPDDR5 roofline 模拟。

UniCore 补充视角（ISCA'26，weight-stationary + S-FPMA 加法型可组合 PE 的位宽可扩展脉动阵列）：UNICORE 的 GEMM Unit 是 weight-stationary 的 2D Tile 阵列（图 7 以 4/8-bit 为例，自然推广到任意位宽）：权重（W）与激活（A）均沿列方向垂直馈入，权重预载入并驻留 PE 列，激活经 PreAdd 单元做指数偏置校正（T=A−B）后连续向下流动实现列宽复用；每个 PE 是双 slice 的 S-FPMA（Scalable FPMA）——W4A4 时左右 slice 独立做两个低比特 MAC，W8A8 时经内部进位链动态融合成一个宽 MAC，W16A16 时四 slice 级联。与乘法器型可组合脉动阵列（部分积成本 O(n²)、高位宽吞吐按 1/n² 塌缩）不同，S-FPMA 把浮点乘法近似为整数加法（R≈X+Y−B），slice 级联时面积/时延严格线性 O(n) 扩展；配合双链部分和累加数据通路（W4A4 两链求和、W8A8 两链拼接，无 mux）与 Rescale 反量化 + 全局 Accumulator，同一阵列在 W4A4/W4A8/W8A8/W16A16 均保持高利用率。Tile 组成 Group（PE 列数=量化 group size），支持逐 group 低比特量化；配套 Weight Buffer、Unified Buffer、Vector Unit 与 Control Unit。评估：SpinalHDL RTL + Synopsys Design Compiler TSMC 28nm@1GHz 综合，扩展 BitMoD cycle-accurate 模拟器注入 post-synthesis timing/energy 模型，512KB activation+weight buffer（CACTI）+ DRAMsim3（DDR4 25.6GB/s / HBM2 256GB/s）；GEMM 计算密度 W8A8 3.95 TOPS/mm²（2.47×–3.95× 优于 OliVe/Tender/M-ANT），W16A16 达 5.26× 优势。
