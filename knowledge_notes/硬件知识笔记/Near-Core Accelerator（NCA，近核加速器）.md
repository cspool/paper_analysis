## Near-Core Accelerator（NCA，近核加速器）

术语解释
一种新的 CPU 集成加速器抽象：拥有独立的内存读接口（不经核的通用访存硬件），但只把输出写回核架构寄存器、任务调用无状态，因此可被推测/乱序调用。ATX 论文提出的实现将 NCA 置于核 L2 旁。

CPU 集成加速器按"与核架构状态的交互方式"分成三类：ICA（核内，寄存器↔寄存器）、OCA（核外，内存↔内存）、以及本文提出的 NCA（取两者之长）。NCA 像 OCA 一样直接从内存系统读输入（拥有 UTE 这类专用访存硬件，MLP 高），像 ICA 一样永远不写内存、只写核寄存器，且调用后不留内部状态。两条性质合起来解决了一个关键矛盾：加速器执行结果可以被"撤销"（错预测时丢弃未提交的寄存器值与已取入缓冲的数据即可），因此 NCA 任务能像普通 load 一样在核 ROB 中推测执行、乱序发出、被 squash 后重发——这是 OCA 做不到、而 ICA 做得差（数据供给）的事情。论文配置：每核一个 UTE 控制多个 NCA，NCA 位于 L2 旁（"goldilocks zone"），共享核的 L2 TLB/MMU 与 L2 缓存做缓冲复用，从而用小 scratchpad 支撑大任务流。

一个 NCA 任务的完整流程（论文图 4）：①核经 ATX Port 把一条 ATX 指令发给 UTE → ②UTE 用指令中的元数据生成虚拟地址、向核的 L2 发读请求（L2 miss 走常规访存路径，L1 dirty 线由现有一致性机制供最新值）→ ③取回数据写入目标 NCA 的输入缓冲（scratchpad），数据齐后 UTE 通知 NCA 开始计算 → ④NCA 完成，UTE 读回输出 → ⑤输出经 ATX Port 写回核的物理寄存器文件（PRF），ATX 指令完成、在 ROB 头提交 → ⑥核可用输出做后续计算或自行写回内存。错预测时核通知 UTE：中断对应 NCA 任务、清空已取入的输入缓冲、释放 PAcc Port 与 Stream Units——因为 NCA 无状态且不写内存，无需任何回滚状态。NCA 的任务输出上限 = 输出寄存器容量（论文用最多 2 个 1KB tile 寄存器，即 2KB），输入上限 = scratchpad 容量（2×32KB 双缓冲）。

实现要点：NCA 本体是算术单元（论文建模 SPADE-like 的 SpMM/SDDMM 单元、8×8 µtile 双精度 GeMM 单元、DECA-like 解压单元 W=64/L=16），外加输入 scratchpad、PAcc Port 与任务状态位；控制与数据供给完全由 UTE 代管，NCA 自身无需知道核与内存拓扑。使用场景：输入在内存里、任务小而多、需与核细粒度交错的计算密集负载（稀疏 kernel、模型解压）；不适合粗粒度写密集操作（NCA 不写内存）或输入主要在寄存器/L1 的场合（此时 ICA 更好）。论文效果：vs 纯 CPU 2.7–4.0×、vs ICA 1.3–2.3×、vs L2 OCA 1.4–3.9×、vs LLC OCA 2.6–18×。
