## 密文侧信道（Ciphertext Side Channel）

术语解释
- 密文侧信道是确定性内存加密（AES-XTS，地址作 tweak）造成的泄漏：同一物理地址写入同一明文产生同一密文，攻击者通过内存总线嗅探/观察 DRAM 密文可检测"值重复或变化"，从而推断访问模式或恢复机密。

- 机制链：TME 用 AES-XTS(addr, D) 确定性加密 → 同一 (addr, D) 恒得同一 C → 攻击者可观察 DRAM 密文流，检测某位置密文是否变化 → 若程序写入相同明文（ORAM 中 dummy/未变块、stash 未变条目、常数时间密码的固定查找），密文不变就暴露"该位置没被修改/重复访问"。已知攻击：CipherLeaks（SEV 上破坏常数时间密码）、CipherSteal（TEE 神经网络窃取输入）、Wiretap（DRAM 总线插桩）；缓解：CipherGuard/Cipherfix（编译级）、Obelix（64 位计数器）。
- 在 ORAM 中的破坏力（论文 V）：⟨Read 0, Read 0⟩ 第二次读时块 0 以 1/2 概率留根节点、整树密文不变，而 ⟨Read 0, Read 3⟩ 必改变某路径密文 → 区分优势 1/4；暂存条目不变→密文不变，暴露暂存占用与 dummy 位置。这直接破坏 ORAM 的不可区分性。

```
攻击流程（威胁模型 II）：
1) 敌手经内存总线/侧信道观察 DRAM 密文读写流
2) 记录每个物理地址的密文是否随访问变化
3) 密文不变 → 推断该位置内容未变（dummy/重复读/常数时间查找）
4) 结合 ORAM 树/暂存布局 → 还原访问模式/stash 占用 → 破坏 obliviousness
防御（MC-ORAM）：加密前值 = (data XOR mask)||ctr，ctr 每次访问 +1
  → 同掩码周期：ctr 必不同（概率 1）
  → 跨周期：掩码独立（概率 1-2^-112 不同）
  → AES-XTS 密文每次访问不同 → 侧信道失效
```
- 例子：PathORAM 第二次 ⟨Read 0⟩ 若不刷新密文，攻击者观察到树密文无变化（概率 ≥1/4）即可区分两条访问序列；MC-ORAM 下同地址两次写入密文必变，区分优势归零。

- 实现：缓解分三级——编译器/软件加固（CipherGuard、Cipherfix）、系统级计数器（Obelix 64 位交错计数器，2× 带宽）、掩码+短计数器（MC-ORAM 16 位+112 位掩码+摊销刷新，1.125× 带宽）。
- 使用：任何依赖确定性 TME 加密的 TEE 工作负载（ORAM、安全数据库、机密推理）需评估密文侧信道；MC-ORAM 给出 ORAM 场景下的低开销修复。
