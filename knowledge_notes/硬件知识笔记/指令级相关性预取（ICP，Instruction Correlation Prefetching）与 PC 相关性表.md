## 指令级相关性预取（ICP，Instruction Correlation Prefetching）与 PC 相关性表

- ICP 是本文（ISCA 2026）提出的纯硬件不规则访存预取方案，核心洞察：不规则访存的"内存地址"虽不复现，但"产生这些访存的指令（PC）及其数据依赖关系"在程序中稳定复现。因此 ICP 记录指令级相关性（PC_pre, PC_suc）（PC_suc 发出不规则访存、PC_pre 是产生其输入值的前驱指令，两者间存在数据依赖路径），而非地址级相关性；当 PC_pre 的 cache line 响应（demand 或 prefetch）到达时，用其中数据沿依赖路径投机执行算出 PC_suc 的目标地址并预取。一条指令级相关性隐式覆盖其产生的成百上千条地址相关性，故元数据开销仅 448B（总 2.1KB），比时序预取器（最高 1MB）小三个数量级，复用率反而高约 10^5 倍。设计分两阶段：(1) PC 相关性检测——PC Selector/Classifier 用 Sample Table（按 PC 统计 demand miss / prefetch hit，LRU 淘汰，epoch 制，L1/L2 各一份）按式(1) S_suc=Top_n({PC_i | misses(PC_i)≥θ_miss}) 选 miss 最多的 PC 作 PC_suc 候选（基本预取器覆盖不到的最可能不规则），按式(2) Cov=PF_Hits/(PF_Hits+Demand_Misses)≥θ_cov 选 PC_pre^f（可被基本预取器服务，提升及时性），式(3) S_pre^nf=S_suc（链式嵌套如 *(*p) 中前级 PC_suc 可作后级 PC_pre）；PC Correlation Detector 用 ROB commit 信息 + 简化 O(N) 寄存器重命名（Node Table + Produce Map）构造以 PC_pre 为根的依赖树（≤128 条指令或 16 节点终止），路径存入 Correlation Table（每条 PC 最多 2 个后继，Counter 保留最频繁者，含 Friendly/Level/Corr PC/Corr Inst/Src Pred 字段）；(2) PC 相关性预取——监听 cache line 响应，Data Extractor 从 line 提取 PC_pre 数据（demand line 用访问 offset 直接取；prefetch line 用历史 offset 概率表、阈值 0.1 推断 offset），Lightweight Calculator 沿 Corr Inst（仅 ADD/SUB/SHL/SHR/AND/OR/XOR + 立即数，>70% 路径 ≤3 条指令、最长 13 条，1–13 cycle）递归投机执行到 PC_suc，Source Predictor 预测链外稳定源寄存器（单值 + 置信位），算出 PC_suc 地址发预取（prefetch 触发发到当前缓存级，demand 触发转发 LLC 提升及时性）。

- ICP 在缓存层级中的运转流程（Figure 3，两个阶段）：采样阶段——demand 请求带 PC 进入 Sample Table 统计（L1/L2 各一份）→ epoch 末按式(1)(2)(3) 把 S_suc/S_pre^f/S_pre^nf 写入 Candidate Table（S_pre^nf 与 S_suc 共用一个字段压缩）；检测阶段——ROB commit 指令经 8×16B 异步 FIFO 流入 PC Correlation Detector，命中 PC_pre 候选时触发依赖树构建：Produce Map 把物理寄存器映射到生产者节点 ID，Node Table 记录 ID/Parent/PC/CInst/Attr，源寄存器查 Produce Map 命中即建父子边，不相关指令写覆盖时无效化对应项，扫描重建 (PC_pre,PC_suc) 路径（DFS 仅 O(N) 次查表）写入 Correlation Table；预取阶段——MSHR 目标项扩展的 10-bit 压缩 PC（16 MSHR × 8 targets × 10 bit = 160B）随 cache line fill 回传，命中 Correlation Table 的 PC_pre（friendly 才用 prefetch line，非 friendly 只用 demand line）→ Data Extractor 取数 → Lightweight Calculator 沿链投机执行（链外操作数由 Source Predictor 补）→ 生成 PC_suc 预取请求。集成特点：不修改核的 decode/execute、无额外线程，ROB 扩展 2 个源寄存器 tag 字段（288×2×8 bit ≈ 576B），全部结构合计 2.1KB SRAM（≈40k–53k NAND2），能耗用 CACTI 22nm 评估（内部能耗仅占内存层次 0.24%）。消融：Data Extractor 移除导致 SPEC 性能明显下降（无法推断 offset → 遍历 line 内所有 offset → 多余预取 + 缓存污染）；Source Predictor 对 GAP 关键（双操作数中间指令的链外基址）；demand-trigger 占次要地位（SPEC 中 prefetch-trigger 贡献 9.02% vs demand-trigger 4.92%，后者在 gcc 等控制流密集、PC_pre 与 PC_suc 被资源争用拉开数千周期时补充及时性）。
