## 内存一致性模型（Memory Consistency Model，MCM）与 RVWMO（RISC-V Weak Memory Ordering）

内存一致性模型（MCM）定义多核/多 hart 系统中各执行单元（核、hart）发起的 load/store 之间的排序约束，决定并发程序可观察到的合法行为。最强的模型是顺序一致性（Sequential Consistency，SC，Lamport 1979）：要求所有内存操作按程序顺序在全局内存序（GMO）中依次执行——load 必须返回全局最近一次已提交 store 的值；弱内存模型（WMM）则允许一个 hart 的内存操作被其他 hart 以不同顺序观察到（如经 store buffer 转发、缓存失效延迟），以换取微架构性能，代价是并发软件必须显式同步。RVWMO（RISC-V Weak Memory Ordering）是 RISC-V 的官方弱一致性模型，定义在 RISC-V ISA 手册第 17 章：它以 GMO（对所有内存事件的全序）为骨架，规定程序序（po）中必须被 GMO 保持的"保持程序序"（PPO）子集，并配三条公理——Load Value Axiom（每个 load 返回在 po 与 GMO 中位于其之前、对同一地址最近的 store 的值）、Atomicity Axiom（LR/SC 配对的原子性）、Progress Axiom（前向推进）。RVWMO 满足多拷贝原子性（一个 hart 看到某写后所有 hart 都必须看到），并显式允许 store-buffer 转发等硬件优化。Web 来源：RISC-V 官方说明（https://docs.riscv.org/reference/isa/v20240411/unpriv/mm-eplan.html ）与形式化 Alloy 规范（https://docs.riscv.org/reference/isa/v20240411/unpriv/mm-formal.html ）。

在硬件架构中，MCM 是 CPU 内存子系统（store buffer、写合并队列、缓存一致性协议、load-store unit、LSU 重放逻辑、FENCE 实现）必须满足的契约；HARTBREAKER 正是在 RTL 仿真中检查设计是否违背该契约。运转流程例子（表 I store-buffer litmus：P0 执行 x←1、x1←y；P1 执行 y←1、x2←x）：两 hart 的 store 先提交到各自 store buffer → load x1/x2 可能读到对方尚未刷新的旧值 0 → 按 RVWMO 该结果（x1=0,x2=0）合法（store-buffer 转发造成的读读弱序），但 SC 禁止。RVWMO 通过 13 条 PPO 规则（如"同地址两连续 store 不得重排"、保数据/控制依赖、FENCE 同步、acquire/release、LR/SC 配对）约束 GMO 中哪些 po 边必须保持。HARTBREAKER 的 MCM 求解验证流程：RTL 仿真收集并发 load 返回值 → 把执行 trace 翻译成等价 litmus test（用 xor/sub 清零保留句法依赖）→ 交 MCM solver（Dartagnan）检查"该返回值组合在 RVWMO 下是否存在合法 GMO 排序"→ 不存在即内存一致性 bug（如 B1/N1 的非法 load-load 重排序）。论文用 PPO 规则覆盖概率（图 8）衡量测试程序对所有规则的压力：除 rule 8（LR/SC 顺序，因 ISA 允许 spurious SC failure 无法区分合法/活性 bug 而排除）外全部规则均被覆盖。

实现层面：硬件侧由 store buffer、内存一致性协议与 FENCE/AMO 单元共同实现模型；验证侧由两类工具落地——(1) 公理模型检查器（herd7 用 CAT 模型、Dartagnan 用 SMT 编码，见 Dartagnan 条目）输入 litmus 测试判定结果合法/禁止；(2) 形式化（PipeCheck/RTLCheck/TriCheck）对微架构模型做穷举。HARTBREAKER 的用法：作为 fuzzer 的验证后端，先把任意生成的多 hart 测试程序经"等价 litmus 翻译"（图 7 依赖构造法：store 值从确定性 ISS 获取、句法依赖生成时静态提取、load 返回值从仿真 trace 收集）转成 litmus，再交给 solver；窗口大小（两个同步锚之间的内存操作数）受 solver 容量限制——自研 solver ~10 个内存操作，改用 Dartagnan 后 ~100 个（讨论节）。QED 的 MCM 验证视角补充：MCM 由"线程内排序（within-thread ordering）+ 写原子性（write atomicity，全部写或仅 RMW）"两部分构成；QED 把序分为程序序 <p（MCM 要求保持的线程内序）与全局内存序 <m（其他线程观察到的访问顺序），并把 <m 扩展到外部一致性事件（invalidation、外部读、eviction、prefetch、miss）作为其他线程指令在本核的代理。QED 对三种 MCM 生成探索树（SC 26/TSO 36/RVWMO 167 棵，含同/异地址区分），用环检测判违反，把违反 trace 转成谓词决策树，再用 JasperGold 对 BOOMv3 的 LSQ RTL 无界验证（RVWMO 227 谓词、128ld/64st、10 天内全 proof）；two+two 结果保证谓词数与程序长度、in-flight 指令数、核心数无关（见"传递归约与直接序对"与"FSM fast-forwarding"条目）。RVWMO 侧 QED 视角：configurable FENCE 用 4-bit 注解排列前后 load/store 的相对序但 fence 之间无排序；atomic、load-reserved、store-conditional 支持 acquire-release 注解（类似 RCSC）。

täkōFormal 的 cache-aware ISA 级 MCM 补充视角（首个能刻画 cache miss/eviction/writeback、回调与 phantom 地址语义的 ISA 级 MCM）：传统 MCM（SC/TSO/RC/C11）没有 phantom 地址与 cache 事件回调的概念，无法刻画 täkō 这类可编程内存层级——因为 prefetching/替换策略这些以往隐藏的硬件细节现在直接决定程序功能结果。täkōFormal 在 ISA 级引入新事件（Rcb/Wcb/RMWcb=phantom 地址读写、Ms/Me=OnMiss 起止、Es/Ee=OnEvict/OnWB 起止、Fl=FlushRange）与新关系（cbo=单地址回调全序、viscb、vf/ef/eb），把 hb 从 (sb∪sw)^+ 扩展为含回调序的闭包，并用前缀封闭公理（VfWf/EbWf/CboVal/EvDirty/WbDirty/OEInt/OMInt/MeInt/VisCb 等，图 6）约束合法执行，从而禁止 r1=2,r2=0 这类反直觉结果并形式化 FlushRange 同步语义；该 MCM 与详细 Dafny 微架构模型之间用"ISM+归纳+refinement"做了端到端机器检查 soundness 证明（61K LoC 证明注解、119 条归纳不变量子句）。
