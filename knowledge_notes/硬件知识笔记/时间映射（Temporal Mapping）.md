## 时间映射（Temporal Mapping）

- 时间映射指把计算按时间顺序复用到相同硬件资源上的映射方式，与空间映射（spatial mapping，直接把计算逻辑铺在硬件上、每个逻辑单元占独立物理资源）相对。硬件仿真器的本质是空间映射：RTL 综合成门、跨 FPGA 铺开、每周期锁步通信。时间映射让多个任务随时间共享同一核，从而用少量核仿真远超其物理规模的设计。
- 在 Lotus（ISCA'26）中：核心洞察是"多 FPGA 仿真器被通信瓶颈拖累，空间映射没有意义"——设计适配单 FPGA 时可跑 100+ MHz，但跨 FPGA 每周期通信要几百 ns，速度被限制到几 MHz，每 FPGA 只用其可达速度约 1/100。Lotus 改为把设计编码为任务数据流图、把任务跨系统映射、用数千核"随时间"执行：①多个任务复用同一核（效率↑、可仿真远大于 FPGA 物理规模的设计）；②时间执行解耦通信与计算（隐藏跨芯片 200ns 延迟）；③FPGA 可以跑在 400 MHz 高主频（而非被锁步通信拖慢到几 MHz），用高频率弥补用核而非直接映射的开销。

- 运转流程（对比 emulator 与 Lotus 处理 NTT 设计）：emulator：综合 NTT → 门级网表跨 60 个 FPGA 空间展开 → 每模拟周期 60 FPGA 锁步交换信号（受限 800 KHz）→ 系统规模=可仿真电路规模。Lotus：NTT 的 11264 个模乘任务映射到 8 FPGA/544 tiles → 每模拟周期这些任务在 2176 个核上"随时间"执行（任务排队等待核）→ 核之间 token 异步传递、通信与计算重叠 → 同一 FPGA 同时执行多个不同任务的调用 → 2.47 MHz 仿真速度且只用 8 FPGA。
- 关键推论：时间映射下"更大的设计只是更慢地仿真"，而非"仿真不了"（emulator 则受限于芯片数）；系统规模与仿真规模解耦。

- 实现：静态任务映射（编译器用 PaToH 分层超图划分把任务分到 FPGA/tile）+ 任务单元管理任务执行 + token 网络异步通信 + 高主频核阵列。工程上 Lotus 用 68 tile/FPGA（每 tile 4 核+任务单元）、400 MHz、HBM2 16GB、25×25 蝶形 token 交换机、Aurora 光链路全互联。
- 使用：目标是"软件仿真性能追平甚至超过硬件仿真器"——Lotus 在 DSL benchmark 上比 emulator gmean 快 42%、少用 2.85× FPGA；同时保留软件仿真秒级编译与灵活性（支持 RTL 之外的周期级建模）。
