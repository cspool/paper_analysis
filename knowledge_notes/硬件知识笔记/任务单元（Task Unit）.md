## 任务单元（Task Unit）

- 任务单元是数据流任务执行架构中的硬件模块，负责任务数据流的全部管理工作：缓冲任务输入、在输入齐备时标记任务就绪、把就绪任务派发给核、在任务结束后为每条输出边产生输出 token。它把数据流语义从通用核的职责中剥离，核只执行任务函数本身。Lotus 每个 tile 有一个任务单元，与 4 个 RISC-V 核共享 tile。
- 在 Lotus（ISCA'26）中：任务单元包含输入单元、调度器、输出单元三部分。它静态存储整个数据流图（不同于 ASH 的动态展开）：每任务有唯一 taskId，绝大多数存储按 taskId 索引（无关联查找）；变长输入/输出 token 存储按区间索引（一级间接）。配置：1024 tasks/tile、8K 元素输入值与输出 token 内存、每任务最多 15 输入值/63 输出 token/255 输入 token、双版本（奇/偶周期）存储。资源占用 1914 LUT/2249 Reg/5.5 BRAM/4 URAM，比等价 ASH 任务管理硬件少 17× 逻辑。

- 运转流程（图 4/图 5）：①输入单元：token 网络送来的 (cycleId, taskId) token → 值写入输入内存、计数剩余输入 token，全部到达 → 该次调用入 ready queue；②调度器：从 ready queue 按优先级出队，存储任务指针等元数据，把输入从输入内存流式送入核；③输出单元：接收运行中任务产生的输出，任务 finish 后为每条输出边产生一个 token（复制输出值）经 token 网络发出。所有部件全流水化，每周期可处理一个 token。
- 关键设计：因为图静态，任务单元在配置时装载函数指针与输出 token 目的地；token 只携带 (cycleId, taskId) 而非完整元数据，减少通信；双版本输入存储使相邻模拟周期可重叠执行（一个周期的任务执行与下一周期的 token 到达并行）。

术语一般如何实现？如何使用？通过联网搜索让回答具体和精准。
- 实现：Bluespec SystemVerilog，全流水化。输入/输出 token 内存用 FPGA BRAM/URAM（每 tile 15 URAM、5.5 BRAM）；就绪队列 + 分层位图优先级队列（见"优先级执行"条目）管理派发顺序。核设有输入任务缓冲，使任务单元可在当前任务执行时派发下一任务（消除任务切换间隙）。
- 使用：编译器生成"任务单元配置数据"（任务表、边表、输入存储分配）+ 每 tile 可执行代码，host 经控制接口加载后启动；配置大小决定可支撑的数据流图规模（更大的图需要更多任务单元内存、更少 cache 的配置）。
