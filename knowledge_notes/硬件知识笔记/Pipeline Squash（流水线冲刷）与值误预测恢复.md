## Pipeline Squash（流水线冲刷）与值误预测恢复

术语解释
<pipeline squash 是 OoO 处理器对分支/值误预测的标准恢复机制：丢弃误预测点之后的所有指令及其投机状态，从正确后继指令重新执行。值预测论文中它是精度的硬约束——误预测率非零时 squash 惩罚直接吃掉投机收益。>

- 逻辑链：① 投机执行（分支预测、值预测）允许在不确定时抢先执行，但必须保证"架构正确性"——一旦发现预测错误，处理器要把执行状态回滚到误预测点：① squash/冲刷流水线中误预测点之后的所有指令；② 回滚重命名映射/PRF 分配、ROB/IQ/LQ/SQ 条目；③ 从正确的后继指令重新取指执行；④ 恢复机制的代价是损失已完成的投机工作（重执行）——因此误预测惩罚（本论文建模最小 21 cycles，与分支误预测相当）必须被收益覆盖，值预测精度须 >99%。
- 对值预测器的特殊影响（本论文核心动机之一）：投机更新污染——gDiff 用 OoO 引擎的投机结果更新 GVQ 与预测表，但分支/值误预测时这些未提交值可能来自无效路径；gDiff 采用 no-squash 策略（squash 时不清理值队列），错误投机值滞留队列继续影响后续预测（Fig.4），精度随时间恶化；EgDiff 改为：pipeline squash 时只回滚"投机段"（比 squash 点年轻的投机条目全部失效），"非投机段"（已提交值）保持不动——预测器只用架构正确值训练，杜绝污染。
- 值误预测的验证时机：load 在 LQ 完成执行 → 与投机 GVQ 中的预测值比对 → 不匹配置 misp 标志 → 尽早触发 pipeline squash（回滚依赖投机状态）；squash 同时清理值队列投机段。

- 硬件流程（EgDiff 下的一次值误预测）：① 指令 I6 被预测值 = base(I1) + 40，写入 PRF 唤醒依赖指令 I7 等；② I6 完成执行，LQ 返回实际值 ≠ 预测值 → GVQ 条目置 misp=1；③ 触发 pipeline squash：丢弃 I6 之后所有指令的投机状态（ROB/IQ/PRF 回滚）、重启取指（最小 21 cycle 惩罚）；④ 同时回滚投机 GVQ：比 squash 点年轻的投机条目失效；⑤ 非投机段不动——后续预测器更新仍只由已提交值驱动；⑥ lastmisp 机制随后全局抑制 1024 条指令内的预测输出，防止级联错误。
- 对比 gDiff：gDiff 在 squash 时不清理值队列（no-squash），错误投机值（如分支 I2 误预测路径上的值）残留在 GVQ 与预测表，持续污染后续预测——Fig.4 展示该场景；EgDiff 的 squash vq 策略（清理投机段）+ 非投机更新是论文"更新策略"实验的第三档（nonSpec 3.11%→3.25%，+squash vq →3.61%）。
- 相关设计（本论文 §III-D）：正确预测时值在 GVQ 内验证、不回写 PRF、不发 wakeup——误预测才回写 PRF 并 squash，因此高精度下 PRF 端口压力最小。

术语一般如何实现？如何使用？通过联网搜索让回答具体和精准。
- 实现：复用 OoO 处理器现有的分支误预测恢复基础设施（ROB 回滚、重命名映射 checkpoint、IQ/LQ/SQ 清理）；值预测器侧需要"预测缓冲与 LQ/ROB 同锁步"以便 squash 时按年轻/年老判定清理（EgDiff 的投机 GVQ 与 LQ 同构对齐）；gem5 O3 CPU（src/cpu/valuepred/ 的 squash(ThreadID, seq_no) 接口）支持在值预测器中实现 squash 钩子。
- 使用方式（复现）：在模拟器中配置值误预测惩罚（本论文最小 21 cycles）、比较 no-squash vs squash vq vs 非投机更新的 IPC/覆盖率（Fig.10：3.11% → 3.25% → 3.61%）；用 squash 频率/重执行损失解释各 benchmark（如 511.povray、531.deepsjeng 在 naive 置信下的负收益）。论文未明确说明 21-cycle 惩罚的具体恢复细节分解。
