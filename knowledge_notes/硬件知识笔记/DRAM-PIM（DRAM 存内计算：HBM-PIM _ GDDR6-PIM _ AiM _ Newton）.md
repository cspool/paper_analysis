## DRAM-PIM（DRAM 存内计算：HBM-PIM / GDDR6-PIM / AiM / Newton）

DRAM-PIM 在 DRAM 工艺存储阵列旁/内集成 MAC 等算术单元，行激活的数据直接在 bank 内计算，复用 DRAM 巨大的内部带宽与容量。优势：容量大（GB 级/bank）、向量并行度高（SIMD，控制器集中控制、全部 bank 共享指令上下文）、与标准 DRAM 接口兼容（GDDR6/HBM）。代表：SK hynix AiM（ISSCC'22，1y-nm 8Gb GDDR6-AiM、16Gb/s/pin、1 GHz PU、1 TFLOPS MAC、支持多种激活函数）、Newton（MICRO'20，把 32:1 列译码器放在逻辑侧）、Samsung FIM-DRAM/HBM-PIM、UPMEM（见本库 UPMEM DPU 条目）。CompAir 采用 CENT（ASPLOS'25 "PIM is all you need"，GDDR6-PIM + CXL，开源 artifact https://github.com/Yufeng98/CENT）的 bank 配置：32MB/bank、16 MAC/bank、BF16，tRCDWR=14ns、tRCDRD=18ns、tRAS=27ns、tCL=25ns、tRP=16ns。

从硬件架构角度拆解术语，比如术语如何在硬件架构中发挥作用，给出术语在硬件架构中运转流程的具体例子。通过联网搜索让回答具体和精准。
CompAir 中 DRAM-PIM 的角色 = 可扩展性 + attention + memory-bound 算子：bank 内 16 输入 BF16 MAC 以 SIMD 执行 GeMV 形态（QK^T、SV 的 K^T/V 输入相关、无 batch 复用、权重每次推理都变，不适合权重驻留的 SRAM-PIM）。执行流程：激活行与权重行被激活后经列译码器选通进 MAC 阵列累加，结果写回 bank 或经 global buffer 做跨 bank 归约。两个关键设计点：(1) 列译码器决定读带宽——Newton 32:1 每操作只出 32B，CompAir 拆成 8:1（SRAM 用）+4:1 提升带宽（+15% 面积、Llama2-13B 端到端 1.15–1.5×）；(2) 跨 bank 归约是固有弱点——global buffer 带宽有限且需串行访问 bank，传统 DRAM-PIM 因此回避 input-split、只用 output-split（代价是输入广播与形状失衡，输入输出比 >17:1）。

术语一般如何实现？如何使用？通过联网搜索让回答具体和精准。
实现：MAC 阵列放在列译码器外侧以最大化逻辑集成密度（代价是位宽受限）；指令统一广播（SIMD）；非线性/重排交给外部（PNM/NLU）或 NoC。CompAir 的增强：解耦列译码器、每 bank 256 HB bonds 直连逻辑 die、归约与非线性卸载给 CompAir-NoC。评估：ramulator2.0 推演时序、CENT 模拟器推演指令执行与 CXL 通信。使用方式：GeMV 形态、长序列 attention、需要容量与带宽的算子。CHIME（ISCA'26）把该家族扩展到 DIMM 形态：bank PU 用 DRAM 工艺集成在 bank 旁（等效带宽相对主机 >30×），rank PU（softmax/adder/re-layout 单元）置于 buffer chip 逻辑工艺；2TB DDR4-3200 + 13.0TB/s 的配置按 DRM 分析是带宽与容量均衡的最优加速器（HBM-PIM 容量不足、CPU 卸载带宽不足，DIMM-PIM 两者兼顾，见 CHIME-PIM 条目）。DCC（ISCA'26）给出 HBM-PIM 在 GPU-PIM 异构系统中的具体建模：每两 bank 共享一个 16-way FP16 FPU 与两个 16×256-bit GRF 寄存器（每 bank 一个），由 Host 内存控制器经 DRAM 计算命令驱动；平台为 A100 + 5 个 HBM3 PIM 设备（5.2Gbps/pin、333MHz、16 pCH、每 pCH 64 bank；tCK=0.79、tRCD=19、tRP=19、tCL=19、tCCD=4、BL=2）。DCC 编译器自动生成数据分区+计算调度后，GEMV/RED/VA/RELU 平均较 HBM-PIM 默认固定分布再提速 1.53×/2.09×/1.64×/1.54×（对 GPU 至多 7.68×、平均 2.21×）。注意 16-way SIMD 宽度是调度剪枝的硬约束：每 core 分配的维度尺寸非 16 倍数无法满带宽（RED 1024/2048 下 HBM-PIM 默认 tiling 因此落后 GPU 0.48×，DCC 提速 2.26× 反超）。

P3-LLM 补充视角（ISCA'26，低精度 PIM 计算单元 PCU）：P3-LLM 在 HBM-PIM 之上设计了支持混合数值格式（W4A8KV4P8）的低精度 PCU——1 个 PIM channel 含 8 个 PCU、每 2 个 bank 共享 1 个 PCU 摊销面积；因权重/KV 为 4-bit，每 PCU 配 64 个乘法器匹配 HBM 256-bit 列访问粒度（相对 HBM-PIM 的 16 个 FP16 乘法器吞吐 4×），但保持与 HBM-PIM 相同的输出寄存器数量、仅增加 16-bit 输入寄存器带宽（规避 SIMD 每乘法器配 32-bit 累加器的寄存器开销）；PCU 含 16 个 PE、计算 1×4×16 GEMV tile（4 个 8-bit 输入 × 64 个 4-bit 权重 → 16 个 32-bit 输出）；每个 PE 用 6-bit 定点乘法器（signed 输入尾数 5-bit 含隐藏位 + 符号位；INT4-Asym KV 加 zero-point 后 5-bit；BitMoD 权重 6-bit）执行 4-way dot product，4-bit 输入指数移位乘积，4:2 压缩树归约后 32-bit 定点累加，去除 FP16/FP32 MAC 的高精度乘法器与指数对齐模块。评估：SystemVerilog RTL + Synopsys Design Compiler（TSMC 28nm）综合，DeepScaleTool 缩放到 HBM-PIM 的 20nm，按 DRAM 工艺 10× 低晶体管密度修正；HBM 面积开销 17.5%（PCU compute 8.4mm² + buffer 6.2mm²，低于 25% 逻辑占比上限，相对 HBM-PIM FP16 仅 +1.1%）；PE 对比：P3-LLM 4 MACs/cycle、1109.2 µm²（1.08×）、0.18 pJ/MAC（0.26×），优于 BitMoD（2 MACs、1291.6 µm²、0.61 pJ/MAC）与 MANT（2 MACs、717.3 µm²、0.40 pJ/MAC，因自适应数值类型需昂贵加法器加两个部分和）；解码性能平均 4.9× 相对 HBM-PIM、2.0× 相对 Ecco、3.4× 相对 Pimba、7.8× 相对 NPU-FP16。系统级：4 NPU core（128×128 systolic array + 128-way vector unit + 16MB CACTI 建模 scratchpad）+ 16 pseudo HBM channel，NPU 1 GHz / PCU 500 MHz（tCCD_S），PIM 部分按 Newton 方法论扩展建模（cycle-level simulator 未开源）。

RoCC 补充视角（ISCA'26，与双模 HBM-PIM 方案的对比）：RoCC 论文把 T3（ASPLOS'24，DMA 数据传输 + PIM 归约）作为最接近的硬件 SOTA 对比，并指出双模 HBM-PIM 的缺陷：PIM 必须在计算模式与内存模式间切换（[55][56][62]），PIM 归约会阻塞普通内存请求，在 GEMM 访存密集时产生严重争用。论文在实用双模 HBM-PIM 系统上实现 T3 并对比：4 GPU 下 T3 23% vs RoCC 48% 加速，RowLinear kernel 差距最大——因为 RoCC 用"原生近内存 ROP"做归约，而双模 PIM 的 GEMM 访存与 PIM 归约相互竞争。结论：RoCC 复用 ROP 免去 PIM 模式切换，是更轻量（2.4% L2 slice 面积）的近内存 CC 方案。
