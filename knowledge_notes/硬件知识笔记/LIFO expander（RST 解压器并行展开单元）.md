## LIFO expander（RST 解压器并行展开单元）

术语是什么？回答尽量完整，回答逻辑链中每一步都解释出来。通过联网搜索让回答具体和精准。
- LIFO expander 是 RST 解压器的核心并行单元：多个独立的后进先出（Last-In First-Out）栈式展开器，把压缩的 DRAM 块分段并行展开成原始字节。因为 RST 的序列字典是显式存储的（每个字典索引映射回 2–5 符号序列，展开表 ≤2880 bits 只读结构、寄存器实现供并行访问），多个字典索引（含深度嵌套索引）可以同时展开，无需像 LZ 流式解压那样从页首串行。
- 从硬件架构角度拆解术语（Fig.17 端到端例子）：压缩输入 [2*, 1*] → 展开表查 1*→XY、2*→Z1*Y → 并行 LIFO 展开得到 ZXYYXY。运转流程：① 位置元数据前缀和定位含目标块的 DRAM 块；② 静态符号字典解码（压缩数据 ~8 cycle、序列字典 ~16 cycle，可并行）；③ DRAM 块均匀分段，每段一个 LIFO，每个 LIFO 维护一个初始化为其段的栈，每周期最多 2 次操作：栈顶是字面量则 pop 到输出缓冲，是字典索引则按倒序 push 对应序列入栈；④ 所有栈清空后各段输出拼接成解压块。栈组织使数据在被完全展开前保持压缩态，栈小而省面积。最坏情况（极端压缩+深嵌套）：n 符号块的展开树含 O(n) 个字典项、需 <4n 次栈操作，64 符号块 <128 cycle 完成（平均 18ns@2.5GHz）。

- 硬件实现：多个 LIFO expander 共享公共展开表（寄存器实现），随 RST 解压器综合（0.03mm²、91mW、13.3GB/s，ASAP7 2.5GHz），功能正确性经 post-synthesis gate-level 仿真 100 万页 byte-exact 验证；RTL 开源（Verilator 验证，见 Verilator 条目）。使用场景：内存控制器中随机解压任意请求的 64B 块；对比 TMCC ASIC Deflate 流式解压（需顺序重建整页字典）与 OCP Zipline/IBM/CDPU 的流式解压器（1–2µs 级延迟）。
