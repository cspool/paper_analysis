## 任务数据流执行（Task Dataflow Execution）

- 任务数据流执行是一种并行执行模型：程序被编码为数据流图，节点是"任务"（task），边表示数据/顺序依赖；任务在其所有输入 token 到达后变为就绪，被派发到核上执行，输出 token 沿边送往下游任务。与指令级数据流（按指令粒度、动态标记匹配）不同，任务数据流以函数为粒度，常由硬件任务队列/任务单元管理就绪与调度。Lotus 用它把循环级仿真表达为"每个模拟周期重放一张静态数据流图"。
- 在 Lotus（ISCA'26）中：任务被实现为运行在 RISC-V 核上的函数（如 add/mult 任务各约 2 条指令），任务单元静态存储整个图（函数指针、输出 token 目的地、输入存储），不动态展开图（对比 ASH 的动态展开）。每个任务通过 stream_outputs（流出一个/两个寄存器值作为输出）与 finish_task（结束当前任务释放核）两条自定义 ISA 指令支持。tile 内共享内存 + token 值传递构成完整通信模型；任务输出值产生后由 task unit 为每条输出边复制成 token。

- 运转流程（Lotus 一个任务的一生）：①输入 token（携带 (cycleId, taskId)）经 token 网络到达任务单元输入单元 → 写入输入内存并计数；②全部输入到达 → 该次调用入 ready queue；③调度器按优先级出队，把任务指针与输入流式送入某个空闲核；④核执行任务函数（可含内存访问与副作用）；⑤输出单元接收输出，为每条输出边产生一个 token（复制输出值），经 token 网络送达消费者；⑥核执行 finish_task 后空闲，可执行下一任务。每个模拟周期图被完整执行一遍，静态映射保证每个任务固定在某 tile。
- 与 ASH 的关键差异：Lotus 利用图静态性，任务单元存储固定数量任务、足够输入存储、永不溢出到内存，taskId 直接索引（无关联查找），逻辑比 ASH 动态展开方案少 17×；内存模型采用"任务 store 先于后续任务 load"的弱顺序 + DeNovo 式自失效（tile 内一致性，跨 tile 仅靠 token），无跨 tile 一致性硬件。

术语一般如何实现？如何使用？通过联网搜索让回答具体和精准。
- 实现：任务单元（输入单元/调度器/输出单元）+ token 网络 + 定制 RV32IM 核（4 级流水、数据/PC 旁路、输入任务缓冲实现任务间零间隙切换）。核实现 1474 LUT，比 Taiga/VexRiscv/PicoRV32 等开源软核每 LUT 性能更高。
- 使用：用 Lotus DSL（C++ 嵌入式，In/Out/InOut/PartialIn 等参数类型）或改版 Verilator 生成任务代码与图配置；任务粒度可小到单条指令（论文用 coarsening 合并以提高计算/通信比）。系统峰值约 900 GIPS、每秒派发超 2000 亿任务。
