## 压缩翻译条目（CTE）与位置元数据（location metadata）

- 压缩翻译条目（Compression Translation Entry, CTE）是硬件压缩内存系统中把 OS 物理页映射到压缩 DRAM 中机器物理位置的每页翻译项；位置元数据（location metadata）记录压缩页内各逻辑块（64B）的存放位置，是随机访问压缩页所必需的。与未压缩内存"块 N 在偏移 N×64"不同，压缩块变长变对齐，必须靠元数据定位目标块。位置元数据精度不足会造成内存碎片/泄漏，故需精确跟踪块间距离。
- 从硬件架构角度拆解术语：朴素设计每块用 6-bit 偏移（log2 64）精确记录与前一逻辑块的字节距离，64 块/页共 48B——吃掉 128B 字典空间的一大部分。RST 的 48B→8B 压缩（§IV-B）：洞察是 6-bit 偏移里很多位用于精确到块内字节，这种块内信息可嵌进各 DRAM 块自身——每个 DRAM 块开头嵌 1 个 6-bit 偏移记录其内首个逻辑块的起始位置（计入压缩大小），第二个逻辑块的位置由解压第一个后隐式计算；页级元数据放宽为"粗略距离"，量化到 DRAM 块：64-bit 向量，每位对应一个逻辑块，"0"=与前任同 DRAM 块、"1"=在下一个 DRAM 块。定位 = 对 64-bit 向量做前缀和（~1ns 操作）后取对应 DRAM 块。在 DyLeCT 系统中，8B 位置元数据与 CTE 共存，每页翻译项 16B。
术语一般如何实现？如何使用？通过联网搜索让回答具体和精准。
- 实现：页级位置元数据作为压缩页翻译项的组成部分；块内 6-bit 偏移随压缩数据存储。zsmalloc 式分配器把变长压缩页打包进 DRAM（放置开销 1–2%，TMCC/DyLeCT 采用），不可压页经 CTE 原样存储。使用流程（读请求）：CTE 查压缩页 → 64-bit 向量前缀和定位含目标块的 DRAM 块 → 取该块（块头 6-bit 偏移定位块内目标逻辑块）→ 解压。对比：无位置元数据的流式 LZ 压缩页无法随机访问单个块。
