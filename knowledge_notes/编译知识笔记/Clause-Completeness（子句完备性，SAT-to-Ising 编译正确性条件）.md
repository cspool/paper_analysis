## Clause-Completeness（子句完备性，SAT-to-Ising 编译正确性条件）

术语是什么？回答尽量完整，回答逻辑链中每一步都解释出来。通过联网搜索让回答具体和精准。
Clause-completeness 是 SATIC 论文定义的第二个 SAT-to-Ising 编译正确性条件：若一个变量被选入子问题，那么所有包含该变量的子句都必须被包含进该子问题（该变量上的约束全集在子问题内一致考虑）。理由：QUBO 求解器对变量 x 倾向于选择最大化其所在子问题内被满足子句数的赋值（相当于对含 x 的全部子句做多数投票）；若部分含 x 的子句被排除在子问题外，赋值可能被偏置，且不同子问题分别优化同一变量的不同约束子集会产生冲突赋值，拖慢或阻止收敛。代价：clause-completeness 可能增大子问题规模（一个变量的所有约束子句都要装进去）。

在 SATIC 编译框架中，clause-completeness 由"沿 VIG 的 BFS 邻域选变量"保证：VIG 中相邻变量共享子句，BFS 从根扩散时把整簇约束装入子问题。运转流程：
```
# 目标：含 x3 的子句 C1=(x1∨x2∨x3)、C2=(¬x3∨x4∨x5) 要么都进、要么都不进同一子问题
# SATIC：freeze 边界变量（x4,x5）后，含被选变量的全部子句保留在子 CNF → 完备
# 反例（QUBO 层随机/能量选变量）：C1 与 C2 各自单独成子问题，共享变量 x3
#   → 两子问题分别对 x3 定值可能冲突（C1 的解让 x3=0 满足 ¬x3，C2 的解让 x3=1 满足 x3）
# 受控实验（UF75，50K 迭代，100 实例）：
#   违反 clause-completeness（但 ancillary-aware）→ 0/100 解出（完全失败）
#   SATIC（两条件都满足，无 tricks）→ 87/100；SATIC++ → 100/100
```

术语一般如何实现？如何使用？通过联网搜索让回答具体和精准。
实现：变量选择基于 VIG 邻域（BFS）而非任意集合，配合 freeze 消除边界影响；避免按能量/度随机挑变量跨子句。使用：与其他分解器（qbsolv/EID、Cilasun et al.）对比时，clause-completeness 是 SATIC 收敛的关键来源（论文受控实验证明其缺失导致完全无法收敛）；它在概念上与"把约束视为整体"的 SAT 结构保持一致，是 SAT-to-Ising 编译器正确性评估的框架性条件。
