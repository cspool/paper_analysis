## Liveness Analysis（活跃性分析）

- Liveness analysis 是经典编译期数据流分析：对程序每个点计算"某个变量/数据在其后是否仍可能被使用（live）"。在寄存器分配中它决定变量能否共享同一寄存器；MANATEE 把该概念移植到页级——对静态划分的 NVM 逻辑页计算 live range（活跃区间），live range 相交的页（同一时刻都存活）在着色时不能共享同一 SPM frame。
- MANATEE 的页级 liveness 依赖别名分析（Andersen 算法 [7]）在 CFG 上完成，指针精度 >99%（97% 指针指向全局数组、地址从 .map 可见；mayalias 指针保守分配新颜色或最远可用颜色）；已知迭代次数的循环先 unroll 再做指针分析，未知迭代次数的循环/I/O 页保留专用颜色。

- 运转流程例子：程序访问全局数组 arr 的多段（如 arr[0:64]、arr[128:192]），.map 给出其在 NVM 的地址 → 划分为页 P1、P3 → CFG 上逐基本块做页级 liveness：若路径 A 上 P1 的访问结束后（其后不再访问 P1）在访问 P3 前有断电（T_on 窗口外），则 P1/P3 可共享颜色；若在窗口内则冲突、需不同颜色或窃取窗口外颜色。liveness 结果直接驱动干扰图构建与滑动窗口回收。
