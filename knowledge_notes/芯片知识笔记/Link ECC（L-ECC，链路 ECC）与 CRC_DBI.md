## Link ECC（L-ECC，链路 ECC）与 CRC/DBI

Link ECC（L-ECC）是保护内存控制器与 DRAM 之间高速 I/O 链路传输错误的机制（Cerberus 论文 Fig.1 中绿色一层）：发送方在传输前对数据附加校验冗余，接收方到达即校验，出错立即触发重传，从而阻止被破坏的数据写入 DRAM 阵列（写路径）或送到主机（读路径）。逻辑链：I/O 速率到每 pin 数十 Gbps、信号摆幅不断降低 → 传输中瞬态错误不可忽略；S-ECC 只在读时解码、发现不了写路径错误（坏数据会永久存入 DRAM），且低成本/低功耗系统常省掉 S-ECC → 需要链路层一线快速检测 + 重传。不同内存形态的实现：DDR5 每 4 个 DQ 配 8 位 CRC；HBM 每 32 个 DQ 配 1 个数据奇偶位，L-ECC 经专用 sideband pin 传输、不占主数据接口带宽；LPDDR6 用 16 位奇偶，可配置为单错纠正或纯检测。本文语境下还涉及 DBI（Data Bus Inversion）：LPDDR6 的 2B 外部冗余时隙在 L-ECC 冗余与 DBI 信息间复用（降低总线翻转功耗的技术）。

L-ECC 的物理位置在通道边界（DRAM 的 PHY/I-O 与控制器 PHY 之间），是芯片间互连的可靠性层：它与 O-ECC/S-ECC 的物理域正交（O-ECC 管 die 内、S-ECC 管端到端），因此独立设计时三层的冗余互相不可复用，这是 Cerberus 指出的"分层碎片化"结构问题。运转流程（HBM4 写路径）：控制器对 32B 数据算 1B 奇偶 → 数据走主接口、奇偶走 sideband pin → DRAM 接收端校验 → 通过则连同冗余写入阵列；错误则 ALERT 请求重传。带宽利用上的芯片设计取舍：sideband 传输使主数据接口不损失拍数（HBM4 做法），而 DDR5 的 CRC 要占额外 beat（16 拍突发中加 2 拍，12.5% 传输开销）。Cerberus 的结构性改造：不再在控制器做写路径 L-ECC 编码，而是把一次编码产生的 32b 冗余中 R2 部分直接由 DRAM 内 Decoder1 用 H2 校验——链路检测与片上纠错共用同一份冗余，物理上消除了独立 L-ECC 编码器与 sideband/额外 beat。

实现：线性校验（奇偶/CRC）的编码器在发送端、校验器在接收端，检测失败走重传协议（如 ALERT/写重试），属于"检测 + 重传"而非强纠错（优先级是低延迟检测）。选择上：CRC16 的漏检概率约 0.002%（比 SEC-DED 的约 0.4% 低两个数量级），所以 HBM4 的 2B S-ECC 预算更常被配成 CRC 而不是 SEC-DED；HBM 的 1B 奇偶对宽位错误（DQSE 数据选通错误）只能约 50% 检出。Cerberus 的做法是让 16 位 R2 的 H2 满足 CRC8 条件（任意 8 连续列线性无关）并整体提供 1−2^-16 ≈ 99.998% 的随机错误检测，等效 CRC16 级检测能力，同时同一 H2 还做片上 SEC-DED——即"检测/纠错同码复用"的实现范本。使用场景：所有带高速 I/O 的 DRAM（DDR5/HBM/LPDDR6）的写路径一线防护；在无 S-ECC 的低成本系统里它是唯一防护。
