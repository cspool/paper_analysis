## Hotness Separation（热度分离，HS）

术语解释
- SSD 写分配策略：把写请求按热度（更新频率）分成热/冷两类，分别写入不同 block，使同一 block 内的页热度相近、可同时失效，从而降低 GC 的有效页迁移成本并减少 GC 触发次数。

- 若一个 block 内混合热（频繁更新、很快失效）与冷（长期有效）数据，GC 时热数据早已失效、冷数据拖累迁移成本——有效页比例高、每次 GC 迁移量大。热度分离让同类热度数据聚集在同一 block：热度相近的页会在相近时间点失效，block 内可同时失效大量页，GC 被触发时迁移更少有效页、单次回收更多空间。论文的实现细节：热度阈值设为 1 分钟（>60% 的写请求在该窗口内被更新，[19] 依据），超过阈值的请求归为热/冷并路由到对应 block。
- 从系统架构角度拆解术语：HS 是 FTL 写分配（write allocation）层面的调度策略，与 GC 调度协同。论文数据：HS 较 baseline 平均延迟降 25.0%，GC 数降 16.7%、平均 GC 时间降 21.3%；对读密集负载（USR_1、SRC1_1）GC 频率分别降 20.3%、27.9%，显著减少 host I/O 阻塞。HS 也是 LOONG 两个方案（8-stride、pSP-GC）的叠加组件：pSP-GC + HS 时 GC 数与 HS 持平、但 pSLC 迁移与重编程进一步压低迁移成本与补偿 GC 开销。

- 实现：FTL 维护热度统计（请求更新时间窗口），写分配器按热度路由到热块/冷块；阈值（1 分钟）可配置。使用上，HS 常与其他优化叠加：在 LOONG 中，HS 减少迁移页数（pSP-GC 有效页数较 baseline 降 32.4%），pSLC 编程与长跨度重编程进一步降低迁移成本并消除容量损失；写密集负载（如 SRC1_2）因块内热度相近，HS 只降 2% GC 频率，收益有限（延迟仅降 9.1%）。最坏场景（全部为热数据）下 pSP-GC 退化为 HS 水平。
