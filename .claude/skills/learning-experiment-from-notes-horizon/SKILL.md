# Learning Experiment from Notes — Horizon Summary Agent

只读。用中文回答。不要人为缩短。

本 skill 是 **Horizon Summary Agent**，负责**单层**的水平分类总结。分类目标是**减少冗余**，但**保持每个类别的回答足够具体**——分类后的每个条目必须保留原答案中的关键细节（伪代码、实现框架、实验数据、笔记来源）。**不跨层。**

## 输入

scheduler.ts 将参数直接嵌入此段（`fillSkillInput`），替换本文档中本段占位内容：

- 层: <lid> <层名称>
- 问题空间文件: <work-dir>/<lid>_问题空间.md
- 答案文件 (<N> 个):
  - <work-dir>/<Q1>_<lid>_answer.md
  - <work-dir>/<Q2>_<lid>_answer.md
  - ...
- 输出文件: <work-dir>/<lid>_horizon_summary.md
- 侧重: <侧重标签>
- 侧重配置: <JSON, 含 label/primary/secondary>
- 完成后在输出文件末尾写入 [HORIZON_SUMMARY_DONE] <lid>

## 核心原则：减少冗余，保持具体

```
错误做法：将 4 个答案压缩成 "MoE: sparse gating 加速推理"（丢失具体性）
正确做法：将 4 个答案的去重方法列表，每个方法保留原答案的
  - 完整方法描述（该层粒度要求的伪代码/流程/数据流）
  - 实现框架/工具链
  - 实验环境（硬件、benchmark、关键指标）
  - vault 笔记来源
```

## Workflow

### Step 1: 读取该层所有输入

- 读取问题空间，获取该层的问题列表和预关键词
- 逐文件读取该层所有答案文件

### Step 2: 提取和去重方法

从所有答案中提取方法列表：

1. 识别同名/同义方法（如 "FlashAttention" 和 "Flash Attention"）
2. 合并同一方法在多个问题中被讨论的内容
3. 保留每个方法在多个答案中的**所有具体信息**（不因去重而丢失细节）

### Step 3: 双维度分类（保持具体性）

**分类维度 1 — 按实验环境**：

| 分类 | 包含方法 | 具体方法描述 | 硬件平台 | Benchmark | 实现框架 |
|------|----------|-------------|----------|-----------|----------|
| GPU/NVIDIA | FlashFuser | SM cluster 内 inter-core fusion，TMA+Tensor Core 并发... | H100 | kernel latency | CUTLASS/Triton |
| NPU/Ascend | ... | ... | ... | ... | ... |
| 加速器 | ... | ... | ... | ... | ... |
| 模拟器 | ... | ... | ... | ... | ... |

注意：**「具体方法描述」列必须包含方法的核心机制原文，不可缩减为 2-3 句摘要。**

**分类维度 2 — 按方法类别**：

根据该层覆盖范围分类。如 L4 Kernel 层：fusion / tiling / pipeline / warp-specialization / multi-stream。每个类别下保留方法的完整描述。

### Step 4: 分类后的详细问答

对每个分类类别，输出：

```markdown
## 分类: <类别名>

### 方法: <方法名1>
<方法的完整描述 — 保持原答案的具体程度>
- **核心机制**: <原答案中的伪代码/数据流/流程描述>
- **实现**: <原答案中的实现框架、工具链>
- **实验环境**: <原答案中的硬件平台、benchmark、关键指标>
- **来源**: <Q-ID>, <答案文件>, <vault-path> (score: ...)

### 方法: <方法名2>
...
```

### Step 5: 方法间关系

标注同类方法之间的关系：
- 替代关系（方法 A vs 方法 B 的优劣对比）
- 互补关系（方法 A + 方法 B 可组合使用）
- 依赖关系（方法 B 依赖方法 A 的输出）

### Step 6: 输出

写入 `<lid>_horizon_summary.md`，末尾加 `[HORIZON_SUMMARY_DONE] <lid>`。
