# Export Conversation Notes

## Overview

将当前可见对话保存为论文相关的 Markdown 笔记到 `conv_notes/`。默认使用中文作为标题和状态文本，保留论文文件名、路径、决策、命令、错误和生成产物等技术细节。

## Workflow

### 第一步：识别当前论文标题

- 优先使用对话中明确提及的论文标题或路径。
- 如果 IDE 上下文中有当前活跃的论文文件，使用其去除扩展名的 basename。例如 `papers/paper_2026/71-TokenFlow.md` → `71-TokenFlow`。
- 如果多个论文标签可见但没有明显当前论文，简要询问用户确认。
- 不要自行编造标题。若无法识别论文，先说明不确定性后使用 `未命名论文对话记录`。

### 第二步：准备输出路径

- 确保 `conv_notes/` 目录存在。
- 清理文件名：将 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 替换为安全分隔符，去除首尾空白。
- 输出路径：`conv_notes/<当前论文标题>.md`。

### 第三步：提取对话记录

- 仅使用当前上下文中可见的对话内容。如果上下文被压缩或早期轮次不可用，说明记录仅覆盖可见对话。
- 对话较短时，使用按时间顺序的发言者标签记录（User/Claude）。
- 对话较长时，写忠实结构化记录：用户请求、Claude 动作、关键工具结果、修改的文件、错误、决策和待解决问题。
- 不要添加对话中未出现的论文主张、实验细节或结论。

### 第四步：写入 Markdown 文件

分三种情况处理：
- **文件不存在**：使用新文件模板创建。
- **文件存在但为空**：使用新文件模板写入。
- **文件存在且非空（增量模式）**：仅追加新内容到文件末尾，绝不修改、删除、重排、摘要、规范化或替换已有内容，即使已有内容存在错误或格式不一致。

## Markdown Template

### 新文件模板

```md
# <当前论文标题>

- 导出时间：<YYYY-MM-DD HH:MM TZ>
- 来源：当前 Claude Code 可见对话上下文
- 保存路径：conv_notes/<当前论文标题>.md

## 对话记录

### User
<用户消息或结构化摘要>

### Claude
<Claude 回复、执行动作、关键工具结果或结构化摘要>

## 已产生的文件或修改

- <路径或 N/A>

## 后续待办

- <待办或 N/A>
```

### 增量追加模板

在文件末尾追加（不修改已有内容）：

```md
---

## 对话记录补充：<YYYY-MM-DD HH:MM TZ>

<同上所需段落>
```

## Completion Response

保存后简要回复输出路径以及是创建还是追加。如有标题推断不确定性或对话上下文不完整，一并说明。
