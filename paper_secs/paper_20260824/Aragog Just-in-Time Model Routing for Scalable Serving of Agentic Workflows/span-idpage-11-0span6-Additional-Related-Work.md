# <span id="page-11-0"></span>6 Additional Related Work

LLM serving optimizations. The rapid deployment of large language models has driven significant innovations in serving optimizations. Some focus on application level compression that craft lightweight variants for efficient inference [\[13,](#page-12-18) [23,](#page-12-19) [28,](#page-13-15) [31\]](#page-13-16). Some employ compiler techniques to optimize execution for low latency [\[33,](#page-13-17)[49\]](#page-14-8). Other works focus on system perspectives like request scheduling [\[14,](#page-12-20) [54\]](#page-14-5), KV cache memory management [\[21,](#page-12-15) [58\]](#page-14-9), parallelism [\[26,](#page-13-18) [64,](#page-14-10) [65\]](#page-14-11), efficient kernels [\[12,](#page-12-21)[53\]](#page-14-12), and resource allocation [\[42,](#page-13-19)[56,](#page-14-13)[63\]](#page-14-14). Aragog operates as an orchestration layer between LLM serving engines and the agentic workflow layer. As such, these optimizations are orthogonal to Aragog and can be incorporated into the underlying serving engines.

Agent serving optimizations. The rise of LLM-powered agents introduces new challenges for LLM serving, as agent execution involves an input-dependent and varying number of interceptions (e.g., tool calls) and LLM calls. Recent research has focused on addressing these agent-specific inefficiencies [\[3,](#page-12-22) [16,](#page-12-23) [29,](#page-13-20) [30,](#page-13-11) [61\]](#page-14-15). For instance, InferCept [\[3\]](#page-12-22) reduces GPU resource waste arising from frequent LLM interceptions, while Autellix [\[30\]](#page-13-11) mitigates head-of-line blocking caused by the variable number of LLM calls per agent by prioritizing requests based on cumulative service time. These techniques are complementary to Aragog, which orchestrates execution at the workflow level (across a graph of agents) and can leverage agent-serving optimizations within each agent within the graph.

Agentic workflow serving optimizations. Agentic workflows orchestrate multiple agents as a graph, introducing dependencies across agents. Recent systems exploit graph-level knowledge for scheduling and resource management [\[7,](#page-12-24) [27,](#page-13-10) [40,](#page-13-21) [44\]](#page-13-9). For instance, Parrot [\[27\]](#page-13-10) introduces graph-aware batching and KV cache sharing, while Ayo [\[44\]](#page-13-9) rearranges the execution graph for efficient execution and scheduling. These systems optimize for a fixed configuration; Aragog complements them by dynamically adapting configurations at runtime. Other work automates workflow graph design [\[34,](#page-13-22) [59\]](#page-14-16); Aragog is agnostic to graph structure and can serve automatically-generated workflows.
