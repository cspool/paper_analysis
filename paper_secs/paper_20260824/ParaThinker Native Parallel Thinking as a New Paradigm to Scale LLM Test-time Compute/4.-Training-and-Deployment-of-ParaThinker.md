# 4. Training and Deployment of ParaThinker

We use SFT to train ParaThinker. The special challenges include: (1) How to let LLMs know the meanings of <think i> tokens and generate diverse reasoning paths during training? (Section 4.1) (2) How to design attention mask for ParaThinker training? (Section 4.2) (3) How to design inference engine of ParaThinker? (Section 4.3)

#### <span id="page-7-0"></span>4.1. Scalable Train Data Curation

To effectively enable native parallel reasoning, we design a scalable training data curation pipeline that consists of two key components: multi-path training data scaling and extensible special tokens training.

**Multi-Path Training Data Scaling:** We develop a simple yet effective high-quality parallel reasoning dataset by sampling multiple times from teacher reasoning LLM (e.g., DeepSeek-R1 (DeepSeek-AI, 2025)). For a query x and groundtruth answer a, let the  $\hat{P}$  sampled answers denoted as  $\{(r^{(1)}, a^{(1)}), (r^{(2)}, a^{(2)}), \ldots, (r^{(\hat{P})}, a^{(\hat{P})})\}$ . We then concat each parallel answer into a groundtruth answer with the format of:  $\hat{y} = (\sinh 1)r^{(1)} < \sinh 1 > \ldots, (\sinh \hat{P})r^{(\hat{P})} < \sinh \hat{P} > \sinh \hat{P} > \sinh 2r^{(1)} > \ldots$ . The resulting  $Data_{r-1}^{\hat{P}} = (x, \hat{y})$  pairs are then used for SFT.

**Extensible Special Tokens Training:** Due to the high cost of teacher LLM inference, we are often faced with the situation where we cannot generate enough reasoning paths when creating  $Data_{sft}$ , that is,  $\hat{P}$  is less than P in many cases. Thus, during SFT stage, LLMs have to learn to extend to  $(r^{(\hat{P}+1)}, \ldots, r^{(P)})$  with training data  $Data_{r=1}^{\hat{P}}$ . Therefore, we develop a dynamic special token sampling method for extensible special tokens training. Specifically, at each training batch, we randomly sample  $\hat{P}$  special tokens from  $\{1, \ldots, P\}$ . These sample  $\hat{P}$  tokens are placed at the beginning of each reasoning sequence, and the special tokens embeddings are trainable. Thus the special token embeddings are diverse after enough training, and lead LLMs to different reasoning directions.

## <span id="page-7-1"></span>4.2. Attention Mask Design

To enable effective parallel reasoning, ParaThinker adopts a two-phase attention mask design. During the reasoning phase, each reasoning path is decoded independently, with attention restricted to the input prompt and its own token history. Let  $M_{i,j}$  denote the attention mask between the index i and index

j, where attention score can be calculated as:  $A_{i,j} = \operatorname{Softmax}\left(\frac{q_i \cdot k_j + M_{i,j}}{\sqrt{d_k}}\right)$ . The attention mask for the i-th reasoning path  $(r^{(i)})$  is defined as:

$$M_{t,j}^{r^{(i)}} = \begin{cases} 0, & \text{if } j \le t \text{ and } j \in \{1, \dots, l_x\} \cup \text{Ind}_i \\ -\infty, & \text{otherwise} \end{cases}$$
 (8)

where  $l_x$  is the length of the input prompt and  $Ind_i$  is the index range for tokens in the *i*-th reasoning path. This enforces independence across reasoning paths by blocking inter-path attention.

During the summarization phase, where each answer token attends to the entire prompt, all reasoning paths, and previously generated answer tokens. The summarization attention mask is defined as:

$$M_{t,j}^{A} = \begin{cases} 0, & \text{if } j \le t \text{ and } j \in \{1,\dots,l_{x}\} \cup \bigcup_{i=1}^{p} \operatorname{Ind}_{i} \cup \operatorname{Ind}_{a} \\ -\infty, & \text{otherwise} \end{cases}$$
 (9)

where  $Ind_a$  denotes the index range of the answer tokens. This mask allows the final answer to integrate all parallel thoughts without violating autoregressive constraints.

## <span id="page-8-0"></span>4.3. Inference Engine

The inference engine for ParaThinker is built upon the vLLM framework (Kwon et al., 2023) to leverage its efficient parallel scaling. The inference process is divided into two distinct phases:

**Parallel Reasoning Phase:** The engine processes the *P* reasoning paths concurrently as a single batch. This synchronous decoding phase terminates for all paths simultaneously as soon as the one of the following conditions is met: (1) Path Completion: Any one of the *P* paths generates an end-of-sequence (EOS) token. (2) Budget Exceeded: Any one of the *P* paths reaches the predefined token budget, B. This uniform termination strategy ensures all reasoning paths maintain an equal length, preventing processing imbalance. As empirically justified in Section 5.4, this approach yields the highest accuracy.

**Summarization Phase:** Following the parallel reasoning phase, the engine constructs an attention context spanning the KV caches of all *P* reasoning paths, eliminating the need for costly re-prefilling. Leveraging vLLM's PagedAttention, this step is performed with zero data copying, as the summary sequence can directly reference the memory blocks of all preceding paths. The final answer is then autoregressively decoded from this unified context.
