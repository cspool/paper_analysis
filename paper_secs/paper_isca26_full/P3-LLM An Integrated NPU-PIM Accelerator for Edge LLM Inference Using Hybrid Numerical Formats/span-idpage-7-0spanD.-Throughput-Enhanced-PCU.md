# <span id="page-7-0"></span>*D. Throughput-Enhanced PCU*

Despite the proposed low-precision PCU achieving 4× the computational throughput than HBM-PIM, it still supports only GEMV operations. To further exploit data reuse opportunities inside the PCU, one can increase the activation tile size from 1 × 4 to n × 4 (where n > 1), and compute a n × 4 × 16 GEMM tile. But this will increase the number of multipliers by n×, leading to considerable area overhead. A direct workaround is also to reduce the weight size by n×, resulting in a n × 4 × (16/n) GEMM tile without the need for additional multipliers. Nevertheless, this approach causes severe under-utilization of the PIM bandwidth because of the inherent 256-bit column access granularity of HBM.

Instead of adopting spatial data, we introduce a novel optimization that exploits temporal data reuse inside the PCU. Our key insight is that the proposed low-precision PCU not only reduces the area, but also permits a higher operating frequency compared to the baseline HBM-PIM [\[49\]](#page-14-9). Specifically, our evaluation (detailed in Section [VI-A\)](#page-7-1) demonstrates that the PCU of P<sup>3</sup> -LLM can reliably achieve 2× higher frequency than that of HBM-PIM using FP32 accumulators. Given that HBM-PIM operates at a clock cycle of tCCD <sup>L</sup>, which corresponds to 4 memory bus cycles, the proposed PCU can instead operate P<sup>3</sup> -LLM at tCCD <sup>S</sup>, which is typically a half of tCCD <sup>L</sup> across all HBM generations [\[33\]](#page-13-22), [\[36\]](#page-13-23), [\[37\]](#page-13-24).

Fig. [7](#page-7-2) compares the command timing between HBM-PIM and P<sup>3</sup> -LLM. Initially, the host NPU sends input activations to the PCU register. Subsequently, a PIM command is initiated every tCCD <sup>L</sup> on HBM-PIM, which reads out 256-bit weights from the DRAM row buffer and performs a GEMV operation. P 3 -LLM allows the same weight slice to be reused twice by two different inputs, effectively doubling the throughput for cases where multiple inputs share the same weight. Our simulation shows that the PIM power of P<sup>3</sup> -LLM increases by 28% when its PCU operates at tCCD <sup>S</sup> instead of tCCD <sup>L</sup>, resulting in 1.56× better energy efficiency. This is because the majority of PIM power dissipation comes from DRAM cell access and column decoder switching, which do not change as the throughput-enhanced PCU reuses the same set of weights from the row buffer across two consecutive tCCD <sup>S</sup> windows.
