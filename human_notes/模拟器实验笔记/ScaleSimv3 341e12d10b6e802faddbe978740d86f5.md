### 算子分析

基于分析模型，编译生成地址访存指令和计算指令的trace，地址访存通过DRAM仿真器获得延迟数据，结合计算延迟模拟端到端延迟。

回放**trace**估计端到端延迟，内存延迟使用BW粗略估计、或用BW简化估计一批访存指令的延迟、或用Ramulator仿真估计指令level延迟。

  驱动机制：解析式 Trace 驱动（Analytical Trace-Driven）                                                                                                                               
   
  SCALE-Sim 不是 Cycle-Accurate RTL 模拟，也不是事件驱动。它是一个解析式 Trace 驱动模拟器，工作分两个截然分离的阶段：                                                                  
                  
  Phase 1 (Analytical):  层参数 → 用矩阵运算预计算出【全部内存访问地址序列】                                                                                                           
  Phase 2 (Trace-Play):  将地址序列"回放"过 SRAM/DRAM 内存模型 → 统计 cycle/stall/BW                                                                                                   
                                                                                                                                                                                       
  这意味着模拟器不模拟单个 PE 的状态机，而是在抽象层面描述"第 N 个 cycle，脉动阵列的第 k 行需要读取 SRAM 地址 X"，然后检查这个请求是否会产生 DRAM stall。

  def calc_ifmap_elem_addr(self, i, j):                                                                                                                                                
      # i = 输出像素索引(0~T-1), j = 卷积核元素索引(0~K-1)
      Ew = self.ofmap_cols            # = 5                                                                                                                                            
                                                                                                                                                                                       
      # Step 1: 将 output pixel i 映射回 input 坐标                                                                                                                                    
      ofmap_row, ofmap_col = np.divmod(i, Ew)                                                                                                                                          
      i_row = ofmap_row * r_stride    # IFMAP 窗口起点行                                                                                                                               
      i_col = ofmap_col * c_stride    # IFMAP 窗口起点列                                                                                                                               
                                                                                                                                                                                       
      # Step 2: 窗口基地址（NHWC 布局）                                                                                                                                                
      window_addr = (i_row * ifmap_cols + i_col) * channel
                                                                                                                                                                                       
      # Step 3: 将 kernel 元素 j 分解为 (filter行, filter列, 通道)                                                                                                                     
      c_row, k = np.divmod(j, filter_col * channel)
      c_col, c_ch = np.divmod(k, channel)                                                                                                                                              
                  
      # Step 4: 最终物理地址                                                                                                                                                           
      internal_addr = (c_row * ifmap_cols + c_col) * channel + c_ch
      ifmap_px_addr = window_addr + internal_addr + offset

  3.2 GEMM 算子与脉动阵列数据流（WS）                                                                                                                                                  
                                                                                                                                                                                       
  Weight Stationary 流动模式 (systolic_compute_ws.py):
                                                                                                                                                                                       
           PE[0,0]  PE[0,1] ... PE[0,31]
  Filter:    W00      W01   ...   W031     ← 静止不动（Stationary）                                                                                                                    
             ↑        ↑            ↑                                                                                                                                                   
  IFMAP:  →  I0   →   I0   →   →  I0      ← 横向流动（Broadcast/Multicast）                                                                                                            
             ↓        ↓            ↓                                                                                                                                                   
  OFMAP:  ←  O0   ←   O0   ←   ←  O0     ← 向下累积后 drain
                                                                                                                                                                                       
  关键设计细节：                                                                                                                                                                       
                                                                                                                                                                                       
  Filter 逆序加载 (create_filter_demand_mat, line 386):

  原因：脉动阵列中数据从顶部 PE 逐步向下传播，最顶部 PE 最后才需要权重。逆序使第 0 行的权重最后送达，确保所有 PE 在第一个 IFMAP 到达时同步就绪。                                       
                                                                                                                                                                                       
  IFMAP 斜向波前 (skew_matrix, line 614):                                                                                                                                              
  for c in range(cols):                                                                                                                                                                
      out_matrix_np[c:c+rows, c] = input_matrix_np[:, c]

  4. 内存层次状态机（双缓冲 SRAM）                                                                                                                                                     
                                                                                                                                                                                       
  double_buffered_scratchpad 的核心状态逻辑（无显式 FSM 代码，通过 Python 对象状态模拟）：
                                                                                                                                                                                       
  SRAM 状态:      
  ┌─────────────────────────────────────────────────┐                                                                                                                                  
  │  Active Buffer (50%):  正在服务 PE 阵列的请求     │
  │  Prefetch Buffer (50%): 正在从 DRAM 预取下一块    │                                                                                                                                
  └─────────────────────────────────────────────────┘                                                                                                                                  
                                                                                                                                                                                       
  每 cycle 的决策逻辑 [service_memory_requests, line 254]:                                                                                                                             
  │               
  ├─ 请求地址在 hashed_buffer 中？                                                                                                                                                     
  │   YES → hit_latency=1 cycle，无 stall
  │   NO  → 触发 DRAM fetch，stall = fetch_latency - 1                                                                                                                                 
  │                                                                                                                                                                                    
  ├─ stall = max(ifmap_stall, filter_stall, ofmap_stall)  [line 279]                                                                                                                   
  │   (三路内存并行，取最大瓶颈)                                                                                                                                                       
  │                                                                                                                                                                                    
  └─ 预取机制 [read_buffer.py:prefetch_active_buffer]:                                                                                                                                 
      当 active_buffer 使用量超过 active_buf_frac(50%) 时，                                                                                                                            
      触发 prefetch_buffer 从 DRAM 加载下一批数据                                                                                                                                      
      →  实现 DRAM latency hiding                                                                                                                                                      
                                                                                                                                                                                       
  两种带宽模式（estimate_bandwidth_mode）:                                                                                                                                             
  - USER 模式：使用配置文件中的用户指定 DRAM 带宽，实例化 read_buffer                                                                                                                  
  - CALC 模式：使用 ReadBufferEstimateBw [line 106]，通过带宽分析估算 DRAM 访问时间，不需要精确带宽配置

## 指令调度

地址访存延迟和计算延迟的事件驱动模拟器。

  核心结论（先读）                                                                                                                                                                     
                                                                                                                                                                                       
  SCALE-Sim 没有传统意义上的 ISA 指令集。 它使用一种独特的"矩阵式超字指令"（Matrix Superword Instruction）模型：将整个推理过程的控制流预先编译成三维度"需求矩阵"（Demand
