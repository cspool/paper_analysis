## Code

- 你的理解基本对：这个项目不是“直接测 GPU 推理速度当硬件性能”，而是：

真实 VLM 推理 on GPU
-> 在 PyTorch forward 里插入 Focus/CMC/Adaptiv
-> 记录稀疏/聚类 trace
-> simulator 读 trace
-> ScaleSim + 自己的 memory/energy model
-> 得到专用硬件上的 cycle / latency / energy

换成 RTL 视角，可以把 GPU 推理阶段理解成“产生 workload stimulus 和 oracle trace”，后面的
simulator 才是在估算你的 accelerator 跑这些 workload 要多少周期。

仓库三层
algorithm/ 是算法和 trace 生成层。这里会真的加载 VLM，跑 VideoMME/MLVU/MVBench，用 PyTorch
得到每个样本里视觉 token 的冗余情况。

关键文件：

- algorithm/run_eval.py:1：评测入口，相当于 testbench launcher。
- algorithm/focus/interface.py:1：把原模型 forward 替换成带 Focus/CMC/Adaptiv 的 forward。
- algorithm/focus/main.py:1：Focus 核心算法，计算相似性、聚类、mask、trace。
- algorithm/focus/models/：不同 VLM 的 forward 改写版本。
- algorithm/lmms-eval/：评测框架，负责 dataset、prompt、metric。

simulator/ 是架构性能模拟层。它不再跑大模型，只读 trace，然后估算硬件周期、访存、能耗。

关键文件：

- simulator/main.py:1：模拟入口。
- simulator/models/models.py:1：模型结构参数，例如 hidden dim、head 数、层数、各 GEMM
shape。
- simulator/models/sparse_info.py:1：读取 GPU 阶段导出的 trace。
- simulator/core/simulator.py:1：总调度，逐层模拟。
- simulator/core/simulator_comp.py:1：计算周期模型，调用 ScaleSim。
- simulator/core/simulator_mem.py:1：SRAM/DRAM 访问量模型。
- simulator/arch/accelerator.py:1：硬件配置，阵列尺寸、buffer、频率、面积功耗参数。

rtl/ 是硬件模块层。它不是每次 simulation 都跑 Verilog，而是提供 Focus 相关硬件模块实现，部
分面积/功耗数据会以 CSV 形式被 simulator 使用。

GPU Trace 阶段
普通推理命令是：

python -m run_eval --model llava_vid ... --tasks videomme

如果加：

- -focus --export_focus_trace --trace_dir ./output/focus_main/ --trace_meta_dir ./output/

流程会变成：

1. run_eval.py 加载模型和数据集。
2. focus/interface.py 根据 --focus 替换模型内部 forward。
3. 推理每个样本时，Focus 在视觉 token 上做三类事情：
    - SEC：semantic concentration，按 token importance 删除不重要视觉 token。
    - SIC：similarity concentration，找相似视觉 token/vector，把冗余 vector 合并。
    - vector/block 粒度组织：让稀疏模式更适合硬件 tile 和局部访问。
4. focus/main.py 保存 trace。

Focus trace 不是 GPU timeline，也不是 instruction trace。它是硬件模拟需要的稀疏结构：

mask_zero      哪些 token/vector 已经是 0，可以跳过
mask_similar   哪些 vector 与附近 vector 相似，可以合并/复用
group_idx      每个 vector 属于哪个聚类/代表 vector

这些会保存到：

algorithm/output/focus_main/llava_vid_videomme.pth
algorithm/output/meta_data.csv

meta_data.csv 记录模型、数据集、sequence length、帧数、patch 数等。模拟器靠它确定 workload
尺寸。

CMC / Adaptiv 的 trace 更粗，只保存平均 sparsity：

cmc_sparsity.csv
adaptiv_sparsity.csv

Simulator 阶段
模拟命令类似：

cd /data3/Focus/simulator

python [main.py](http://main.py/) \
--accelerator focus \
--trace_dir ../algorithm/output \
--model llava_vid \
--dataset videomme \
--output_dir results

流程是：

1. ModelConfig 读 meta_data.csv，拿到 seq_len、num_frames、num_patches。
2. 它构造 Qwen2-7B 的层配置：q_proj/k_proj/v_proj/o_proj/gate_proj/up_proj/down_proj/
attn。
3. SparseInfo 读 .pth trace 或 baseline sparsity CSV。
4. Simulator 遍历 28 层，每层遍历 linear 和 attention。
5. 对每个 GEMM/attention，计算：
    - dense ops：原始满计算量。
    - num_ops：Focus 后实际计算量。
    - compute_cycles：阵列计算周期。
    simulator/results/main_cmc.csv
    simulator/results/main_adaptiv.csv

从 RTL 角度看
你可以这样对应：

- mask_zero 像 valid mask，告诉硬件哪些 lane/token 不需要算。
- mask_similar 像 merge/reuse 控制信号，告诉硬件哪些 vector 可由 representative 代替。
- group_idx 像 gather/scatter 地址映射表，告诉输出如何恢复到原 token 顺序。
- SEC 对应重要性筛选模块。
- SIC 对应相似度检测、聚类、平均/累加更新模块。
- systolic array 仍负责主 GEMM。
- layouter/similarity_map/similarity_table/concentrate_out 是为 Focus 数据重排和稀疏恢复服
务的 SRAM/buffer。

所以完整 mental model 是：

PyTorch VLM = 生成真实 token 序列和稀疏模式
2. 用 torch.load() 打开一个 .pth，看 mask_zero/mask_similar/group_idx 的 shape。
3. 跑 simulator/main.py --accelerator focus，看 main_focus.csv。
4. 对照 simulator/core/simulator.py:126 的 run_focus()，逐层理解每个 layer 怎么从 mask 变
成 cycle。
5. 最后再看 rtl/，把 RTL block 和 Accelerator.components 里的 Cosine Similarity (SIC)、
Accumulator (SIC)、Max Unit (SEC) 对起来。
