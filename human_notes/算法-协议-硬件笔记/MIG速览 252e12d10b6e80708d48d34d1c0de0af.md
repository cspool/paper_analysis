# xpm

> **[图片提取文字 (image.png)]:**
> 在FPGA设计中,使用存储单元几乎不可避免。xilinx UltraScale+ 和 Versal 系列中有三类存储资 源,分别是分布式存储资源(LUTRAM)、Block RAM和UltraRAM。Vivado提供了四种方式使用这三 类资源: 使用IP Core(Block Memory Generator / FIFO Generator / Distributed Memory Generator)、使用原语(Primitive)直接实例化,使用XPM、使用RTL代码由工具推断。这四种方 式各有优缺点。比如:使用IP Core,对于不同类型的RAM要反复调用IP Core,填入相应的参数,同 时IP Core内部对用户是不可见的。但IP Core使用起来还是比较简单的。只是,如果目标芯片为 Versal, Vivado 2020.2版本不再提供上述IP,取而代之的是Embedded Memory Generator,而且此IP 只支持IPI流程。如果使用原语,会发现所有端口中用户都可见,用户具有最大的可控性,但使用 起来很繁琐。倘若对器件结构不甚清楚,例如不了解URAM如何级联,很可能造成连接错误。同 时,原语还有很多属性,深入了解第一个属性也很费时。如果使用RTL代码,就要求有良好和代码 风格,同时对一些综合属性有所了解,如RAM STYLE, CASCADE HEIGHT等,否则会影响综合 质量。相比下来,使用XPM更为妥当。
> 
> XPM全称为Xilinx Parameterized Macro, 给用户提供了一种参数化的方式使用存储单元、跨时钟域设计等。在Vivado Language Template中可以找到XPM,如下图所示。所以,只用在用户代码中实例化就可以了。

# MIG介绍

MIG是vivado的官方IP，用于生成用户侧的memory接口的模板IP（template）；

> **[图片提取文字 (image.png)]:**
> MIG(Memory Interface Generator<mark>)是由 Xilinx 提供的一款功能强大的官方 IP 核工具,广泛用于其 FPGA 开发环境(如 Vivado</mark> Design Suite **和早期的 ISE)中**。该工具的主要作用是为用户**自动生成针对特定外部存储器(如** DDR2、DDR3、DDR4、
> 
> LPDDR2、LPDDR3、QDR、RLDRAM 等)的高性能接口控制器模块。
> 
> 大大降低了开发难度并提升了设计效率。
> 
> 通过 MIG 内存接口生成器,我们可以快速实现与高速存储器之间的稳定通信,而无需深入理解复杂的内存控制协议与时序细节,

> MIG 封装的核心功能模块: MIG 并不仅仅是一个简单的 IP 核,它实际上封装了多个关键子模块,共同完成对外部存储器的高效访
> 
> | 描述                                     |
> |----------------------------------------|
> | 提供标准化接口供用户访问内存,支持 AXI4 或 Native 接口两种模式 |
> |                                        |
> 
> 实现 JEDEC 标准定义的 DDR 内存初始化、预充电、刷新、突发读写等操作 控制逻辑层(Controller Logic)
> 
> IO 引脚驱动(IO Physical Pins)
> 
> 包括 Write Leveling、Read Leveling、Gate Calibration、VREF Calibration 等, 校准逻辑(Calibration Logic) 确保在高速传输下信号完整性
> 
> 初始化与时序控制(Initialization & 自动管理内存上电初始化流程以及周期性刷新操作,符合 JEDEC 规范 Timing Control)
> 
> 使用 Xilinx 原语(如 ODDR、IDDR、IOBUFDS 等)处理差分时钟、数据线、地 物理层接口(PHY Layer) 址线的输入输出
> 
> > 根据所选器件与内存类型,给出 PCB 引脚布局建议,并配置 IO Bank 的电压标 准(如 SSTL、HSTL)

**用户接口层：MIG和用户设计间的接口，即memory接口和FPGA用户模块间的接口；**

**基于AXI接口生成的memory接口，视为与FPGA互相独立模块，放弃其位于FPGA片上带来的更高设计空间，进行封装降低开发难度；**

**基于native接口/app接口生成的memory接口，需要用户对齐地址和突发长度；**

> **[图片提取文字 (image.png)]:**
> ## 2.2 类型选择
> 
> 用户接口类型选择
> 
> MIG 提供两种类型的用户访问接口:
> 
> | 接口类型      | 特点                       | 适用场景                      |
> |-----------|--------------------------|---------------------------|
> | AXI4 接口   | 标准化接口、信号少、易于与 AXI 总线系统集成 | 建议优先选择,适合 Zynq SoC、IP 核互联 |
> | Native 接口 | 自定义读写信号、延迟可控、信号较多        | 适用于需要精细控制的底层存储控制器设计       |
> 
> ## AXI 接口推荐给大多数开发者; Native 接口适合高级用户。
![image.png](MIG%E9%80%9F%E8%A7%88/image%2011.png)

> **[图片提取文字 (image.png)]:**
> ① 用户接口层(User Interface Layer)
> 
> 这是 MIG 与用户设计之间的交互接口,提供了两种主要模式供选择:
> 
> - AXI4 接口:适用于基于 AXI 总线架构的系统(如 Zynq UltraScale+ MPSoC),支持突发传输、乱序响应等高级特性。
> - Native 接口:提供更底层的读写命令/数据通道,便于 FIFO 或自定义逻辑对接,但需用户自行管理地址与突发长度。
> 
> ☑ 建议对于复杂系统优先使用 AXI 接口;对时序要求严格或资源受限的设计可选用 Native 接口。
![image.png](MIG%E9%80%9F%E8%A7%88/image%2012.png)

**控制逻辑层：将FPGA上模块请求（用户请求）转为DDR命令序列；**

> **[图片提取文字 (image.png)]:**
> ② 控制逻辑层(Contro Logic Layer)
> 
> 该模块负责将用户的访问请求转换为符合 JEDEC 规范的 DDR 命令序列,是整个控制器的"大脑",主要包括:
> 
> 初始化流程(上电后自动执行)
> 
> 刷新机制(Auto Refresh 和 Self Refresh)
> 
> 预充电 (Precharge)
> 
> 行激活(Activate)
> 
> 数据读写(Read/Write)
> 
> 突发操作(Burst Length)
> 
> Bank 状态管理
> 
> 命令优先级调度与仲裁等
> 
> <u> </u>
![image.png](MIG%E9%80%9F%E8%A7%88/image%2013.png)

**校准逻辑：DDR接口在高频传输下的信号完整性；**

> **[图片提取文字 (image.png)]:**
> ③ 校准逻辑(Calibration Logic)
> 
> 由于 DDR 接口运行在高频下,**信号完整性至关重要**。MIG 提供了完整的硬件校准机制,确保在各种 PCB 布局和工艺差异下仍能保 持稳定工作。主要校准过程包括:
> 
> Write Leveling:调整 DQS 与 CK 之间的相位关系,确保写入时序正确。
> 
> Read Leveling:校正从内存返回的数据与采样时钟之间的偏移。
> 
> Gate Calibration:检测读取窗口中心点,确保数据被准确采样。
> 
> VREF Calibration:设置合适的参考电压阈值,提升信号稳定性。
> 
> ☑ 所有校准操作通常在上电初始化阶段完成,并通过状态寄存器反馈结果,便于调试。
![image.png](MIG%E9%80%9F%E8%A7%88/image%2014.png)

**初始化、时序控制：DDR接口的启动；**

> **[图片提取文字 (image.png)]:**
> 该模块负责整个 DDR 接口的启动流程,包括:
> 
> 上电复位后自动执行 JEDEC 定义的初始化流程 设置 Mode Register(MR)、Extended Mode Register(EMR)等配置寄存器 控制时钟使能、ZQ 校准、DLL 锁定等关键步骤 管理 DDR 的进入/退出低功耗模式(如 Self Refresh)
> 
> ![](_page_0_Picture_2.jpeg)
> 
> 🟅 **重要性**:初始化流程必须严格按照 JEDEC 标准执行,否则可能导致接口无法正常工作。
![image.png](MIG%E9%80%9F%E8%A7%88/image%2015.png)

物理层接口：DDR内存和FPGA IO引脚间的物理连接和时序匹配；

> **[图片提取文字 (image.png)]:**
> PHY 是 MIG 的核心之一,它负责实现 DDR 内存与 FPGA IO 引脚之间的物理连接与时序匹配,主要包括以下子模块:
> 
> **时钟域同步逻辑**:处理不同频率域之间的信号同步问题(如 PLL 输出与时钟反馈)。 **IO 驱动单元**:使用 ODDR、IDDR、IOBUFDS 等原语实现差分时钟、地址、控制和数据线的输入输出。
> 
> ★ 关键作用: PHY 负责 DDR 信号的精确采样与发送,直接影响接口的稳定性与最大频率。
> 
> **DFI 接口(DDR PHY Interface)**: 连接 Controller 与 PHY 的标准化接口。
> 
> 数据路径(Data Path):处理读写数据的延迟对齐与位宽转换。
![image.png](MIG%E9%80%9F%E8%A7%88/image%2016.png)

**IO引脚驱动：上一步DDR芯片和FPGA IO引脚连接后，对IO引脚分配和配置；**

> **[图片提取文字 (image.png)]:**
> ⑥ IO 引脚驱动(引脚分配与 IO 配置: Pinout & IO Standard Configuration)
> 
> MIG 工具在生成 IP 时会根据所选的 FPGA 器件和内存类型,**自动生成对应的引脚分配建议(\*.xdc 约束文件)**,并配置 IO Bank 的 电压标准(如 SSTL、HSTL、POD 等),确保接口电平兼容性。此外,MIG 还会考虑 PCB 布线规则(如 Fly-by 布线拓扑、走线长度 匹配等),帮助开发者优化硬件设计。
> 
> 🧩 **建议**:务必遵循 MIG 提供的约束文件进行 PCB 设计,以避免信号完整性问题。
![image.png](MIG%E9%80%9F%E8%A7%88/image%2017.png)
