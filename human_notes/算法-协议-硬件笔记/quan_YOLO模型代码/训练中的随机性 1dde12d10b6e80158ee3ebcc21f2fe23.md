# 训练中的随机性

在用MMDetection做目标检测时，设置了"Set random seed to 0, deterministic: True"，在数据集与模型均相同的情况下做训练，两次训练的mAP并不相同。请问随机性可能来自哪里？

**一句话回答：**

其实不只是 [MMDetection](https://zhida.zhihu.com/search?content_id=364566943&content_type=Answer&match_order=1&q=MMDetection&zd_token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJ6aGlkYV9zZXJ2ZXIiLCJleHAiOjE3NDU1MDI5MzksInEiOiJNTURldGVjdGlvbiIsInpoaWRhX3NvdXJjZSI6ImVudGl0eSIsImNvbnRlbnRfaWQiOjM2NDU2Njk0MywiY29udGVudF90eXBlIjoiQW5zd2VyIiwibWF0Y2hfb3JkZXIiOjEsInpkX3Rva2VuIjpudWxsfQ.5tIZ_u3pes55pkbHn3SJJs9aN0FYI7Z6O0rh5raBBF0&zhida_source=entity) 的训练中有随机性，基本上大部分深度学习框架的训练都具有随机性，核心原因在于 [CUDA](https://zhida.zhihu.com/search?content_id=364566943&content_type=Answer&match_order=1&q=CUDA&zd_token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJ6aGlkYV9zZXJ2ZXIiLCJleHAiOjE3NDU1MDI5MzksInEiOiJDVURBIiwiemhpZGFfc291cmNlIjoiZW50aXR5IiwiY29udGVudF9pZCI6MzY0NTY2OTQzLCJjb250ZW50X3R5cGUiOiJBbnN3ZXIiLCJtYXRjaF9vcmRlciI6MSwiemRfdG9rZW4iOm51bGx9.E_Vz6aqnLoqvbz2waACoDfxm6mTJ41Eo1Q3NSVxU48M&zhida_source=entity) 中的 atomic 操作在并行计算的时候是无序且随机的。

**详细回答如下：**

首先要 refer 一下 [PyTorch](https://zhida.zhihu.com/search?content_id=364566943&content_type=Answer&match_order=1&q=PyTorch&zd_token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJ6aGlkYV9zZXJ2ZXIiLCJleHAiOjE3NDU1MDI5MzksInEiOiJQeVRvcmNoIiwiemhpZGFfc291cmNlIjoiZW50aXR5IiwiY29udGVudF9pZCI6MzY0NTY2OTQzLCJjb250ZW50X3R5cGUiOiJBbnN3ZXIiLCJtYXRjaF9vcmRlciI6MSwiemRfdG9rZW4iOm51bGx9.NrpWzX-UM_-IETeyakSZsqvLl-xuCsPPJfF2jUS67GI&zhida_source=entity) 官方的文档 [https://pytorch.org/docs/stable/notes/randomness.html](https://link.zhihu.com/?target=https%3A//pytorch.org/docs/stable/notes/randomness.html)，里面基本解释了 PyTorch 框架内，一个算法在不同次 训练过程中会遇到的并且可以被控制的不确定性因素，主要可以包含两个方面：1. 随机数的生成，2. 某些算子的实现算法。随机数的生成可以通过设置 numpy 和 torch 的 seed 来进行控制，算子的实现算法可以使用 pytorch 中的一些开关，如 torch.use_deterministic_algorithms 来进行锁定。目前 [OpenMMLab](https://zhida.zhihu.com/search?content_id=364566943&content_type=Answer&match_order=1&q=OpenMMLab&zd_token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJ6aGlkYV9zZXJ2ZXIiLCJleHAiOjE3NDU1MDI5MzksInEiOiJPcGVuTU1MYWIiLCJ6aGlkYV9zb3VyY2UiOiJlbnRpdHkiLCJjb250ZW50X2lkIjozNjQ1NjY5NDMsImNvbnRlbnRfdHlwZSI6IkFuc3dlciIsIm1hdGNoX29yZGVyIjoxLCJ6ZF90b2tlbiI6bnVsbH0.qyS6DZBYp2cHM3HlTkk0uSZb8doJsNh54P-eUyTValA&zhida_source=entity) 系列的算法库都提供了这样的接口封装，来实现同一算法在不同次训练过程中使用一样的 seed 和相同的算法实现，这也是题主在训练过程中，能看到 log 里输出 "Set random seed to 0, deterministic: True" 的原因。

那么问题来了，为什么我们即使设置了 random seed，并保证了每次实验算子实现的确定性，还会出现每次实验结果有波动的情况呢？这是因为一些算子的 CUDA 底层实现中，有时不可避免地会在不同kernel中对同一个地址多次进行加减乘除等原子操作。尤其是在 backward 的时候，atomicAdd 的使用非常的常见。这类 atomic 操作，在进行计算的时候，是无序且随机的，因此，在对同一个地址多次进行原子操作时（如对同一个地址进行多次梯度的累加），由于他们的执行顺序具有不确定性，即使相加的每个数数值一样，在多次运行时，这些数相加的次序也是不一样的。相加次序的随机性引来了另外一个问题，即由于相加的数值一般都是浮点数，而浮点数存在精度丢失问题，最终多次相加的结果会因为相加次序的不同，出现不同程度的精度损失。换句话说：因为每次相加次序的不同导致了最终相加结果出现细微的差别。

关于这一点，在 OpenMMLab 项目开发的早期阶段我们也做过一些实验进行分析，以 [Faster R-CNN](https://zhida.zhihu.com/search?content_id=364566943&content_type=Answer&match_order=1&q=Faster+R-CNN&zd_token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJ6aGlkYV9zZXJ2ZXIiLCJleHAiOjE3NDU1MDI5MzksInEiOiJGYXN0ZXIgUi1DTk4iLCJ6aGlkYV9zb3VyY2UiOiJlbnRpdHkiLCJjb250ZW50X2lkIjozNjQ1NjY5NDMsImNvbnRlbnRfdHlwZSI6IkFuc3dlciIsIm1hdGNoX29yZGVyIjoxLCJ6ZF90b2tlbiI6bnVsbH0.MKEMdKwhoMeq9_CvBF2_5PWq7m0xcXPAtCMaKLrotIo&zhida_source=entity) 为例，这里，通过设置随机种子和 deterministic=True，我们可以做到：在两个单卡单batch实验并使用相同的初始化权重的情况下，每次实验输入的图片、乃至模型的 forward 输出是完全一致的，并且，模型的 loss 数值上也完全相等。但是，在经过一次 BP 以后，两个模型就出现了细微的差别。可以想见，即使每次训练过程中，使用相同的初始化并且给模型喂完全一样的数据，最终训出来的模型 mAP 还是会有细微差别。
